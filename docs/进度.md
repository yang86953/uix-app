## 更小 · 更快 · 更稳

功能面已收敛。后续只围绕三个方向：

- **更小**：缩小内存占用。当前 ~100MB RSS 中 GPU 驱动/交换链占比过半不可控，其余来自字形缓存、CPU 中转缓冲、Picture 离屏池、槽位数组膨胀。Picture 候选现按预计重绘像素 / BGRA 保留字节排序，并受每棵 LayerTree 32 MiB 总离屏硬预算约束；超预算旧缓存会在 rebuild 后 checked 释放。Native GPU Picture 成功提交到 GPU RT 并恢复 swapchain target 后也立即释放可重建 CPU staging，失败源仍保留到 typed retry。目标是继续压低剩余可控 CPU 中转与缓存保留量，逼近同体量 GPU-only 框架的内存水平。
- **更快**：降低每帧耗时。identity transform，且应用当前 offset 后仍位于 surface 内整数范围的普通 SrcOver 矩形 / 圆角填充，已在 full 或部分整数矩形 clip 下走 API-neutral Native IR 与 GPU SDF；当前 fill opacity 会在录制边界量化为可精确恢复 CPU premultiplied 8-bit 源的等价 straight Color；主帧与 Picture 内符合 identity、整数 offset / clip、SrcOver 的字形也会按 CPU 的 alpha-before-premultiply-before-coverage 顺序折叠当前 opacity，保留共享 coverage 后进入 batch IR，D3D11、D3D12 与 OpenGL 均复用有界 R8 atlas。透明底、整数 1:1 映射的完整或局部 source Picture 在可见写区互不覆盖，或每个实际重叠区均被 alpha=255 直角填充与圆角保守 SDF 全覆盖内区的一块或多块无缝并集完整覆盖时，会事务性拼入父 encoder；父画布当前整数 offset 会先固化到 destination，整数目标 clip 会同步裁 source / destination，因此平移容器与目标裁剪下的合格 Picture 也不扩大 scratch。常见直角 / 圆角面板以及相邻不透明分区 seam 上的透明度文字都能保留 glyph coverage `Arc` 并直达 atlas，裁剪仍逐命令保留圆角原始几何与 image source 子段。覆盖并集存在像素缺口的量化重叠、缩放、fractional source/destination/origin、目标相关 blend 或超过同尺寸 BGRA 内存预算时仍整图物化。当前瓶颈仍在 `ab_glyph` CPU 光栅化、其余需要保真组内合成的 Picture、non-identity transform、fractional clip / surface 几何、无法落到整数 surface 几何的 offset 圆角，以及 Picture 整体 / 其他 CPU 图元的 opacity 中转、阴影模糊和首帧 layout 尖峰。目标是稳定 60Hz。
- **更稳**：跨平台真机矩阵闭环。当前仅 Windows Vulkan/NVIDIA 验证；Wayland、macOS、AMD、Intel 均未覆盖。Agent 安全在 Linux/macOS 上缺异 uid 拒绝路径。
