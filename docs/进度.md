Windows「生产可用」至少同时满足（细节与证据 → [当前验证证据](#当前验证证据) · [证据矩阵](#平台与后端证据矩阵)）：

1. `cargo test --all-targets` 零失败；测试总数与结果只在[当前验证证据](#当前验证证据)维护。
2. Windows 图形与输入矩阵达到 production：已达成能力见[需求证据索引](#需求证据索引)与[证据矩阵](#平台与后端证据矩阵)；图形首先关闭 [P6.9](#p69-图形契约整改) 的 Critical/High 缺陷，再补微软拼音 GUI、`ITfTextEditSink` 属性路径、多 GPU/驱动矩阵、前台 capture，以及最小化→最大化实机复验。
3. 架构边界扫描无真实违规、无注释假阳性（[#171](决策.md#d171)）。
4. P0 生产阻塞归零；帧顺序、线程亲和、失败帧 dirty 保留、typed recovery、probe 诊断与 shutdown 均有自动化证据；EGL/Vulkan/DPI 等平台项另须适用平台真机证据。
5. 文档严格检查通过；公开示例与实现状态一致。

Linux/macOS/移动端 **不属于** Windows gate；不得用上层 `#[cfg]` 换取 Windows 通过。

**下一步（P6 · [#167](决策.md#d167)）**：先按 [P6.9](#p69-图形契约整改) 从 GFX-R0/R1/R2/R3 关闭 Critical 正确性与线程安全问题；其后复验 [BUG-20260712-003](问题.md#bug-20260712-003)，再补微软拼音 GUI、GPU/驱动矩阵与前台 capture。Metal `GpuNative` / D3D12 能力扩展不得早于图形契约闭合。改公开 API → [架构 · 术语与公开面](架构.md#术语与公开面)。
