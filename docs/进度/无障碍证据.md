## 现状

- 门禁：无障碍 **blocked / 0/110**——已有语义字段断言不能冒充逐项证据；schema、逐项文件、clean commit 和完整 110 映射尚未闭合。
- S4-03 目标：固化 schema（本文件）、收集器（Rust 真窗测试）、组装器（Python 脚本），并在 clean commit 上生成第一批逐项证据。
- 110 行口径：功能账本 4.4～8.6（104 行）+ 8.7～8.12（6 行历史缺口）。

## Schema

### manifest.json（顶层，`test-reports/<candidate>/accessibility/manifest.json`）

```jsonc
{
  "schema": "uix.accessibility.manifest.v1",
  "candidate": "0.0.1-<commit12>-<YYYYMMDD>",
  "declared": 110,
  "captured": 89,        // 有逐项 JSON 的证据行数
  "pending_scene": 15,   // 需 charts demo 场景的账本行数
  "ledger_gap": 6,       // 账本缺失行数（8.7～8.12）
  "entries": [
    {
      "item_id": "4.4",
      "batch": 4,
      "component": "Table",
      "case_id": "table",           // captured 时指向组件 QA case
      "evidence_file": "items/4.4.json", // captured 时存在
      "status": "captured"          // captured | pending-scene | ledger-gap
    }
  ]
}
```

### 逐项 JSON（`items/<item-id>.json`）

```jsonc
{
  "schema": "uix.accessibility.item.v1",
  "item_id": "6.8",
  "batch": 6,
  "component": "Pagination",
  "case_id": "pagination",
  "component_capture": "components/06-pagination.json",
  "role": "navigation",            // AccessibilityRole 名称
  "name": null,                    // accessible name（无则 null）
  "state": { "disabled": false, "checked": null, "expanded": null,
             "selected": null, "multiline": false, "password": false,
             "required": false },
  "value": { "value_text": null, "value_now": null, "value_min": null,
             "value_max": null, "checked": null, "selected": null,
             "expanded": null },
  "actions": ["focus"],            // 语义动作（invoke/focus/scroll/select/set_value/insert_text/…）
  "focus": { "focused": true, "focusable": true },
  "keyboard": { "actions": ["focus"], "multiline": false, "required": false },
  "declared_states": ["default", "active", "disabled-edge", "focus"]
}
```

### 组件证据（`components/<NN>-<case-id>.json`）

Rust 收集器输出，每组件一份：`schema: uix.accessibility.component.v1`，含 `case_index` / `case_id` / `component` / `declared_states` / `target`（投影）/ `focus`（focus 动作后的节点投影）。

### 状态语义

| status | 含义 | 是否计入证据 |
|---|---|---|
| `captured` | 组件 QA case 已捕获语义证据，逐项 JSON 存在 | ✅ |
| `pending-scene` | 账本行对应组件（advanced charts / Chart 通用）只在 charts demo 页面展示，S4-03 范围外 | ❌（不冒充） |
| `ledger-gap` | 8.7～8.12 历史行迁移时未保留，定义待主人确认 | ❌（不冒充） |

## 收集流程

1. **捕获**（真窗，AMD RX 5700 / 96 DPI / build 26100）：

   ```text
   cargo test --release --features 'agent-control,test-harness' --test agent_gui_windows \
     accessibility::real_demo_captures_component_semantic_evidence \
     -- --exact --ignored --nocapture --test-threads=1
   ```

   设置 `UIX_ACCESSIBILITY_EVIDENCE_DIR=<candidate>/accessibility`。测试遍历 92 个组件 QA case，对每个 case 提取 `component-qa-target` 节点的语义投影；声明 `focus` 状态的 case 额外执行 focus 动作并捕获聚焦后节点。

2. **组装**（110 行 manifest）：

   ```text
   python scripts/build_accessibility_manifest.py <candidate>
   ```

   解析功能账本 4.4～8.6 行，按组件名映射 case id，生成逐项 JSON 与 manifest.json；8.7～8.12 登记 `ledger-gap`。

3. **核验**：`manifest.json` 的 captured + pending_scene + ledger_gap = 110；每个 captured 行必须存在 `items/<id>.json`；条目按 item_id 升序。

## 边界

- 本证据只覆盖组件 QA demo 场景的语义快照字段；不覆盖 advanced charts（pending-scene）、无障碍键盘导航全程（tab 序列断言仍走现有 ignored GUI 测试）、以及账本缺口 8.7～8.12（待主人确认定义）。
- 逐项 JSON 的 `name` 为 null 是真实语义（组件无 accessible name），不是缺失证据。
- 完整 110/110 captured 依赖：① charts demo 场景收集器（后续 S4 批次）；② 8.7～8.12 账本补全（需主人提供定义或授权按现有 Skeleton API 划分）。
