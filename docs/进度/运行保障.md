## 当前结论

当前工作树已有 typed Error 核心与 `Diagnostics` 公开 API；native 和 draw 的旧类型已迁移。Diagnostics 首个 SMC 纵切已经落地：System 只编排自己的私有 Module，报告和恢复实现不再由公开入口直接持有。

系统仍未覆盖整个平台层，也不能标记完成：

- native / graphics / app 的旧日志调用已全部迁移为 `tracing::*`，旧 `core/log` 与 `core/diagnostic` 目录已删除。
- framework 没有实际登记或触发恢复 handler。
- Windows `wnd_proc` 的 DPI、尺寸/移动、IMM、custom chrome（含 DWM frame/圆角）和 ABI panic，以及 DWM frame pacer worker 的 `DwmFlush` / `PostMessageW` 失败，已改为只入队并在 App owner-thread 交给 Diagnostics；TSF composition/text-store callback 和生成 COM thunk panic 也已返回安全 HRESULT 并保留 typed cause。Wayland / macOS FFI callback 仍直接日志或丢失错误原因。wgpu uncaptured/device-lost 与 offscreen destroy void 失败已改为只入队，`WgpuContext` teardown 已通过 checked offscreen 销毁并在成功后关闭 source；其他图形后端的完整 teardown 仍未覆盖。
- CrashReport primitive 尚未实现，配置中的 crash directory 还没有消费者。
- native 平台 trait 的 bool / 空值/void 失败信号已全部清理完毕：`IClipboard` / `ICursor` / `ITimer` / `IFileDialog` / `IFileSystem` / `IDisplay` / `ISystemInfo` / `INotification` / `IConsole` 及 `SpecialDirProvider` 共 12 个接口全部返回 typed `Result`；`NotificationService` 已接入 `Diagnostics::report`。
- framework 已有真实恢复注册：App 组合根对 `Errc::GraphicsDeviceLost` 注册 handler，owner-thread 安全点（`drain_platform_pending_failures`）先 `attempt_recovery`，只有未处理 / 恢复失败的 Error 才最终 `report` 一次；恢复 handler 只通过共享 `RebuildRequest` 请求 `RecoveryDriver` 在下个帧边界执行既有有界恢复序列，领域算法仍归 graphics。
- 崩溃处理已实现：`App::run` 在配置加载前安装绑定 Diagnostics runtime 的 panic hook；配置 `crash_report_directory` 时把有界 `CrashReport` 原子写入（tmp + fsync + rename，冲突 replace，失败清理不残留伪完整报告），未配置时 hook 行为等同默认；hook 内递归 guard 防二次失败，且始终转发 previous hook——不吞 panic，unwind/abort 语义保持。

## 直接切换约束

- 不考虑兼容：`Diagnostics::report` / `attempt_recovery` 不自动执行恢复 handler，避免意外副作用。
- 扩展禁止：首版不引入 wildcard recovery、priority、async handler、cancel、auto-report 或 filter 等复杂机制。静态类型化是 UIX 的核心承诺。
- 仅 owner 报告：只有类型化的最终责任边界掉用 `diagnostics.report`；未被报告的 Error 携带 cause chain 继续上抛，不自动 fallback。
- 固定容量：使用固定容量循环缓冲，不引入动态淘汰策略。
- 不对内暴露 Diagnostics 给后端复杂跑批量报告。
- 区分 origin：应用调用 `report`，框架使用 `report_with_origin`。
- Callback 只入队：callback 不调用 subscriber、recovery handler 或用户代码；owner thread 才能取出 pending failure。

## 快速模型 S2-01 批次 1：native bool / 空值失败语义清理（六个 trait）

已完成。`IClipboard`、`ICursor`、`ITimer`、`IFileDialog`、`IFileSystem`、`IDisplay` 六个 crate-private trait 及 `SpecialDirProvider` 的全部 bool / 空字符串 / 空 Vec / 0 失败信号改为 typed `Result`：

- `IClipboard`：`text/set_text/has_text → Result`；Windows OpenClipboard/GetClipboardData/EmptyClipboard/SetClipboardData 失败转 `PlatformError`，Wayland 锁失败/无 serial 转 `InvalidState`。
