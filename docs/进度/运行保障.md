## 当前结论

当前工作树已有 typed Error 核心与 `Diagnostics` 公开 API；native 和 draw 的旧类型已迁移。Diagnostics 首个 SMC 纵切已经落地：System 只编排自己的私有 Module，报告和恢复实现不再由公开入口直接持有。

系统仍未覆盖整个平台层，也不能标记完成：

- native / graphics / app 大量旧日志调用尚未迁移。
- framework 没有实际登记或触发恢复 handler。
- Windows `wnd_proc` 的 DPI、尺寸/移动和 IMM 失败分支，以及 DWM frame pacer worker 的 `DwmFlush` / `PostMessageW` 失败，已改为只入队并在 App owner-thread 交给 Diagnostics；Windows custom chrome / TSF、Wayland / macOS FFI callback 仍直接日志或丢失错误原因。wgpu uncaptured/device-lost 与 offscreen destroy void 失败已改为只入队，完整 teardown 仍未覆盖。
- CrashReport primitive 尚未实现，配置中的 crash directory 还没有消费者。
- 旧 Collector、Logger、retry、middleware 等重复实现仍留在源码。

| 优先级 | 差距 | 完成条件 |
|---|---|---|

| P1 | 框架无实际恢复注册 | 至少一个真实可失败能力（如 device-lost）注册恢复 handler，并有契约证明 typed Error 可触发对应恢复逻辑 |
| P1 | 崩溃处理未实现 | CrashReport 序列化、panic hook 覆盖、crash dump 写入配置路径完成，并验证安全终止而非静默吞 panic |

## 直接切换约束

- 不考虑兼容：`Diagnostics::report` / `attempt_recovery` 不自动执行恢复 handler，避免意外副作用。
- 扩展禁止：首版不引入 wildcard recovery、priority、async handler、cancel、auto-report 或 filter 等复杂机制。静态类型化是 UIX 的核心承诺。
- 仅 owner 报告：只有类型化的最终责任边界掉用 `diagnostics.report`；未被报告的 Error 携带 cause chain 继续上抛，不自动 fallback。
- 固定容量：使用固定容量循环缓冲，不引入动态淘汰策略。
- 不对内暴露 Diagnostics 给后端复杂跑批量报告。
- 区分 origin：应用调用 `report`，框架使用 `report_with_origin`。
- Callback 只入队：callback 不调用 subscriber、recovery handler 或用户代码；owner thread 才能取出 pending failure。

## 接手实施顺序

1. 检查 typed Error 迁移现状，移走未完成依赖，补 CompileFail 阻断使用旧类型。
2. 保持当前 Diagnostics 公共核心，不扩展 wildcard、priority、async handler 或自动 report/recover，并重跑已有 8 项契约。
3. 已完成 wgpu device-lost / uncaptured / offscreen destroy void、Windows `wnd_proc` 核心失败分支和 DWM frame pacer worker 的统一 pending native failure queue 纵切；下一步进入完整 teardown，再接入 Windows custom chrome / TSF。
4. 将平台可失败接口改为 typed Result；owner 仍可返回时绝不提前报告。
5. 接通 framework recovery registration 与安全点 `attempt_recovery`；领域恢复算法留在 graphics / platform 自己。
6. 按 `platform → graphics → ui/data → app` 迁移旧日志到 tracing，消除 `error_fn(text)`。
7. 搬走唯一日期工具，删除旧 core log/diagnostic 全目录。
8. 最后实现 crash primitive、补齐最终边界和完整构建矩阵。

## 接手时禁止的捷径

- 不让 `Diagnostics::report` 自动执行恢复 handler。
- 不加独立 outcome 类型（与 typed Error 共存的不协调混合体）。
- 不通过放宽`系统列表`的依赖方向或废除架构划分来通过编译。
- 不增添非限定、递归、wildcard 或异步恢复注册。
- 不把完成判据与具体实现绑定——如果新设计能通过全部完成判据并保留 typed Error 核心，就可以替换。
