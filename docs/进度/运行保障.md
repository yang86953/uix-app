> 分类：运行保障

> 权威范围：运行保障核心、恢复登记、tracing 迁移、平台覆盖与崩溃路径的当前实现证据和活跃差距

目标机制见[架构 · 运行保障](../架构/运行保障.md)，当前公开写法见[使用 · 运行保障](../使用/运行保障.md)。

## 当前结论

运行保障核心已经部分落地，不再是“完全未实现”：

- runtime-scoped Diagnostics、bounded ErrorReportStore、App 注入、tracing report event 和精确 Errc 恢复登记已经有源码与公开测试。
- demo 已开始改用 tracing，旧 `core::diagnostic` / `core::log` 公开面已收缩为 crate-private。

系统仍未覆盖整个平台层，也不能标记完成：

- native / draw / app 大量旧日志调用尚未迁移。
- framework 没有实际登记或触发恢复 handler。
- FFI / GPU callback 仍直接日志或丢失错误原因。
- CrashReport primitive 尚未实现，配置中的 crash directory 还没有消费者。
- 旧 Collector、Logger、retry、middleware 等重复实现仍留在源码。

## 已落地事实

| 范围 | 当前实现 |

| 配置 | `DiagnosticsConfig` 已支持 report capacity、crash directory、backtrace policy；容量 0 规范化为 1，默认 256 / FatalOnly |
| Runtime 句柄 | `Diagnostics` 为 Arc-backed Clone 句柄；每实例有独立 runtime id、store、recovery registry 与 emergency 计数 |
| 报告 | `report(Error)` 与 crate-private `report_with_origin` 已实现；先 store、后在锁外发固定 target event |
| 有界投影 | 单报告 32 KiB、单段 2 KiB、16 层 cause、basename 位置、控制字符清理与 bounded backtrace 已实现 |
| 快照 | `ReportId`、`ErrorReport`、`DiagnosticsSnapshot`、total / evicted 与不可变升序快照已实现 |
| 输出隔离 | subscriber panic 隔离、report event 重入抑制和幂次限频 emergency stderr 已实现 |
| App 注入 | AppRuntime 默认持有 Diagnostics；`App::diagnostics(config)` 与 `AppHandle::diagnostics()` 已实现并共享同一实例 |
| 恢复登记 | `on_error(Errc, handler)`、`RecoveryAction`、`RecoveryOutcome`、RAII `RecoverySubscription` 已实现 |
| 恢复安全 | 精确 Errc、稳定注册顺序、锁外执行、首个 Recovered 停止、Failed 保留原 cause、handler panic 隔离与线程局部重入 guard 已实现 |

## 已取得的验证

本轮停止代码实施前已运行：

- `cargo test --test diagnostics_public_api --test app_public_api`
  - App 公共契约 3/3 通过。
  - Diagnostics 公共契约 8/8 通过。
- 已覆盖：无 subscriber 留存、容量淘汰、Fatal 不终止、清洗与 cause 深度、并发 ID、恢复顺序与 RAII、handler panic、固定 target 字段、report 重入、subscriber panic、普通 tracing error 不生成报告。

这些是公开图形枚举半迁移前取得的证据。随后 `cargo check --all-targets` 曾被旧文档中的 `GraphicsBackend::Auto` 示例阻断；本轮文档已改为“省略 builder 表示内部自动策略”。最新 `cargo test --test usage_markdown` 又在编译 library 时被新旧 GraphicsBackend 的 6 处类型不匹配阻断，尚未进入 Markdown 示例。因此既有 Diagnostics 通过记录属于本轮早期证据，接手模型修复 P0 编译断层后必须重新验证。

## 活跃差距

| 优先级 | 差距 | 完成条件 |
|---|---|---|
| P0 | 当前工作树无法编译 | 先按[原生平台层进度](原生平台层.md#已知阻塞与未完成项)收口公开/私有 GraphicsBackend 边界，再重跑 Diagnostics 与文档契约 |
| P0 | 平台 callback 未覆盖 | 统一 PendingNativeFailureQueue；Win32 / ObjC / Wayland / GPU callback 只投递，owner thread 才执行领域恢复、`attempt_recovery`、返回或 report |
| P0 | wgpu device-lost 原因丢失 | callback 保存 bounded reason / resource origin，`ensure_active` 返回含 source 的 `GraphicsDeviceLost`，恢复耗尽后只报告一次 |
| P0 | framework 无恢复调用点 | runtime bootstrap 可登记框架 handler；平台 / graphics owner 在明确安全点调用 `attempt_recovery`；成功不报告，失败仍可传播 |
| P0 | 旧 Error → 文本日志降格 | 删除 `error_fn(text)` 制造 `Errc::Unknown` 的路径；可返回处保留 typed Error，最终消费处使用 runtime Diagnostics |
| P0 | 旧日志轮子仍存在 | 全框架调用迁移到 tracing 后，直接删除 `core::log`、Collector / Logger / Sink 与桥接代码，不保留双写 |
| P0 | 旧通用恢复轮子仍存在 | 删除 diagnostic 下 retry、middleware、circuit breaker、旧 recovery；图形等领域恢复保留在所属模块 |
| P1 | CrashReport 未实现 | 一次性 crash ticket、有界唯一文件、stderr fallback、已有 ReportId 复用、健康期预缓存摘要、绝不调用 tracing / 用户 callback |
| P1 | crash directory 仅配置未消费 | App 默认目录与独立 Diagnostics fallback 按使用契约实现；写入失败可观测且不递归 |
| P1 | origin 尚未贯穿 | native / graphics / worker 的静态 operation 和 opaque resource 进入 report；公开用户 report 继续使用 application origin |
| P1 | 其他最终边界未覆盖 | 用户 callback、joinable / detached worker、event loop、frame、teardown 和 App 顶层各有唯一责任点 |
| P1 | 公共 denylist 不完整 | Logger、Collector、old retry/recovery、普通错误订阅、crash writer 和 native callback 设施均不可达 |
| P1 | 全矩阵未复验 | fmt、lib、all-targets、all-features、文档示例和跨 target 约定矩阵重新通过 |

## 旧轮子删除前的唯一搬迁项

旧 `core::diagnostic::timestamp::days_to_date` 仍被 DatePicker 使用。它是通用日期换算，不属于运行保障；删除旧目录前必须移到现有日期 / 时间基础模块，并让 DatePicker 改用该唯一实现。

除此之外，Collector、ScopedCollector、Logger、Level、Sink、LogHandler、fatal helper、retry、middleware、circuit breaker 和旧 recovery 都不应保留或搬成新名字。

## 接手实施顺序

1. 先修复当前公开/私有 GraphicsBackend 编译断层，重新建立可验证基线。
2. 保持当前 Diagnostics 公共核心，不扩展 wildcard、priority、async handler 或自动 report/recover，并重跑已有 8 项契约。
3. 实现统一 pending native failure queue，并从 wgpu device-lost 与 Windows callback 开始贯通 owner-thread 链。
4. 将平台可失败接口改为 typed Result；owner 仍可返回时绝不提前报告。
5. 接通 framework recovery registration 与安全点 `attempt_recovery`；领域恢复算法留在 graphics / platform 自己。
6. 按 `native → draw → ui/data → app` 迁移旧日志到 tracing，消除 `error_fn(text)`。
7. 搬走唯一日期工具，删除旧 core log/diagnostic 全目录和旧公开测试。
8. 最后实现 crash primitive、补齐最终边界和完整构建 / 测试矩阵。

## 接手时禁止的捷径

- 不让 `Diagnostics::report` 自动执行恢复 handler。
- 不在 FFI / OS / GPU callback、Drop 或持有 native lock 时执行用户 handler或 subscriber。
- 不为“兼容”保留旧 Logger / Collector 并桥接 tracing。
- 不把 retry、退避、熔断、GPU 重建或业务补偿实现塞进 Diagnostics。
- 不把公开 API 返回的 Error 提前写入 ErrorReport。
- 不为每个平台再造各自的 pending queue、origin 或错误 store。

## 完成判据

- 维稳：ABI unwind、callback queue、owner thread、worker、teardown、重入和容量全部有界。
- 纠错：框架和用户可按精确 Errc 登记；安全点显式尝试；顺序、RAII、panic、Failed cause 与重入语义稳定。
- 记录：框架与用户共用 tracing；最终未恢复 Error 只形成一个 ErrorReport；顶层 crash 不调用 tracing。
- 平台：所有 P0 Windows / Wayland / macOS / wgpu callback 只投递，owner 才恢复、返回或报告。
- 删除：公开与内部均不存在旧 Logger、Sink、Collector、diagnostic retry/middleware/recovery 双轨。
- 证据：公开 allowlist / denylist、并发、容量、隐私、callback、device-lost、worker、Fatal、CrashReport 和 target matrix 全部通过。
