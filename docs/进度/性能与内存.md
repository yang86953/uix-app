## 性能

### 测试时长策略

- 日常诊断、晚到帧归因和回归验证的长测默认上限为 **30 分钟**，用于快速收集 raw log、frame、memory 和场景 loop 证据。
- 正式发布 G5 soak 仍保留 8 小时门禁，但只有在主人明确要求发布验收时执行；8 小时历史记录与失败边界不因默认 30 分钟策略改写。
- 30 分钟结果可作为诊断/回归证据，不能直接标记为正式 8 小时 G5 gate 通过。

  - 全屏 overlay 动画可对保留色缓冲做 GPU 纹理快照/恢复（无 CPU readback），只重放浮层

## 内存
- **已做**：
  - 字形缓存由 8192 项 / 32 MiB 收敛为 **2048 项 / 8 MiB**，并由任意 HashMap 淘汰改为 LRU 逐项淘汰
  - 字体卸载定向释放所属 coverage / outline，不等待全局清缓存
  - LayerTree 构建通过所有权转移消除 DisplayList 双 clone，DisplayList 的完整操作序列以 COW `Arc<Vec<PaintOp>>` 共享
  - 普通 clone 不复制 glyph / line 缓冲
  - Label 与 Input 直接移交只绘制一次的新布局，避免 recorder 再 clone
  - Picture 在固定最低资格之上按预计重绘像素 / BGRA 保留字节全局排序，每棵 LayerTree 最多保留 **32 MiB** 离屏
  - 同收益优先高总收益与既有句柄，场景变化后超预算旧缓存降级并进入 checked orphan sweep
  - Native GPU Picture 的 checked flush 与 swapchain restore 均成功后立即释放已上传 GPU RT 的 CPU soft staging
  - 失败的未提交命令 / soft source 保留到 retry
  - ImageService、CPU Picture pool 与 Native GPU offscreen 槽均会回收连续尾部空槽
  - API-neutral recorder 不持有完整 CPU 主表面，主画布 scratch 初始 / resize / shutdown 为 1×1，首次 CPU draw 才扩大
  - recorder Picture 也改为每槽 1×1 scratch 加一份 committed encoder / image
  - IR 的 command、image、coverage 保留量不超过同尺寸 BGRA，超限在发布前物化且不与 IR 双持
  - destroy 释放 coverage `Arc`
  - 1920×1080 recorder resize 不再分配未使用的 CPU 主表面，减少约 **7.91 MiB**
- **已做（运行时短命分配）**：
  - AppState drain、布局收敛与禁用日志的临时容器/字符串改为原位路由、峰值容量复用或完全不物化
  - 注销节点的排队语义事件随快照一起释放，不再无期限占用共享队列
- **已做（字体常驻，2026-08-01 内存批次）**：
  - 系统字体（含 CJK 回退 msyh.ttc ~19 MiB）由整文件 `fs::read` 改为**内存映射惰性分页**（memmap2 + `FontRef` 借用槽位，见 `ab_glyph.rs` FontSlot 契约）：未触达字形页不驻留 working set
  - 实测（AMD RX 5700 / 96 DPI / build 26100、release、1200×800、12s 稳定）：空窗口 working set 124.1→116.2 MiB（**-7.9 MiB**）、private 129.5→114.1（**-15.4 MiB**）；默认首页 134.9→127.1 MiB
  - 字体加载零复制：`load_font_owned`（后端直接消费 `fs::read` 的 Vec），消除整份字体二次复制-释放周期
  - 剖析工具：demo `--empty` 空窗口基线模式、`UIX_SKIP_CJK_FONT=1` 开关（量化 CJK 字体贡献）、`scripts/mem_probe.py`（working set/private 采样探针）
  - 归因结论：空窗口 116 MiB ≈ 驱动/运行时映射大头 + GPU 常驻 ~30 MiB（swapchain 双缓冲 16.6 + retained color 8.3 + R8/RGBA atlas 5）+ 字体映射触达页 ~10；Vulkan 驱动映射与 D3D12 的 ~30 MiB 差距属后端选择（见交付方向）
- **瓶颈**：
  - 主 swapchain canvas 为避免连续 soft 帧分配抖动，仍保留两次 soft-free present / 250ms 的安全 grace
  - 未提交失败源不参与清理

## 图形中转
- **已做**：
  - UI 与 Demo 的生产绘制已统一到可录制 `PaintContext`：点、线、锐角 / 圆角矩形、圆 / 椭圆 / 扇形、多边形 / 折线与任意路径均通过公开 API 规范化为 canonical `PaintOp`
  - 位移、混合与透明度状态同序录制 / 重放，表面尺寸与可见性查询不打断录制
  - 架构边界递归拒绝 raw `Canvas2D`、可写像素和 renderer/backend 旁路
  - 普通 SrcOver 矩形 / 圆角填充的整数 identity 几何与整数 clip 已走 Native IR，fill opacity 会反解为可精确恢复 CPU premultiplied 8-bit 源的 straight Color
  - D3D11 / D3D12 / OpenGL solid shader 以 premultiplied SrcOver 提交
  - 主帧与 Picture 内合格字形把 opacity 按 CPU 同序量化到 straight alpha 后，以共享 `Arc<[u8]>` 进入 `BlitGlyphs` 与有界 R8 atlas；零 alpha 直接 no-op
  - 轴对齐等比 SrcOver 圆扇区以 `GpuSector` 进入统一 RHI `SECTOR` pipeline，径向 / 角向 signed distance 直接生成抗锯齿 coverage；mixed-DPI 下保留物理椭圆外接盒
  - Pie 等连续扇区不再由三角网格边缘叠出深色分隔线，其他变换或 capability 缺失时保留既有回退
  - 透明底、完整或局部 source、整数 1:1 destination 的 Picture 在写区互不覆盖，或每个实际重叠区被 alpha=255 直角填充 / 不透明圆角填充保守 SDF 全覆盖内区的一块或多块无缝并集完整覆盖时会原子拼入父 encoder
  - 父画布当前整数 offset 会先固化到 destination，整数目标 clip 会同步裁 source / destination
  - 平移容器与目标裁剪下也保留 glyph coverage `Arc`、圆角原始几何及 image source 子段
  - 缓存 DisplayList 和新绘 Picture 均不扩大 scratch、不产生 FrameEncoder soft tile
  - opaque-backed planner 覆盖非对称半径、clipped inner intersection、角部回退、四象限 cover union 与单像素缺口回退
  - D3D11 WARP、D3D12 WARP、Windows WGL 的圆角加 tiled-union、opacity-glyph Picture producer 真实读回逐通道误差不超过 1，fake executor 明确验证量化 alpha 与零 soft tile
  - 直接 `CpuSegment` / `PictureBlit` 也会计入 soft-upload diagnostics，并只在可见目标 tile 内参考光栅化，不再分配或扫描透明整帧中间表面
  - 父画布 opacity 非 1 的有限整数 Picture 映射会保留组后语义：hybrid 以携带 `FrameOpacity` 的单个 `PictureBlit` 逐通道量化 soft 上传；严格 GPU（wgpu）以 `draw_image_blits` 纹理四边形 + shader opacity 提交，主 scratch 不扩容且零 opacity 直接 no-op
  - 普通 `blit_image` 的整数 1:1 映射同样只保留可见 source crop 与当前 `FrameOpacity`
  - 缩放或 fractional 映射在 FrameEncoder / hybrid soft 路径保留精确 CPU fallback
  - 严格 GPU（wgpu）路径对整数源 crop 的 1:1 与缩放目标走 `draw_image_blits` 纹理四边形（目标位置可亚像素），不再 typed 失败
  - Picture 重绘失败保留旧 committed；resize 先创建 replacement，失败不先销毁旧缓存
  - wgpu `offscreen_targets` 与 `clear_rects` 已启用：Picture 可创建 GPU RT；脏区以 replace-blend 透明四边形清除
  - `blit_offscreen_target` 转发父画布 opacity
  - 主路径保留色缓冲 + `retained_framebuffer` 解锁绘制侧 partial redraw，present 仍 FullOnly 全幅 blit
  - 轴对齐 scale/translate 的矩形 / 描边 / 线性渐变 / 均匀径向 / 轴对齐盒阴影（含各向异性 blur_x/blur_y），旋转 / 剪切盒阴影经仿射设备四角 + 逻辑 SDF，任意仿射路径网格与直角矩形 mesh，以及对角线线段 stroke mesh，已在严格 GPU canvas 入队共享 wgpu pipeline
  - 共享 wgpu 可分离高斯模糊（水平→垂直；大半径 2× 降采样）经 `blur_offscreen_target` 作用于 Picture RT；`sigma = radius / 3` 与 CPU 一致
  - Picture splice 在 1:1 不透明 `CpuSegment` / `PictureBlit`（组 opacity=1 且源像素全 alpha=255）上亦可证明重叠 cover
  - Picture 采样目标：`FrameSampledRect` 允许亚像素落点与非 1:1 缩放；整数源 crop + GPU `draw_image_blits`，不再因 fractional destination 扩主 scratch
  - 目标相关 Additive 写区在互不覆盖（或被不透明 cover 完整覆盖）时可参与 Picture splice 平移
  - Additive 父 blend 下的采样 Picture / image blit 走 One+One 纹理 pipeline，不再 typed 失败或 SrcOver 冒充
  - 轴对齐各向异性圆角 / 描边以几何平均半径进入共享 SDF
  - 轴对齐缩放与旋转 / 剪切字形复用 R8 / MSDF atlas 纹理四边形（仿射 corners）
  - 字形直达 atlas coverage：`OutlinedGlyph::draw` / `ab_glyph_rasterizer` 为物理 1:1 且 DPR≈1 生成真实像素面积 coverage → R8 atlas + `glyph_fs`
  - 轮廓同时展平为边列表，缩放 / 仿射 / 高 DPR 走共享 wgpu `glyph_cover` MSDF pass（Chlumsky 角点边着色 → CMY 双通道，`0.5+sd/MSDF_RANGE`）写入 RGBA8
  - 采样 `median` + UV `screenPxRange`；MSDF 槽位 fringe ≥ `MSDF_RANGE+1`
  - 像素中心距离场不再作为 1:1 coverage
  - tofu / 展平失败仍回退字体面积 coverage → R8；soft 默认路径优先复用同一面积 coverage
  - `RenderTarget::try_blur_offscreen` / `scene::blur_picture_region` 接通 GPU RT 与 CPU `gaussian_blur`，供毛玻璃消费方在 blit 前调用
- **瓶颈**：
  - 窄 present / TrackedSwapchain：见上文「窄 present 暂缓」——wgpu 公开面缺 image identity 与 present damage
  - OpenGL EGL 仍缺 Wayland 真机像素证据——见[架构§图形](../架构/graphics/renderer.md#模块不变量)
  - MSDF 已落地 generate（真边着色）→RGBA atlas→median sample；真机大字号缩放视觉矩阵仍可再升

## 基础几何填充
- **已做**：
  - `draw_point` 复用圆形填充
  - `fill_rounded_rect` 复用带 `Radius` 的矩形
  - `fill_polygon` 复用共享路径
  - 每个便捷调用只录制一个 canonical op
  - identity / SrcOver 下，应用 offset 后外接正方形为 surface 内整数矩形且 clip 为整数矩形的 `fill_circle`，以等价均匀圆角正方形复用现有 `FillRoundedRect` / `FillRoundedRectClipped` 与 GPU SDF
  - 椭圆、扇形与任意多边形 / 路径进入同一严格 wgpu shape / mesh 提交序列
  - 当前 opacity 保持 CPU premultiplied 量化顺序，主 scratch 保持 1×1
- **瓶颈**：
  - 圆与圆角矩形的专用整数 IR 资格仍窄于共享 mesh 路径
  - fractional / transformed / 非 SrcOver 情况可能失去该 fast path，但不允许在生产 GPU 帧内退回 CPU framebuffer / PixelUpload
  - 严格 GPU 无法精确执行的状态必须 typed 失败并进入整机恢复，不得旁路公开绘图 API

## 矩形与圆形描边
- **已做**：
  - identity / SrcOver 下，应用 offset 后矩形为 surface 内整数几何、clip 为整数矩形、宽度有限正值且圆角合法的 `stroke_rect` 已保留为 `StrokeRoundedRects` IR，并按 CPU premultiplied 顺序折叠 opacity
  - 外接正方形为同类整数几何的 `stroke_circle` 精确改写为四角半径等于圆半径的同一 IR，逐像素保持 CPU parity 且 recorder scratch 保持 1×1
  - 同 clip 且保守可见 bounds 不相交的相邻描边受 2048 项、1M 像素与 4× 稀疏 union 上限约束后合批
  - D3D11 以一个既有 `GpuStrokeRect` batch 提交
  - 无 `stroke_rects` capability 的后端仅光栅化并上传 batch 与 clip 的可见紧凑 tile，两者都不扩大 recorder scratch
- **瓶颈**：
  - 相交描边为保持 8-bit SrcOver 顺序而不合批
  - Picture 安全拼接暂不接受描边写区
  - `StrokeRoundedRects` 专用 IR 不承载折线、多边形或椭圆描边；这些公开 API 规范化为共享 `StrokePath` 并走通用 wgpu mesh，属于 fast-path 差异而非绘制能力或公开入口缺口
