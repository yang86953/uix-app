## 演进清单

### E-01 类型化表单模型 `Form::model`

- **状态**：✅ 已完成（提交 `6db47be`，2026-08-01）。
- **目标形态**：`Form::model(&State<M>)` 双向绑定业务模型，`.field(name, accessor, item)` 声明字段，`.on_submit_typed(|m: M| ...)` 提交即得类型化结果。
- **来源**：[输入与表单](<file:///C:/data/note/我的项目/软件/UIX App/使用/输入与表单.md#理想使用方式>) 目标写法。
- **当前差距**：`FormBuilder` / `FormModel` 已有字符串字段校验模型（`field(name, label)`、`required`、`validate_*`、`Values` 结果），但无业务结构体双向绑定与类型化提交。
- **完成条件**：`Form::model` 绑定 `State<M>`；字段 accessor 投影；`on_submit_typed` 输出 `M`；校验失败不覆盖新输入；示例升级为 rust fence。
- **落地记录**：`Form::model(&State<M>)` 返回 `ModelFormBuilder`（`.field` / `.on_submit_typed` / `.label_width` / `.gap` / `.layout` / `.build`）；`ModelForm<M>` 句柄提供 `view()`（字段区域 View）、`submit()`（校验并组装 `M`，不写回）、`submit_typed()`（写回 `State<M>` 并触发回调，`Err(String)` 上抛）、`reset()`、`model()`；`FormInputItem` / `FormInputNumberItem<T>` / `FormSelectItem<T>` 支持裸配置 `new(name)` + `required(bool)`，由 `FormItemSpec<F>` 契约绑定；`InputNumber` 增加配置克隆（formatter / value_binding 在构建时重建）。API 形态与目标写法的差异：`build()` 返回应用侧句柄而非直接可 embed 的 View（提交需应用侧按钮触发，与 `FormModel` 模式一致），`FormSelectItem::multi` 尚未实现（多选字段后续批次）。行为契约测试 `tests/form_typed_model.rs` 6 项全过；示例已升级为 `rust uix-compile=form-model`（[输入与表单](<file:///C:/data/note/我的项目/软件/UIX App/使用/输入与表单.md#理想使用方式>)）。

### E-02 类型化表格列渲染与声明式虚拟化

- **状态**：✅ 已完成（提交 `9324633`，2026-08-01）。
- **目标形态**：`Table::data(rows, key)` 的列支持任意 View 渲染（已落地 `TableColumn::bind` + `render`），并增加声明式 `.virtualized(true)` 开关。
- **来源**：[数据展示](<file:///C:/data/note/我的项目/软件/UIX App/使用/数据展示.md#理想使用方式>) 目标写法。
- **当前差距**：`Table::data` + `TableColumn::bind` 已落地（列文本投影）；`render` 已支持任意 View；`.virtualized(true)` 声明式开关不存在（虚拟化由 Table 内部策略决定）。
- **完成条件**：`.virtualized(true/false)` 作为公开配置；大行数默认或显式虚拟化路径有行为证据；示例升级为 rust fence。
- **落地记录**：`DataTable<R>` / `Table` / `TableBuilder` 三处新增 `virtualized(bool)` 声明式开关（等价既有 `virtual_scroll`）；行为证据：1000 行 + 32px 行高 + 320px 视口下 `virtualized(true)` 只物化可视区与 overscan（≤30 行）且行身份保留全量，`virtualized(false)` 全量物化（单元测试 3 项，table.rs `tests` 模块）。`TableColumn::bind` + `render` 任意 View 渲染为既有能力，本项补充开关与证据。示例已升级为 `rust uix-compile=data-table-virtualized`（[数据展示](<file:///C:/data/note/我的项目/软件/UIX App/使用/数据展示.md#理想使用方式>)）。

### E-03 受控浮层 Builder（Modal/Drawer）

- **状态**：✅ 已完成（提交 `3da37a3`，2026-08-01）。
- **目标形态**：`Modal::builder().open(&State<bool>).on_open_change(...)` 受控开关；`closable(false)` 在保存中等场景禁用外部关闭但保留 Escape。
- **来源**：[反馈](<file:///C:/data/note/我的项目/软件/UIX App/使用/反馈.md#理想使用方式>) 目标写法。
- **当前差距**：`Modal::show` / `confirm` / `info` / `warning` / `error` 与 `ModalBuilder`（`closable`、`destroy_on_close`）已落地；无受控 `open(&State)` 与 `on_open_change` 回调。
- **完成条件**：受控 open 绑定 State；`on_open_change` 在用户侧关闭时回调；与 `ModalContext::close` 共存不冲突；示例升级为 rust fence。
- **落地记录**：`Modal::builder()` 受控入口 + `ModalBuilder::open(&State<bool>)`（初始值同步首帧呈现）+ `on_open_change(Fn(bool))`（用户侧关闭与公开 `open`/`close` 时触发）+ `content(FnOnce -> View)`；组件新增 `ControlledOpen` 受控绑定：每帧 `controlled_sync` 跟随外部 State（`set(true)` 下一帧打开，`set(false)` 走离场动画），用户侧关闭（mask / close 按钮 / Escape / 公开 `close()`）写回 State 并触发回调，写回后下一帧同步无环；`closable(false)` 保留 Escape 行为不变；`show` / `ModalContext::close` 机制原样保留，与受控模式共存。Drawer 为直接组件形态（无 builder），目标写法未涉及，不在本项范围。行为契约测试 modal.rs 单元测试 5 项全过；示例已升级为 `rust uix-compile=feedback-controlled-modal`（[反馈](<file:///C:/data/note/我的项目/软件/UIX App/使用/反馈.md#理想使用方式>)）。

- **完成条件**：门面可解析当前窗口的反馈管理器；在事件回调、定时器与 CLI 上下文行为明确；示例升级为 rust fence。
- **落地记录**：新增 `feedback/facade.rs` 进程级注册表（静态 RwLock）：`Message::new()` / `Notification::new()` 构造自动注册为当前反馈目标（逐窗隔离：每窗口一个组件实例，最近挂载生效），`ui::register_feedback(message, notification)` / `register_message` / `register_notification` 显式覆盖，`unregister_feedback` 窗口销毁清理；门面 `ui::message()`（`success` / `info` / `warning` / `error` / `add` / `is_available`）与 `ui::notify()`（同名四方法 + `is_available`）未注册时 no-op 返回 0、不 panic；prelude 导出 `message` / `notify` / `MessageFacade` / `NotificationFacade`。行为契约测试 `tests/feedback_facade.rs` 4 项全过；示例已升级为 `rust uix-compile=feedback-facade`（[反馈](<file:///C:/data/note/我的项目/软件/UIX App/使用/反馈.md#理想使用方式>)）。

### E-05 组件声明式无障碍动作 `semantic_actions`

- **状态**：✅ 已完成（提交 `e29b7ed`，2026-08-01）。
- **目标形态**：`component!` 内 `semantic_actions => [SemanticAction::Adjust { min, max }]` 声明自定义组件的无障碍动作。
- **来源**：[事件](<file:///C:/data/note/我的项目/软件/UIX App/使用/事件.md#理想使用方式>) 目标写法。

- **完成条件**：`component!` 支持 `semantic_actions`；`Adjust` 或等价连续值动作进入语义快照；动作经窗口 owner thread 安全路由；示例升级为 rust fence。
- **落地记录**：`component!` 新增 `semantic_actions => [...]` 槽位（前置分支转换为合成方法 `__semantic_actions_decl` 后递归展开；槽位须位于 `@new` 之后、其他方法之前），生成 `WidgetComponent::declared_semantic_actions()`；`SemanticActionKind::Adjust` + `SemanticAction::Adjust { min, max }` 进入动作枚举（as_str `adjust`）；`supported_semantic_actions` 合并组件声明与 role 推断（Slider / SpinButton 同时获得 `Adjust`）；`Adjust` 执行 = 聚焦目标并 Handled，方向性步进由 `Increment` / `Decrement` 驱动；`SemanticAction` / `SemanticActionKind` 公开导出并进 prelude。动作经窗口 owner thread 的既有 automation 执行器路由（`perform_semantic_action`）。行为契约测试 `tests/semantic_actions.rs` 4 项全过；示例已升级为 `rust uix-compile=event-semantic-actions`（[事件](<file:///C:/data/note/我的项目/软件/UIX App/使用/事件.md#理想使用方式>)）。

- **落地记录**：`App::register` / `Container::register` 批量注册聚合服务对象（应用自定义 `AppServices` 结构体整体注册为单例，组件经 `resolve` 取用，与 `singleton` 共存）；新增 `src/ui/i18n.rs` 进程级资源表：`register_translations`（增量合并、同 key 覆盖）/ `set_translations`（整体替换、语言切换）/ `t_lookup`（未命中返回 key 原文，容错不 panic）/ `t_lookup_fmt`（`{0}` 占位格式化，返回 `String` 只影响显示不改变业务值）；`t!` 宏（`#[macro_export]`，支持带参版本）与翻译函数经 prelude 导出。`t!` 资源表与 `Locale` 结构体并存：Locale 承载内置组件文案，资源表承载应用自定义文案。行为契约测试 `tests/services_i18n.rs` 5 项全过；示例已升级为 `rust uix-compile=framework-services-i18n`（[框架能力](<file:///C:/data/note/我的项目/软件/UIX App/使用/框架能力.md#理想使用方式>)）。
