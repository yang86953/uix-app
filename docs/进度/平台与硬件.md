## 0.0.1 Windows 矩阵边界

发布验收拆成三个独立矩阵，不默认做“全部组件 × 全部 DPI × 三厂商 × 所有 backend”的笛卡尔积：

1. **组件视觉矩阵**：冻结提交生成的最终公开库存 × 全部适用状态；每项至少有浅色桌面、深色紧凑和适用交互状态，按[测试说明](../使用/测试.md#逐组件视觉验收)执行。
2. **窗口 / DPI 矩阵**：Windows 主路径分别覆盖 100% / 150% / 200% DPI，以及 resize、最大化 / 还原、最小化恢复、遮挡、多窗、主题切换与 DeviceLost；不把每个窗口场景乘到每个组件。
3. **硬件 / backend 矩阵**：NVIDIA、AMD、Intel 各自执行 `Auto` 启动、交互、resize、连续 present 与恢复冒烟；release feature 实际包含的强制 backend 另做显式路径验证，Software 整体回退单列。除非 G0 另行冻结，不要求每个厂商执行每个强制 backend。

G0 已冻结最低 Windows 11 24H2 x64（build 26100），release 只含默认 `vulkan` feature，生产 `Auto` 的候选路径为 Vulkan → Software 整体回退。D3D11、D3D12、OpenGL / OpenGLES 与 Metal 均不进入 `0.0.1` 交付构建；因此 G4 的显式 backend 路径只验收 Vulkan 与 Software，但三厂商 `Auto` 冒烟仍不可缩减。
