[← 返回进度 索引](../进度.md)

> 分类：运行诊断
> 权威范围：当前实现证据、活跃差距与验收状态

## 当前结论

[架构目标](../架构/运行诊断.md)和[公开用法](../使用/诊断.md)已经确定；本轮没有修改源码。当前生产实现仍是 typed `Error`、`Collector`、`LogHandler` / `Logger` 三条并行通道，不能标记为统一 Diagnostics。

## 当前实现证据

| 方面 | 当前事实 | 活跃差距 |
|---|---|---|
| 失败模型 | [`Error`](../../src/core/error/types.rs) 保留 `Errc`、消息、严重度、位置与 `Option<Box<Error>>` source | 继续作为唯一失败值；报告时还没有生成有界、脱敏 ErrorReport |
| 收集 | [`Collector`](../../src/core/diagnostic/collector.rs) 是全局单例；生产 `src` 在 core 之外没有直接调用 | 尚无 runtime-scoped `Diagnostics`、`ReportId`、`ErrorReport` 与不可变快照 |
| 日志 | [`core::log`](../../src/core/log/mod.rs) 有全局 `LogHandler`，[`Logger`](../../src/core/log/logger.rs) 又维护独立 singleton 与 Sink | 尚未迁移到 tracing；第二套 Logger / Level / Sink 仍公开 |
| typed 完整性 | `error_fn(text)` 会新建 `Errc::Unknown`；日志级别过滤还能阻止该收集 | 尚未实现“先留存 typed 快照、再发一个固定 target event” |
| 初始化 | `Logger::instance()` 才尝试安装高级 handler，调用顺序决定哪套 handler 生效；失败静默 | 尚未改成 App 默认 Diagnostics + 宿主独立安装 subscriber |
| Fatal / panic | [`install_fatal_handler`](../../src/core/diagnostic/fatal.rs) 没有生产安装点；`Collector::collect(Fatal)` 已 dump + abort，hook/helper 后续存在重复和不可达路径 | 尚未拆开普通 report 与不调用 tracing 的内部 crash primitive |
| 输出线程 | Sink 与 Collector callback 在产生日志线程同步执行，可能阻塞 GUI、wgpu callback 或 FFI 路径 | 尚未删除同步 callback；FFI/GPU 故障也未统一投递到 owner thread |
| 崩溃文件 | 固定覆盖当前目录 `uix_crash.log`，错误大多忽略，报告上下文有限 | 尚无配置目录、唯一文件名、大小上限、预缓存系统摘要和 emergency fallback |
| 恢复 | middleware、通用 recovery、circuit breaker 与图形域恢复职责重叠，部分使用阻塞 sleep | 尚未从诊断系统移除 |
| worker / FFI | Win32 / ObjC callback、detached worker 等没有统一 panic 汇聚 | 尚未明确 join owner、detached wrapper 和 owner-thread 报告点 |
| 测试 | 现有公开测试锁定 Collector bridge、retry 和 middleware，缺少 fatal、并发、FFI 与图形 typed 报告证据 | 尚未按目标公开面重建证据 |

图形路径已有典型断点：wgpu device callback 先把 reason 写成字符串日志，后续设备失效状态只保留布尔值；最终 `GraphicsDeviceLost` 与原 reason 没有稳定关联。目标实现需在 callback 保存有界 owned 原因并投递给 graphics owner；若恢复失败且本层最终消费 Error，再报告一次。

## 建议实施顺序

后续实现直接替换，不保留两套公开兼容层：

1. 实现有界 ErrorReportStore、runtime `Diagnostics`、ReportId、快照和 App 注入；
2. 引入 tracing，先统一 target / 字段，再迁移框架日志调用点；
3. 接通 API、用户回调、joinable/detached worker、FFI、GPU、event loop 与 frame 的唯一最终报告点，并保留内部 typed origin；
4. 实现不调用 tracing 的 crash primitive、唯一文件名、预缓存摘要和有界同步 emergency 输出；
5. 删除旧 fatal 重复路径、Collector、Logger/Sink SPI 与诊断目录内的 retry/middleware/recovery；
6. 收缩公开导出并重建分层测试。

不要先把 tracing 桥接到旧 Logger，也不要让 Collector 订阅 tracing；这会制造第四条临时数据流。

## 完成判据

- 用户和框架日志进入同一个宿主 subscriber；没有 subscriber 时 ErrorReport 仍留存。
- 用户可从 AppHandle 取得 Diagnostics、报告 Error、读取有界快照。
- 一次非重入普通 report 对应一个 ID、一个 ErrorReport 和一条固定 target event；重入 report 留存但抑制递归 event，普通 `error!` 不创建报告。
- crash 路径不调用 tracing，已有 ReportId 时不重复留存。
- ErrorReport 不暴露原始 Error 文本；清洗、截断、cause 深度和总字节预算有边界测试。
- 并发报告身份唯一，total / retained / evicted 与容量淘汰一致。
- FFI/GPU callback 只投递；joinable worker 只由 join owner、detached worker 只由入口 wrapper 报告。
- GPU/FFI 的 typed origin 能在 owner-thread 报告后保留 operation 与 opaque resource 身份。
- Fatal 的普通报告不终止；runtime crash primitive 对同一 ticket 只执行一次。
- CrashReport 只做有界同步文件/stderr 输出，不调用普通 sink、网络、用户 Layer 或 callback。
- `panic=abort` 与 native fault 明确不在首版保证范围。
- 公开 API 中不存在 Logger、Sink、Collector、Diagnostics Layer、同步订阅或通用 retry。
