## 权威范围

框架核心功能已收敛，当前聚焦三个交付方向——缩小运行内存与使用方构建成本、降低每帧耗时至稳定 60Hz、四平台同等视觉矩阵。

**活跃阻塞**：D3D11 与 OpenGL ES 仍通过逐 UI 操作的 `IGraphicsContext` 兼容门面承载尚未迁移的语义；OpenGL ES legacy queue 已收回当前生产 UI 所需的渐变、扇形、solid mesh、BGRA image blit、描边与阴影，D3D11 legacy queue 也已收回 BGRA affine image blit，D3D11/OpenGL ES legacy Picture blit 也已支持组 opacity 与 Additive；大字号旋转 Watermark 的真实 manifest/present 已通过，但专用 WGC 像素快照、完整图元/Picture parity、真实物理 surface/device lost 及多 DPI/GPU/OS 运行矩阵未闭合，当前 `test-harness` lower injection 已证明 D3D11 与 Windows WGL OpenGL ES 各三轮 teardown/rebuild 边界，第三轮交错另一类故障。D3D11 为 `FullOnly` present 且不保留主 framebuffer，生产 `retained_framebuffer` 仍关闭。

## 未排期目标：性能与资源持续优化

**状态：📋 规划中（未排期）。** 在不牺牲正确性、稳定性、可恢复性和跨平台一致性的前提下，持续降低使用方应用的启动与首帧时间、输入响应和稳定帧成本，并减少 CPU、GPU、内存、线程、磁盘 I/O、缓存与空闲能耗。使用方的编译成本和 release 产物体积由[使用方按需编译](使用方按需编译.md)目标持有。

本条只确立长期优化方向，不代表已经立项或正在执行；当前不指定开始时间、执行顺序、量化预算或绑定版本。未来决定执行时，先为目标平台和代表性场景建立可复现基线，再单独确定预算、优先级与验收门禁。

## 未排期目标：收敛后端图形 API

**状态：🔄 进行中（底层契约、两个 adapter 与首个绘制子集）。** 目标采用[通用 GPU Renderer + 薄原生 RHI](../架构/graphics/backend.md)：矩形、路径、字形、图片、Picture、离屏、模糊、混合、batch 与 atlas 等 UI 图形语义留在通用层，D3D11、D3D12、Vulkan、Metal、OpenGL adapter 只承担资源、pass、draw/copy、submit 与 present。当前已建立有序 `FramePlan`、资源上传契约，并由 D3D11 与可选 OpenGL ES WGL/EGL adapter 执行 solid mesh、SrcOver/Additive textured quad、仿射 linear/radial gradient、仿射 R8 glyph coverage、RGBA8 MSDF glyph、轴对齐与变换圆角/描边矩形、原生扇形、仿射 box shadow、Picture texture 合成与两段 blur 子集；MSDF 已加入带 gutter 和子区域上传的有界多页 atlas，且大字号旋转 Watermark 已通过两个 adapter 的真实 manifest/present 专项；扇形 uniform ABI 已统一为共享 64 字节常量；WGL 已完成首帧 probe 与实际 RHI submit 运行验证；生产路径仍保留兼容高层绘制调用。

当前已有共享的 `RenderBackend` / `GpuBackend`，但 `IGraphicsContext` 和 `NativeRasterCaps` 仍按逐 UI 操作组织尚未迁移的原生能力，且其他完整旋转/仿射图元、专用大字号 WGC 像素快照、Picture 的完整语义 parity、resize/lost 运行矩阵尚未闭合，因此目标尚未完成。本条不指定开始时间、执行顺序、版本或交付承诺。

完成声明需要 D3D11 参考 adapter 和至少第二个原生 adapter 复用同一帧计划与资源策略、bootstrap 能拒绝不满足 GPU 基线的实现，并以真实 adapter 覆盖图片、Picture、opacity、additive、offscreen、blur、resize、surface/device lost 及一次最终 present 的视觉或像素验证；当前已闭合代表性 Demo 的首帧最终 present 与 D3D11 双向 resize，尚未闭合其余矩阵。

## 目标：全面检查布局

**状态：🔄 进行中（最高优先级，主人 2026-08-05 决定）。** 布局是组件正确性的地基：历史缺陷（测量/绘制/命中分叉、越界、负区域、未请求布局收缩等）分散记录在[组件稳定性](组件稳定性.md)的逐组件修复条目中，现正系统检查 `src/ui/layout/`（`engine`/`flex`/`grid`）与各组件自有布局辅助。本目标覆盖：

- **不变量审计**：对照[架构 · layout](../架构/ui/layout.md)不变量逐条核验——结果尺寸与 frame 有限非负、measure/paint/hit-test 对同一组件使用同一实际 frame、无界轴只走约束语义而不把 `f32::MAX` 写入实际 frame、子 frame 收敛后同步父级可见性、布局不执行业务 I/O / 任意应用 callback / present / 跨窗 wake
- **算法边界**：Flex/Grid 的 grow/shrink/wrap/gap/span/align 在负剩余空间、极小/极大约束、非有限输入与空子集下的行为；margin 推开兄弟、border/padding 收敛到 content rect、阴影不影响 content box 的语义
- **组件级一致性**：浮层、表格、富文本、通知等自带布局辅助的组件与共享 `LayoutEngine` 收敛；各组件修复记录中的历史缺陷类别全量回归复核
- **增量与缓存**：Layout dirty 标记边界（paint-only 变化不触发、几何动画触发）、布局 scratch 与输出快照的树版本/约束失效、虚拟滚动物化范围边界
- **验证**：真窗视觉矩阵（含既有 92 组件回归）、行为断言与像素验证，并在当前 D3D11 生产路径确认

**首批进展（2026-08-05，`7de6fcd8`）**：共享 BoxModel/Flex/Grid 已在公开布局边界归一非有限值、负尺寸与 `f32::MAX` 测量哨兵；margin 保留有限负值语义，border/padding 与 Grid gap 收敛为有限非负值；共享入口未新增 track 归一化副本，纯 Grid 求解器继续借用 columns 并沿用既有 implicit row 缓冲。`tests/layout_invariants.rs` 固化五项契约：修复前四个病理输入用例均可复现失败，修复后五项全通过，且正常 Flex/Grid 精确几何保持不变。本批只闭合有限几何与盒模型入口。

**第二批进展（2026-08-05，`7e03fe41`）**：Flex 现先落实 min/max 再分行，以无额外分配的有界迭代把 grow/shrink/Stretch 在子项触顶或触底后的剩余空间转交给仍可伸缩的兄弟；wrapped 零尺寸 bootstrap 保持固有主轴自然尺寸，单行与 wrapped 行账本均把 margin 纳入交叉轴总量，Center/End 在扣除非对称 margin 后对齐，固有反向主轴按实际内容镜像。六个新增聚焦断言在修复前稳定失败；修复后公开布局契约 9/9、内部 Flex 边界 4/4、库测试 101/101，并通过公开 API、使用门面、无默认特性库与全特性全目标检查。本批仍不代表 Grid、Flex 其余组合、组件、缓存或真窗验证已经完成。

**依赖与边界**：检查发现的缺陷直接修复并按既有组件稳定性流程记录；本目标不扩展布局 API 能力，只保证既有语义正确；不指定开始时间、量化预算或绑定版本。

**完成声明**：不变量逐条有对应断言或真窗验证；历史缺陷类别全部回归通过；检查与修复记录登记到[组件稳定性](组件稳定性.md)与[已知缺陷](已知缺陷.md)文档。

## 目标：复杂文本排版

**状态：⏳ 待开始（已立项，未排期）。** 目标让文本层按 Unicode 标准提供完整排版语义，覆盖四个子项：

- **复杂脚本 shaping**：Indic、阿拉伯文等需要组合与上下文替换的脚本，按正确 glyph 顺序与定位进入测量、布局与绘制。当前 `ab_glyph` 仍是逐 Unicode 标量的 advance/kerning 与 CPU 轮廓提取（见[性能与内存](性能与内存.md)瓶颈），只保证拉丁、CJK 等简单文本顺序正确。
- **双向文本（UAX#9）**：混合 LTR/RTL 段落按 Unicode 双向算法重排，逻辑顺序、视觉顺序与命中顺序一致。
- **字素簇光标（UAX#29）**：光标移动、文本选择与命中按字素簇边界进行，组合字符与 emoji 序列不中途断开。
- **完整断行（UAX#14）**：按 Unicode 断行规则换行，替换当前逐标量断行。

**依赖与边界**：文本测量/布局路径（`ab_glyph` 的替换或扩展）与 R8/MSDF 字形管线、富文本、输入控件、无障碍文本语义需随各子项同步验证；字形缓存预算与现有性能基线保持一致。本目标不包含可变字体轴、复杂合字排版、移动端 backend 或完整 OpenType 排版引擎承诺；不指定开始时间、执行顺序、量化预算或绑定版本。

**完成声明**：四个子项均有真实窗口视觉/像素验证（含既有 92 组件视觉矩阵回归）与行为断言（双向段落重排、字素簇光标移动、断行边界），并在当前 D3D11 生产路径建立 shaping/断行后的测量与性能基线；实现前先为代表文本场景建立可复现基线，再单独确定预算、优先级与验收门禁。

## 目标：丰富富文本组件

**状态：⏳ 待开始（已立项，未排期）。** 当前 `RichText`（`src/ui/widgets/other/rich_text/`）已具备混合样式段落显示：Text/Code/Link/NewLine 四类段、Markdown 风格解析（仅围栏代码块与内联反引号）、字符级布局与折行、链接键盘导航、文字选择与代码复制。目标扩展其能力边界，让富文本从「混合样式段落显示」走向「Markdown 级排版与内联富元素」，覆盖：

- **解析与段类型扩展**：`parse_rich_text` 目前只识别围栏代码块与内联反引号，需补齐标题、粗体/斜体标记、Markdown 链接语法、无序/有序列表、引用块与分割线等元素，并新增对应 `RichTextSegment` 变体
- **测量统一**：measure 路径与公开测量辅助 `layout_rich_text` / `layout_rich_text_segments` 使用启发式字符宽度估算（按字符类别比例，不依赖 FontService），与 render 路径 `layout_rich_text_real` 的真实字形测量存在精度差距；需统一为真实测量，保证命中、选择与像素一致
- **样式与排版**：段级字体族/字号变体（当前粗体为 x+0.6 二次偏移模拟，`italic` 仅为数据标志、渲染无字形变体）、行高与段间距、水平对齐、缩进与上下标
- **内联富元素**：段落内嵌图片/图标（`Image` 目前是独立组件，无法嵌入段落）、内联按钮与自定义 widget 槽位
- **选择与无障碍同步**：选择/命中/无障碍语义与结构化快照随新段类型与内联元素同步扩展

**依赖与边界**：折行与光标质量依赖[目标：复杂文本排版](#目标复杂文本排版)的 shaping/断行成果，两个目标共享文本测量与字形管线改动；`RichText` 保持只读显示定位，不包含富文本编辑器；本目标不指定开始时间、执行顺序、量化预算或绑定版本。

**完成声明**：新段类型与内联元素均有公开使用示例（`uix-compile` 锚点）、行为断言与真窗视觉/像素验证；measure 与 render 宽度一致；既有 92 组件视觉矩阵与无障碍 manifest 回归通过。

## 更小 · 更快 · 更稳

### 更小：缩小内存占用

- **当前生产基线**：wgpu 已移除；Windows 默认 feature 与 factory 使用原生 D3D11，`opengles` feature 可构造 WGL/EGL OpenGL ES adapter。`draw::Renderer` / `GpuBackend` 仍共享，逐 UI 操作的原生 pipeline 与资源实现正在收敛到 thin RHI；OpenGL ES legacy compatibility 的真实窗口 traversal 已通过，WGC 已确认硬件窗口捕获到非空完整 UI，但完整像素矩阵仍未闭合
- **历史实测**：Windows/NVIDIA release、1200×800、中文 Demo 首屏稳定 5 秒后的 Vulkan/D3D12，以及 2026-08-01 AMD RX 5700 内存批次均来自已移除的 wgpu 路径，只保留为历史对照，不能作为当前 D3D11 基线；原始数字见[性能与内存](性能与内存.md)
- **已做**：字形缓存 LRU 2048 项/8 MiB、Picture 32 MiB 硬预算、DisplayList COW Arc 共享、主画布 scratch 1×1、Label/Input 直接移交单次绘制的新 glyph layout、1920×1080 resize 不再分配未用 CPU 主表面（约 −7.91 MiB）
- **瓶颈**：当前 D3D11 的驱动、shader、GPU 资源与中文字体常驻成本尚未建立同口径实测；native adapter 在 RHI 收敛前仍承担重复 pipeline/资源实现
- **使用方构建**：目标是未选择且非传递必需的能力不进入应用编译图，已选择但不可达的代码不进入 release 产物；当前九个公开 capability、`agent-control`、演示专属 `demo-logging` 与五种 backend 公开选择面已有正反门禁，`windows-core` 已收缩到 Windows target，schema v6 的 38 场景双目标矩阵还加入了排除内部 `test-harness` 的全能力外部 fixture，并在同条件下记录最小/完整 release 产物 8,293,442 B / 19,957,355 B。整体门禁仍缺其余能力分区、生产 backend/其他 target 及产物符号与资源断言，详见[使用方按需编译](使用方按需编译.md)
- **目标**：逼近同体量 GPU-only 框架内存水平，并让应用只承担实际选择能力的构建与产物成本

### 更快：降低每帧耗时

- **已做**：生产只有一个 `draw::Renderer`；相邻兼容 op 在 API 中立层合批；失效队列、布局热路径与到期工作已完成一批分配/遍历优化
- **历史实测**：Vulkan 首帧约 14.6 ms、稳定后采样帧约 4.7 ms 来自已移除的 wgpu 路径，不代表当前 D3D11；D3D11 的首帧与稳定帧需要重新测量
- **热路径 scratch 复用**：Layout 遍历复用扩展签名/已调整子节点集合；Flex/Grid/溢出流式不分配主轴尺寸副本；Overlay 新旧签名流式比较；Timer discovery 复用 route map
- **布局失效优化**：同节点 Layout 队列项去重但 revision 仍逐请求推进；向上传播复用每树祖先链缓冲
- **到期工作清退**：registry 在一次有序 retain 扫描中处理；动画注册原位同步不逐帧重建 desired map
- **瓶颈**：`ab_glyph` 仍是逐 Unicode 标量的 advance/kerning 与 CPU 轮廓提取；MSDF RHI lowering、带硬预算的多页 atlas 和大字号 Watermark 的真实 present 已落地，但专用 WGC 像素快照与更宽的字号/DPI 视觉矩阵未闭合；完整复杂文本排版（shaping/双向文本/字素簇光标/UAX#14 断行）已立项为[目标：复杂文本排版](#目标复杂文本排版)
- **目标**：稳定 60Hz

### 更稳：跨平台真机现状

- **当前生产路径**：Windows 默认原生 D3D11；启用 `opengles` feature 时 WGL/EGL 走同一薄 RHI host；D3D11 present coherency 为 `FullOnly`，`retained_framebuffer=false`，D3D11 与 OpenGL ES/WGL 已有真实 context、正式 RHI surface present 和 1200×800 首帧视觉验证，D3D11 另有 1200×800↔900×640 双向 resize 验证，大字号 Watermark 已有两个 adapter 的真实 present 专项，但仍缺专用 WGC 像素快照、完整 surface/device lost 与跨环境矩阵
- **历史数据**：Windows Auto→Vulkan、强制 Vulkan、最小化/隐藏恢复与 wgpu device-lost 验证来自已移除路径，不能替代当前 D3D11 验收
- **数据缺口**：D3D11 下最低支持 build 26100、96/144/192 DPI、NVIDIA/AMD/Intel、最小化/隐藏恢复、surface/device lost，以及 Wayland/macOS 生产 backend 均无闭合的当前报告；既有组件视觉矩阵需按当前 backend 重新确认
- **目标**：四平台同等视觉/图形矩阵
