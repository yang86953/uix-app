## 权威范围

框架核心功能已收敛，当前聚焦三个交付方向——缩小运行内存与使用方构建成本、降低每帧耗时至稳定 60Hz、四平台同等视觉矩阵。

### 进度总览

| 状态 | 事项 |
|------|------|
| ✅ 已完成 | Windows 生产 GPU factory/default feature 切换到原生 D3D11 并移除 wgpu；生产只有一个 `draw::Renderer`；字形缓存收敛至 2048 项/8 MiB LRU、Picture 缓存 32 MiB 硬预算、DisplayList COW Arc 共享延迟分配、热路径 scratch 复用、布局失效优化、到期工作清退、动画注册原位同步、AppTimer 变更驱动、浮层修复（Modal/Drawer 布局+backdrop） |
| 🔄 进行中 | D3D11 原生绘制覆盖与真实视觉证据闭合、MSDF 多通道字形视觉矩阵、当前生产路径的内存/帧耗时重新建立基线 |
| 📋 规划中 | 使用方按需编译：建立能力 feature / crate 边界，使未选择能力及其依赖不参与应用构建，并验证 release 目标程序不含不可达代码 |
| 📋 规划中（未排期） | 图形后端收敛：通用 GPU Renderer 只实现一次 UI 图形语义，原生 adapter 只实现薄 RHI；目标契约见[backend](../架构/graphics/backend.md) |
| ⏳ 待开始 | 复杂脚本 shaping、双向文本、字素簇光标、完整 UAX#14 断行 |
| 📋 规划中 | 四平台同等视觉与图形矩阵；当前仅 Windows 有生产 GPU backend，Linux/macOS 原生 GPU backend 仍为 test-only；窄 present 需要后端提供可靠的 retained/partial-present 事实能力 |

**活跃阻塞**：D3D11 仍通过逐 UI 操作的 `IGraphicsContext` 暴露能力且部分语义证据未闭合，Linux/macOS 暂无生产 GPU backend，当前 D3D11 为 `FullOnly` present 且不保留主 framebuffer，多 DPI/GPU/OS 证据空白。

## 未排期目标：性能与资源持续优化

**状态：📋 规划中（未排期）。** 在不牺牲正确性、稳定性、可恢复性和跨平台一致性的前提下，持续降低使用方应用的启动与首帧时间、输入响应和稳定帧成本，并减少 CPU、GPU、内存、线程、磁盘 I/O、缓存与空闲能耗。使用方的编译成本和 release 产物体积由[使用方按需编译](使用方按需编译.md)目标持有。

本条只确立长期优化方向，不代表已经立项或正在执行；当前不指定开始时间、执行顺序、量化预算或绑定版本。未来决定执行时，先为目标平台和代表性场景建立可复现基线，再单独确定预算、优先级与验收门禁。

## 未排期目标：收敛后端图形 API

**状态：📋 规划中（未排期）。** 目标采用[通用 GPU Renderer + 薄原生 RHI](../架构/graphics/backend.md)：矩形、路径、字形、图片、Picture、离屏、模糊、混合、batch 与 atlas 等 UI 图形语义留在通用层，D3D11、D3D12、Vulkan、Metal、OpenGL adapter 只承担资源、pass、draw/copy、submit 与 present。

当前已有共享的 `RenderBackend` / `GpuBackend`，但 `IGraphicsContext` 和 `NativeRasterCaps` 仍按逐 UI 操作组织原生能力，因此目标尚未完成。本条不指定开始时间、执行顺序、版本或交付承诺。

完成声明需要 D3D11 参考 adapter 和至少第二个原生 adapter 复用同一帧计划与资源策略、bootstrap 能拒绝不满足 GPU 基线的实现，并以真实 adapter 覆盖图片、Picture、opacity、additive、offscreen、blur、resize、surface/device lost 及一次最终 present 的视觉或像素证据。

## 更小 · 更快 · 更稳

### 更小：缩小内存占用

- **当前生产基线**：wgpu 已移除；Windows 默认 feature 与 factory 使用原生 D3D11，Linux/macOS 暂无生产 GPU backend。`draw::Renderer` / `GpuBackend` 仍共享，但逐 UI 操作的原生 pipeline 与资源实现尚未收敛到 thin RHI
- **历史实测**：Windows/NVIDIA release、1200×800、中文 Demo 首屏稳定 5 秒后的 Vulkan/D3D12，以及 2026-08-01 AMD RX 5700 内存批次均来自已移除的 wgpu 路径，只保留为历史对照，不能作为当前 D3D11 基线；原始数字见[性能与内存](性能与内存.md)
- **已做**：字形缓存 LRU 2048 项/8 MiB、Picture 32 MiB 硬预算、DisplayList COW Arc 共享、主画布 scratch 1×1、Label/Input 直接移交单次绘制的新 glyph layout、1920×1080 resize 不再分配未用 CPU 主表面（约 −7.91 MiB）
- **瓶颈**：当前 D3D11 的驱动、shader、GPU 资源与中文字体常驻成本尚未建立同口径实测；native adapter 在 RHI 收敛前仍承担重复 pipeline/资源实现
- **使用方构建**：目标是未选择且非传递必需的能力不进入应用编译图，已选择但不可达的代码不进入 release 产物；当前处于规划阶段，详见[使用方按需编译](使用方按需编译.md)
- **目标**：逼近同体量 GPU-only 框架内存水平，并让应用只承担实际选择能力的构建与产物成本

### 更快：降低每帧耗时

- **已做**：生产只有一个 `draw::Renderer`；相邻兼容 op 在 API 中立层合批；失效队列、布局热路径与到期工作已完成一批分配/遍历优化
- **历史实测**：Vulkan 首帧约 14.6 ms、稳定后采样帧约 4.7 ms 来自已移除的 wgpu 路径，不代表当前 D3D11；D3D11 的首帧与稳定帧需要重新测量
- **热路径 scratch 复用**：Layout 遍历复用扩展签名/已调整子节点集合；Flex/Grid/溢出流式不分配主轴尺寸副本；Overlay 新旧签名流式比较；Timer discovery 复用 route map
- **布局失效优化**：同节点 Layout 队列项去重但 revision 仍逐请求推进；向上传播复用每树祖先链缓冲
- **到期工作清退**：registry 在一次有序 retain 扫描中处理；动画注册原位同步不逐帧重建 desired map
- **瓶颈**：`ab_glyph` 仍是逐 Unicode 标量的 advance/kerning 与 CPU 轮廓提取；MSDF 多通道 atlas 已落地但大字号真机视觉矩阵未闭合
- **目标**：稳定 60Hz

### 更稳：跨平台真机现状

- **当前生产路径**：Windows 默认原生 D3D11；present coherency 为 `FullOnly`，`retained_framebuffer=false`。Linux/macOS registry 明确将原生 Vulkan/OpenGL/Metal 保持为 test-only，暂无生产 GPU backend
- **历史数据**：Windows Auto→Vulkan、强制 Vulkan、最小化/隐藏恢复与 wgpu device-lost 证据来自已移除路径，不能替代当前 D3D11 验收
- **数据缺口**：D3D11 下最低支持 build 26100、96/144/192 DPI、NVIDIA/AMD/Intel、最小化/隐藏恢复、surface/device lost，以及 Wayland/macOS 生产 backend 均无闭合的当前报告；既有组件视觉矩阵需按当前 backend 重新确认
- **目标**：四平台同等视觉/图形矩阵
