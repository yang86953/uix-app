## 当前事实

- 主题类型迁移
  - `IColorTokens` / `ShadowToken` 已放入 `src/ui/theme/color_tokens.rs`
  - 排版、间距、阴影及聚合 `ThemeTokens` trait 已放入 `src/ui/traits/theme.rs`
  - `TokenPatch` 与 scope 实现已移到 `src/ui/theme/token_patch.rs`
- 公开入口调整
  - `draw::api` 的主题与 token 公开重导出已删除
  - `ui` 根与 prelude 已补充 UI 归属的公开入口；`uix::ui::PaintContext` 现在指向 UI-owned 绘制上下文
- 上下文边界已收口
  - `src/draw/api/theme.rs` 已删除；`ThemeSnapshot` 全仓无残留
  - `draw::PaintContext` 不再持有 `ScopedThemeTokens` / `ThemeTokens`，`new()` 与 `new_for_test()` 移除 tokens 参数
  - `LayerRenderEnv`、`LayerTree::render*`、`FrameRenderInput` 不再携带主题；离屏 Picture 栅格化路径同理
  - UI-owned `src/ui/core/paint_context.rs`：包装 `draw::PaintContext`，持有 `ScopedThemeTokens`（根令牌为 owned `Arc<dyn ThemeTokens>`），显式转发全部绘制/查询方法（不使用 `DerefMut`，保留同表达式二段式借用），`with_opacity` 闭包接收底层 draw 上下文、令牌由调用方提前解析
  - `WidgetTree` 持有主题令牌根（默认 antd_light），`ScenePaint::paint` 在 UI 边界构造 UI-owned 上下文；`WindowDriver` 每帧渲染前 `tree.set_theme_tokens(theme_ref.tokens_arc())` 同步
  - `WidgetRender::render` 与全部组件签名保持 `&mut PaintContext` 名字不变（类型已换为 UI-owned）
- 验证状态
  - `cargo check --workspace --all-targets`、`cargo check --target x86_64-pc-windows-msvc --lib`、`cargo check --target x86_64-pc-windows-gnu --lib`：通过（警告数与基线一致）
  - `cargo test --quiet`：全部通过（22 项 GUI ignored 入口未执行，与基线一致）
  - `rg "crate::ui" src/draw/`：0 处；`rg "ThemeTokens|TokenPatch|TokenScope|ThemeSnapshot" src/draw/`：0 处
  - 改动文件 rustfmt 检查与 `git diff --check`：通过；基线既有无关格式差异未触碰
  - `no-default-features` 的 `drawable_size` 编译失败为进度文档已记录的既有缺陷，非本次引入

## 直接切换约束

- 不考虑兼容：删除旧 `draw::api::{IColorTokens, ThemeTokens, TokenPatch, ShadowToken, ...}`，不添加 deprecated alias 或 facade。
- 不用"文件已移动"代替分层完成；`src/draw` 不得重新出现 `crate::ui` 引用。
- `Color`、路径、字体句柄、DisplayList 与 renderer 仍属于 graphics 系统；品牌色、语义色、明暗模式、组件覆盖与主题继承属于 UI。
- 主题令牌根由 UI 域（`WidgetTree`）持有；graphics 只接收已解析颜色、尺寸和绘制值。
