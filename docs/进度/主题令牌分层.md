> 分类：主题令牌分层  
> 权威范围：主题与颜色 token 从 draw 迁入 UI 的当前事实、活跃差距与直接切换验收

目标契约见[架构 · 设计令牌与色彩](../架构/设计令牌与色彩.md)与[架构 · 边界与分层](../架构/边界与分层.md)。

## 当前事实

- 工作树已把 `IColorTokens` / `ShadowToken` 放入 `src/ui/theme/color_tokens.rs`，把排版、间距、阴影及聚合 `ThemeTokens` trait 放入 `src/ui/traits/theme.rs`，并把 `TokenPatch` 与 scope 实现移到 `src/ui/theme/token_patch.rs`。
- `draw::api` 的主题与 token 公开重导出已删除，`ui` 根与 prelude 已补充 UI 归属的公开入口；`tests/ui_public_api.rs` 已加入 UI 公开路径断言。
- 迁移尚未满足最终分层：`src/draw/api/theme.rs` 的 `ThemeSnapshot`、`src/draw/api/paint_context.rs` 和 `src/draw/scene/picture.rs` 仍直接引用 `ui` 主题类型，形成架构禁止的 `draw → ui` 依赖。
- 停止代码工作前，`cargo check --all-targets` 与 `cargo test --test ui_public_api` 曾通过；随后仅发生过一次撤回/恢复操作，当前工作树需由接手模型重新验证，不能把此前结果视为最终证据。

## 活跃差距

| 差距 | 完成条件 |
|---|---|
| 主题快照仍在 draw | `ThemeSnapshot` 迁入 UI 绘制接入或被等价 UI-owned 机制替代；`draw` 不出现该主题类型 |
| `PaintContext::tokens()` 混合职责 | UI-owned 上下文负责 `tokens()` 与组件补丁 scope；底层 `draw::PaintContext` 只接收解析后的绘制值 |
| draw 反向依赖 UI | `rg` 证明 `src/draw` 不引用 `crate::ui`，恢复 `draw → core/native` 的单向边界 |
| scope 生命周期未归 UI | subtree theme / `TokenPatch` 的替换与恢复由 UI 节点渲染边界托管，正常返回与 panic 展开均不得泄漏到兄弟节点 |
| 公开面未最终核验 | UI allowlist 覆盖全部主题 trait、`Theme`、`DesignTokens`、`TokenPatch`；compile-fail 或等价 denylist 证明 `draw::api` 旧路径不可用 |
| 全量证据需刷新 | 当前工作树重新通过格式检查、`cargo check --all-targets`、主题公开 API 测试及组件 token scope 定向测试 |

## 直接切换约束

- 不考虑兼容：删除旧 `draw::api::{IColorTokens, ThemeTokens, TokenPatch, ShadowToken, ...}`，不添加 deprecated alias 或 facade。
- 不用“文件已移动”代替分层完成；只要 `src/draw` 仍引用 `crate::ui`，任务就未完成。
- `Color`、路径、字体句柄、DisplayList 与 renderer 仍属于绘图层；品牌色、语义色、明暗模式、组件覆盖与主题继承属于 UI。
- 接手模型应先解决上下文边界，再机械更新组件调用点；不要通过放宽[边界与分层](../架构/边界与分层.md)来容纳反向依赖。
