## 当前结论

当前工作树已经建立 `uix::platform` 的具体公开面，并把原 `uix::native` 根模块改为 crate-private。

这还不是平台层完成状态。当前最新工作树仍存在以下未收口问题：

- 公开图形枚举与内部选择边界已收口：`App::graphics_backend` 只在入口转换一次，`application/runtime.rs`、renderer 与 native factory 使用内部枚举。
- 旧 native SPI 与部分非平台实现仍留在目录内。
- Windows 系统通知尚未闭环。
- Windows `wnd_proc` 的 DPI、尺寸/移动和 IMM 失败分支，以及 DWM frame pacer worker 的 `DwmFlush` / `PostMessageW` 失败，已接入运行保障的 owner-thread 最终报告链；custom chrome / TSF、Wayland / macOS FFI callback 仍未接入。wgpu uncaptured/device-lost 与 offscreen destroy void 失败已接入队列，`WgpuContext` teardown 已完成 checked offscreen 销毁和 source close；D3D11、D3D12、Vulkan、EGL、WGL 等其他图形 teardown 仍未全覆盖。

## 平台 callback 审计结论

尚未落地但必须覆盖的首批位置：

- **`native/graphics/wgpu_backend`**
  - ✅ uncaptured error → Diagnostics pending failure queue
  - ✅ device-lost → Diagnostics pending failure queue
  - ✅ offscreen destroy void 失败 → Diagnostics pending failure queue
  - ✅ checked teardown → 先销毁 bound/offscreen 资源，成功后关闭 source；旧 source 晚到 callback 不污染 replacement source
- **Windows**
  - ✅ `wnd_proc` 的 DPI / 尺寸移动 / IMM 失败 → Diagnostics pending failure queue
  - ✅ DWM frame pacer 的 `DwmFlush` / `PostMessageW` 失败 → Diagnostics pending failure queue
  - custom chrome
  - TSF
  - 线程亲和析构
- **Wayland**
  - event-loop dispatch / poll / fd
  - clipboard pipe / I/O
  - seat callback
  - detached timer
- **macOS**
  - window delegate
  - text input view
  - display link 的 ObjC callback
- **图形 teardown**
  - D3D11
  - D3D12
  - Vulkan
  - EGL
  - WGL
  - thread-bound context

详细 owner 规则由[架构 · 运行保障](<file:///C:/data/note/我的项目/软件/UIX App/架构/platform/diagnostics.md#平台层全覆盖>)唯一规定；本文不复制恢复算法。

S1-01 定向证据：`src/native/graphics/wgpu_backend/mod.rs` 的 legacy `destroy_offscreen_target` 失败路径只入队，不直接 `core::log::*`；`offscreen_destroy_failure_*` 两项单元测试证明 typed cause 可由 owner 取回且 source 关闭后晚到失败被丢弃。

S1-02 定向证据：`WgpuContext::try_shutdown` 先切回 swapchain、逐项调用 checked `try_destroy_offscreen_target`，失败时不清空 owner 状态、不关闭 source；成功后清理槽位、关闭旧 source，再执行 device poll。新增 `offscreen_destroy_failure_after_source_close_cannot_reach_replacement_owner` 与 `teardown_source_close_is_idempotent_and_discards_late_failures` 生命周期测试；真实 GPU teardown 仍未以无硬件环境测试冒充证据。

## 接手实施顺序

1. 保持当前 `uix::platform` allowlist，不再扩大公开对象。
2. 把内部 Auto / fallback 从 `GraphicsBackend` 设备枚举中拆成私有选择策略，确保公开只有一套实际 API 类型。
3. 为 App 内部 native owner 显式注入同一个 Diagnostics；公开独立 Platform 仍只返回 Result。
4. 已实现跨 OS / graphics 共用 queue 的 wgpu callback 与 checked teardown/source close 首个覆盖，并完成 Windows `wnd_proc` 核心失败分支和 DWM frame pacer worker；继续接入 Windows custom chrome / TSF、Wayland / macOS callback，以及其他图形后端 teardown，并保持 callback 只入队。
5. 将可返回的 native 失败改为 Result；只有无返回路径的 final owner 才报告一次。
6. 迁移 native 日志、删除重复 core 日志/诊断轮子，再补 compile-fail 与 feature / target 矩阵。

不得为了让现有调用继续编译而恢复 `pub mod native`、公开实现 trait、deprecated alias、兼容 facade 或新旧 DTO 双轨。

## 完成判据

- `uix::platform` 只公开具体 Platform 与 owned hardware / graphics / service 值。
- `uix::native`、所有 backend SPI、raw handle、context 与厂商对象对外不可达。
- 公开查询全部使用既有 typed Error，取消与失败不再混用空值。
- 平台 callback 不调用 subscriber 或用户代码；所有 pending failure 在 owner thread 被恢复、返回或只报告一次。
- owned DTO 满足 `Clone + Send + Sync`，Platform 保持 `!Send + !Sync` 和单实例事务语义。
- Windows MSVC/GNU、Linux、macOS、默认 / no-default / 单 backend / all-features 的约定矩阵通过。
- allowlist、denylist、callback panic、queue overflow、device-lost reason 与 teardown 边界均已明确。
