## 当前结论

当前工作树已经建立 `uix::platform` 的具体公开面，并把原 `uix::native` 根模块改为 crate-private；Windows 主机上的基础公开契约取得过构建和测试证据。

这还不是平台层完成状态。当前最新工作树仍存在以下未收口问题：

- 公开图形枚举切换到一半，造成编译阻塞：`application/runtime.rs` 的多个内部函数签名被解析为新公开枚举，而 renderer / native factory 仍要求旧私有枚举。
- 旧 native SPI 与部分非平台实现仍留在目录内。
- Windows 系统通知尚未闭环。
- FFI / GPU callback 没有接入运行保障的 owner-thread 恢复与最终报告链。

### Windows 图形现状

- 工作树分母为 92 项（87 Widget、2 Composite、3 Provider），包含 663 个声明状态；现有 wgpu 报告含 847 条证据行、329 张原图与 22 张联系表，标记为 `UNVERIFIED`。
- Windows build 26200、NVIDIA、96 DPI 下已有 `Auto → Vulkan`、强制 Vulkan与 Software 整体回退的工作树报告。Software 报告由测试夹具请求 Windows 不支持的 `metal` 后触发，不代表生产 `Auto` 的自然失败路径。
- `0.0.1` 的最低平台定义为 Windows 11 24H2 x64（build 26100），release 只含默认 `vulkan` feature；D3D11、D3D12、OpenGL / OpenGLES 与 Metal 不进入本版本交付构建。
- 144 / 192 DPI、AMD、Intel、最低 build 26100、真实 compositor occlusion、多窗与 DeviceLost 组合暂无当前报告。
- Vulkan 当前报告 `present_occlusion=unsupported`；现有最小化 / 隐藏恢复数据只反映窗口生命周期恢复。

## 已取得的验证

本轮切换为"只写文档"前取得过以下证据：

- `cargo check --lib`：Windows MSVC 主机通过。
- `cargo check --lib --target x86_64-pc-windows-gnu`：通过。
- `cargo clippy --lib`：platform 新代码无警告；当时只有 diagnostics 未使用字段警告。
- `cargo test --test native_public_api`：2/2 通过。

这些证据只覆盖当时的部分工作树，不等价于最终全仓验证。之后工作树还包含其他未收口改动，接手模型必须重新运行完整矩阵。

当前最新验证 `cargo test --test usage_markdown` 在编译 library 时失败，尚未进入 Markdown 示例。失败原因分析：

- `application.rs` 向 `create_preferred_engine` / `drain_pending_open_windows_with_backend` 传入私有枚举，但目标签名被解析成公开枚举。
- `application/runtime.rs` 又把公开枚举传给 `gpu_recipe_candidates` / `bootstrap_renderer`。
- 新公开枚举没有内部日志格式化所需的 `Display`。

这不是文档错误，而是已保留的半完成源码改动；接手模型必须首先收口类型边界。

## 已知阻塞与未完成项

| 优先级 | 差距 | 下一完成条件 |
|---|---|---|
| P0 | 当前 library 编译被图形 enum 半迁移阻塞 | App 的公开 builder 接受 platform enum，并只在入口一次转换为私有选择类型；`application/runtime.rs`、renderer 与 native factory 全程使用私有类型。不要给公开枚举补 `Auto` / D3D11，也不要用双向散落转换掩盖边界 |
| P0 | 平台运行保障未接通 | App 内部 native owner 显式持有 runtime Diagnostics；Win32 / ObjC / Wayland / GPU callback 只投递统一有界 pending failure，owner thread 执行领域恢复、registry 恢复、返回或最终报告 |
| P0 | wgpu callback 丢失 typed 原因 | device-lost / uncaptured callback 保存 bounded reason 与 opaque device origin；`ensure_active` 返回或最终报告时保留 cause，callback 不直接 tracing / report |
| P0 | ABI panic 边界不完整 | Win32 wnd_proc、ObjC thunk、Wayland callback 与生成的 FFI thunk 均保证 unwind 不跨 ABI，并使用平台安全返回值 |
| P0 | native 失败语义仍有 bool / 空值 | event loop、clipboard、cursor、timer、display、dialog 等 crate-private trait 的真实失败改为 typed Result；取消使用独立 outcome，不能与失败共用空字符串 / false |
| P0 | 旧日志轮子仍被 native 使用 | native 的 `core::log::*` 调用迁移为 tracing 或 typed Error；最终删除旧 core log/diagnostic，不建立桥接双写 |
| P1 | 图形 enum 仍双轨 | 公开枚举只保留实际 API；内部 `Auto` 与 fallback 必须成为私有选择策略，而不是另一套同名公共设备枚举；不提供 alias |
| P1 | `uix::native` deny 证据不足 | 新增 compile-fail，拒绝 native 根、backend SPI、raw handle、context、厂商对象和默认构建 fake |
| P1 | 目录归属尚未完成 | shader、glyph atlas、blur、raster command / executor、renderer recovery 等从 native 归还 draw；只移动真实归属，不复制实现 |
| P1 | Windows system notification 未闭环 | 当前独立调用因缺少应用身份返回 `NotImplemented`；需定义并验证符合目标边界的应用身份来源，或明确首版保持 unsupported |
| P1 | Windows no-feature / OpenGLES | 既有 `drawable_size` cfg 遗漏仍阻塞 `--no-default-features` 与单 `opengles` library check |
| P1 | Linux target | 既有 Wayland 0.31 API 不兼容阻塞构建 |
| P1 | macOS target | 既有 wgpu `CoreAnimationLayer` API 不兼容阻塞构建 |

## 平台 callback 审计结论

尚未落地但必须覆盖的首批位置：

- **`native/graphics/wgpu_backend`**
  - uncaptured error
  - device-lost
  - offscreen destroy
  - teardown
- **Windows**
  - `wnd_proc`
  - DPI
  - custom chrome
  - frame pacer
  - TSF / IMM
  - 线程亲和析构
- **Wayland**
  - event-loop dispatch / poll / fd
  - clipboard pipe / I/O
  - seat callback
  - detached timer
- **macOS**
  - window delegate
  - text input view
  - display link 的 ObjC callback
- **图形 teardown**
  - D3D11
  - D3D12
  - Vulkan
  - EGL
  - WGL
  - thread-bound context

详细 owner 规则由[架构 · 运行保障](../架构/platform/运行保障.md#平台层全覆盖)唯一规定；本文不复制恢复算法。

## 接手实施顺序

1. 先修复当前图形 enum 编译断层：公开 builder 入口只转换一次，内部 runtime / renderer / factory 不再意外解析到公开类型。
2. 保持当前 `uix::platform` allowlist，不再扩大公开对象。
3. 把内部 Auto / fallback 从 `GraphicsBackend` 设备枚举中拆成私有选择策略，确保公开只有一套实际 API 类型。
4. 为 App 内部 native owner 显式注入同一个 Diagnostics；公开独立 Platform 仍只返回 Result。
5. 实现一个跨 OS / graphics 共用的 bounded pending failure queue，并先覆盖所有 P0 callback。
6. 将可返回的 native 失败改为 Result；只有无返回路径的 final owner 才报告一次。
7. 迁移 native 日志、删除重复 core 日志/诊断轮子，再补 compile-fail 与 feature / target 矩阵。

不得为了让现有调用继续编译而恢复 `pub mod native`、公开实现 trait、deprecated alias、兼容 facade 或新旧 DTO 双轨。

## 完成判据

- `uix::platform` 只公开具体 Platform 与 owned hardware / graphics / service 值。
- `uix::native`、所有 backend SPI、raw handle、context 与厂商对象对外不可达。
- 公开查询全部使用既有 typed Error，取消与失败不再混用空值。
- 平台 callback 不调用 subscriber 或用户代码；所有 pending failure 在 owner thread 被恢复、返回或只报告一次。
- owned DTO 满足 `Clone + Send + Sync`，Platform 保持 `!Send + !Sync` 和单实例事务语义。
- Windows MSVC/GNU、Linux、macOS、默认 / no-default / 单 backend / all-features 的约定矩阵通过。
- allowlist、denylist、callback panic、queue overflow、device-lost reason 与 teardown 均有契约测试。
