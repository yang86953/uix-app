## 当前结论

当前工作树已经建立 `uix::platform` 的具体公开面，并把原 `uix::native` 根模块改为 crate-private。

这还不是平台层完成状态。当前最新工作树仍存在以下未收口问题：

- 公开图形枚举与内部选择边界已收口：`App::graphics_backend` 只在入口转换一次，`application/runtime.rs`、renderer 与 native factory 使用内部枚举。
- 旧 native SPI 与部分非平台实现仍留在目录内。
- Windows 系统通知已具备真实后端与 typed 失败语义：`Platform::show_notification` 在 Windows 走 `Shell_NotifyIconW`（NIM_ADD / NIM_MODIFY 带回退）、Linux 走 `notify-send`，失败转 `PlatformError`；macOS 返回 `NotImplemented`。`NotificationService` 在最终责任边界通过 `Diagnostics::report` 提交观察。剩余未决是产品决策 D0-01：首版是否把系统通知作为交付能力（含应用身份来源）。
- Windows `wnd_proc` 的 DPI、尺寸/移动、IMM、custom chrome 失败分支和 ABI panic，以及 DWM frame pacer worker 的 `DwmFlush` / `PostMessageW` 失败，已接入运行保障的 owner-thread 最终报告链；TSF composition/text-store callback 失败与生成 COM thunk panic 也已转为安全 HRESULT 和 typed owner failure。Wayland / macOS FFI callback 仍未接入。wgpu uncaptured/device-lost 与 offscreen destroy void 失败已接入队列，`WgpuContext` teardown 已完成 checked offscreen 销毁和 source close；S1-06 已用并发 producer、overflow 单次信号和 generation replacement 测试固定 queue 边界；D3D11、D3D12、Vulkan、EGL、WGL 等其他图形 teardown 仍未全覆盖。

## 平台 callback 审计结论

尚未落地但必须覆盖的首批位置：

- **`native/graphics/wgpu_backend`**
  - ✅ uncaptured error → Diagnostics pending failure queue
  - ✅ device-lost → Diagnostics pending failure queue
  - ✅ offscreen destroy void 失败 → Diagnostics pending failure queue
  - ✅ checked teardown → 先销毁 bound/offscreen 资源，成功后关闭 source；旧 source 晚到 callback 不污染 replacement source
- **Windows**
  - ✅ `wnd_proc` 的 DPI / 尺寸移动 / IMM 失败 → Diagnostics pending failure queue
  - ✅ DWM frame pacer 的 `DwmFlush` / `PostMessageW` 失败 → Diagnostics pending failure queue
  - ✅ custom chrome 的 Win32/DWM/命中测试失败 → Diagnostics pending failure queue；每条 custom chrome 消息最多入队一次
- ✅ TSF composition / text-store callback 与生成 COM thunk panic → WindowsPlatform pending failure source；COM 失败返回安全 `HRESULT`
  - 线程亲和析构
- **Wayland**
  - event-loop dispatch / poll / fd
  - clipboard pipe / I/O
  - seat callback
  - detached timer
- **macOS**
  - window delegate
  - text input view
  - display link 的 ObjC callback
- **图形 teardown**
  - D3D11
  - D3D12
  - Vulkan
  - EGL
  - WGL
  - thread-bound context

详细 owner 规则由[架构 · 运行保障](<file:///C:/data/note/我的项目/软件/UIX App/架构/platform/diagnostics.md#平台层全覆盖>)唯一规定；本文不复制恢复算法。

S1-01 定向证据：`src/native/graphics/wgpu_backend/mod.rs` 的 legacy `destroy_offscreen_target` 失败路径只入队，不直接 `core::log::*`；`offscreen_destroy_failure_*` 两项单元测试证明 typed cause 可由 owner 取回且 source 关闭后晚到失败被丢弃。

S1-02 定向证据：`WgpuContext::try_shutdown` 先切回 swapchain、逐项调用 checked `try_destroy_offscreen_target`，失败时不清空 owner 状态、不关闭 source；成功后清理槽位、关闭旧 source，再执行 device poll。新增 `offscreen_destroy_failure_after_source_close_cannot_reach_replacement_owner` 与 `teardown_source_close_is_idempotent_and_discards_late_failures` 生命周期测试；真实 GPU teardown 仍未以无硬件环境测试冒充证据。

S1-03 定向证据：`custom_chrome.rs` 将 `GetWindowLongW`、`SetWindowPos`、`GetWindowRect`、`DwmExtendFrameIntoClientArea` 和 `DwmSetWindowAttribute` 失败统一为 typed `Error`；`wnd_proc` 的 `WM_NCCALCSIZE` / `WM_NCHITTEST` / `WM_SIZE` 不直接 tracing、report、subscriber 或 recovery，owner source 只接收一次本条 custom chrome 消息的失败。Windows MSVC/GNU check、Windows 测试目标编译，以及 invalid-HWND owner-boundary 测试均通过；真实 DWM 硬件行为未写成已验证证据。

## 完成判据

- `uix::platform` 只公开具体 Platform 与 owned hardware / graphics / service 值。
- `uix::native`、所有 backend SPI、raw handle、context 与厂商对象对外不可达。
- 公开查询全部使用既有 typed Error，取消与失败不再混用空值。
- 平台 callback 不调用 subscriber 或用户代码；所有 pending failure 在 owner thread 被恢复、返回或只报告一次。
- owned DTO 满足 `Clone + Send + Sync`，Platform 保持 `!Send + !Sync` 和单实例事务语义。
- Windows MSVC/GNU、Linux、macOS、默认 / no-default / 单 backend / all-features 的约定矩阵通过。
- allowlist、denylist、callback panic、queue overflow、device-lost reason 与 teardown 边界均已明确。

## 快速模型 S2-08：Wayland callback failure queue

本批完成 Wayland callback 到 owner-thread failure queue 的第一段闭环：`LinuxPlatform` 现在接收运行时 `PendingFailureQueue`，Wayland `Dispatch` callback 使用 `catch_unwind` 将 callback panic 转为 typed `PlatformError`，事件循环的 `flush`、`poll`、display fd、socket read、dispatch 与 wake pipe 失败进入同一 source；剪贴板读写、receiver 关闭和 pipe 建立失败也不再只写日志。Linux owner 通过 `Platform::take_pending_failure` 交给既有 `drain_platform_pending_failures`，恢复/最终报告仍只发生在 owner-thread。

验证：workspace all-targets `cargo check`、完整 `cargo test`（110 passed、31 ignored）、Python 测试（15 passed）、文档链接（4 passed）、测试目录门禁（3 passed）和改动文件 `git diff --check` 通过。该批只证明代码路径和契约编译/测试通过，尚无真实 Wayland compositor 运行证据；macOS ObjC callback、其他图形后端 teardown 和 `event_created_child` 的未知协议分支仍保持未闭合，不能写成跨平台 callback 全覆盖。
## 快速模型 S2-09：macOS ObjC callback failure queue 首段
