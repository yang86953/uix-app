## 交付物

Windows x64 内部候选包的交付契约为 `uix-0.0.2-internal-win-x64.zip`：`scripts/build_internal_release.ps1` 从干净工作树生成，`scripts/verify_internal_release.ps1` 在构建结束前校验以下精确载荷：

- release `uix-lang-demo.exe`
- 内部 `uix-0.0.2.crate`
- `LICENSE`
- `THIRD_PARTY_NOTICES.md`
- `CHANGELOG.md`
- `README.md`
- `assets/images/demo.png`
- 覆盖上述七个 payload 的 `SHA256SUMS.txt`

Windows 候选包统一由 `scripts/build_internal_release.ps1` 生成并执行交付物完整性校验。图形后端只允许通过公开 `App`、`GraphicsBackend` 与 `Platform` API 的外部消费者测试；GPU parity、surface 回读、故障注入和 test-harness 不属于项目测试。候选包生成或校验成功也不等于公开 API 已在真实 Windows 环境通过。

Linux x64 内部候选包的交付契约为 `uix-0.0.2-internal-linux-x64.tar.gz`：`scripts/build_internal_release.sh` 从干净的 Linux x86_64 工作树生成，`scripts/verify_internal_release.py` 在构建结束前校验以下精确载荷：

- release `bin/uix-lang-demo`
- 内部 `uix-0.0.2.crate`
- `LICENSE`
- `THIRD_PARTY_NOTICES.md`
- `CHANGELOG.md`
- `README.md`
- `assets/images/demo.png`
- 覆盖上述七个 payload 的 `SHA256SUMS.txt`

Linux 包使用 gzip 压缩的 POSIX ustar 容器。八个条目按上述顺序写入，不产生目录、链接、设备或 PAX 扩展条目；时间统一为 Unix epoch，数字 uid/gid 均为 `0`，主演示模式固定为 `0755`，其余文件为 `0644`，gzip header 不携带文件名或构建时间。校验器拒绝额外、缺失、重排、重复、绝对、路径穿越、反斜杠、元数据漂移或摘要不匹配的条目。相同源码、工具链与依赖输入必须生成字节一致的归档。

Windows ZIP 条目只使用规范相对路径，并统一写入 ZIP 规范允许的最早时间 `1980-01-01 00:00:00`；校验器拒绝额外、缺失、重复、绝对、路径穿越、反斜杠或时间戳漂移条目，并逐项核对小写 SHA-256 与解包内容。相同 payload 与顺序由自动化契约保证生成字节一致的 ZIP 容器。Windows 与 Linux 候选包分别冻结自身平台的容器和可执行文件契约，不要求两者使用相同归档格式或二进制路径。

两个候选包均按仓库默认图形 feature 构建：自动策略先探测 Vulkan（priority `100`）；Windows 继续探测 D3D11（`30`）与 OpenGL ES（`10`），Linux 继续探测 OpenGL ES（`10`）。显式固定某个 API 时失败必须返回 typed error，不得静默改选。

## 0.0.2 分发、升级与回滚策略

- **签名边界**：`0.0.2` 不创建或托管发布签名私钥，也不提供 detached signature。包内 `SHA256SUMS.txt` 只证明解包载荷完整性，发布页登记的容器 SHA-256 只证明取得的容器与登记值一致；二者均不单独提供发布者身份认证。
- **来源与分发**：正式制品只附加到本仓库的私有 Gitea Release，并绑定精确 `v0.0.2` tag、提交 SHA 与本次实际提供容器的 SHA-256；只允许授权账户经既有私有访问路径下载，不复制到公开网盘、公开 Release 或公共 registry。
- **安装与升级**：本版本不提供安装器或自动更新器。部署方先核对容器 SHA-256 与包内清单，再解压到新的并行版本目录，完成启动验收后才切换入口；不得原地覆盖仍在运行的旧目录。候选包不包含、迁移或删除应用 Settings，使用方须按自己的显式 Settings 路径单独备份。
- **回滚**：切换前保留 `0.0.1` 已验证制品、版本目录和 Settings 备份。`0.0.2` 验收失败时先停止新进程，再把入口切回 `0.0.1` 目录并恢复匹配的 Settings 备份；不得原地覆盖或把不匹配版本的 Settings 伪装为成功回滚。

上述策略冻结 `0.0.2` 的操作边界。私有 Gitea Release 绑定 `v0.0.2` tag，本次先附带已完成确定性构建与独立校验的 Linux x64 制品；Windows Vulkan、D3D11 与最终 surface 的真实主机验收已完成，但 Windows x64 制品将在 Windows 环境完成最终打包后追加到同一 Release。候选包及正式制品均只能按内部授权使用。
