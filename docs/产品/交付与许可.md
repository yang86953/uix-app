## 许可边界

仓库 `LICENSE` 声明 UIX 为专有内部使用软件。未经版权持有人事先书面许可，不得对外分发、公开、转授权、销售、转移或向未授权人员披露源码、二进制、文档和资产。

第三方材料仍按各自许可执行；它们的存在不授予 UIX 自身代码、文档或资产的额外权利。

## 交付物

Windows x64 内部候选包的交付契约为 `uix-0.0.3-internal-win-x64.zip`：`scripts/build_internal_release.ps1` 可在 Windows x64 干净工作树原生生成；`scripts/build_internal_windows_cross_release.sh` 可在具备冻结 `cargo-xwin` 与 LLVM 的 Linux x64 干净工作树交叉生成。两个入口分别调用独立校验器检查以下精确载荷：

- release `uix-lang-demo.exe`
- 内部 `uix-0.0.3.crate`
- `LICENSE`
- `THIRD_PARTY_NOTICES.md`
- `CHANGELOG.md`
- `README.md`
- `assets/images/demo.png`
- 覆盖上述七个 payload 的 `SHA256SUMS.txt`

Windows 原生入口由 `scripts/verify_internal_release.ps1` 校验，Linux 交叉入口由 `scripts/verify_internal_release.py` 校验；二者冻结相同载荷、规范路径、最早 ZIP 时间戳和逐项 SHA-256。图形后端只允许通过公开 `App`、`GraphicsBackend` 与 `Platform` API 的外部消费者测试；GPU parity、surface 回读、故障注入和 test-harness 不属于项目测试。交叉候选包生成或校验成功证明 PE/COFF 链接与交付物完整性，不等于该提交已在真实 Windows 环境完成窗口、GPU、输入或 Agent 运行验收。

Linux x64 内部候选包的交付契约为 `uix-0.0.3-internal-linux-x64.tar.gz`：`scripts/build_internal_release.sh` 从干净的 Linux x86_64 工作树生成，`scripts/verify_internal_release.py` 在构建结束前校验以下精确载荷：

- release `bin/uix-lang-demo`
- 内部 `uix-0.0.3.crate`
- `LICENSE`
- `THIRD_PARTY_NOTICES.md`
- `CHANGELOG.md`
- `README.md`
- `assets/images/demo.png`
- 覆盖上述七个 payload 的 `SHA256SUMS.txt`

Linux 包使用 gzip 压缩的 POSIX ustar 容器。八个条目按上述顺序写入，不产生目录、链接、设备或 PAX 扩展条目；时间统一为 Unix epoch，数字 uid/gid 均为 `0`，主演示模式固定为 `0755`，其余文件为 `0644`，gzip header 不携带文件名或构建时间。校验器拒绝额外、缺失、重排、重复、绝对、路径穿越、反斜杠、元数据漂移或摘要不匹配的条目。相同源码、工具链与依赖输入必须生成字节一致的归档。

Windows ZIP 条目只使用规范相对路径，并统一写入 ZIP 规范允许的最早时间 `1980-01-01 00:00:00`；校验器拒绝额外、缺失、重复、绝对、路径穿越、反斜杠或时间戳漂移条目，并逐项核对小写 SHA-256 与解包内容。相同 payload 与顺序由自动化契约保证生成字节一致的 ZIP 容器。Windows 与 Linux 候选包分别冻结自身平台的容器和可执行文件契约，不要求两者使用相同归档格式或二进制路径。

两个候选包均按仓库默认图形 feature 构建：自动策略先探测 Vulkan（priority `100`）；Windows 继续探测 D3D11（`30`）与 OpenGL ES（`10`），Linux 继续探测 OpenGL ES（`10`）。显式固定某个 API 时失败必须返回 typed error，不得静默改选。

## 0.0.3 分发、升级与回滚策略

- **签名边界**：`0.0.3` 不创建或托管发布签名私钥，也不提供 detached signature。包内 `SHA256SUMS.txt` 只证明解包载荷完整性，发布页登记的容器 SHA-256 只证明取得的容器与登记值一致；二者均不单独提供发布者身份认证。
- **来源与分发**：正式制品只允许附加到本仓库的私有 Gitea Release，并绑定精确 `v0.0.3` tag、提交 SHA 与实际提供容器的 SHA-256；只允许授权账户经既有私有访问路径下载。
- **平台与验证边界**：本版交付 Linux x64 与 Windows x64。Linux 制品在 Linux x64 宿主原生链接；Windows 制品在 Linux x64 宿主经冻结 `cargo-xwin 0.23.1` 与 LLVM 真实链接为 PE/COFF。两者均完成确定性容器构建与独立完整性校验；Windows 真机窗口、GPU、输入与 Agent 运行验收不由交叉链接替代。
- **安装与回滚**：本版本不提供安装器或自动更新器。部署方先核对容器 SHA-256 与包内清单，再解压到新的并行版本目录，完成启动验收后才切换入口。验收失败时停止新进程、切回 `0.0.2` 目录并恢复匹配版本的 Settings 备份；不得原地覆盖或混用 Settings。

上述策略冻结 `0.0.3` 的操作边界。私有 Gitea Release 绑定 `v0.0.3` tag 和提交 `33f8fbccdaac94544e4b3e950d219e1aff44fae1`；发布前 45 个公开 API suite、85 项测试全部通过。Linux x64 容器大小为 34,661,176 字节，SHA-256 为 `d616b9b10091e2ad8735b67df27bf923f95231e2cdfb8ef06e20a3ef1181a2e0`；Windows x64 容器大小为 34,584,126 字节，SHA-256 为 `6542b76f377c818034b75caaab8c97975bbf69ba9eaf6ac2ccf394bd29b76d5e`。两平台制品均完成连续两次相同摘要的候选构建、独立校验、上传和重新下载逐字节核对；Windows 真机运行验收仍遵循上述证据边界。候选包及正式制品均只能按内部授权使用。
