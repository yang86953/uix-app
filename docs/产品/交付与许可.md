## 交付物

Windows x64 内部候选包的交付契约为 `uix-0.0.1-internal-win-x64.zip`：`scripts/build_internal_release.ps1` 从干净工作树生成，`scripts/verify_internal_release.ps1` 在构建结束前校验以下精确载荷：

- release `uix-lang-demo.exe`
- 内部 `uix-0.0.1.crate`
- `LICENSE`
- `THIRD_PARTY_NOTICES.md`
- `CHANGELOG.md`
- `README.md`
- `assets/images/demo.png`
- 覆盖上述七个 payload 的 `SHA256SUMS.txt`

Linux 同属 `0.0.1` 首发范围；上述 ZIP 仅定义 Windows x64 平台专用交付物，不向 Linux 复制其命名、载荷或构建假设。Linux 平台专用交付物细节与活跃差距由 [Vikunja 项目 4](https://yang-server.tail9d5559.ts.net:3456/projects/4) 的 [#770](https://yang-server.tail9d5559.ts.net:3456/projects/4/tasks/1548) 及其子任务持有。

ZIP 条目只使用规范相对路径，并统一写入 ZIP 规范允许的最早时间 `1980-01-01 00:00:00`；校验器拒绝额外、缺失、重复、绝对、路径穿越、反斜杠或时间戳漂移条目，并逐项核对小写 SHA-256 与解包内容。相同 payload 与顺序由自动化契约保证生成字节一致的 ZIP 容器。本交付契约只定义内部候选包的结构、完整性和容器确定性；正式发布、签名、分发、升级与回滚进展统一由 [Vikunja 项目 4](https://yang-server.tail9d5559.ts.net:3456/projects/4) 的 [#770](https://yang-server.tail9d5559.ts.net:3456/projects/4/tasks/1548) 维护。

`SHA256SUMS.txt` 用于检测载荷是否与清单一致，不等同于发布者签名或来源认证。当前仓库文档没有把签名、分发渠道、安装、升级或回滚定义为已完成能力；在这些事实由发布任务确认前，候选包只能按内部授权和既定渠道使用。
