# 能力与边界

[← 返回产品索引](../产品.md)

> **接口**：声明 UIX 的功能能力清单与明确边界（不做/暂缓）。依赖：[定位与原则](定位与原则.md)。导出：具体功能的公开用法 → [使用文档](../使用.md)。

## 适用线索

需要回答“UIX 是否把某项能力纳入产品范围”时，以本文为准；需要确认当前 API 与限制时，继续阅读表中的使用文档。

## 权威范围

本文持有产品能力范围、不做项和暂缓项。它不单独证明某项能力已在当前版本的全部平台或 feature 组合中交付；公开用法与限制由链接到的使用文档持有，完成度以实际代码与公开 API 测试结果为准。

具体控件、表单、虚拟列表、图表与组件预设由组件库拥有。本页只列框架职责。

## 完整应用开发能力目标

**方向确认（2026-09-12）**：`uix-app` 应提供开发完整应用所需的通用能力，网络和 ORM 明确属于框架职责，不再将应用基础设施整体留给使用方自行拼装。React 只类比组件层；`uix-widgets` 仍是可复用组件库，不承接网络或数据库运行时。

围绕完整应用开发，能力范围按以下领域组织。网络与 ORM 的纳入已明确；协议、数据库后端、具体库和接口仍待设计，以下不是已交付 API 清单或本轮实施计划。

| 能力域 | 框架目标职责 | 当前基线与待补齐部分 |
| --- | --- | --- |
| 界面与组件 | 组件、状态、布局、绘制、输入、导航与多窗口，以及语言的编译和动态加载 | 已有公开机制；统一 TSX 式组件语言仍待实现 |
| 应用运行与服务 | 启动关闭、服务组合、异步任务、取消、调度、资源生命周期与 UI 协作 | 已有 App、服务容器、定时器和跨线程回投；不能据此宣称所有外部任务已统一管理 |
| 网络通信 | 请求与响应、类型化数据交换、长连接、上传下载，以及超时、取消、错误与重试机制 | 尚无统一公开网络客户端；HTTP、WebSocket 等协议覆盖与底层选型待定 |
| 数据库与 ORM | 数据库接入、实体映射、类型化查询、事务、迁移与连接生命周期 | 当前设置/键值存储不是 ORM；数据库后端和 ORM 实现方案待定 |
| 数据协作 | 序列化、缓存及应用所需的同步接入机制，与网络和持久化能力协作 | 不再把同步一概排除在产品范围外；具体同步模型与交付范围待设计，应用仍定义业务冲突规则 |
| 文件与系统服务 | 文件和资源访问、配置、凭据存储接入及跨平台系统能力 | 已有部分平台服务与设置；不表示完整文件服务或专用凭据存储已交付 |
| 工程与运行保障 | 国际化、诊断、测试、调试、构建，以及应用交付所需的工具支持 | 已有部分实现；平台覆盖、打包签名和更新机制等以具体交付说明为准 |

**完整能力不等于全量默认编译，也不等于所有底层都自行重写。** 框架应提供一致、可组合的公开入口、错误和生命周期契约，可以按实际需要集成成熟 Rust 库；具体选型沿用[依赖治理](../架构/依赖治理.md)。保持当前两包结构，框架内部按能力组织；未选且非传递必需的网络、ORM、驱动及相关资源不进入使用方构建与交付。新增 feature 名称和依赖图以实现后的[框架能力拆分](../架构/框架能力拆分.md)为准。

Rust 与 UIX Lang 应复用同一套框架服务；目标语言通过类型化公开接口使用所需能力，不因调用网络或 ORM 就强制每个应用另写配套 Rust 胶水。编译与动态路径保持相同的服务语义；动态路径仍要求对应实现已经编入宿主并显式开放。语言异步、资源和绑定语法尚待设计，不能把本目标当作当前可运行用法。

应用继续定义领域模型、业务规则、服务端地址、数据结构与业务策略；框架提供实现这些业务所需的通用机制。“框架提供能力”与“应用选择、配置和拥有业务资源”并不冲突，也不代表框架为每个应用运营云服务。

## 能力组合与责任导航

能力表回答“能做什么”；[系统列表的状态与生命周期责任](../架构/系统列表.md#状态与生命周期责任)回答“由谁拥有和关闭”。先按[入口与阅读路径](../使用/入门/入口与阅读路径.md)选择最短流程，再读相关契约；不要求先读完整架构。

组件/UI 状态、领域数据、派生语义、扩展实例与真实外部资源不可互相冒充。网络、ORM 与任务资源的通用管理属于框架目标；应用显式选择能力并定义业务配置、授权与资源作用域，不因创建 UI 自动发起请求或事务。当前外部执行器和资源仍按既有公开合同由调用方管理，不能以目标替代现状。扩展入口优先复用 Rust 窄端口、自定义 Widget、Scheme 或可移植模块的现有合同，不另建通用插件层。

## 可移植 UIX 应用模块

[应用模块规范](../uix-lang/规范/应用模块.md)持有受检函数、状态、命令、异步端口和动态 View 的语言合同；[补充方案](../uix-lang/设计/应用模块与动态执行.md)持有完整目标与取舍。`uix-modules` 是 AOT/共享运行能力，`uix-dynamic` 显式增加运行期前端。它们与 Scheme `extensions` 共存，不隐式转换旧 UI 宏，不承诺解释任意 Rust。首版有限验收入口为 TASK-066（内部历史记录，不作为公开版本说明），设计条目不是全项验收证明。

## 明确不做

- WebView 或浏览器界面运行时。
- 跨网络远程控制；显式启用的同用户本机 Agent 控制面是唯一例外。
- 远程日志上传；应用若需要上传，必须在 UIX 诊断边界之外自行实现并承担授权与隐私责任。
- 将任意历史 `.uix` / Rust 绑定直接动态执行，或借应用模块开放任意 eval、FFI、线程和无授权 I/O。旧 UI AOT 与受检可移植模块分别遵守自身合同；Scheme 主路线不被替换。

此前“网络请求、云服务与跨设备同步属于明确不做项”的总括边界已被完整应用框架定位替代。网络与 ORM 属于明确目标；云服务接入和同步按具体需求设计，不承诺框架自营云服务或已有完整同步实现。

## 软件动态扩展的产品边界

目标是无需重编译或重启宿主就能增加软件功能，包含扩展自有的业务算法、状态与流程，以及可选的动态界面；纯逻辑扩展无需窗口。Rust 宿主持有原有领域真值、进程生命周期和授权边界，扩展只通过显式端口组合宿主已编译并开放的能力。扩展自己的状态由扩展拥有，不能把全部扩展限制为 UI 模板或纯计算命令。

该能力默认关闭，按需进入构建与运行时；应用不采用时不引入解释器和包扫描。原生动态库、任意 Rust 机器码热替换、插件市场和网络分发不在首期范围。注意：响应式更新、`AppHandle::update_view` 与开发期 `HotReloadAdapter` 是框架既有机制，不等于软件动态扩展；扩展的装载、热替换与撤权语义以[目标设计](../架构/app/extensions.md)与[公开用法](../使用/能力与边界/软件动态扩展.md)为准。

## 需求状态与选择规则

- **有效当前需求**：已明确批准的有限验收清单和文档声称可调用的行为。当前动态首版以TASK-066（内部历史记录，不作为公开版本说明）为入口；实现、待验收、阻塞与通过状态只在任务持有，不复制另一份看板。
- **候选/暂缓**：本文长期平台目标及专题中明确列为未支持/限制的能力，不因“在文档出现”自动变成当前必做项。具体组件的候选能力由组件库独立维护，不借组件需求扩大框架边界。
- **被替代的旧断言**：Scheme“尚未实现”、所有`.uix`“只能UI/AOT”、UIX动态补充“暂不实施”已由专属规范与当前批准任务替代；旧UI宏自身的AOT/绑定限制仍有效。历史数量G1/G2与全局依赖棘轮已退役，理由保留在依赖治理。
- **验收与停止**：范围内合同有公开行为和必要关键体验证据，任务与使用说明一致且无阻断即可收口；剩余候选不阻止有限目标结项，也不据此宣称所有平台/整个产品完成。

## 暂缓与交付边界

- **移动端 backend**：属于长期产品目标，但当前暂缓，不是 `0.0.7` 交付承诺。
- **当前平台**：`0.0.7` 声明 Windows 与 Linux；macOS 与其他平台的目标定位不等于当前发布支持。
- **发布设施**：签名、分发、自动升级和回滚不由本能力清单承诺，当前定义见[交付与许可](交付与许可.md)。

平台与硬件的覆盖以实机验证结果与[交付与许可](交付与许可.md)声明为准；内部 Adapter、RHI 与驱动执行不建立项目测试。
