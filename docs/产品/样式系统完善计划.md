# 样式系统完善计划

## 目标

以原生桌面界面的表达能力、组合一致性和调试体验为目标，保留 `.uix`、Rust 和现有原生渲染，
不采用 HTML/CSS/TypeScript 或 WebView 替换。

**本文是后续设计与阶段顺序，不是公开 0.0.8 的已交付能力清单。** 已完成实现只有进入公开
源码/发行版本后，才能作为该版本能力；内部阶段验收不是公开发行。

## 基线与已知差距

### 当前源码进展

S1 声明/六态、S2 主题目标过渡、S3 尺寸约束/百分比 inset/窗口断点/有限 minmax
已进入当前源码并有对应公开入口测试。它们尚未随 crates.io 新版本发行；已发布 0.0.8
仍对应历史快照。具体支持与拒绝集合以[样式规范](../uix-lang/规范/样式与主题.md)和
[属性参考](../uix-lang/参考/样式属性.md)为准。S4 精细视觉与 S5 工作台仍是后续工作。

下表保留计划开始时的差距，用于说明阶段设计，不是当前源码的未完成清单。

规划针对现有样式层的实际差距；后续开发按对应公开提交与源码重新核对。编译器工具链跟随最新稳定版，外部架构规范不在本计划中顺带升级。

已有基础包括样式类、多 class、extends、内联样式、主题 token、Flex/Grid、定位、变换和有限动画。本计划不重做已验收功能。

| 核查事实 | 实际影响 | 处理方向 |
|---|---|---|
| `Style::apply` 以非零、非默认值判断部分字段是否声明 | Rust 差异样式不能可靠表达 padding=0、radius=0、flexShrink=1 等恢复；不据此断言所有 `.uix` 路径都存在同一缺陷 | 区分未声明与显式值，贯通解析和运行时 |
| `.uix` 状态规则为 disabled > checked > hover；Rust StyleSet 只选择 disabled/focused/pressed/hover 中一个覆盖层 | 两个入口组合语义不同，焦点与按下不能按同一语言契约表达 | 统一状态来源及逐字段叠加 |
| transition 颜色目标拒绝主题 token，限定固定尺寸与少量属性 | 主题按钮悬停、切换主题和正在进行的动画难以组合 | 解析有效 token 后驱动既有动画 |
| Grid 轨道主要为固定值/fr，定位 inset 拒绝百分比与 calc；公开样式缺少完整响应式表达 | 常见窗口宽度变化需要额外业务分支 | 有界长度表达、尺寸约束与窗口断点 |
| Style 单圆角、单阴影；背景单层，图片按固有尺寸，渐变有限 | 卡片、封面、分组控件等精细视觉受限 | 先补直接支撑真实页面的视觉能力 |

依据：[样式规范](../uix-lang/规范/样式与主题.md)、[属性参考](../uix-lang/参考/样式属性.md)、[主题架构](../架构/ui/theme.md)、[编译器架构](../uix-lang/设计/编译器架构.md)、[样式合并实现](../../src/ui/theme/style/methods.rs)、[状态实现](../../src/ui/theme/style/variant.rs)。以上来自文档与源码核查，不是新一轮视觉或性能验收。

## 总体设计

### 1. 声明、解析结果与运行态分离

- 样式声明必须保留字段是否出现；零、false、none、auto、默认枚举值均可作为显式覆盖，不能用等于默认值推断未声明。
- 采用最小必要的类型化差异表示和最终有效样式；可复用现有表示时不新增平行状态树。编译器拥有语法、类型与诊断，ui 运行时拥有解析、失效、布局与交互事实，graphics 消费解析后的绘制值。
- 同一入口内各类声明共享字段登记与覆盖规则。Rust 公开 API 和 `.uix` 经相同最终语义路径，禁止为了新语法复制布局或控件绘制。
- 沿用现有基础层关系：组件/主题默认 → class（从左到右，extends 先父后子）→ 内联声明。setStyle 沿用原入口的替换目标含义，清空后恢复原声明，不能积累上次分支字段。
- 活跃状态在基础结果上按 hover → focus → focus-visible → active → checked → disabled 逐字段叠加；同一字段后者优先，未声明字段保留低层结果。disabled 节点不进入 active。focus-visible 是既有焦点加输入方式判定，不建立另一套焦点所有者。
- 该次序保留旧 `.uix` 的相对次序，修正 Rust 单选状态层的差异；执行前用实际公开调用核对受影响行为。迁移既有调用和示例，避免默认按钮外观被无意重设计。若需要破坏公开类型/外部调用且无法局部兼容，先汇报具体影响，由维护者评估；不能以此停止不受影响部分。

### 2. 状态与组件一致性

首批统一 hover、focus、focus-visible、active、checked、disabled。状态来自现有事件、焦点和控件事实；指针移出/捕获丢失、失焦、禁用及节点移除时正确清理。checked 只用于有对应事实的控件，非法绑定仍编译诊断。

代表组件覆盖 Button、Input/TextArea、Checkbox/Switch、Select、Tabs、Container、Text；其它组件按实际消费统一 Style 的路径检查，不逐个复制状态实现。组件内部部位只使用明确公开的样式入口，不在本期引入通用后代选择器或允许任意穿透私有结构。

### 3. 主题与动效

- 对现有可插值颜色字段和数值字段开放类型匹配的 token 目标。先解析当前 Provider 有效值，再插值；明确采用与现有颜色插值一致的空间，不另建主题动画器。
- hover 中切主题、切局部 Provider、动画未完成再次变更，均从当前呈现值 retarget 到新目标；首次挂载不额外播放入场，时长零立即完成。
- token 改变按实际影响触发 Paint 或 Layout；无变化不重启，完成后停止帧调度，节点卸载取消并释放。
- 减少动效使用现有能力（若已存在）或最小显式配置，开启后跳至最终值。首批不承诺 auto/百分比尺寸动画，也不自动开放任意 transform/keyframes 插值。

### 4. 自适应尺寸与窗口断点

首批提供 `minWidth/maxWidth/minHeight/maxHeight`，统一 px、%、auto 的适用范围；补齐百分比 inset 与有界 `calc()`（长度加减，px 与 %，不接受任意函数和业务表达式）。测量/布局时保留单位和参照轴；未定父尺寸、嵌套百分比、零尺寸及 min>max 必须有明确规则和诊断，不能提前一律转成 f32 像素。

窗口级断点采用 `@media (min-width: …)` / `(max-width: …)`，允许 and 组合，长度为 px 或已登记 screen token；用逻辑客户区宽度，区间边界含等号。同一条件层按源码顺序合并，之后仍由内联和状态层覆盖。只依赖相关窗口尺寸与主题，不引入轮询；容器查询、任意 CSS media feature 不在本期。

补充 Grid `minmax()` 的有界组合（固定/比例下界，固定/fr 上界的可实现集合由 S3 明确），支撑卡片最小宽度；不以“支持 minmax”冒充完整 CSS Grid。首批不引入 auto-fit/auto-fill、隐式复杂轨道和文档流布局。既有 Flex/Grid 与绝对定位统一消费尺寸约束，不另加一套布局引擎。

### 5. 精细视觉

首批补齐四角圆角、`backgroundSize: cover/contain/auto/显式尺寸`、带角度的多色标线性渐变、多重外阴影。圆角按盒尺寸缩放，背景在相应圆角区域裁剪；边框和子树裁剪边界分别明确。backgroundPosition/Repeat 与新增 Size 可组合；cover/contain 的剩余空间可能为负，不按旧固有尺寸算法强行截断。

多阴影定义绘制次序与扩张/模糊边界，动画与 opacity 不丢失层级；资源释放和缓存按现有 graphics 合同。首批仍为单背景来源；多背景层、inset 阴影、滤镜、复杂 radial-gradient 和 3D 属后续候选，不作为本期完成条件。

### 6. 使用与诊断

扩展共享 schema、check、compile、query、fmt 和 LSP 中受影响能力；AOT 与已支持该能力的动态入口共用语义。动态入口确实不适用的部分给明确拒绝和支持表，不静默忽略，不把全部动态模块改造混入本期。

提供可定位到原 `.uix` 声明的错误；复用已有 query/诊断展示最终样式与来源的可行入口，在代表页面能查到来源 class/token/状态、解析尺寸与裁剪边界。不新增独立 DevTools 产品或常驻全树采样。文档须区分已支持、有限取值、明确不支持，移除与最终行为冲突的“完整”表述。

## 分阶段交付

按 S1 → S2 → S3 → S4 → S5 串行推进。实现者 实现/自检，现有 Codex 维护者管理语义、文档和必要复核；每阶段通过后自动续派下一阶段，无需用户重复批准常规细节。阶段不按不可信日期估工；前一阶段实测后可将过大的执行轮次在原任务内切小，不能只完成调查就关闭任务。

| 阶段 | 交付边界 | 必须看到的结果 |
|---|---|---|
| S1 声明与状态 | 显式默认覆盖、统一逐字段状态解析、六种状态、代表组件接入 | padding/圆角恢复零、opacity恢复1、none/auto恢复；focus+hover+disabled组合与清理；Rust/UIX一致 |
| S2 主题动效 | token过渡、局部主题变化、retarget、取消与减少动效 | 悬停中切主题连续、结束后静止、卸载释放；首次挂载/零时长正确 |
| S3 自适应布局 | min/max、单位和有限calc、百分比inset、窗口断点、有限Grid minmax | 窄/中/宽窗口内容不意外重叠，布局绘制命中一致；非法/循环尺寸确定处理 |
| S4 精细视觉 | 四角圆角、背景尺寸、多色标线性渐变、多外阴影 | cover/contain与定位组合、圆角裁剪及阴影边界实际可见；换图/主题后不残留 |
| S5 场景收口 | 在现有demo增加样式工作台，公开消费者验证，文档同步与资源比较 | 同页组合全部增量，能由公开接口实现，无临时私有hack；实际限制明确 |

关联任务由服务分配 ID 后列在文末。任务正文持有唯一验收标准及运行记录，本文不复制进度台账。

## 验证与完成条件

选择能发现语义错误的公开行为测试和必要编译负例，避免只断言生成字符串含有字段。S1–S4 每阶段围绕改动做必要验证，S5 复用有效证据，只补组合与回归缺口。项目已有必要检查照常完成，不把最小 feature、默认 feature 或单平台结果冒充全量通过。

代表场景为框架内“样式工作台”：工具栏/侧栏、表单、选中/禁用控件、长列表、封面卡片、弹层入口。使用合成数据与本地资源，不操作用户真实任务或媒体。窗口逻辑宽度至少 480/800/1280，亮暗主题与局部 Provider，鼠标和键盘焦点，长中文、滚动和窗口缩放；空闲/连续切换/关闭覆盖状态及资源生命周期。系统缩放至少核对可用环境的 1.0/1.25/1.5/2.0；不可用的真实平台列为未测，模拟尺度不冒充 OS DPI。

视觉验证必须记录具体二进制/源码、后端、尺寸和缩放，检查边框、圆角、裁剪、阴影、文字与命中位置。可用的原生窗口呈现优先；离屏图片、语义树与真实输入分别说明。既有视觉缺陷需按其实际复现输入单独核验，不能用工作台通过替代。

性能采用同机同输入对照，观察空闲帧调度、主题切换、窗口resize、代表长列表的响应、RSS及关闭回收。与本次改动有因果关联的明显退化需解释并修正；没有用户业务SLO不编造百分比门槛，不以单次样本保证长期稳定。

完成必须满足：五阶段任务按实际证据通过复核；规范/参考/主题、布局、动画架构与示例一致；样式工作台可独立构建运行；源码提交可追溯；未测平台与保留限制公开。仅解析成功、代码编译通过或属性表打勾均不构成整体完成。

## 执行、迁移与风险处理

- 复用现有 实现者 managed 桥接，前置阶段未通过时不放行后续；不创建第二执行器，不抢其它项目在途任务。维护者身份保持现有会话。
- managed 模式由桥接唯一写本任务执行结果。执行者只生成 `MPM_TASK_RESULT_FILE` 信封；review_policy=required 时成功提交 doing 等待复核，受阻提交 blocked，不直接写 done、不自己 PATCH/results 或修改任务文件。
- 开工读最新任务、源码指令和采用基线，保留无关修改。实现者仅提交本阶段已验证源码与测试，默认不推送；维护者复核后依既有内部仓库流程正常推送。正式包、tag/Release、安装部署及消费者升级不包含在本计划内。
- 长期文档由维护者通过版本化 API 更新，执行者在结果内给出准确语义变化与可用示例；经维护者明确交接某份文档后才可由执行者写。阶段内修改结果写任务，不额外创建报告、docs/evidence或样式机器台账。
- 原始日志、截图、临时探针、性能样本归源码 target 下；样式工作台等持续维护的代码归源码 demo/examples。已发布0.0.8制品、历史验收与其他消费者锁定保持可追溯。
- 核心风险：默认值迁移改变旧外观、状态叠加改变控件反馈、主题更新重排范围扩大、百分比尺寸循环、背景/圆角绘制与命中分离。按风险定点验证并在原任务修正；重大公共API破坏、渲染引擎替换或显著依赖扩张由维护者提交具体选择，不自行扩展本期。
- 不为本任务改变 SMC 规范、Scheme/动态扩展路线或其它产品。不因历史文档中的临时协作安排恢复旧双会话执行器。



## 已知主题度量边界

后续样式实现需区分 Custom(px) 与主题字号档位。若测量期缺少有效主题上下文，档位默认值只能是近似，不能宣称任意自定义主题下测绘一致；涉及布局 token 时应先明确现有度量路径及必要 API 影响，不新造第二套主题引擎。
