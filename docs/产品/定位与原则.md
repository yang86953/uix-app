## 定位

UIX 是一个 Rust 原生跨平台应用框架，目标是让同一套界面与应用逻辑运行在多个平台的原生窗口上。当前 `0.0.7` 发布范围是 Windows 与 Linux；这一定义不构成对 macOS 或移动端当前完成度的承诺。

跨平台复用的单位是完整应用，而不只是 Widget 树：UIX 统一应用组合根、生命周期、窗口与事件循环、平台能力、本地数据和运行保障；应用自身的业务规则、领域状态与服务编排继续由 Rust 持有。使用方可以在确有平台差异时消费显式 capability，但不应把窗口、渲染、输入或生命周期分支散落到普通应用逻辑中。

UIX 不把浏览器或 WebView 作为界面运行时。界面推荐用 uix-lang 描述并在正式构建时转换为 Rust；业务逻辑、领域状态、服务调用、导航与应用生命周期使用 Rust 实现。也可以直接使用 Rust 声明式 API 构建界面。框架通过自身图形管线绘制到原生窗口。“全栈”只表示 UI、应用壳和本地数据能力，不包含网络或同步。

**界面与业务开发方式**（产品方向声明）：

- **界面推荐方式**：uix-lang——用 `.uix` 文档描述界面结构、样式、展示数据、界面状态与局部交互；正式构建默认在编译期生成 Rust，不携带语言解释器（规范与边界见 [uix-lang 语言首页](../uix-lang/README.md)）。
- **业务实现方式**：Rust——持有业务规则、领域模型、持久化、网络与平台服务、异步任务、导航/窗口编排和应用生命周期；通过 props、回调或显式根输入向 UI 提供窄契约。
- **支持的界面方式**：Rust 声明式 API——需要直接使用完整组件能力时，也可在 Rust 中构建界面；uix-lang 已登记能力映射到相同的 Rust UI 语义。

UIX Lang 不因编译目标也是 Rust 而取得业务职责：生成代码只负责构造和连接 UI。事件需要业务处理时，界面调用 Rust 提供的类型化回调或能力；业务结果再通过 State / props 驱动界面更新。长期边界见 [UIX Lang 语言边界](../uix-lang/设计/语言边界.md)。

## 目标用户

- 当前需要用 Rust 构建 Windows 或 Linux 桌面应用的开发者
- 希望复用大部分界面与应用逻辑，并把平台差异收敛在框架边界内的团队
- 在乎应用体积和资源消耗
- 想要声明式 UI，但不要 WebView 或 JavaScript

当前不适合作为首选方案的场景：需要复用现有 Web 前端、依赖框架内建网络/云同步、立即交付移动端，或需要以开源许可向外部分发 UIX 本身。相关边界见[能力与边界](能力.md)和[交付与许可](交付与许可.md)。

## 方案取舍

| 对比方向 | UIX 的选择 | 需要同时考虑 |
|---|---|---|
| Electron | 不捆绑浏览器内核，使用 UIX 自身的布局与绘制管线 | 实际体积、内存和启动速度取决于应用内容、资源、后端与构建配置，不承诺固定倍数 |
| Tauri | 不使用 HTML/CSS/JavaScript 作为界面技术栈，界面由 uix-lang 或 Rust 描述 | 无法直接复用 Web 组件生态；UIX Lang 只映射 UIX 自身语义 |
| Qt 等跨平台原生框架 | 以 Rust 类型和 Cargo 工具链为中心，提供声明式界面与统一平台契约 | UIX 当前为早期 `0.0.7` 版本，生态、平台覆盖和成熟度需单独评估 |
| Win32 等平台 API | 将平台差异封装在框架边界内，减少应用层条件分支 | 需要精确使用平台专属能力时，仍受 UIX 当前公开能力范围限制 |

## 原则

1. **资源优先**——空闲时进入休眠；重绘、缓存和后台工作必须有明确触发条件与生命周期。
2. **Rust 业务优先**——uix-lang 在编译时转换为 Rust，但只描述 UI；业务逻辑由 Rust 持有。运行期不引入第二套业务语言解释器，可静态检查的 UI 错误尽量在编译期暴露。
3. **原生优先**——上层契约不散落平台条件分支，平台差异由明确边界吸收；平台本身不支持的能力返回可识别错误。
4. **容错可观测**——失败有类型和责任边界，恢复有明确路径，最终失败可以形成报告。
5. **使用方按需编译**——未选择且非传递必需的能力不进入使用方编译图；已选择能力中最终不可达的代码和数据由 release 链接裁剪。运行时关闭能力不能替代编译期裁剪。
6. **最小外部依赖**——外部 crate 只在自研代价与风险显著高于引入收益时引入；新增依赖须论证登记，基线口径计数不得净增长。削减目标、基线与保留清单见 [依赖治理](../架构/依赖治理.md)。
