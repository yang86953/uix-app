## 定位

UIX 是一个跨平台 App 框架。写一套代码，跑在多个平台的原生窗口上。

不像 Electron 那样绑一个浏览器进来，也不像 Tauri 那样依赖 Web 技术栈。界面用 uix-lang 描述（编译时转换为 Rust），框架直接画在原生窗口上。全栈指 UI + 应用壳 + 本地数据，不含网络和同步。

**界面描述方式推荐等级**（产品方向声明）：

- **推荐**：uix-lang——用 `.uix` 文档描述界面结构与样式，编译时由框架自动转换为 Rust（规范见 [uix-lang 语言规范](../uix-lang/README.md)）。
- **不推荐**：直接书写 Rust 声明式 API 描述界面——保留为底层入口，供自定义组件、画布绘制与高级场景使用；转换器落地前它是唯一可用入口。

## 目标用户

- 用 Rust 写桌面/移动端应用的开发者
- 需要跨平台，但不想为每个平台维护不同代码
- 在乎应用体积和资源消耗
- 想要声明式 UI，但不要 WebView 或 JavaScript

## 竞品对比

- **vs Electron**：没有浏览器内核，体积和内存是数量级差距
- **vs Tauri**：不需要 HTML/CSS/JS，全部逻辑在 Rust 里
- **vs 原生（Qt/Win32）**：声明式写法更简洁，一套代码跨平台

## 原则

1. **资源优先**——好用是底线，但资源消耗是第一位。空闲必须真休眠，不做多余绘制，不浪费内存
2. **Rust 优先**——没有第二门运行语言。界面描述语言 uix-lang 在编译时转换为 Rust，运行期只有 Rust；类型系统在编译期保证正确性
3. **原生优先**——上层代码不感知平台差异，不把平台 ifdef 散落各处
4. **容错可观测**——出错有类型，恢复有路径，崩溃有报告
5. **使用方按需编译**——UIX 作为应用依赖时，未选择且非传递必需的能力不进入使用方编译图；已选择能力中最终不可达的代码和数据不进入 release 目标程序。运行时关闭某项能力不能替代编译期裁剪
