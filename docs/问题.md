# 问题

## 状态与入账规则

- 状态流：`待确认 -> 已确认 -> 修复中 -> 待验证 -> 已关闭`；无法继续时使用 `阻塞`。
- `待确认` 需要直接证据；`已确认` 需要从已知基线完成最小复现。
- 已改产物只进入 `待验证`；原始复现和至少一个相邻场景通过后才进入 `已关闭`。
- 工具限制、环境/驱动问题和测试数据问题保留在单次报告的限制章节，不作为产品问题入账。
- 重复、非问题、无法复现或明确不修复的条目保留原 ID，并在关闭记录中注明原因。
- 严重度按用户/项目影响判断；禁止把单机或单后端结果外推为跨平台结论。
