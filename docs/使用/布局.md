# 布局

[← 返回使用 索引](../使用.md)

> **接口**：声明 UIX 布局系统的公开用法——column/row 容器、Flex 伸缩、Grid（含响应式）、Splitter、Affix/Sider、ScrollView 和 VirtualScroll。依赖：[响应式基础](响应式基础.md)。导出：布局引擎架构 → [架构 · 布局引擎](../架构/ui/layout.md)。

## 容器

| 容器 | 行为 |
|------|------|
| `column` | 子项沿纵轴排列；内容高度优先，剩余空间按显式伸缩规则分配 |
| `row` | 子项沿横轴排列；交叉轴对齐与溢出策略由容器统一决定 |
| Flex | 支持主轴/交叉轴对齐、间距、grow、shrink 与 basis |
| Grid | 支持固定、内容自适应、比例和响应式列；轨道尺寸由内容需求与父级可用空间共同解析 |
| Splitter | 用指针或键盘调整相邻面板比例，并保持最小尺寸 |
| ScrollView | 持有滚动偏移、视口和内容范围，不把滚动状态藏在业务组件中 |
| VirtualScroll | 只物化可见区附近项目，以稳定 key 复用行状态 |

Flex 的 `overflow_content` 模式保留子项自然主轴尺寸，不执行主轴增长或压缩；`Start`/`Center`/`End`/`Space*` 分布、交叉轴对齐、gap、反向方向和逐项 `align_self` 仍然生效。实际主轴小于自然内容时，Center/End 保留负剩余空间并分别向主轴起点外溢一半或全部差值，Start 与 Space* 保持起点和基础 gap；零尺寸 bootstrap 不应用负偏移。交叉轴 Center/End 会先扣除两侧 margin，再在剩余区域内定位子项；固定主轴按容器长度镜像反向顺序，单行 `overflow_content` 的零主轴 bootstrap 则始终按自然内容长度镜像，即使直接构造 `FlexLayout` 且没有额外设置 `intrinsic_main`。零交叉轴 bootstrap 会由子项自然外尺寸撑开，默认 Stretch 不会把内容压成零。没有子项时，固定尺寸 Flex 继续占用父级分配的两条轴；`intrinsic_main` 或 `overflow_content` 只把自然主轴收敛为零，交叉轴仍保留父级分配尺寸，反向方向遵守同一规则。

启用 `wrap` 不改变未实际换行时的交叉轴 Stretch：单行仍扣除 margin 后填满容器。形成多行且容器交叉轴还有正剩余空间时，默认 Stretch 会在保留固定行间 gap 后把空间均分给各行；逐项 `align_self` 只覆盖子项在扩展行盒内的尺寸与位置，不取消其他行的扩展。单行与换行路径最终都会用子项交叉轴 `min_size` / `max_size` 约束 Stretch 候选尺寸；行盒仍消费容器剩余空间，达到最大值的子项停在行盒起点而不会被继续拉大。非 Stretch 行组超过实际交叉轴时，Center/End 仍保留负剩余空间：Center 向两端等量溢出，End 让最后一行末端贴住容器末端；零交叉轴 bootstrap 尚无实际对齐范围，两者都从自然起点开始并由自然行组撑开输出。零主轴尺寸子项仍算作当前行中的一个项目；后续子项连同 gap 超过主轴上限时会正常另起一行，不会因累计占用为零而吞掉换行边界。

当 `wrap` 已开启但所有子项最终仍落在同一行、且容器已经获得实际交叉轴尺寸时，唯一行盒直接使用完整容器交叉轴；因此较小容器会像 non-wrap 一样让 Stretch 在扣除 margin 后收缩，逐项 `align_self: Center/End` 也相对真实容器定位。对 `overflow_content` 而言，只要没有实际分行，wrap 开关在四种方向、七种主轴分布、四种交叉轴对齐以及主轴/交叉轴 bootstrap 下都不改变子项矩形或自然尺寸账本。真正形成多行后，Row 与 Column、RowReverse 与 ColumnReverse 在交换 frame、子项尺寸及四侧 margin 的两轴时仍保持子项矩形和总尺寸账本完全转置；该关系覆盖全部主轴分布、交叉轴对齐、逐项 `align_self`，以及交叉轴宽裕、溢出和零尺寸 bootstrap。反向方向以实际容器主轴末端为镜像边界，物理 margin 仍附着对应侧；若同时交换每项主轴起止 margin，RowReverse/ColumnReverse 的每行结果就是 Row/Column 的精确物理镜像，内容总尺寸不变。`overflow_content` 还会在公开布局边界冻结所有子项的 `flex_grow` / `flex_shrink`；即使声明负值、极大值或非有限值，实际分行仍只由自然外尺寸与 gap 决定，子项矩形和内容总尺寸不会因弹性因子改变。有限负 gap 会让相邻行或列按声明值重叠；自然交叉轴总尺寸取所有行盒物理末端的最大值，而不是最后一行的末端，因此较高的前行、较宽的前列仍完整进入滚动内容范围。自然外尺寸仍保留在内容总尺寸账本中，多行继续采用自然行组分布规则。

实际多行的 `overflow_content` 同样遵守“负尾侧 margin 不裁剪可见矩形”：负下外边距或负右外边距可以让下一行或下一列提前开始，但自然交叉轴总尺寸还会覆盖所有已放置子项的最远可见末端。比如 30px 高/宽的首项带 -10px 尾侧交叉轴 margin、后续 5px 子项按 20px 行盒推进时，内容账本仍为 30px，而不是后续子项末端的 25px。

负尾侧主轴 margin 也只缩短兄弟项的自然推进与换行占用，不裁剪当前子项自身的可见末端。比如 30px 宽/高的首项带 -10px 右/下 margin 时，其自然占用仍是 20px；后续 10px 子项会在 25px 主轴 frame 中换到下一行/列，但自然主轴总尺寸仍覆盖首项完整的 30px，而不是停在 20px。该可见末端账本独立于 justify 偏移与反向方向的物理放置。

`Container` 与 `Space` 都让子项 margin 参与 Flex 占位；正右/下 margin 会进入下一轮内容尺寸缓存，负尾侧 margin 只改变兄弟推进而不会裁掉子项自身可见范围。因此无固定宽高的内容容器可由完整外尺寸稳定撑开。

`RichText` 的固有高度随当前宽度约束重新折行；同一实例从宽区域进入窄区域时，测量缓存不会复用旧行高。估算测量刷新后，旧行坐标与代码复制命中区域立即失效，下一次绘制再以相同宽度和真实字体度量重建几何，避免文字已换行而父级仍按旧高度裁切。

`Notification` 的 384px 是设计上限，不是窄窗口中的强制宽度。组件会先从实际窗口宽度扣除左右各 24px 留白，再以 384px 封顶；绘制、浮层边界、脏区与命中测试都复用这一条目矩形，因此 400px 宽窗口中的通知为 352px 宽并位于 `x=24px`。

`Table` 的选择列先绘制，普通列区再按中间滚动区、左固定区、右固定区依次覆盖，物理行展开箭头最后绘制。两层表头会在每个列区内先绘制有标题分组、再绘制叶表头，然后才进入更高层列区；因此后声明的左固定组不会覆盖右固定组，跨两层的左固定单列也不会越过列区层级遮住右固定分组标题。跨行合并锚点在物理行背景之后补绘时只使用该列区最终仍可见的片段，所以左固定合并单元格不会反向遮住已绘制的右固定列。普通文本列的 `col_span` 会按全部覆盖列的真实物理位置求联合矩形，再按 Middle → Left → Right 分片补绘；右固定锚点即使先声明，也能向左覆盖后声明的左固定列，并与覆盖列命中返回同一锚点。自定义 View 跨固定区时仍只布局一个完整跨度的状态子树，父布局把最终可见的多个区片段交给合成、可见性与命中链共同约束；片段间隙不会穿透完整 frame 包围盒。窄视口使固定列互相重叠或侵入 32px 选择区时，单元格、选择动作与列宽调整句柄都按视觉层级选择最后绘制的列；只有没有可见列覆盖的选择区才响应复选框。可展开表格的真实数据行尾部 32px 交互区优先切换展开，即使该区域覆盖选择列或普通单元格；表头与展开内容区不产生展开动作。不同固定区的调整线重合时也优先选择上层列区，再在同一列区内按指针距离选择句柄。

声明协调移除最后一个直接子项时，`Container`、`Space`、`Affix` 会立即清除旧内容占位，`ScrollView` 会把内容范围、运行态偏移及受控偏移归零，`Carousel` 也会清除旧幻灯片数量；不需要等待下一轮空布局，且自定义轮播箭头不会被计为幻灯片。

## Grid

```rust uix-compile=layout-grid
use uix::prelude::*;

// 按列轨道声明布局，子项用 tree! 包裹
embed(tree! { Grid::new()
    .columns(vec![GridTrack::Fr(1.0), GridTrack::Fr(2.0)])
    .gap(8.0) => [
        label("1fr"),
        label("2fr"),
    ]
});

// 响应式 24 栅格：断点列宽声明式表达
embed(Grid::responsive()
    .cols(vec![
        Col::new().span(24).sm(12).md(8).lg(6),
        Col::new().span(24).sm(12).md(8).lg(6),
    ])
    .gap(4.0));
```

Grid 支持固定（`GridTrack::Px`）、比例（`GridTrack::Fr`）与自动（`GridTrack::Auto`）轨道；`Auto` 取子项的有限测量外尺寸（含 margin），纯 `Auto` 网格保持内容尺寸而不自动填满父容器，`Fr` 则分配扣除固定轨道、`Auto` 与 gap 后的剩余空间。跨多条且不含正权重 `Fr` 的子项会在所覆盖的 `Auto` 轨道间均分尺寸缺口；同时覆盖 `Auto` 与部分正权重 `Fr` 时，若 span 外还有竞争 `Fr`，Grid 会在父级容量内把外部可让份额转入 span 内 `Auto`，避免自然尺寸被无谓裁剪。`Grid::justify(...)` 对齐整组列轨：Start/Center/End 控制轨道组起点，SpaceBetween/SpaceAround/SpaceEvenly 分配正剩余空间，Stretch 只扩展 `Auto` 列而不拉伸单元格内子项；没有可扩展 `Auto` 时保持 Start。`Grid::responsive()` 提供 24 栅格断点列宽。

当 span 覆盖全部 `Fr`，或 span 内没有 `Auto` 可承接外部份额时，Grid 保持作者声明的 `Fr` 权重并服从父级容量；子项按实际单元格收敛，不把自然尺寸隐式写成 `Fr` 轨道最小值。列跨度和行跨度遵守同一规则。

Grid 子项可用 `.align_self(...)` 覆盖容器级交叉轴对齐；覆盖值会进入单元格求解，并在扣除上下 margin 后的可用高度内执行 Start/Center/End/Stretch。

Grid 放置使用有界资源窗口：每轴最多解析 4096 条轨道，稠密占用账本最多 65,536 个单元格，因此列数增加时可用行数可能更小。超限显式列/行只保留窗口内部分，`grid_cell` 收敛到最后一个可地址单元格，column/row span 收敛到起点后的剩余轨道。自动放置耗尽整个窗口且没有完整空闲矩形时，该子项保留零 frame，不通过重叠或无界扩行伪造放置成功。

## Splitter

```rust uix-compile=layout-splitter
use uix::prelude::*;

// 可拖拽分割面板：声明面板数与最小尺寸（component，直接 embed）
embed(Splitter::new()
    .panels(2)
    .min_size(0, 120.0)
    .vertical(false));
```

Splitter 用指针或键盘调整相邻面板比例，并保持最小尺寸；方向可用 `.vertical(true)` 切换。

## Affix / BackTop / Sider

```rust uix-compile=layout-affix
use uix::prelude::*;

// 固钉：滚动越过阈值后固定在视口（子节点包裹）
embed(ViewNode::new(
    Affix::new(12.0).scroll_y(180.0),
    vec![button("回到操作").into()],
));

// 回到顶部：滚动高度超过阈值后显示
embed(BackTop::new().visibility_height(400.0));
```

应用壳组件：`Sider`（可折叠侧边栏）、`Header`（顶部）、`Content`（主内容）、`Footer`（底部）通过 `Layout` 组合成标准应用骨架。

## 滚动

```rust uix-compile=layout-scroll
use uix::prelude::*;

// 滚动容器：内容超出时出现滚动条
scroll(column(
    (0..100).map(|i| label(format!("行 {i}"))).collect::<Vec<_>>(),
))
.height(300.0);

// 虚拟滚动：只物化可视区行
embed(VirtualScroll::new()
    .item_count(100_000)
    .item_height(24.0)
    .render(|index| label(format!("行 {index}")).height(24.0))
    .build());
```

ScrollView 持有滚动偏移、视口和内容范围：纵向与双向模式按纵列排布，横向模式按单行排布；四侧 margin 会推开兄弟，非滚动轴填充会先扣除两侧 margin。经典沟槽滚动条出现时，双轴最大滚动距离按扣除对侧沟槽后的真实内容视口计算，不会让末端内容少滚一个沟槽。

VirtualScroll 只物化可视区附近项目，单次最多保留 4096 行，并让可见内容优先于 overscan。正常有限输入保持请求的双侧 overscan；行高或 viewport 为 NaN、无穷、零或负值时返回空窗口，不把非法几何写入子 frame。需要可变行高时，在固定 `.item_height(...)` 估算值基础上调用 `.variable_height()`；已物化子项的测量高度会进入稀疏缓存，测量版本变化可通过 `.measurement_version(...)` 触发失效。普通 `.render(...)` 由框架按绝对索引统一拥有节点身份与组件私有状态，只适合顺序不可变的数据；renderer 不得自行给行根设置 key。数据可能排序、插入或删除时必须使用 `.render_keyed(key_fn, renderer)`，键工厂会在行构建前提供业务稳定 key，并让窗口协调和组件私有状态使用同一身份。业务 key 必须在整个数据集中唯一、稳定。大数据集一律虚拟化（资源优先）。

## 保留的布局约束

这些约束与实现语言无关，并与 Rust `layout` / `virtualization` 架构一致：

- 所有公开布局值使用 logical 坐标；DPI 换算留在窗口与呈现边界。
- 子项测量先收窄约束再返回有限尺寸；NaN、无穷和负尺寸不得进入后续布局。
- 固有内容测量只回答内容需求，不绕过父级约束。
- 溢出、裁剪、嵌套滚动与 overscroll 必须由最近的容器明确拥有。
- 虚拟列表以业务稳定 key 保留可变数据的状态；绝对索引后备 key 只用于顺序不可变的数据，当前窗口内的局部位置不能替代身份。
- 声明更新只改变 `Label` 颜色或 `Container`/`Grid` 背景等纯视觉字段时只重绘；文本、尺寸、盒模型、Flex/Grid 属性、轨道或可见性变化会重新布局。其余内建组件、`Unknown` 与 `Custom` 快照显式采用保守 Layout + Paint，补齐字段测试前不会静默吞掉未知几何变化；完整矩阵见[架构布局失效分类](../架构/ui/layout.md#失效分类矩阵)。

完成度与性能测试见 [Vikunja 项目 4](https://yang-server.tail9d5559.ts.net:3456/projects/4)。

## 理想使用方式

按产品定义（资源优先、Rust 优先），理想布局写法：

```rust uix-compile=layout-app-shell
use uix::prelude::*;

// 应用壳 + 响应式栅格 + 虚拟化大列表
fn app_shell() -> ViewNode {
    row((
        embed(Sider::new(200.0).collapsible(true)),
        column((
            embed(Header::new(48.0).title("工作台")),
            embed(Content::new().child(
                Grid::responsive()
                    .cols(vec![
                        Col::new().span(24).sm(12).md(8).lg(6),
                        Col::new().span(24).sm(12).md(8).lg(6),
                        Col::new().span(24).sm(12).md(8).lg(6),
                    ])
                    .children(cards()),
            )),
        )).flex_grow(1.0),
    ))
}
```

- 布局状态（滚动偏移、折叠、splitter 比例）由框架/组件持有，业务代码不复制一份。
- 大数据集一律虚拟化：VirtualScroll 以 4096 行硬上限物化可视区，长列表不整棵渲染。
- 响应式断点声明式表达，不在业务代码里做平台/尺寸 ifdef。
