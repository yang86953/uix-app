# 多窗口

→ [使用总览](../使用.md)

窗口客户区尺寸、布局、指针与 resize 都使用 logical 坐标；每窗 drawable 随所在显示器的 DPI 独立变化。应用无需监听 DPI 消息或手工缩放窗口内容。

## 自定义标题栏

Windows 主窗调用 `.custom_title_bar(true)` 隐藏系统标题栏，再用普通 View 组合自己的标题栏。框架会把客户区扩到外窗边缘（保留边缘缩放命中），绘制内容应贴齐窗口四边，不在四周留下透出桌面的非客户区空隙。`window_drag_region` 把展示内容变成原生拖动区域；`window_control` 提供最小化、最大化 / 还原和关闭，外观仍完全由应用决定。仓库内 `cargo run --release --bin uix-demo` 默认运行同一模式，可直接查看完整组合：

```rust uix-compile=custom-title-bar
use uix::prelude::*;

fn title_bar() -> ViewNode {
    row((
        window_drag_region(
            label("My App")
                .font_size(14.0)
                .padding_h(12.0),
        )
        .flex_grow(1.0)
        .height(40.0),
        window_control_named(
            WindowControl::Minimize,
            "最小化窗口",
            embed(Icon::new("minus").size(14.0)),
        )
            .width(46.0)
            .height(40.0)
            .bg_hover(Color::hex("#E5E7EB"))
            .bg_focus(Color::hex("#FFF4CE"))
            .bg_active(Color::hex("#D1D5DB")),
        window_control_named(
            WindowControl::MaximizeRestore,
            "最大化或还原窗口",
            embed(Icon::new("maximize-2").size(14.0)),
        )
            .width(46.0)
            .height(40.0)
            .bg_hover(Color::hex("#E5E7EB"))
            .bg_focus(Color::hex("#FFF4CE"))
            .bg_active(Color::hex("#D1D5DB")),
        window_control_named(
            WindowControl::Close,
            "关闭窗口",
            embed(Icon::new("x").size(14.0)),
        )
            .width(46.0)
            .height(40.0)
            .bg_hover(Color::hex("#E81123"))
            .bg_focus(Color::hex("#FFF4CE"))
            .bg_active(Color::hex("#C50F1F")),
    ))
    .height(40.0)
    .align(AlignItems::Center)
}

App::new()
    .title("My App")
    .size(900, 600)
    .custom_title_bar(true)
    .root(|| column((
        title_bar(),
        label("窗口内容").padding(24.0).flex_grow(1.0),
    )))
    .run();
```

拖动区可放普通展示内容，也可嵌入独立交互控件：命中子控件时由子控件处理，命中未处理输入的内容时才开始拖窗；左键双击同一区域会切换本窗最大化 / 还原，右键在同一区域按下并释放会显示本窗原生系统菜单。内层交互控件若处理右键，则保留自己的上下文菜单。拖窗、标题栏双击和原生系统菜单都不会改变正文中已有的键盘焦点，应用无需自行计时、计数、维护窗口状态或绘制系统菜单。窗口控制包装器自身接管鼠标与键盘，内部 View 只负责展示，不应再嵌套 `button` 等交互控件；即使误放，展示子树也不会形成可命中的嵌套控件或重复语义节点。`bg_hover` / `bg_focus` / `bg_active` 分别声明悬停、焦点与鼠标按住或 Enter / Space 激活期间的背景；按压优先于焦点，焦点未声明专用颜色时沿用当前悬停色或 `bg`。指针在控件外松开会取消动作，鼠标与键盘按下 / 松开不得交叉配对。`window_control` 自带英文无障碍名称；标题栏使用图标或需要本地化时，改用 `window_control_named` 显式命名。两者都只在语义树中暴露包装器自身这个可 `Invoke` 的具名 `Button`，调用仍走同一键盘事件与逐窗 `WindowAction` 路径。关闭动作进入正常窗口关闭事件，框架会先释放图形与窗口会话。最小化后本窗按 `Suspended` 规则停掉 layout / paint / present（详见[架构 · 主循环](../架构.md#主循环要点)）；还原只唤醒本窗。

副窗同样逐窗 opt-in：

```rust uix-compile=custom-title-bar-child-window
fn open_tool_window(handle: &AppHandle) {
    let child = WindowConfig::new("工具", 480, 320, || label("工具内容"))
        .custom_title_bar(true);
    let _ = handle.open_window(child);
}
```

当前自定义标题栏已落地 Windows backend；其他 backend 未实现该原生能力时会返回 typed error，不静默显示系统标题栏冒充成功。

在 `on_start` 中获取句柄：

```rust uix-compile=open-window-on-start
App::new()
    .on_start(|handle| {
        // 打开第二个窗口
        let _win2 = handle.open_window(
            WindowConfig::new("子窗口", 400, 300, || label("我是第二窗口"))
        );
    })
    .root(|| label("主窗口"))
    .run();
```

窗口间通信通过各自 `AppHandle`（详见[定时与异步](定时与异步.md)）：

```rust uix-compile=inter-window-post
use std::time::Duration;

fn connect_windows(handle_a: &AppHandle, handle_b: AppHandle) {
    handle_a.run_after(Duration::from_secs(1), move || {
        handle_b.post_to_ui(|| { /* 更新 B 的状态 */ });
    });
}
```
