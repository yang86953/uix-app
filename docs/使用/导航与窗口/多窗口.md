# 多窗口

[← 返回使用索引](../../使用.md)

> **接口**：声明 UIX 多窗口的公开用法——窗口创建、跨窗通信、自定义标题栏与窗口控制。依赖：[响应式基础](../入门/响应式基础.md)。导出：多窗架构 → [架构 · 托管与多窗](../../架构/app/window.md)。

窗口客户区尺寸、布局、指针与 resize 都使用 logical 坐标；每窗 drawable 随所在显示器的 DPI 独立变化。应用无需监听 DPI 消息或手工缩放窗口内容。

## 已落地示例

```rust uix-compile=multi-window-open
use uix_app::prelude::*;

// 在事件回调中打开第二个窗口；open_window 返回新窗口的 AppHandle
let window_handle = handle.clone();
button("打开设置窗口").on_click_fn(move || {
    // 请求创建设置窗口，并保留平台返回的 typed 结果。
    let open_result = window_handle.open_window(
        // 用拥有型配置声明新窗口标题、逻辑尺寸与根视图。
        WindowConfig::new("设置", 480, 360, || column((label("设置面板"),))),
    );
    // 显式处理窗口创建失败，不把平台或资源错误伪装成成功。
    if let Err(error) = open_result {
        // 示例输出完整 typed error；产品应用应转为可操作的用户反馈。
        eprintln!("open settings window failed: {error}");
    // 结束窗口创建错误处理分支。
    }
});

// 跨窗共享状态：业务 State 在所有窗口共享
let theme = State::new(false);
// 任一窗口切换主题，其他窗口只重绘语义色节点
let _ = handle.set_theme(if dark { Theme::antd_dark() } else { Theme::antd_light() });
```

```rust uix-compile=multi-window-lifecycle
use uix_app::prelude::*;

fn activate_if_open(handle: &AppHandle) -> Result<(), Error> {
    // is_open 是瞬时快照；请求仍须保留关闭竞态的 typed 失败。
    if handle.is_open() {
        handle.request_activate()?;
    }
    Ok(())
}
```

`request_activate` 只把激活请求投递给该窗口的 owner thread；成功不承诺窗口管理器最终授予焦点。
旧句柄关闭后稳定返回 `InvalidState`，不会按标题或创建顺序重定向到另一个窗口。

```rust uix-compile=multi-window-control
use uix_app::prelude::*;

// 标准窗口控制组合：按顺序创建最小化、最大化/还原、关闭按钮
let controls = window_controls(true, true, true);

// 深色标题栏表面需要显式指定图标前景色以保持对比度
let dark_controls = window_controls_with_icon_color(true, true, true, "#E7F2ED".into());

// 单独定制关闭控件时使用带无障碍名称的窗口交互包装器
let close = window_control_named(WindowControl::Close, "关闭窗口", button("×"));

// 可拖拽区域：自定义标题栏需要为移动提供等价行为
window_drag_region(column((label("自定义标题栏"),)).height(40.0));

// 调整大小热区：四条边和四个角分别放置对应方向的透明命中区域
window_resize_region(
    WindowResizeEdge::BottomRight,
    space(12.0).width(12.0),
);
```

## 自定义标题栏

自定义标题栏仍需为移动、调整大小、最小化、最大化和关闭提供平台等价行为；可拖拽区不能覆盖交互控件。使用 `window_resize_region` 在四条边及四个角放置 `Top`、`Bottom`、`Left`、`Right`、`TopLeft`、`TopRight`、`BottomLeft`、`BottomRight` 热区，框架会设置对应光标并把主按钮手势交给原生窗口管理器。窗口控制必须有可读无障碍名称和键盘等价入口，不能只依赖图标或指针命中。Agent / 无障碍 `Invoke` 会直接进入该控件声明的类型化窗口动作，不经坐标点击、字符串命令或键盘事件猜测默认行为；平台最终状态仍由窗口生命周期事实确认。

## 窗口所有权

每个窗口由独立 `WindowSession` 持有布局、焦点、输入、呈现和关闭状态。共享应用服务不能反向借用窗口私有对象。

## 跨窗通信

跨窗共享业务状态或通过 `AppHandle` 投递拥有型消息；不直接传递 raw window、surface、焦点句柄或短生命周期事件上下文。

## 关闭顺序

关闭先停止新输入和新帧，再取消窗口任务与订阅，释放 UI/graphics 资源，最后销毁原生窗口。一个窗口关闭不能使其他窗口的会话、swapchain 或计时器失效。

## 平台限制与失败

- `open_window`、`request_activate`、窗口状态动作和自定义标题栏初始化都可能返回 typed error；调用方
  必须保留并展示可操作原因。`is_open` 只是瞬时快照，不能替代后续请求的失败处理。
- Wayland 等窗口系统可能不允许普通客户端设置绝对位置；缺少能力时返回可识别错误或由 compositor 放置，不伪造移动、居中成功。
- 跨窗共享 `State` 会让全部消费窗口观察同一业务值；包含敏感或窗口私有数据时应缩小共享范围，不把焦点、输入会话或原生资源放入共享状态。
- 窗口关闭后，旧 `AppHandle`、窗口代际和投递目标可能失效；迟到任务应处理失败，不能重定向到另一个相似窗口。

## 推荐用法

按产品定义（原生优先、容错可观测）：

```rust uix-compile=multi-window-config
use uix_app::prelude::*;

// 窗口即配置，多窗共享状态与主题
let settings_window = WindowConfig::new("设置", 480, 360, settings_page)
    .custom_title_bar(true);        // 声明式自定义标题栏

App::new()
    .root(main_page)
    .on_start(move |handle| {
        // 需要时再打开，不预建窗口
        let _ = handle.open_window(settings_window);
    })
    .run();
```

## Wayland 桌面 layer surface

桌面外壳可通过平台中立的 `WindowSurfaceRole` 与 `DesktopLayerConfig` 创建壁纸、面板、
启动器或覆盖层。前置条件是 Linux Wayland 合成器提供 `zwlr_layer_shell_v1`；`OnDemand` 键盘
交互另要求协议 v4。普通应用窗口
继续默认使用 `WindowSurfaceRole::Toplevel`，无需修改。

```rust
use uix_app::prelude::*;

let top_bar = DesktopLayerConfig::new(DesktopLayer::Top)
    .anchor(DesktopAnchor::Top, true)
    .anchor(DesktopAnchor::Left, true)
    .anchor(DesktopAnchor::Right, true)
    .exclusive_zone(36)
    .keyboard_interactivity(DesktopKeyboardInteractivity::OnDemand)
    .namespace("uixos-top-bar");

App::new()
    .title("UIX OS 顶栏")
    .size(0, 36)
    .surface_role(WindowSurfaceRole::DesktopLayer(top_bar))
    .root(|| label("顶栏"))
    .run();
```

合成器会决定输出与最终尺寸；锚定相对两边时可把对应初始宽或高设为 `0`。正独占区只对有效
边缘锚定组合有意义，`-1` 用于壁纸或锁屏一类不避让其他独占区的 surface。缺少 layer-shell
时创建稳定返回 `Errc::NotImplemented`；保留负数（小于 `-1`）、空 namespace、超过 128 字节
或包含 NUL 的 namespace 在发送协议请求前拒绝。Windows、macOS 与不支持该协议的 Wayland
合成器不会把桌面角色降级成普通窗口，避免面板错误地出现在应用窗口层。

- 多窗共享业务 `State` 与 App 主题；窗口私有对象（session、swapchain）不跨窗传递。
- DPI 由每窗独立处理，应用代码始终写 logical 坐标。
- 关闭顺序由框架保证：先停输入帧，再释放资源，最后销毁原生窗口。
- 窗口创建和状态动作处理 typed error；平台不支持的定位能力按稳定降级展示。

上述所有权、DPI 隔离和关闭约束为语言无关约束，并与 Rust [window 模块](../../架构/app/window.md)一致。
