# 定时与异步

[← 返回使用索引](../../使用.md)

> **接口**：声明 UIX 定时器与异步的公开用法——Timer、post_to_ui 和异步加载模式。依赖：[响应式基础](../入门/响应式基础.md)。导出：生命周期边界 → [不必做](../能力与边界/不必做.md)。

## 定时器

```rust uix-compile=app-timers
use uix_app::prelude::*;
use std::time::Duration;

fn schedule_work(handle: &AppHandle) {
    let detached = handle.run_after(Duration::from_secs(2), || {
        // 2 秒后执行
    });
    detached.detach(); // 不受 drop 影响

    let cancelled = handle.run_interval(Duration::from_millis(100), || {
        // 每 100ms 执行
    });
    cancelled.cancel(); // 显式取消
}
```

`handle` 必须来自目标窗口的 App 启动/事件边界。窗口会话拥有调度队列，应用决定计时器属于页面还是整个窗口：保留 `TimerHandle` 时 Drop/cancel 取消排队项并释放其捕获；`detach(self)` 消耗句柄并放弃 Drop 取消，不能再用已消费的句柄取消。一次性任务完成或所属窗口会话回收时才结束其剩余生命周期，**普通页面卸载不自动取消窗口计时器**。已开始执行的同步回调不是可强制抢占的外部任务。

## 跨线程回 UI

从任意线程更新 UI 状态，只走 `post_to_ui`：

```rust uix-compile=background-post-to-ui
use uix_app::prelude::*;

fn load_in_background(handle: &AppHandle, data: &State<u32>) {
    let handle_clone = handle.clone();
    let data = data.clone();
    std::thread::spawn(move || {
        let result = 42;
        handle_clone.post_to_ui(move || {
            data.set(result);
        });
    });
}
```

`post_to_ui` 绑定目标窗口的 `WindowSession`，不会唤醒其他窗口。当前返回 `()`，不是接纳、执行或呈现回执；窗口关闭会清空未执行队列，向已关闭窗口回投不执行闭包。需要知道业务是否完成时，以业务结果读回为准，不把调用返回当确认。

后台线程、网络客户端和其他外部执行器不由 UIX 自动取消或 join。应用必须拥有取消令牌、请求代际和资源关闭顺序；窗口关闭、页面卸载或新请求替代旧请求后，迟到结果不得覆盖新状态。`detach()` 表示调用方有意放弃 `TimerHandle` 的 Drop 取消语义，只应用于生命周期确实由其他 owner 管理的任务。

上例只展示跨线程回 UI 的最小传递机制；它不展示任务取消、线程 join 或请求代际。生产流程必须在启动任务时生成请求身份，并在 `post_to_ui` 闭包内再次核对页面/请求仍有效；调用返回不表示闭包已执行或状态已经呈现。

## 异步数据加载模式

UIX 的异步数据加载不是"调一个 async 函数然后自动渲染"，而是用 `State` 管理加载三态 + `post_to_ui` 回到主线程。

当前尚无统一公开网络客户端；下例中的 `fetch_users()` 代表应用自行接入的数据源，现有 `post_to_ui` 不替它实现超时、取消、重试、认证或响应校验。网络与 ORM 已纳入[完整应用框架目标](../../产品/能力.md#完整应用开发能力目标)，后续由相应服务定义公开机制；此处描述当前接入责任，不是永久排除网络能力，也不是未来 API 示例。

### 三态枚举

以下是已引入 `uix_app::prelude::*` 的应用构建片段，不是独立 main；State 由应用持有并传入目标根视图。

```rust uix-compile=async-load-state
#[derive(Clone)]
struct User { name: String }

#[derive(Clone)]
enum LoadState<T> {
    Loading,
    Loaded(T),
    Error(String),
}

// 在 App 中
let users = State::new(LoadState::<Vec<User>>::Loading);

// 页面根据状态渲染
users.map(|state| match state {
    LoadState::Loading => embed(Spin::new().large()),
    LoadState::Loaded(data) => {
        column(data.iter().map(|u| label(&u.name)).collect::<Vec<_>>())
    }
    LoadState::Error(msg) => {
        embed(ResultView::new(ResultType::Error)
            .title("加载失败")
            .subtitle(msg)
            .extra_text("重试"))
    }
});
```

### 完整示例：加载用户列表

本节“完整”仅指加载三态、后台计算与 UI 回传的闭环，不代表外部任务治理已经齐全；真实应用仍须按上文增加取消、请求代际、超时、认证和资源关闭。

```rust uix-compile=async-load-pattern
use uix_app::prelude::*;
use std::thread;

#[derive(Clone)]
struct User { name: String, email: String }

#[derive(Clone)]
enum LoadState<T> { Loading, Loaded(T), Error(String) }

fn main() {
    let users = State::new(LoadState::Loading);

    App::new()
        .title("用户列表")
        .size(600, 400)
        .on_start({
            let users = users.clone();
            move |handle| {
                let handle = handle.clone();
                let users = users.clone();
                thread::spawn(move || {
                    match fetch_users() {
                        Ok(data) => {
                            handle.post_to_ui(move || {
                                users.set(LoadState::Loaded(data));
                            });
                        }
                        Err(e) => {
                            handle.post_to_ui(move || {
                                users.set(LoadState::Error(e));
                            });
                        }
                    }
                });
            }
        })
        .root(move || {
            users.map(|state| match state {
                LoadState::Loading => embed(Spin::new().large()).padding(40.0),
                LoadState::Loaded(data) => {
                    column(data.iter().map(|u| {
                        row((
                            label(&u.name).font_size(14.0),
                            label(&u.email).color(Color::gray()).font_size(12.0),
                        )).gap(8.0).padding_v(4.0)
                    }).collect::<Vec<_>>()).padding(16.0)
                }
                LoadState::Error(msg) => {
                    embed(ResultView::new(ResultType::Error)
                        .title("加载失败")
                        .subtitle(msg.as_str())
                        .extra_text("重试"))
                }
            })
        })
        .run();
}

fn fetch_users() -> Result<Vec<User>, String> {
    // 模拟 HTTP 请求
    Ok(vec![
        User { name: "Ada".into(), email: "ada@example.com".into() },
        User { name: "Alan".into(), email: "alan@example.com".into() },
    ])
}
```

### 简化：用 `Option` 表示未加载

对于简单场景，可以用 `Option` 替代枚举。以下片段同样要求已引入 `uix_app::prelude::*`，由应用持有并挂载其状态投影：

```rust uix-compile=async-optional-state
#[derive(Clone)]
struct User { name: String }

let data = State::new(None::<Vec<User>>);

// 加载中
data.map_opt(|d| d.as_ref().map(|items| {
    column(items.iter().map(|u| label(&u.name)).collect::<Vec<_>>())
}));
// data 为 None 时什么都不渲染——适合搭配 Spin 或骨架占位
data.map(|state| match state {
    None => embed(Spin::new().large()),
    Some(items) => column(items.iter().map(|u| label(&u.name)).collect::<Vec<_>>()),
});
```

`Option` 不能区分“尚未加载、空结果、失败或已取消”，只适合这些状态不需要分别呈现的场景；否则使用显式枚举并保留 typed error。

## 推荐用法

按产品定义（Rust 优先、容错可观测），以下是应用集成片段，不是内建网络 API。前置：应用提供 `User`、返回 `Result<Vec<User>, E>` 的 `fetch_users`、返回 `ViewNode` 的 `user_list` 和当前窗口的 `handle`，且 `Error: From<E>`；这些业务类型/函数不能直接从 UIX 导入。

```rust uix-compile=async-typed-three-state
use uix_app::prelude::*;
use std::thread;

// 异步任务携带 typed 错误，UI 只消费三态
#[derive(Clone)]
enum AsyncState<T, E> { Loading, Ready(T), Failed(E) }

let users: State<AsyncState<Vec<User>, Error>> = State::new(AsyncState::Loading);

// 为后台任务克隆业务状态句柄，保留原句柄用于声明渲染
let task_users = users.clone();
// 为后台任务克隆目标窗口句柄，避免借用逃逸当前作用域
let task_handle = handle.clone();
// 后台线程失败携带 typed Error，回到 UI 后保留原因
thread::spawn(move || {
    let result = fetch_users().map_err(Error::from);
    task_handle.post_to_ui(move || {
        task_users.set(match result {
            Ok(data) => AsyncState::Ready(data),
            Err(error) => AsyncState::Failed(error),
        });
    });
});

// 渲染：三态 → 三种视图（user_list 返回 ViewNode），错误可重试
users.map(|state| match state {
    AsyncState::Loading => embed(Spin::new().large()),
    AsyncState::Ready(data) => embed(user_list(data)),
    AsyncState::Failed(error) => embed(ResultView::new(ResultType::Error)
        .title("加载失败")
        .subtitle(&error.short_what())
        .extra_text("重试")),
});
```

- 定时器用 `AppHandle::run_after` / `run_interval`，返回的 `TimerHandle` 决定取消或 detach。
- 跨线程回 UI 只走 `post_to_ui`，不直接跨线程碰 `State`。
- 异步失败保留 typed 原因，UI 层可展示、可重试，不吞错误。
- 每次请求持有代际或取消令牌；新请求、页面卸载和窗口关闭会使旧结果失效，迟到结果不得覆盖当前状态。
- UIX 只负责回到目标 UI owner；外部线程、网络、文件与数据库资源仍由应用关闭和回收。
- `post_to_ui` 接纳、任务线程结束和 UI 状态更新是三个不同事实；业务需要确认时必须使用相应结果/状态，而不是从 enqueue 成功推断完成。
