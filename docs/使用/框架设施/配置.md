> **接口**：声明 UIX 配置的公开入口——Settings、图形后端与 CLI 模式配置。依赖：[快速开始](../入门/快速开始.md)。导出：无。（终端使用文档）

## Settings

```rust uix-compile=settings-service
App::new()
    .settings("app.settings.json")  // 可选；相对路径以可执行文件目录为基准
    .on_start(|handle| {
        let Some(settings) = handle.resolve::<SettingsService>() else {
            return;
        };
        let theme: Option<String> = settings.get("theme");
        settings.set("theme", "dark");
        let launches = settings.get_typed_or("launches", 0u32).unwrap_or(0);
        settings.set_typed("launches", launches + 1);
        if let Err(error) = settings.save() {
            eprintln!("save settings failed: {error}");
        }
    })
    .run();
```

KV 模型；文件是 key 唯一、key/value 均为字符串的严格 flat JSON，非法格式返回 typed `FormatError`。默认不读盘（opt-in），`path` 必须非空；`AppHandle` 解析出的 Clone 共享同一应用状态。`set` / `set_typed` / `set_struct` / `remove` / `clear` 只改内存，`save` 显式落盘且要求此前已由 `.settings(path)` 或 `load(path)` 配置路径，否则返回 typed `InvalidState`。落盘通过已同步 temp + backup 可恢复替换；下次 load 会恢复中断前的已提交版本并清理 sidecar；不进 UI 热路径。

Settings 是普通应用配置存储，不承诺加密、密钥管理、系统凭据库或多进程合并语义。应用负责选择保存位置、配置操作系统访问权限并避免把密码、令牌等秘密写入 Settings；temp、backup 与其他恢复 sidecar 可能包含同一配置值，也应采用相同的数据保护和清理策略。

### 类型化读写

`set_typed` 通过 `Display` 写入标量，`get_typed` / `get_typed_or` / `require_typed` 通过 `FromStr` 读取；类型不匹配返回 `ParseError`，`require_*` 缺 key 返回 `NotFound`。方法只访问内存，不会隐式 load 或 save：

```rust uix-compile=settings-typed-scalars
fn read_launch_count(settings: &SettingsService) -> std::result::Result<u32, Error> {
    settings.set_typed("launches", 42u32);
    let optional: Option<u32> = settings.get_typed("launches")?;
    let with_default = settings.get_typed_or("missing", 0u32)?;
    let required = settings.require_typed::<u32>("launches")?;
    assert_eq!((optional, with_default), (Some(42), 0));
    Ok(required)
}
```

结构体 codec 是 opt-in：应用为 `uix` 启用 `settings-serde`，并直接依赖带 derive 的 `serde`。每个结构体按独立 key 编成一个 JSON 字符串，因此外层文件仍是 flat string KV，其他 key 不会被批量覆盖：

```toml
[dependencies]
uix-app = { version = "=0.0.8", features = ["settings-serde"] }
serde = { version = "1", features = ["derive"] }
```

```rust uix-compile=settings-structured uix-feature=settings-serde
#[derive(Debug, Default, serde::Serialize, serde::Deserialize)]
struct AppPrefs {
    theme: String,
    window_width: f64,
    recent_files: Vec<String>,
}

fn store_preferences(settings: &SettingsService) -> std::result::Result<(), Error> {
    let mut prefs = settings
        .get_struct::<AppPrefs>("preferences")?
        .unwrap_or_default();
    prefs.theme = "dark".into();
    settings.set_struct("preferences", &prefs)?;
    let persisted = settings.require_struct::<AppPrefs>("preferences")?;
    assert_eq!(persisted.theme, "dark");
    Ok(())
}
```

结构体序列化失败返回 `SerializationError`，反序列化失败返回 `ParseError`；失败不会覆盖该 key 的原值。调用方仍需显式 `save()` 才会落盘。

读取到 `FormatError`、`ParseError` 或 `SerializationError` 时，不应静默清空全部配置或把失败伪装成默认值。应用可以保留原文件、提示用户修复或选择明确的重置操作；是否备份、迁移和删除旧数据由应用产品策略决定。

## 图形后端

```rust uix-compile=graphics-backend
// 不调用 graphics_backend：使用框架内部的自动选择策略。
let _automatic = App::new();

// 默认 feature 集启用 vulkan，因此可显式固定三平台参考 API。
let _vulkan = App::new()
    .graphics_backend(GraphicsBackend::Vulkan);
```

公开 `GraphicsBackend` 没有代表策略的 `Auto`；省略 `.graphics_backend(...)` 才表示使用框架内部选择策略。每个显式变体只随同名 Cargo feature 导出：`Direct3D11` 对应 `d3d11`、`Direct3D12` 对应 `d3d12`、`Vulkan` 对应 `vulkan`、`Metal` 对应 `metal`、`OpenGlEs` 对应 `opengles`。关闭某个 feature 后，其公开变体会在编译期消失，而不是保留到运行时才失败。生产始终使用唯一的 `draw::Renderer`，不是按平台复制的多套 Renderer。`0.0.7` 默认自动策略在 Windows/Linux 优先构造 Vulkan GPU-native swapchain；Windows 继续探测 D3D11，Linux/Wayland 继续探测 OpenGL ES。显式启用 `d3d12` 时，Windows 自动候选顺序为 Vulkan（100）、D3D12（40）、D3D11（30）、OpenGL ES（10）；显式启用 `metal` 时，macOS 自动候选顺序为 Vulkan（100）、Metal（90）。显式固定某个 API 不会静默改选其他 API。注意：自动策略的探测顺序不等于各公开变体已完成真实环境验收；每条路径的“已实现 / 待验收”边界以[后端状态矩阵](../../架构/graphics/backend.md#当前实现状态)为准，其中 Windows Vulkan/D3D11 已完成 `0.0.2` 真实主机验收，Windows D3D12 与 macOS Metal 仍待验收。Drawing 统一生成 FramePlan，platform Adapter 只负责把共享资源、pipeline、pass、submit 与 present 契约机械映射为原生对象。通用资源、FramePlan、pipeline ABI、Device/Surface 生命周期、提交事务、错误与坐标语义统一归属 `platform::presentation`，具体 API 不得复制。图形迁移差距、视觉 parity 与真机矩阵以[后端状态矩阵](../../架构/graphics/backend.md#当前实现状态)为准；显式指定已编译 API 时失败会给出 typed Error，禁止静默改选另一 GPU API。

例如只编译 OpenGL ES 时，在使用方清单中关闭默认集合并显式选择 backend：

```toml
# 只启用 OpenGL ES backend；其他公开 backend 变体不会导出。
uix-app = { version = "=0.0.8", default-features = false, features = ["opengles"] }
```

应用始终传 logical 窗口尺寸。若自定义 `RenderTarget` 的 `Canvas2D` 使用 drawable physical pixels，须覆盖 `logical_extent()` 返回精确 logical viewport；不得用 `canvas / DPR` 分别反推宽高。

## CLI 模式

适合无 GUI 的脚本或服务场景。CLI 模式下不创建窗口，命令逻辑经 `.cli()` 注册的处理器执行；未注册 `.cli()` 时 `run()` 记录错误并返回退出码 `1`。注意 `on_start` **仅在 GUI 模式建窗后触发**，CLI 模式不会执行，不要把启动逻辑放在 `on_start` 里期望无头运行：

```rust uix-compile=cli-mode
use uix_app::prelude::*;
use uix_app::app::{Cli, CliArgs};

fn greet(args: &CliArgs) -> i32 {
    let name = args.positional.first().map(String::as_str).unwrap_or("world");
    let lang = args.get_or("lang", "zh");
    println!("你好，{name}（{lang}）");
    0
}

fn main() {
    let mut cli = Cli::new();
    cli.command("greet", greet, "打印问候");
    // 可选：为未匹配的命令设置回退处理器；无命令时打印帮助并返回 0。

    let code = App::new()
        .mode(AppMode::CLI)
        .cli(cli)
        .run();
    std::process::exit(code);
}
```

`Cli`/`CliArgs` 由 `uix_app::app` 导出（不在 prelude）。长选项用 `--key=value` 赋值，`--key` 单独出现视为布尔开关（`get` 返回 `"true"`）；短选项 `-k value` 在后随非选项参数时消费为键值。命令处理器签名只接收 `&CliArgs`，拿不到 `AppHandle`；简单 CLI 可在处理器内显式创建独立 `SettingsService` 并 `load`/`save`；这不会自动取得 App 容器中的实例。不要同时对同一文件启用 App `.settings(path)` 和另一独立实例而忽略两者的状态所有权。

## 推荐用法

按产品定义（Rust 优先、容错可观测）：

```rust uix-compile=settings-typed-struct
use uix_app::prelude::*;

// 配置集中在组合根，类型化读写 + 显式落盘
App::new()
    .settings("app.settings.json")          // opt-in：不配置路径就不读盘
    // 默认 feature 集启用三平台统一的 Vulkan 参考后端
    .graphics_backend(GraphicsBackend::Vulkan)
    .on_start(|handle| {
        let Some(settings) = handle.resolve::<SettingsService>() else {
            return;
        };
        // 结构体按独立 key 编解码，失败不覆盖旧值；on_start 闭包返回 ()
        // 不能使用 ?，逐段处理 typed Error
        if let Ok(Some(mut prefs)) = settings.get_struct::<AppPrefs>("preferences") {
            prefs.theme = "dark".into();
            if let Err(error) = settings.set_struct("preferences", &prefs) {
                eprintln!("save preferences failed: {error}");
            }
        }
        if let Err(error) = settings.save() {   // 显式落盘，失败有 typed Error
            eprintln!("save settings failed: {error}");
        }
    })
    .run();
```

- Settings 是 opt-in：不配置路径就不读盘、不占资源（资源优先）。
- 结构体用 `settings-serde` feature 按 key 编解码，其他 key 不被批量覆盖。
- 图形后端省略时用框架自动选择；显式指定失败给出 typed Error，不静默改选。
- CLI 模式适合脚本/服务：不创建窗口，命令逻辑经 `.cli()` 注册的处理器执行；`on_start` 仅在 GUI 模式建窗后触发，未注册 `.cli()` 时 `run()` 返回 `1`。
- Settings 不用于保存凭据；配置内容、恢复 sidecar、目录权限与保留周期由应用负责。
