# 测试驱动

[← 返回使用索引](../../使用.md)

> **接口**：声明 test-harness 的公开 UI 驱动入口——TestApp 的语义动作与系统事件注入。依赖：[快速开始](../入门/快速开始.md)。导出：无。（终端使用文档）

## 前置条件

- Cargo 依赖启用 `test-harness` feature（仅开发与测试环境，不进入发布构建）；
- 通过 `uix_app::ui::test_harness::TestApp` 构造无窗口应用：`TestApp::new((宽, 高), 根视图工厂)`。

## 语义动作

`snapshot()` / `text()` / `find()` 读取语义树；`click`、`focus`、`select`、`toggle`、`type_text`、`press_key`、`scroll`、`set_value` 等以 `automation_id` 驱动组件的语义行为。所有变更方法在动作前后各执行一次收敛（`settle`），收敛超过上限返回 `DidNotSettle`。

## 系统事件注入

语义动作无法覆盖的交互（文件拖放、指针序列等）经 `dispatch_system_event` 注入，返回树级分发结果：

```rust
use uix_app::prelude::*;

let result = app.dispatch_system_event(&SystemEvent::FileDrop {
    files: vec!["/tmp/evidence.png".to_owned()],
    position: upload_center,
})?;
assert_eq!(result, EventResult::Handled);
```

- **坐标空间**：`position` 使用应用内逻辑客户区坐标，与 `snapshot()` 的 `frame` / `visible_bounds` 同空间；TestApp 没有渲染表面，不涉及 device pixel ratio 换算。
- **可见失败**：`Handled` / `NotHandled` / `Bubbled` 原样返回；停止树（fail-stop）返回 `NotHandled("widget_tree")`；收敛超限返回 `AutomationError::DidNotSettle`。
- **适用限制**：视口变化使用 `resize()`（裸 `Resize` 事件不更新根 frame）；`Wheel` 的 delta 遵循组件层「正向下」归一化约定；拖拽手势由指针移动在树内合成，外部注入应使用 PointerDown → PointerMove → PointerUp 序列；键盘、文本与 FileDrop 族事件受窗口焦点门控，注入 `WindowBlur` 后会被拦截。

## 原生窗口的只读人工诊断

当前源码另有显式 opt-in 的原生语义文件导出，用于开发环境下把语义状态与独立原生呈现观察对照。它不是 `TestApp` 的无窗口快照，也不是 [Agent 控制](../能力与边界/Agent控制.md) 的后台工作面；不会登记前台 Agent 端点、接受外部动作或改变后台隔离。旧固定 revision 和正式包是否包含该入口，应按各自源码/交付记录核对。

启用 `test-harness` 构建自己的开发应用，并在进程启动前设置 `UIX_AUTOMATION_DIR` 为显式、私有的绝对目录；公开常量位于 `uix_app::ui::test_harness::{AUTOMATION_DIR_ENV, AUTOMATION_SCHEMA}`。未设置或空值不启用。只对自己的合成场景或明确授权的应用使用；目录权限由宿主负责，文件可能包含界面文字和输入值，**不要假定具备 Agent 协议的敏感值过滤**，不上传真实私人内容。

每个窗口更新 `uix-<process_id>-window-<window_id>.json`，schema 为 `uix.automation.v1`。这是最新状态文件，不是逐帧录像、永久日志或能力发现目录。独立观察者应：

1. 绑定本次启动的进程身份、`window_id` 与 `generation`，不凭同名文件或“最新文件”自动选择其他窗口。
2. 核对 `closed`、`revision`、`presented_revision` 及目标节点的 `automation_id`、`frame`、`visible_bounds`、`name`。导出在窗口帧尾更新，可能落后于刚提交的动作；相同语义状态也不保证生成新修订。只读快照不能代替动作完成回执，`presented_revision` 也不证明桌面 compositor 已完成 scanout。
3. `frame` / `visible_bounds` 使用窗口客户区的 logical 坐标；此文件没有 Agent 快照的 `device_pixel_ratio` 字段。与像素图对齐时另行记录窗口实际缩放和 surface 尺寸，不能套用后台固定 DPR 1。物化节点集合不等于所有业务数据，`visible_bounds=None` 也不能单独证明绘制缺失。
4. 正常关闭会写出 `closed=true` 与空节点集，此时语义修订可能大于最后呈现修订；异常终止、导出 I/O 失败或窗口不再更新时，旧文件可能仍在。不可把文件存在视作窗口存活或导出成功；导出失败通过框架诊断观察，按本次进程状态核验。

同一开发 feature 下，公开 `AppHandle::request_surface_readback_for_test()` 可请求下一次成功 GPU 帧的规范 surface 像素；调用方仍需触发实际绘制，并在非 UI 线程有界等待票据。结果是左上原点的 `0xAARRGGBB` 像素，不是桌面截图或用户目视验收。对照时保留同进程/窗口/阶段的语义文件和像素，不能通过选中或重建待观察节点来“修复”其 bounds；需要额外 Paint 时可使用独立、只在绘制中读取 State 的标记区域。

原生窗口、GPU 像素、导出文件与时序对照属于独立人工诊断，**不为这些入口或其内部实现建立项目测试，也不计入公开组件行为测试数**。`test-harness` 不进入发布构建；产物留在源码构建目录，不复制为工作区验收报告。
