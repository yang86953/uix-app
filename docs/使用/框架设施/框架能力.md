## DI 容器

应用在所属 App 组合根注册服务，并在应用启动、路由或 handler 边界解析已知服务，再把完成当前职责所需的窄依赖显式传给 View 工厂或业务对象。组件、Module 与 Component 不在运行路径中自行查找容器；Module 私有实现不作为可解析服务暴露，窗口私有资源也不进入进程全局容器。

以下是 builder 配置片段：在同一个 App 注册和解析服务，之后继续为该 app 配置根视图并 `run()`。独立创建的 `DiContainer` 不会自动注入已有 `AppHandle`。

```rust uix-compile=framework-di
use uix_app::prelude::*;

let app = App::new()
    .singleton(SettingsService::new())
    .on_start(|handle| {
        let _settings = handle
            .resolve::<SettingsService>()
            .expect("组合根已注册 SettingsService");
        // 在这个应用边界把所需窄依赖传给业务对象。
    });
```

`resolve::<T>()` 返回 `Option<T>`，未注册为 `None`；上例的 expect 只表达同一组合根已注册的内部不变量，不把未知外部输入当作必然成功。无 App 的代码可直接在自己持有的 `DiContainer` 上注册和解析。

单例作用域是所属容器及其克隆，不是进程静态全局。容器克隆共享已注册条目的内部 Arc，但注册表是快照，后续增删不反向修改原容器；`AppHandle::resolve` / `resolve_clone` 仍遵循 **T::clone**，普通值会复制，只有 Arc 或本身可共享的句柄保留同一服务。最后引用负责资源释放，DI 不代替服务执行取消、关闭或 join。

`AppHandle::resolve` 是应用组合/路由边界的公开入口，不是组件内的 Service Locator。若某个组件需要业务能力，优先传入窄 callback、trait 端口或只含必要字段的业务对象；不要把 `AppHandle`、`DiContainer` 或聚合全部服务的对象下传到整棵组件树。

## 类型化上下文

框架只传递值；默认密度、语言字段和组件行为由应用或组件库定义。

```rust
use uix_app::prelude::*;
#[derive(Clone, Default, PartialEq)]
struct Density(u8);
let view = ContextProvider::new(Density(2))
    .child(|| label(format!("density: {}", use_context::<Density>().0)))
    .build();
```

最近的同类型值覆盖外层值；不同类型独立继承。同步构建作用域结束或 panic 后恢复外层，已构建节点保留其快照。启用 `application` 时，`App::new().context(Density(2))` 设置每个窗口的根默认值。

组件库的 `WidgetConfig`、`WidgetOverrides`、`ConfigProvider`、`Locale` 和 `LocaleProvider` 从 `uix_widgets::prelude::*` 导入；应用配置扩展还需要组件库的 `application` feature。其字段和优先级见组件库文档。

## 中性布局与文字

仅启用 `uix-app/ui` 即可使用 `Container`、`Label`、`ScrollView`、行列组合子与 Unicode 编辑器。它们不加载图标或设计系统资源。`TextEditState` 保存文本、光标和选择；`edit(multiline, max_length)` 借用为 `TextEditor`，按完整字素簇移动和编辑。

## 通用主题

`ThemeTokens::value` 接受命名空间键并返回 `Option<TokenValue>`；`TokenPatch::with` 增量覆盖键。设计系统决定自己的字段和样式预设，框架不要求实现 Ant Design 接口。`ColorValue::token(key, fallback)` 在绘制时解析，数值构建表达式在所属主题作用域内读取。

## 业务翻译表

`register_translations` / `set_translations` / `t!` 操作进程级 key 到文案表。注册增量合并，set 整表替换，缺失 key 返回 key 原文。写表不触发 UI 失效，已得到的 String 不自动更新；应用负责切换资源并驱动相关视图重建。该表与类型化 Context 独立，也不由组件库 Locale 自动选择。
