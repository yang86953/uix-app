## DI 容器

应用在所属 App 组合根注册服务，并在应用启动、路由或 handler 边界解析已知服务，再把完成当前职责所需的窄依赖显式传给 View 工厂或业务对象。组件、Module 与 Component 不在运行路径中自行查找容器；Module 私有实现不作为可解析服务暴露，窗口私有资源也不进入进程全局容器。

以下是 builder 配置片段：在同一个 App 注册和解析服务，之后继续为该 app 配置根视图并 `run()`。独立创建的 `DiContainer` 不会自动注入已有 `AppHandle`。

```rust uix-compile=framework-di
use uix_app::prelude::*;

let app = App::new()
    .singleton(SettingsService::new())
    .on_start(|handle| {
        let _settings = handle
            .resolve::<SettingsService>()
            .expect("组合根已注册 SettingsService");
        // 在这个应用边界把所需窄依赖传给业务对象。
    });
```

`resolve::<T>()` 返回 `Option<T>`，未注册为 `None`；上例的 expect 只表达同一组合根已注册的内部不变量，不把未知外部输入当作必然成功。无 App 的代码可直接在自己持有的 `DiContainer` 上注册和解析。

单例作用域是所属容器及其克隆，不是进程静态全局。容器克隆共享已注册条目的内部 Arc，但注册表是快照，后续增删不反向修改原容器；`AppHandle::resolve` / `resolve_clone` 仍遵循 **T::clone**，普通值会复制，只有 Arc 或本身可共享的句柄保留同一服务。最后引用负责资源释放，DI 不代替服务执行取消、关闭或 join。

`AppHandle::resolve` 是应用组合/路由边界的公开入口，不是组件内的 Service Locator。若某个组件需要业务能力，优先传入窄 callback、trait 端口或只含必要字段的业务对象；不要把 `AppHandle`、`DiContainer` 或聚合全部服务的对象下传到整棵组件树。

## Provider 与配置继承

主题、Locale、尺寸和组件令牌沿 View 子树继承。最近 Provider 覆盖上层值；覆盖在子树卸载后随生命周期一起释放。

```rust uix-compile=framework-provider
use uix_app::prelude::*;

// LocaleProvider：子树语言覆写
embed(LocaleProvider::new(zh_cn())
    .child(|| column((
        label("中文界面"),
        embed(Empty::new().icon("inbox")),
    )))
    .build());

// ConfigProvider：子树尺寸 + 禁用态
embed(ConfigProvider::new()
    .widget_size(ControlSize::Large)
    .disabled(true)
    .child(|| column((
        button("继承 Large"),
        input().placeholder("继承禁用态"),
    )))
    .build());
```

```rust uix-compile=framework-overrides
use uix_app::prelude::*;

// 组件构造覆盖：Input 前后缀统一注入，业务页无需逐个传参
let mut overrides = WidgetOverrides::default();
overrides.input.prefix = Some("¥".to_string());

embed(ConfigProvider::new()
    .overrides(overrides)
    .child(|| input().placeholder("自动注入前缀"))
    .build());

// 组件令牌窄覆盖：只调整 Button 的主色与圆角
embed(ConfigProvider::new()
    .widget_tokens::<Button>(TokenPatch {
        color_primary: Some(Color::hex("#722ed1")),
        border_radius: Some(10.0),
        ..TokenPatch::default()
    })
    .child(|| button("紫色按钮").primary())
    .build());
```

## 国际化

内置组件文案由 `App::locale` 提供默认值，`LocaleProvider` 为子树构建覆盖，`use_locale()` 读取当前文案快照；退出 Provider 构建作用域恢复外层，节点保留所需上下文。业务内容由应用提供，业务稳定 key 不随显示文案改变。

业务 `register_translations` / `set_translations` / `t!` 使用另一张**进程级 key→文案表**，与内置 Locale 互不联动：注册增量合并并覆盖同 key，set 整表替换并影响同进程所有使用者，缺失 key 返回 key 原文。Provider 卸载不清空此表。`t!` 返回 String 快照，写表不触发 UI 响应式失效，已有 String 不会自动更新；需要业务切换语言时，由应用选表并驱动相关 UI 重建，不把它误当子树隔离的自动翻译服务。

```rust uix-compile=framework-locale
use uix_app::prelude::*;

let locale = zh_cn();

App::new()
    .locale(locale)
    .root(move || {
        let locale = use_locale();
        column((
            label(format!("空态文案：{}", locale.empty_description)),
            embed(Empty::new().icon("inbox")),
        ))
    })
    .run();
```

## 尺寸与令牌

紧凑、默认和宽松密度由主题令牌表达。组件可以声明窄覆盖，但不得复制整套主题或直接依赖平台常量。

## 推荐用法

按产品定义（Rust 优先、原生优先）：

```rust uix-compile=framework-singleton
use uix_app::prelude::*;

// 在该 App 组合根注册服务（main_view 由应用提供）
App::new()
    .singleton(SettingsService::new())
    .root(main_view)
    .run();
```

```rust uix-compile=framework-services-i18n
use uix_app::prelude::*;

let locale = zh_cn();
// 在构建目标 UI 前注册业务资源；LocaleProvider 不选择这张全局表。
register_translations(&[("common.save", "保存")]);
embed(LocaleProvider::new(locale)
    .child(|| label(t!("common.save")))
    .build());
```

- 服务注册与解析收敛在组合根或明确的应用路由边界；组件接收窄依赖，Module 私有实现不可解析。
- 子树覆盖（内置 Locale / 尺寸 / 令牌）随节点生命周期释放，不反向改应用默认值；业务 key 表不是 Provider 资源。
- 文案走资源表 + key，格式化只影响显示，不改变业务值。
- 密度由主题令牌表达，业务不复制整套主题。

## 保留边界

保留组合根、显式窄 DI、子树 Provider、可替换服务和生命周期释放原则；容器解析不能替代依赖声明。Rust 的实际注册与获取 API 以 `application`、`theme` 模块为准。
