# 运行保障

[← 返回使用索引](../../使用.md)

> **接口**：声明 UIX 运行保障的公开入口——typed Error、精确错误恢复、统一调试模式、结构化日志、错误报告、复现清单、快照与宿主 subscriber 配置。依赖：[快速开始](../入门/快速开始.md)。导出：运行保障架构 → [架构 · 诊断与运行保障](../../架构/platform/diagnostics.md)。

运行保障由同一个 `uix::diagnostics` 公开面承担三件事：

1. 以 typed `Error` 保留错误类别、来源和责任边界。
2. 为可恢复资源登记恢复动作，并在恢复完成后发布稳定状态。
3. 汇总结构化日志、最终错误报告、有界复现清单与快照，供宿主展示或持久化。

## 公开运行契约

- 平台或图形回调只把 typed failure 放入有界队列，资源 owner 在所属线程的安全边界处理；回调不直接重入 UI 或在错误线程恢复资源。
- 每个资源来源保持隔离，关闭后清理晚到回调；队列容量耗尽时转换为可识别的 `InsufficientResources`，不无界增长。
- 图形 surface/device 故障进入统一恢复边界。恢复由资源所有者决定，观察者不能通过订阅回调取得资源生命周期。
- Windows TSF 与 `CrashReport` 提供有界字段、原子写入和 panic hook。真实 Wayland compositor、macOS AppKit 及非默认图形后端的环境覆盖由 [仓库状态账目](../../../TODO.md) 持有。

## 使用示例

```rust uix-compile=diagnostics-report
use uix::prelude::*;
use uix::diagnostics::{Diagnostics, DiagnosticsConfig, RecoveryAction};

// 宿主创建 Diagnostics runtime（固定容量 pending queue）
let diagnostics = Diagnostics::new(DiagnosticsConfig::default());

// 报告 typed Error：报告是有界的，保留类别与原因
diagnostics.report(Error::new(Errc::PlatformError, "failed to open file"));

// 订阅恢复：device-lost 等可恢复资源由所有者登记恢复动作
let subscription = diagnostics.on_error(Errc::GraphicsDeviceLost, |_error| {
    // 恢复动作在 owner-thread 边界执行
    RecoveryAction::Recovered
});
```

## 错误与恢复

恢复必须由资源所有者发起；观察者只能订阅状态。重复故障应去重并保留最近上下文，恢复回调在锁外执行，失败不能阻断其他恢复项。

## 日志与报告

库使用 `tracing` 事件，宿主决定 subscriber、过滤和输出位置。报告默认移除敏感输入、令牌和用户内容，只保存诊断所需的有界字段。

诊断结构化事件统一使用 `target: "uix::diagnostics"`（报告发射、恢复尝试与事件抑制均以此 target 记录）；`ErrorReport` 另携带来源标记（框架内部 `framework` 或应用业务 `application`）。宿主可按 target 过滤框架诊断事件，或按来源标记区分框架与业务报告，例如 `EnvFilter` 只保留 `uix::diagnostics` 目标并配置业务报告展示策略。

宿主直接依赖日志 subscriber；UIX 只依赖 `tracing` 门面，不决定 subscriber 实现：

```toml
# 宿主启用环境过滤能力并拥有日志输出策略。
[dependencies]
# subscriber 不进入 UIX 自身的运行依赖。
tracing-subscriber = { version = "0.3", features = ["env-filter"] }
```

```rust uix-compile=diagnostics-tracing
use tracing_subscriber::EnvFilter;

// 宿主安装 subscriber：库只发射 tracing 事件，不决定输出位置
tracing_subscriber::fmt()
    .with_env_filter(EnvFilter::from_default_env())
    .init();
```

## 统一调试模式

调试开关属于同一个 `Diagnostics` runtime，所有窗口共享。以下入口语义一致：

- 组合根：`App::new().debug_mode(true)`；
- 运行时：`diagnostics.set_debug_mode(true)`；
- 启动环境：`UIX_DEBUG=1`（也接受 `true/yes/on` 与对应的关闭值）；
- 原生窗口内：`Ctrl+Shift+D` 动态切换。

开启后，运行时在 `uix::diagnostics` target 发射固定 schema 的输入、悬停、帧摘要与卡顿段事件。同一批原生输入、状态变化和最终帧共享 `correlation_id`，可直接沿「输入 → 悬停目标 → 帧」追踪因果。右上 HUD 明确展示“上一已提交帧”的序号、关联身份、树版本、近似 FPS、布局/渲染/提交/呈现耗时、实际重绘范围、失效数量与最大失效节点、动画和协调事实；累计布局/绘制/呈现/空闲次数单独标为 `calls`，不再与单帧数据混淆。

悬停检查器在应用内容、`AfterChildren` 与全部浮层之后执行唯一最终顶层 Debug Pass，不会被普通卡片、滚动裁剪、Picture 缓存或 Popup 覆盖。它显示组件类型与内部节点号、layout/viewport/visible 三套几何、裁切、变换、滚动、层级、不透明度、Picture 资格、动态/交互能力、输入状态和生命周期；根到叶路径颜色与屏幕轮廓一一对应。为避免把业务文本带入截图，覆盖层不展示 automation id、key、组件文本、路径或资源身份。调试帧有视觉工作时会采用全幅重绘以清除上一轮顶层轮廓，但不会自行连续轮询；关闭时不扫描组件树、不采集帧计时，也不改变正常局部重绘策略。

只需捕获卡顿而不显示覆盖层时，可设置 `UIX_SLOW_FRAME_MS=<正整数>`；超过阈值的连续帧会形成一次开始/结束事件，避免逐帧刷屏。

### 导出复现清单

```rust uix-compile=diagnostics-repro
use uix::diagnostics::Diagnostics;

fn save_repro(diagnostics: &Diagnostics) -> Result<(), uix::core::Error> {
    let path = diagnostics.write_debug_repro_manifest("logs/repro")?;
    eprintln!("repro manifest: {}", path.display());
    Ok(())
}
```

清单是上限 32 KiB 的行式 `key=value` 文件，最多保留最近 128 个固定事件、8 个窗口数值快照和 16 个错误码事实。它记录 UIX 版本、目标 OS/架构、窗口尺寸、关联身份、帧阶段耗时、脏区比例、动画/失效数量、错误码及原因码；不记录用户文本、窗口标题、组件内容、资源标识、环境变量、主机/用户名或本地路径。配置 `crash_report_directory` 后，panic hook 会在 CrashReport 旁自动写出 `reason=panic` 的复现清单；清单不复制 panic 文本。

推荐定位顺序：先复现并记下覆盖层的 `correlation_id`，再按同一身份过滤 `uix::diagnostics` 日志；若问题转瞬即逝，立即导出复现清单并连同最小步骤、预期/实际结果一起保存。

## 报告的隐私与保留

- UIX 对框架已知的敏感字段执行最小化和脱敏，但无法保证识别应用自行写入错误消息、日志字段或上下文字符串中的所有秘密。应用不得把密码、令牌、完整用户内容或不必要的本地路径放入这些字段。
- UIX 不上传日志或 CrashReport。宿主决定输出目录、文件权限、保留期限、访问审计和删除策略；若应用另行上传，上传属于应用能力并需独立取得授权。
- 报告和快照有容量与字段边界，适合定位已登记上下文，不是完整内存转储或无限期审计记录。发生截断或队列容量错误时，应保留 typed 原因而不是假定报告完整。

## 崩溃边界

无法恢复的 panic/崩溃只做最小安全记录，不尝试在损坏状态下继续运行复杂 UI。`App::run` 在配置加载前安装绑定 Diagnostics runtime 的 panic hook（配置 `crash_report_directory` 时原子写入 CrashReport 与脱敏复现清单，未配置时等同默认；始终转发 previous hook 不吞 panic）。

CrashReport 目录不可写或报告落盘失败时，应用仍应保留 previous hook 与宿主日志输出；不得为了生成报告而吞掉 panic、继续运行损坏状态，或把记录失败解释为业务成功。

## 推荐用法

按产品定义（容错可观测）：

```rust uix-compile=error-typed-business
use uix::prelude::*;

// 应用业务错误也走 typed Error，可展示、可恢复、可报告
fn save_document(settings: &SettingsService) -> Result<(), Error> {
    settings.save().map_err(|error| {
        Error::new(Errc::WriteFailure, "save failed").with_source(error)
    })
}
```

```rust uix-compile=diagnostics-app-config
use uix::prelude::*;
use uix::diagnostics::{DiagnosticsConfig, BacktracePolicy};

// 宿主统一展示与持久化报告：注入共享 runtime 配置 + panic 原子写入目录
App::new()
    .diagnostics(
        DiagnosticsConfig::default()
            .report_capacity(256)
            .crash_report_directory("logs/crash")
            .backtrace(BacktracePolicy::ErrorsAndFatal),
    )
    .run();
```

```rust uix-compile=diagnostics-runtime-inject
use uix::prelude::*;
// Diagnostics runtime 不在 UI prelude 中，由宿主显式导入
use uix::diagnostics::{Diagnostics, DiagnosticsConfig};

// 注入已构建的 Diagnostics runtime 实例（宿主持有共享句柄）
let diagnostics = Diagnostics::new(DiagnosticsConfig::default());

App::new()
    .diagnostics_runtime(diagnostics.clone())
    .run();
```

- 业务失败一律 typed `Error`：类别 + 原因 + 责任边界，不用布尔/空值伪装成功。
- 恢复由资源所有者发起，观察者只订阅状态；恢复回调锁外执行。
- 日志输出位置由宿主决定；报告与快照有界、脱敏，不携带敏感值。

保留 typed failure、所有者恢复、锁外通知、敏感信息最小化与有界报告原则。
