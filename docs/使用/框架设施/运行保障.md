# 运行保障

[← 返回使用索引](../../使用.md)

> **接口**：声明 UIX 运行保障的公开入口——typed Error、精确错误恢复、结构化日志、错误报告、快照与宿主 subscriber 配置。依赖：[快速开始](../入门/快速开始.md)。导出：运行保障架构 → [架构 · 诊断与运行保障](../../架构/platform/diagnostics.md)。

运行保障由同一个 `uix::diagnostics` 公开面承担三件事：

1. 以 typed `Error` 保留错误类别、来源和责任边界。
2. 为可恢复资源登记恢复动作，并在恢复完成后发布稳定状态。
3. 汇总结构化日志、最终错误报告与有界快照，供宿主展示或持久化。

## 公开运行契约

callback → owner-thread 的运行保障统一服从以下公开契约：`Diagnostics` runtime 共享固定容量 pending failure queue，每个 graphics context / Windows platform owner 使用隔离 source；历史 GPU 后端的 uncaptured error、device-lost、offscreen destroy 与 checked teardown、Windows `wnd_proc` 的 DPI / 窗口尺寸移动 / IMM 失败分支、Windows DWM frame pacer worker 的 `DwmFlush` / `PostMessageW` 失败、Windows custom chrome 的 Win32/DWM 失败，以及 Windows TSF composition / text-store callback 的唤醒、锁回调和借用冲突失败，只入队 typed `Error`，分别由 owner-thread 在 `ensure_active` 或 App 任务边界交给 `RecoveryDriver` / Diagnostics。生产 D3D11 与 OpenGL ES 的 surface/device failure 通过薄 RHI 的 typed recovery 边界处理。队列溢出转换为有界的 `InsufficientResources`，source 关闭会清理晚到 callback；TSF 激活失败也不再直接写日志。

真实 Wayland compositor、macOS AppKit，以及 D3D12、Metal、Vulkan 等非默认图形后端的 teardown 覆盖、当前差距、负责人和阻塞统一由 [Vikunja 项目 4](https://yang-server.tail9d5559.ts.net:3456/projects/4) 维护。Windows TSF 与 `CrashReport` 提供有界字段、原子写入和 panic hook。

## 使用示例

```rust uix-compile=diagnostics-report
use uix::prelude::*;
use uix::diagnostics::{Diagnostics, DiagnosticsConfig};

// 宿主创建 Diagnostics runtime（固定容量 pending queue）
let diagnostics = Diagnostics::new(DiagnosticsConfig::default());

// 报告 typed Error：报告是有界的，保留类别与原因
diagnostics.report(Error::new(Errc::PlatformError, "failed to open file"));

// 订阅恢复：device-lost 等可恢复资源由所有者登记恢复动作
let subscription = diagnostics.on_error(Errc::GraphicsDeviceLost, |_error| {
    // 恢复动作在 owner-thread 边界执行
});
```

## 错误与恢复

恢复必须由资源所有者发起；观察者只能订阅状态。重复故障应去重并保留最近上下文，恢复回调在锁外执行，失败不能阻断其他恢复项。

## 日志与报告

库使用 `tracing` 事件，宿主决定 subscriber、过滤和输出位置。报告默认移除敏感输入、令牌和用户内容，只保存诊断所需的有界字段。

```rust uix-compile=diagnostics-tracing
use tracing_subscriber::EnvFilter;

// 宿主安装 subscriber：库只发射 tracing 事件，不决定输出位置
tracing_subscriber::fmt()
    .with_env_filter(EnvFilter::from_default_env())
    .init();
```

## 崩溃边界

无法恢复的 panic/崩溃只做最小安全记录，不尝试在损坏状态下继续运行复杂 UI。`App::run` 在配置加载前安装绑定 Diagnostics runtime 的 panic hook（配置 `crash_report_directory` 时原子写入 CrashReport，未配置时等同默认；始终转发 previous hook 不吞 panic）。

## 理想使用方式

按产品定义（容错可观测）：

```rust uix-compile=error-typed-business
use uix::prelude::*;

// 应用业务错误也走 typed Error，可展示、可恢复、可报告
fn save_document(settings: &SettingsService) -> Result<(), Error> {
    settings.save().map_err(|error| {
        Error::new(Errc::WriteFailure, format!("save failed: {error}"))
    })
}
```

```rust uix-compile=diagnostics-app-config
use uix::prelude::*;
use uix::diagnostics::{DiagnosticsConfig, BacktracePolicy};

// 宿主统一展示与持久化报告：注入共享 runtime 配置 + panic 原子写入目录
App::new()
    .diagnostics(
        DiagnosticsConfig::default()
            .report_capacity(256)
            .crash_report_directory("logs/crash")
            .backtrace(BacktracePolicy::Always),
    )
    .run();
```

```rust uix-compile=diagnostics-runtime-inject
use uix::prelude::*;

// 注入已构建的 Diagnostics runtime 实例（宿主持有共享句柄）
let diagnostics = Diagnostics::new(DiagnosticsConfig::default());

App::new()
    .diagnostics_runtime(diagnostics.clone())
    .run();
```

- 业务失败一律 typed `Error`：类别 + 原因 + 责任边界，不用布尔/空值伪装成功。
- 恢复由资源所有者发起，观察者只订阅状态；恢复回调锁外执行。
- 日志输出位置由宿主决定；报告与快照有界、脱敏，不携带敏感值。

保留 typed failure、所有者恢复、锁外通知、敏感信息最小化与有界报告原则。
