# 平台能力

[← 返回使用索引](../../使用.md)

> **接口**：声明 UIX 平台能力的公开用法——Platform、系统硬件查询、GPU adapter 信息与独立原生服务。依赖：[快速开始](../入门/快速开始.md)。导出：平台架构 → [架构 · 平台能力](../../架构/platform/capabilities.md)。

本文只描述当前公开的平台契约。Windows 系统通知包含身份配置、只读登记探测与 Toast 提交；其他操作系统 Provider 和跨目标环境矩阵的覆盖以实机验证结果与[交付与许可](../../产品/交付与许可.md)声明为准。

## 查询与服务

- 显示器、主题、系统版本、CPU/内存与 GPU adapter 等信息通过 `Platform` 的稳定值类型查询。
- 剪贴板、文件对话框、系统目录、通知、字体和控制台是独立服务；调用方不持有原生句柄。
- 可能不可用的能力返回 typed error 或 capability，而不是用空值伪装成功。

## 已落地示例

```rust uix-compile=platform-query
use uix_app::platform::Platform;
use uix_app::platform::graphics::{GpuAdapterInfo, GraphicsBackend};
use uix_app::platform::hardware::{CpuInfo, DisplayInfo, MemoryInfo, OsInfo};

// 查询结果全部是 owned 描述，不把原生句柄暴露给调用方。
type PlatformSnapshot = (
    OsInfo,
    CpuInfo,
    MemoryInfo,
    Box<[DisplayInfo]>,
    Box<[GpuAdapterInfo]>,
);

// 把平台单实例的创建、查询和析构边界放进一个可独立编译的函数。
fn query_platform() -> uix_app::core::Result<PlatformSnapshot> {
    // 平台实例线程亲和：必须在进程主线程创建，每进程最多一个。
    let platform = Platform::new()?;
    // 系统信息查询传播 typed failure。
    let os = platform.os_info()?;
    let cpu = platform.cpu_info()?;
    let memory = platform.memory_info()?;
    // 显示器与 GPU 查询只返回 owned 描述。
    let displays = platform.displays()?;
    // 默认 feature 集启用三平台参考 API；查询其原生物理设备描述。
    let adapters = platform.gpu_adapters(GraphicsBackend::Vulkan)?;
    // 返回快照后，Platform 在函数末尾按 owner-thread 逆序析构。
    Ok((os, cpu, memory, displays, adapters))
}
```

`GraphicsBackend` 的可构造变体随对应 Cargo backend feature 导出；关闭 feature 后，使用方无法编译对该 backend 的显式查询。同步 adapter 枚举由 D3D11/D3D12 的 DXGI、Vulkan 物理设备和 macOS Metal 原生设备 API 分别提供。OpenGL ES 没有无上下文的可移植 adapter 枚举协议，因此该查询明确返回 typed `NotImplemented`，不会伪造设备或静默改查另一 API。

```rust uix-compile=platform-service
use std::path::PathBuf;
use uix_app::platform::Platform;
use uix_app::platform::services::{
    AppUserModelId, FileDialogFilter, SpecialDir, SystemNotification,
    SystemNotificationCapability,
};

// 同步选择一个或多个图片文件；用户取消是成功的空值。
fn choose_images(platform: &mut Platform) -> uix_app::core::Result<Option<Box<[PathBuf]>>> {
    // 过滤器拥有并规范化扩展名，应用不拼接平台相关格式。
    let images = FileDialogFilter::new("Images", ["png", "jpg", "jpeg"])?;
    // 原生面板必须在 Platform owner thread 调用，确认结果为 owned 路径。
    platform.open_files("选择图片", &[images])
}

// 显式借用调用方拥有的 Platform，保持通知所需的可变 owner 边界。
fn documents_dir_and_notify(platform: &mut Platform) -> uix_app::core::Result<PathBuf> {
    // 系统目录查询返回 owned 路径，不隐式创建目录。
    let documents = platform.special_dir(SpecialDir::Documents)?;
    // AUMID 必须与 MSIX 或安装器创建的开始菜单快捷方式登记完全一致。
    let identity = AppUserModelId::new("UIX.NotificationDemo")?;
    // UIX 仅保存显式身份，不负责修改系统登记。
    platform.set_notification_app_user_model_id(identity)?;
    // 发送前可读取配置与部署登记的可解释状态。
    if platform.system_notification_capability()? != SystemNotificationCapability::Available {
        // 示例选择不发送；产品可在这里展示安装或配置指引。
        return Ok(documents);
    }
    // 系统通知同步传播 typed failure，调用方不持有原生句柄。
    platform.show_notification(SystemNotification::new("UIX", "任务完成"))?;
    // 把已查询的目录交还调用方，避免示例丢弃结果。
    Ok(documents)
}
```

`Platform::open_files`、`Platform::save_file` 和 `Platform::open_folder` 都是同步 owner-thread 服务。文件与保存入口接收已验证的 `FileDialogFilter`；目录入口不接收过滤器。用户取消统一返回 `Ok(None)`，确认返回 owned `PathBuf`，启动失败、权限问题和原生 API 异常继续返回 typed error。传入空过滤器切片表示不限制文件类型；单个过滤器至少包含一个确定扩展名，路径模式、NUL 与 `*.*` 全通配符会在进入 Provider 前被拒绝。

Windows 通知环境约定：

| 环境 | capability / 发送结果 |
|---|---|
| 开发目录直接运行，未配置身份 | `IdentityRequired`；发送为 typed `NotImplemented` |
| 配置 AUMID，但安装器未登记同一身份 | `IdentityUnregistered`；发送为 typed `InvalidState` |
| MSIX 或开始菜单快捷方式已登记同一 AUMID | `Available`；通过 Windows Toast API 提交，系统错误继续类型化返回 |
| 没有通知 Provider 的目标 | `Unsupported`；发送为 typed `NotImplemented` |

应用定义的 AUMID 需为 1–128 个 UTF-16 单元且不含空白或 NUL；推荐采用 `CompanyName.ProductName` 形式。登记由 MSIX 或安装器完成，UIX 不创建、修复或删除快捷方式与注册表项。

Linux 与 macOS 的 capability 查询会只读检查 `PATH` 中是否存在可执行的 `notify-send` 或 `osascript`。Provider 可发现时返回 `Available`，不可发现时返回 `Unsupported`；查询不会启动进程，实际发送时的权限、会话或 Provider 退出错误仍以 typed error 返回。

## 权限与隐私

- 系统信息、硬件描述、本地路径、剪贴板和用户选择的文件都可能包含设备或用户信息；只读取完成当前任务所需的最小范围，不把完整值默认写入日志或诊断报告。
- 文件对话框是同步 owner-thread 服务，调用会等待用户完成或取消；不要在持有业务锁时打开，也不要把取消 `Ok(None)` 当作权限失败。
- UIX 返回用户选择的 owned 路径，但不替应用承诺后续读写权限、文件仍然存在或内容可信；实际访问仍需处理权限、竞态与格式错误。
- 系统通知可能显示在锁屏、通知中心或其他用户可见位置。应用负责避免在标题和正文中放入秘密或不必要的个人数据。
- Linux/macOS 通知 capability 只表示 Provider 可发现；实际启动外部 Provider 时仍可能因会话、权限或退出状态失败，必须处理 typed error。

## 线程与生命周期

窗口、输入和部分系统服务具有 owner-thread 约束。后台工作必须通过公开队列回到拥有线程；平台回调只复制必要数据，不在回调栈中重入 UI。

## 推荐用法

按产品定义（原生优先、容错可观测）：

```rust uix-compile=platform-system-info
use uix_app::prelude::*;

// 能力查询统一走 Platform，失败转 typed Error 展示
fn show_hardware(platform: &Platform, status: &State<String>) {
    match (platform.os_info(), platform.cpu_info(), platform.memory_info()) {
        (Ok(os), Ok(cpu), Ok(mem)) => {
            // 把字节换算为整数 MiB，避免示例查询内存后丢弃结果。
            let total_memory_mib = mem.total_bytes() / (1024 * 1024);
            // 只通过公开访问器组合可直接展示的系统摘要。
            status.set(format!(
                "{} · {} · {} 核 · {} MiB 内存",
                os.name(),
                cpu.architecture(),
                cpu.logical_cores(),
                total_memory_mib
            ));
        }
        // 任一查询失败都展示对应 typed Error，不遗漏 CPU 或内存失败组合。
        (Err(error), _, _) | (_, Err(error), _) | (_, _, Err(error)) => {
            status.set(format!("无法读取系统信息：{}", error.short_what()));
        }
    }
}
```

- 平台能力只通过 `Platform` 具体方法消费，不持有原生句柄。
- 不可用能力返回 typed error，UI 可展示、可降级，不用空值伪装成功。
- owner-thread 约束由框架表达；跨线程回 UI 走 `post_to_ui`。

## 限制与降级

- capability 表示当前环境能否提供某项服务，不是未来持续可用的保证；调用仍需处理 typed error。
- 不支持的能力应展示明确降级或禁用相应操作，不使用空值伪装成功，也不以固定轮询反复探测。
- 平台对象和部分服务具有 owner-thread 生命周期；后台任务通过 `post_to_ui` 回到拥有线程。
- UIX 不把原生窗口、surface、GPU 或服务句柄交给应用；没有公开入口时，不通过内部类型绕过边界。
