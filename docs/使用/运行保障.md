# 运行保障

[← 返回使用索引](../使用.md)

> 分类：运行保障
>
> 权威范围：typed Error、精确错误恢复、结构化日志、错误报告、快照与宿主 subscriber 配置

运行保障由同一个 `uix::diagnostics` 公开面承担三件事：

- **维稳**：错误不越过 ABI、驱动 callback 或线程所有权边界；队列、报告和递归都有上限。
- **纠错**：框架与用户可以为一个精确 `Errc` 注册恢复逻辑，并在安全线程显式尝试。
- **记录**：普通运行记录进入 `tracing`，最终未恢复的 typed Error 进入 `ErrorReport`。

公开核心与恢复注册已经部分落地；平台 owner-thread 接入、旧日志删除和 CrashReport 仍未完成。精确状态见[进度 · 运行保障](../进度/运行保障.md)。

## Error 是唯一失败值

能返回给调用方的失败继续使用 `Result<T, Error>`，传播时保留错误码、严重度、位置与 source chain：

```rust uix-compile=assurance-typed-errors
use uix::prelude::*;

let source = Error::new(Errc::IoError, "磁盘空间不足");
let error = Error::new(Errc::WriteFailure, "保存失败").with_source(source);

assert_eq!(error.code(), Errc::WriteFailure);
println!("{}", error.root_cause());
println!("{}", error.short_what());
```

不要把 typed Error 先格式化成文本，再用 `Errc::Unknown` 重建；不要在每一层同时 `log + return Err`。

## 注册指定错误的恢复逻辑

`on_error` 只匹配一个精确 `Errc`。它注册的是恢复逻辑，不是普通日志监听器或错误广播：

```rust uix-compile=assurance-register-recovery
use uix::core::Errc;
use uix::diagnostics::{
    Diagnostics,
    RecoveryAction,
    RecoverySubscription,
};

fn register_timeout_recovery(
    diagnostics: &Diagnostics,
) -> RecoverySubscription {
    diagnostics.on_error(Errc::Timeout, |_error| {
        // 真实代码必须先恢复自己拥有的不变量，再返回 Recovered。
        RecoveryAction::Recovered
    })
}
```

必须保存返回的 `RecoverySubscription`；drop 后不再参与后续恢复。已经开始的一次调用可以执行完毕。

匹配处理器按注册顺序运行：

| 返回值 | 行为 |
|---|---|
| `RecoveryAction::NotHandled` | 当前处理器不负责，继续下一个同码处理器 |
| `RecoveryAction::Recovered` | 不变量已恢复，立即停止；只写恢复 event，不生成 ErrorReport |
| `RecoveryAction::Failed(error)` | 恢复自身失败，立即停止；保留原错误作为 cause |

处理器 panic 会被隔离并转成 typed `TaskAbandoned`。处理器运行期间不会持有注册表锁；同一线程递归调用恢复会被拒绝，避免恢复环。

首版不公开 wildcard、任意 predicate、优先级、重试次数、退避、熔断或异步 handler。一个错误码不够表达资源专属恢复时，领域层应先判断自己拥有的资源，再决定 `Recovered` 或 `NotHandled`，不要把动态资源选择器扩散成公共总线。

## 显式尝试，不由 report 自动触发

恢复必须由当前错误责任方在安全线程调用：

```rust uix-compile=assurance-attempt-recovery
use uix::core::Error;
use uix::diagnostics::{Diagnostics, RecoveryOutcome};

fn recover_or_propagate(
    diagnostics: &Diagnostics,
    error: Error,
) -> Result<(), Error> {
    match diagnostics.attempt_recovery(error) {
        RecoveryOutcome::Recovered => Ok(()),
        RecoveryOutcome::Unhandled(error)
        | RecoveryOutcome::Failed(error) => Err(error),
    }
}
```

`attempt_recovery` 不会自动报告失败。调用方仍可继续返回 `Error`；只有无法再返回的最终责任边界才调用 `report`。

`report` 也不会反向触发恢复。这个分离避免日志、快照读取或终止记录意外执行用户代码。

FFI、Win32 / ObjC / Wayland callback、GPU driver callback 和析构函数不能直接调用用户恢复处理器。它们只投递有界 owned failure；平台或图形 owner thread drain 后才允许 `attempt_recovery`。

## 框架与用户共用

每个 App runtime 只有一个 `Diagnostics`。框架内部和应用从同一实例注册与尝试恢复：

```rust uix-compile=assurance-app-handle
use uix::app::AppHandle;
use uix::diagnostics::{
    Diagnostics,
    RecoveryAction,
    RecoverySubscription,
};
use uix::prelude::Errc;

struct RecoveryRegistrations {
    _timeout: RecoverySubscription,
}

fn install_recovery(handle: &AppHandle) -> RecoveryRegistrations {
    let diagnostics: Diagnostics = handle.diagnostics();
    RecoveryRegistrations {
        _timeout: diagnostics.on_error(
            Errc::Timeout,
            |_| RecoveryAction::NotHandled,
        ),
    }
}
```

把 registration 存入应用服务或其他明确 owner；释放该 owner 即注销恢复。App 之外的工具与测试可用 `Diagnostics::new(config)` 创建隔离实例。

## 普通日志

框架和应用直接使用标准 `tracing` event / span。UIX 不安装进程全局 subscriber，也不提供第二套日志宏、Level、Logger、Sink 或 Layer：

```toml
[dependencies]
tracing = "0.1"
tracing-subscriber = "0.3"
```

```text
tracing_subscriber::fmt()
    .with_max_level(tracing::Level::INFO)
    .try_init()?;
```

```rust uix-compile=assurance-user-tracing
let item_count = 3usize;
let span = tracing::info_span!("import", item_count);
let _entered = span.enter();
tracing::info!("开始导入");
tracing::warn!(skipped_count = 1usize, "部分项目已跳过");
```

普通 `tracing::error!` 只是记录，不会创建 `Error` 或 `ErrorReport`。宿主负责文本 / JSON 输出、文件轮转、外部 Layer、worker guard 与 flush 生命周期。

## 最终错误报告

如果错误还能返回，就继续返回。若当前层已经最终消费且恢复未成功，只报告一次：

```rust uix-compile=assurance-final-report
use uix::core::Error;
use uix::diagnostics::Diagnostics;

fn finish_job(
    diagnostics: &Diagnostics,
    result: Result<(), Error>,
) {
    if let Err(error) = result {
        let _report_id = diagnostics.report(error);
        // 不再为同一个失败额外写 tracing::error!。
    }
}
```

`report` 先把有界、脱敏 `ErrorReport` 留存在 runtime store，再在锁外发送一条固定 target 的 tracing event。即使没有 subscriber、event 被过滤或 subscriber panic，快照仍保留报告。

Fatal 的普通 `report` 不会终止进程。只有顶层 runtime 判定不能安全继续时才进入独立 CrashReport 路径。

## 配置与快照

```rust uix-compile=assurance-config
use uix::diagnostics::{
    BacktracePolicy,
    Diagnostics,
    DiagnosticsConfig,
};

let diagnostics = Diagnostics::new(
    DiagnosticsConfig::default()
        .report_capacity(1_024)
        .crash_report_directory("logs/crash")
        .backtrace(BacktracePolicy::ErrorsAndFatal),
);

let snapshot = diagnostics.snapshot();
assert_eq!(snapshot.reports().len(), 0);
```

默认容量是 256；配置为 0 会规范化为 1。单条报告最多 32 KiB、最多 16 层 cause、单段文本最多 2 KiB，这些安全预算不能由用户放大。

```rust uix-compile=assurance-snapshot
use uix::diagnostics::Diagnostics;

fn print_snapshot(diagnostics: &Diagnostics) {
    let snapshot = diagnostics.snapshot();
    println!(
        "total={}, retained={}, evicted={}",
        snapshot.total_reports(),
        snapshot.reports().len(),
        snapshot.evicted_reports(),
    );

    for report in snapshot.reports() {
        println!(
            "{} {:?} {:?} {}",
            report.id(),
            report.code(),
            report.severity(),
            report.summary(),
        );
    }
}
```

快照是调用时点的不可变副本，按 `ReportId` 从旧到新排列。`ReportId` 只在一个 `Diagnostics` 生命周期内唯一，不是跨进程身份。`ErrorReport` 不返回原始 `Error` 或无界 `what()`。

## 公开 API

唯一目标公开面为：

```text
uix::diagnostics::{
    BacktracePolicy,
    Diagnostics,
    DiagnosticsConfig,
    DiagnosticsSnapshot,
    ErrorReport,
    RecoveryAction,
    RecoveryOutcome,
    RecoverySubscription,
    ReportId,
}

Diagnostics::new(config: DiagnosticsConfig) -> Diagnostics
Diagnostics::on_error(
    &self,
    code: Errc,
    handler: impl Fn(&Error) -> RecoveryAction + Send + Sync + 'static,
) -> RecoverySubscription
Diagnostics::attempt_recovery(&self, error: Error) -> RecoveryOutcome
Diagnostics::report(&self, error: Error) -> ReportId
Diagnostics::snapshot(&self) -> DiagnosticsSnapshot

RecoveryOutcome::is_recovered(&self) -> bool
RecoveryOutcome::into_error(self) -> Option<Error>

DiagnosticsConfig::report_capacity(self, usize) -> DiagnosticsConfig
DiagnosticsConfig::crash_report_directory(self, impl Into<PathBuf>) -> DiagnosticsConfig
DiagnosticsConfig::backtrace(self, BacktracePolicy) -> DiagnosticsConfig

App::diagnostics(self, config: DiagnosticsConfig) -> App
AppHandle::diagnostics(&self) -> Diagnostics

DiagnosticsSnapshot::reports(&self) -> &[ErrorReport]
DiagnosticsSnapshot::total_reports(&self) -> u64
DiagnosticsSnapshot::evicted_reports(&self) -> u64

ErrorReport::id(&self) -> ReportId
ErrorReport::observed_at(&self) -> SystemTime
ErrorReport::code(&self) -> Errc
ErrorReport::severity(&self) -> ErrorSeverity
ErrorReport::summary(&self) -> &str
ErrorReport::origin_target(&self) -> &str
ErrorReport::operation(&self) -> Option<&str>
ErrorReport::resource(&self) -> Option<(&str, &str)>
ErrorReport::causes_truncated(&self) -> bool
ErrorReport::event_emitted(&self) -> bool
```

这些类型从 `uix::diagnostics` 显式导入，不进入 prelude。既有 `Error`、`Errc`、`ErrorSeverity` 与 `Result` 保持原公开位置。

不公开第二套 `Logger` / `Sink` / `Collector`、普通 ErrorReport 订阅总线、恢复优先级、通用 retry / circuit breaker、用户可实现的 Diagnostics Layer、crash writer 或 abort 函数。

## 隐私与宿主责任

- 不把密码、token、secret、剪贴板、输入内容、窗口标题、文件内容或完整路径写入 Error / tracing / pending failure。
- 固定清洗和截断不能理解任意业务秘密；应用 Error 消息仍必须是安全诊断文本。
- 恢复处理器不得阻塞 owner thread，不得等待自己所在的主循环，也不得在持有领域锁时调用未知用户代码。
- 宿主 Layer 不得在处理 `uix::diagnostics` event 时再次调用 `report`；框架仍以重入 guard 抑制递归 event。
- UIX 默认不上传诊断信息。
