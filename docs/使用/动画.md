# 动画

UIX 提供两层动画 API：声明式 `Animated<T>` 绑定普通 View 属性，指令式 `Animation<T>` 用于自定义 `component!`。两者都由逐窗 frame opportunity 推进；**勿用 [`run_interval`](定时与异步.md#定时器) 模拟帧动画。**

带 `uix-compile` 的 Rust fence 是外部 consumer 持续编译的公开写法。

> 快速导航：[声明式动画](#声明式动画推荐) · [进出场动画](#进出场动画) · [缓动曲线](#缓动曲线) · [底层 API](#底层-api自定义组件)

---

## 场景速查

| 需求 | API |
|------|-----|
| 透明度淡入 | `Animated::new(0.0).to(1.0, 0.3, Easing::ease_out)` |
| 弹入效果 | `Animated::new(0.0).to_spring(1.0, Spring::bouncy())` |
| View 透明度绑定 | `.opacity_animated(&opacity)` |
| 列表逐项入场 | `AnimationGroup::stagger(items, 0.05)` |
| 多步关键帧 | `Animated::keyframes([...]).duration(0.6)` |
| 并行动画 | `AnimationGroup::parallel([a.group_item(), b.group_item()])` |
| 串行动画 | `AnimationGroup::sequential([a.group_item(), AnimationGroup::delay(0.1), b.group_item()])` |
| 弹窗进场 | `Modal::show(...).enter_animation(AnimationConfig::zoom_in(0.2))` |
| 循环呼吸灯 | `Animated::new(0.3).to(1.0, 1.0, Easing::ease_in_out).loop_alternate()` |
| 自定义组件动画 | `component!` + `update_animation` + `Animation<T>` |

## 快速入门

最简单的动画只需要两行——创建 `Animated`，在 View 中绑定：

```rust uix-compile=animated-quickstart
let fade = Animated::new(0.0_f32).to(1.0, 0.3, Easing::ease_out);
// ↓ 在 root 中读取 value()，框架自动推进帧
label("淡入文字").opacity(fade.value());
```

## 声明式动画（推荐）

当前声明式公开面是固定时长的单值过渡、延迟启动、循环播放、单次 Spring、typed 单值 keyframe、由 `keyframe!` 定义的多属性聚合 keyframe、一次性完成回调、View 样式与视觉 offset / scale 的直接绑定、普通 View 的进出场与列表级 stagger，以及有限时间线的并行 / 串行 / stagger 编排。

### Animated\<T\> —— 声明式动画值

`Animated<T>` 是一个共享的响应式动画值。把它创建在 `App::root` 外，并在 root closure 中读取 `value()`；框架会把仍在运行的值登记到该窗口，值变化时只 reconcile 原 root，不增加布局节点或常驻轮询。多个 clone 共享进度，同一个值至多由一个窗口推进。

#### 创建与配置

```rust uix-compile=animated-basic
use uix::prelude::*;

fn main() {
    let opacity = Animated::new(0.0_f32).to(1.0, 0.3, Easing::ease_out);
    let view_opacity = opacity.clone();

    App::new()
        .title("Animated")
        .root(move || label("淡入").opacity(view_opacity.value()))
        .run();
}
```

`.to(...)` 适合构造时启动；后续目标变化在 UI 事件中调用 `animate_to(target, duration_secs, easing)`，跨线程触发则放进 `AppHandle::post_to_ui`。它会从当前插值重新定向；`duration_secs <= 0` 立即提交终值，不登记帧工作。

延迟启动使用 `to_after(delay_secs, ...)` 或 `animate_to_after(delay_secs, ...)`：

```rust uix-compile=animated-delay
let delayed = Animated::new(0.0_f32)
    .to_after(0.2, 1.0, 0.3, Easing::ease_out);

let retargetable = Animated::new(10.0_f32);
retargetable.animate_to_after(0.1, 20.0, 0.25, Easing::linear);
```

等待期保留起值与 `progress() == 0`，`is_finished()` 为 false；框架只登记一次 deadline，不连续申请动画帧。`delay_secs <= 0` 等同立即启动；即使 `duration_secs <= 0`，正延迟也会等到 deadline 才提交终值。暂停会保存剩余等待时间，继续时重新登记；`restart()` / `reverse()` 会重新等待原延迟。

#### 读取值

```rust uix-compile=animated-read-state
let anim = Animated::new(0.0_f32).to(1.0, 0.3, Easing::ease_out);
let current = anim.value();       // 当前插值，并把该值登记到当前 root
let progress = anim.progress();   // 当前一轮的 [0, 1]，也登记 root 依赖
let finished = anim.is_finished();
```

#### 控制播放

```rust uix-compile=animated-playback-controls
use std::sync::atomic::{AtomicBool, Ordering};
use std::sync::Arc;

let anim = Animated::new(0.0_f32).to(1.0, 0.3, Easing::ease_out);
anim.pause();   // 暂停并保留当前进度
anim.resume();  // 继续未完成的过渡
anim.stop();    // 跳到终值并停止
anim.restart(); // 从原始起值重播
anim.reverse(); // 交换起止值并重播

let repeating = Animated::new(0.0_f32)
    .to(1.0, 0.3, Easing::ease_in_out)
    .loop_count(3);      // 总共正向播放 3 次
let forever = Animated::new(0.0_f32)
    .to(1.0, 0.3, Easing::linear)
    .loop_forever();     // 每轮回到起点
let breathing = Animated::new(0.3_f32)
    .to(1.0, 1.0, Easing::ease_in_out)
    .loop_alternate();   // 无限往返

let completed = Arc::new(AtomicBool::new(false));
let completed_in_callback = Arc::clone(&completed);
let with_callback = Animated::new(0.0_f32)
    .to(1.0, 0.3, Easing::ease_out)
    .on_finish(move || {
        completed_in_callback.store(true, Ordering::Release);
    });
```

`loop_count(0)` 立即提交目标值且不登记帧；`restart()` 与 `reverse()` 会重置整段循环序列。无限循环必须由应用在 View 移除、窗口关闭或显式 `stop()` 时结束；窗口 `Suspended` 期间仍冻结，不产生隐藏帧。

`on_finish` 把 `FnOnce() + Send + 'static` 绑定到当前 playback，所有 clone 共享且只触发一次；`set_on_finish` 可替换尚未触发的回调。自然完成时先发布终值并释放 playback 锁，再在所属窗口的动画推进中执行；有限循环要等全部轮次结束，deadline 延迟和零时长仍各自遵守原完成时点。`stop()` 不消费回调，随后 `restart()` 自然完成仍会触发；`animate_to*` / `animate_keyframes` 替换 playback 时丢弃旧回调。若绑定时 source 已在终态（包括没有 playback），回调会在调用线程立即执行。因此回调只能使用公开线程安全句柄或排队入口，不得捕获并直接访问 `WidgetTree` 等窗口内部对象。

#### 完整 API 参考

| 方法 | 说明 |
|------|------|
| `Animated::new(initial_value)` | 创建并设定初值 |
| `.to(target, duration_secs, easing)` | 构造并启动固定时长过渡 |
| `.to_after(delay_secs, target, duration_secs, easing)` | 构造并在 deadline 后启动过渡 |
| `.animate_to(target, duration_secs, easing)` | 从当前插值重新定向 |
| `.animate_to_after(delay_secs, target, duration_secs, easing)` | 从当前值登记延迟过渡 |
| `.to_keyframes(frames, duration_secs)` | 构造并启动单次 typed keyframe 序列 |
| `.animate_keyframes(frames, duration_secs)` | 替换为单次 typed keyframe 序列 |
| `.to_spring(target, spring)` / `.animate_to_spring(...)` | 构造或替换为单次 Spring |
| `.value()` | 当前插值 |
| `.progress()` | 进度 [0, 1] |
| `.is_finished()` | 是否到达终点 |
| `.pause()` / `.resume()` | 暂停 / 继续 |
| `.stop()` | 跳到终点并停帧 |
| `.restart()` | 从初值重播 |
| `.reverse()` | 交换起止值重播 |
| `.loop_count(n)` | 总共正向播放 n 次；0 次立即提交终值 |
| `.loop_forever()` | 无限正向重播，每轮回到起点 |
| `.loop_alternate()` | 无限正反向交替播放 |
| `.on_finish(callback)` | builder 写法：为当前 playback 绑定一次性完成回调 |
| `.set_on_finish(callback)` | 替换当前 playback 尚未触发的完成回调 |

### Spring —— 弹簧物理动画

弹簧动画不按固定时长播放，而是根据物理参数自然衰减到终点。适合需要"手感"的交互（按钮回弹、拖拽释放、列表边缘效果）。

#### 预设

```rust uix-compile=animated-spring
let bouncy = Spring::bouncy();   // 弹跳感强
let gentle = Spring::gentle();   // 柔和平滑
let snappy = Spring::snappy();   // 快速响应
let critical = Spring::critical(); // 临界阻尼，不过冲

let scale = Animated::new(1.0_f32)
    .to_spring(0.95, snappy);
scale.animate_to_spring(1.0, bouncy);
```

#### 自定义参数

```rust uix-compile=spring-custom
let custom_spring = Spring::custom()
    .stiffness(200.0)    // 刚度（默认 170），越大回弹越快、震荡频率越高
    .damping(15.0)       // 阻尼（默认 20），越小震荡越久
    .mass(1.0)           // 质量（默认 1），越大惯性越大
    .velocity(0.0)       // 初始速度，正值朝向目标、负值背离目标
    .rest_speed(0.001)
    .rest_displacement(0.001);

let mut direct = SpringAnimation::new(0.0_f32, 1.0, custom_spring);
let current = direct.update(1.0 / 60.0);
```

| 预设 | stiffness | damping |
|------|-----------|---------|
| `bouncy` | 170 | 12 |
| `gentle` | 120 | 18 |
| `snappy` | 300 | 25 |
| `critical` | 170 | `2 * sqrt(170)` |

Spring 用解析解采样归一化位移和速度，不依赖固定 duration，也不因大 `dt` 数值爆炸。实际值距终点与实际速度同时进入静止阈值后，值精确提交到目标并撤销帧登记；`progress()` 裁到 `[0, 1]`，`value()` 仍保留欠阻尼过冲。`pause()` / `resume()` / `stop()` / `restart()` / `reverse()` 与固定时长过渡共用控制面；`to_spring` 每次启动单次物理过渡并清除之前的循环模式，循环修饰只适用于固定时长过渡。窗口 Suspended 时仍由主循环统一冻结。

直接使用 `SpringAnimation<T>` 时可继续调用 `value()`、`progress()`、`is_finished()`、上述播放控制与一次性 `on_finish`；它适合自定义 `component!`，声明式 View 绑定优先使用 `Animated<T>`。

### Keyframe —— 关键帧动画

`Keyframe<T>` 为一个 `Animatable` 值声明归一化 offset，以及从该点到下一点使用的 easing；`KeyframeAnimation<T>` 可直接用于自定义组件，`Animated<T>` 则把同一序列交给逐窗 sidecar：

```rust uix-compile=animated-keyframes
let pulse = Animated::new(1.0_f32)
    .to_keyframes(
        [
            Keyframe::new(0.0, 1.0).easing(Easing::ease_out),
            Keyframe::new(0.5, 1.2).easing(Easing::ease_in),
            Keyframe::new(1.0, 1.0),
        ],
        0.6,
    )
    .expect("non-empty finite keyframes");

pulse
    .animate_keyframes(
        [Keyframe::new(0.0, pulse.value()), Keyframe::new(1.0, 0.8)],
        0.2,
    )
    .expect("non-empty finite keyframes");
```

offset 必须有限，随后会裁到 `[0, 1]` 并稳定排序；重复 offset 以后声明者为准。缺少 0 时，`Animated` 从当前值补起点，直接 `KeyframeAnimation::new` 则重复首个声明值；缺少 1 时重复末值。空序列返回 `KeyframeError::Empty`，非有限 offset 返回 `NonFiniteOffset`。非有限或非正 duration 直接提交终值且不登记帧；大 `dt` 一次裁到终态。pause / resume / stop / restart / reverse 与完成回调复用底层播放控制；keyframe 是单次序列，循环修饰仍只作用于普通固定时长 `.to(...)`。

#### 多属性 keyframe!

`keyframe!` 定义一个普通 typed 属性结构体，并自动生成逐字段 `Animatable` 实现。把这个结构体作为单个 `Animated<T>` 的值，即可让全部属性共享同一时间线：

```rust uix-compile=animated-keyframe-properties
keyframe! {
    #[derive(Debug, PartialEq)]
    struct MotionFrame {
        opacity: f32,
        offset_y: f32,
        scale: f32,
    }
}

let slide_up = Animated::new(MotionFrame::new(0.0, 30.0, 1.0))
    .to_keyframes(
        [
            Keyframe::new(0.0, MotionFrame::new(0.0, 30.0, 1.0))
                .easing(Easing::ease_out),
            Keyframe::new(0.6, MotionFrame::new(0.8, -5.0, 1.0))
                .easing(Easing::ease_in),
            Keyframe::new(1.0, MotionFrame::new(1.0, 0.0, 1.0)),
        ],
        0.5,
    )
    .expect("non-empty finite keyframes");

let current = slide_up.value();
let opacity = current.opacity;
let offset_y = current.offset_y;
let scale = current.scale;
```

结构体、字段与构造器的可见性由宏声明决定；每个字段类型都必须实现 `Animatable`，否则在编译期失败。宏只生成值类型，不生成独立播放器：整组属性仍只有一个 `Animated` source、一次逐窗 registration、一个 `progress()` 和一份播放控制。每段 easing 同时采样整组字段；`KeyframeError` 仍归属于整条序列，无效序列不会部分替换属性。聚合 `delta` 取各字段绝对 delta 的最大值，因此 Spring 也要等所有字段进入静止阈值才完成。

### AnimationGroup —— 编排

`AnimationGroup` 把已有 `Animated<T>` source 组合成并行、串行或按固定间隔错峰启动的有限时间线。不同值类型先用 `group_item()` 擦除类型；组本身不新增 frame registration，每个子 source 仍沿用自己的 open / deadline 登记。

```rust uix-compile=animation-group
let opacity = Animated::new(0.0_f32).to(1.0, 0.3, Easing::ease_out);
let offset = Animated::new(Point::new(0.0, 20.0))
    .to(Point::new(0.0, 0.0), 0.3, Easing::ease_out);
let enter = AnimationGroup::parallel([
    opacity.group_item(),
    offset.group_item(),
])
.expect("finite parallel animations");

let fade = Animated::new(0.0_f32).to(1.0, 0.3, Easing::ease_out);
let scale = Animated::new(1.0_f32).to(1.1, 0.2, Easing::ease_out);
let sequence = AnimationGroup::sequential([
    fade.group_item(),
    AnimationGroup::delay(0.1),
    scale.group_item(),
])
.expect("finite sequential animations");

let item_a = Animated::new(0.0_f32).to(1.0, 0.3, Easing::ease_out);
let item_b = Animated::new(0.0_f32).to(1.0, 0.3, Easing::ease_out);
let staggered = AnimationGroup::stagger(
    [item_a.group_item(), item_b.group_item()],
    0.05,
)
.expect("finite staggered animations");

let enter_progress = enter.progress();
let sequence_progress = sequence.progress();
let staggered_progress = staggered.progress();
sequence.pause();
sequence.resume();
sequence.restart();
```

构造组会从各子动画的原始起值重新排程；`parallel` 以最长子项为总时长，`sequential` 按声明顺序排程，`stagger(items, interval_secs)` 让第 n 项从 `n * interval` 启动，`delay(seconds)` 是不改变 View 值的有限占位项。大 `dt` 或迟到的 deadline 会一次消费已经越过的时间，不逐段 busy retry；有限 `loop_count(n)` 在组内按全部 n 轮计算进度。`duration()`、`progress()`、`is_finished()` 提供整组状态，`pause()` / `resume()` / `restart()` / `stop()` 同时控制全部子项。在 root closure 中读取子动画的 `value()`；只需观察组状态时，读取 `progress()` 或 `is_finished()` 也会 capture 全部子 source。

组必须能在构造时证明总时长且每个 source 只排程一次：空组、重复 source、未配置 playback 的 source、已经带 `to_after` 延迟的 source、Spring 与无限循环分别返回 typed `AnimationGroupError`。串行空档应显式使用 `AnimationGroup::delay`；非有限或非正 delay / stagger interval 归一为零。

### View 属性动画绑定

把已有 `Animated<T>` 直接交给同类型的样式方法；方法只在 root build 中读取 `value()`，动画配置和后续 retarget 仍由 source 自己负责。

```rust uix-compile=animated-view-style
let opacity = Animated::new(0.0_f32).to(1.0, 0.3, Easing::ease_out);
let background = Animated::new(Color::WHITE)
    .to(Color::hex("#E8F4FD"), 0.3, Easing::ease_out);
let foreground = Animated::new(Color::BLACK)
    .to(Color::hex("#1677FF"), 0.3, Easing::ease_out);
let width = Animated::new(120.0_f32).to(180.0, 0.3, Easing::ease_out);
let height = Animated::new(32.0_f32).to(40.0, 0.3, Easing::ease_out);
let radius = Animated::new(4.0_f32).to(12.0, 0.3, Easing::ease_out);
let offset = Animated::new(Point::new(0.0, 20.0))
    .to(Point::new(0.0, 0.0), 0.3, Easing::ease_out);
let scale = Animated::new(0.9_f32).to(1.0, 0.3, Easing::ease_out);

let card = label("animated style")
    .opacity_animated(&opacity)
    .bg_animated(&background)
    .color_animated(&foreground)
    .width_animated(&width)
    .height_animated(&height)
    .radius_animated(&radius)
    .offset_animated(&offset)
    .scale_animated(&scale);
```

这些 binding 不创建 wrapper View、widget timer 或额外动画 source；同一个 source 绑定多个属性时，root capture 仍按 source id 去重。reconcile 保留原节点身份，opacity / color / background / radius 走既有样式绘制差异，width / height 仍按普通样式变化进入布局。

`.offset(Point)` / `.scale(f32)` 及对应的 animated 方法是 visual-only transform：布局 frame 不变，scale 以节点布局 frame 中心为原点，随后应用 offset。绘制、命中、空间事件坐标、语义边界与 damage 使用同一祖先变换链；scale 为 0 时节点折叠且不可命中。变换子树暂不使用 Picture 缓存；变换路径中的滚动不提交像素搬移，而是保守重绘。

#### 已落地属性方法

| 方法 | 动画类型 | 适用场景 |
|------|----------|----------|
| `.opacity_animated(&source)` | `Animated<f32>` | 淡入淡出 |
| `.bg_animated(&source)` | `Animated<Color>` | 背景色过渡 |
| `.color_animated(&source)` | `Animated<Color>` | 文字色过渡 |
| `.width_animated(&source)` | `Animated<f32>` | 宽度变化 |
| `.height_animated(&source)` | `Animated<f32>` | 高度变化 |
| `.radius_animated(&source)` | `Animated<f32>` | 圆角变化 |
| `.offset_animated(&source)` | `Animated<Point>` | 不改变布局的视觉位移 |
| `.scale_animated(&source)` | `Animated<f32>` | 以布局 frame 中心缩放 |

## 进出场动画

### 普通 View 进出场动画

给 View 设置一次性进场和离场动画；列表项使用稳定 key 时，移除期间可保留原节点完成离场：

```rust uix-compile=view-enter-animation
let faded = label("new item")
    .key("item-1")
    .enter_animation(AnimationConfig::fade_in(0.2))
    .leave_animation(AnimationConfig::fade_out(0.15));
let slid = label("from bottom")
    .enter_animation(AnimationConfig::slide_in(Placement::Bottom, 0.3));
let zoomed = label("zoom")
    .enter_animation(AnimationConfig::zoom_in(0.2));
let staggered = column((label("first"), label("second"), label("third")))
    .stagger_enter(0.05, AnimationConfig::slide_in(Placement::Bottom, 0.3));
```

进场只在节点首次挂载时启动；同 key、同组件类型的正常 reconcile 保留当前进度，不会重播。带 `leave_animation` 的节点从声明树移除后，保留原节点和布局位置直至动画完成，同时立即退出命中、焦点、语义、Timer 与浮层管理；完成后才删除并请求布局。同 key 在完成前重新出现会取消离场并复用原节点；进场中转为离场会从当前视觉状态衔接，不跳帧。

单独配置的 duration 为 0 时直接完成，不登记帧。`enter_animation` 只接受 `fade_in` / `slide_in` / `zoom_in`，`leave_animation` 只接受对应 exit 预设，误传会立即报错。opacity 与 offset / scale 作用于整棵子树但不改变布局，逐窗主循环只在动画仍活动时登记下一帧。

`stagger_enter(interval_secs, config)` 把给定进场预设应用到直接子节点：首次挂载时按声明顺序编号；后续 reconcile 只给本轮新挂载项重新从 0 编号，已有同 key 节点不重播、等待中的 deadline 也不重置。第一项立即开始，第 n 项在 `n * interval_secs` 后开始；等待期只登记一个 deadline，不连续申请帧，唤醒迟到时一次消费超期。非有限或非正 interval 归一为 0；零时长项仍等到自己的 deadline 才提交终态。

### 浮层进出场动画

[反馈](反馈.md) 中的 Modal / Drawer / Popover / Message / Notification 支持可配置的 enter + leave 两段式动画：

```rust uix-compile=overlay-animations
// Modal 弹出/关闭
Modal::show(|_| label("Modal content"))
    .enter_animation(AnimationConfig::fade_in(0.2))
    .leave_animation(AnimationConfig::fade_out(0.15));

// Drawer 滑入/滑出
Drawer::new("设置")
    .placement(DrawerPlacement::Right)
    .show()
    .enter_animation(AnimationConfig::slide_in(Placement::Right, 0.25))
    .leave_animation(AnimationConfig::slide_out(Placement::Right, 0.2));

// Popover 从触发点右侧滑入
Popover::new("详情")
    .placement(PopoverPlacement::Right)
    .enter_animation(AnimationConfig::slide_in(Placement::Right, 0.15))
    .leave_animation(AnimationConfig::fade_out(0.1));
```

`AnimationConfig` 预设：

| 方法 | 效果 |
|------|------|
| `AnimationConfig::fade_in(duration)` | 淡入（opacity 0→1） |
| `AnimationConfig::fade_out(duration)` | 淡出（opacity 1→0） |
| `AnimationConfig::slide_in(placement, duration)` | 方向滑入（含位移 + 淡入） |
| `AnimationConfig::slide_out(placement, duration)` | 方向滑出（含位移 + 淡出） |
| `AnimationConfig::zoom_in(duration)` | 缩放弹出（scale 0.8→1 + 淡入） |
| `AnimationConfig::zoom_out(duration)` | 缩放收起（scale 1→0.8 + 淡出） |

// 基础
let linear = Easing::linear;

## 底层 API（自定义组件）

声明式 API 内部也使用这套底层机制。在自定义 `component!` 中直接使用时：

```rust uix-compile=component-animation-fade
component! {
    pub struct FadingBox {
        opacity: f32,
        fade: Animation<f64>,
    }

    @new -> Self {
        Self {
            opacity: 0.0,
            fade: Animation::new(0.0, 1.0, 0.3).easing(Easing::ease_out),
        }
    }

    render => (&self, frame: Rect, ctx: &mut PaintContext) {
        ctx.fill_rect(frame, Color::rgba(0, 0, 255, (self.opacity * 255.0) as u8), None);
    }

    update_animation => (&mut self, dt: f64) -> bool {
        self.opacity = self.fade.update(dt) as f32;
        !self.fade.is_finished()
    }

    dirty_bounds => (&self, frame: Rect) -> Rect {
        // 动画只改变本组件 frame 内的像素。
        frame
    }
}
```
