# 快速开始

[← 返回使用索引](../../使用.md)

> **接口**：声明 UIX 的依赖配置、第一个应用（Hello World）、计数器示例和公开 crates.io 接入写法。依赖：[产品](../../产品.md)（需先了解 UIX 是什么）。导出：响应式基础 → [响应式基础](响应式基础.md)；运行保障 → [运行保障](../框架设施/运行保障.md)。

> **推荐方式**：界面用 uix-lang 描述，见 [uix-lang 快速开始](../../uix-lang/指南/快速开始.md)（`uix!` 生成 View，`uix_app!` 生成完整 App builder）；本页为当前可运行的 Rust 声明式 API 写法，也是 uix-lang 的底层表示。

## 前置条件

- 使用最新稳定版 Rust/Cargo；本次 0.0.8 发布验证使用 1.98.1，未独立承诺最低 Rust 版本。
- 具备目标平台需要的原生构建环境，平台和 feature 边界见[交付与许可](../../产品/交付与许可.md)。
- 正文使用系统字体或应用显式提供的 FontBundle；框架不再内置完整正文字体。

## 添加依赖

在应用的 Cargo.toml 中添加：

```toml
[dependencies]
uix-app = "=0.0.8"
```

Cargo 包名为 uix-app，Rust 库路径为 uix_app。四个同版本依赖从公开 crates.io
解析，不需要私有 Registry、发布令牌或内部授权。应用可保留 Cargo.lock 记录版本与
checksum；这不等于固定 Rust 工具链。MIT 许可及源码联调方式见[交付与许可](../../产品/交付与许可.md)。

## 第一个应用

> **推荐方式**：界面用 [uix-lang](../../uix-lang/README.md)（`.uix` 文档）描述，编译时自动转换为 Rust；Rust 声明式 API 同样受支持，已登记语言能力具有确定的 Rust 语义映射。公开 `uix!` 生成 `ViewNode`，`uix_app!` 从 `<App>` 根生成现有 `App` builder；以下 Rust 写法继续承担窗口生命周期扩展和尚未登记能力，也是 uix-lang 的底层表示。

```rust uix-compile=quick-start-hello
use uix_app::prelude::*;

fn main() {
    App::new()
        .title("Hello UIX")
        .size(400, 300)
        .root(|| label("Hello, world!").font_size(32.0))
        .run();
}
```

运行后应创建一个逻辑尺寸为 400 × 300 的原生窗口并显示 “Hello, world!”；关闭窗口后结束应用。窗口或图形初始化失败时应保留 typed error 和诊断输出，不把失败改写成空白界面或伪成功。

## 带交互的计数器

```rust uix-compile=quick-start-counter
use uix_app::prelude::*;

fn main() {
    let count = State::new(0);

    App::new()
        .title("计数器")
        .size(360, 200)
        .root(move || {
            column((
                count.map_text(|n| format!("{n}")).font_size(48.0),
                row((
                    button("-1").on_click(&count, |c| c.update(|v| *v -= 1)),
                    button("+1").primary().on_click(&count, |c| c.update(|v| *v += 1)),
                )).gap(8.0),
            ))
            .gap(16.0)
            .padding(24.0)
        })
        .run();
}
```

## 推荐用法

```rust uix-compile=quick-start-typed-route
use uix_app::prelude::*;

// 类型化页面切换 + 组件组合（已落地 API 的推荐组合）
#[derive(Clone, PartialEq)]
enum Page { Home, Settings }

impl std::fmt::Display for Page {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        f.write_str(match self {
            Self::Home => "home",
            Self::Settings => "settings",
        })
    }
}

// 声明首页的最小公开 View 构造函数。
fn home_view() -> ViewNode {
    // 返回可直接参与页面组合的首页节点。
    label("首页")
// 结束首页 View 构造函数。
}

// 声明设置页的最小公开 View 构造函数。
fn settings_view() -> ViewNode {
    // 返回可直接参与页面组合的设置页节点。
    label("设置")
// 结束设置页 View 构造函数。
}

// 声明由主题和响应式页面状态驱动的应用根。
fn app_root(theme: &Theme, page: &State<Page>) -> ViewNode {
    column((
        embed(Navigation::<Page>::new("我的应用")
            .item("首页", Page::Home)
            .item("设置", Page::Settings)
            .active_page(page)
            .build(theme.tokens())),
        page.map(|p| match p {
            Page::Home => home_view(),
            Page::Settings => settings_view(),
        }),
    ))
}
```

```rust uix-compile=route-display-derive
// 导入公开 Display 派生宏。
use uix_app::prelude::*;

// Display 派生宏免除手写实现，使路由定义更紧凑。
#[derive(Clone, PartialEq, Display)]
enum Page { Home, Settings }
```

要点：

- 状态用 `State<T>` 持有，界面由状态驱动，不手工操作 DOM 或绘制队列。
- 组合优先：先用小组件拼出页面，需要私有状态/精细事件时再升级为 `widget!`（见[组件](../界面构建/组件.md)）。
- 平台能力、图形后端、窗口生命周期由框架托管（见[不必做](../能力与边界/不必做.md)）。

## 出错怎么办

失败有类型、恢复有路径、崩溃有报告（容错可观测）：业务失败一律返回 typed `Error`（不吞错、不转伪成功）；可恢复资源由所有者登记恢复动作；无法恢复的崩溃由框架安装的 panic hook 记录有界 CrashReport；日志输出位置由宿主决定。框架与应用共用同一个 `uix_app::diagnostics` 公开面，完整用法见[运行保障](../框架设施/运行保障.md)。

按症状排查编译、feature、平台服务、Settings、日志或 Agent 问题时，参见[故障排查](故障排查.md)；产品与交付边界的常见疑问见[常见问题](常见问题.md)。
