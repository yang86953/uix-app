## 前置条件

- 已获得 UIX 私有 Cargo Registry 的授权访问权；共同养护框架的第一方应用也可使用[源码联调通道](../../产品/交付与许可.md#第一方源码联调通道)。UIX 不从 crates.io 解析。
- 目标平台属于当前交付范围，并具备对应的 Rust/Cargo 与原生构建环境。仓库文档当前没有声明独立 MSRV，不应自行推断最低 Rust 版本。
- 已根据目标平台选择需要的 Cargo feature；平台、图形后端与真实环境覆盖见[交付与许可](../../产品/交付与许可.md)和[配置](../框架设施/配置.md#图形后端)。
- 已决定使用 UIX Lang（推荐）还是 Rust 声明式 API（支持）；两种方式可以在应用组合根衔接，但不要把未登记的 UIX Lang 能力当作已交付。

## 添加依赖

```toml
[registries.gitea]
index = "sparse+https://yang-server.tail9d5559.ts.net/api/packages/admin/cargo/"
```

独立消费者在应用 `Cargo.toml` 中锁定正式包：

```toml
[dependencies]
uix = { version = "=0.0.7", registry = "gitea" }
```

UIX 按 `yangyanhui` 专有、仅限内部授权使用的方式发布到私有 Registry，不发布到 crates.io，也不对外分发；正式包消费者必须保留 `Cargo.lock` 中的版本、Registry 来源和 checksum。第一方应用只可按[源码联调通道](../../产品/交付与许可.md#第一方源码联调通道)固定私有 Git 完整提交，不得提交本地 `path` 或跟随移动分支。

正式包依赖添加成功后，Cargo 应从私有 Registry 解析 `uix`、`uix-derive` 与 `uix-lang-compiler` 三个同版本包。若失败，先检查 Registry 可达性和授权，不要用本地源码伪装正式包。

## 第一个应用

> **推荐方式**：界面用 [uix-lang](../../uix-lang/README.md)（`.uix` 文档）描述，编译时自动转换为 Rust；Rust 声明式 API 同样受支持，已登记语言能力具有确定的 Rust 语义映射。公开 `uix!` 生成 `ViewNode`，`uix_app!` 从 `<App>` 根生成现有 `App` builder；以下 Rust 写法继续承担窗口生命周期扩展和尚未登记能力，也是 uix-lang 的底层表示。

```rust uix-compile=quick-start-hello
use uix::prelude::*;

fn main() {
    App::new()
        .title("Hello UIX")
        .size(400, 300)
        .root(|| label("Hello, world!").font_size(32.0))
        .run();
}
```

运行后应创建一个逻辑尺寸为 400 × 300 的原生窗口并显示 “Hello, world!”；关闭窗口后结束应用。窗口或图形初始化失败时应保留 typed error 和诊断输出，不把失败改写成空白界面或伪成功。

## 带交互的计数器

```rust uix-compile=quick-start-counter
use uix::prelude::*;

fn main() {
    let count = State::new(0);

    App::new()
        .title("计数器")
        .size(360, 200)
        .root(move || {
            column((
                count.map_text(|n| format!("{n}")).font_size(48.0),
                row((
                    button("-1").on_click(&count, |c| c.update(|v| *v -= 1)),
                    button("+1").primary().on_click(&count, |c| c.update(|v| *v += 1)),
                )).gap(8.0),
            ))
            .gap(16.0)
            .padding(24.0)
        })
        .run();
}
```

## 推荐用法

```rust uix-compile=quick-start-typed-route
use uix::prelude::*;

// 类型化页面切换 + 组件组合（已落地 API 的推荐组合）
#[derive(Clone, PartialEq)]
enum Page { Home, Settings }

impl std::fmt::Display for Page {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        f.write_str(match self {
            Self::Home => "home",
            Self::Settings => "settings",
        })
    }
}

// 声明首页的最小公开 View 构造函数。
fn home_view() -> ViewNode {
    // 返回可直接参与页面组合的首页节点。
    label("首页")
// 结束首页 View 构造函数。
}

// 声明设置页的最小公开 View 构造函数。
fn settings_view() -> ViewNode {
    // 返回可直接参与页面组合的设置页节点。
    label("设置")
// 结束设置页 View 构造函数。
}

// 声明由主题和响应式页面状态驱动的应用根。
fn app_root(theme: &Theme, page: &State<Page>) -> ViewNode {
    column((
        embed(Navigation::<Page>::new("我的应用")
            .item("首页", Page::Home)
            .item("设置", Page::Settings)
            .active_page(page)
            .build(theme.tokens())),
        page.map(|p| match p {
            Page::Home => home_view(),
            Page::Settings => settings_view(),
        }),
    ))
}
```

```rust uix-compile=route-display-derive
// 导入公开 Display 派生宏。
use uix::prelude::*;

// Display 派生宏免除手写实现，使路由定义更紧凑。
#[derive(Clone, PartialEq, Display)]
enum Page { Home, Settings }
```

要点：

- 状态用 `State<T>` 持有，界面由状态驱动，不手工操作 DOM 或绘制队列。
- 组合优先：先用小组件拼出页面，需要私有状态/精细事件时再升级为 `widget!`（见[组件](../界面构建/组件.md)）。
- 平台能力、图形后端、窗口生命周期由框架托管（见[不必做](../能力与边界/不必做.md)）。

## 出错怎么办

失败有类型、恢复有路径、崩溃有报告（容错可观测）：业务失败一律返回 typed `Error`（不吞错、不转伪成功）；可恢复资源由所有者登记恢复动作；无法恢复的崩溃由框架安装的 panic hook 记录有界 CrashReport；日志输出位置由宿主决定。框架与应用共用同一个 `uix::diagnostics` 公开面，完整用法见[运行保障](../框架设施/运行保障.md)。

按症状排查编译、feature、平台服务、Settings、日志或 Agent 问题时，参见[故障排查](故障排查.md)；产品与交付边界的常见疑问见[常见问题](常见问题.md)。
