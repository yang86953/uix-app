# 常见问题

> **范围**：本文回答产品边界与接入方式中最容易混淆的问题。动态完成度仍以 [仓库状态账目](../../../TODO.md) 为准。

## 产品与交付

### UIX 已经正式发布了吗？

没有。当前版本为已内部发布的 `0.0.2`，仍处于早期 `0.y.z` 阶段；Windows 与 Linux 属于当前发布范围，但不代表 API 已承诺 `1.0.0` 级稳定性。候选包、正式发布、签名和分发是不同事实，详见[交付与许可](../../产品/交付与许可.md)。

### UIX 会发布到 crates.io 或按开源许可分发吗？

当前不会。根 crate 设置为 `publish = false`，UIX 按专有、仅限内部授权使用的方式交付；第三方材料继续遵循各自许可证。

### 当前支持哪些平台？

`0.0.2` 发布范围是 Windows 与 Linux。macOS 属于产品目标但不是本文档声明的当前交付；移动端 backend 暂缓。具体硬件与环境覆盖由 Gitea 持有。

## 开发方式

### 应该使用 UIX Lang 还是 Rust API？

UIX Lang 是推荐方式，Rust 声明式 API 是受支持的底层表示和扩展入口。已登记的 UIX Lang 能力映射到相同 Rust 语义；未登记能力仍使用 Rust API，不能假定两边已经覆盖完全相同的表面。入口见 [UIX Lang 快速开始](../../uix-lang/指南/快速开始.md)和 [Rust 快速开始](快速开始.md)。

### UIX Lang 是运行期脚本语言吗？

不是。`.uix` 在编译期转换为 Rust，运行期没有 UIX Lang 解释器。未登记语法在编译期报错，不在运行时猜测或降级。

### 为什么 Rust 组件数量与 UIX Lang 标签数量不同？

Rust 组件库和 UIX Lang 登记矩阵是两个范围：Rust 侧包含泛型或仅适合代码表达的能力，UIX Lang 只暴露已经登记并具有确定文本映射的标签。比较时分别查看[组件速查](../界面构建/组件速查.md)和 [UIX Lang 状态声明](../../uix-lang/README.md#状态声明)，不要把数量差异当作缺陷或完成度证明。

### UIX 会自动引入未使用的全部能力吗？

不会把所有可选能力都伪装成最小默认集。Cargo feature 决定哪些可选能力进入编译图，release 链接再移除已选能力中的不可达内容；运行时关闭能力不能替代编译期选择。详见[使用方按需编译](../../架构/使用方按需编译.md)。

## 能力与安全

### UIX 内建网络、同步或 WebView 吗？

不内建。网络请求、云同步和 WebView 运行时属于明确不做项；应用需要时应在 UIX 边界之外选择并治理相应能力。

### Settings 可以保存密码或令牌吗？

Settings 提供 strict flat JSON KV、类型化转换和可恢复保存，但当前契约不承诺加密、密钥管理或系统凭据库语义。不要把密码、令牌或其他秘密直接写入 Settings；需要时由应用选择专用凭据存储并承担访问控制。

### Agent 控制可以远程操作应用吗？

不可以。Agent 控制仅提供显式启用的同用户本机 IPC，远程控制不在范围内。同用户本机进程仍可能代表高权限调用方，因此正式应用应设置只读、受保护目标、禁止动作或用户确认策略，并避免在语义快照中暴露敏感值。

### 自动图形后端选择会掩盖显式配置错误吗？

不会。省略 `.graphics_backend(...)` 才使用自动策略，且只在已经编入的候选集合中选择；显式指定的 GPU API 失败时返回 typed error，不静默换成另一 GPU API。整体 CPU 回退和显式选择的详细边界见[配置](../框架设施/配置.md#图形后端)。

## 文档与进度

### 应该到哪里确认“现在做到哪一步”？

仓库文档持有稳定的产品、使用、语言和架构契约；带时点的任务、负责人、阻塞、环境矩阵和公开 API 测试结果只由 Gitea 持有。版本内已经发生且影响使用方或交付的变化记录在[变更记录](../../../CHANGELOG.md)。

### 文档和当前环境不一致怎么办？

先保留完整错误、feature、平台和最小复现，并按[故障排查](故障排查.md)确认是否属于平台限制或配置问题。无法由现有契约验证的差异应标为“待确认”并进入 Gitea，不能直接把临时观察写成全平台事实。
