# 故障排查

[← 返回使用索引](../../使用.md)

> **范围**：本文按症状汇总 UIX 接入、编译、平台服务、设置、诊断与 Agent 控制的排查入口。具体 API 和错误语义仍以链接到的专题文档为准；平台与硬件覆盖以实机验证结果与[交付与许可](../../产品/交付与许可.md)声明为准。

## 先收集这些信息

1. 记录完整的 typed `Error` / `Errc` 或 UIX Lang 编译诊断，不要只保留“失败了”的界面提示。
2. 记录目标操作系统、CPU 架构、启用的 Cargo feature、显式选择的图形后端，以及问题发生在编译期、启动期还是运行期。
3. 把问题缩小到最小可复现步骤，并说明预期结果与实际结果。
4. 删除日志中的密码、令牌、用户内容和本地敏感路径后再共享；不要假定任意业务错误文本都会被框架自动脱敏。
5. 运行时问题先用 `Ctrl+Shift+D` 开启覆盖层，记录异常帧的 `correlation_id`；转瞬即逝的问题用 `write_debug_repro_manifest` 保存有界现场。

## 常见症状

| 症状 | 可能原因 | 处理方式 |
|---|---|---|
| Cargo 找不到 `uix-app` | crates.io 网络或包名/版本配置错误 | 确认依赖为 `uix-app = "=0.0.8"`，Rust 路径为 `uix_app`；不配置旧私有 Registry。参见[交付与许可](../../产品/交付与许可.md) |
| UIX Lang 报未知标签、属性、事件或样式 | 能力未登记、拼写错误，或示例依赖不同版本 | 按诊断位置检查[语言参考](../../uix-lang/README.md#文档地图)；未登记能力不会生成占位 View，也不会静默降级 |
| Rust 中不存在某个 `GraphicsBackend` 变体 | 对应 Cargo feature 没有进入编译图 | 启用与变体同名的 backend feature，或省略显式后端选择以使用已编入候选集合的自动策略；见[图形后端](../框架设施/配置.md#图形后端) |
| 平台查询返回 `NotImplemented` 或 capability 不可用 | 当前操作系统、backend 或部署环境不提供该能力 | 在调用前查询 capability；把不可用作为稳定分支展示或降级，禁止用空值伪装成功、固定间隔重试或静默改查另一 API；见[平台能力](../框架设施/平台能力.md) |
| 文件对话框没有返回路径 | 用户取消是正常结果 `Ok(None)`；启动失败或权限问题才是错误 | 区分取消与 typed error，不把取消记录成故障；过滤器规则见[平台能力](../框架设施/平台能力.md#查询与服务) |
| Windows 系统通知不可用 | 未配置 AUMID、安装器未登记同一身份，或目标没有 Provider | 先读取通知 capability，再按[Windows 通知环境约定](../框架设施/平台能力.md#查询与服务)修正身份或部署 |
| Settings 返回 `FormatError` / `ParseError` | 外层文件不是严格 flat string KV JSON，或读取类型与写入格式不匹配 | 检查损坏 key 和类型；结构体需启用 `settings-serde`，详见[配置](../框架设施/配置.md#settings) |
| Settings 返回 `InvalidState`，或修改后重启丢失 | 未配置非空路径，或只修改了内存而没有显式 `save()` | 通过 `.settings(path)` / `load(path)` 配置路径，并处理 `save()` 返回的 typed error |
| 没有看到 UIX 日志 | UIX 只发射 `tracing` 事件，宿主没有安装 subscriber 或过滤条件排除了目标 | 由宿主安装并配置 subscriber；诊断事件目标和示例见[运行保障](../框架设施/运行保障.md#日志与报告) |
| `Ctrl+Shift+D` 后没有覆盖层 | 事件未进入目标窗口、组合根使用了不同 Diagnostics runtime，或窗口尚未触发下一帧 | 确认焦点窗口与共享 runtime；也可用 `App::debug_mode(true)` 或 `UIX_DEBUG=1` 启动，详见[统一调试模式](../框架设施/运行保障.md#统一调试模式) |
| 卡顿偶发且来不及看覆盖层 | 问题只在少数帧出现，普通日志缺少同批输入关联 | 设置 `UIX_SLOW_FRAME_MS`，按 `correlation_id` 过滤 `uix_app::diagnostics`，复现后立即[导出复现清单](../框架设施/运行保障.md#导出复现清单) |
| 没有生成 CrashReport 或 panic 复现清单 | 未配置 `crash_report_directory`、目录不可写，或问题不是进入 panic hook 的崩溃 | 核对诊断配置与目录权限，同时保留 previous panic hook 的输出；见[崩溃边界](../框架设施/运行保障.md#崩溃边界) |
| Agent 端点没有出现 | `agent-control` feature 与 `.enable_agent_control()` 没有同时启用，或 Demo 缺少运行参数 | 核对双门禁；主演示还需传 `--agent-control`。只传参数会在创建窗口前以退出码 2 失败 |
| Agent 返回 `stale_window` / `stale_revision` / `node_not_found` | 窗口代际、语义修订或节点已经变化 | 重新执行 `list_windows` 和 `snapshot`，再使用新快照中的稳定目标；不得把旧动作重定向到相似节点 |
| Agent 返回 `forbidden` / `requires_confirmation` | 动作命中只读、保护、禁止类别或用户确认策略 | 不绕过策略；按错误码结束动作或完成一次性确认流程，详见[授权模型](../能力与边界/Agent控制.md#授权模型三层) |

## 仍无法定位时

先沿错误所属边界查阅[运行保障](../框架设施/运行保障.md)、[配置](../框架设施/配置.md)、[平台能力](../框架设施/平台能力.md)或 [Agent 控制](../能力与边界/Agent控制.md)。若问题依赖真实硬件、窗口系统或尚未发布的交付环境，保留环境、最小复现、typed error 与验证结果的记录，不在仓库文档中写入临时结论。
