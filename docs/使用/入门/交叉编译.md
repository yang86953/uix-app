# 交叉编译

[← 返回使用索引](../../使用.md)

> **接口**：声明 UIX 桌面目标的编译入口、工具链前置条件、产物边界与失败语义。依赖：当前交付平台 → [交付与许可](../../产品/交付与许可.md)，真实图形状态 → [图形后端](../../架构/graphics/backend.md)。

UIX 使用 `scripts/cross_compile.sh` 统一检查和构建框架库与带 `agent-control` 的 `uix-lang-demo`。脚本不安装 SDK、不修改 Rust 默认工具链、不清理现有产物，也不把交叉编译成功解释为真实窗口或 GPU 验收。

## 目标矩阵

| 入口名称 | Rust target | 编译配置 | 当前边界 |
|---|---|---|---|
| `linux-x64` | `x86_64-unknown-linux-gnu` | Vulkan 首选、Wayland EGL/OpenGL ES 回退、Agent | `0.0.4` 当前平台；真实链接要求 Linux x64 宿主 |
| `windows-x64` | `x86_64-pc-windows-msvc` | Vulkan 首选、D3D11 与 WGL 回退、Agent | `0.0.4` 当前平台；非 Windows 宿主通过 `cargo-xwin` 取得 MSVC CRT/Windows SDK 后链接 |
| `macos-arm64` | `aarch64-apple-darwin` | 原生 Metal、Agent 与公开组件能力 | 编译目标；仍不是 `0.0.4` 当前交付平台，真实链接和运行验收要求 macOS/Apple SDK |
| `macos-x64` | `x86_64-apple-darwin` | 原生 Metal、Agent 与公开组件能力 | 编译目标；仍不是 `0.0.4` 当前交付平台，真实链接和运行验收要求 macOS/Apple SDK |

Android、iOS、BSD 与 WASM 当前没有对应的窗口、输入、surface 和生命周期后端，不在这个矩阵内。Rust 标准库存在某个 target 不表示 UIX 已支持该平台。

## 准备工具链

所有宿主都需要当前仓库使用的 Rust/Cargo 与四个目标标准库：

```bash
rustup target add \
  x86_64-unknown-linux-gnu \
  x86_64-pc-windows-msvc \
  aarch64-apple-darwin \
  x86_64-apple-darwin
```

从 Linux 或 macOS 链接 Windows MSVC 产物时，还需要 LLVM 的 `clang-cl`、`lld-link`、`llvm-lib` 与冻结版本的 `cargo-xwin`：

```bash
cargo install --locked cargo-xwin --version 0.23.1
```

`cargo-xwin` 会把 Microsoft CRT 与 Windows SDK 下载到用户缓存；使用它表示接受其上游列出的 Microsoft 软件许可。需要离线构建时，先在获准联网的环境运行 `cargo xwin cache xwin`，再按组织的软件与缓存分发规则转移缓存，不能把 SDK 提交进本仓库。

macOS 真实链接必须在 macOS 宿主安装 Xcode Command Line Tools，并让 `xcrun --show-sdk-path` 能找到合法 Apple SDK。本仓库不下载、复制或提交 Apple SDK；Linux/Windows 宿主只能对 macOS 执行 `check`，不能据此生成或宣称可运行的 `.app`。

## 编译检查

先检查全部四个目标。该模式编译根库和主演示的目标代码，但不执行最终链接：

```bash
bash scripts/cross_compile.sh check all dev
```

也可以只检查一个目标，或切换到 release 编译配置：

```bash
bash scripts/cross_compile.sh check windows-x64 release
bash scripts/cross_compile.sh check macos-arm64 dev
```

`check` 通过只能证明 Rust 目标代码、过程宏和 feature 图可编译；它不证明系统链接库、动态 loader、窗口系统、输入法、Agent IPC 或 GPU 驱动可用。

## 生成链接产物

`build` 每次必须显式指定一个目标，因为三类平台的 SDK 与链接器所有权不同。

Linux x64 宿主生成 Linux 框架库和主演示：

```bash
bash scripts/cross_compile.sh build linux-x64 release
```

Windows MSVC 宿主原生生成、或 Linux/macOS 宿主通过 `cargo-xwin` 交叉生成 Windows x64 产物：

```bash
bash scripts/cross_compile.sh build windows-x64 release
```

macOS 宿主可为 Apple Silicon 与 Intel 分别生成产物：

```bash
bash scripts/cross_compile.sh build macos-arm64 release
bash scripts/cross_compile.sh build macos-x64 release
```

根库产物进入 `target/<target>/<profile>/`，主演示进入 `demo/target/<target>/<profile>/`。脚本复用 Cargo 增量目录，不删除调用方已有结果。

## 自动化门禁

- `.gitea/workflows/cross-compile.yml` 在 Linux runner 上执行四目标 `check`，并真实链接 Linux x64 与 Windows x64。
- `.gitea/workflows/macos-build.yml` 只允许手动触发，在持有 Apple SDK 的 macOS runner 上真实链接两种 macOS 架构。
- runner 标签、Actions 开关与外部 SDK 许可由 Gitea 管理方持有；工作流入库不等于 runner 已在线。

交叉产物仍需在对应真实平台执行公开 API、窗口、输入、Agent 和图形验收。Windows/Linux 的内部候选包继续分别由现有发布脚本在各自规定的干净宿主生成；本入口不替代候选包结构校验或正式 Release。

## 可见失败

| 失败 | 含义与处理 |
|---|---|
| `Rust target is not installed` | 按错误中的 `rustup target add` 安装精确 target |
| `cargo-xwin 0.23.1 is required` | 非 Windows 宿主缺少冻结版本，或安装了未经本矩阵验证的版本 |
| 缺少 `clang-cl` / `lld-link` / `llvm-lib` | 安装完整 LLVM 工具链后重试 Windows 链接 |
| `macOS linking requires a macOS host` | 当前宿主没有合法 Apple SDK；只能运行 macOS `check` |
| Cargo 编译错误 | 目标条件依赖或源码边界回归；不得改用宿主 cfg、跳过主演示或把失败目标从矩阵静默删除 |
| 产物无法在目标机启动/呈现 | 交叉编译门禁已经结束，应转入对应平台真实运行验收，检查系统版本、动态库、窗口会话和 GPU 后端 |
