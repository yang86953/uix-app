# 响应式基础

[← 返回使用索引](../../使用.md)

> **接口**：声明 UIX 响应式编程模型——State、Computed、Effect、View 组合与剪贴板的公开用法。依赖：[快速开始](快速开始.md)（需先了解项目搭建）。导出：组件开发 → [组件](../界面构建/组件.md)，事件处理 → [事件](../交互与反馈/事件.md)。

## 适用线索

需要管理组件状态、派生值、执行副作用或组合视图时，以本文为准。

## 权威范围

本文持有响应式基础（State / Computed / Effect / View / 剪贴板）的公开入口、API 契约与行为约定。

## State —— 响应式状态

```rust uix-compile=state-basics
let count = State::new(0);       // 创建
count.set(5);                     // 写入
count.update(|v| *v += 2);       // 基于旧值更新
let val: i32 = count.get();      // 读取
```

写入 `State` 会标记受影响的视图，由框架合并为至多一次重绘。高频写入不自动节流——用 `run_interval` 或动画驱动周期性变化。

`State` 属于目标 UI owner 的响应式真相。事件、timer、Effect 和 `post_to_ui` 闭包可以在该窗口 UI 轮次写入；后台线程只计算并传递 owned 结果，不直接读写 State。跨线程、取消和晚到结果处理见[定时与异步](../动画与异步/定时与异步.md#跨线程回-ui)。

## Computed —— 派生状态

自动追踪依赖，惰性求值，仅在依赖变化时重算：

```rust uix-compile=computed-full-name
let first = State::new("Ada");
let last  = State::new("Lovelace");
let full  = Computed::new(move || format!("{} {}", first.get(), last.get()));

// 映射到视图
full.map_text(|s| s.clone()).font_size(20.0);
```

`map` / `map_text` / `map_opt` 将 `State<T>` 或 `Computed<T>` 转为响应式 View：

| 方法 | 输入 | 输出 |
|------|------|------|
| `.map(\|v\| view)` | `T` → `impl View` | 依赖变化时重建子视图 |
| `.map_text(\|v\| format!(…))` | `T` → `String` | 常用简写 |
| `.map_opt(\|v\| Option<impl View>)` | `T` → `Option<impl View>` | 条件渲染 |

`map` / `map_opt` 放在 `App::root` 的构建闭包内，依赖变化时由框架请求结构 reconcile；`map_text` 只失效对应文本的绘制。

### State::map —— 通用响应式 View

`State::map` / `map_opt` 与 `Computed` 语义一致：在 `App::root` 构建期读取当前值，并把依赖登记到所属根 View；值变化后请求结构 reconcile。

```rust uix-compile=state-view-mapping
let count = State::new(0u32);

// 通用 map：从 State<T> 构建响应式 View
count.map(|n| {
    if *n == 0 {
        label("暂无数据").color(Color::gray())
    } else {
        label(format!("共 {n} 条")).font_size(16.0)
    }
});

// map_opt：条件渲染
count.map_opt(|n| {
    if *n > 100 {
        Some(label("超标").color(Color::red()))
    } else {
        None
    }
});
```

### scoped —— 子树作用域

`map` 的结构粒度是整棵根 View：值变化后框架重跑根闭包并全树 diff。当某个子树的结构依赖变化频繁、而其余界面很重时，用 `scoped` 把重跑范围收敛到该子树：

```rust uix-compile=scoped-subtree
let highlight = State::new(0usize);
let lines = vec!["第一行".to_string(), "第二行".to_string()];

// 闭包内读取的 State 登记为该子树的作用域依赖
scoped(move || {
    let active = highlight.get();
    let rows = lines
        .iter()
        .enumerate()
        .map(|(index, text)| {
            let style = if index == active {
                label(text.clone()).font_size(17.0)
            } else {
                label(text.clone()).font_size(14.0)
            };
            style.height(32.0)
        })
        .collect::<Vec<_>>();
    column(rows)
});
```

`scoped(闭包)` 在挂载时执行一次闭包；闭包内读取的 `State` 变化时，框架只重跑本闭包并原位协调该子树，不触发整树根重建。外层其他 State 变化引起的根重建会照常重跑本闭包。

约定与限制：

- 闭包契约与 `map` 一致：可重复执行的纯构建，不修改外部可变状态、不依赖执行次数。
- 闭包不得直接返回另一个 `scoped` 节点（会被显式拒绝）；需要嵌套时在两者之间包一层 `column` 等容器。
- 高频更新的值仍应优先用窄失效通道（`canvas`、`map_text`、输入组件绑定）；`scoped` 面向「结构随状态变化」的中低频子树。
- 作用域闭包内创建的 Effect 与动画源随该节点生命周期释放。

## Effect —— 副作用

依赖变化时执行（不产生视图）：

```rust uix-compile=effect-dependency
let count = State::new(0);
let watched_count = count.clone();

Effect::new(move || {
    println!("count 变为 {}", watched_count.get());
    // 自动追踪 count
});
```

Effect 在事件轮次末尾、重绘之前批量执行，只适合短小、幂等或可取消的同步观察与状态衔接。它运行在 UI owner 上，不执行阻塞文件/网络/数据库 I/O，不持有业务锁等待外部资源；耗时工作由应用任务 owner 启动，完成后经 `post_to_ui` 回传。

## View —— 组合模型

所有界面元素实现 `View` trait，通过组合构建 UI 树：

```rust uix-compile=conditional-and-list
// 条件渲染
let visible = true;
let conditional = column(show(visible, label("可见内容")));
let retained = label("保留节点身份").visible(visible);

// 列表渲染（少量项目）
let items = ["Ada", "Alan", "Grace"];
let list = column(items.iter().enumerate().map(|(i, item)| {
    label(*item).automation_id(format!("item-{i}"))
}).collect::<Vec<_>>());

// 大量列表 → VirtualScroll（见[布局 · 滚动](../界面构建/布局.md#滚动)）
```

`Option<impl View>` 自动处理 `None`（不渲染）和 `Some(view)`（渲染）。`show(...)` / `Option` 会结构性增删子树；`.visible(false)` 保留节点及 reconcile 身份，但整棵子树不参与布局、绘制、命中或焦点候选，适合稍后恢复原节点的场景。

## 剪贴板

从事件回调中读取或写入系统剪贴板：

```rust uix-compile=clipboard-event
// 写入
copy_to_clipboard("https://example.com");

// 读取
if let Some(text) = read_text_from_clipboard() {
    // 使用 text
}
```

仅在事件分发期间有效（受框架词法作用域托管）；无活动事件时当前入口为 no-op，因此不能把调用返回当作剪贴板已写入的确认。需要可观察成功/失败的业务流程应在有效事件回调内调用，并自行向用户陈述这一能力限制。

## 推荐用法

按产品定义（Rust 优先、资源优先），推荐写法是：

```rust uix-compile=computed-model
use uix_app::prelude::*;

// 业务模型即 State，派生值用 Computed，副作用收敛到 Effect
struct CounterModel {
    count: State<u32>,
}

impl CounterModel {
    fn new() -> Self {
        Self { count: State::new(0) }
    }

    fn doubled(&self) -> Computed<u32> {
        let count = self.count.clone();
        Computed::new(move || count.get() * 2)
    }
}
```

- 状态归最近的业务拥有者，不散落到组件内部。
- 能派生就不复制：派生值用 `Computed`，避免手工同步两份状态。
- 轻量同步副作用集中在 `Effect`，不在渲染闭包里写；持久化、网络和其他阻塞工作由应用任务 owner 执行，再经 `post_to_ui` 回传结果。
