# 事件

[← 返回使用索引](../../使用.md)

> **接口**：声明 UIX 事件系统的公开用法——语义事件、原始输入（指针/键盘/焦点/滚动）与无障碍事件覆写。依赖：[响应式基础](../入门/响应式基础.md)。导出：事件系统架构 → [架构 · 事件系统](../../架构/ui/event.md)。

## 适用线索

需要响应点击、处理键盘输入、管理焦点、拦截滚动事件或覆写无障碍语义时，以本文为准。

## 语义事件与原始输入

- 业务组件优先消费 Click、Change、Submit 等语义事件。
- 指针、键盘、滚轮、文字提交与 IME 预编辑是原始输入；只有自定义交互需要直接处理。
- 键盘按键与文字输入必须分离，快捷键不能从已提交文本反推。

## 已落地示例

```rust uix-compile=event-semantic
use uix_app::prelude::*;

let count = State::new(0);

// 语义事件：on_click 绑定 State，回调里更新
button("+1")
    .on_click(&count, |c| c.update(|v| *v += 1));

// 语义事件：on_semantic 精确匹配（on_semantic 在 ViewNode 上，先 build 再绑定）
button("提交").build()
    .on_semantic(SemanticKind::Click, |_| {
        // 提交逻辑
    });

// 自定义点击回调（不绑定 State）
button("通知")
    .on_click_fn(|| println!("clicked"));
```

```rust uix-compile=event-keyboard
use uix_app::prelude::*;

// 键盘：在组件 on_event 中处理原始输入
widget! {
    pub struct ShortcutPad { pub activated: bool }
    @new -> Self { Self { activated: false } }

    on_event => (&mut self, event: &SystemEvent) -> EventResult {
        match event {
            SystemEvent::KeyDown { key, .. } if *key == KeyCode::Enter => {
                self.activated = true;
                EventResult::Handled
            }
            _ => EventResult::NotHandled,
        }
    }

    // widget! 必须提供 render 槽位；无自绘内容时也需声明
    render => (&self, frame: Rect, ctx: &mut PaintContext) {
        let color = if self.activated { ctx.tokens().color_success() } else { ctx.tokens().color_text() };
        ctx.draw_text("ENTER", Point::new(frame.x + 8.0, frame.y + 8.0), color, 14.0);
    }
}
```

## 路由与焦点

事件按捕获、目标、冒泡三阶段传播。目标在一次分发中保持稳定；组件可阻止继续传播或禁止默认行为，但不得改写已确定的目标身份。

指针捕获属于具体接触点；组件卸载、窗口失焦或接触结束时必须释放。键盘焦点使用逻辑焦点链，Modal/Drawer 等浮层负责圈闭与关闭后的焦点恢复。

## 无障碍

组件公开 role、name、value、state 和 actions。敏感值默认不进入语义快照；无障碍动作与普通语义动作走同一安全路由，不直接操作平台对象。

```rust uix-compile=event-a11y
use uix_app::prelude::*;

// 语义名称：图标/图形必须有可读名称（role + automation_id）
embed(Icon::new("settings").size(16.0)).role(AccessibilityRole::Image);

// 自定义组件声明无障碍角色
label("进度：60%").role(AccessibilityRole::ProgressBar);
```

## 生命周期

事件闭包不得跨窗口借用短生命周期上下文。需要跨线程发起 UI 工作时，通过应用队列回到 owner thread；返回动作结果的代际句柄（如 Agent 动作）必须对陈旧/关闭目标返回其契约规定的 stale/closed 失败，不能当成功动作继续。`AppHandle::post_to_ui` 则是返回 `()` 的窗口回投入口，并不提供该结果合同；关闭后不执行，页面卸载也不自动使其失效。需要确认执行或避免迟到结果时，按[定时与异步](../动画与异步/定时与异步.md#跨线程回-ui)使用明确的业务完成事实与请求身份，不以调用返回声称成功。只有文档明确声明幂等的取消/释放操作可以返回“已经不存在”，且不能据此声称目标动作执行成功。

## 推荐用法

按产品定义（Rust 优先、容错可观测）：

```rust uix-compile=event-semantic-actions
// 交互即语义：键盘与指针同路径
button("删除").build().on_semantic(SemanticKind::Click, |_| {
    // 键盘 Enter/Space 与指针点击最终汇入同一语义入口
    confirm_delete();
});

// 自定义组件声明无障碍动作，不直接操作平台对象。
widget! {
    pub struct VolumeSlider { pub level: f32 }
    @new -> Self { Self { level: 0.5 } }

    // 槽位须位于 @new 之后、其他方法之前
    semantic_actions => [SemanticAction::Adjust { min: 0.0, max: 1.0 }]

    render => (&self, _frame: Rect, _ctx: &mut PaintContext) {}
}
```

- 业务交互一律走语义事件；原始输入只留给自定义绘制组件。
- 焦点链、浮层圈闭、关闭后焦点恢复由框架托管，业务不手工干预。
- 敏感值（密码、令牌）默认不进语义快照与日志。
