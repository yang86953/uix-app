## Error —— 唯一失败类型

框架 API 继续返回 `Result<T, Error>`。`Error` 含错误码、严重级别、消息及 source chain：

```rust uix-compile=typed-errors
use uix::prelude::*;

let err = Error::new(Errc::InvalidArgument, "输入不能为空");
let err = Error::not_found("config.json");
let err = Error::invalid_state("窗口已销毁");

let root = Error::new(Errc::IoError, "磁盘满");
let wrapped = Error::new(Errc::WriteFailure, "写入失败").with_source(root);
println!("{}", wrapped.root_cause());
println!("{}", wrapped.what());
println!("{}", wrapped.short_what());

match err.code() {
    Errc::NotFound => { /* 处理未找到 */ }
    Errc::InvalidState => { /* 处理非法状态 */ }
    _ => {}
}
```

常用错误码：`InvalidArgument` / `NotFound` / `InvalidState` / `IoError` / `Timeout` / `NotImplemented` / `PlatformError` / `InsufficientResources` / `GraphicsOutOfMemory`。

## 用户能使用什么

| 需求 | 入口 |
|---|---|
| 返回可预期失败 | `Result<T, Error>` |
| 记录普通日志、字段和耗时范围 | 标准 `tracing` event / span |
| 报告已到应用最终边界的 typed Error | `Diagnostics::report` |
| 读取有界、脱敏错误历史 | `Diagnostics::snapshot` |
| 文本、JSON、文件或外部监控 | 宿主的标准 tracing subscriber / Layer |

框架 target 使用 `uix::*` 前缀，应用使用自己的 crate target。两者进入同一 ambient subscriber；ErrorReport 则按 App runtime 隔离。

## 日志初始化

UIX 不安装全局 subscriber。应用可执行入口显式初始化标准 tracing 输出：

```text
tracing_subscriber::fmt()
    .with_max_level(tracing::Level::INFO)
    .try_init()?;

App::new()
    .root(app_view)
    .run();
```

App 默认创建 `Diagnostics`，日志 subscriber 与错误报告容量互不依赖。没有 subscriber 时普通日志没有输出，`AppHandle::diagnostics().report(error)` 仍会保留 ErrorReport。

嵌入已有宿主时沿用宿主 subscriber，不再设置第二个全局 subscriber。调用方应把生态 crate 作为直接依赖，不使用 `uix_info!` 一类包装宏：

```text
[dependencies]
tracing = "0.1"
tracing-subscriber = "0.3"
```

## 用户日志

应用代码直接使用标准宏与 span：

```text
let span = tracing::info_span!(
    target: "my_app::import",
    "import",
    job_id = %job_id,
);
let _entered = span.enter();

tracing::info!(item_count = items.len(), "开始导入");
tracing::warn!(skipped_count = skipped, "部分项目已跳过");
```

普通 `tracing::error!` 仍只是日志，不会伪造 `Errc::Unknown` 或进入错误历史。

## 报告用户 Error

如果错误还能返回给调用方，就继续返回，不要提前报告。只有当前层已经消费该错误、不会再把 typed Error 交给下一层时才调用：

```text
fn run_job(app: &AppHandle) {
    if let Err(error) = import_items() {
        let report_id = app.diagnostics().report(error);
        // report 已留存 ErrorReport，并发出一条关联 event。
        // 不要再为同一失败写第二条 tracing::error!。
    }
}
```

传播与最终报告分开：

```text
fn load() -> Result<Data, Error> {
    read_data().map_err(|error| {
        Error::new(Errc::ReadFailure, "读取数据失败").with_source(error)
    })
}

fn worker_boundary(diagnostics: &Diagnostics) {
    if let Err(error) = load() {
        diagnostics.report(error);
    }
}
```

框架返回给用户的 `Err` 不会替用户预先进入错误历史。已恢复或已降级的失败只记录语义明确的 tracing event；若恢复逻辑还要向上返回 Error，也不要在本层报告。

公开 `report` 可在普通应用或 worker 线程调用，但会同步进入宿主 subscriber。FFI、OS 和 GPU callback 必须先把 owned 故障投递给 owner thread，不直接调用 `report`。

## 自定义容量和崩溃目录

通常不必显式配置。需要更改默认策略时，在 App 启动前提供 `DiagnosticsConfig`：

```text
use uix::diagnostics::{BacktracePolicy, DiagnosticsConfig};

App::new()
    .diagnostics(
        DiagnosticsConfig::default()
            .report_capacity(1_024)
            .crash_report_directory("logs/crash")
            .backtrace(BacktracePolicy::ErrorsAndFatal),
    )
    .root(app_view)
    .run();
```

非 App 场景和隔离测试可直接创建：

```text
let diagnostics = Diagnostics::new(DiagnosticsConfig::default());
```

脱敏和单报告字节上限是固定安全不变量，不提供关闭开关或用户 callback。

## 快照

```text
let snapshot = app.diagnostics().snapshot();

println!(
    "total={}, retained={}, evicted={}",
    snapshot.total_reports(),
    snapshot.reports().len(),
    snapshot.evicted_reports(),
);

for report in snapshot.reports() {
    println!(
        "{} {:?} {:?} {}",
        report.id(),
        report.code(),
        report.severity(),
        report.summary(),
    );
}
```

`ErrorReport` 只暴露有界、脱敏内容，不返回原始 `Error` 或无界 `what()`。快照在创建后不可变，报告按 `ReportId` 从旧到新排列。`ReportId` 只在当前 `Diagnostics` 生命周期内唯一，不是跨进程持久身份。

日志查询、过滤、格式化与持久化继续使用 tracing Layer；Diagnostics 不提供同步 callback token、订阅、`clear` 或 `flush`。

## 公开 API

目标公开面：

```text
uix::diagnostics::{
    BacktracePolicy,
    Diagnostics,
    DiagnosticsConfig,
    DiagnosticsSnapshot,
    ErrorReport,
    ReportId,
}

Diagnostics::new(config: DiagnosticsConfig) -> Diagnostics
Diagnostics::report(&self, error: Error) -> ReportId
Diagnostics::snapshot(&self) -> DiagnosticsSnapshot

DiagnosticsConfig::report_capacity(self, usize) -> DiagnosticsConfig
DiagnosticsConfig::crash_report_directory(self, impl Into<PathBuf>) -> DiagnosticsConfig
DiagnosticsConfig::backtrace(self, BacktracePolicy) -> DiagnosticsConfig

App::diagnostics(self, config: DiagnosticsConfig) -> App
AppHandle::diagnostics(&self) -> Diagnostics

DiagnosticsSnapshot::reports(&self) -> &[ErrorReport]
DiagnosticsSnapshot::total_reports(&self) -> u64
DiagnosticsSnapshot::evicted_reports(&self) -> u64

ErrorReport::id(&self) -> ReportId
ErrorReport::observed_at(&self) -> SystemTime
ErrorReport::code(&self) -> Errc
ErrorReport::severity(&self) -> ErrorSeverity
ErrorReport::summary(&self) -> &str
ErrorReport::origin_target(&self) -> &str
ErrorReport::operation(&self) -> Option<&str>
ErrorReport::resource(&self) -> Option<(&str, &str)>
ErrorReport::causes_truncated(&self) -> bool
ErrorReport::event_emitted(&self) -> bool
```

诊断类型从 `uix::diagnostics` 显式导入，不进入 prelude。既有 `Error` / `Errc` / `Result` 保持原公开位置。

不再公开 `Collector`、`Logger`、自制 `Level`、`LogHandler`、`Sink`、Diagnostics Layer、callback id、retry middleware、crash writer 或 abort 函数。

`BacktracePolicy` 的首版取值为 `Disabled`、`FatalOnly`、`ErrorsAndFatal`；backtrace 在最终报告点捕获，不伪装成错误创建点。

默认配置为：

- `report_capacity = 256`
- `backtrace = FatalOnly`
- 单条 ErrorReport 最多 32 KiB、最多 16 层 cause、单段文本最多 2 KiB；这些安全预算不可由用户放大
- App 未指定 crash 目录时使用平台提供的每应用数据目录下 `diagnostics/crash`；非 App 的 `Diagnostics::new` 未指定目录时只保留 ErrorReport，并在 crash emergency 路径退回 stderr

## Fatal 与 CrashReport

应用调用 `report` 报告 Fatal 也不会自动终止。只有 App runtime 确认不能安全继续时，才由内部 crash 路径写 `CrashReport` 并终止。

CrashReport 不走 tracing subscriber。它允许终止前有上限的同步文件或 stderr 写入，但不会调用普通 sink、网络、用户 Layer 或 callback。`panic=abort`、访问冲突等 native fault 不保证生成 UIX CrashReport。

## 隐私与宿主责任

- 不把密码、token、secret、剪贴板、输入内容或文件内容写入 Error 或 tracing。
- 完整路径、窗口标题和用户文本默认省略、散列或截断。
- 应用 Error 消息也必须是安全诊断文本；固定清洗不能理解任意业务秘密。
- subscriber 的同步成本、输出队列、文件轮转、远程 Layer 与 flush 生命周期由宿主负责。
- 宿主 Layer 不得在处理 `uix::diagnostics` event 时再次调用 `Diagnostics::report`；框架仍用 reentrancy guard 防止递归 event。
- UIX 默认不上传任何诊断信息。
