# 软件动态扩展

[← 返回使用索引](../../使用.md)

> **接口**：声明运行时软件扩展的公开用法与限制，含动态界面、事件、热替换与 Agent 后台操作面集成。依赖与生命周期语义见[目标设计](../../架构/app/extensions.md)；引擎证据与兼容矩阵见[引擎取证](../../架构/app/extensions-engine.md)。

## 适用线索

需要在已运行的应用中装载用 Scheme（R7RS-small 受限宿主环境）编写的新命令、规则或业务逻辑，且不重启宿主时，以本文为准。运行中装载、动态面板、事件订阅、异步端口、热替换与撤权均已实现（P1–P4 主干）；文本处理工作台扩展已作为**外部扩展包**交付在 `extensions/text-bench/`（独立清单与 `.scm` 源文件，示例与测试共用同一交付物），`examples/text_workbench.rs` 是外部包装载、显式生命周期管理与 Agent 独立后台操作面集成的完整业务示例。

## 前置条件

- 构建启用 Cargo feature `extensions`（默认关闭；未启用时本模块不进入编译图，使用方不承担解释器成本）。
- 宿主应用显式创建 `ExtensionHost` 并注入所需业务端口；扩展不能凭脚本获得未注入的能力。
- 扩展包由两部分组成：S 表达式清单（`manifest.scm`）与 `.scm` 源文件集。内存快照经 `ExtensionPackage::from_parts` 构造；外部目录在应用显式指定路径时经 [`ExtensionPackage::read_from_directory`](#外部扩展包目录交付与显式读取) 读取并冻结为不可变快照——库不扫描、不监听目录，允许哪些来源由宿主应用策略决定。

## 执行步骤：装载并调用一个文本转换扩展

```rust
use uix_app::extensions::{
    ExtensionHost, ExtensionPackage, ExtensionValue,
};

// 1. 构造包：清单 + 源文件（真实应用从磁盘或网络通道取得并冻结）。
let manifest = r#"
(uix-extension
  (schema-version 1)
  (id "text-tools")
  (version "0.1.0")
  (language r7rs-small)
  (entry "main.scm"))
"#;
let source = r#"
(define count 0)
(register-command! "shout"
  (lambda (text)
    (set! count (+ count 1))
    (string-upcase text)))
(register-command! "uses"
  (lambda () count))
"#;
let package = ExtensionPackage::from_parts(
    manifest.to_string(),
    [("main.scm".to_string(), source.to_string())]
        .into_iter()
        .collect(),
)?;

// 2. 准备（独立候选环境中求值入口、暂存命令）并激活（发布为活动代）。
let mut host = ExtensionHost::new();
let prepared = host.prepare(&package)?;
assert_eq!(prepared.commands(), ["shout", "uses"]);
let receipt = host.activate(prepared)?;
assert_eq!(receipt.extension_id, "text-tools");

// 3. 类型化调用：扩展状态在调用间保留（同一实例串行复用）。
let outcome = host.call_command(
    "text-tools",
    "shout",
    &[ExtensionValue::Text("hello".to_string())],
)?;
assert_eq!(outcome, ExtensionValue::Text("HELLO".to_string()));
let uses = host.call_command("text-tools", "uses", &[])?;
assert_eq!(uses, ExtensionValue::Int(1));

// 4. 停止：撤销注册并释放实例。
host.deactivate("text-tools")?;
```

## 宿主端口（受控业务能力）

清单 `capabilities` 声明所需能力名；`ExtensionHost::with_port` 注入实现。实际可调用能力 = 清单声明 ∩ 宿主已注入端口；声明了宿主没有的能力在 `prepare` 即被 `Incompatible` 拒绝。端口签名 `Fn(&[ExtensionValue]) -> Result<ExtensionValue, String>`：入参是跨边界 owned 值，返回值同样受限；闭包、环境与 continuation 不离开引擎。

```rust
use std::sync::Arc;

let host = ExtensionHost::new().with_port(
    "documents-query",
    Arc::new(|arguments: &[ExtensionValue]| {
        // 只读业务端口示例：按 key 返回文档文本。
        match arguments.first() {
            Some(ExtensionValue::Text(key)) if key == "intro" => {
                Ok(ExtensionValue::Text("UIX 扩展示例文档".to_string()))
            }
            _ => Err("未知文档".to_string()),
        }
    }),
);
```

脚本侧直接按能力名调用：`(documents-query "intro")`。

## 外部扩展包：目录交付与显式读取

文本处理工作台扩展以外部包目录交付在 `extensions/text-bench/`（`v1/` 与 `v2/` 为两个版本），每个包目录恰好包含一份 `manifest.scm` 清单与一个或多个 `.scm` 源文件。示例、公开 API 测试与运行期装载使用同一交付物；不把源码字符串复制进示例或测试，也不把 `include_str!` 后重新编译宿主当作运行期外部包装载。

```rust
use uix_app::extensions::ExtensionPackage;

// 应用显式指定来源（授权策略归应用）；读取即冻结为不可变快照，
// 检查与执行使用同一快照。
let package = ExtensionPackage::read_from_directory(
    std::path::Path::new("extensions/text-bench/v1"),
)?;
assert_eq!(package.manifest()?.version, "0.1.0");
// 随后经既有生命周期入口执行：prepare → activate（或 replace）。
```

读取规则与限制：

- 目录形态：恰好一个 `manifest.scm`；其余条目必须是 `.scm` 普通文件。子目录、符号链接与非 `.scm` 条目拒绝，包内不跟随任何链接（不因加载包扩大文件访问面）。
- 上限沿用包冻结合同：清单 ≤16 KiB、单文件 ≤256 KiB、包总字节 ≤1 MiB、文件数 ≤64（读取前按元数据预检单文件大小）。
- 来源不存在、缺清单、清单语法错误、读取失败与不完整包（入口缺失）均返回类型化 `Package` 失败，不静默忽略任何条目。
- 多文件包：入口可经 `(include "lib.scm")` 引用包内其他源文件；来源解析只读冻结快照内已存在的路径，未登记来源拒绝。
- 能力、语言与配额校验不变：读取只产生内存快照，不带来任何授权；实际可调用能力 = 清单声明 ∩ 宿主已注入端口（`prepare` 期校验）。

## 取消与资源

- `host.cancel_handle(id)` 返回跨线程安全的取消令柄；下一次求值检查点以 `Cancelled` 终止。
- 默认资源边界（可在 `ExtensionHostConfig` 调整）：准备 5 s、单次命令 1 s 墙钟；燃料 5×10⁶ 步；存活堆 4 MiB。超限分别返回 `Timeout` / `Quota`，不可被脚本捕获。
- 引擎在安全点执行标记-清扫回收：循环 pair、闭包-环境互引等不可达环会被断开释放；实例停用时执行关闭清扫。

## 可观察失败

`ExtensionError` 为类型化结果（不经过日志冒充处置）：

| 错误 | 触发 |
|---|---|
| `Package` | 清单结构、未知字段、入口缺失、路径逃逸、大小超限、目录读取失败（来源不存在、缺清单、非法条目） |
| `Parse` | 源码读取失败 |
| `Incompatible` | schema / 语言不受支持、声明能力无对应端口、同 ID 重复激活 |
| `ScriptFailure` | 脚本 `error` / 未捕获 `raise`，携带 write 形式摘要 |
| `UnknownExtension` / `UnknownCommand` | 未激活、已卸载或命令不存在 |
| `Argument` | 跨边界值类型不符（NaN/Inf、非严格列表、超大精确整数等） |
| `Quota` / `Timeout` / `Cancelled` | 资源边界 |
| `HostFailure` | 端口自身失败 |
| `EnginePoisoned` | 引擎 panic 后实例弃用 |

## 动态 UI：挂载位、事件与异步端口（P2）

窗口应用经 `spawn_worker` 进入 UI 模式：引擎整体存活在独立执行线程，
UI 线程只投递命令与消费 owned 声明，layout / paint / 命中路径无解释器。

### 扩展侧：`(uix ui)` 与 `(uix tasks)` 库

```scheme
;; 声明是 tagged list：属性为 (名 值) 对，容器其余子项为子节点。
(submit-ui! 'panel                          ; 挂载位（应用白名单授权）
  (list 'column (list 'key "root") (list 'pad 8.0) (list 'gap 6.0)
        (list 'text (list 'key "title") "点击次数: 0")
        (list 'button (list 'key "btn") (list 'on-click 'on-increment) "增加")
        (list 'input (list 'key "field") (list 'on-change 'on-field-change) "")
        (list 'list (list 'key "items") (list "甲" "乙"))))

(register-handler! "on-increment"            ; 面板事件处理（ui-event 命名空间）
  (lambda () (submit-ui! 'panel (next))))

(call-async "documents-analyze" (list "intro")  ; 异步端口：立即返回
  (lambda (request result)                       ; 终态回调（代际校验）
    (submit-ui! 'panel (with-status result))))
```

支持的节点：`column` / `row`（pad、gap、bg）、`text`（color、size）、
`input`（placeholder、on-change、reset）、`button`（on-click、disabled）、
`list`（字符串项）。提交点全量校验：未知节点 / 字段、重复 key、深度
>16、节点 >512、文本 >4KiB、列表 >256 项拒绝并保留原树。

### 应用侧：挂载位与声明交付

```rust
use uix_app::extensions::{ExtensionHost, UiProjector, UiUpdate};
use uix_app::prelude::*;

let (updates_tx, updates_rx) = std::sync::mpsc::channel();
let host = ExtensionHost::new()
    .with_mount("panel")                       // 开放挂载位（能力 mount-panel）
    .with_port(/* 同步端口 */)
    .with_async_port("documents-analyze", /* Arc<Fn(u64, &[ExtensionValue], AsyncCompletion)> */)
    .with_ui_sink(Arc::new(move |update| { let _ = updates_tx.send(update); }));
let handle = host.spawn_worker();              // 引擎进入执行线程

// 投影器：声明 → ViewNode；事件闭包只发送（on_change / on_click_fn）。
let projector = UiProjector::new("panel-ext", receipt.generation, handle.event_sender());
App::new().on_start(move |app_handle| {
    // 桥：sink（扩展线程）→ post_to_ui（窗口 owner thread）
    //     UiUpdate::Applied { node, revision, .. } → 更新声明快照 + revision State
}).root(move || {
    revision.get();                            // 修订 State 驱动 scoped 重建
    projector.lock().unwrap().project("panel", &current_declaration)
})
```

- `UiUpdate::Applied { mount, extension, generation, revision, node }` /
  `Rejected { mount, extension, reason }`：回执区分「已接收 / 已应用」；
  GPU 呈现由 `perform` 的 `presented_revision` 另行确认。
- 事件闭包携带提交代；停用后的陈旧事件稳定拒绝，不写入新代。
- 输入草稿按稳定 key 保留（声明值变更不覆盖编辑中内容）；`(reset #t)`
  是本次 Applied 的一次性指令，应用层经
  `UiProjector::consume_declaration_resets` 在 Applied 处执行并消耗标记，
  重投影不得再次覆盖编辑中内容；同 key 同类型节点沿 UIX reconcile 原位复用。
- `automation_id` 为 `<扩展>/<挂载位>/<key...>`；TestApp 或独立后台根内的 Agent 按此定位，不控制用户窗口的投影器。

### 服务扩展点

`(register-service! "name" proc)` 登记版本化服务实现；宿主经
`call_service`（同步）或 `ExtensionUiHandle::call_service`（worker 模式）
调用，语义与命令一致（`UnknownCommand` 拒绝未登记名）。

### 真窗示例

`examples/extension_panel.rs`（`--features extensions`）保留用户真窗中的计数器、输入回显、异步分析与列表。加 `--hot-replace` 参数，5 秒后演示热替换：标题标记升级（v2）、点击计数状态迁移保留、步进算法由 +1 变 +2，旧代事件授权随之失效。

该模板的 UiProjector、声明回传与 AppHandle 属于前台，不再默认开放共享窗口 Agent 端点。后台接入须独立建立根、投影器和 UI worker，仅共享领域端口，见下节与 [Agent 独立后台操作面](Agent后台操作面.md)；不能把同一投影器 clone 给两棵树冒充隔离。

## 后台操作面接入（独立 UI worker 与共享领域端口）

AI 在独立后台操作面使用扩展时，前台与后台分别拥有自己的根、组件树、投影器、交互状态与执行实例；唯一共享的是应用显式注入的领域端口（如文档查询与受控提交）。`examples/text_workbench.rs`（`--features extensions,agent-control`）是完整业务示例：宿主启动时不装载任何扩展，外部包（`extensions/text-bench/`）经 `--extension-source` 显式授权后装载；Scheme 扩展实现真实文本统计算法与面板，AI 经 `scripts/agent_client.py` 在后台完成读取 → 输入 → 处理 → 提交闭环。

```rust
use uix_app::extensions::{ExtensionHost, ExtensionValue, UiProjector, UiUpdate};

// 1. 后台操作面：独立根（修订 State 驱动重建）与投影器槽。
let revision = State::new(0u64);
let current: Arc<Mutex<Option<UiNode>>> = Arc::new(Mutex::new(None));
let projector: Arc<Mutex<Option<UiProjector>>> = Arc::new(Mutex::new(None));
let workspace = AgentWorkspace::new(760, 600, {
    /* 根闭包：revision.get() + current + projector 投影 */
}).spawn()?;
// 2. 可克隆转发出口：扩展 worker 线程声明应用后唤醒后台 owner。
let poster = workspace.poster();
// 3. 独立扩展 worker：挂载位、共享端口与 sink（能力与 handle 一致）。
let host = ExtensionHost::new()
    .with_mount("panel")
    .with_port("documents-query", shared_query)      // 与前台共享同一领域数据
    .with_port("documents-commit", shared_commit)
    .with_ui_sink(Arc::new(move |update| {
        if let UiUpdate::Applied { mut node, generation, .. } = update {
            // 代际切换 + 一次性 reset 消耗 + 声明快照 + 修订推进 + 唤醒
            //（update 必须先于 wake）。
        }
    }));
let handle = host.spawn_worker();
// 4. 装载：经 read_from_directory 读取授权来源，激活后安装投影器并补帧。
```

装配与操作要点：

- **装配补帧**：初始声明的重帧可能早于投影器安装（先渲染出空面板且不再有新触发）。激活后先安装 `UiProjector`，再推进一次修订并 `poster.wake()`；`revision.update` 必须发生在 `wake()` 之前，否则 owner 消费唤醒令牌时可能看不到待办工作。
- **wake 顺序**：sink 内 `update`（标记待办）→ `poster.wake()`（唤醒）；AgentWorkspacePoster 可跨线程长期持有，能力与 handle 相同，不转移租约与关闭责任。
- **一次性 reset 消耗**：`(reset #t)` 属于本次 `UiUpdate::Applied` 的一次性指令。同一声明随后会因无关重绘被重投影，应用层必须在 Applied 处调用 `UiProjector::consume_declaration_resets(&mut node)`（以声明值重建对应草稿 State 并清除标记），此后 `project` 对该声明幂等——否则重投影会以声明值再次覆盖用户刚输入的编辑（读取后编辑丢失即此竞争）。
- **单实例停用**：`ExtensionUiHandle::deactivate(id)` 返回 `TeardownReceipt`；挂载子树的清空由应用在收到终态后执行（置空声明快照 + 推进修订 + 唤醒）。`revoke` 先行时新调用与事件被拒、面板保留可观察状态；`ExtensionUiHandle::list()` 回读活动实例状态（含 `revoked` 标记）。
- **前台共存**：前台（真窗或 TestApp）用另一个 `ExtensionHost` 装载同一外部包（两侧各自开放同名挂载位，互不干扰），各自持有投影器与草稿库；合法提交产生的共享数据更新按业务端口契约对两侧可见（如版本号推进），局部交互状态互不可见。
- **版本冲突**：受控写端口应携带预期版本，不一致时返回冲突结果（携带当前版本），不静默覆盖任何一方的新修改；脚本侧向用户回显冲突事实。

### 显式生命周期管理与关闭语义

text_workbench 宿主在两个根（前台真窗与后台操作面）各持有原生管理按钮（`manage-load` / `manage-replace` / `manage-status-btn` / `manage-revoke` / `manage-deactivate`），执行同一套管理操作；AI 经既有 Agent `perform invoke` 驱动后台管理按钮，不控制前台按钮，也不另造管理服务。管理状态经共享 `State<String>` 两侧同显（`manage-status` 文本节点可从快照读取），结果区分阶段：包检查（版本、文件数）→ 候选准备 → 活动代切换（generation、命令表）→ 界面应用；GPU 呈现由 Agent `wait` 的 `presented_revision` 另行确认。两侧操作结果分别报告；一侧替换失败时如实呈现该侧失败与另一侧成功，不宣称跨实例原子升级。

收尾责任统一：正常关闭与 `--quit-after` 复用同一收尾函数（前台 worker → 后台 worker → 后台操作面），每步取得真实终态并打印诊断；任何失败或超时以非零退出码如实报告，不把强制进程退出冒充资源已优雅释放。

可复制的操作回路（详见示例文件头）：

```sh
cargo run --release --features extensions,agent-control --example text_workbench \
  -- --extension-source extensions/text-bench/v1 [--quit-after 秒]
python3 scripts/agent_client.py apps                              # 枚举并确认实例
python3 scripts/agent_client.py --instance <实例ID> list_windows   # 只有 visible=false 的后台视口
python3 scripts/agent_client.py --instance <实例ID> snapshot 0     # 语义状态（manage-* 与 text-bench/panel/…）
python3 scripts/agent_client.py --instance <实例ID> perform <载荷.json>   # set_value / invoke（含 manage-* 按钮）
python3 scripts/agent_client.py --instance <实例ID> screenshot 0 /tmp/panel.png
```

预期结果：装载按钮把外部包读入两侧并激活（管理状态显示包检查、generation 与命令表）；处理按钮把统计算法结果回显到 `stats` 文本；提交成功后 `status` 显示新版本、共享文档按端口契约更新；携带陈旧版本提交显示「版本冲突」且文档不变。只修改外部包文件（如把来源目录内容换为 v2）后点替换按钮：宿主不重编译、不重启，算法与界面共同升级且兼容状态（草稿、读取版本）保留；提交无效包或迁移失败候选时该侧如实报告失败，旧代继续服务。撤权后新调用与面板事件被拒；停用后扩展节点退出语义树、挂载子树清空，宿主与操作面保持存活。后台失败不会降级为前台控制。

公开行为验证：`tests/text_workbench_public_api.rs`（`cargo test --features agent-control,test-harness,extensions --test text_workbench_public_api`）覆盖 v1 词数边界输入（`stats` 命令）、后台读取-编辑-处理-提交闭环（断言提交的是编辑后内容）、陈旧版本冲突、前后台交互状态独立、热替换升级算法与界面并保留兼容状态后继续编辑提交、无效候选保留旧代、撤权与停用终态（扩展节点退出语义树、宿主与操作面存活）、停用后重新装载完成业务且陈旧事件不污染新实例；`tests/extensions_public_api.rs` 覆盖目录读取冻结快照与类型化读取失败（含符号链接与子目录拒绝）。

## 热替换、状态迁移与撤权（P3）

### 替换协议

```rust
// 准备候选（独立引擎求值；准备期无外部效果）。
let candidate = host.prepare(&package_v2)?;
// 以预期活动代替换：门控（命令串行化）→ 静止点导出 → 候选导入 →
// 提交新代 → 旧代关闭清扫。
let receipt = host.replace(candidate, expected_generation)?;
// receipt.migrated 标记是否执行了状态迁移；generation 递增不复用。
```

- 提交前失败（候选语法、迁移抛错、schema 不一致、冲突代）丢弃候选，
  旧代保留并继续接收；`expected_generation` 不符返回 `StaleGeneration`。
- worker 模式（`ExtensionUiHandle::replace`）同语义；在途异步终态经
  代际校验丢弃，不写入新代、不重放外部效果。
- 界面应用：替换回执后调用 `UiProjector::update_generation(new)` 切换
  事件代际；草稿库随投影器保留，兼容输入沿合同延续。

### 状态迁移合同

- 清单 `state-schema-version`：双方为 0 视为无状态（跳过迁移）；
  非零且版本一致时，`(register-state-export! proc)`（无参，返回跨边界
  owned 兼容值）与 `(register-state-import! proc)`（单参）必须同时
  注册，否则替换被拒绝（禁止静默清空）。
- 迁移路径下准备期暂存的初始声明被丢弃：**迁移过程拥有状态解释权**，
  由其在导入后以新状态重新 `submit-ui!`（或保持旧界面至新声明到达）。
- 导出与迁移只允许纯计算；闭包、环境与 continuation 不进入快照。

### 撤权与终态

- `host.revoke(id)`：撤权后新调用返回 `CapabilityDenied`，面板事件与
  异步终态丢弃；已发生或不能取消的效果由宿主收尾。实例保留至
  `deactivate`（状态可观察：`list()` 回读含 `revoked` 标记）。
- 卸载终态：`deactivate` 返回 `TeardownReceipt` 后实例已排空并释放
  （关闭清扫断开全部环引用）；重复停用返回 `UnknownExtension`。

## 适用限制

- 语言是「R7RS-small 实现中的受限宿主环境」：文件 / 进程 / 时钟 / 网络 / REPL 库拒绝，多值、异常、lazy、bytevector、内存字符串端口开放；完整矩阵见[引擎取证](../../架构/app/extensions-engine.md)。
- 同步 `ExtensionHost` 非线程安全：实例串行求值，仅取消令柄可跨线程；窗口应用用 `spawn_worker`（引擎移入执行线程，`spawn_worker` 前不得已装载实例）。
- 脚本域内部运行时错误（未绑定变量、类型不符）不可被 `guard` 捕获，直接终止当次调用；配额 / 取消 / 超时同样不可捕获；面板事件处理失败静默终止本次调用（不中断宿主）。
- `with-exception-handler` 的 handler 以子机器调用，handler 内 continuation 逃逸语义受限（矩阵已登记）。
- 首期单窗基线：多窗口事务请求拒绝；`activate` 遇同 ID 活动实例仍直接拒绝（升级走 `replace`）。
- 持久化可选协议（跨进程崩溃恢复）不在本阶段；进程内热替换不承诺崩溃恢复。
