# 浮层与反馈

[← 返回使用 索引](../使用.md)

> 分类：浮层与反馈  
> 权威范围：Modal、Drawer、Message、Notification、Popover 与焦点陷阱

框架自动维护 `OverlayStack`，应用不手管层级。

## Modal

```rust uix-compile=modal-overlay
Modal::show(|ctx| {
    let cancel_ctx = ctx.clone();
    let confirm_ctx = ctx;
    column((
        label("确认删除？").font_size(18.0),
        row((
            button("取消").on_click_fn(move || cancel_ctx.close()),
            button("确认").danger().on_click_fn(move || {
                // 执行删除
                confirm_ctx.close();
            }),
        )).gap(8.0),
    ))
    .gap(16.0)
})
.title("提示")
.width(400.0);
```

`Modal::show` 打开 overlay 并把闭包返回的 `View` 作为普通内容子树；默认隐藏内置 footer，由内容自行声明操作按钮。`ModalContext` 可 clone，`ctx.close()` 应在该子树的事件回调中调用，只关闭持有此 context 的 Modal，并先播放现有 leave transition。需要直接构造底层组件时，用 `Modal::new("标题").visible(true)` 声明初始打开状态。

直接构造的闭合 Modal 提供可聚焦 Button 触发器；父布局拉伸 frame 时，96×32 的视觉与命中区域共同居中，指针及 `Enter` / `Space` 都只在匹配释放后打开。打开后切换为 Dialog 语义并发布 `expanded=true`，Tab 焦点限制在内容子树的真实控件间；关闭槽和可关闭 mask 也只在同一目标完成按下与释放后提交，移出、失焦或交互几何变化会取消，`Escape` 关闭最上层 Modal。

`.size(width, height)` 会把非有限或负尺寸归零，并把遮罩对话框收敛到实际 surface。header、body、footer、关闭反馈与内容子树共享有限非负几何和裁剪边界；长标题在 Lucide 关闭图标前按 Unicode 单行省略。业务确认与取消应继续放在内容子树中绑定真实 Button；不需要内置 footer 视觉槽时使用 `.footer_visible(false)`。

```rust uix-compile=feedback-modal-shortcuts
// 快捷确认对话框
let on_ok = || {};
let on_cancel = || {};
Modal::confirm("提示", "确定删除？", on_ok, on_cancel);

// 单按钮信息提示
Modal::info("提示", "操作成功");
Modal::warning("警告", "磁盘空间不足");
Modal::error("错误", "保存失败");

// 关闭后从树中移除
Modal::new("标题").destroy_on_close(true);

// 隐藏关闭按钮
Modal::new("标题").closable(false);
```

## Drawer

```rust uix-compile=drawer-overlay
tree! { Drawer::new("详情")
    .placement(DrawerPlacement::Right)
    .size(480.0, 640.0)
    .show() => [
    label("抽屉内容"),
]};
```

闭合态内置触发器是可聚焦 Button，指针或 `Enter` / `Space` 必须完成匹配释放才打开；父布局拉伸 frame 时，96×32 的触发视觉与命中区域共同居中。打开后切换为 Dialog 语义并由 Drawer overlay 约束 Tab 焦点。关闭按钮同样只在同一目标内完整释放后提交，移出、失焦或外部释放会取消，`Escape` 关闭最上层 Drawer。`.size(width, height)` 会把非有限/负尺寸归零，并把遮罩 Drawer 收敛到实际 surface；标题与 `extra` 各自在关闭槽前单行省略，面板、header/footer、关闭反馈和内容子树统一裁在实际区域内。`footer_visible(true)` 目前只提供本地化确认按钮的视觉槽，业务提交仍应放在内容子树中绑定真实 Button。

## Message / Notification

```rust uix-compile=message-notification
let messages = Message::new().placement(Placement::BottomLeft);
let message_handle = messages.handle();
let saved = message_handle.success("保存成功");
messages.error("保存失败");
message_handle.dismiss(saved); // 启动该项离场动画

let notifications = Notification::new().placement(Placement::TopRight);
let notification_handle = notifications.handle();
let updated = notification_handle.info("更新完成", "已更新到 v2.0");
notifications.warning("空间不足", "请清理缓存后重试");
notification_handle.dismiss(updated);
```

`Message` 默认置顶居中，`Notification` 默认置于右上角；二者共享 `Placement`，可选 `Top`、`Bottom`、`Left`、`Right` 及四个角。`add(...)`、`success/info/warning/error(...)` 返回稳定 ID；handle 可在组件交给 View 后继续增删队列。`MessageItem` / `NotificationItem` 的 `duration_ms = 0` 表示持续展示，直到 `dismiss(id)`、`clear()` 或关闭按钮触发离场。其他项在进入动画完成后开始计时，持有期间不申请动画帧，只登记最近一个到期 timer。

`Message` 会按所属窗口实际 frame 只绘制当前能容纳的最新提示，较早项仍保留在公开队列并继续遵循原计时/稳定 ID 契约；卡片、状态与关闭图标、单行内容及动画统一裁在窗口内，长内容在关闭槽前按 Unicode 省略。可关闭项只有在同一关闭槽内完成指针按下与释放才进入离场，移出、失焦、外部释放、窗口尺寸或 placement 改变会取消未完成动作。非空队列以 Alert 语义发布当前提示内容，空队列不发布有效提示语义。

`Notification` 也只绘制实际 frame 能容纳的最新通知，带说明和不带说明的卡片按各自高度参与容量计算；隐藏的较早项仍保留在公开队列中。标题、说明、状态与关闭图标统一裁在窗口内，过长文字会在关闭槽前单行省略。关闭同样要求在同一通知的关闭槽内完成按下与释放，未完成动作会在移出、失焦、窗口尺寸或 placement 改变时取消；非空队列以 Alert 语义发布标题和说明。

队列始终约束在所属窗口的 logical 客户区内，底部放置时整组向上避让；空队列不占布局，也不拦截命中。后台线程不直接操作组件 handle；用目标窗 `AppHandle::post_to_ui` 回到 UI 线程（详见[定时与异步](定时与异步.md#跨线程回-ui)）。`AppHandle::notify_error` 使用目标窗口自己的通知队列；返回的 ID 可交给 `dismiss_notification(id)`，不会唤醒或修改其他窗口。

```rust uix-compile=feedback-toast-options
// ---- Notification ----

// 操作按钮
Notification::new()
    .action("撤销", || {});

// 自定义状态图标
Notification::new().icon("star");

// 自定义关闭按钮文字
Notification::new().close_text("忽略");

// 距边缘偏移
Notification::new().offset(16.0, 80.0);

// ---- Message ----

// 操作按钮
Message::new().action("重试", || {});

// 自定义图标
Message::new().icon("check-circle");
```

## Popover / Tooltip

```rust uix-compile=popover-tooltip-popconfirm
tree! { Popover::new("弹出内容").trigger(PopoverTrigger::Click) => [
    Button::new("详情"),
]};

tree! { Tooltip::new("提示文字").trigger(TriggerMode::Hover) => [
    Button::new("悬停查看"),
]};

tree! { Popconfirm::new().title("确定删除？") => [
    Button::new("删除").danger(),
]};
```

三类组件都是交互包装器：子 View 铺到包装器的实际 frame 并负责触发展示，包装器接管其指针命中区域；选择 focus 触发时，包装器观察整个子树的焦点边界，同一包装器内切换子控件不会关闭重开，焦点离开或已聚焦子树移除时才关闭。Tooltip 的单行气泡按 12 logical、Unicode 宽字符和 16 logical 横向 padding 计算自然宽度，绘制、overlay bounds 与 damage 使用同一尺寸，CJK 文本不会按 UTF-8 字节数放大。

Popover 与 Popconfirm 的 Click 触发器只有在同一目标内完成指针按下与释放，或完成 `Enter` / `Space` 的按下与释放后才打开。浮层优先使用声明的 placement，空间不足时沿主轴翻转并收敛到所属窗口；标题、正文和 Popconfirm 的确认/取消文字在实际槽位内单行省略，箭头、阴影和全部绘制统一裁在窗口内。Popover 以 Button 语义发布 `expanded` 和内容值，`Escape` 关闭当前浮层。

`Popconfirm` 只响应鼠标左键；自身可用 Tab 聚焦，打开后用 Left / Right / Home / End 选择确认或取消，当前操作进入语义值。确认或取消同样只在匹配释放后提交，移出、失焦或交互几何变化会取消未完成动作；Escape 或焦点离开整个包装器会关闭。只有确认操作在弹层关闭后发出载荷为 `"confirm"` 的 `SemanticKind::Submit`，可在返回的 View 上用 `.on_submit(...)` 执行业务动作。

```rust uix-compile=feedback-popover-options
// ---- Popover ----

// 受控打开状态
let open_state = State::new(true);
Popover::new("内容").controlled_open(&open_state);

// 自定义触发器 View
Popover::new("内容").trigger_view(label("打开"));

// 隐藏箭头
Popover::new("内容").arrow(false);

// 自定义背景色
Popover::new("内容").bg(Color::WHITE);

// ---- Tooltip ----

// 自定义颜色
Tooltip::new("提示").bg(Color::BLACK).color(Color::WHITE);

// 隐藏箭头
Tooltip::new("提示").arrow(false);
```

## 进度与加载

```rust uix-compile=progress-loading
ProgressBar::new().progress(0.65).round(false); // 65%，方角
ProgressBar::new().indeterminate();             // 不确定进度
ProgressBar::new().progress(0.8).circle();       // 圆形进度
Spin::new().large();                             // 大号加载旋转
grid([ViewNode::new(
    Spin::new().tip("加载中").wrapper_mode(),
    vec![label("业务内容")],
)]).width(320.0).height(88.0);                   // 在明确 frame 上覆盖内容
Skeleton::new().size(320.0, 48.0);               // 骨架占位
```

确定进度把 `0.0..=1.0` 暴露为 `ProgressBar` 的 `value_now/min/max`；不确定进度只保留 role，不伪造当前值或范围。非有限 progress 收敛为 0，有限值裁到该区间；负数或非有限宽高收敛为 0，小尺寸圆形进度也不会产生负半径，`.round(false)` 使用真实方角。两种进度形态都只在 Content 阶段绘制并裁在实际 frame 内。

普通 `Spin` 按实际 frame 缩小转子并发布 Status"加载中"；设置 `.tip(...)` 后该文本成为可访问名称。`.wrapper_mode()` 保持零固有占位，须像上例由 Grid 或其他容器分配明确 frame；其子树铺满该 frame，加载时才在 AfterChildren 阶段叠加主题自适应遮罩、转子和单行省略提示，`.spinning(false)` 时不遮挡内容。

`Skeleton` 提供 `Rect`、`Circle` 与两行 `Text` 三种静态占位形态。`.size(width, height)` 的负数或非有限尺寸收敛为 0；布局继续约束时，圆角、圆形半径以及 Text 的行高与间距都按实际 frame 重新计算，并统一裁在该 frame 内。

```rust uix-compile=feedback-spin-options
// 延迟显示，避免瞬时加载闪烁
Spin::new().delay(std::time::Duration::from_millis(500));

// 小号旋转器，可内联在文本中
Spin::new().size(SpinSize::Small);
```

## FocusTrap —— 焦点陷阱

Modal 和 Drawer 自动启用焦点陷阱：Tab / Shift+Tab 仅在浮层内可聚焦节点间循环，无法逃逸到底层视图。

手动使用时：

```rust uix-compile=manual-focus-trap
tree! { FocusTrap::new().active(true) => [
    Input::new("用户名"),
    Button::new("提交"),
]};
```

框架自动收集子树的 `focusable_ids`，并在 Tab 键事件中调用 `next_focus()` 按深度优先顺序循环。

## 浮层类型

框架内部通过 `OverlayStack` 管理浮层层级。`OverlayKind` 枚举定义浮层类别：

| 变体 | 对应组件 | 默认行为 |
|------|----------|----------|
| `Modal` | `Modal` | modal + dismiss_on_outside + focus_trap |
| `Drawer` | `Drawer` | modal + dismiss_on_outside + focus_trap |
| `Popover` | `Popover` | 点击外部关闭 |
| `Tooltip` | `Tooltip` | hover 触发 |
| `ContextMenu` | — | 右键菜单 |
| `Message` | `Message` | 自动消失 |
| `Notification` | `Notification` | 自动消失 |
| `Custom` | 自定义 | 无预设行为 |

`OverlayEntry` 可通过 `managed()` 标志交由框架自动清理（默认所有内置浮层均为 managed），也可设为 `false` 手动管理生命周期。

## Alert

```rust uix-compile=alert-feedback
Alert::new("注意")
    .description("这是一条提示信息")
    .show_icon(true)
    .closable();
```

`.closable()` 让关闭按钮进入 Tab 顺序；指针必须在关闭区内完成按下与释放才会提交，移出、失焦或在外部释放会取消。聚焦后 `Enter` / `Space` 也在匹配释放时提交，`Escape` 可直接关闭；关闭会隐藏当前 Alert、触发布局回收并发出载荷为 `"closed"` 的 `SemanticKind::Change`。`show_icon(false)` 可隐藏状态图标；需要复用同一实例时可调用 `open()` / `close()`，应用 reconcile 不会把用户已经关闭的运行态重新打开。消息与说明各保持单行并在实际宽度内按 Unicode 省略，所有状态色、图标、文字、关闭反馈和焦点框统一裁在实际 frame；无障碍名称发布消息，非空说明发布为可访问值。

```rust uix-compile=feedback-alert-options
// 类型构造器
Alert::success("操作成功").description("数据已保存");
Alert::info("提示").description("这是一条信息");
Alert::warning("注意").description("请检查输入");
Alert::error("失败").description("操作未完成");

// 操作链接/按钮
Alert::new("通知").action("查看详情", || {});

// 通栏横幅模式
Alert::new("公告").banner(true);
```

## FloatButton

```rust uix-compile=float-button
let create = FloatButton::new("plus")
    .tooltip("新建")
    .badge(3)
    .size(44.0)
    .position(12.0, 8.0)
    .reserve_layout_space(true);
```

`FloatButton::new(...)` 的参数是 Lucide 图标名，不是显示文字；按钮始终通过 `Icon` 组件管线绘制该名称。`FloatButton` 默认保持零布局占位，以 `.position(x, y)` 设置相对槽位左上角的视觉偏移，并由[浮层栈](#浮层类型)提升绘制层级；需要内联预览或为锚点保留空间时显式设置 `.reserve_layout_space(true)`，此时按钮进入普通布局与绘制顺序。真实按钮区域参与命中、脏区与语义边界。组件默认进入 Tab 顺序，点击或按 `Enter` / `Space` 触发普通 `SemanticKind::Click`，可在返回的 View 上直接链 `.on_click(...)`；tooltip 在 hover 或键盘聚焦时显示。`FloatButtonBackTop::new()` 只提供箭头与文案预设，滚动动作仍通过 `.on_click(...)` 绑定应用持有的滚动 `State`，配合 [BackTop](布局.md#affix-backtop-sider) 使用。

```rust uix-compile=feedback-float-group
// 浮动按钮组，展开/收起动画
FloatButtonGroup::new().buttons(vec![
    FloatButton::new("star"),
    FloatButton::new("heart"),
    FloatButton::new("edit"),
]);

// 悬浮触发 tooltip
FloatButton::new("plus").trigger(TriggerMode::Hover);
```
