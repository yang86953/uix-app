# 浮层与反馈

[← 返回使用 索引](../使用.md)

> **接口**：声明 UIX 浮层与反馈的公开用法——Modal、Drawer、Message、Notification、Popover 与焦点陷阱。依赖：[响应式基础](响应式基础.md)、[事件](事件.md)。导出：浮层架构 → [架构 · 浮层](../架构/ui/overlay.md)。

框架自动维护 `OverlayStack`，应用不手管层级。

## Modal

```rust uix-compile=feedback-modal
use uix::prelude::*;

// 确认对话框：标题 + 内容 + 确定/取消回调
embed(Modal::confirm(
    "确认删除",
    "此操作不可恢复，确定继续？",
    || { /* 删除逻辑 */ },
    || {},
)
.title("确认删除")
.build());

// 声明式 Modal：show 返回构建器，内容用闭包组装
embed(Modal::show(|ctx| {
    column((
        label("自定义内容"),
        row((
            button("关闭").on_click_fn(move || ctx.close()),
        )).gap(8.0),
    )).gap(12.0)
})
.title("设置")
.build());
```

```rust uix-compile=feedback-modal-shortcuts
use uix::prelude::*;

// 快捷对话框：info / warning / error 单确认按钮
embed(Modal::info("提示", "操作完成").build());
embed(Modal::warning("警告", "磁盘空间不足").build());
embed(Modal::error("错误", "保存失败").build());

// 关闭策略：closable 禁用关闭槽但保留 Escape；destroy_on_close 离场后移除子树
embed(Modal::confirm("保存", "确定保存？", || {}, || {})
    .closable(false)
    .destroy_on_close(true)
    .build());
```

Modal 进入时保存原焦点、圈闭键盘焦点并阻断背景交互；关闭时先移除事件入口，再恢复到仍有效的原焦点。页脚可见时，确定按钮和 Enter / Space 只执行确认回调，取消按钮、标题栏关闭、可关闭遮罩与 Escape 共享取消回调；两类操作随后都进入同一离场并把受控 `State<bool>` 写回 `false`，离场期间不再接受重复激活。

## Drawer

Drawer 与 Modal 共享层叠和焦点规则，但保留方向、尺寸及非模态产品选择。拖动或动画期间仍只能存在一个生命周期所有者。

## Message / Notification

```rust uix-compile=feedback-message
use uix::prelude::*;

// Message：轻量操作反馈（管理器 + 队列）
let message = Message::new();
message.success("已保存");
message.warning("即将过期");
message.error("操作失败");

// Notification：可保留、可操作的通知（管理器）
let notify = Notification::new();
notify.info("更新完成", "v0.0.1 已就绪");

// Popconfirm：气泡确认
embed(Popconfirm::new()
    .title("确定删除？")
    .confirm_text("确认")
    .cancel_text("取消"));
```

```rust uix-compile=feedback-toast-options
use uix::prelude::*;

// Notification 快捷构造：success / info / warning / error
let notify = Notification::new();
notify.success("完成", "任务已结束");
notify.warning("注意", "即将过期");

// 可操作通知：时长与可关闭性由管理器协调
notify.open(NotificationItem {
    type_: StatusLevel::Info,
    title: "更新".into(),
    description: "v0.0.1 已就绪".into(),
    duration_ms: 5000,
    closable: true,
});
```

Message 用于短时全局反馈，Notification 用于可保留并可操作的通知。重复项的合并、超时与手动关闭由反馈管理器统一协调。

## Popover / Tooltip

```rust uix-compile=feedback-popover-options
use uix::prelude::*;

// Popover 高级配置：受控开关、真实触发子 View、箭头与背景
let open = State::new(false);
embed(Popover::new("内容")
    .title("标题")
    .controlled_open(&open)
    .trigger_view(button("触发"))
    .arrow(true)
    .bg(Color::WHITE));

// Tooltip：组件包裹唯一触发 View，气泡不取得业务焦点
embed(ViewNode::new(
    Tooltip::new("提示")
        .placement(TooltipPlacement::Top)
        .arrow(true)
        .bg(Color::WHITE),
    vec![button("悬停")],
));
```

Popover 锚定稳定组件身份；锚点卸载时关闭，窗口移动、尺寸变化或布局变化时按当前 logical surface 重算登记、绘制与命中几何。Tooltip 不取得业务焦点，必须有键盘与无障碍等价入口；`placement` 表示优先方向，首选方向越界更多时会翻转到主轴反向，并将气泡与长文字裁在当前 logical surface 内。

## Alert

```rust uix-compile=feedback-alert-options
use uix::prelude::*;

// Alert 状态构造 + 操作槽 + 关闭槽 + 通栏
embed(Alert::success("保存成功"));
// 操作槽保留独立的业务回调。
embed(Alert::warning("磁盘空间不足").action("清理", || {}));
// 可关闭警告由 Alert 运行态拥有关闭后的可见性。
embed(Alert::warning("磁盘空间不足").closable());
embed(Alert::error("保存失败").banner(true));
```

Alert 支持 success / info / warning / error 四种状态；操作槽与关闭槽分离，通栏模式改变实绘且目标不重叠。

## 进度与加载

```rust uix-compile=feedback-spin-options
use std::time::Duration;
use uix::prelude::*;

// Spin：延迟显示与尺寸（delay 为 Duration）
embed(Spin::new().delay(Duration::from_millis(200)).size(SpinSize::Large));
embed(Spin::new().large());
```

`Spin` 支持 `.delay(...)`（计时到期才显示，重新激活重计时）与 `.size(SpinSize)` / `.large()`；进度条与骨架屏见[数据展示](数据展示.md#进度与加载)。

## FloatButton

```rust uix-compile=feedback-float-group
use uix::prelude::*;

// 独立 FloatButton：窗口右下角锚定，作者偏移在锚点之后应用并收敛到当前 surface
embed(FloatButton::new("message")
    // description 扩展按钮的绘制与命中区域
    .description("意见反馈")
    // tooltip 继续使用可读的辅助提示
    .tooltip("打开反馈")
    // 数字徽标保存数量语义
    .badge(7)
    // dot 启用时视觉上优先于数字，数字仍保留在 authored config
    .badge_dot(true)
    // placement 复用窗口 logical 客户区契约
    .placement(Placement::BottomRight)
    // position 是相对 placement 锚点的有限作者偏移
    .position(-8.0, -8.0));

// FloatButtonGroup：展开后子按钮可命中，收起后命中隔离
embed(FloatButtonGroup::new()
    .buttons(vec![
        FloatButton::new("edit"),
        FloatButton::new("share"),
    ]));
```

浮动操作按钮属于窗口内 overlay，遵循安全边距、命中区域和遮挡规则；显式 `.placement(...)` 时，布局、绘制、damage、命中与 OverlayStack 登记共同使用当前窗口 logical surface。未设置 placement 的 Rust 调用继续保持既有的 frame-relative 定位，`.position(x, y)` 在两种模式下都是有限作者偏移；普通布局示例可用 `.reserve_layout_space(true)`，此时 placement 不接管布局位置。

`description` 会把圆形按钮扩展为同高胶囊，并与图标共同构成交互区域；`badge_dot(true)` 在视觉上优先显示圆点，`badge(count)` 的非负数量仍保留在快照与无障碍状态中。紧凑尺寸下图标仍需有可读语义名称，名称按 description、tooltip、Lucide icon 名依次回退。

## FocusTrap 焦点陷阱

浮层只允许最上层可交互项接收输入。Escape、关闭按钮、外部点击等退出路径必须服从组件策略，并确保离场动画完成后清理句柄和订阅。

```rust uix-compile=feedback-focustrap
use uix::prelude::*;

// 自定义浮层内容时用 FocusTrap 圈闭焦点（以子节点包裹）
embed(ViewNode::new(
    FocusTrap::new(),
    vec![
        button("确定"),
        button("取消"),
    ],
));
```

`FocusTrap` 本身只声明稳定作用域；后代可聚焦性与 Tab 正反向循环由 `WidgetTree` 在运行时解析。overlay 的焦点恢复属于独立生命周期，不由普通 `FocusTrap` 声明。该核心组件不要求启用 `feedback` capability。

这些约束来自与 Rust `overlay` / `event` 架构一致的行为部分。

## 理想使用方式

按产品定义（容错可观测、原生优先）：

```rust uix-compile=feedback-controlled-modal
use uix::prelude::*;

// 反馈状态由业务 State 驱动，框架管理层级与焦点（E-03 已落地）
let saving = State::new(false);

embed(Modal::builder()
    .open(&saving)
    .title("保存中")
    .content(|| embed(Spin::new().large()))
    .closable(false)        // 保存中禁止外部关闭（Escape 仍可关闭）
    .on_open_change(|open| saving.set(open))
    .build());
```

```rust uix-compile=feedback-facade
// 全局反馈门面：任意位置（事件回调 / 定时器 / CLI）可取用（E-04 已落地）
message().success("已保存");
notify().info("后台任务完成", "同步完成");
```

- 浮层层级、焦点圈闭、关闭恢复由框架托管，业务不手管 OverlayStack。
- Modal 与 Drawer 均可由受控 State 驱动：外部 `set(true)` 在下一动画帧打开，用户侧关闭写回 `false`；Modal 额外触发 `on_open_change`，Drawer 在离场期间吞掉输入且不重复启动关闭动画。
- `Message::new()` / `Notification::new()` 挂载即注册为当前反馈目标（逐窗隔离：每窗口一个组件实例，最近挂载生效）；`ui::register_feedback` 可显式覆盖，未注册时门面为 no-op 且 `is_available()` 可查询。
- 离场动画完成后才清理句柄与订阅，不残留不可达操作。
