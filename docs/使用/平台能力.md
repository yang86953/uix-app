## 入口

平台能力从所属窗口的 `AppHandle` 获取。handle 可以跨线程保存；具体 OS 操作由框架投递到正确线程：

```text
use uix::platform::capability::PlatformCapability;
use uix::platform::hardware::HardwareValue;

App::new()
    .on_start(|app| {
        let platform = app.platform();
        let capabilities = platform.capabilities();

        if capabilities
            .status(PlatformCapability::HardwareInventory)
            .is_available()
        {
            let snapshot = platform.hardware().snapshot();
            if let (
                HardwareValue::Available(cpu),
                HardwareValue::Available(displays),
            ) = (snapshot.cpu(), snapshot.displays())
            {
                println!(
                    "{} logical CPUs, {} displays",
                    cpu.logical_cores(),
                    displays.len(),
                );
            }
        }
    })
    .run();
```

快照带 `generation` 与采集时间。同步的 `snapshot()` 只返回缓存，不在 UI 线程临时枚举设备。

## GPU 与图形运行时

GPU inventory 是显式、可取消的探测；同一物理 GPU 在不同 backend 下可能出现为多个 adapter：

```text
use uix::platform::hardware::{HardwareQuery, HardwareValue};

let request = platform
    .hardware()
    .refresh(HardwareQuery::basic().with_gpus());

let _cancellation = request.on_complete(|result| {
    match result {
        Ok(snapshot) => {
            if let HardwareValue::Available(adapters) = snapshot.gpu_adapters() {
                for adapter in adapters {
                    println!(
                        "{}: {:?}, {:?}, driver={:?}",
                        adapter.name(),
                        adapter.device_class(),
                        adapter.backend(),
                        adapter.driver(),
                    );
                }
            }
        }
        Err(error) => eprintln!("{error}"),
    }
})?;
```

应用配置的是选择策略，不把 `Auto` 冒充具体 backend：

```text
use uix::platform::graphics::{
    AdapterPreference,
    GraphicsBackend,
    GraphicsFallbackPolicy,
    GraphicsOptions,
    GraphicsRuntimeState,
    GraphicsSelection,
    PowerPreference,
};

let graphics = GraphicsOptions::builder()
    .selection(
        GraphicsSelection::auto().prefer_backends([
            GraphicsBackend::Vulkan,
            GraphicsBackend::Direct3D12,
        ]),
    )
    .adapter_preference(AdapterPreference::Default)
    .power_preference(PowerPreference::HighPerformance)
    .fallback(GraphicsFallbackPolicy::AllowCpu)
    .build()?;

App::new()
    .graphics(graphics)
    .on_start(|app| {
        let runtime = app.platform().graphics().snapshot();
        match runtime.state() {
            GraphicsRuntimeState::ActiveGpu(device) => {
                println!("{} via {:?}", device.adapter_name(), device.backend());
            }
            GraphicsRuntimeState::ActiveCpuFallback(fallback) => {
                println!("software renderer: {}", fallback.reason());
            }
            GraphicsRuntimeState::Initializing
            | GraphicsRuntimeState::Recovering(_) => {}
            GraphicsRuntimeState::Failed(error) => {
                eprintln!("{error}");
            }
            GraphicsRuntimeState::Closed => {
                println!("graphics runtime closed");
            }
        }
    })
    .run();
```

`HardwareSnapshot` 说明系统发现了什么；`GraphicsRuntimeInfo` 说明当前窗口真实创建并正在使用什么。adapter 被枚举到不保证它能为当前 surface 创建设备。

若要让后续新窗口精确选择一次枚举结果，使用 adapter 提供的 `GpuAdapterRef`；它同时携带 snapshot generation。引用已过期、backend 不匹配或该 adapter 无法为新 surface 创建设备时，窗口创建返回 typed 错误，不静默换设备：

```text
use uix::platform::graphics::{
    GraphicsFallbackPolicy,
    GraphicsOptions,
    GraphicsSelection,
};

let window_graphics = GraphicsOptions::builder()
    .selection(GraphicsSelection::require_adapter(adapter.reference()))
    .fallback(GraphicsFallbackPolicy::Disallow)
    .build()?;

app.open_window(
    WindowConfig::new()
        .title("GPU preview")
        .graphics(window_graphics),
)?;
```

## 原生服务

可能阻塞、弹窗或请求权限的调用返回 `PlatformRequest<T>`，不阻塞主循环：

```text
use uix::platform::services::{
    ClipboardWrite,
    DialogOutcome,
    FileFilter,
    OpenFileDialog,
};

let activation = event.user_activation();
let write = ClipboardWrite::text("hello")
    .user_activation(activation.clone());

platform.clipboard().write(write).on_complete(|result| {
    if let Err(error) = result {
        eprintln!("{error}");
    }
})?;

let options = OpenFileDialog::new()
    .title("打开图片")
    .user_activation(activation)
    .filter(FileFilter::extensions("图片", ["png", "jpg", "jpeg"]));

platform.dialogs().open_file(options).on_complete(|result| {
    match result {
        Ok(DialogOutcome::Selected(path)) => println!("{}", path.display()),
        Ok(DialogOutcome::Cancelled) => {}
        Err(error) => eprintln!("{error}"),
    }
})?;
```

`event.user_activation()` 只在受信任键盘 / 指针派发期间提供 opaque token；Windows 等不要求 token 的平台可以省略，Wayland 等要求 compositor serial 的平台在 token 缺失或过期时返回 typed `NotReady(UserActivationRequired)`。文件对话框使用 `PathBuf`，取消是正常 outcome；请求取消另带 `Requested` / `WindowClosed` / `AppShutdown` / `Superseded` 原因，权限拒绝、平台不支持和 IO 失败保留 typed 错误。

`PlatformRequest` 未激活即丢弃时不启动操作。`on_complete` 受理失败会同步返回 `Closed` 且不注册回调；一旦返回 cancellation handle，完成回调就始终异步投递到 App 级 completion queue 且恰好一次，不依赖来源窗口 session，也不在调用点重入。系统原生通知与 UI 的 `Message` / `Notification` 是不同能力。

## 不公开的对象

应用不取得以下对象：

- backend registry / recipe 与 probe loop
- `PlatformWindow` / presenter / graphics context
- `wgpu::Device`、Vulkan / D3D / Metal / OpenGL 对象
- raw window / display / surface handle
- native 事件循环、帧 callback 与 IME session

窗口创建、渲染、GPU 恢复和资源释放继续由 `App` 托管。
