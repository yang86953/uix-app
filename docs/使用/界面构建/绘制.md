# 绘制与图像帧

[← 返回使用索引](../../使用.md)

本页由 `uix-app` 维护图形 API：绘制闭包、`PaintContext`、CPU 图像帧及字体输入。独立 CPU 绘制选择 `graphics`；View 绘制选择 `ui`；原生窗口呈现额外需要应用与图形后端能力。

## 独立 CPU 绘制

[offscreen 示例](../../../examples/offscreen.rs) 使用 `CpuBackend` 创建像素表面、写入矩形并检查像素，不需要 UI 树或原生窗口：

```sh
cargo run --no-default-features --features graphics --example offscreen
```

## Canvas

需要自定义绘制但不需要完整生命周期时使用 canvas/绘制闭包。绘制只消费解析后的尺寸、主题和业务快照，不在 painter 中执行 I/O、计时或状态写入。

```rust uix-compile=widget-canvas
use uix_app::prelude::*;

// 固定尺寸画布：绘制只消费 frame 与 PaintContext
canvas(120.0, 40.0, |frame, ctx| {
    let color = ctx.tokens().color_primary();
    ctx.fill_rounded_rect(frame, color, Radius::uniform(8.0));
});
```

## PaintContext

`PaintContext` 是 UI 到 graphics 的规范绘制入口（UI-owned，包装底层 draw 上下文并持有主题令牌作用域）；组件记录绘制意图，不直接选择 GPU backend、surface 或 present 策略。

```rust uix-compile=widget-paint-context
// render 内使用令牌与绘制原语
render => (&self, frame: Rect, ctx: &mut PaintContext) {
    // 语义色来自主题令牌，不硬编码
    let primary = ctx.tokens().color_primary();
    let bg = ctx.tokens().color_primary_bg();

    // 绘制原语：圆角矩形、文本、圆形、阴影
    ctx.fill_rounded_rect(frame, bg, Radius::uniform(8.0));
    ctx.fill_circle(frame.x + 20.0, frame.y + 20.0, 10.0, primary);
    ctx.draw_text("hello", Point::new(frame.x + 8.0, frame.y + 8.0), primary, 14.0);
}
```

绘制命令逐一转发给底层 draw 上下文；`with_opacity` 闭包接收底层 draw 上下文（令牌需提前解析）。`dirty_rect` 声明自绘区域的脏矩形，帮助框架最小化重绘（资源优先）。

## 合成帧与视频帧

当前源码通过 `uix_app::draw::FrameImage` 和 `PaintContext::draw_frame_image` 复用既有图像录制、缩放和呈现链路。它是可替换的 **CPU 帧输入**，不是视频解码器或第二套 present 接口；使用方需固定包含这些接口的源码版本，不假定已发布的 `0.0.7` 包具备它们。

### 帧值与绘制

- `FrameImage::new(width, height, Vec<u32>)` 接管像素；`from_shared(width, height, Arc<Vec<u32>>)` 接管共享不可变像素，不复制载荷；`solid(width, height, Color)` 创建预乘单色帧。构造失败返回实现 `std::error::Error` 的 `FrameEncoderError`，可用 `?` 向应用错误边界传播，不会提交部分帧。
- 宽高必须为正，像素数量必须精确等于宽乘高。像素为左上原点、逐行紧密排列的 **预乘 `0xAARRGGBB` 数值**，不是与平台字节序无关的 RGBA 字节流。构造器检查尺寸和长度，不替调用方验证颜色通道已经预乘。带行填充、YUV、HDR、色彩转换与外部解码器内存均由应用适配为该格式。
- 帧可 `Clone + Send + Sync`，克隆共享不可变载荷；`width()`、`height()`、`pixels()` 为只读查询。外部持有的 `Arc` 不能原地修改已共享像素；写时复制产生的是另一个帧，而不是修改已提交帧。
- `draw_frame_image(&image, bounds)` 保持源宽高比并在 logical 目标矩形内居中，留白不清除；`draw_frame_image_fill` 拉伸铺满，不保持比例。缩放跟随既有图像采样、变换、裁剪、透明度和混合状态，不在应用端再次乘 DPR。目标包含非有限值、非正尺寸或溢出边界时不绘制；负位置仍允许被正常裁剪。
- 绘制只记录/执行意图，不隐式读取文件、请求下一帧或提供 present 完成回调。不要把调用返回、状态发布或入队成功当作屏幕已经呈现。

```rust
use uix_app::draw::FrameImage;
use uix_app::prelude::*;

fn frame_canvas(current: State<Option<FrameImage>>) -> ViewNode {
    canvas(640.0, 360.0, move |bounds, ctx| {
        ctx.fill_rect(bounds, Color::BLACK, None);
        if let Some(frame) = current.get() {
            ctx.draw_frame_image(&frame, bounds);
        }
    })
}
```

`canvas` 中读取的 `State` 触发该节点的 Paint 失效，不需要每帧替换整个视图。需要拉伸时把上例调用替换为 `draw_frame_image_fill`。关闭视频时清空帧状态，并保留背景绘制，避免把上一帧当作停播后的内容。

### 线程、取消与释放

应用拥有生产者和播放会话，不把解码器类型、指针或原生窗口句柄交给 UIX：

1. 在生产线程完成解码/转换，交付拥有型 `FrameImage`。原始解码器租约必须在完成拷贝后由应用归还，不延长到 UIX 的异步绘制完成。
2. 用有界队列或单槽“最新帧”邮箱传递，明确丢帧策略；不要逐帧无限累积 `post_to_ui`。通过 UI 定时器消费邮箱，或合并为至多一个待处理 UI 通知。
3. 仅在目标窗口的 UI owner thread 更新 `State`。播放/切源使用递增请求代际，应用帧前再次核对代际与取消状态；窗口关闭后不再投递，迟到帧直接释放。具体调度边界见[定时与异步](../动画与异步/定时与异步.md#跨线程回-ui)。
4. 关闭/卸载按“取消并使代际失效 → 停止定时器/通知 → 停止并 join 生产线程（不在 painter 中等待）→ 清空邮箱与当前帧 → 拆除视图/窗口”的顺序清理。线程、定时器、状态与取消令牌必须有明确 owner；没有 owner 的后台线程不属于 UIX 保证。

帧引用是一份 Rust 共享所有权，不是 GPU fence、解码器 release callback 或扫描输出完成租约。调用方可在绘制返回后丢弃自己的引用；框架录制命令和在途绘制可以继续持有像素，**替换当前帧不承诺旧载荷立即释放**。最后一个拥有者释放后内存确定性回收，不依赖 GC；`Weak` 可观察应用所提供 `Arc` 的最终释放，但不能由此推断 GPU 已扫描输出。需要在固定回调时刻归还外部缓冲区或零复制纹理导入的消费者，仍需另外设计并验收窄的同步/租约合同，不能滥用本接口。

## 字体集合与系统回退

TTC/OTC 的文件路径不足以标识一个字体：同一文件可含简中、繁中、日文、韩文等不同字体面。即使 Unicode 字符和 em advance 相同，默认地域字形也可能不同；不能用新旧截图相同或统一缩放来证明字形正确。

Linux 的系统默认字体、CJK 回退与显式字体族发现保留 fontconfig 返回的 **文件路径与面索引**，通过 `platform::services::SystemFontSource` 传到 FontService。排版与栅格化从完整集合文件加载同一索引，不截断集合数据，不强制使用第零面，也不擅自替换 fontconfig 的字体族/语言选择策略。

自定义 `FontSystemInfo` 可实现 `default_font_sources`、`probe_cjk_font_sources` 和 `probe_family_font_source`。仅提供路径的方法默认包装为第零面；集合感知的 Provider 不应只按路径去重。文本后端的 `load_font_index` 与 `load_font_mapped_index` 接收从零开始的面索引；普通 TTF/OTF 使用零。无效索引或后端不支持非零面时必须失败，由已有候选回退处理，不能静默加载另一张面。仅支持路径的平台适配器、变量字体命名实例及自动语言策略不因此获得额外承诺。
