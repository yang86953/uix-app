# 样式与主题

[← 返回使用索引](../../使用.md)

> **接口**：声明 UIX 样式系统与主题管理的公开用法——语义样式、细粒度样式链、色板体系、主题切换和自定义主题。依赖：[响应式基础](../入门/响应式基础.md)。导出：设计令牌架构 → [架构 · 绘制几何](../../架构/graphics/geometry.md)，主题与配置 → [架构 · 主题](../../架构/ui/theme.md)。

## 语义样式

业务代码优先选择 primary、success、warning、danger、muted 等语义值，而不是硬编码颜色。组件状态从主题的组件令牌派生，默认、hover、pressed、focus、disabled 与 error 必须保持可辨识。

```rust uix-compile=style-semantic
use uix_app::prelude::*;

label("主要文字").color(ColorValue::Neutral(NeutralRole::Text));
button("保存").primary();
button("危险").danger();
Tag::new("成功").color(TagColor::Success);
```

## 细粒度样式

尺寸、间距、边框、圆角、字体与背景可由 View 样式链覆盖。局部覆盖只作用于当前节点或显式子树 Provider，不反向修改全局主题。

动态 `<Text>{表达式}</Text>` 同样消费样式类中的 `lineHeight`、`textAlign`、`fontFamily`、`fontWeight` 与 `textDecoration`（语法见[样式属性](../../uix-lang/参考/样式属性.md)），也可由 Rust `ViewNode::map_style` 设置对应 `Style` 字段。背景和边框保留公共样式语义。显式行高用于测量与绘制；省略时静态与动态文本统一使用 1.5 倍最终字号。文本测量按窗口主题、子树主题和组件令牌覆盖取得字号；有限宽度内自动换行，内容更新后重新计算高度。窗口与后台 Agent 的布局作用域借用同一字体服务，固有宽度与绘制共享字体族、fallback 和 shaping，避免短文本在自己的自然宽度内误换行；仅无字体上下文时回退字符估算。需要单行展示的动态短标签可显式使用 `<Text ellipsis flexGrow={1} flexShrink={1}>{name}</Text>`：在父行分配的有限宽度内显示省略号，不挤占相邻计数；默认动态 Text 的正常折行行为不变。

```rust uix-compile=style-chain
use uix_app::prelude::*;

column((label("卡片"),))
    .bg(ColorValue::Neutral(NeutralRole::BgContainer))
    .border(1.0, ColorValue::Neutral(NeutralRole::BorderSecondary))
    .radius(8.0)
    .box_shadow(Some(
        BoxShadowDef::new(Color::from_rgba(0, 0, 0, 40), 8.0, 0.0, 2.0)
            .with_spread(1.0),
    ))
    .padding(16.0)
    .gap(8.0);
```

`BoxShadowDef::new(color, blur, offset_x, offset_y)` 保持零 spread；需要扩张或内缩阴影基准盒时追加 `.with_spread(value)`。正值向外扩张，负值向内收缩；内缩耗尽宽度或高度时不绘制阴影。UIX Lang 使用 `boxShadow: h-offset v-offset blur [spread] color` 的等价语法。

## 色板与设计令牌

主题拥有颜色、排版、间距、圆角、阴影、动效与组件默认值；graphics 只消费解析后的绘制值，不反向拥有 UI 语义令牌。令牌类型位于 `uix_app::ui::theme`（`Theme`、`DesignTokens`、`TokenPatch`、`ThemeTokens` trait 族），`draw` 层不暴露主题类型。

## ThemeToggle 主题切换按钮

```rust uix-compile=theme-toggle
use uix_app::prelude::*;

// 声明式切换按钮：ThemeToggle 内置亮色/暗色切换
embed(ThemeToggle::new().dark(is_dark));

// 应用级切换：AppHandle 设置全局主题
let handle = ...;
handle.set_theme(Theme::antd_dark());
```

`ThemeToggle` 切换亮色/暗色主题，实际主题状态由 Provider/应用配置持有。切换后重算受影响子树并请求必要帧，不由业务代码手工遍历组件。`AppHandle::set_theme(theme)` 是跨窗口广播的权威入口：仅色板变化只重绘使用语义色的节点；字号令牌变化同时请求布局，避免继续使用旧行盒。

## 自定义主题

自定义主题以完整基础主题加窄覆盖构建。项目测试只从公开主题 API 的外部消费者观察对比度、焦点可见性、禁用态和错误态，不测试主题内部实现。

```rust uix-compile=theme-custom
use uix_app::prelude::*;

// 组件令牌窄覆盖：在 ConfigProvider 子树内对 Button 调整主色与圆角
embed(ConfigProvider::new()
    .widget_tokens::<Button>(TokenPatch {
        color_primary: Some(Color::hex("#722ed1")),
        border_radius: Some(10.0),
        ..TokenPatch::default()
    })
    .child(|| button("紫色按钮").primary())
    .build());
```

保留语义令牌、子树继承、状态完整性和公开 API 测试边界。

## 推荐用法

```rust uix-compile=theme-custom-app
use uix_app::prelude::*;

// 自定义主题：从基色生成 DesignTokens，再注入 App
let theme = Theme::new(DesignTokens::from_primitives(ThemePrimitives {
    primary: Color::hex("#722ed1"),
    ..ThemePrimitives::antd_light()
}, false));

App::new()
    .theme(theme)
    .follow_system_theme(true)   // 系统明暗变化自动跟随
    .root(app_root)
    .run();

// 组件侧：颜色一律来自令牌，不写死
render => (&self, frame: Rect, ctx: &mut PaintContext) {
    ctx.fill_rect(frame, ctx.tokens().color_primary_bg(), None);
}
```

```rust uix-compile=theme-custom-seed
// 通过 PrimaryHue 声明式切换品牌色种子，主题自动生成色板。
App::new()
    .theme(Theme::custom(
        ThemePrimitives::antd_light().with_brand_primary(PrimaryHue::Purple),
    ))
    .follow_system_theme(true)
    .root(app_root)
    .run();
```

- 业务代码只写语义值，主题负责具体外观；换肤不修改业务组件。
- 自定义主题用窄覆盖构建，不整套复制。
- 主题切换后只重绘受影响的语义色节点，不做全量重绘。


## 字号、行盒与控件排版契约

`fontSize` 表示逻辑像素中的 **em 尺度**，不是字体 ascent−descent 的总高度，也不是每个字形的墨迹高度。字体后端依据各字体的 units-per-em 换算布局、度量和光栅比例；中西文回退字体共享 em 尺度，小数字号不再先取整再进入字形缓存。字形实际宽高仍由字体和字符决定。

静态 `Text`（Label）、动态 `Text`、Input/textarea 以及 RichText 基本文本的默认行盒统一为最终字号 × 1.5；未显式指定字号时使用当前主题字号。显式行高覆盖默认值，字体 ascent/descent 周围的剩余空间上下均分，以同一行盒基线绘制。相同字号和行高在相同居中行框中对齐；不同字号的 `align="center"` 只保证盒子中心一致，不承诺共享 alphabetic baseline。若要精确混排，需显式安排共同基线，不能把矩形居中误当作基线布局。

- 文字样式应声明在实际的 `Text`、`Input` 或 `RichText` 节点上；普通父 Container 的 `fontSize` 不等于 CSS 自动继承。子树统一使用显式主题 Provider。
- Input/textarea 的字号、行高、字体族、文字色和非零 padding 声明进入控件内核；同一行盒用于测量、绘制、滚动、光标和选择命中。单行控件在给定高度内居中，textarea 从内容框顶部开始逐逻辑行布局；textarea 仍按显式换行分行，不因此增加自动折行功能。字号大于原控件高度时，应增加高度，不能依赖裁剪得到缩小字体。
- Input 无 padding 覆盖时使用水平 12px、垂直 6px。当前 Style 的零 padding 与未声明共用默认表示，因此全零值不能作为清除 Input 默认内边距的独立指令；非零覆盖可用。14px 默认 Input 的内容最小高度为 21 + 12 = 33px，较旧 medium 固定 32px 有变化。
- RichText 接收自身的字体族、字号、行高、文字色、padding 和布局宽高；保留既有默认 flex grow = 1。需要内容固有高度时显式设 `flexGrow={0}`，并结合父容器的拉伸规则。不同字号的行内段共用该行的基线；行高倍率按段字号参与混排行高，显式 px 行高在 RichText 中换算为基准字号倍率后作用于各段，不承诺把更大标题强压到同一固定行高。段落全局 `fontWeight` / `textAlign` 不在这次适配承诺内，已有富文本段样式仍独立生效。

这是可观察的排版兼容变更：同一数值通常比旧的 ab_glyph 高度口径显示更大，并可能改变换行、滚动或固定尺寸裁剪。消费应用应按实际窗口检查中英文、多字号、输入、标题切换和长文档，不能用整体放大/缩小字号替代适配。框架主线已采用此口径；仍使用旧 Agent 接口的应用可单独采用 `fix/typography-f65-20260908` 兼容修复，不因此获得或迁移新的 Agent 根接口。


### Text 的布局约束与裁剪

静态 `<Text>字面量</Text>` 与动态 `<Text>{表达式}</Text>` 均在父布局最终分配的内容宽度内折行，并按同一字体、字号与行高重新测量高度。嵌套 Column 无须为每层重复指定宽度；Row 的兄弟项占用空间后按最终槽位宽度重测交叉轴高度。请求宽度不能绕过父级的有限测量上限。

文本字形、选区与装饰的绘制限制在扣除 padding 后的内容框内；零内容尺寸不绘制。固定高度不足时裁剪超出部分，不缩小字号；需要完整显示时应允许自动高度或提供滚动容器。此规则不把全部容器改为 `overflow: hidden`，显式滚动、阴影及浮层仍保留各自边界。

`Label` / `label("…")` 保留既有不自动折行用途；Rust 可用 `Label::new("…").word_wrap(true)` 启用折行。单行需要省略号时使用 `<Text ellipsis>…</Text>` 或 `elided_label`，语义文本仍保存完整原文。

编译器的文档示例回归从权威工作区读取：`UIX_DOCS_ROOT=docs cargo test --locked -p uix-app-lang-compiler`。该入口不向源码目录复制文档。

### 字体集合与系统回退

TTC/OTC 的文件路径不足以标识一个字体：同一文件可含简中、繁中、日文、韩文等不同字体面。即使 Unicode 字符和 em advance 相同，默认地域字形也可能不同；不能用新旧截图相同或统一缩放来证明字形正确。

Linux 的系统默认字体、CJK 回退与显式字体族发现保留 fontconfig 返回的 **文件路径与面索引**，通过 `platform::services::SystemFontSource` 传到 FontService。排版与栅格化从完整集合文件加载同一索引，不截断集合数据，不强制使用第零面，也不擅自替换 fontconfig 的字体族/语言选择策略。

自定义 `FontSystemInfo` 可实现 `default_font_sources`、`probe_cjk_font_sources` 和 `probe_family_font_source`。旧的路径方法仍兼容，默认包装为第零面；集合感知的 Provider 不应只按路径去重。文本后端的 `load_font_index` 与 `load_font_mapped_index` 接收从零开始的面索引；普通 TTF/OTF 使用零。无效索引或后端不支持非零面时必须失败，由已有候选回退处理，不能静默加载另一张面。仅支持路径的平台适配器、变量字体命名实例及自动语言策略不因此获得额外承诺。
