# UIX 文档中心

[← 返回项目首页](../README.md)

UIX 是一个 Rust 原生跨平台应用框架：让同一套界面与应用逻辑运行在多个平台的原生窗口上。本目录是项目文档的统一入口，正式文档分为产品、UIX Lang、使用与架构四部分；先按要解决的问题选择入口，不必按目录顺序通读。UIX Lang 只负责界面描述，当前应用业务与生命周期由 Rust 持有；目标中的[标准 Lisp 动态扩展](架构/app/extensions.md)可承载扩展业务与界面，尚未实现。带时点的进度、任务、负责人、阻塞与公开 API 测试结果以 [仓库状态账目](../TODO.md) 及其子 Issue 为唯一事实源，仓库内不复制动态进度。

## 文档边界与事实来源

- 同一事实只在一处持有；其他部分保留必要摘要和相对链接。
- 带时点的进度状态、任务、负责人、阻塞和公开 API 测试结果只由 Gitea Issue 持有；仓库内不复制带时点的状态。
- 产品文档声明定位、产品范围和交付边界，不以“产品范围内”暗示“当前所有平台均已交付”。
- UIX Lang 规范持有语言规则；使用文档只写当前公开、可验证的调用行为；架构文档写内部边界和必须保持的不变量。
- 变更记录只登记版本内已经发生、对使用方或交付有影响的变化，不承担任务看板职责。
- 目标设计领先实现时，正文必须显式标为“目标”或“迁移中”，并把动态差距路由到 Gitea。

## 状态用语

| 用语 | 含义 | 可以据此假定什么 |
|---|---|---|
| 已支持 / 已实现 | 当前公开行为已经存在，且正文应给出可验证入口或契约 | 可以按文档使用，但仍受平台、feature 与版本限制 |
| 产品范围 / 目标 | UIX 选择承担的长期能力或已批准设计 | 不代表当前版本已经交付 |
| 迁移中 | 新旧边界尚未完全收敛 | 只能依赖正文明确列出的当前公开行为 |
| 暂缓 | 属于产品方向，但当前没有交付承诺 | 不应据此安排当前版本接入 |
| 不做 | 明确排除在产品边界外 | 应选择外部能力或由应用自行实现 |

凡是无法从产品说明、现有契约或可访问事实源确认的信息，都应标为“待确认”，不得改写成确定事实。Gitea 与内部知识库链接可能需要授权网络或本机知识库；仓库文档必须保留足够摘要，使读者在暂时无法访问外部来源时仍能理解当前边界。

## 维护约定

1. 先更新持有事实的正文，再更新对应索引中的摘要。
2. 项目文档使用仓库相对 Markdown 链接，不保留 Obsidian Frontmatter、Wiki 链接或生成式目录索引。
3. 新增或修改使用说明时，至少说明前置条件、执行步骤、预期结果、可见失败和适用限制；涉及本地文件、权限、Agent 或外部进程时补充安全边界。
4. 示例必须区分 UIX Lang、Rust、命令行和伪代码；未落地的设计不得放进可复制示例。
5. 文档改动只复核受影响的链接、锚点与公开示例；文档结构、源码路径和覆盖清单不建立项目测试。
6. 公开示例变化时，只运行对应的外部消费者 `*_public_api.rs`；纯文字或导航改动不运行测试。
7. 进度变更只更新 Gitea Issue；提交说明记录变更范围、公开 API 测试结果和仍待确认的事实。
