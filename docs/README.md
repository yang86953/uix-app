# UIX 文档中心

当前代码由 `uix-app`（机制、原生平台、语言与工具）和独立 `uix-widgets`（具体控件、主题与资源）组成。见 [两包迁移](使用/两包迁移.md)。历史目录说明中的具体控件职责已迁至组件库。

> 现行产品文档随开源仓库维护；当前公开发行是 0.0.8。用法示例采用 `uix-app` / `uix_app`。目标设计和[样式完善计划](产品/样式系统完善计划.md)不代表已包含在 0.0.8 中。


[← 返回项目首页](../README.md)

UIX 是一个 Rust 原生跨平台应用框架：让同一套界面与应用逻辑运行在多个平台的原生窗口上。本目录是项目文档的统一入口，正式文档分为产品、UIX Lang、使用与架构四部分；先按要解决的问题选择入口，不必按目录顺序通读。旧 UI 描述只负责界面；[可移植应用模块](uix-lang/规范/应用模块.md)是显式 AOT/动态补充路线，宿主领域真值、授权与生命周期仍由 Rust 持有；[标准 Lisp 动态扩展](架构/app/extensions.md)（Scheme R7RS-small 受限宿主环境，Cargo feature `extensions`）可在运行中装载扩展业务与界面。仓库内不维护带时点的动态进度账目：完成度以实际代码和各文档事实所有者为准，用户可观察的版本变化见 [公开 Release](https://github.com/yang86953/uix-app/releases)。

## 文档边界与事实来源

- 同一事实只在一处持有；其他部分保留必要摘要和相对链接。
- 长期文档在本公开仓库维护，不复制内部任务看板；任务、负责人、阻塞和测试验收结果统一维护在内部项目管理记录。历史 Gitea 记录只证明对应时点，不替代当前任务和运行证据。
- 产品文档声明定位、产品范围和交付边界，不以“产品范围内”暗示“当前所有平台均已交付”。
- UIX Lang 规范持有语言规则；使用文档只写当前公开、可验证的调用行为；架构文档写内部边界和必须保持的不变量。
- 变更记录只登记版本内已经发生、对使用方或交付有影响的变化，不承担任务看板职责。
- 目标设计领先实现时，正文必须显式标为“目标”或“迁移中”，并写明当前已交付部分。

## 状态用语

| 用语 | 含义 | 可以据此假定什么 |
|---|---|---|
| 已支持 / 已实现 | 当前公开行为已经存在，且正文应给出可验证入口或契约 | 可以按文档使用，但仍受平台、feature 与版本限制 |
| 产品范围 / 目标 | UIX 选择承担的长期能力或已批准设计 | 不代表当前版本已经交付 |
| 迁移中 | 新旧边界尚未完全收敛 | 只能依赖正文明确列出的当前公开行为 |
| 暂缓 | 属于产品方向，但当前没有交付承诺 | 不应据此安排当前版本接入 |
| 不做 | 明确排除在产品边界外 | 应选择外部能力或由应用自行实现 |

凡是无法从产品说明、现有契约或可访问事实源确认的信息，都应标为“待确认”，不得改写成确定事实。外部架构规范未随本仓库发布；采用摘要和本项目的具体边界在本仓库内说明。

## 维护约定

1. 先更新持有事实的正文，再更新对应索引中的摘要。
2. 项目文档使用仓库相对 Markdown 链接，不保留 Obsidian Frontmatter、Wiki 链接或生成式目录索引。
3. 使用说明以读者能完成任务为准，按内容需要说明前置条件、用法、结果与限制；涉及权限或外部操作时说明实际安全边界。
4. 示例必须区分 UIX Lang、Rust、命令行和伪代码；未落地的设计不得放进可复制示例。
5. 纯文字或导航改动复核内容、链接与锚点；公开示例变化按[公开 API 测试契约](架构/使用方按需编译.md#公开-api-测试契约)验证。
