# UIX 文档中心

[← 项目首页](../README.md)

本目录是 UIX 项目文档的唯一当前位置。文档按事实责任分为产品、使用、架构与进度四类；先选择要回答的问题，再进入对应索引。

## 四类文档

| 角色 | 回答的问题 | 权威范围 | 入口 |
|---|---|---|---|
| 产品 | 为谁解决什么问题，价值与边界是什么 | 定位、目标用户、能力范围、产品约束、许可与验收语义 | [产品](产品.md) |

## 文档边界

- 同一事实只由一个角色持有；其他角色保留必要摘要和相对链接。
- 产品写目标契约，使用只写当前可验证的公开行为，架构写内部机制，进度写带时点的状态和证据。
- 目标设计领先实现时，架构声明目标与当前映射，差距由进度文档持有。
- `test-reports/` 是本地证据产物；残留文件不能替代与 clean commit 绑定的结论。

通用 System / Module / Component 定义以仓库内[通用 SMC 文档](System%20Module%20Component%20设计模式.md)为唯一权威；本项目只维护[系统列表](架构/系统列表.md)和[路由清单](架构/路由清单.md)。

## 维护约定

1. 先更新持有事实的正文，再更新对应索引中的摘要。
2. 当前状态使用 `✅ 已完成`、`🔄 进行中`、`⏳ 待开始`、`📋 规划中`；`blocked`、`fail`、`UNVERIFIED` 不得改写为通过。
3. 项目文档使用仓库相对 Markdown 链接，不保留 Obsidian Frontmatter、Wiki 链接或生成式目录索引。
4. 文档改动后运行：

   ```powershell
   python scripts/check_docs_links.py
   python tests/test_check_docs_links.py -q
   ```
