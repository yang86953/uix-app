# 框架能力拆分

`uix-app` 保持一个 Cargo package，组件库仍为独立的 `uix-widgets`。
框架内部按实际依赖提供编译能力；旧 `runtime` 总开关已删除。

| 能力 | 职责 | 直接依赖的框架能力 |
| --- | --- | --- |
| `core` | 几何、身份、错误与损伤区域值 | 无 |
| `reactive` | State、Computed、Effect、订阅与租约 | core |
| `layout` | Flex/Grid 求解、盒模型 | core |
| `diagnostics` | 诊断报告、恢复登记 | core |
| `data` | 配置持久化 | core |
| `platform-contracts` | 输入、系统服务、窗口和图形协议值 | core |
| `graphics` | CPU 绘制、绘制命令、文本排版、字体与图像资源、场景合成 | core、diagnostics、platform-contracts |
| `graphics-gpu` | 通用 GPU 渲染、帧计划与 RHI 转换 | graphics |
| `ui` | View 树、协调、事件、样式、动画与绘制桥接 | reactive、layout、graphics、platform-contracts |
| `platform` | OS 窗口、输入法、剪贴板和系统服务实现 | platform-contracts、diagnostics |
| `application` | 窗口应用、生命周期与事件循环组装 | ui、platform、data |

`platform-contracts` 只提供协议与共享值，不编译 OS 适配器。
`graphics` 包含文本能力；当前不承诺把字体与绘制命令再分别裁剪。
`vulkan`、`opengles`、`d3d11`、`d3d12`、`metal` 选择对应适配器，并依赖
`platform` 和 `graphics-gpu`。它们不隐式选择窗口应用或 UI 树。

`lang-build` 提供构建期编译器，`lang-tools` 加入严格构建、CLI 和 LSP。
`uix-modules` 提供独立的可移植模块执行；`uix-dynamic` 增加源码装载和编译器。
`extensions` 提供独立脚本引擎，仅依赖 core 与数值运算库。
`test-harness` 依赖 ui，可在没有原生平台的构建中测试布局与交互。
`agent-control` 和 `hot-reload` 属于 application 的可选开发能力。

## 使用

普通 Cargo 开发选择能力时关闭默认功能。例如仅使用状态：

```toml
uix-app = { path = "../uix-app", default-features = false, features = ["reactive"] }
```

```rust
use uix_app::ui::State;
let count = State::new(0);
count.update(|value| *value += 1);
```

`application` 是完整应用组装能力；默认功能额外提供 Windows/Linux 图形后端和图像解码。
手动关闭默认功能的原生应用须选择所需图形后端。

正式交付通过 `uix build --release`，配置中的能力名与 Cargo feature 对应：

```json
{
  "packages": [{"path": "../uix-app"}],
  "rust": ["uix-app/reactive"]
}
```

框架自身的 `uix-library.json` 声明能力闭包，由同一个构建器处理。
`<App>` 源文件自动要求 application；View 源文件不会仅因使用控件就要求窗口应用。
Rust 中的 `App` 调用和 `with_widgets()` 分别显式声明 `uix-app/application`、
`uix-widgets/application`，组件库负责声明，框架负责选择和裁剪。

## 边界与验证

响应式状态只调用自身拥有的 `InvalidationTarget` 通知契约。
UI 层把这个契约接到已有渲染失效队列，保持订阅身份和释放时机；状态模块不引用渲染器。
UI 树的 `ScenePaint` 实现由 UI 协调层拥有，不再依靠窗口应用启用它。
绘制层接受中立图形合同，具体 OS 实现只随 platform 和所选后端编译。

可运行示例：

```sh
cargo run --no-default-features --features reactive --example reactive
cargo run --no-default-features --features layout --example layout
cargo run --no-default-features --features graphics --example offscreen
cargo run --no-default-features --features test-harness --example headless_ui
```

验收同时检查公开行为、目标 `rustc` 的 `.d` 源码输入、实际依赖和交付资源。
状态与布局的生产目标不编译第三方库；CPU 绘制不编译 UI、原生适配器或 GPU 渲染实现；
无窗口 UI 不编译应用层或原生适配器。这些是能力边界，不能用最终二进制变小代替验证。
