# 原生平台层

[← 返回架构 索引](../架构.md)

> 分类：原生平台层
> 权威范围：平台能力公开面、硬件发现、线程边界与内部实现归属

## 角色

`crate::native` 是 OS、窗口和图形平台实现，不是公开命名空间。公开消费面是 `uix::platform`，只回答两类问题：

- 当前系统有什么：OS、CPU、内存、显示器，以及指定图形 API 能枚举到的 GPU adapter。
- 当前平台能独立执行什么：查询 OS-known directory 和发送系统通知。

应用生命周期、渲染策略、CPU fallback、device-lost 恢复、帧调度和 backend 扩展 SPI 均不属于该公开面。

```text
uix::platform
├── Platform    # 线程亲和的具体能力入口
├── services    # special directory、system notification
├── hardware    # OS / CPU / memory / display 值
└── graphics    # GraphicsBackend、GpuAdapterInfo、GpuDeviceType
```

`Platform` 是字段私有、不可由调用方实现的具体类型。唯一公开入口是 `Platform::new() -> Result<Platform>`。跨平台调用方必须在进程主线程创建它；每个进程同一时刻最多存在一个实例，销毁后可以重新创建。错误线程、Windows 已进入不兼容 COM apartment 或已有存活实例都返回 `Errc::InvalidState`。

构造是事务性的：任一步失败都按逆序释放已经初始化的 provider / FFI 资源并清除实例占用，再返回原始 typed 错误。成功后该线程固定为 owner thread。`Platform` 无 `Default`、`Clone` 或全局访问器，明确 `!Send + !Sync`；`Drop` 因而只能在 owner thread 执行，完成资源撤销但不派发事件或调用用户代码。`Platform::new()` 不采集硬件，也不加载 GPU driver。

## 复用约束

公开面优先直接修正并复用仓库已有抽象，不建立平行体系：

| 语义 | 唯一类型或机制 |
|---|---|
| 成功与失败 | `crate::core::{Result, Error, Errc}`；缺少可分支错误时扩充 `Errc`，不增加 `PlatformError` / `PlatformResult` |
| 坐标与边界 | `crate::core::Rect` |
| 系统值 | 现有 `OsInfo`、`MemoryInfo`、`DisplayInfo` 原位修正，不保留新旧 DTO 双轨 |
| 图形 API | 现有 `GraphicsBackend` 原位收口为唯一实际 API 枚举 |
| 平台实现 | 复用现有 Windows / Wayland / macOS provider、factory 探测和 FFI 资源管理；全部保持 crate-private |

以下抽象不进入目标 API：

- `PlatformHandle`、request / cancellation / subscription、completion queue、异步完成 callback 或 `Future`
- 通用 capability 枚举、capability registry 或预检查 snapshot
- `HardwareValue<T>`、`HardwareQuery`、缓存 generation
- GPU / display identity、generation 与 stale-id 协议
- `GraphicsOptions`、power / adapter preference、fallback policy、逐窗 graphics runtime 状态

能力方法直接返回 typed `Result`，避免 capability 预检查与真实操作之间的 TOCTOU。各硬件查询独立失败，可选元数据使用 `Option<T>`。

公开信息 struct 使用私有字段和只读 getter，不提供无意义的 builder；调用方构造的 options 使用私有字段和校验过的 constructor / builder。可扩展的分类 enum 使用 `#[non_exhaustive]`。不可获得的元数据使用 `None`，不以空字符串、`0` 或虚构的 “unknown” 文本代替。

## 执行与生命周期

- 所有 `Platform` 方法同步执行，并且只能在 owner thread 调用。公开层不自建 executor、工作线程、任务队列或缓存。
- GPU 枚举可能加载 driver 并阻塞；调用时机与调度属于调用者策略，不进入 platform API。
- 返回的所有信息值都实现 `Clone + Send + Sync`；它们不持有原生对象或 driver lease。公开 API 测试使用静态断言锁定该契约。
- 不提供全局 `current()`，不允许从任意线程取得或复制 `Platform`。

平台失败继续使用既有错误码：

| 情况 | `Errc` |
|---|---|
| feature 未编译或该 OS 不支持 | `NotImplemented` |
| 权限被拒绝 | `PermissionDenied` |
| OS / driver 调用失败 | `PlatformError` 或现有 graphics 错误码 |

## 平台服务

服务是 `Platform` 的具体同步方法，不公开 `IFileSystem`、`INotification` 等可实现 trait，也不返回 service locator：

| 能力 | 公开语义 |
|---|---|
| Special directories | 复用并收紧 `SpecialDir`，返回 `Result<PathBuf>`；非 UTF-8 路径不经 `String` 损失 |
| System notification | 使用独立的 `SystemNotification` options，返回 `Result<()>`；unsupported 不冒充成功 |

核心方法固定为：

```text
Platform::special_dir(&self, directory: SpecialDir) -> Result<PathBuf>
Platform::show_notification(
    &mut self,
    notification: SystemNotification,
) -> Result<()>
```

Timer 复用调用方已有调度设施，console 复用日志 / `std::io`，普通文件读取复用 `std::fs`；这些不再由 platform 复制一套服务。`ControlSize`、`ScrollDirection`、`StatusLevel`、toast 和文件便利封装也不是平台能力。

`SpecialDir` 只保留 `Home`、`AppData`、`LocalAppData`、`Documents`、`Desktop`、`Downloads` 等 OS-known user folders，并使用 `#[non_exhaustive]`。`Temp`、`Current`、`Executable` 分别直接使用 `std::env::temp_dir`、`current_dir`、`current_exe`，不在 platform 重复包装。

剪贴板和原生文件对话框依赖 seat、窗口或受信任输入 activation，不能由独立 `Platform` 闭环完成，因此不进入目标公开面。现有实现保持 crate-private；等其窗口 / 输入生命周期拥有独立的公开契约时再整体设计，不预埋 token、callback 或 request 类型。

## 系统硬件

```text
Platform::os_info(&self) -> Result<OsInfo>
Platform::cpu_info(&self) -> Result<CpuInfo>
Platform::memory_info(&self) -> Result<MemoryInfo>
Platform::displays(&self) -> Result<Box<[DisplayInfo]>>
```

- `OsInfo`：非空系统名称，以及可选的版本与 build；不默认采集用户名、主机名、序列号等身份信息。
- `CpuInfo`：非空架构名、`NonZeroUsize` 逻辑核数，以及可选的 vendor / model；无法得到核数时整项返回 `Err`。
- `MemoryInfo`：`u64` 字节数的系统物理总量与当前可用量，保证 `total_bytes > 0` 且 `available_bytes <= total_bytes`。进程 working set / private bytes 属于诊断，不进入平台硬件 API。
- `DisplayInfo`：logical bounds、有限且大于零的 scale、是否主显示器，以及可选的名称与 `u32` millihertz 刷新率。多显示器坐标允许为负；没有消费 ID 的公开操作，因此不虚构 `DisplayId`。

每个方法只即时采集所请求的类别，不建立 snapshot、缓存、刷新、generation 或订阅。空显示器数组是成功的空结果；失败必须是 `Err(Error)`，不能用空字符串、`0` 或固定容量兜底。调用方需要采集时间时直接使用 `SystemTime`，platform 不再包装 timestamp。

不定义万能 `HardwareDevice`、统一 `open_device()` 或设备基类。音频、摄像头、存储和网络设备具有不同的权限、热插拔与资源生命周期；出现真实消费契约时分别增加 typed domain，而不是塞入一个总枚举。

## GPU 与图形 API

GPU 单独按具体 API 显式枚举：

```text
Platform::gpu_adapters(
    &self,
    backend: GraphicsBackend,
) -> Result<Box<[GpuAdapterInfo]>>
```

- `GraphicsBackend` 只含 `Vulkan`、`Direct3D12`、`Metal`、`OpenGlEs`；`Auto` 不是实际 API，D3D11 不是生产 backend。
- `GpuAdapterInfo` 是 owned 描述值：名称、vendor ID、device ID 与 driver 均为 `Option<T>`；backend 和设备类型始终存在。空 driver 字符串与 `0` vendor / device ID 规范化为 `None`。
- `GpuDeviceType` 区分 integrated、discrete、virtual、software 与 unknown；它和 `GraphicsBackend` 都是 `#[non_exhaustive]` 枚举。
- 同一物理 GPU 经不同 API 枚举时是不同 adapter，不猜测跨 API 永久身份。
- `GpuAdapterInfo` 不是稳定 ID，也不能传回 platform 打开设备；没有真实消费操作前不发布 handle / lease。
- platform 只报告 adapter，不定义 auto、偏好排序或 fallback 等选择策略。

不公开显存大小、预算或可用量：离散显存、UMA 共享内存和 Metal working set 没有统一语义。也不公开 `wgpu::AdapterInfo`、`wgpu::Limits`、feature bitset、总线结构或厂商 API struct；没有明确消费契约前，不把 `wgpu` 能力表复制成 UIX 自有全集。

结果顺序不稳定，调用方不得依赖“第一个”。成功但没有 adapter 时返回 `Ok([])`；backend 未编译、当前 OS 不适用或无法脱离 surface 真实枚举时返回 `NotImplemented`；driver 枚举失败返回 `Err`。单项缺失元数据使用 `Option`，但已经报告的 adapter 无法安全转换时整次查询失败，不能静默漏项。枚举信息不代表任意 surface 可用；device / surface 创建、presentation 和恢复仍是 crate-private 实现事实，CPU renderer fallback 与逐窗运行态不属于 platform API。

## 运行保障接入

公开平台查询和内部 native runtime 使用不同的最终责任边界：

- `uix::platform::Platform` 的公开方法直接返回 typed `Result`。框架不提前写 ErrorReport，也不替调用方触发恢复；用户可在自己的责任边界使用共享 [`Diagnostics`](运行保障.md)。
- App 内部的 `crate::native` 由 AppRuntime 显式注入同一 Diagnostics 句柄。不能使用全局 singleton，也不能让 backend 自建一套 logger、recovery registry 或 report store。
- Win32、ObjC、Wayland 和 GPU callback 只向统一的有界 pending queue 投递 owned typed failure；owner thread drain 后才执行领域恢复、用户/框架登记的恢复、向上返回或最终报告。
- owner 仍能返回 Error 时继续返回；只有 event-loop、detached worker、Drop 等已无返回路径的最后责任点才 `report_with_origin` 一次。

平台内部 origin 使用固定静态 schema：

| 来源 | `origin.target` | operation 示例 | resource |
|---|---|---|---|
| Windows callback | `uix::native::windows` | `wnd_proc.dispatch`、`dpi.apply` | `window` + opaque id |
| Wayland callback | `uix::native::wayland` | `event_loop.dispatch`、`clipboard.pipe` | `display` / `seat` + opaque id |
| macOS callback | `uix::native::macos` | `window_delegate.dispatch`、`display_link.tick` | `window` + opaque id |
| 图形 callback | `uix::native::graphics` | `device_lost`、`uncaptured_error` | `device` + opaque id |

Opaque id 只用于同一进程报告关联，不是公开设备身份。Origin 不保存剪贴板、IME 文本、窗口标题、文件内容或完整路径。

图形 device-lost 的 owner 顺序固定为：保留 driver reason → `ensure_active` 观察 → 图形领域恢复 → 共享 recovery registry → 若可返回则 typed Error → 无返回路径才 ErrorReport。不能在 driver callback 直接执行 subscriber 或用户逻辑。

## 内部边界

```text
foundation: Error / Result / Errc / Rect
                     ↓
uix::platform: owned values + thread-affine Platform
                     ↓
crate::native
├── OS event / input normalization
├── clipboard / dialogs / paths / system notification
├── hardware and adapter providers
├── native window / device / surface ownership
└── factory / registry / FFI / teardown
```

- `crate::native` 不依赖 `app`、`ui` 或 `draw`。
- raster command、shader、glyph atlas、blur、renderer policy 与 recovery driver 不归 native。
- backend registry、recipe、presenter、graphics context、raw window / display / surface handle 和所有实现 trait 均为 crate-private。
- 旧公开路径在实现目标面时直接删除；不提供 deprecated alias、兼容重导出或双轨 DTO。

当前实现差距见[进度 · 原生平台层](../进度/原生平台层.md)和[进度 · 运行保障](../进度/运行保障.md)。
