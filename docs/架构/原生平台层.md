# 原生平台层

[← 返回架构 索引](../架构.md)

> 分类：原生平台层
> 权威范围：平台能力公开门面、硬件发现、线程模型与内部实现边界

## 角色

`crate::native` 是框架内部实现层，不再作为消费命名空间。应用公开面命名为 `uix::platform`：它是供应用消费的跨平台能力门面，不是第三方 backend 实现 SDK。应用可以查询平台与硬件、请求受支持的原生服务，并观察当前窗口的图形运行时；不能取得事件循环、backend registry、presenter、graphics context、raw window / surface 或 GPU 原生对象的所有权。

公开面保持为：

```text
uix::platform
├── PlatformHandle / PlatformRequest / PlatformCancellation / PlatformSubscription
├── capability  # 能力与可用状态
├── input       # 跨平台输入值
├── services    # 剪贴板、文件对话框、系统通知、路径
├── hardware    # OS、CPU、内存、显示器、GPU adapter 快照
└── graphics    # backend 选择与当前图形运行时快照
```

`AppHandle::platform()` 返回带有当前 App 和窗口上下文的 `PlatformHandle`。创建窗口仍走 `AppHandle::open_window` / `WindowConfig`；绘制仍只走 `PaintContext` 和框架托管的 `Renderer`。

`uix::platform` 根只重导出 handle、request / cancellation / subscription 与 error / result；能力、输入、服务、硬件和图形值类型从对应子模块导入，避免把所有平台类型灌入根或 prelude。

## 能力与执行模型

- `PlatformHandle` 是轻量、`Clone + Send + Sync` 的运行时代理，通过弱引用绑定所属 App，并携带来源 `WindowId`；不提供全局 `current()`。hardware、paths 等 App 作用域能力可持续到整个 App shutdown；dialogs、cursor、逐窗 graphics 等窗口作用域能力在来源窗口关闭后返回 typed `Closed`。
- `PlatformCapabilities` 按 `PlatformCapability` 返回 `CapabilityStatus`。状态区分 `Available`、`Unavailable`、`PermissionRequired` 与 `NotReady`，不得用空字符串、空数组或 `false` 混淆失败。
- 已缓存的只读快照可同步读取，且值对象是 `Clone + Send + Sync`；快照带单调递增 `generation` 与采集时间，不伪装成永远实时。
- 会阻塞、弹出原生 UI、访问权限或可能加载驱动的操作返回 `#[must_use] PlatformRequest<T>`。request 在 `on_complete` 激活前不执行；未激活即丢弃时没有副作用。激活后，请求排入正确的 UI 线程或有界后台工作，主循环线程不执行无界阻塞探测。
- `on_complete` 消费 request，并返回 `PlatformResult<PlatformCancellation>`。若请求作用域在受理前已关闭，调用立即返回 typed `Closed(scope)` 且不注册回调；受理成功后，终态回调通过独立于任何 `WindowSession` 的 App completion queue 恰好投递一次、永不内联。App shutdown 先停止受理，再把已受理请求终止并排空终态回调，最后才关闭 completion queue。
- 受理后的取消原因区分 `Requested`、`WindowClosed`、`AppShutdown` 与 `Superseded`；完成与取消竞争时只有一个终态获胜。丢弃 `PlatformCancellation` 不会隐式取消，显式 `cancel()` 幂等且为 best-effort。用户取消文件对话框属于正常的 `DialogOutcome::Cancelled`，不冒充请求取消或 IO 失败。v1 只承诺 callback 模型；若未来增加 `Future`，须另行定义首次 poll、drop-cancel 与 completion queue 语义后再公开。
- `PlatformError` 使用 `#[non_exhaustive] PlatformErrorKind` 区分 unsupported、permission denied、not ready、closed、cancelled、IO 与 backend failure，并保留可选 source；`Closed` 只表示受理前作用域已关闭，已受理请求因关闭终止使用 `Cancelled(WindowClosed | AppShutdown)`，调用方不解析错误字符串。

## 平台服务

公开服务使用具体 handle，不公开由调用方实现的 OS trait。作用域决定关闭语义：

| 服务 | 作用域 | 公开语义 |
|---|---|---|
| Capabilities / hardware | App | 读取缓存或显式刷新；来源窗口关闭不使其失效，App shutdown 后关闭 |
| Clipboard | App + activation | `read_text -> PlatformRequest<Option<String>>`；write 使用拥有所有权的 request；需要 compositor serial 的平台必须消费有效 user activation |
| File dialogs | Window | 参数使用拥有所有权的 options、`PathBuf`、typed filter 与可选 user activation；结果显式区分 selected / cancelled / failed |
| System notification | App | 与 UI 内的 Message / Notification 分名；返回请求结果与可选 receipt，不把 unsupported 当成功 |
| Paths | App | 特殊目录返回 `PlatformResult<PathBuf>`；非 UTF-8 路径不经 `String` 损失 |
| Cursor / window service | Window | 只作用于 `PlatformHandle` 的来源窗口；不接受 raw native handle |
| Graphics runtime | Window | 返回当前缓存快照；generation 变化时可订阅通知，不允许每帧重新探测 |

`UserActivationToken` 是由受信任键盘 / 指针事件派发产生的 opaque、短期、窗口作用域能力，不暴露 Wayland serial 等平台值。服务 options 可以携带该 token；平台要求激活而 token 缺失、过期或窗口不匹配时返回 `NotReady(UserActivationRequired)`，不得伪造 serial、静默成功或退化为不安全的全局操作。

Timer、帧机会、IME 会话、原始键盘状态和事件循环属于框架托管机制，不作为普通平台服务公开。`ControlSize` 与 `ScrollDirection` 属于 UI 设计/布局语义，也不由 `platform::input` 所有。

## 硬件快照

`HardwareSnapshot` 是一次尽力保持一致、允许部分成功的采集结果。每一类数据使用 `HardwareValue<T>` 表达 `Available(T)`、`Unavailable(reason)` 或 `Failed(error)`，禁止用空字符串、`0`、空数组或固定兜底容量冒充成功：

- `OsInfo`：系统名称、版本、build 与架构；不默认包含用户名、主机名等身份信息。
- `CpuInfo`：架构、逻辑核数及可获得时的 vendor / model。
- `SystemMemoryInfo`：`u64` 物理总量与当前可用量；`ProcessMemoryInfo` 独立表达进程 working set / private bytes，不使用随目标位宽变化的 `usize`。
- `DisplayInfo`：opaque `DisplayId`、logical bounds、scale、主显示器，以及可获得时的名称、刷新率、色彩 / HDR 摘要。
- `GpuAdapterInfo`：snapshot 作用域的 `GpuAdapterId`、名称、设备类别、backend、vendor / device ID、driver、可选总线标识、可选显存和稳定的 `GpuLimits` / `GpuFeature` 摘要。

GPU adapter 是“某图形 API 看到的 adapter”，同一物理 GPU 可能分别以 Vulkan、D3D12 或 Metal adapter 出现；公开层不做无法证明的跨 API 永久身份合并。`GpuAdapterId` 只在当前进程和对应 snapshot generation 内有效。

基础 OS / CPU / 内存 / 显示器快照在平台初始化后缓存。GPU 枚举可能加载驱动，必须由 `HardwareQuery` 显式请求并缓存；刷新生成新 generation，不在每帧或普通窗口创建时重复枚举。

不定义万能 `HardwareDevice` 枚举或统一 `open_device()`。GPU adapter 是图形域的发现结果；以后加入音频、摄像头、存储或网络设备时，按各自权限、热插拔和资源生命周期建立独立 descriptor / service，避免把不相干契约塞进一个总接口。

## 图形选择与运行时

实际 API 与选择策略分开：

- `GraphicsBackend` 只表示实际 backend：`Vulkan`、`Direct3D12`、`Metal`、`OpenGlEs`。`Auto` 不是设备，归 `GraphicsOptions` 的选择策略；只用于 legacy test backend 的 D3D11 不进入生产枚举。
- `GraphicsOptions` 组合 `GraphicsSelection`、`PowerPreference`、`AdapterPreference` 与 `GraphicsFallbackPolicy`。`GraphicsSelection::auto()` 可附带有序 preferred backends；`require_backend(backend)` 禁止静默换成另一 GPU API；`require_adapter(GpuAdapterRef)` 同时锁定 snapshot generation、adapter 与其 backend，不再重复指定 backend。preferred backends 只存在于 auto selection；`GraphicsOptionsBuilder::build()` 拒绝 exact adapter 与 adapter preference 等冲突组合；过期精确引用返回 typed stale 错误。Software 整体回退只有 `GraphicsFallbackPolicy::AllowCpu` 显式允许时才发生。`App::graphics(options)` 提供默认配置，`WindowConfig::graphics(options)` 可逐窗覆盖。
- `GraphicsBackendStatus` 分别表达 build 未启用、平台不适用、未发现 adapter、可用或探测失败。仅“已编译”不能声称可创建当前 surface。
- `GraphicsRuntimeInfo` 是所属窗口的实际状态，包含请求选项、generation 与 `Initializing` / `ActiveGpu` / `ActiveCpuFallback` / `Recovering` / `Failed` / `Closed` 状态；GPU 活跃态携带 adapter + backend，CPU 回退态携带 typed fallback 原因。配置偏好不得冒充运行结果。
- `GraphicsRuntimeHandle::snapshot()` 只读缓存；`subscribe` 仅在 generation 变化时向 App 主循环投递新快照，返回 drop-to-unsubscribe 的 `PlatformSubscription`，不制造逐帧轮询。

硬件 inventory 不等于 surface 可用性；只有真实窗口创建 device / surface 成功后，adapter 才能成为 `ActiveGraphicsDevice`。恢复状态机仍由框架托管，公开面只提供只读状态。

公开值类型使用私有字段、getter、builder 与 `#[non_exhaustive]` 保留演进空间。不得直接重导出 `wgpu::AdapterInfo`、`wgpu::Limits` 或厂商 API struct。

## 内部边界

```text
public facade
    ↓
runtime proxy / cached snapshots
    ↓
crate-private contracts
    ├── platform runtime + event normalization
    ├── OS services
    ├── window backends (Windows / Wayland / macOS)
    └── graphics implementation + factory + recovery
```

- crate-private contracts 可以为测试使用 trait，但不得因实现便利泄到默认 rustdoc。
- OS `cfg` 只在 native 内；上层只依赖 facade 值类型与 handle。
- raw pointer / FFI、线程亲和对象与 checked teardown 留在最小内部边界。
- 若未来支持第三方 backend，另建 feature-gated、版本化的 extension SDK；不能把默认消费 API 反向扩大为实现 SPI。
