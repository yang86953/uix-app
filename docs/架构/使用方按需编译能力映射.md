# 使用方按需编译能力映射

> **状态**：ODC-02 首轮盘点 + ODC-03/05 首批落地（2026-08-04）。本文记录当前源码与 Cargo 清单事实；只有经过独立 fixture、resolved graph 和 release 产物验证的边界才写成已落地结论。

## 盘点口径

主清单是 [`Cargo.toml`](../../Cargo.toml)，公开门面是 [`src/prelude.rs`](../../src/prelude.rs)，系统所有权以各根 Module 的 SMC 说明为准：

| 所有权 | 当前根 Module | SMC 证据 |
|---|---|---|
| 基础契约 | [`src/core`](../../src/core/mod.rs) | SMC-01，模式外基础依赖 |
| 平台与原生后端 | [`src/native`](../../src/native/mod.rs) | SMC-02，私有实现与组装边界 |
| 绘制与渲染 | [`src/draw`](../../src/draw/mod.rs) | SMC-03，graphics System |
| UI 与组件 | [`src/ui`](../../src/ui/mod.rs) | SMC-04，组件与 View 门面 |
| 数据设置 | [`src/data`](../../src/data/mod.rs) | SMC-05，SettingsService |
| 应用与 Agent | [`src/app`](../../src/app/mod.rs) | SMC-06，组合根与自动化 |

本表中的“已门控”只表示存在 feature 或 target `cfg`；是否真的从使用方的 Cargo resolved graph、编译日志和 release 产物中消失，仍由 ODC-01/ODC-07 门禁证明。

## 尚未形成 feature 的候选能力

下列依赖和源码目前仍由主 crate 无条件编译，不能在 ODC-01 的 `minimal` fixture 中声称已经排除：

| 候选能力 | 当前无条件依赖 | 主要源码入口 | 所有权与下一步 |
|---|---|---|---|
| 字体与文字布局 | `ab_glyph` | [`draw/resources/font`](../../src/draw/resources/font/mod.rs) | SMC-03；先确认 App 启动和基础 Typography 是否共同需要，再决定 optional feature 或独立 crate |
| 图片解码与位图组件 | `image` | [`draw/resources/image`](../../src/draw/resources/image/mod.rs)、[`ui/widgets/display/image.rs`](../../src/ui/widgets/display/image.rs) | SMC-03/04；当前渲染、离屏和组件路径都有调用，不能只凭单个 Widget 拆分 |
| 表单校验 | `regex` | [`ui/form/form_validation`](../../src/ui/form/form_validation/mod.rs) | SMC-04；候选 `form-validation` feature，需清理 `prelude` 的无条件导出 |
| 字体轮廓与路径几何 | `earcut`、`bytemuck` | [`draw/geometry/tessellator.rs`](../../src/draw/geometry/tessellator.rs)、绘制 backend | SMC-03；可能是绘制基础共享依赖，不能直接按组件 feature 切断 |
| 日志订阅与平台桥接 | `tracing-subscriber`、`raw-window-handle`、`windows-core` | 应用启动、平台和宏展开入口 | SMC-02/06 与基础宏契约交叉；先做调用点和 target 矩阵盘点，再判断是否可选化 |

`image`、`ab_glyph`、`earcut`、`bytemuck` 等依赖同时出现在绘制基础路径中；它们是否可拆，必须以“关闭候选能力后最小 fixture 仍能 clean release build”为前提，不能仅按依赖名称机械 optionalize。

## 需要保留的边界事实

1. `d3d11`、`d3d12`、`opengles`、`vulkan`、`metal` 是 backend 轴；target `cfg` 与 capability feature 必须分别记录，不能把运行时 registry 条目当作已编译实现。
2. `settings-serde` 与 `agent-control` 都会启用 `serde_json`；Cargo feature 合并后，单独 fixture 的 resolved graph 必须记录实际合并结果。
3. `prelude` 除 `QRCode` 首批门控外仍无条件导出大量绘制、设置和组件类型；继续收缩前必须定义哪些导出属于基础契约，哪些应随 feature 隐藏。
4. `qrcode` 已从未选场景的实际 resolve 节点中消失；其余候选依赖仍只是事实映射，不得据此宣称已完成裁剪。
