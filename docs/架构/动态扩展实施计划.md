# 软件动态扩展实施计划

[← 返回架构索引](../架构.md) · [目标设计](app/extensions.md) · [引擎取证](app/extensions-engine.md)

> **状态**：文档计划。P0 取证与第一版合同已冻结（见[引擎取证](app/extensions-engine.md)）；P1 起进入实施。
>
> **权威范围**：未来实施的依赖顺序、阶段产物、验收与停止条件；语言、生命周期与失败语义由[目标设计](app/extensions.md)唯一持有。阶段编号不表示当前完成度，不作为实时任务看板；实际实施进度按仓库既有任务治理记录。

## 交付路线

```text
P0 标准与引擎取证
 → P1 无界面扩展最小闭环
 → P2 动态界面与宿主能力
 → P3 热替换、迁移与卸载
 → P4 交付与开发工具
```

首个验收应用采用“文本处理工作台”：宿主提供文档查询与受控改写端口；Lisp 扩展实现转换规则、命令和可选面板。先在没有窗口的运行时中调用命令，再在同一应用实例内加载面板、更新规则与布局、保留兼容草稿、注入失败并卸载。此场景用于证明新增软件功能，不以单纯改标题或颜色代替。

## P0：冻结标准、执行与接入合同

输入为本设计、UIX 既有 app/ui 契约和小贝参考快照。先完成以下产物，再修改生产实现：

- R7RS-small 逐项兼容矩阵：必需语义、可选实现行为、受限环境库、已知缺口与验收出处；测试集合需记录真实来源与版本，不笼统声称存在“官方全量套件”。
- 引擎对照记录：小贝引擎独立化的依赖与语义缺口，以及已有实现嵌入的取舍；比较回收、配额、可取消性、宿主回调、平台、许可和默认关闭后的构建成本。
- 包清单、Rust 管理门面、Scheme 宿主库、类型映射、生命周期结果和状态 schema 的第一版合同；发布前才冻结兼容版本。
- UI 挂载位、提交 / 应用 / 呈现回执的缺口清单；单窗基线和多窗部分完成策略；动态 widget 登记与 AOT 共享事实的边界。
- 参考负载、测量方式与候选资源上限；明确哪些是硬拒绝、哪些是超时取消或过载处理。

语言语义或长期回收不满足要求时继续解决引擎缺口，不以缩减为私有 Lisp 方言跳过阶段。无法做到可控执行时不在 UI 线程试运行。独立化若需要修改小贝，作为后续跨仓库任务明确范围，本计划不改其源码。

## P1：先交付无界面的软件扩展

实现显式启用的扩展宿主、包冻结与检查、实例求值、命令注册、类型化调用、列举与基础停止。只接纯计算与一个只读宿主端口；扩展有自己的状态，重复命令调用复用实例。

完成定义：无需窗口加载文本转换扩展，实际执行新算法并读取授权宿主数据；两个扩展环境互不污染；未知命令、冲突 ID、无效包、禁止能力、超限与取消有明确结果。基础停止必须排空并释放实例，不能把安全回收推迟到热替换阶段。

先把新公开行为写入使用文档，再建立外部消费者 `tests/*_public_api.rs`。用真实输入、输出与公开失败验证标准语义和宿主边界；不为私有 reader、求值机或目录结构另设项目测试。

## P2：接通动态 UI、事件与业务能力

在 P1 的同一扩展实例上增加公开事件、异步端口和受控业务改写。扩展点同时支持命令与服务实现；宿主明确端口 schema、调用权限、取消与结果责任。

接入一个窗口的稳定挂载位，冻结足够完成表单交互的一组动态 widget：容器、文本、输入、按钮与列表等，具体清单以登记事实为准。Lisp 构造 UI 数据，Rust 校验并沿现有 view/reconcile 路径应用；交互通过事件队列回到扩展，不能在 layout/paint 执行 Lisp。

完成定义：运行中新增面板和命令，输入调用新逻辑、受控更新宿主文档，异步进度回显；结构、样式与事件绑定实际变化。无效属性、重复 key、错误 revision 和未编译 capability 拒绝后原树完整；输出回执区分接收、应用和呈现。无窗口模式仍能使用同一扩展的逻辑部分。

## P3：热替换、状态迁移与完整卸载

实现独立候选环境、旧代入口门控、排空、状态导出与迁移、注册集提交、代际防护和回退候选流程。补齐活动资源的停止 / 卸载、持久化可选协议、撤权和失败隔离；多窗口扩展按逐窗结果接入。

完成定义：同一进程连续加载、替换、卸载，命令算法与界面共同升级；兼容业务状态和 UI 草稿按合同保留。注入候选失败、迁移失败、关闭窗口、旧代异步回包、重复操作及卸载超时，均能观察到真实终态，原宿主仍可操作。具有外部效果的任务不能因替换被重复执行或错误标成完成。

无在途调用与存活资源后才能宣布卸载完成；反复替换后 Scheme 堆、闭包、订阅、任务和挂载节点不随次数无界增长。多窗口应用失败须真实返回部分结果，不能把逻辑注册成功等同于全部窗口呈现。

## P4：交付与开发体验

提供包检查、显式加载 / 替换、状态观察和源码诊断的使用入口；文件监听仅作为可选开发工具，以去抖后的不可变快照走同一替换流程，不绕过生命周期门禁。交付一个可以审查的完整扩展包和宿主示例，分别说明标准语法与 UIX 宿主库。

核对 feature 关闭和开启的构建图、平台能力、发布产物与资源成本。Windows/Linux 完成对应真实环境验收；macOS 按实际交付范围单独列证，不凭交叉编译宣称运行支持。插件下载分发、市场和原生代码加载仍不进入这一阶段。

## 验收矩阵

以下都是未来实现的门禁，本次文档交付不执行。

| 维度 | 必须观察到的结果 | 验证方式 |
|---|---|---|
| 标准语义 | 声明支持的词法、尾调用、宏卫生、库隔离、数值与 continuation 语义成立；缺口诚实报错 | 经扩展公开装载 / 调用入口提交规范程序，记录标准章节 |
| 软件扩展 | 无 UI 的新命令、规则、服务端口与状态工作；宿主侧效果实际发生 | 外部消费者公开 API 行为测试 |
| 动态 UI | 新结构与交互真实生效；兼容状态保留；预检失败不改树 | 公开组件行为测试 + Agent 真窗操作 |
| 生命周期 | 失败保留旧代、陈旧结果拒绝、迁移正确、撤权生效、关闭有终态 | 公开装载 / 替换 / 调用 / 卸载与宿主端口的故障场景 |
| 资源 | 深度、宏展开、大数、循环分配、事件风暴受限；可取消、无无界积累 | 公开失败行为 + 独立性能及资源测量 |
| 诊断 | 定位到扩展版本、入口与源码位置；失败责任唯一、秘密值不泄漏 | 公开结果 / Diagnostics 消费者 + 诊断契约审计 |
| 构建与平台 | 关闭能力时无扩展运行成本；已交付平台实际可加载并退出 | 构建图人工复核、相关目标构建与真实环境验收 |

公开 API 测试只使用实际新增并已文档化的入口，拟议测试文件名不提前创建。日常运行直接受影响的 `--test <实际名称>`；跨系统交付按仓库规则选取全量公开 API 命令。修改 `src/` 错误、日志或 panic 路径后运行 `python3 scripts/diagnostics_audit.py --verbose`，违规清零后提交。

运行中的 UIX 应用只通过 `scripts/agent_client.py` 验收：先 `apps` 枚举并明确绑定实例，再读取语义状态和执行动作；像素证据仅用 Agent `screenshot` 落盘。真实窗口与性能证据不冒充公开 API 测试通过项。

## 测量与停止条件

参考负载采用一个无窗口纯逻辑扩展、一个含输入 / 列表 / 异步操作的交互扩展，以及多扩展突发输入与连续替换场景。实施前冻结各场景的包大小、实例 / 节点数、调用量、替换次数、环境与候选配额，形成可重复基线，不在无测量时承诺生产 SLO。

分别记录冷装载、命令端到端延迟、替换暂停时间、逐窗应用 / 呈现延迟、CPU、RSS、Scheme 存活堆、峰值分配、回收暂停和空闲唤醒。与相同宿主的静态实现及未开启扩展构建对照，预热并重复采样，报告离散程度和资源退化；测量档案进入既有[性能记录](../性能/README.md)体系。

达到对应阶段的功能、失败与资源门禁后再进入下一阶段。首期交付以“新增软件功能、动态 UI、失败可恢复、卸载有终态”共同成立为准，不以解释器能算表达式或界面能换标题作为全部完成。暂不绑定发布版本或工期。
