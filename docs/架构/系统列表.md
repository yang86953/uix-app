## 设计阶段的三层粒度

现行规范唯一来源是 code/smc（外部规范；本仓库采用摘要见 SMC采用.md），全仓采用范围和固定提交见 [SMC 架构采用](SMC采用.md)。本页区分现有隔离映射与目标组织策略：保持公开契约、状态权威、授权和回收责任；目标默认简单依赖，但不要求所有兄弟协作绕经转发层。实际实现调整按具体任务审查，不因本页改动自动重构。

| 层级 | 设计定义 | 代码重构后的落点 | 文档责任 |
|---|---|---|---|
| System | 承担可验证结果、适用状态权威与失败语义的逻辑边界，无状态能力亦可承担此角色 | 可由公开门面、函数或多处实现共同承载，不要求独立运行对象 | 本文声明责任、结果、状态与公开依赖 |
| Module | 围绕变化原因隐藏实现决策的可选组织边界，没有独立价值时省略 | 通常落在私有或 `pub(crate)` Rust module，可由一个或多个源码单元承载 | 对应正文记录变化原因、访问边界与不变量 |
| Component | 用途、可验证行为与成本明确的实现能力；不要求独立实例或动态替换接口 | 可由纯函数、算法、Adapter、类型或生成代码实现；稳定私有调用可直接绑定 | 记录适用的输入输出、失败、访问期、执行成本和验证入口 |

**三层角色不是物理目录的别名。** 本目录描述重构完成后应形成的逻辑架构；当前路径只作为定位遗留实现的迁移线索，不得反向决定 System、Module 或 Component 的数量、命名和职责。一个现有文件可能包含多个角色的实现，多个现有目录也可能共同承载一个逻辑角色。没有独立契约、替换价值或变化原因的普通函数、基础算法、生成代码和外部资源不强行归入三层。

## 术语语义基线：component 只指 SMC 的 Component

「component」在本仓库代码与架构文档中只指 SMC 三层中的 **Component**——用途与可验证行为明确的实现能力，可以是函数或算法；不要求独立实例或动态替换接口。UI 实体一律称为 widget：`Widget`（主契约）、`WidgetId`（身份）、`WidgetHandle` / `WidgetConfig` / `WidgetOverrides`（句柄/配置）、`widget_snapshot`（派生快照）、widgets 库实现以及 UIX Lang `Widget` 声明均不属于 SMC Component 术语。

ui System 的组件运行时框架由 `widget_runtime` 私有 Module 承载（WidgetTree / WidgetNode / 契约 / 管理器 / 配置 / i18n / 焦点陷阱）；该命名与 SMC Component 层保持区分。原 `component` Module 的迁移记录由 历史组件迁移记录（当前源码使用 widget_runtime） 持有，任何新代码与文档不得再引入「component 指模块」的用法。

下列目录是职责导航，不是必须创建的物理模块清单。没有独立变化原因时可合并或省略，职责与资源责任仍须清楚。为保持其他三类文档在分阶段迁移中可导航，少量旧文件名可暂存“迁移路由（非模块）”；这些路由不进入目标架构，引用迁移完毕后删除。

## 候选领域边界

下表按可承诺的结果和实际责任划分，不以历史“六系统”或目录数量定级。`core` 与 `bus` 当前作为共享基础能力，不为满足层级命名而新增运行对象；无状态不构成 v2 的 System 排除条件。`bus` 的同步分发语义见 code/smc 进程内执行（外部规范；本仓库采用摘要见 SMC采用.md），UIX 继续由明确所有者管理现有私有实例与订阅。

| 系统 | 核心职责 | 允许依赖 |
|---|---|---|
| `core`（基础依赖，待定级） | 无平台、图形和 UI 语义的基础值与失败模型 | — |
| `bus`（模式外基础设施，待定级） | 进程内同步类型化事件分发 | — |
| `diagnostics` | runtime 级错误观察、恢复协调、callback 失败归队和崩溃记录 | `core` |
| `platform` | OS 窗口、输入、呈现能力和本机传输 | `core`、`diagnostics`、`bus` |
| `graphics` | 绘制录制、场景、资源、后端与提交 | `core`、`diagnostics`、`platform`、`bus` |
| `ui` | 组件、声明式视图、状态、交互和通用组件 | `core`、`platform`、`graphics`、`bus` |
| `data` | 不进入每帧热路径的应用数据服务 | `core`、`bus` |
| `app` | 组装并调度所有下层系统 | `core`、`diagnostics`、`platform`、`graphics`、`ui`、`data`、`bus` |

这是目标代码依赖的有向无环图，不要求每个 System 依赖排序中紧邻的边界。例如 data 只依赖 core；ui 不得为了调用 AppHandle 而反向依赖 app，所需能力由组合根或上层 System 注入窄契约。

```text
core ─ diagnostics ─ platform ─ graphics ─ ui ─┐
  └─ data ─────────────────────────────────────┤
bus（独立基础设施，由所有者按需实例化）────────┤
                                              └─ app
```

## core：基础契约（System 定级待定）

core 只拥有跨系统稳定、无运行时策略的值类型。它不包含日志器、性能探针、字体轮廓等上层机制。

| 目标模块 | 目标职责 | 代表组件 | 文档 |
|---|---|---|---|
| identity | 稳定身份与代际失效 | `WidgetId`、`WindowId` | [identity](core/identity.md) |
| geometry | logical 坐标、尺寸、矩形和约束 | `Point`、`Size`、`Rect`、`Constraints` | [geometry](core/geometry.md) |
| damage | 增量失效与提交前后真相 | `DirtyFlags`、`DamageRegion`、`PresentDamageTracker` | [damage](core/damage.md) |
| error | typed error 和统一结果语义 | `Error`、`Errc`、`Result<T>` | [error](core/error.md) |

## diagnostics：运行保障系统

diagnostics 对框架与应用宿主提供单一 runtime 级运行保障公开面。它拥有报告容量、恢复登记、callback 失败归队和崩溃记录生命周期；不负责具体资源重建、业务补偿、远程上传或应用展示。

| 目标模块 | 目标职责 | 代表组件 | 文档 |
|---|---|---|---|
| reporting | typed error 脱敏、有界存储、快照和结构化事件 | `ReportDraftBuilder`、`ReportStore`、emission guard | [diagnostics](platform/diagnostics.md) |
| recovery | 精确错误码恢复登记、递归保护和结果保真 | `RecoverySubscription`、`RecoveryGuard` | [diagnostics](platform/diagnostics.md) |
| crash | panic 最小安全记录、原子落盘和 hook 生命周期 | `CrashReport`、panic hook、atomic writer | [diagnostics](platform/diagnostics.md) |

> **迁移路由**：文档暂保留在 `platform/diagnostics.md`，只为避免迁移期链接失效；该路径不表示 diagnostics 属于 platform 的私有 Module。

## app：应用运行时系统

app 是唯一允许组装全部下层系统的顶层。它拥有进程与窗口生命周期、等待/唤醒和逐窗推进，但不重新定义 UI 语义或图形执行。

| 目标模块 | 目标职责 | 代表组件 | 文档 |
|---|---|---|---|
| application | 应用组装、共享服务、运行模式和关闭 | `App`、`AppHandle`、`Container` | [application](app/application.md) |
| event-loop | 平台等待、活动工作、timer 和帧机会 | `EventLoop`、`ActiveWorkRegistry` | [event-loop](app/event-loop.md) |
| window | 窗口创建、逐窗会话、单帧驱动和 IME | `Window`、`WindowSession`、`WindowDriver`、`FrameScheduler` | [window](app/window.md) |
| agent | 可选本机控制面、协议和语义动作桥 | `AgentProcessBridge`、`AgentProtocolSession`、`AgentWindowRegistration` | [agent](app/agent.md) |
| extensions（已有公开实现） | Scheme软件扩展、活动代、能力登记、状态迁移与回收 | ExtensionHost与显式宿主端口；按需启用 | [extensions](app/extensions.md)、[公开使用](../使用/能力与边界/软件动态扩展.md) |
| modules（源码能力） | 可移植UIX模块实例、AOT/动态执行、worker与投影 | 宿主拥有实例生命周期，编译器拥有检查产物；两侧UI各自实例 | [应用模块](../uix-lang/规范/应用模块.md) |

`AgentCommandQueue`、`WindowAgentState`、`AgentCommandExecutor` 与 `AgentSemanticsPort` 是 app System 私有的跨 Module 契约和状态边界，不归任一 Module 私有。`session_runtime` 组合根创建并注入队列、执行器与语义端口；`agent` 提供执行和发布端口实现，`event-loop` / `window` 只消费 System 私有契约。

动态扩展也由 app System 组装：`extensions` 不直接持有 `application`、`window`、`event-loop` 或 `agent` Module，通过 app 私有契约取得窗口提交、任务与关闭能力。ui 只消费声明数据，不反向依赖 Lisp 引擎；具体执行与所有权见[目标设计](app/extensions.md#4-职责执行位置与状态权威)；当前公开入口与未测边界由使用说明和对应任务验收。

## 系统内业务流向

下列箭头描述责任协作与主要数据流，不要求每个箭头新增对象、事件或一次System转发。固定同进程协作可以通过窄内部契约直接调用或共享不可变表示；只有职责/语义发生变化时才转换。涉及独立权限、线程亲和、生命周期或替换边界时继续明确注入/隔离。

| System | 由 System 编排的主业务流 |
|---|---|
| core | `geometry → damage`；identity、geometry、error 彼此独立 |
| diagnostics | `typed error → recovery`；未恢复错误再进入 reporting；panic 独立进入 crash；三个 Module 互不直连 |
| platform | `windowing → presentation`；`windowing → agent-transport`；capabilities 独立 |
| graphics | `geometry → painting → scene`；`painting → backend`；`{geometry, backend} → resources`；`{scene, backend, resources} → renderer` |
| ui | `widget_runtime → reactive → view → theme`；`widget_runtime → layout → event → accessibility`；`{widget_runtime, reactive} → animation`；`{event, animation} → overlay`；`{widget_runtime, reactive, event} → form`；`{widget_runtime, layout, view} → virtualization`；上述能力最终供 widgets 组合 |
| data | settings 当前无系统内模块依赖 |
| app | `window → {event-loop, agent} → application`；event-loop 与 agent 互不依赖 |

> **当前实现映射**：上表只表达 System 编排的数据流。`event_loop` / `window` 不直接引用 `agent` Module；Agent 命令协议、队列与每窗状态已由 app System 私有边界持有，具体执行器和语义发布端口由 `session_runtime` 在组装期注入。这条Agent当前隔离映射继续有效，不因通用组织简化而允许绕过授权或前后台隔离；没有针对性任务不改线。

不得通过私有穿透、任意服务发现或隐式回调取得其他模块的状态写权/生命周期控制。是否直接协作按契约和变化原因选择，不为“兄弟”命名一律禁止；事件总线不应成为绕路解决固定调用的工具。

## 跨层强制规则

| 规则 | 设计契约 |
|---|---|
| OS 隔离 | OS 专属实现和条件编译收敛在 platform；上层只依赖 owned 描述值和明确能力 |
| 绘制入口 | UI 和内置组件只使用 graphics/painting；raw backend、可写像素和原生上下文不进入组件 API |
| 主题归属 | Theme、DesignTokens、组件配置和 Locale 属于 ui；graphics 只接收已解析视觉值 |
| 单一 UI 管线 | View → WidgetTree → layout/event/paint 是唯一可写界面路径；无障碍与 Agent 都是派生或动作桥 |
| 资源身份 | 长寿命窗口、组件和图形句柄使用 generation；旧 generation 只能失效，不能误命中新资源 |
| 逐窗隔离 | timer、动画、帧请求、surface 状态、IME、Agent 队列和语义 revision 归所属窗口 |
| 热路径 | 设置 I/O、服务解析和阻塞系统调用不得进入 reconcile/layout/paint/present 热路径 |
| 失败语义 | 内层传播 typed error；最终责任边界只观察/报告一次，不把失败伪装成成功 |
| 诊断隔离 | diagnostics 只观察、登记和协调；具体资源重建、业务补偿与用户展示仍由资源所有者或应用负责 |
| 深度休眠 | 无事件、到期工作、队列或帧机会时进入 DeepIdle；禁止固定 tick 和无条件轮询 |
| 公开边界 | 公开 API 由产品与使用文档约束；源码内部 module graph 不自动成为兼容承诺 |
| 协作边界 | 固定协作可直接绑定窄契约；独立权限/生命周期保持隔离，不访问他方私有状态 |
| 组件所有权 | 生命周期所有者、状态权威与访问权分别明确；允许受控共享不可变数据/句柄，禁止无协议多写者 |
| 组合根 | 最终应用选择和注入 System；框架不提供固定的全系统聚合对象 |

| 应用领域数据与本地设置 | 业务真值由应用拥有；`SettingsService` 只持所选键值，UI 是投影，不自动保存 | [配置](../使用/框架设施/配置.md)：显式载入/修改/保存，I/O 失败仍由调用方处理；不提供云同步 |
| 界面状态、输入、主题与语言 | UI owner 更新状态；子树内置 Locale/主题覆写不改应用默认值，业务翻译表则是独立的进程级资源；窗口间不借用私有状态 | [响应式](../使用/入门/响应式基础.md)、[框架设施](../使用/框架设施/框架能力.md)、[事件](../使用/交互与反馈/事件.md)；自定义 Widget 仍走同一布局/事件/绘制入口 |
| 调度与外部工作 | 窗口会话管理自己的 UI 调度；应用拥有外部任务及其取消、代际和 join | [定时与异步](../使用/动画与异步/定时与异步.md)：启动→后台结果→目标窗口回投→核对请求仍有效；`post_to_ui` 返回 unit 而非接纳/执行回执，页面卸载不等于外部工作已停止 |
| 图形与媒体帧 | graphics 管理录制、提交和引用期；应用拥有源媒体、解码器与提交预算 | [帧输入合同](../使用/界面构建/绘制.md#合成帧与视频帧)：生产→有界交接→绘制→最后引用释放；不把提交返回当扫描输出或 CPU 帧已回收 |
| 平台资源 | 原生资源由明确 owner-thread 服务持有，业务权限由应用决定 | [平台能力](../使用/框架设施/平台能力.md)：capability 与 typed 失败边界 |
| 派生语义与 Agent | 语义树从当前 WidgetTree 派生；Agent 独立后台 UI，业务共享仅由显式端口决定 | [accessibility](ui/accessibility.md)、[后台操作面](../使用/能力与边界/Agent后台操作面.md)：发现/绑定→观察→动作→观察结果；陈旧身份失效，不改绑前台 |
| 扩展与可移植模块 | 扩展拥有自身状态，Rust 持宿主真值/权限/生命周期；编译器持检查产物而非运行状态 | [Scheme](app/extensions.md)、[应用模块](../uix-lang/规范/应用模块.md)：准备候选→受控提交→撤权/停止/回收；候选失败不覆盖活动代，不隐式开放宿主能力 |
| 诊断与恢复 | diagnostics 持有界报告和恢复登记；资源 owner 执行重建，应用决定业务补偿 | [运行保障](../使用/框架设施/运行保障.md)：传播→有权边界处理→未恢复再报告；不吞错、重复恢复或默认上传 |

## 关键数据流

```text
platform event
  → app/event-loop 定位目标 app/window
  → ui/event 更新 ui/reactive 或组件运行态
  → ui/view reconcile → ui/layout
  → graphics/painting → graphics/scene
  → graphics/renderer/backend
  → platform/presentation
```

settings、theme、accessibility 和 agent 不建立旁路：settings 只在应用冷路径读写；theme 只改变 UI 解析上下文；accessibility 从组件树派生；agent 动作重新进入其独立后台工作面的正常事件路径，不改绑用户前台窗口。
