# 系统列表

[← 架构索引](../架构.md)

> **接口**：声明 UIX 六层单向依赖的架构分层与跨层约束规则。每层的模块分解与组件清单下放到对应子文档。依赖：[产品](../产品.md)。导出：各模块详设 → 对应子文档。

## 概念层级

UIX 源码按三层粒度组织：

| 层级 | 源码对应 | 职责 |
|------|----------|------|
| **系统** | `src/{core,platform,graphics,ui,data,app}/` | 单向依赖的架构边界，声明层间契约 |
| **模块** | 系统下的子目录（如 `src/ui/animation/`）或主文件 | 独立构建和替换的最小功能域 |
| **组件** | 模块内的 struct / trait / 函数 | 最小接口单元，声明输入输出和生命周期 |

框架的六层架构即六个**系统**，按 `core → platform → graphics → ui → data → app` 单向依赖。违反方向即架构违规。

---

## core 系统

> 基础抽象，不依赖其他系统。

提供几何类型、标识符、脏区管理、字形轮廓、性能探针等跨层共享的基础设施。模块与组件清单 → [`core/` 子文档](core/)。

---

## platform 系统

> OS 抽象与平台能力，仅依赖 `core`。`#[cfg(OS)]` 仅限此系统。

封装 OS 差异，暴露稳定的平台 trait 与公开门面；同时承载诊断与运行保障（错误处理、诊断收集、崩溃处理、恢复策略、日志）。模块与组件清单 → [`platform/` 子文档](platform/)。

---

## graphics 系统

> 绘制管线与视觉基础，依赖 `core` + `platform`。禁依赖 `ui` 或 `app`。

PaintContext、Renderer、DisplayList、颜色、字体、场景管理等绘制管线全链路实现。模块与组件清单 → [`graphics/` 子文档](graphics/)。

---

## ui 系统

> UI 引擎与子系统，依赖 `core` + `platform` + `graphics`，不碰 backend。

组件核心、布局引擎、事件系统、动画、主题、View 声明式、浮层、内置组件等。模块与组件清单 → [`ui/` 子文档](ui/)。

---

## data 系统

> 数据抽象，仅依赖 `core`，不进热路径。

设置持久化等应用数据管理。模块与组件清单 → [`data/` 子文档](data/)。

---

## app 系统

> 应用组装层，依赖所有下层系统。

应用入口、事件循环、帧调度、窗口管理、依赖注入、Agent 系统等。模块与组件清单 → [`app/` 子文档](app/)。

---

## 架构强制规则

| 规则 | 内容 |
|------|------|
| **OS 能力** | 经 `native::traits`；上层禁 `use native::backends::*` |
| **平台条件编译** | `#[cfg(OS)]` 仅限 `platform` 系统 |
| **绘制边界** | 生产绘制只依赖 `PaintContext`；raw canvas 只留在 `graphics`/`platform` 内部和 `app` presenter 桥 |
| **公开入口** | `uix::prelude::*` |
| **资源句柄** | generation 槽位复用 `(slot_index, generation)`；适用 BitmapHandle、WidgetId、ImageHandle |
| **运行时** | 原生窗口 + 原生绘制；**禁 WebView / 嵌入式浏览器** |
| **图形初始化** | `draw::renderer::bootstrap → native::factory`（recipe 为单位）；生产只构造 `draw::Renderer` |
| **测试** | 只从 crate 外部验证六层公开 API；使用 `tracing`，不增加 `cfg(test)` 白盒入口 |
| **样式链** | 只写入节点唯一 `Style`；padding 保留另一轴；阴影进同一盒模型 |
