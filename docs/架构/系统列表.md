# 系统列表

[← 架构索引](../架构.md)

> **接口**：适用于决定重构后能力属于哪个系统、哪个目标模块，以及该模块允许依赖哪些下层。本文档权威持有六系统依赖、目标模块目录和跨层规则；模块内部组件契约由各模块文档持有。依赖：[产品](../产品.md)。导出：[架构索引](../架构.md)中的全部模块正文。

## 设计阶段的三层粒度

| 层级 | 设计定义 | 代码重构后的落点 | 文档责任 |
|---|---|---|---|
| 系统 | 单向依赖、资源所有权和失败边界 | `core / platform / graphics / ui / data / app` 六个顶层边界 | 本文声明允许依赖和系统职责 |
| 模块 | 系统内可独立理解、测试、替换的最小功能域 | 一个内聚目录或主模块，可包含多个实现文件 | 每份模块文档声明职责、组件和不变量 |
| 组件 | 模块向内或向外提供的最小接口单元 | `struct`、`enum`、小型 `trait`、关键函数或受控 side table | 模块文档以“组件清单”和“组件：XXX”描述 |

**目标模块不是当前源码目录的别名。** 本目录描述重构完成后应形成的架构；当前路径只作为定位遗留实现的迁移线索，不得反向决定模块数量、命名或职责。一个现有文件可能拆入多个目标模块，多个现有目录也可能合并为一个目标模块。

系统与模块目录只以本文列出的目标模块为准。为保持其他三类文档在分阶段迁移中可导航，少量旧文件名可暂存“迁移路由（非模块）”；这些路由不进入目标架构，引用迁移完毕后删除。

## 六系统依赖

| 系统 | 核心职责 | 允许依赖 |
|---|---|---|
| `core` | 无平台、图形和 UI 语义的基础值与失败模型 | — |
| `platform` | OS 窗口、输入、呈现能力、诊断和本机传输 | `core` |
| `graphics` | 绘制录制、场景、资源、后端与提交 | `core`、`platform` |
| `ui` | 组件、声明式视图、状态、交互和通用组件 | `core`、`platform`、`graphics` |
| `data` | 不进入每帧热路径的应用数据服务 | `core` |
| `app` | 组装并调度所有下层系统 | `core`、`platform`、`graphics`、`ui`、`data` |

这是有向无环依赖图，不要求每个系统依赖排序中紧邻的系统。例如 data 只依赖 core；ui 不得为了调用 AppHandle 而反向依赖 app，所需能力由 app 注入下层契约。

```text
core
├─ platform ─ graphics ─ ui ─┐
└─ data ─────────────────────┤
                             └─ app
```

## core：基础契约系统

core 只拥有跨系统稳定、无运行时策略的值类型。它不包含日志器、性能探针、字体轮廓等上层机制。

| 目标模块 | 目标职责 | 代表组件 | 文档 |
|---|---|---|---|
| identity | 稳定身份与代际失效 | `ComponentId`、`WindowId` | [identity](core/identity.md) |
| geometry | logical 坐标、尺寸、矩形和约束 | `Point`、`Size`、`Rect`、`Constraints` | [geometry](core/geometry.md) |
| damage | 增量失效与提交前后真相 | `DirtyFlags`、`DamageRegion`、`PresentDamageTracker` | [damage](core/damage.md) |
| error | typed error 和统一结果语义 | `Error`、`Errc`、`Result<T>` | [error](core/error.md) |

## platform：操作系统适配系统

platform 对上提供 owned 值和线程亲和能力，对内收敛 `#[cfg(target_os = ...)]` 与原生资源。分派用的 trait 是组件或实现手段，不单独形成 traits 模块。

| 目标模块 | 目标职责 | 代表组件 | 文档 |
|---|---|---|---|
| capabilities | 显示器、主题、硬件与轻量系统查询 | `Platform`、`MonitorInfo`、`HardwareInfo` | [capabilities](platform/capabilities.md) |
| windowing | 原生窗口、事件源、输入、剪贴板与 IME | `PlatformWindow`、`EventSource`、`TextInputSession` | [windowing](platform/windowing.md) |
| presentation | surface、图形 recipe 与 presenter | `SurfaceHandle`、`GraphicsRecipe`、`Presenter` | [presentation](platform/presentation.md) |
| diagnostics | runtime 级观察、报告与恢复协调 | `Diagnostics`、`ErrorReport`、`RecoverySubscription` | [diagnostics](platform/diagnostics.md) |
| agent-transport | 可选同用户本机 IPC 和 discovery | `AgentListener`、`PeerIdentity`、`DiscoveryLease` | [agent-transport](platform/agent-transport.md) |

## graphics：图形与呈现系统

graphics 接收解析后的视觉值并完成录制、场景组织、资源管理、backend 执行与提交。Theme、组件状态和窗口事件不属于本系统。

| 目标模块 | 目标职责 | 代表组件 | 文档 |
|---|---|---|---|
| geometry | 图形领域的颜色、路径和空间变换 | `Color`、`Path`、`Transform` | [geometry](graphics/geometry.md) |
| painting | 规范绘制 API、命令录制与帧编码 | `PaintContext`、`DisplayList`、`FrameEncoder` | [painting](graphics/painting.md) |
| scene | retained layer、picture 和场景差异 | `LayerTree`、`Layer`、`Picture` | [scene](graphics/scene.md) |
| renderer | 帧编排、RenderTarget、提交结果和恢复 | `Renderer`、`RenderTarget`、`GraphicsRecovery` | [renderer](graphics/renderer.md) |
| backend | CPU/GPU 执行、能力协商和 fallback | `RenderBackend`、`BackendCaps` | [backend](graphics/backend.md) |
| resources | 字体、文本布局、图像和代际句柄 | `FontService`、`ImageService`、resource handle | [resources](graphics/resources.md) |

## ui：声明式界面系统

ui 拥有从 View 输入到持久组件树、布局、交互和语义的完整界面模型。它通过 graphics/painting 录制，不直接接触原生 surface 或 backend。

| 目标模块 | 目标职责 | 代表组件 | 文档 |
|---|---|---|---|
| component | 持久组件树、能力分派和树级运行态 | `WidgetTree`、`WidgetComponent`、`WidgetManagers` | [component](ui/component.md) |
| view | 声明式节点、组合器和 reconcile 输入 | `View`、`ViewNode`、`ViewAdapter` | [view](ui/view.md) |
| reactive | 状态、派生值、依赖捕获和副作用 | `State`、`Computed`、`Effect` | [reactive](ui/reactive.md) |
| layout | 测量、盒模型、Flex/Grid 与有限几何 | `LayoutEngine`、`FlexLayout`、`GridLayout` | [layout](ui/layout.md) |
| event | 系统事件、语义事件、传播和 handler | `SystemEvent`、`SemanticEvent`、`HandlerTable` | [event](ui/event.md) |
| animation | 插值、过渡、活动源和暂停 | `Animation`、`Animated`、`TransitionPlayer` | [animation](ui/animation.md) |
| accessibility | 无障碍快照、语义树和动作 | `AccessibilitySnapshot`、`SemanticNode`、`SemanticAction` | [accessibility](ui/accessibility.md) |
| theme | 主题令牌、组件配置、本地化和 Provider | `Theme`、`ConfigProvider`、`LocaleProvider` | [theme](ui/theme.md) |
| overlay | 窗口内浮层栈、focus trap 和进退场 | `OverlayStack`、`OverlayEntry`、`FocusTrap` | [overlay](ui/overlay.md) |
| form | 字段模型、校验、提交和动态行 | `FormModel`、`FieldError`、field adapter | [form](ui/form.md) |
| virtualization | 大数据视图物化、稳定 key 和测量缓存 | `VirtualViewport`、`MaterializedRange`、`ItemKey` | [virtualization](ui/virtualization.md) |
| widgets | 内置通用与复合组件库 | `Button`、`Input`、`Table`、`Modal` | [widgets](ui/widgets.md) |

## data：应用数据服务系统

data 持有明确由应用触发的冷路径数据能力，不感知窗口、主题、组件树或图形 backend。

| 目标模块 | 目标职责 | 代表组件 | 文档 |
|---|---|---|---|
| settings | 设置状态、编解码与可恢复原子保存 | `SettingsService`、codec、sidecar protocol | [settings](data/settings.md) |

## app：应用运行时系统

app 是唯一允许组装全部下层系统的顶层。它拥有进程与窗口生命周期、等待/唤醒和逐窗推进，但不重新定义 UI 语义或图形执行。

| 目标模块 | 目标职责 | 代表组件 | 文档 |
|---|---|---|---|
| application | 应用组装、共享服务、运行模式和关闭 | `App`、`AppHandle`、`Container` | [application](app/application.md) |
| event-loop | 平台等待、活动工作、timer 和帧机会 | `EventLoop`、`FrameScheduler`、`ActiveWorkRegistry` | [event-loop](app/event-loop.md) |
| window | 窗口创建、逐窗会话、单帧驱动和 IME | `Window`、`WindowSession`、`WindowDriver` | [window](app/window.md) |
| agent | 可选本机控制面、协议和语义动作桥 | `AgentProcessBridge`、`AgentProtocolSession`、`WindowAgentState` | [agent](app/agent.md) |

## 系统内模块依赖方向

下列箭头表示“左侧提供契约，右侧可以依赖左侧”。目标实现不得引入反向引用形成环。

| 系统 | 允许的主依赖方向 |
|---|---|
| core | `geometry → damage`；identity、geometry、error 彼此独立 |
| platform | `windowing → presentation`；`{windowing, diagnostics} → agent-transport`；capabilities 独立 |
| graphics | `geometry → painting → scene`；`painting → backend`；`{geometry, backend} → resources`；`{scene, backend, resources} → renderer` |
| ui | `component → reactive → view → theme`；`component → layout → event → accessibility`；`{component, reactive} → animation`；`{event, animation} → overlay`；`{component, reactive, event} → form`；`{component, layout, view} → virtualization`；上述能力最终供 widgets 组合 |
| data | settings 当前无系统内模块依赖 |
| app | `window → {event-loop, agent} → application`；event-loop 与 agent 互不依赖 |

下表只帮助后续重构定位遗留代码，不是目标模块定义。

| 目标系统 | 当前主要实现线索 |
|---|---|
| core | `src/core/` |

实际迁移应以“目标组件归属”逐项搬运：先建立新边界和单向依赖，再迁移组件，最后删除旧入口。不得为了维持当前目录而新增目标模块，也不得在文档中把临时兼容层提升为长期架构。

## 跨层强制规则

| 规则 | 设计契约 |
|---|---|
| OS 隔离 | OS 专属实现和条件编译收敛在 platform；上层只依赖 owned 描述值和明确能力 |
| 绘制入口 | UI 和内置组件只使用 graphics/painting；raw backend、可写像素和原生上下文不进入组件 API |
| 主题归属 | Theme、DesignTokens、组件配置和 Locale 属于 ui；graphics 只接收已解析视觉值 |
| 单一 UI 管线 | View → WidgetTree → layout/event/paint 是唯一可写界面路径；无障碍与 Agent 都是派生或动作桥 |
| 资源身份 | 长寿命窗口、组件和图形句柄使用 generation；旧 generation 只能失效，不能误命中新资源 |
| 逐窗隔离 | timer、动画、帧请求、surface 状态、IME、Agent 队列和语义 revision 归所属窗口 |
| 热路径 | 设置 I/O、服务解析和阻塞系统调用不得进入 reconcile/layout/paint/present 热路径 |
| 失败语义 | 内层传播 typed error；最终责任边界只观察/报告一次，不把失败伪装成成功 |
| 深度休眠 | 无事件、到期工作、队列或帧机会时进入 DeepIdle；禁止固定 tick 和无条件轮询 |
| 公开边界 | 公开 API 由产品与使用文档约束；源码内部 module graph 不自动成为兼容承诺 |

## 关键数据流

```text
platform event
  → app/event-loop 定位目标 app/window
  → ui/event 更新 ui/reactive 或组件运行态
  → ui/view reconcile → ui/layout
  → graphics/painting → graphics/scene
  → graphics/renderer/backend
  → platform/presentation
```

settings、theme、accessibility 和 agent 不建立旁路：settings 只在应用冷路径读写；theme 只改变 UI 解析上下文；accessibility 从组件树派生；agent 动作重新进入目标窗口的正常事件路径。
