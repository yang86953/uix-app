## 事件系统

<a id="事件系统"></a>

### SystemEvent —— 系统事件

平台 backend 先产生 crate 内部 `UiEvent`。App 层消费窗口关闭、可见性、遮挡和帧机会等生命周期事件，并把可进入 UI 的输入子集归一化为 `SystemEvent`；UI 再基于命中、焦点与指针手势合成 `PointerEnter` / `PointerLeave`、`FocusIn` / `FocusOut` 和 Drag 系列事件。`SystemEvent` 共 31 种变体：

| 类别 | 变体 |
|------|------|
| 指针 | `PointerDown` / `PointerDoubleClick` / `PointerUp` / `PointerMove` / `PointerEnter` / `PointerLeave` |
| 滚轮 | `Wheel` |
| 键盘 | `KeyDown` / `KeyUp` |
| 剪贴板 | `Copy` / `Cut` / `Paste` |
| 文本输入 | `TextInput` |
| IME | `ImeCompositionStart` / `ImeCompositionUpdate` / `ImeCompositionEnd` |
| 焦点 | `FocusIn` / `FocusOut` |
| 窗口 | `Resize` / `WindowMaximize` / `WindowMinimize` / `WindowRestore` / `WindowFocus` / `WindowBlur` |
| 主题/区域 | `ThemeChanged` / `LocaleChanged` |
| 定时器 | `Timer` |
| 拖拽 | `DragStart` / `DragMove` / `DragEnd` |
| 文件 | `FileDrop` |

`Wheel.delta` 在原生后端统一为滚动偏移方向：正 `x` / `y` 分别增加向右 / 向下的内容偏移，负值向左 / 向上；组件消费时不得再次反转符号。滚动组件只按自身 viewport 将该无量纲增量换算为 logical 距离，并在边界处返回未处理或零实际位移。

事件先沿 root → target 执行 opt-in capture，再从 hit-test target 向祖先冒泡；capture 保留窗口 logical 指针坐标，target / bubble 为每个当前节点换算 local logical 坐标并补偿祖先滚动偏移。返回 `EventResult::Handled` 即停止；无障碍状态为 `disabled` 的节点不得成为 Tab / FocusHandle / hover 目标，也不得建立 pressed、drag 或 keyboard activation；reconcile 将节点切为 disabled 时，须在 patch 前清除该子树 hover（原目标收一次 `PointerLeave`）、终止 potential / active pointer gesture（活动拖拽发一次 `DragEnd`、pressed 目标收 `PointerLeave`），再向当前焦点子树发送 `FocusOut` 并取消 outstanding keyboard activation，避免新配置的 disabled 早退吞掉清理。捕获阶段拦截 `PointerDown` 时同步撤销命中目标的 pressed / potential drag，不得在后续释放合成目标 Click 或 Drag；拦截 `PointerUp` 时仍以 `PointerLeave` 取消原 pressed 目标并窄标脏，禁止遗留激活视觉。键盘 Enter / Space 只允许一个 outstanding activation：首次已处理 KeyDown 锁定目标、键与修饰键，自动重复和另一激活键被吸收，匹配 KeyUp 回到同一存活焦点目标后才合成一次 Click；任意实际焦点切换先取消该激活，再向旧目标发送 `FocusOut` 清理视觉。`WindowBlur` / `WindowMinimize` 清除本窗 hover、终止 potential / active pointer gesture 和 outstanding keyboard activation：活动拖拽按最后位置发出一次 `DragEnd`，每个受影响的 hover / pressed 目标至多收到一次 `PointerLeave`，焦点目标收到 `FocusOut` 清理键盘 pressed；窗口 focus 状态幂等切换，逻辑键盘焦点身份保留，但停用 / focus 分别只向该目标与 focus-within 路径发送一次 `FocusOut` / `FocusIn`，`WindowRestore` 不冒充 `WindowFocus`。停用状态拒绝随后迟到的 Pointer、Wheel、FileDrop、Key、TextInput、IME 与 Copy/Cut/Paste，不把旧输入交给保留的逻辑焦点，也不得重新建立 hover、pressed 或 drag。`PointerDoubleClick` 在每个节点先按专用变体派发，节点未处理时在同一节点回退为第二次 `PointerDown` 后才继续冒泡，确保内层普通控件不会被外层双击手势抢占。

View 的 `.on_event` / `.on_pointer` / `.on_key` / `.on_focus` / `.on_scroll` handler 作为节点元数据随 build 与 reconcile 替换，先于组件 `EventHandler` 执行；返回未处理才进入组件和父节点。`*_capture` 使祖先参与捕获。`.on_pointer` 明确选择连续 PointerMove；其他 View 不改变边界感知快路径。`focusable(true)` / 正 `tab_index` 只登记该节点的 Tab 顺序，不产生 timer、frame request 或跨窗状态；`.focus_handle(&handle)` 绑定应用持有句柄，reconcile 保留同一节点身份时换绑，remove / root reset / session shutdown 时失效。

### SemanticEvent —— 语义事件

组件可将原生输入转为高层语义动作，供 `on_semantic` 回调、Agent Bridge 以及 `ComponentHandle::emit()` 消费：

| `SemanticKind` | 触发源 |
|----------------|--------|
| `Click` | 鼠标左键 / Enter 键 |
| `Change` | 值变化（Input、Select、Slider） |
| `Submit` | 表单提交 |
| `Cancel` | Escape 键 / 取消按钮 |
| `Toggle` | Space 键（Checkbox/Switch） |
| `Navigate` | 方向键导航 |
| `Select` | 选项选中 |
| `Scroll` | 滚动偏移变化 |
| `Expand` | 展开/折叠 |
| `Custom` | 用户自定义 |

`SemanticPayload` 携带具体数据（点击坐标、变化值、选中等）。

### HandlerTable

`WidgetTree` 按 `ComponentId` 索引 `HandlerTable`，每个节点可注册多个 `HandlerRegistration`（按 `SemanticKind` 分组）。Reconcile 时同类型同 key 复用，不同 key 替换，适配 `State` 指纹绑定。

原始 `SystemEvent` View handler 直接属于 `BoxedWidget`，不进入语义 `HandlerTable`；reconcile 整体替换同节点声明，remove / root reset 随节点释放。无 handler 且组件无 `EventHandler` 的节点不参与交互态缓存判定。
