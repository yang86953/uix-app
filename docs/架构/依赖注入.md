> 分类：依赖注入
> 权威范围：应用级服务注册、解析与生命周期机制

## 容器

`app` 层提供 `Container`（prelude 别名 `DiContainer`）——基于类型的轻量服务注册与解析。自定义服务在 `App::run()` 前经 `App::singleton` 注册；`.settings(path)` opt-in 时，框架在进入运行模式前 load 并注册 `SettingsService`。字体与图片服务由图形运行时直接持有，不冒充可解析单例。

- 注册：`App::singleton(impl Any + Send + Sync)`，或直接使用 `container.singleton(...)`
- 解析：`handle.resolve::<T>()` 返回服务的 `Clone`，`container.resolve::<T>()` 返回容器内引用
- 生命周期：与 App 同寿，窗口间共享
- `SettingsService` 的 Clone 共享同一锁保护状态，load / save 是冷路径
- 标量 codec 仅做 `Display` / `FromStr` 内存转换；`settings-serde` 结构体 codec 把单个 key 编成 JSON 字符串，均不触发 I/O
- save 先同步同目录 temp，再把旧文件移入 backup 后安装新文件；load 会恢复“旧文件已移走但新文件未安装”的中断状态，并清理已提交或未提交的 sidecar

依赖容器不承担日志、错误报告、恢复协调、后台任务或生命周期探测；运行保障由独立的 [`Diagnostics`](运行保障.md) 契约负责。
