## 布局

<a id="布局"></a>

布局分两阶段：**measure**（自底向上确定尺寸）→ **layout**（自顶向下分配位置）。

### Constraints

父容器向子节点传递 `Constraints { min: Size, max: Size }`：子节点在约束内自由选择尺寸，返回值被 `clamp` 到约束范围。`-1.0` 表示无上限，`0.0` 表示可为零。

### 容器布局算法

| 容器 | 主轴 | 交叉轴 |
|------|------|--------|
| `column` | 纵向 | 横向填满容器宽 |
| `column_fit` | 纵向 | 横向撑开到内容最大宽 |
| `row` | 横向 | 纵向填满容器高 |
| `row_fit` | 横向 | 纵向撑开到内容最大高 |
| `stack` | — | 子节点各自独立 measure，尺寸取最大 |

- `gap` 在主轴上插入固定间距；`padding` 收缩子节点可用空间
- `expand(true)` 子节点在分配剩余空间时获得弹性份额
- layout invalidation 仅标记受影响的子树
- 子节点溢出默认参与收敛扩张；Affix 等定位容器保留自然占位并只移动可见子树，不让视觉位移反向撑大父布局
- 事件与 Timer 轮次先批量收集 Paint / Layout / Composite，最外层返回时一次加锁提交；队列以节点索引合并 Paint。`WidgetTree` 按 `tree_version` 借用先序缓存，layout 以复用的根、祖先路径与栈一次收集受影响顺序；layout order、遍历集合/栈、两份扩展签名、已调整子节点集合、父子可见性变更表、收缩操作及 expand / shrink child-id 缓冲均属于每树峰值容量 scratch，在 layout 调用之间继续复用。收敛阶段直接反向迭代同一顺序，不另建逆序 `Vec`。仅计算 positions 的 top-down、viewport 与 parent-slot 阶段直接借用节点 children slice；必须跨 frame mutation 持有 id 的 expand / shrink 阶段不按容器重新 `to_vec()`。Table / VirtualScroll 动态子树刷新仍分别重取全树快照以看到前序 mutation，但复用 layout order 容量，不为三次快照各建临时 `Vec`。layout 尾部 Overlay 重建只保留跨 stack mutation 必需的 entries / 旧状态快照；新签名与旧签名流式比较，focus trap 恢复直接查询重建后的 stack，不再另建两份派生列表；动画节点的 owner Overlay 一致性检查同样只读取 0/1/第二个匹配项，第二项即按重复失配，不收集 owner 列表。触发生命周期回调前必须冻结的 `(id, should_be_active)` 快照使用每树峰值容量 scratch，并在回调完成后归还；同轮 AppState 同步直接复用该快照，不再重新全树遍历，`set_app_state` 的独立初始化扫描不变。Timer discovery 临时取出并清空 route map，使全树扫描只读借用 traversal cache，扫描完成再归还复用 map，不复制整树 id。WindowDriver 在释放 AppTimer 队列锁前把 deadline 复制到每窗口峰值容量 scratch；Timer / AppTimer registry 同步以交替代次标记原位更新并清退失效托管项，不再为 desired 集合重建临时 map。每帧动画工作同步把 `AnimatedSource` 与 ViewTransition 直接汇入同一注册缓冲，注册后由 `ActiveWorkRegistry` 自身判断 managed ownership，不复制第二份 managed id；registry 直接处理旧集合移除项和新集合当前项，不再构造 affected union set。WindowDriver 在 registry 即将因本帧同步而 mutation 前，把开放动画 id 冻结到每窗口峰值容量 scratch；动画 discovery 直接借用该 slice，组件动画 id 以惰性迭代器送入 registry；树 mutation 前必须冻结的动画候选 id 则使用每树峰值容量 scratch，更新完成后归还，均不再逐帧重建。稳定性判定、Timer 路由、Overlay membership / trap 恢复、生命周期回调与 AppState 同步顺序、动态刷新顺序、动画发现、deadline / 组件动画优先级、可见性同步时机及 10×3 上限不变
- 同一节点的 Layout 失效在队列中只保留一项，重复请求仍递增 revision，保证帧内新工作不会被条件清空；向上传播使用每树峰值容量祖先链缓冲，重复传播既不扩张队列，也不为每次调用新建 `Vec`。子项描述只取得一次 `WidgetLayout` 能力对象再读取 flex / margin / grid 元数据；Phase 2 的显式尺寸锁和滚动溢出轴直接读取布局组件字段，不通过面向语义/自动化的 `SnapshotFields` 构造拥有型快照
- Masked Modal / Drawer 在进入 overlay 时请求布局，把普通流占位收缩为零；离场动画完成、切回关闭态触发器时必须再次请求布局，恢复 96×32 的可聚焦/可命中槽。只在关闭开始请求一次会让动画后的 frame 高度永久为零，破坏后续重复打开
- `ActiveWorkRegistry` 在同一次有序 `retain` 扫描中把到期 work 写入 WindowDriver 的每窗口峰值容量 scratch，并同步删除到期 entry 与 Timer 托管标记；不再为 due 集合逐轮分配或逐项二次树查找，派发顺序不变
- declarative animation registration 与开放组件动画集合也使用持久有序 map 和交替代次标记原位同步；移除一侧时按另一侧恢复 open / deadline，不再逐帧重建 desired map / set
- `AppTimerQueue` 在 deadline 集合的插入、成功移除、fire 与 interval 重排时递增队列内 revision；每个 WindowDriver 只在 revision 变化时刷新其 deadline scratch 并同步 registry，未变化轮次不复制或重扫，快照后仍先释放队列锁再进入 registry

### Grid

普通 Grid 由 `GridTrack::{Px, Fr, Auto}` 定义列/行，自动放置按源顺序寻找完整可用矩形；超过显式列数的 column span 在求解入口截断，防止自动放置搜索无法收敛。非拉伸对齐先从单元格扣除 margin，再以子节点固有尺寸计算 Start / Center / End；Stretch 使用剩余单元格尺寸。非有限 gap、轨道和 Flex 因子以及负轨道 / 负 Flex 因子统一归零，输出 frame 不传播非法尺寸。

响应式 Grid 固定 24 个 `Fr(1)` 单元，以本 Grid 内容区的 logical 宽度解析 `Breakpoints`；每次正常 layout 都重新计算 `Col` 的当前 span，并将 offset/order 转成无重叠的显式 cell 后交给同一 `GridLayout`。resize 只使受影响窗口的布局子树失效，不登记轮询、帧请求或跨窗状态。`order` 不改 WidgetTree、事件或语义顺序；reconcile 同步断点/列配置并保留既有子节点运行态。

Flex 求解输入把尺寸、margin 与伸缩元数据合并在同一借用切片，Grid 求解借用组件轨道；普通 Grid 不复制响应式子项，跨度矩形由首尾轨道位置常数时间求得。求解器仍只返回本轮 positions / total size，不缓存跨树状态，也不改变 WidgetTree 收敛上限。
