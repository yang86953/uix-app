# 依赖治理

[← 返回架构索引](../架构.md)

> **接口**：持有外部依赖的维护成本、按需能力、历史计数口径、候选手段与保留清单。依赖：[使用方按需编译](使用方按需编译.md)——capability 收纳解决「未选能力不进图」，本文解决「已进图的依赖要更少」。导出：原则表述 → [定位与原则](../产品/定位与原则.md)。

## 适用线索

需要回答「外部依赖数量目标是什么、怎样计数、新增依赖有什么门槛、哪些依赖明确不削」时，以本文为准。

## 权威范围

本文持有外部 crate 的选择与复核原则。具体改动与验证结果归项目任务（内部历史记录，不作为公开版本说明）；历史数字只作对应日期的观察，不承担当前状态看板。

## 目标

方向：保持正确性、平台覆盖和按需编译，控制实际构建成本、制品体积、资源与维护风险。不以 crate 数量净下降替代收益判断，也不为凑数重写成熟 Unicode/VT/平台能力。2026-09-08 按用户本轮架构优化授权，退役无实际成本证据支持的全仓数量棘轮；不改任何 Cargo 依赖或默认 feature。下表保留旧方案与理由，均为历史候选而非现行验收标准。

| 阶段 | 目标 | 前提 |
|---|---|---|
| G1（下一功能版本） | 默认图 ≤ 68，最小图 ≤ 49 | 只使用 P1 手段，不改公开行为契约 |
| G2（产品决策后） | 默认图 ≤ 55 | 完成 P2 中至少一项默认能力收纳决策并重估数字 |

G1、G2 原为数量目标，现已退役；未来只有具体构建/维护证据成立时，才对单个候选另行派发，不按本表自动排期。

## 计数口径与基线

计数按 crate 名去重、剔除工作区成员，含构建期过程宏栈（它们同样占用使用方构建时间与供应链面）；平台 target 依赖按当前宿主解析，Linux 图含 wayland 栈、不含 windows/objc2 栈。

```bash
# 默认图
cargo tree -p uix-app --edges normal --prefix none \
  | awk '{print $1}' | sort -u \
  | grep -vE '^(uix|uix-derive|uix-lang-compiler)$' | wc -l
# 最小图：同一命令追加 --no-default-features
# demo 二进制
cargo tree --manifest-path demo/Cargo.toml --edges normal --prefix none \
  | awk '{print $1}' | sort -u \
  | grep -vE '^(uix|uix-derive|uix-lang-compiler|uix-lang-demo)$' | wc -l
```

基线（2026-09-05，v0.0.8，Linux 宿主）：

| 口径 | 外部 crate 数 |
|---|---|
| uix 默认 features | 75 |
| uix 最小图（`--no-default-features`） | 51 |
| uix-lang-demo 二进制 | 82 |

Windows/macOS 目标图随 target 解析不同，不设独立数字；新增依赖论证义务对实际受影响目标生效，不要求无关平台重计。

## 削减手段分级

### P1（不改公开行为契约，可直接排期）

| 手段 | 预期收益 | 说明 |
|---|---|---|
| 图片栈窄化：`image` 换 `png` + `zune-jpeg` 直用 | 默认图 −5～−8 | image-codecs capability 实际只消费 PNG/JPEG 解码；`png` 已在 agent-control 图内，收益集中在 `image`、`moxcms`、`pxfm`、`zmij`、`quick-xml` 等。涉及约十个源文件的类型替换，行为由现有快照公开 API 测试覆盖 |
| `tracing` 关闭 attributes feature | 各口径 −2 | 全库无 `#[instrument]` 使用；消除 `tracing-attributes` 并解除 syn v2/v3 双版本并存 |
| 被动收敛 `miniz_oxide` 双版本 | −1（与上重合） | 由 png/flate2 上游版本对齐自然消除，不单独排期 |

### P2（改变默认交付行为或公开契约，须决策后另行排期）

| 手段 | 影响决策点 |
|---|---|
| 默认 features 收纳（image-codecs、qrcode、form-pattern 不再默认启用） | 开箱即用范围收窄；默认图可降至最小图附近 |
| 日志契约内化（`tracing` → 内部门面） | 改变已文档化的「日志契约仅保留 tracing」承诺 |
| plasma shadow 协议降级为可选 feature | 默认构建失去 KDE 窗口阴影，需与桌面兼容性取舍一并决策 |

### 保留清单（不作为削减对象）

- `wayland-client` 及协议族、`windows`、`objc2` 平台绑定：平台窗口、输入与合成器协议的必需边界，自研等于重写平台层。
- `rustybuzz`、`ab_glyph`、`unicode-*` 文本与断行栈：复杂脚本 shaping 与 Unicode 算法正确性优先，自研风险不可接受。
- `libc`、`bytemuck`、`vte`：薄封装或成熟状态机，替换收益低于维护成本。
- 过程宏栈（`syn`、`quote`、`proc-macro2`、`serde_json`）：uix-lang 编译期转 Rust 的既有契约。

## 变更与验收规则

1. 新增或替换依赖时，在对应任务/提交说明其用途、feature/target范围、许可与合理替代方案；已有成熟能力优先复用，不为少一个crate增加高风险自研。
2. 只有提出构建成本或体积优化主张时，按受影响配置测量；依赖计数作为辅助信息，不设无证据净增长审批门槛。默认能力/公开行为、许可风险或重大产品方向变化仍先由策划决定。
3. 保留清单体现当前合理选择，不构成永久不可替换清单；有实测收益时可重新评估。方案变更不降低已有业务/安全保证。

## 验证

- 依赖治理是构建图事实，不建立项目测试；按「计数口径与基线」中的命令人工复核。
- P1/P2 手段落地时，按受影响面运行对应 `*_public_api` 测试；仅在实际影响诊断契约时补对应验证，不因触及src而全量审计。
