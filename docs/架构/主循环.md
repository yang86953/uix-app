> 权威范围：事件、帧机会、休眠、恢复与逐窗调度不变量

## 主循环

<a id="主循环要点"></a>

事件循环三态；surface 可用性是正交的逐窗状态：

| 轴 | 状态 | 含义 |
|----|------|------|
| `LoopState` | `DeepIdle` / `RegisteredActive` / `Active` | 无待办并阻塞；等待已登记 deadline / frame callback；已有可立即执行工作 |
| `SurfaceState` | `Renderable` / `Suspended(reason)` / `Recovering { retry_at, attempt }` / `TerminalFailure` | 可提交；等待 expose / 非零 extent / surface 恢复；按 typed 原因有界重试；不可恢复吸收态（无 deadline / frame request，仅随窗口 session 重建退出） |

### 必须

- `DeepIdle`：无待处理事件、queue、due work、reconcile，也无 outstanding frame request / recovery deadline。`Suspended` / `TerminalFailure` 窗的 dirty 不算可立即执行工作。
- wake ∈ {OS / 生命周期、queue、due deadline、frame opportunity、recovery / availability deadline}；一窗 wake / Active 不得把他窗拉成 Active；`TerminalFailure` 窗不因普通生命周期 / surface 信号重开视觉帧。
- 每个 `Active` 轮次先非阻塞分发挂起的 OS 事件，再执行 due work / frame；连续动画、Agent settle 或其他持续工作不得饿死输入、生命周期、关闭与跨线程 wake。
- **事件轮次**：批量 drain UiEvent + 同步 semantic → due 非视觉工作 → `post_to_ui` → AppState focus / semantic → Effect；同一目标窗的相邻 `WindowResize` 在进入窗口驱动前按最后尺寸合并，输入、生命周期或其他窗口事件仍是保序屏障，因而每批只为最终尺寸重建一次 engine / presenter；其余阶段只合并 dirty / reconcile，并为该窗申请至多一个 frame request。
- **帧轮次**：收到 `FrameOpportunity { request_token, frame_time, target_present_time? }` 后，消费截至该点的最后一次 root → **一次** reconcile → 按需 layout → paint → 至多一次 present。成功才消费 dirty；提交后仍有动画 / dirty 才申请下一次。
- frame request：one-shot、可合并、逐窗所有；`request_token = surface_generation + request_id`；原生回调只可完成完全相同的 outstanding token。fallback / surface 变化 / suspend 消费或取消 token 后，不能取消 OS 对象的 backend 必须抑制迟到回调。
- 动画保持 open registration，全窗只维护一个下一帧请求；`dt` 来自 frame opportunity 单调时间。`Suspended` 时取消视觉 deadline、冻结动画，恢复首帧 `dt = 0`，不补跑隐藏帧；业务时间继续由 Timer 表达。
- `Hidden` / `Minimized` / zero extent → `Suspended`：保留 dirty 与 animation registration，取消视觉 deadline，不 layout / paint / present。`WindowHide` / `WindowShow` 是逐窗生命周期信号；视觉阶段前复核真实可见性。延迟首显在第一次成功 present 前豁免；可用性信号只解除匹配的 suspend reason；`TerminalFailure` 为吸收态，普通 suspend / resume / surface change 与迟到 failure 均不得降级或重开 frame request，只能随窗口 session 重建。
- `SurfaceLost` / `OutOfDate` / `WouldBlock` → `Recovering` 或等待生命周期信号；重试有界并以 deadline 登记；持续失败不得因 retained dirty 形成 Active busy loop。`DeviceLost` 走同 API recipe → Software FSM，各步只尝试一次；`begin_frame` 内更换 engine 后，`FrameRenderer` 与 `WindowDriver` 须重读新 capability 并在同帧采用新提交协议。Software CPU 帧经窗口唯一 `ExternalPresenter` 成功才重置序列，重建或提交再失败则进入无 deadline 的 `TerminalFailure`。`OutOfMemory` 直接进入同一终态，不静默回退，也不接受普通生命周期恢复。
- 图形 engine 只返回 typed failure；普通遮挡为 Debug 可用性事件，其他最终 present 失败只由 `WindowSession` 边界记录一次 Error。
- 脏区尽量窄到 rect / Composite / 节点；同帧多个滚动视口分别登记 viewport + delta，统一并入 dirty / clear，保留到提交成功；禁用单槽「最后滚动覆盖」。

### 禁止

固定 16ms / interval 探活；DeepIdle 下 `tick_effects`；未 register 的周期工作；以 WebView 充当呈现或布局运行时；因 retained dirty 在不可呈现或持续失败时保持 Active busy loop。

### 平台帧机会与遮挡

各平台须按自身契约实现 one-shot frame callback（静态窗不创建节拍）。DWM/display link/`wl_surface.frame` 均不等于逐窗遮挡；遮挡检测须用本窗独立 compositor/window-server 能力。

- **Windows**：live recipe 以 `GraphicsContextCaps::present_occlusion` 声明能力。`PresentStatusAndTest` recipe：`Present` 返回 [`DXGI_STATUS_OCCLUDED`](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/dxgi-status) → `Suspended(Occluded)`，100 ms→1 s 有界 [`Present(…, DXGI_PRESENT_TEST)`](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/dxgi-present) 探测。`Unsupported` recipe 不登记遮挡 probe，只依赖 Hidden/Minimized/ZeroExtent 生命周期休眠。禁 DWM/帧机会冒充遮挡。
- **macOS**：[`windowDidChangeOcclusionState:`](https://developer.apple.com/documentation/appkit/nswindowdelegate/windowdidchangeocclusionstate%28_%3A%29?language=objc) 只 wake 目标窗；Visible 只解除精确 Occluded（无探测 deadline），恢复首帧 `dt = 0`。
- **Wayland**：`wl_buffer.release` 前 busy；双 busy → `WouldBlock` 保留 dirty。遮挡需 `xdg_toplevel.state.suspended`(v6+)；禁 frame/activation 冒充。Clipboard 与 display 同 poll、nonblocking、64 KiB 预算；`set_selection` 只用真实 press serial。
