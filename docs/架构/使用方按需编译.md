# 使用方按需编译

正式构建入口是 `uix build --release --config uix.json`。项目只有两个自有 Cargo package：
`uix-app` 拥有机制、原生平台、UIX 语言及构建工具，`uix-widgets` 拥有具体控件、Ant Design 主题和资源。
第三方依赖不受“两包”数量约束；不再生成自有辅助包或过程宏包。

框架主体的细分能力与不兼容迁移见[框架能力拆分](框架能力拆分.md)。

## 使用根

```json
{
  "packages": [
    {"path": "../uix-app"},
    {"path": "../uix-widgets"}
  ],
  "sources": ["ui/main.uix"],
  "rust": ["uix-app/opengles"],
  "dynamic": []
}
```

`sources` 指定的 UIX 根及其可达导入、组件、数据构造和主题映射自动产生所需单元。
未引用的 Widget 定义不会激活它的实现依赖。
Rust 直接调用如 `button()` 时在 `rust` 加入 `uix-widgets/button`；动态候选在 `dynamic` 中声明。
框架计算所有传递依赖和资源，不要求使用方展开控件依赖，也不要求组件提供 feature 或运行裁剪代码。

## Cargo 前构建

框架读取候选库的描述，校验归属和依赖，计算闭包，按源码内容、目标平台和配置生成不可变缓存：

```text
target/uix/views/<fingerprint>/
  application/Cargo.toml
  packages/uix-app/Cargo.toml
  packages/uix-widgets/Cargo.toml
  resources/
  plan.json
```

仅已选库出现在实际应用目标依赖边中。缓存包保持原 package 名和版本；模块入口、共享门面及枚举分支按声明选择。
可选第三方候选可保留在清单供 host 构建解析，只有所选依赖被目标 feature 激活。
构建工具运行在 host，应用运行在显式 target；目标不能因为 host 编译器使用 `syn`、`quote` 或解析器就携带它们。
源码仓库与原 Cargo 清单不被修改。源码在生成期间发生变化时构建失败并要求重新计算，半成品缓存不会被发布。

未选控件及其专属依赖必须不参加目标编译；最终资源只能来自相同计划中的资源闭包。
LTO 仍可消除已选单元内不可达符号，但不作为这项隔离承诺的替代。
`--plan` 生成并打印计划，不执行 Cargo。正常命令将可执行文件、所选资源和计划交付到 `target/uix/dist/<fingerprint>/`。

## 动态边界

正式构建把动态闭包和相关库声明嵌入生成的框架源码。
模块装载、脚本装载与 `with_ui_decoder` 登记都检查该白名单，不靠运行时扫描磁盘上的新库扩大能力。
例如动态 Input 使用 `uix-app/uix-dynamic` 与 `uix-widgets/input`；脚本 UI 使用 `uix-app/extensions` 与 `uix-widgets/ui-projector`。
开发仓库的普通 Cargo 构建保留完整调试入口；正式交付的隔离保证以该预构建入口为准。

## 验证

验证应检查实际 `rustc` 目标输入/依赖与交付资源，并运行所选行为；只比较可执行文件大小不足以证明“不参与编译”。
新增库可以通过 `CompilerSystem` 与 `ComponentCatalog` 公开接口验证，不依赖官方控件名字。
