# 路由清单

[← 返回架构索引](../架构.md)

> **接口**：适用于审查 UIX 全部进程内同步订阅。通用 SMC 治理要求 G-05 规定每条同步订阅必须进入可审查的路由清单，记录事件契约及所有者、发布方、订阅方、事实建立点、注册位置、Bus 作用域、执行上下文、延迟或阻塞预算、失败策略、重入策略和生命周期所有者。通用角色与不变量以[通用 SMC 文档](<file:///C:/data/note/程序开发/System%20Module%20Component%20设计模式.md>)为唯一权威；本文档权威持有 UIX 的当前登记与治理流程。导出：架构审查。

## 术语对照

| 通用 SMC 概念 | UIX 落点 | 说明 |
|---|---|---|
| `ModuleEvent` | Module 私有边界事件类型 | 由 Module 拥有，把 Component 窄输出映射为可广播事实 |
| `SystemEvent`（SMC） | System 私有边界事件类型（如 `app::app_events::ThemeApplied`） | 跨 Module 事实广播契约，由 System 私有边界拥有 |
| `DomainEvent` / `TechnicalEvent` | 语义分类 | 与所有权分类正交，不要求统一命名 |

**命名冲突裁决**：UIX 历史类型 `ui::event::SystemEvent` 是「UI 输入语义事件」（指针/键盘/窗口事件传播），与通用 SMC 的 `SystemEvent`（System 私有边界跨 Module 事件契约）概念不同，不重命名公开 API；本清单及架构文档引用 SMC 概念时使用「SystemEvent(SMC)」措辞区分。

## 登记模板

| 列 | 必填 | 说明 |
|---|---|---|
| 事件契约 | 是 | 类型名（UIX 内部类型或 SMC 事件契约） |
| 契约所有者 | 是 | System 私有边界 / Module / 模式外基础设施 |
| 发布方 | 是 | 代码位置（文件:行 或模块） |
| 订阅方 | 是 | 代码位置（文件:行 或模块） |
| 事实建立点 | 是 | 发布前必须越过的事实边界；非事实广播标注「输入事件，非事实」 |
| 注册位置 | 是 | 组装期注册点（文件:行） |
| Bus 作用域 | 是 | 窗口 / Module / System 作用域 |
| 执行上下文 | 是 | 主线程 / 发布者线程（同步沿用） |
| 延迟/阻塞预算 | 是 | 处理器最长耗时预算或「无声明」 |
| 失败策略 | 是 | 隔离并继续 / 汇总技术失败 / 直接契约（不适用） |
| 重入策略 | 是 | 禁止 / 延迟生效 / 快照（含嵌套深度限制） |
| 生命周期所有者 | 是 | 持有订阅句柄并负责释放的对象 |

## 当前登记

### 模式外基础设施（`src/bus/`）

| 列 | 值 |
|---|---|
| 事件契约 | 由各消费 Module/System 定义并拥有的类型化事实（如阶段 D 试点事件） |
| 契约所有者 | 消费方边界（Module / System 私有边界） |
| 发布方 | 事实建立点之后的业务代码（经 `EventBus::publish` 或窄端口 `Publisher<F>`） |
| 订阅方 | 组装期注册的 Module/System 处理器 |
| 事实建立点 | 按各事实在下方「当前登记」中声明 |
| 注册位置 | 所属 Module/System 组装期（组合根只执行注册动作，不决定业务路由） |
| Bus 作用域 | 单 Module / 单 System（禁止跨 System 共享） |
| 执行上下文 | 发布者上下文（同步沿用，单线程基础设施 `!Send + !Sync`） |
| 延迟/阻塞预算 | 处理器应短小有界；`publish` 同步执行全部匹配处理器 |
| 失败策略 | 隔离并继续（panic 隔离计数）；`DispatchReport` 仅诊断，不充当业务应答 |
| 重入策略 | 处理器不可重入（占用中跳过并计入 `skipped`）；嵌套发布深度上限 64 |
| 生命周期所有者 | 订阅方持有 `Subscription` 句柄（Drop 自动注销，幂等；Bus 关闭后空壳） |

> 本表描述基础设施使用规则；具体事件的登记见下方「app 主题变更试点」。

### app 主题变更事实（阶段 D 试点）

| 列 | 值 |
|---|---|
| 事件契约 | `app::app_events::ThemeApplied { is_dark, revision }`（SystemEvent(SMC)） |
| 契约所有者 | app System 私有边界（`src/app/app_events.rs`，任何 Module 不拥有） |
| 发布方 | `App::run` 主窗口循环（`src/app/application/application/mod.rs`）两处：① `apply_runtime_theme_change` 完成主题替换后（应用指定主题路径）；② 系统主题事件转发闭包（OS 深色模式切换路径，主窗口循环唯一转发目标，同一事实仅发布一次） |
| 订阅方 | 主题变更诊断遥测（tracing 发射，`target: "app.theme"`） |
| 事实建立点 | 新主题已写入主题槽并分发给全部窗口 UI 树（两条路径各自生效后）；失败或回滚时不得发布 |
| 注册位置 | `App::run` 组装期（主窗口循环启动前，`src/app/application/application/mod.rs`） |
| Bus 作用域 | 单主窗口会话（System 私有边界实例，随会话结束释放） |
| 执行上下文 | 主线程（同步沿用） |
| 延迟/阻塞预算 | 遥测处理器为 tracing 宏，有界 |
| 失败策略 | 隔离并继续（panic 隔离计数）；发布失败可诊断（tracing::error） |
| 重入策略 | 处理器不可重入（占用中跳过计入 `skipped`）；嵌套深度上限 64 |
| 生命周期所有者 | `App::run` 持有 `Subscription` 句柄，会话循环结束后 Drop 注销 |

### 平台输入事件分发（`native::windowing::event::EventBus`）

| 列 | 值 |
|---|---|
| 事件契约 | `UiEvent`（`UiEventType` 精确类型分发） |
| 契约所有者 | platform System 私有边界（windowing Module） |
| 发布方 | `native::windowing::event::EventBus::publish`（`src/native/windowing/event/bus.rs`） |
| 订阅方 | 当前无业务订阅者：UIX 事件路径经 `map_event → tree.dispatch_event` 直接分发；本通道为 platform 私有预留分发点（发布为 no-op） |
| 事实建立点 | 输入事件，非领域事实广播；不适用 FactEstablished |
| 注册位置 | `IPlatform::event_bus()` 返回的 Bus 上注册（组合根/会话运行时） |
| Bus 作用域 | 单 Platform 实例 |
| 执行上下文 | 主线程（UIX 线程亲和窗口事件） |
| 延迟/阻塞预算 | 处理器应短小有界；`publish` 同步执行全部匹配处理器 |
| 失败策略 | 已治理：移除 `-> bool` 命令式返回（事件分发不承诺业务应答）；panic 沿发布调用传播，属平台私有进程级缺陷 |
| 重入策略 | 未声明支持处理器内注册/注销/嵌套发布；业务代码不得依赖（登记为已知边界） |
| 生命周期所有者 | 订阅方各自持有 `usize` 句柄并手动执行幂等 `unsubscribe`；验证必须覆盖重复注销、Bus 关闭与目标失效，不在本清单记录动态通过数量 |

### 诊断恢复订阅（`diagnostics`）

| 列 | 值 |
|---|---|
| 事件契约 | 精确 `Errc` 对应的 typed `Error` 恢复处理器（`RecoverySubscription`） |
| 契约所有者 | diagnostics System 公开边界 |
| 发布方 | 资源 owner 在安全线程调用 `Diagnostics::attempt_recovery` |
| 订阅方 | 应用会话或资源所有者显式登记的恢复处理器 |
| 事实建立点 | typed failure 已到达资源 owner 的安全边界并请求恢复；最终报告事实尚未建立 |
| 注册位置 | `Diagnostics::on_error` 公开契约 |
| Bus 作用域 | 单 Diagnostics runtime |
| 执行上下文 | 调用方选择的安全 owner thread（同步、锁外执行 handler） |
| 延迟/阻塞预算 | handler 必须短小有界；耗时重建只登记到资源所属状态机，不在回调内阻塞 |
| 失败策略 | `Recovered` 停止最终报告；`Unhandled` / `Failed` 保留原 Error 并由最终责任边界报告一次 |
| 重入策略 | 同线程递归恢复由 guard 拒绝；handler 不得再次同步触发同一恢复链 |
| 生命周期所有者 | 登记方持有 RAII `RecoverySubscription`；runtime closing 前注销，Drop 幂等 |

## 治理流程

1. 新增任何进程内同步订阅（EventBus 订阅、恢复回调、事件源注册）时，先在本清单登记再提交；
2. 同步订阅纳入依赖环、锁顺序和最长调用链审查：登记时检查订阅方是否反向依赖发布方边界、是否持有发布方可能再取得的业务锁；
3. 每次 SMC 变更人工复核路由清单与代码映射；该私有结构不建立项目测试；
4. 清单中的「待治理」或「无声明」项必须有明确收敛任务，发布前不能把未知阻塞、重入或生命周期风险当作已解决；
5. 试点订阅一旦保留为长期路径，就按普通登记维护，不继续使用阶段名代替契约状态。
