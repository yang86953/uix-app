## 1. 目标与典型场景

已运行的 UIX 应用能够装载扩展包，增加或替换软件功能与界面，并在正常情况下无需重新编译、重启宿主。扩展可以只有业务逻辑，没有窗口；动态 UI 是同一扩展机制的一种输出。

| 扩展方向 | 目标行为 | 所有权边界 |
|---|---|---|
| 命令与业务规则 | 增加文本转换、校验器、导入导出策略、应用命令 | Lisp 扩展拥有自己的算法与状态；宿主决定可调用的业务端口 |
| 事件与流程 | 订阅应用公开事件、组合宿主操作、跟踪异步完成 | 宿主持有执行、取消及外部副作用责任，扩展保存流程状态 |
| 服务扩展点 | 为宿主预先定义的能力接口增加可替换实现 | 经版本化端口调用，不任意替换 Rust singleton 或私有对象 |
| 动态界面 | 新增面板、页面、菜单项、交互绑定，更新结构、样式和内容 | 挂载位由应用开放，布局、输入、焦点与渲染由 ui System 托管 |
| 运行中演进 | 加载、启用、停用、热替换、迁移状态、卸载 | 每个扩展有稳定身份、活动代、资源归属和可观察终态 |

例如：应用启动后加载一个“文本处理”扩展；它在无窗口模式中提供转换命令，在 GUI 中向编辑器工具区增加面板。替换扩展后，转换规则和面板布局共同升级，兼容的输入草稿保留；卸载后命令、订阅、任务与面板全部退出，宿主继续运行。

范围包括扩展自身的业务逻辑和流程，不能只做字符串模板、皮肤切换或预编译组件显隐。范围受宿主已编译并开放的能力限制：Lisp 可以组合已有原语形成新功能，不能凭脚本增加尚未编译的 OS backend、原生驱动或任意 Rust 类型。

首期不承担插件市场、下载更新器、跨网络分发、原生动态库 ABI、Rust 机器码热替换或任意私有状态访问。扩展的网络、数据库、文件与进程操作仍经宿主显式开放的端口访问；网络与 ORM 已纳入[完整应用框架目标](../../产品/能力.md#完整应用开发能力目标)，这些端口可接入后续框架服务。服务由框架提供不等于扩展自动获得访问权，本节首期边界不排除整个框架的网络或数据能力。

## 3. 标准 Lisp 与宿主环境

### 语言基线

本方案按小贝的选择采用 **Scheme，R7RS-small** 作为 Lisp 扩展语言；不把“Lisp”解释为自制 S 表达式命令表，也不混用 Common Lisp 语法。依据是 [R7RS-small 工作组正式报告入口](https://small.r7rs.org/wiki/R7RSHomePage/)及其勘误；[可检索标准正文](https://standards.scheme.org/r7rs-html5/index.html)用于定位章节（核对日期：2026-09-06）。

语言语义与宿主 API 分别版本化：词法作用域、尾调用、宏、数值、record、continuation 和库语义以标准为准；`(uix extension)`、`(uix commands)`、`(uix events)`、`(uix tasks)`、`(uix ui)` 等拟议库提供普通过程、值与标准宏，不引入 UIX 私有求值规则。应用自有业务库使用独立命名空间。

合规矩阵逐项区分标准必需语义、标准允许的实现选择、受宿主策略限制的环境能力和尚未实现项。限制 I/O 不得掩盖宏卫生、库隔离、尾调用或 continuation 语义缺陷；仅有语法外形相同不算标准兼容。在覆盖不足时明确称“R7RS-small 实现中的受限宿主环境”，不能发布“完整标准兼容”的承诺。

### 能力与标准库

- 导入库按包内声明和标准库登记解析，不搜索任意用户目录。包内 `include` 等来源访问与环境 feature 查询须分别定义兼容行为；缺失功能返回明确错误，不能假装导入成功。
- 标准纯计算与内存端口按兼容矩阵开放；文件、进程环境、时钟、随机源及其他环境访问逐项列清来源与权限。不得仅凭标准库名称进入白名单就隐式开放其全部原语。
- `eval`、`load`、宏展开、动态导入均不能增加权限或绕过源码、步数、分配与取消限制；若某环境入口暂不支持，明确拒绝并登记兼容缺口。
- 标准语言不等于可信执行环境。无任意 FFI、原生库加载、raw window/GPU 句柄或默认 OS 端口。宿主应用可以按需要授权具体业务能力。

### 引擎选择

语言标准先确定，引擎实现随后用证据选择。优先评估小贝引擎能否提取为不依赖 Agent 的独立实现，同时对照已有标准实现的嵌入方案；不把“参考小贝”当成直接复制其私有源码或另造不兼容方言的决定。

选择门槛包括标准语义、Windows/Linux 目标可交付性、可控执行、循环对象回收、宿主借用安全、崩溃边界、许可和构建成本。引擎由 app 扩展实现私有适配，插件不依赖引擎内部值类型或具体品牌。独立 crate、第三方依赖及默认配额均在取证后冻结，本次不修改依赖清单。

## 4. 职责、执行位置与状态权威

沿用 UIX 的 System 边界，新增 app 私有 `extensions` Module，app 对外提供扩展管理窄门面。无需为每种扩展点创建独立 System，也不把现有功能全部强制插件化。

| 所有者 | 拥有的状态与责任 | 协作方式 |
|---|---|---|
| Rust 应用组合根 | 宿主领域真值、能力授权、扩展点定义、启停策略 | 显式创建扩展宿主并注入类型化业务端口 |
| app System / extensions | 包身份、活动代、注册集、执行环境、配额、任务与关闭责任 | 私有实现可直接组合；与兄弟 Module 通过 app 私有契约接线 |
| Lisp 扩展实例 | 扩展算法、局部领域状态、流程状态与导出的版本化快照 | 单实例串行求值；通过授权宿主端口请求外部效果 |
| ui System | 挂载子树、WidgetId、焦点、输入、布局、绘制与组件资源 | 消费经验证的 owned 视图描述；不依赖解释器或反向查找 app |
| data / platform / graphics | 各自已有的数据与平台资源 | 沿既有公开契约访问，不被 Lisp 直接持有私有实例 |
| diagnostics | 结构化错误观察、恢复及最终报告 | app 注入窄诊断出口，避免解释器自行全局安装 hook |

扩展私有业务状态可以由 Lisp 持有；宿主既有业务状态只能通过端口请求修改。状态保存在哪里、谁仲裁写入、是否持久化在扩展点合同中逐项声明，不能把宿主真值复制到无类型字典后双写。

执行映射：文件读取、解析、宏展开和纯计算在扩展执行器运行；每实例只有一个写者，同代回调排队串行。基线使用共享的有界执行资源，按实例轮转调度，不默认每插件一线程。后台 I/O 由宿主异步端口承担，结果以 owned 数据回到原实例队列；UI 修改只在目标窗口 owner thread 消费。UI 帧、布局、绘制与命中路径均不求值 Lisp，不同步等待脚本完成。

本设计最初参考 SMC v2.0，源仓库 `smc` 提交 `2f83bac4595c9edd59d55fa916a14dc21fa9957a`；当时只覆盖此扩展设计。自 2026-09-08 起，全仓版本与范围统一由 [SMC 架构采用](../SMC采用.md)和源码 Cargo 元数据持有。本设计的契约、状态、访问回收、代际、资源、权限及 UIX 组合根注入、兄弟私有实现隔离继续有效；目标能力不因此自动变成已实现能力。

## 5. 扩展包与宿主契约

### 包身份与兼容性

拟议包由清单、`.scm` 源码、声明资源组成。清单持有：`schema_version`、稳定 `extension_id`、版本、内容摘要、入口库、语言标准、宿主 API 兼容范围、依赖及其兼容范围、扩展点、所需能力、状态 schema 版本和资源预算。格式及字段名在实施阶段冻结，当前没有可复制清单。

检查与执行必须使用同一不可变内容快照；入口仅能访问包内规范相对路径。拒绝路径逃逸、链接越界、重复身份、未知必需字段和不兼容版本。摘要表示内容身份，不等于来源可信或授权；宿主策略单独决定可执行来源与能力。

包库依赖先解析成显式闭包，验证缺失、循环、版本和命名冲突。首期支持包内库和宿主库，第三方扩展间运行时依赖后续按明确契约开放；必需依赖暂不支持时直接拒绝。不得用全局可变 Scheme 环境共享两个扩展的状态。存在活动依赖者时，停用或替换提供方必须先验证兼容并排空受影响闭包，否则返回依赖占用，不自动级联卸载。

### 最小公开操作形状

下表描述目标行为，不是已存在的 Rust 方法签名。

| 操作 | 输入与成功含义 | 可观察拒绝或失败 |
|---|---|---|
| 检查 / 准备 | 冻结包、解析入口、验证兼容与能力，生成候选；不发布注册或执行外部副作用 | 来源、语法、兼容、配额、能力或依赖错误 |
| 启用 | 候选成为活动代，完整注册集对新调用可见 | 名称冲突、宿主关闭、初始状态或 UI 预检失败 |
| 调用 / 查询 | 通过命令或服务端口提交类型化输入并取得结果 | 参数不符、不可用、背压、取消、执行或宿主失败 |
| 替换 | 指定稳定 ID、预期旧代和新候选；发布成功产生新代 | 并发版本冲突、排空超时、状态迁移或提交失败 |
| 停用 / 卸载 | 停止新调用，撤销注册并等待资源退出；停用可保留包，卸载释放运行实例 | 依赖占用、排空或回收未完成；不能先报成功 |
| 列举 / 观察 | 查询来源、版本、活动代、能力、状态与操作结果 | 无运行时或已关闭；不暴露脚本秘密值 |

入口返回操作身份和最终结果，区分“已接收”“已激活”“已应用到窗口”“已呈现”“已卸载”。包删除属于宿主的存储管理，不由运行实例卸载隐式执行。无窗口扩展没有呈现状态。

命令和服务名称采用“扩展 ID + 局部名称”，参数与结果 schema、错误、异步、取消及副作用责任明确。宿主服务注册是显式能力表，不开放 `Container` 的任意字符串查找。跨语言数据使用有界 owned 值或不透明代际句柄；大整数、精确数、字节、空值与布尔值按端口 schema 转换，拒绝有损窄化、循环数据和不支持的类型。闭包、continuation、借用引用和 raw pointer 不跨 FFI 或持久化。

宿主异步能力返回操作 ID，终态通知带 `extension_id + generation + request_id`，同一操作只向实例交付一次终态。取消请求不冒充宿主任务已结束；外部效果已发生或结果未知时，由宿主查询、幂等或补偿合同负责，不能靠脚本重跑宣称 exactly-once。

事件合同声明来源、schema、顺序和丢失策略。基线为同实例按接受次序串行处理的进程内通知，不承诺崩溃恢复；队列满时命令明确背压，可重算状态通知只能按已声明的 revision 规则合并。替换期间不接受的新通知不能静默声称已交付，新代激活后通过宿主快照重新同步。不得丢失的业务事件由宿主可靠端口持有确认与恢复责任，不能降级进入普通 UI 事件队列。宿主回调不同步重入同一实例；反馈排队到当前求值结束之后。

## 6. 加载、替换与卸载

```text
包快照 → 校验 → 候选求值与暂存注册 → Ready
Ready → 启用提交 → Active(g)
Active(g) + Ready(g+1) → Quiescing(g) → 迁移与预检 → 提交 Active(g+1)
Active(g) → Quiescing(g) → 撤销注册 → 排空与回收 → Unloaded
```

每个 ID 的生命周期操作串行仲裁，提交校验预期活动代。旧候选重复提交、同时替换与卸载均产生明确冲突或已完成结果，不靠最后写入覆盖。运行实例 generation 递增，永不复用来表示另一份代码。

### 准备与替换协议

1. 新包在独立候选环境中读取、展开、求值，构造命令、事件与 UI 声明。准备和迁移只允许纯计算及被冻结的只读输入；所有登记暂存，计时器、订阅和外部写操作此时不生效。顶层代码也服从这一阶段能力限制。
2. 候选基本预检完成后，暂时关闭旧代的新调用入口，保留其现有注册与视图，等待在途回调和宿主效果达到可交接状态。旧界面可保留显示，但相关动作明确返回正在替换；不积攒无界输入。
3. 在静止点导出旧状态，将 owned 快照交给新代迁移，生成完整注册集和受影响挂载位的候选树，验证身份、类型、能力、容量和窗口存活。
4. app 在明确提交点切换活动代与注册集。单窗首期在同一窗口的串行提交协议内协调界面采用与动作开放，禁止一半新命令配一半旧回调。进入提交点后的内存申请及失败点必须预留或有显式补偿方案，不能假定现有树更新天然可回滚。
5. 新代开放后按其代际接收结果；旧代剩余注册、闭包、环境与资源仅在无非法在途访问时回收。激活后的业务动作独立取得终态，激活成功不表示后续业务必然成功。

提交前失败丢弃候选，原代码和权威状态保留并恢复旧代接收；排空超时可以终止替换。已经取消的任务不能假装仍在运行，回退结果应携带实际终态变化。提交后发生业务错误按新代失败处理，不自动重放外部操作或声称已恢复旧业务事实。需要回退版本时，把旧包作为另一候选，重新校验权限、兼容和反向迁移。

多窗口不承诺同时呈现：逻辑活动代一次发布，每窗按目标代应用并独立回执；未完成切换的扩展区域保持动作门控。窗口关闭返回明确的跳过或失败结果，宿主选择要求全部窗口还是允许部分应用。只有全部必需窗口完成才报 UI 应用完成；GPU 呈现另计。首期不支持的多窗事务请求必须拒绝，不能伪造全局原子结果。

### 停用、卸载与隔离

卸载先拒绝新工作、撤销命令与订阅，按所有者取消计时器和任务，卸载子树，再释放句柄、闭包、continuation、Scheme 堆和包资源。清理钩子受独立的有界预算约束，不得启动新的长期工作或阻止宿主最终关闭；无钩子、钩子失败和重复卸载均有确定结果。

宿主任务仍持有资源或尚未确认取消时，返回“停止中 / 关闭失败”，保留回收责任；不得从登记表消失就报“已卸载”。晚到结果只能用于旧任务终态与释放，不能写入新代或被重新解释为新命令。

未处理的脚本失败停止本次调用；若实例状态无法证明有效则隔离该代并撤销其能力。引擎 panic 后不可复用。普通错误的隔离不等于 OS 进程沙箱，分配失败、native 缺陷等进程故障另属宿主失败边界；需要更强隔离时另评估受监督进程，不虚构进程内硬隔离保证。

## 7. 状态迁移与动态界面

### 状态分类

| 状态 | 替换规则 |
|---|---|
| 宿主领域真值 | 始终由宿主保留，新代通过相同业务端口取得投影 |
| 扩展私有业务 / 流程状态 | 显式 schema 版本、导出和迁移；同 schema 也需校验；不兼容且无迁移时拒绝替换，不能静默清空 |
| 闭包、环境、continuation | 属于原代解释器堆；不序列化、不移植到新代 |
| 输入草稿、选区、滚动、展开、焦点 | 同父范围内稳定 key 与类型兼容时沿 UI 契约保留；类型改变、节点移动或移除时显式重置 / 焦点回退 |
| 外部句柄与在途任务 | 宿主保持资源所有权；只有端口声明支持交接才可重新绑定，否则排空或取消 |

状态快照有字节与结构深度上限，迁移不得修改旧状态或执行外部效果。持久化由宿主明确启用，指定命名空间、codec、版本和原子保存策略；保存失败不覆盖旧持久记录。首期的进程内热替换不承诺崩溃恢复。

### 声明与更新

Lisp 通过普通库过程构造有界 UI 描述值，由 Rust 校验后投影为 UIX 的 `ViewNode`；不解释 `.uix`、不执行 `TypedUiIr`，不把 Scheme 闭包直接送入 WidgetTree。视图生成是纯投影，宿主事件触发 Lisp 更新扩展状态后再提交新声明。

应用以稳定挂载位显式开放扩展区域，原有 AOT `.uix` 与 Rust UI 可以包围该区域。描述覆盖结构、属性、样式、稳定 key、事件入口和语义身份；首期冻结一组足以完成真实交互的 widget，未登记项、字段类型错误或缺失 Cargo capability 在改树前拒绝。复用 UI 语义与已有登记事实；共享元数据必须与编译器执行逻辑分离，不能为动态 UI 把整个编译器带进发布依赖。

UI 身份命名空间包含扩展 ID、挂载位与逻辑 key；generation 属于回调与授权句柄，不自动混入 widget key，否则每次升级都会清空草稿。同一父范围重复 key 拒绝，类型或父范围改变时不保证原地保留。扩展只能提交自己拥有的挂载区域，不能接管宿主或其他扩展树。

UI 事件经已有捕获、目标、冒泡语义路由后形成 owned 事件进入扩展队列。必须同步决定的消费 / 冒泡、默认编辑动作等由预先验证的绑定声明和原生 widget 决定，不能事后等待异步 Lisp 结果改变已经完成的路由。事件绑定带活动代校验，失效回调稳定拒绝。

批量 UI 提交带目标窗口、挂载位、预期 revision 和扩展代；容量、节点、深度、文本和输出字节均有上限。预检失败保留原树；成功接收只说明已入队，应用与呈现由各自回执确认。沿用 reactive、reconcile、damage 与原生调度；空闲不运行固定 Lisp tick 或全树轮询。

现有 `AppHandle::update_view` 可作为接入线索，但其无结果回执和整根替换入口不足以完成上述合同。后续需要公开的挂载位与提交结果能力，并保持既有 API 的兼容性；不能以当前 `()` 返回值推导更新成功。

## 8. 配额、授权与诊断

配额必须覆盖源码和读取深度、宏展开、求值步数、单次执行时间、在途数、队列、注册项、UI 输出、快照和诊断。大数运算、字符串复制及宿主原语也需按实际工作量计费或限幅；只在表达式入口扣燃料不足以保证延迟。各项数值经参考负载验证后冻结。

长期实例需要可回收的堆；必须覆盖闭包与环境互引、循环 pair、continuation 捕获和宿主句柄。小贝一次性执行的累计分配限制不能直接变成长驻实例的终身额度。实例存活字节、单次分配和回收暂停分别约束；采用 tracing GC、arena 或其他方案由证据决定。

实际能力取“包声明 ∩ 宿主已编译能力 ∩ 当前授权 ∩ 当前生命周期允许项”。每次调用在宿主执行入口再次校验资源范围和授权代，不能仅在加载时检查。撤权阻止新效果，已发生或不能取消的效果继续由宿主负责收尾；扩展不能自行扩大权限。UIX 提供授权策略端口，具体是否弹窗确认由应用负责。

错误至少区分包 / 解析 / 标准支持 / 兼容 / 能力拒绝 / 参数 / 背压 / 配额 / 取消 / 超时 / 陈旧代 / 迁移 / 宿主失败 / 引擎污染 / 关闭未完成。诊断携带扩展 ID、版本、代、入口、源位置和操作 ID，不默认记录完整源码、业务参数或凭据。错误先作为结果交给责任方，未恢复错误再按[诊断契约](../platform/diagnostics.md)报告，不能重复写日志冒充处置。

## 9. 与现有交付的关系

本 Scheme 方案及 [P0 第一版合同](extensions-engine.md)继续作为当前实施主线。[UIX 应用模块与动态执行](../../uix-lang/设计/应用模块与动态执行.md)另作为补充方案保留，暂不实现、不改变本方案的语言选择、依赖和阶段验收，也不要求已有扩展迁移。

动态扩展按独立、默认关闭的构建能力设计，编译进能力后还需应用显式创建和配置运行时。未使用者不承担解释器、包扫描、执行线程与空闲唤醒成本；纯逻辑扩展不要求创建窗口或 graphics 实例。具体 feature 名称待实现冻结。

UIX Lang 继续 AOT 编译为 Rust；其语法、宏返回值、IR 与现有开发期热重载不因本设计改变。Lisp 是软件扩展语言，Rust 仍拥有宿主安全边界和进程生命周期；Lisp 可以承担扩展自己的业务，不把这些逻辑塞入 `.uix`。

引擎引入必须遵守[按需编译](../使用方按需编译.md)和[依赖治理](../依赖治理.md)。记录开启扩展的独立依赖成本，同时复核现有默认、最小与 demo 三口径；若需净增长，届时按既有规则登记论证，本文不预先豁免依赖门禁。
