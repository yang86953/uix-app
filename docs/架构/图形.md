## 图形

<a id="图形-api与帧提交硬约束"></a>

`GraphicsBackend` = wgpu adapter API 请求（非 OS 别名）。生产 GPU 只有一套 `WgpuRenderer`、一份 WGSL 和一套资源 / batch / present 生命周期；Vulkan、D3D12、Metal、OpenGL 只是 wgpu 后端选择，禁止再实现平行的 API 专属 UI raster pipeline。

解析：builder > 环境变量 > Settings > 默认 **Auto**。Windows 固定 Vulkan → D3D12 → OpenGL，Linux 固定 Vulkan → OpenGL，macOS 固定 Vulkan → Metal；每个候选都创建同一个 `WgpuContext + WgpuRenderer`。全部 adapter 初始化失败后才创建 CPU Software engine。显式 API 只探测该 API，禁跨 API 偷换；registry 只陈述 adapter 能力，不拥有渲染实现。

```text
App / WindowSession
  → resolve GraphicsBackend
  → bootstrap（wgpu adapter | Auto 候选）
  → WgpuContext（Instance / Adapter / Device / Queue / Surface）
  → WgpuRenderer（唯一 WGSL / pipeline / atlas / vertex buffer）
  → Native GPU command batches（单一有序、API 中立）
  → Queue::submit + Queue::present -> typed Result
```

- **GPU / CPU 边界**：GPU engine 直接把 LayerTree 画入严格 GPU canvas；矩形、圆角（含轴对齐各向异性几何平均半径）、描边、渐变、网格、阴影（含轴对齐各向异性 blur 与旋转 / 剪切仿射四角）、字形（物理 1:1 面积 coverage → R8 atlas；缩放/仿射/高 DPR → 共享 wgpu MSDF atlas cover → 仿射采样四边形）、可缩放图像 blit、轴对齐 / 网格化变换几何（含对角线线段 mesh）、带 opacity / 亚像素目标 / Additive 父 blend 的 Picture offscreen blit / FrameEncoder `FrameSampledRect` PictureBlit，以及离屏可分离模糊（`GraphicsEngine::try_blur_offscreen` / `compositor::blur_picture_region`）都由共享 wgpu pipeline 光栅化 / 合成。CPU 仍负责布局、命令生成、字体 shaping、轮廓提取 / 展平，以及物理 1:1 字形的 `OutlinedGlyph::draw` 面积 coverage；后者只生成紧凑 R8 atlas 数据，不创建 CPU framebuffer，也不把 software frame 作为 PixelUpload 中转。遇到 GPU-only 未实现操作时该帧 typed 失败并进入既有恢复状态机；只有 GPU engine 整体不可用时才创建 CPU Software engine。
- **复用边界**：WGSL shader、batch 合并、glyph atlas、vertex buffer 扩容、scissor、offscreen RT、texture blit、surface acquire / submit / present、device-lost 与 uncaptured-error 处理均只在 `native::graphics::wgpu_backend` 实现一次。平台代码只负责 raw window / display handle 与 drawable extent；旧的每 API context 仅保留在测试编译中作为迁移期回归夹具，不进入生产 module graph 或 registry。

- **帧提交**：一帧一条命令序列；禁双画序；每帧至多一个 `Presenter`；成功指标仅提交成功后记。initialize / resize / make-current / begin-end-frame / present → typed `Result`；CPU 像素写入 retained buffer 不等于提交成功，最终 OS present（含 GDI `GetClientRect` / `GetDC` / `StretchBlt`）失败须 typed 返回；失败帧保留 dirty。透明 CPU segment 只收 source-independent op；Additive / Scroll 等目标相关 op 必须进入 Native IR，无法精确降级的几何或状态在录制边界 typed 拒绝。

下列 `FrameRecordingEngine`、`CpuSegment`、PixelUpload 及各 API 原生 shader 细节只描述 CPU Software 与 test-only 迁移夹具，不是生产 GPU 执行链；与上面的 wgpu 边界冲突时，以 wgpu 边界为准。
- **DisplayList 录制**：文本指令（`DrawText` / `TextCenter` 等直接字符串变体）以 `Arc<str>` 共享不可变内容；DisplayList 自身以 copy-on-write 的 `Arc<Vec<PaintOp>>` 保存完整操作序列，普通 clone 只增加引用计数，不复制任何 op 或其中的 `TextLayout`，只有 clone 后继续 `push` 的非常规构建路径才复制既有操作。Label 与 Input 将只绘制一次的新 `TextLayout` 在即时绘制后直接移交 recorder，避免录制时再复制 glyph / line 缓冲；保留的借用入口也只在确实存在 recorder 时建立 owned layout，公开 `PaintOp::BlitGlyphLayout { layout: TextLayout }` 结构不变。Picture 缓存命中时通过 `LayerTree::collect_picture_handles` 所有权转移避免重复 clone。缓存 DisplayList 与新绘 Picture 现在都进入私有 `FrameRecordingCanvas`，不再先 replay 到完整 CPU 表面。主帧与 Picture 内符合 identity / 整数 offset / SrcOver / 整数矩形 clip 的字形，先把当前 opacity 按 CPU 的 straight alpha 截断顺序折叠进 `Color`，再保留共享 coverage；紧邻同 clip 字形合为一个 `BlitGlyphs` Native IR，折叠后 alpha=0 直接 no-op。identity transform 下的普通矩形 / 圆角矩形先按 CPU 同样的 f32 加法应用当前 offset，只有最终几何为 surface 内整数矩形且为 SrcOver 时才保留为 Native IR；当前 fill opacity 先把 CPU 的 premultiplied 8-bit 源反解为可精确恢复同一源像素的 straight Color，部分整数 clip 由独立 `FillRoundedRectClipped` 携带，clip 直接使用 push 当时固化的 surface-space 坐标，空交集直接 no-op。Picture 只在透明开头、完整或局部 source、整数 1:1 destination、父画布 identity / SrcOver / opacity=1 且当前 offset 为有限整数、目标 clip 为整数矩形，且每对可见写区互不相交，或其实际交叠区被一块或多块已证明全不透明 cover 的无缝并集完整覆盖时，才丢弃局部 Clear、先把 offset 固化到 destination、按目标 clip 同步裁 source / destination，再按 source crop 收窄命令并检查坐标后事务性平移整条命令流；未覆盖重叠仍因 8-bit SrcOver 舍入不满足结合律而整图物化。其他 Picture 状态同样物化。父画布 opacity 非 1 时不会把透明度下推到组内命令；有限整数映射会先物化组结果，再用携带 `FrameOpacity` 的单个 `PictureBlit` 按 CPU 同序对 premultiplied RGBA 逐通道截断，零 opacity 直接 no-op，且不扩大主 scratch。普通 `Canvas2D::blit_image` 在 identity / SrcOver、有限整数 offset / source / destination、1:1 映射与整数 clip 下复用同一命令边界，只复制目标 clip 与 surface 内实际可见的 source crop；缩放或 fractional 采样继续走原 CPU fallback。scratch batch 是 CPU 绘制的核心节省机制：连续 CPU draw 不逐次 flush 上传，而是积累到 scratch 表面，在 painter-order 边界一次性 pack 紧凑脏区为 CpuSegment。主画布 scratch 初始及 resize / shutdown 后只保留 1×1 安全占位；每个 Picture 候选录制结束或失败后也立即收缩回 1×1。首次真实 CPU draw 才分配整面；纯 native 帧不扩容。scratch 只清已写并集，写区过大或无界时清整面；成功 flush 后复用同尺寸 scratch 分配并只重置光栅状态，中途放弃的录制在下帧前保守全清。圆角矩形的无变换 CPU 填充 / 描边按左右半扫描线只计算 SDF 边界，连续实心段批量写入，结果须逐像素等价于完整 SDF。recorder 嵌套、panic 展开与 replay 临时停录均须恢复上一层目标和开关，禁止留下悬空录制指针或改变调用方状态。
- **圆形填充录制**：`Canvas2D::fill_circle` 在 identity / SrcOver、应用 offset 后外接正方形为 surface 内整数矩形且 clip 为整数矩形时，精确改写为四角半径均等于圆半径的现有 `FillRoundedRect` / `FillRoundedRectClipped`；两者共用同一 SDF coverage 与 opacity 量化语义，因此半像素圆心 / 半径只要外接边界为整数也无需 CPU scratch。fractional 外接边界、变换或其他 blend 保留原 CPU 路径。
- **矩形与圆形描边录制**：`Canvas2D::stroke_rect` 在 identity / SrcOver、应用 offset 后原始矩形为 surface 内整数矩形、clip 为整数矩形、宽度有限正值且圆角合法时，保留为携带原始几何、`FrameStrokeWidth`、`FrameRadius` 与 clip 的 `StrokeRoundedRects` Native IR；`stroke_circle` 在相同状态约束且外接正方形为整数几何时，精确改写为四角半径均等于圆半径的同一 IR，opacity、clip 与 CPU coverage 语义不变。同 clip、保守可见 bounds 两两不相交的相邻描边，仅在不超过 2048 项、union 不超过 1M 像素且不超过累计可见 bounds 4 倍时合批，相交、稀疏或过大的 union 保持独立 painter-order 边界，避免 8-bit SrcOver 非结合律改变结果并限制合批检查成本。opacity 仍先量化成可恢复同一 premultiplied 8-bit 源的 straight Color。具备 `stroke_rects` capability 的 D3D11 以一个既有 `GpuStrokeRect` batch 提交；D3D12 / OpenGL 等无该 capability 的执行器只为 batch 与 clip 的可见交集生成精确透明 tile，再按 painter order 上传，不分配 recorder 整面 scratch。Picture 的安全拼接暂不接受描边写区，含描边 Picture 会按既有规则物化；fractional / transformed / target-dependent 状态继续走原 CPU 路径。
- **字体加载与文本布局**：`FontService` 以完整字体文件委托后端选择 face；TTC / OTC 的 table 可跨 face 共享，禁止按 offset 区间切成伪 TTF。主字体安装须原子更新句柄、family 与 path；显式 family 命中或降级后仍探测一枚通过中文字形 probe set 的 CJK fallback，不满足覆盖的候选立即卸载并继续；回退链的新增、替换与卸载同步到后端。布局先按实际字体回退分段，同一 pass 内相同 Unicode 标量只做一次字体覆盖探测；各字体段只能输出顶部对齐的自然布局，`max_height` 与垂直对齐在段拼接完成后统一应用一次，禁止不同字体段各自偏移。随后在有限 `max_width + word_wrap` 下按字形推进并优先回退到最近的空白或连字符断点；单一字体长词仍可按字形兜底，不得旁路宽度约束。自动断行边界的连续可折叠空白保留源字符下标但收敛为零宽，不扩大上一行或制造空白行；NBSP / NNBSP / word joiner 不产生软断点。CRLF 作为一个硬换行、独立 CR 与 LF 作为硬换行进入真实 `LineInfo`，连续与末尾空行均保留；tab 以不可见四空格 advance 参与布局，不生成 tofu。常见中西文开放标点不得留在行尾，闭合标点不得落在行首；只有成对内容本身宽于容器时才允许兜底溢出。命中与选择均以源字符下标为契约，不假设一个 Unicode 标量等于一个 glyph 槽；选择范围直接扫描行内 glyph，不物化临时列表，Label / Typography 缓存每行真实字符与 glyph 范围，以 glyph advance 中点选择最近光标边界，空行也返回该行源字符边界。无字体上下文的测量使用与真实布局一致的词边界、硬换行、可折叠空白、宽字符和标点禁则估算：`Typography::Paragraph` 按可用宽度计行，`Label` 不自动折行但须为全部显式行保留高度，并以样式 token / 物理单位字号参与首帧布局；`Button` 按样式字号和宽字符估算单行内容宽度，再在绘制时用实际字体宽度居中；`Tag` 同样按宽字符估算正文，并把勾选 / 关闭动作区作为固定宽度加入固有尺寸，关闭符号走 Lucide 图标字体；`Badge` 的普通胶囊按 11 logical、状态 / 圆点标签按 13 logical 估算可见文本，普通胶囊的 text 优先级与绘制、语义一致，溢出计数按实际 `max+` 标签量宽；`Tooltip` 的单行气泡按 12 logical 估算可见文本并加入 16 logical 横向 padding，render、overlay bounds 与 dirty damage 共用同一气泡尺寸和箭头间距；`Checkbox` 按尺寸档位以 12 / 13 / 14 logical 估算单行标签，并只为可见标签加入间距，测量与绘制共用该间距规则。Label / Button / Tag 字号在测量和绘制前统一收敛为有限正值，非法值分别回到组件默认值；Badge 的像素 / 物理 offset 转换后按分量收敛非有限值为 0。`Timeline` 以归一化实际 frame 计算行距、节点、连接线和文字槽，固定单行标签 / 说明按 Unicode 边界省略，全部绘制受 frame 与各自文字槽双层裁剪；反转只改变已完成项的视觉与 `List` 语义顺序，pending 始终位于末尾。
- **Switch 几何**：Small / Medium / Large 的轨道分别为 28×16 / 40×22 / 52×28 logical，并垂直居中于 24 / 32 / 40 logical 控件框；圆形滑块直径为 12 / 18 / 24 logical，横纵轴共用 2 logical 内边距，关闭态贴左、开启态贴右。
- **Radio 布局与焦点**：选项固有宽度由共享 Unicode 估算器量取当前尺寸字号，再加入随控件尺寸缩放的指示器与尾部空间；横向组累加各项且至少 120 logical，纵向组取最大项宽并按 24 / 32 / 40 logical 行高堆叠。焦点属于整个 `RadioGroup`，绘制时以当前选中项为锚，在原圆环外增加随尺寸缩放的独立焦点环；方向键相邻索引在首尾循环，受控值无匹配时按前进 / 后退方向分别进入首项 / 末项。
- **Input 行模型与附件**：Textarea 写入时把 CRLF / CR 收敛为 LF，以 `split('\n')` 的逻辑行保留末尾空行；固有高度、上下移动、光标绘制、选择区和滚动后点击命中共享该行模型，逐行命中坐标以 text area 为局部原点并按绝对逻辑行索引保存。空值 placeholder 不得生成超出真实值的光标索引；隐藏密码把已提交字符映射为掩码，但 IME 预编辑仍插在当前字符索引，光标按掩码前缀量宽；同一 password 模式 reconcile 保留运行时可见性，退出 password 模式时强制复位。Addon 使用 13 logical 的共享 Unicode 估算宽度加 16 logical 横向 padding，并与 prefix / suffix、clear、password、search 的独立槽共同进入单行固有宽度；`InputGroup` 只把声明的前后 addon 合并进单个 Input，不增加中间 Widget；非空 status message 固定增加 18 logical 高度，边框与消息共用语义状态色。绘制使用窗口坐标，交互命中矩形必须转换回组件局部坐标。
- **图标单一管线**：应用 View 树中的图标必须构建为 `Icon::new(name)`；内置组件没有独立子节点空间的紧凑图标槽只能调用 `Icon::paint_in_frame`，其字体句柄、名称映射与对齐仍由 `Icon` 所有。普通组件不得直接调用 `icon_char`，不得把 Unicode / ASCII 符号或 locale 文案当图标，也不得另画一套手绘图标。图表数据标记、加载进度弧、滑块 / 单选等控件几何以及 Popover / Tooltip 指示箭头属于数据或控件形状，不属于图标。`tests/icon_policy.rs` 对组件、Demo 与 locale 执行静态门禁。
- **基础组件增强边界**：Button loading 只在加载期间登记逐帧工作，停止后清空相位；ButtonGroup 构建为零间距 Row，并由各 Button 的位置快照收敛连接边框。Tag 扩展色与图标、Badge 预设色与 ribbon 都只改变测量、快照和绘制，不创建 timer 或后台任务；预设 Badge 前景按背景明暗选择黑白，直接 `Color` 输入保留历史白色前景。
- **InputNumber 数值文本与几何**：数值缓冲使用可往返 `f64` 文本，聚焦 / 失焦不得把有效精度强制截成两位；`formatter(Fn(f64) -> String)` 只投影非编辑态显示、快照 `display_value` 与无障碍 `value_text`，聚焦编辑缓冲、typed State、`value_now` 及 Change 始终保持原始数值语义。reconcile 替换 formatter 时保留正在编辑的缓冲，显示配置不反向解析或写入真值。步进前先提交当前缓冲，再按现值与 `step` 的十进制位数对常见浮点加法尾差做有限精度收敛，typed State 仍由 `InputNumberValue` 执行最终类型转换。`keyboard(false)` 不接受实体按键、`TextInput` 或粘贴，不显示文本光标，也不把 reconcile 前的未提交缓冲写入真值；指针步进和无障碍 Increment / Decrement 仍直接走同一 `step_by` 数值路径。三档固有尺寸固定保留 80 logical 文本主体，并在右侧追加 24 / 32 / 40 logical 方形步进区；实际受限高度下，按钮命中按本次绘制矩形的上下半区判断。背景、禁用色和焦点描边覆盖完整外框，内部只绘制步进分隔线；数字文本在主体 clip 内按实际字体推进定位光标，溢出时左移以保留尾部，步进箭头使用 Lucide 图标字体。
- **Select 文本、交互与浮层几何**：固有宽度按选项、分组与 placeholder 的 Unicode 文本指标估算并至少为 120 logical；实际受限高度同时决定绘制、光标与命中。触发器文字、搜索查询和多选标签只在扣除 28 logical 箭头槽后的内容区绘制，查询光标按实际字体推进定位并在溢出时保留尾部；多选标签按实测文字宽度裁切，关闭槽与 Lucide 图标保持独立。搜索 / 多选键盘高亮与已提交值分离，方向键不得提前写回，单选仅由 `Enter` 提交，多选由 `Enter` / `Space` 切换且保持展开。下拉行高固定 28 logical、视口上限 280 logical，空结果仍保留一行本地化空态；绘制前按 logical surface 选择下方或上方，滚动、行命中、dirty 与 popup bounds 共用本次渲染矩形。`render_option` 以构建期 render handler 保存应用闭包，仅按 `VirtualListScroll` 当前窗口物化 View 子树；子树使用原选项索引生成稳定 key，声明式重建可原位 reconcile，滚动、renderer 移除与关闭动画完成时及时增删。自定义 View 只负责选项内容，固定行几何、父级裁切、复选框 / 选中标记及整行命中仍归 Select，避免子 View 改写选择语义。展开及关闭过渡期间注册 `Popover` overlay，使下拉在普通兄弟内容之后合成；触发器与下拉正文分别裁切，长文本不得覆盖箭头、复选框或相邻控件。
- **Segmented 文字与分段几何**：各项固有宽度由共享 Unicode 估算器按当前尺寸字号量取可见文字，再加入随高度缩放的 24 logical 基准横向空间；三档固有高度为 24 / 32 / 40 logical。绘制时以 `min(frame.h, nominal_height)` 作为实际控件高度，并把各项固有宽度按总宽比例缩放到完整 frame；绘制、分隔线和二维半开命中逐项消费同一宽度表，最后一项吸收浮点余量。字号、内边距和圆角共享实际高度比例，整体与每项分别裁切，受限宽高不得留下不可点击尾部，也不得让后续分段、选中块或文字越出控件。整体或单项禁用的当前选择使用独立 disabled thumb 填充与弱化文字，仍须保留选择辨识。方向键从当前索引向前或向后循环查找首个启用项；外部值未匹配时分别从首项或末项开始，全禁用时不改值。非受控 reconcile 优先按当前选项文本在新 options 中恢复选择，文本已移除时才回退到仍有效的旧索引。组件语义是互斥选择的 `RadioGroup`，不是关联面板的 `TabList`。
- **CPU 分配与资源上界**：可呈现主表面与真实离屏表面先检查像素数并可失败预留，resize 只在这些预分配成功后提交；失败返回 `GraphicsOutOfMemory`，保留旧尺寸且不消耗离屏句柄。API-neutral recorder 不持有可呈现 CPU 主表面；resize 只验证 logical extent 可寻址并原子更新。Native GPU 执行 `CpuSegment` / `PictureBlit` 时也不再构造透明整帧 `ReferenceFrame`，而是仅为命令与目标 surface 的可见交集分配参考 tile。recorder Picture 槽只常驻 1×1 scratch 与一份 committed 表示：保留 IR 的 command / image / coverage 总量不超过同尺寸 BGRA 预算，超限在发布前物化为单张 `FrameImage`，二者不同时常驻。录制 scratch 的全尺寸像素同样延迟到首次 CPU draw；void 绘制入口的分配失败保留 1×1 安全占位和既有光栅状态，并把 typed OOM 延迟到帧边界。native GPU 的惰性软回退（`NativeGpuCanvas2D::ensure_soft`）分配失败时同样只保留 1×1 安全占位并把原 typed OOM 延迟到帧边界；OpenGL 的全目标 RGBA upload texture 也只在首次真实 soft upload 时创建，glyph-only / native-only 帧不预留。清除 / 重叠复制的裁剪加减使用扩宽整数，极端坐标不得溢出。图片缩放与字形 blit 先验证源 / 目标缓冲，只遍历实际可见目标区，禁按被缩小的源面积或离屏 coverage 空转。`ImageService` 的目标尺寸圆形 / 圆角方形 / 圆角矩形派生位图按源句柄、物理尺寸、圆角与 fit 模式缓存，分配失败回退原图绘制，源图卸载时同步失效派生句柄。字形光栅尺寸上限为 512 px，统一缓存受 **2048 项与 8 MiB coverage** 预算约束（Chrome / Flutter 同等水平），容量压力按 LRU 逐项淘汰；字体卸载同步释放该字体的缓存项，不等待全局容量压力。D3D11、D3D12 与 OpenGL atlas 均最多 2048×2048 R8，cache 只保留精确尺寸的共享 coverage allocation，避免尾随 payload 绕过该上界。D3D12 使用两个固定且互不覆写的 shader-visible SRV 槽位隔离 soft texture 与 glyph atlas；图集满时按命令顺序先提交已有字形段，再覆写同一固定纹理。每段 glyph coverage 共用一张最多 4 MiB 的 staging footprint 并以 source box 分区复制，避免窄字形逐项 256-byte row pitch 放大；glyph 路径仅在当前 backbuffer 的 retained upload pool 预计总容量不超过 8 MiB 时长期复用，否则只保活到对应 fence。无原生 glyph 能力或字形单边超过 2048 的后端回退 cluster 面积上限为 1M 像素（4 MiB BGRA）、稀疏 union 上限为累计可见字形面积的 4 倍，最终 tile 不超过 1024×1024。高斯核以完整半径位编码进入最多 32 项的线程本地 LRU，半径上限为 256，命中共享不可变内核而不复制权重数组。

- **回退**：`Auto` 按平台顺序探测所有 wgpu GPU adapter，全部初始化失败后才整体创建 CPU Software engine。生产 GPU 帧禁止 CPU PixelUpload / `CpuSegment` 混合回退；未实现图元在帧边界 typed 失败，禁近似冒充或暗中切换另一套 raster pipeline。
- **恢复**：surface rebuild → recipe rebuild → 同 API 下一 recipe → Software，各步只尝试一次；仅 `Auto` 可跨 API。旧 engine 须先 checked teardown，再创建同 native surface 的 replacement；teardown 失败时禁止探测第二份 context。Software 的 `ExternalPresenter` 成功才重置序列，序列耗尽或 `OutOfMemory` 进入终态。resize 失败仍记住最新目标 extent；backend 不得把 `DeviceLost` / `SurfaceLost` / OOM 抹成 `NotImplemented`。Vulkan wait-idle 返回 `DeviceLost` 时仍须销毁本窗 child；共享 device 标记 lost 后所有 peer typed 停止提交，池不得把它交给 replacement，最后一个 lease 才销毁逻辑 device。其他 wait 失败保持 typed 且保留未排空父对象。显式 `test-harness` 可为单窗安排至多一个下一帧 `GraphicsDeviceLost`：该真实绘制帧必须先返回 `Failed` 并保留 dirty，后续帧才进入同一生产恢复 FSM；无可恢复 GPU engine、重复待处理注入或关闭窗口须 typed 拒绝。默认构建不含此入口，注入证据不得冒充真实驱动或硬件矩阵。
- **诊断**：成功 recipe 记录请求 backend 与 wgpu adapter 的名称、类型和 driver；adapter / device / surface 创建失败保留候选与 typed 根因。wgpu uncaptured error 进入日志，device-lost callback 转为共享 lost 状态，后续提交统一返回 `GraphicsDeviceLost`。
- **滚动帧**：`begin_frame` 先清 dirty 区，故 `ScrollCopy` 读到的是已清空像素；render_frame 须把滚动视口并入清/绘区。
- **绘制裁剪同步**：`begin_frame` 以 `FrameReady` 返回实际清除 / 裁剪区；`FrameRenderer` 必须以该区驱动录制剪枝。引擎把 `DirtyRects` 请求提升为 Full 时，present damage 也须提升；因后端不支持局部绘制而主动请求 Full 时，仍可在缓冲一致性已证明后保留窄 present damage。实际区不得小于请求区，否则 typed `InvalidState`；禁另算一份录制 clip。
- **所有权**：`draw` 不持有 GL / D3D / Vulkan / Metal 对象，只消费 API-neutral graphics trait。每窗 `WgpuContext` 拥有 Instance / Adapter / Device / Queue / Surface；`WgpuRenderer` 拥有 pipeline、atlas 与 vertex buffer，字形批与 MSDF cover 分属 `glyph_batch` / `glyph_cover`，绘制流类型在 `draw_stream`；raw window/display handle 只存在于 `native::graphics::wgpu_backend::platform`。生命周期边界为 checked `try_shutdown`，线程绑定包装器仍禁止错线程 native teardown。
