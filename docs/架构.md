# 架构

> 分层、主循环、托管与图形硬约束（不含用法与排期）。附能力（测试 / Agent）见文末。

## 分层

依赖只能向下，未列边禁止：

| 域 | 允许依赖 |
|----|----------|
| `core` | — |
| `native` | `core` |
| `draw` | `core`, `native` |
| `ui` | `core`, `native`, `draw` |
| `data` | `core` |
| `app` | `core`, `native`, `draw`, `ui`, `data` |

- OS 能力经 `native::traits`；禁上层 `use native::backends::*`
- `#[cfg(OS)]` 仅限 `native/` 层；上层（`core`/`draw`/`ui`/`data`/`app`）禁止
- `draw` ↛ `ui`/`app`；`ui` 不碰 backend；业务回调不进组件 struct（语义 handler、paint renderer、虚拟子项 factory 随节点以 `ComponentId` 登记，reconcile / remove / root reset 同步清理）；`Form` 自定义 validator 只由应用侧 `FormModel` 持有；`data` 不进热路径
- 运行时是原生窗口 + 原生绘制；**禁 WebView / 嵌入式浏览器作为 UI 或呈现运行时**
- 图形初始化：`draw::engine::bootstrap → native::factory`（recipe 为单位）
- 公开入口：`uix::prelude::*`
- View 样式链只写入节点唯一 `Style`；水平 / 垂直 padding 保留另一轴，阴影进入同一盒模型绘制，不在组件内复制视觉字段
- `Computed::map` / `map_opt` 在根 View 构建期重放底层 State 依赖并绑定结构 reconcile；`map_text` 走 DynamicLabel 的窄 Paint 绑定。缓存命中不得跳过依赖捕获
- `canvas(width, height, paint)` 仅提供固定 logical measure + render，无子节点 / 事件能力；绘制期读取的 State / Computed 在共享 ScenePaint 边界绑定到本节点 dirty rect，变化只产生窄 Paint，不注册每帧工作
- controlled Input 以绑定的 `State<String>` 为外部真值：构建期读取绑定结构 reconcile，编辑事件同步回写；内建 patch 比较运行值，值变化才重置文本 / 光标并发 Layout + Paint，同值重建保留运行态。`textarea` / `password` 工厂只声明模式，`max_length` 按 Unicode 字符限制用户输入；绑定值不进入公开 config snapshot
- controlled Checkbox / Switch 以绑定的 `State<bool>` 为外部真值：构建期读取触发结构 reconcile，点击或键盘切换同步回写，绘制期依赖只绑定本节点 Paint。非受控 `default_checked` 仅是初值，无关 reconcile 不覆盖用户运行值；两种模式均不轮询
- controlled Select 以选项文本作为外部真值：单选是 `State<String>`，多选是 `State<HashSet<String>>`；构建期将值映射为稳定选项顺序中的索引并绑定 reconcile，点击 / 键盘更改同步回写，绘制期只绑定本节点 Paint。`searchable()` 仅在聚焦后接收 `TextInput`，按大小写不敏感的包含关系过滤并保留原选项索引；查询、弹层、过渡与滚动均是实例运行态，无关 reconcile 保留且无轮询，过滤收窄时 damage 仍覆盖有上限的原弹层。非受控 `default_selected` 仅是初始索引
- Table 的 `sortable` / `selection` / `bordered` / `virtual_scroll` 是声明式配置：表级排序覆盖所有列，列级排序可单独开启，点击只切换方向并发 `Change`，数据顺序由调用方重建；复选框列仅在 selection 开启时参与 measure / hit-test / paint。虚拟滚动关闭时保持完整行遍历，开启后按固定 `virtual_row_height` 只遍历 viewport 与有界 overscan；两者滚动都只产生 body Composite，不注册逐帧工作。排序方向、有效范围内的单选 / 多选行在同配置 reconcile 中保留并进入快照
- Table 列布局在每次 paint / hit-test 时划分 left / middle / right：固定列按声明顺序锚定两侧，只有 middle 应用有界水平偏移并裁在剩余视口。纵向滚动沿用 Composite；横向偏移会改变固定区与中间区的叠放关系，coherency 未覆盖该组合时退回本 Table Paint，不提交整表像素搬移
- Table 的 `column_groups` 在构建期扁平化为叶列与稳定范围元数据，排序、行数据和固定列继续只索引叶列。存在分组时表头增为两层：具名范围分占上下层，`TableColumnGroup::column` 的独立列跨两层；分组范围进入结构化快照，reconcile 仍按叶列位置保留可排序运行态
- Table 展开 factory 不进入组件 struct，而是按 `ComponentId` 存在 `RenderHandlerTable`；展开时只物化当前行的一个普通 View 子树，应用 reconcile 复用同类型 / 同 key 节点，折叠或换根随节点生命周期清理。子树以表体为 clip，并复用 body 的 viewport scroll transform；paint 不调用 factory
- controlled Slider 以 `State<f64>` 为外部真值：构建期读取并按 inclusive range 约束显示，拖动、方向键与语义增减同步回写，绘制期依赖只绑定本节点 Paint；非受控 `default_value` 仅是初值，无关 reconcile 保留运行值。区间、步进与公开快照统一使用 `f64`，步进从区间起点对齐，不轮询
- controlled DatePicker 以 `State<Date>` 为外部真值：构建期读取触发结构 reconcile，选日同步回写，绘制期读取只绑定本节点 Paint；非受控 `default_value` 仅是初值，无关 reconcile 保留选值、弹层开闭与浏览月份。禁用谓词只在命中测试/绘制中求值，Week / Month / Quarter 先归一到周一/月初/季初再提交；快照导出格式化日期供无障碍 / Agent 读取，不轮询
- DateRangePicker 复用同一日历面板，以两个 `State<Date>` 为外部真值；首击仅保留组件内 pending 起点，次击排序后回写双 State，reconcile 保留弹层、浏览月份与未完成选择。预设在构建期解析为起止值，点击与普通范围共用禁用端点和提交路径；无逐帧工作

## 诊断

<a id="诊断"></a>

`core` 层提供统一诊断基础设施——错误收集、崩溃处理、中间件管道。所有上层模块无需引入第三方日志/错误收集库。

### 错误收集器（`Collector`）

线程安全的全局单例，收集、聚合、快照应用内所有 typed `Error`：

- **收集**：`Collector::instance().collect(error)` —— 任意线程可调用
- **配置**：`CollectorConfig` 控制最大容量（默认 4096）、非 Fatal 自动日志开关与级别、去重策略；Fatal 始终先写日志与崩溃报告再 abort
- **快照**：`Collector::instance().snapshot()` 返回 `CollectorSnapshot`，含时间戳、总量、当前存储数、按错误码/类别聚合统计
- **回调**：可按 `callback_id` 注册/注销，每个收集到的错误触发回调（例如对接外部监控）

### 崩溃处理（`fatal`）

- **panic hook**：`install_fatal_handler()` 将 Rust panic 转为 typed `Error`，写入 Collector，dump 崩溃报告（`uix_crash.log`），flush 日志后 abort
- **手动终止**：`fatal_abort(error)` / `abort_if_fatal(error)` / `collect_or_abort(error)` —— 按错误严重级别决定是否终止进程
- **崩溃报告**：含时间戳、总量、按错误码统计、每个错误简述

### 中间件管道（`middleware`）

可组合的请求处理拦截链，用于服务调用、IO 操作等需要在调用前后插入通用逻辑的场景：

- **`MiddlewarePipeline`**：`add(mw)` 注册中间件，`execute(ctx, handler)` 链式执行
- **`LogMiddleware`**：记录每次请求耗时与成功/失败状态
- **`RetryMiddleware`**：可配置最大重试次数，失败自动重试

```rust
let mut pipeline = MiddlewarePipeline::new();
pipeline.add(LogMiddleware);
pipeline.add(RetryMiddleware::new(3));

let mut ctx = MiddlewareContext {
    service_name: "FileService".into(),
    operation: "read".into(),
    ..Default::default()
};
pipeline.execute(&mut ctx, |c| {
    // 实际操作
    c.succeeded = true;
});
```

### 错误模型

所有错误走 `Error` 类型——含错误码（`Errc`）、严重级别（`ErrorSeverity`）、消息、源链、文件/行号。`what()` / `Display` 按外层到根因输出完整源链，`short_what()` 只输出单行简述；图形 frame / resize / external present 失败日志必须用完整文本，不能丢失 driver fault 根因。严重级别 `Fatal` 在收集时自动触发崩溃报告并 abort。

### 依赖注入

`app` 层提供 `Container`（prelude 别名 `DiContainer`）——基于类型的轻量服务注册与解析。自定义服务在 `App::run()` 前经 `App::singleton` 注册；`.settings(path)` opt-in 时，框架在进入运行模式前 load 并注册 `SettingsService`。字体与图片服务由图形运行时直接持有，不冒充可解析单例。

- 注册：`App::singleton(impl Any + Send + Sync)`，或直接使用 `container.singleton(...)`
- 解析：`handle.resolve::<T>()` 返回服务的 `Clone`，`container.resolve::<T>()` 返回容器内引用
- 生命周期：与 App 同寿，窗口间共享；`SettingsService` 的 Clone 共享同一锁保护状态，load / save 是冷路径。save 先同步同目录 temp，再把旧文件移入 backup 后安装新文件；load 会恢复“旧文件已移走但新文件未安装”的中断状态，并清理已提交或未提交的 sidecar

## 主循环

<a id="主循环要点"></a>

事件循环三态；surface 可用性是正交的逐窗状态：

| 轴 | 状态 | 含义 |
|----|------|------|
| `LoopState` | `DeepIdle` / `RegisteredActive` / `Active` | 无待办并阻塞；等待已登记 deadline / frame callback；已有可立即执行工作 |
| `SurfaceState` | `Renderable` / `Suspended(reason)` / `Recovering { retry_at, attempt }` / `TerminalFailure` | 可提交；等待 expose / 非零 extent / surface 恢复；按 typed 原因有界重试；不可恢复吸收态（无 deadline / frame request，仅随窗口 session 重建退出） |

### 必须

- `DeepIdle`：无待处理事件、queue、due work、reconcile，也无 outstanding frame request / recovery deadline。`Suspended` / `TerminalFailure` 窗的 dirty 不算可立即执行工作。
- wake ∈ {OS / 生命周期、queue、due deadline、frame opportunity、recovery / availability deadline}；一窗 wake / Active 不得把他窗拉成 Active；`TerminalFailure` 窗不因普通生命周期 / surface 信号重开视觉帧。
- 每个 `Active` 轮次先非阻塞分发挂起的 OS 事件，再执行 due work / frame；连续动画、Agent settle 或其他持续工作不得饿死输入、生命周期、关闭与跨线程 wake。
- **事件轮次**：批量 drain UiEvent + 同步 semantic → due 非视觉工作 → `post_to_ui` → AppState focus / semantic → Effect；只合并 dirty / reconcile，并为该窗申请至多一个 frame request。
- **帧轮次**：收到 `FrameOpportunity { request_token, frame_time, target_present_time? }` 后，消费截至该点的最后一次 root → **一次** reconcile → 按需 layout → paint → 至多一次 present。成功才消费 dirty；提交后仍有动画 / dirty 才申请下一次。
- frame request：one-shot、可合并、逐窗所有；`request_token = surface_generation + request_id`；原生回调只可完成完全相同的 outstanding token。fallback / surface 变化 / suspend 消费或取消 token 后，不能取消 OS 对象的 backend 必须抑制迟到回调。
- 动画保持 open registration，全窗只维护一个下一帧请求；`dt` 来自 frame opportunity 单调时间。`Suspended` 时取消视觉 deadline、冻结动画，恢复首帧 `dt = 0`，不补跑隐藏帧；业务时间继续由 Timer 表达。
- `Hidden` / `Minimized` / zero extent → `Suspended`：保留 dirty 与 animation registration，取消视觉 deadline，不 layout / paint / present。`WindowHide` / `WindowShow` 是逐窗生命周期信号；视觉阶段前复核真实可见性。延迟首显在第一次成功 present 前豁免；可用性信号只解除匹配的 suspend reason；`TerminalFailure` 为吸收态，普通 suspend / resume / surface change 与迟到 failure 均不得降级或重开 frame request，只能随窗口 session 重建。
- `SurfaceLost` / `OutOfDate` / `WouldBlock` → `Recovering` 或等待生命周期信号；重试有界并以 deadline 登记；持续失败不得因 retained dirty 形成 Active busy loop。`DeviceLost` 走同 API recipe → Software FSM，各步只尝试一次；`begin_frame` 内更换 engine 后，`FrameRenderer` 与 `WindowDriver` 须重读新 capability 并在同帧采用新提交协议。Software CPU 帧经窗口唯一 `ExternalPresenter` 成功才重置序列，重建或提交再失败则进入无 deadline 的 `TerminalFailure`。`OutOfMemory` 直接进入同一终态，不静默回退，也不接受普通生命周期恢复。
- 图形 engine 只返回 typed failure；普通遮挡为 Debug 可用性事件，其他最终 present 失败只由 `WindowSession` 边界记录一次 Error。
- 脏区尽量窄到 rect / Composite / 节点；同帧多个滚动视口分别登记 viewport + delta，统一并入 dirty / clear，保留到提交成功；禁用单槽「最后滚动覆盖」。

### 禁止

固定 16ms / interval 探活；DeepIdle 下 `tick_effects`；未 register 的周期工作；以 WebView 充当呈现或布局运行时；因 retained dirty 在不可呈现或持续失败时保持 Active busy loop。

### 平台帧机会与遮挡

各平台须按自身契约实现 one-shot frame callback（静态窗不创建节拍）。DWM/display link/`wl_surface.frame` 均不等于逐窗遮挡；遮挡检测须用本窗独立 compositor/window-server 能力。

- **Windows**：live recipe 以 `GraphicsContextCaps::present_occlusion` 声明能力。`PresentStatusAndTest` recipe：`Present` 返回 [`DXGI_STATUS_OCCLUDED`](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/dxgi-status) → `Suspended(Occluded)`，100 ms→1 s 有界 [`Present(…, DXGI_PRESENT_TEST)`](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/dxgi-present) 探测。`Unsupported` recipe 不登记遮挡 probe，只依赖 Hidden/Minimized/ZeroExtent 生命周期休眠。禁 DWM/帧机会冒充遮挡。
- **macOS**：[`windowDidChangeOcclusionState:`](https://developer.apple.com/documentation/appkit/nswindowdelegate/windowdidchangeocclusionstate%28_%3A%29?language=objc) 只 wake 目标窗；Visible 只解除精确 Occluded（无探测 deadline），恢复首帧 `dt = 0`。
- **Wayland**：`wl_buffer.release` 前 busy；双 busy → `WouldBlock` 保留 dirty。遮挡需 `xdg_toplevel.state.suspended`(v6+)；禁 frame/activation 冒充。Clipboard 与 display 同 poll、nonblocking、64 KiB 预算；`set_selection` 只用真实 press serial。

无真实窗口 / GPU 时：主循环与托管语义须能被单元 / 集成测试验证（不依赖真机 present），至少覆盖 one-shot 合并、可变 frame timestamp、隐藏动画零唤醒、失败不忙循环与恢复后 retained dirty。测试仅在 `src/tests`；业务模块不挂载、不内联测试。

## 托管与多窗

<a id="托管与多窗"></a>

每窗一个 `WindowSession` 与配对 `WindowDriver`：session 自有 `ActiveWorkRegistry`，driver 自有 `FrameScheduler` 与 `SurfaceState`。

| 种类 | 进入 RegisteredActive | 退出 |
|------|----------------------|------|
| Timer / AppTimer | 已登记且未到期清空 | due 执行完或 cancel/drop |
| Animation | open-register；`Renderable` 时全窗合并一次下一帧 | 结束 unregister；`Suspended` 仅停帧 |
| ImeSession | 焦点在可文本输入节点并 start | blur / stop |
| FocusHandle command | 唯一存活绑定收到 focus / blur 后进入所属 AppState 队列 | 目标窗 UI 轮次消费；移除 / 换绑清除旧目标 |
| FrameRequest / Recovery | 本窗 dirty / animation 已申请 callback，或 typed 恢复登记了 deadline；同类至多一个 outstanding | 消费 / 成功提交 / `Suspended` / `TerminalFailure` |

- `post_to_ui` / 窗级定时只入**目标** session
- `FocusHandle` 只保存 `ComponentId` 与所属 `AppState` 弱引用，不持有 `WidgetTree`；同一 handle 只允许一个存活 View 目标，跨窗误复用返回 typed 歧义错误。focus / blur 可跨线程登记并 wake 目标窗，其他窗口的 drain 看不到该命令；节点隐藏或不接收事件时消费命令但不强制聚焦。
- Timer cancel/drop 移除 pending 后必须 wake 重算 deadline，使可回 DeepIdle
- Frame cancel/callback 必须带 `WindowId` + generation；迟到只能丢弃
- 自定义标题栏是逐窗 opt-in 的窗口能力，不是组件皮肤。创建阶段须在首显前隐藏系统标题栏并重新校正 logical 客户区尺寸；配置失败则该窗创建失败，禁静默回系统标题栏。当前 Windows 仅移除 `WS_CAPTION`，保留 `WS_THICKFRAME` 等原生缩放能力；`GetWindowLongW` / `SetWindowLongW` 的零返回须先清空并读取 last-error 才能判定成败，任一样式读写失败必须 typed 返回。未实现 backend 返回 typed `NotImplemented`。
- `window_drag_region` / `window_control` / `window_control_named` 只在所属 `WidgetTree` 产生一次性 `WindowAction`，事件轮次内由本窗 `PlatformWindow` 消费；禁止进全局队列、跨窗广播或新增轮询 / frame request。拖动区允许子树先命中：子控件处理输入则停止冒泡；未处理的左键由拖动 / 双击接管，未处理的右键只在同一区域按下并释放后产生系统菜单动作，移出释放取消。`BeginMoveDrag`、最大化切换与系统菜单都保留客户区既有键盘焦点；系统菜单动作同时抑制该手势的 UI `ContextMenu` 默认项。窗口控制的展示子树不参与命中，也不导出独立语义节点；控制项自身可键盘聚焦，在语义树中是唯一的具名 `Button`，`Invoke` 复用 Enter 键路径而不直连平台窗口。指针捕获在控件外释放时先送 `PointerLeave` 取消动作；激活状态记录 Pointer 或具体键，只接受同源松开。组件消费 `FocusIn` / `FocusOut` 维护焦点视觉，背景按 active → focus → hover → normal 解析；交互态变化仅标脏该控制项 rect，不申请持续帧。
- Windows 窗口类启用 `CS_DBLCLKS`；拖动把当前左键手势移交 `WM_NCLBUTTONDOWN(HTCAPTION)`，拖动区左键 `PointerDoubleClick` 切换本窗最大化 / 还原，右键释放读取当前屏幕坐标并投递 `WM_NCRBUTTONUP(HTCAPTION)`，由 `DefWindowProc` 进入系统菜单 / `WM_SYSCOMMAND` 路径。屏幕坐标按有符号 `POINTS` 编码，允许负坐标显示器。最小化、最大化 / 还原继续产生既有逐窗生命周期事件；关闭只投递 `WM_CLOSE`，由 app 先 shutdown 图形与 session 再销毁 HWND。原生动作失败须终止或请求关闭该窗口会话，不得 busy retry。
- Wayland：每个存活 `wl_surface` 登记 `WindowId`；seat 跟踪 pointer/keyboard focus 只投递已验证目标；generation 丢弃迟到回调。
- macOS：事件从 `NSEvent.window`/delegate 解析 `WindowId`；IME owner = `WindowId` + native view identity + generation。生命周期由 `MacosWindowOps` 管理，图形 shutdown 后 close release。
- Windows DPI：上层客户区尺寸、resize 与指针 / 滚轮 / 拖放事件均为 logical；`GetClientRect` / drawable 为 physical。创建 UIX HWND 时仅在 `CreateWindowExW` 词法作用域切到 Per-Monitor V2，随后恢复宿主线程 context；`AdjustWindowRectExForDpi` 保证请求尺寸是客户区，`WM_DPICHANGED` 应用系统建议外窗矩形，再由同步 `WM_SIZE` 进入唯一逐窗 resize / graphics rebuild 路径。GPU 直接使用 physical client；Vulkan 创建与每次 resize 均从同一 HWND 查询 drawable，PresentUpload 的 CPU canvas 与 swapchain 对齐 physical，另存精确 logical viewport；GDI 保留 logical DIB，以同一全帧 `StretchBlt` 原点和外扩 physical clip 提交。target extent 改变须推进 surface generation，使下一帧 Full。禁改宿主 process awareness，禁一窗 DPI 变化重建他窗。
- **IME**：单行/多行文本均走系统 IME；框架只托管会话与光标矩形，不自造拼写/候选管线。composition → commit 须按平台输入法协议送达目标窗的目标控件；未 commit 的 composition 不得当最终文本写入 State。每窗 IME 归 `WindowSession`；共享原生输入只一个 owner（`WindowId` + native view identity + generation）。start/stop/失败须 typed，禁静默丢弃。隐藏含焦点子树须统一 `FocusOut` 并同帧注销 IME。
- Windows IME：TSF `ITextStoreACP` 文档锁只在 `OnLockGranted` 回调内有效；read lock 内的异步 read-write 升级排队一次并返回 `TS_S_ASYNC`，同步重入返回 `TS_E_SYNCHRONOUS`。`GetTextExt` 返回 caret 的屏幕坐标，`GetScreenExt` 返回完整客户区的屏幕范围；TSF 活跃时忽略 IMM composition，避免重复提交。
- `Tab` / `Shift+Tab` 只遍历有效可见可接收事件节点；无当前焦点时分别从首项 / 末项开始；浮层内受 `OverlayStack` focus trap 约束
- `WindowDriver` 是逐窗 pipeline 唯一实现（work → reconcile → paint → present）；主循环只 wait/路由。
- 浮层：`WidgetTree` 内 `OverlayStack`；不单独作跨窗 wake 源。
- 语义事件在 Active 帧与 UiEvent 同步派发；不另开轮询线程。
- Clipboard 只在事件/due work 词法作用域注入；组件不得保存 platform 指针。

## 动画

<a id="动画"></a>

UIX 提供泛型逐帧动画系统，由主循环统一推进 `dt`（秒），窗口不可呈现时自动暂停。

### Animation\<T\> —— 泛型插值

`Animation::new(from, to, duration)` 创建从 `from` 到 `to` 的插值动画，类型参数 `T: Animatable`。

| 方法 | 作用 |
|------|------|
| `update(dt)` | 推进时间，返回当前插值 |
| `value()` | 只读当前插值，不推进 |
| `is_finished()` / `progress()` | 查询完成状态与进度 [0,1] |
| `pause()` / `resume()` | 暂停 / 继续 |
| `restart()` | 回到起始位置并继续播放 |
| `stop()` | 跳到终态并停止，不触发完成回调 |
| `reverse()` | 交换 from/to 并重新播放 |
| `easing(e)` | 设置缓动曲线 |
| `on_finish(FnOnce)` | 下一次推进到终态时触发一次 |

非正 `duration` 归一为零，并在首次 `update()` 时到达终态。完成回调要求 `Send + 'static`；`Animation` 克隆体共享同一个一次性回调，任一克隆体先完成后其余克隆体不再重复触发。

内置 `Animatable` 实现：`f32`、`f64`、`Color`、`Point`、`Rect`。`Animation<f32>` / `Animation<f64>` 额外提供 `fade_in(duration)` 和 `fade_out(duration)` 便捷构造。

### Easing —— 缓动曲线

`Easing` 枚举将 `t ∈ [0,1]` 映射到缓动值：

| 变体 | 说明 |
|------|------|
| `Linear` | 线性 |
| `QuadIn` / `QuadOut` / `QuadInOut` | 二次方 |
| `CubicIn` / `CubicOut` / `CubicInOut` | 三次方 |
| `QuartIn` / `QuartOut` / `QuartInOut` | 四次方 |
| `BackIn` / `BackOut` | 弹性（超出后回弹） |
| `Bounce` | 分段弹跳缓出，输出保持 [0,1] |
| `Elastic` | 衰减振荡缓出，允许短暂越过终值 |
| `CubicBezier(x1,y1,x2,y2)` | 自定义三次贝塞尔（牛顿法 + 二分法回退） |

公开链式写法使用 `Easing::linear`、`ease_in/out/in_out`、`cubic_in/out/in_out`、`bounce`、`elastic` 这些关联常量；`Easing::cubic_bezier(...)` 构造自定义曲线。`sample(t)` 会收敛输入范围，但 Back / Elastic 的输出可越过 [0,1] 以形成回弹。

antd 5 预设：`antd_default()`（`cubic-bezier(0.25,0.1,0.25,1)`）、`antd_in()`、`antd_out()`、`antd_in_out()`。

### AnimationConfig / TransitionPlayer —— 进出场过渡

借鉴 antd 的 Modal / Drawer / Notification 等浮层 enter + leave 动画模式：

- `AnimationConfig` 只通过 `fade_in/out`、`slide_in/out`、`zoom_in/out` 构造，持续时间统一归一到非负值；应用不直接拼内部枚举字段
- `slide_in/out(Placement, duration)` 以 `Top / Bottom / Left / Right`（含角落变体归并到上下方向）表达视觉来源 / 去向；通用位移为 24 logical px，组件预设可在内部按自身尺寸收紧
- `TransitionPlayer` 是组件内部的单次播放器，将配置分解为 opacity / offset / scale 三路 `Animation<T>`，完成后停止登记帧工作
- 内建预设覆盖 Modal zoom、Drawer slide、Tooltip / Popover fade 与 Collapse fade；公开组件只接收 `AnimationConfig`

**enter 动画**：节点挂载或浮层打开时播放。**leave 动画**：关闭前播放，`finished` 后由 `OverlayStack` 移除节点。

### 帧驱动与暂停

- 动画由主循环每帧 `dt` 推进，通过 `WidgetAnimation::update_animation(dt)` 生命周期钩子传播
- 每窗 `ActiveWorkRegistry` 只登记仍返回 active 的动画节点；事件、reconcile 或失效发生时发现新动画，稳定逐帧阶段只推进已登记 id，不遍历整棵树
- **Suspended 时冻结**：窗口不可呈现时所有动画暂停，恢复首帧 `dt = 0` 重基，避免时间跳跃导致动画瞬切到终态
- 动画完成（`is_finished() == true`）后从 registry 取消登记，不再触发帧请求

## 主题与配置

<a id="主题与配置"></a>

### LocaleProvider —— 可持久化的子树语言上下文

- `App::locale` 将全局默认 `Locale` 注册到应用容器，主窗与后续副窗构建根 View 时读取同一默认值。
- `LocaleProvider::child` 在词法作用域内构建子树；每个 `ViewNode` 捕获最近 Provider 上下文，展开后的 widget 节点继续持有该上下文。
- measure / event / render / lifecycle 进入组件钩子时恢复节点上下文；reconcile 同步替换上下文并触发布局与绘制失效，因此延迟渲染不会退回全局语言。
- Provider 作用域由 guard 托管，正常返回与 panic 展开都会恢复上层上下文；嵌套子树采用最近 Provider。

### ConfigProvider —— 组件树配置继承

借鉴 Ant Design 的 `ConfigProvider` 模式，UIX 提供组件树层级的配置继承机制。配置沿组件树下传，子节点继承父节点配置，局部可覆写。

- **已落地配置项**：`component_size`（`ControlSize::{Small, Medium, Large}`）、`disabled`、`ComponentOverrides`、按组件类型索引的 `TokenPatch`、`render_empty` View factory；Locale 由独立 `LocaleProvider` 管理。
- **继承链**：`App::config` 把全局 `ComponentConfig` 放入应用容器；`ConfigProvider::child` 只覆写显式字段，节点捕获最近上下文。不包裹时使用全局值或框架默认值。
- **优先级**：组件局部属性 > 最近 `ConfigProvider` > `App::config` > 框架预设。
- **实现**：与 Locale 共用 View 构建词法作用域和节点持久化上下文；reconcile 比较上下文，变化时同时失效布局与绘制。作用域 guard 保证 panic 展开后恢复父层。
- **当前影响范围**：尺寸默认值进入 Button（含 `button()` DSL）、Input、InputNumber、Select、Checkbox、Switch、Radio、Segmented、Slider、Rate、DatePicker、DateRangePicker、TimePicker、ColorPicker、List、Descriptions、Modal、Drawer；禁用默认值进入 Button（含 `button()` DSL）、Input、Select、InputNumber；构造覆盖进入 Button、Input、Select、Form；List / Table 的普通 View 路径消费 `render_empty`。

### 组件级令牌覆写

在 `DesignTokens` 层面按组件类型覆写令牌值，对标 antd v5 的 `theme.components`：

- **查询路径**：每个 widget 节点保留 Provider 上下文；绘制前按组件 `TypeId` 查 `ComponentTokenOverrides`，命中才进入补丁层。
- **载体**：`TokenPatch` 是覆盖全部现有 token 字段的 `Clone + PartialEq` 纯数据 struct；未设置字段委托给当前子树 `Theme`，再回退每帧根主题。
- **绘制作用域**：`PaintContext` 持有根主题引用及可恢复的 subtree theme / patch Arc；节点绘制前替换作用域，绘制后恢复，不改 `WidgetRender` 与 `TokenProvider` 公开签名。
- **失效**：Provider 上下文发生变化时 reconcile 保守失效该子树的布局与绘制；稳定帧只多一次组件类型查询，不引入轮询或帧请求。

## 组件系统

<a id="组件系统"></a>

UIX 的 UI 树由 `WidgetTree` 管理，节点通过 `component!` 宏定义，框架自动处理 reconciliation（diff → 复用/创建/销毁）。

### component! 宏

`component!` 将一个 struct 转为完整组件节点，自动生成 reconciliation 逻辑。可定义的生命周期方法：

| 方法 | 签名 | 调用时机 |
|------|------|----------|
| `measure` | `(&self, Constraints) -> Size` | 布局 measure 阶段，给定约束返回期望尺寸 |
| `render` | `(&self, Rect, &mut PaintContext, &WidgetTree)` | 帧绘制阶段 |
| `build` | `(&self) -> Vec<Box<dyn WidgetComponent>>` | reconcile 阶段，返回子节点列表 |
| `on_event` | `(&mut self, &SystemEvent) -> EventResult` | 事件派发阶段，返回是否消费 |
| `update_animation` | `(&mut self, dt: f64) -> bool` | 每帧动画推进；返回是否仍需下一帧 |
| `dirty_bounds` | `(&self, Rect) -> Rect` | 返回本次动画变化的窄绘制区域 |
| `on_mount` | `(&mut self)` | 节点首次挂载到树中 |
| `on_unmount` | `(&mut self)` | 节点从树中移除前 |
| `wants_continuous_pointer_move` | `(&self) -> bool` | 是否接收逐帧 PointerMove（默认 false） |

含子节点的组件通过 `children: WidgetChildren` 字段 + `build` 方法声明。

### WidgetTree 与 Reconciliation

- **树结构**：`WidgetTree` 为扁平 `SlotMap`，节点以 `NodeId` 索引；容器节点持有子节点列表
- **Reconciliation**：逐层 diff 新旧 struct，同类型且 key 匹配则复用节点，否则销毁重建
- **回调登记**：`render` / `on_event` / `build` 等闭包随节点以 `ComponentId` 登记在侧表中；reconcile / remove / root reset 时同步清理
- **脏标记**：`State::new` / `clone` 本身不绑定根 reconcile；仅根 View 构建期的结构性 `State::get` 绑定 reconcile，绘制期与 DynamicLabel 读取只绑定对应节点 Paint。`State` 写入只标脏实际依赖；`Computed` 惰性求值；同帧多次写入合并为一次 reconcile

### 指针移动优化

同一 hit 目标上连续 `PointerMove` 不每帧触发重绘——仅 hover 目标变化时标脏。需要逐帧 PointerMove 的组件通过 `wants_continuous_pointer_move => true` opt-in。

### Widget Trait 契约

所有组件通过以下 trait 接入框架，`component!` 自动为 struct 生成实现：

| Trait | 职责 |
|-------|------|
| `WidgetComponent` | 组件入口，提供 `as_any()`、`snapshot_fields()`、`sync_from()`；复合交互组件可用 `exposes_semantic_children()` 折叠纯展示子树语义 |
| `WidgetLayout` | `measure(Constraints) -> Size` + `layout_children(frame, children, tree)` |
| `WidgetRender` | `render(frame, ctx, tree)` — 每帧绘制 |
| `WidgetLifecycle` | `on_mount()` / `on_unmount()` — 挂载/卸载钩子 |
| `EventHandler` | `on_event(&SystemEvent) -> EventResult` — 事件分发；滚动组件可用 `scroll_delta_for_dirty` + `scroll_composite_viewport` 将 Composite 限定到真实 viewport |
| `WidgetAnimation` | `update_animation(dt)` 推进并返回是否仍 active；`dirty_bounds(frame)` 限定窄标脏 |
| `WidgetCapabilities` | `wants_continuous_pointer_move() -> bool` |
| `WidgetTextInput` | `accepts_text_input()` / `ime_composition_rect()` — IME 支持 |
| `Animatable` | 定义可插值类型（f32、Color、Point、Rect 等），供 `Animation<T>` 使用 |
| `TokenProvider` | 提供色彩/字号/间距/阴影令牌，组件通过 `ctx.tokens()` 获取 |
| `TextRenderer` | 文本测量与绘制 |
| `DebugRenderer` | 调试叠加层绘制 |

`IntoWidgetNode` 将任意组件转为 `WidgetNode`，由 `ViewNode` 和所有内置组件 impl。

### Manager 系统

`WidgetTree` 通过组合的 `WidgetManagers` 提供横切能力，每个 manager 独立管理一种关注点：

| Manager | 职责 |
|---------|------|
| `StateManager` | 响应式 `State<T>` / `Computed<T>` 的依赖追踪与失效通知 |
| `FocusManager` | 焦点节点追踪、Tab 序管理、焦点变化事件 |
| `InteractionManager` | 指针命中测试、hover 状态、拖拽目标识别 |
| `DragManager` | 拖拽会话生命周期（DragStart/Move/End），跨节点数据传输 |
| `TextManager` | IME 组合态、文本选区、光标矩形管理 |
| `StyleManager` | 遗留样式预设查询（新代码优先 `ui::style::Style`） |

`WidgetManagers` 支持 per-component override：个别组件可使用独立 manager 实例，否则回退到树级默认。

## 布局

<a id="布局"></a>

布局分两阶段：**measure**（自底向上确定尺寸）→ **layout**（自顶向下分配位置）。

### Constraints

父容器向子节点传递 `Constraints { min: Size, max: Size }`：子节点在约束内自由选择尺寸，返回值被 `clamp` 到约束范围。`-1.0` 表示无上限，`0.0` 表示可为零。

### 容器布局算法

| 容器 | 主轴 | 交叉轴 |
|------|------|--------|
| `column` | 纵向 | 横向填满容器宽 |
| `column_fit` | 纵向 | 横向撑开到内容最大宽 |
| `row` | 横向 | 纵向填满容器高 |
| `row_fit` | 横向 | 纵向撑开到内容最大高 |
| `stack` | — | 子节点各自独立 measure，尺寸取最大 |

- `gap` 在主轴上插入固定间距；`padding` 收缩子节点可用空间
- `expand(true)` 子节点在分配剩余空间时获得弹性份额
- layout invalidation 仅标记受影响的子树
- 事件与 Timer 轮次先批量收集 Paint / Layout / Composite，最外层返回时一次加锁提交；队列以节点索引合并 Paint。`WidgetTree` 按 `tree_version` 借用先序缓存，layout 以复用的根、祖先路径与栈一次收集受影响顺序，并在整轮收敛中复用正序与逆序结果

### Grid

普通 Grid 由 `GridTrack::{Px, Fr, Auto}` 定义列/行，自动放置按源顺序寻找完整可用矩形。

响应式 Grid 固定 24 个 `Fr(1)` 单元，以本 Grid 内容区的 logical 宽度解析 `Breakpoints`；每次正常 layout 都重新计算 `Col` 的当前 span，并将 offset/order 转成无重叠的显式 cell 后交给同一 `GridLayout`。resize 只使受影响窗口的布局子树失效，不登记轮询、帧请求或跨窗状态。`order` 不改 WidgetTree、事件或语义顺序；reconcile 同步断点/列配置并保留既有子节点运行态。

## 浮层

<a id="浮层"></a>

浮层组件（Modal / Drawer / Notification / Message / Popover / Tooltip / Popconfirm）由 `OverlayStack` 统一管理层级与焦点。

`Message` / `Notification` 以共享 `Placement` 将队列约束在本窗 logical 客户区；窗口尺寸变化时由当前 frame 重算整组矩形。每项以稳定 ID 经 `Entering → Holding → Leaving` 推进：仅进出场登记连续动画帧，持有期只用一个最近截止 timer，`duration_ms = 0` 不登记 timer；leave 完成后才删除运行项。队列为空时命中与 overlay entry 同时为空，放置与动画配置随 reconcile 同步且保留既有队列。

应用默认通知层由每窗独立 `NotificationHandle` 驱动；`AppHandle::notify_error` 只写入并唤醒其 `WindowId` 对应的队列。窗口间不共享 `State` slot、到期 timer 或动画登记。

### OverlayStack

- `WidgetTree` 内每个窗口一个 `OverlayStack`，维护 `OverlayEntry` 节点栈
- 后打开的浮层层级更高；关闭时自动从栈中移除节点
- 浮层不单独作为跨窗 wake 源
- overlay 命中先递归 owner 子树，再回退 owner，保证 Modal / Drawer 内容可正常接收输入且遮罩仍阻断底层；`Modal::show` 的内容是普通 View 子树，`ModalContext::close` 的 scoped 请求在语义回调结束后由 owner 路径消费，启动既有 leave transition。遮罩覆盖整窗，因此关闭与过渡使用 full-frame damage，但不轮询

#### OverlayEntry

每个浮层由 `OverlayEntry` 描述：

| 字段 | 说明 |
|------|------|
| `owner` | 触发浮层的 `ComponentId` |
| `kind` | `OverlayKind`（Modal/Drawer/Popover/Tooltip/ContextMenu/Message/Notification/Custom） |
| `bounds` | 浮层在窗口中的逻辑矩形 |
| `z_index` | 层叠顺序（后开 > 先开） |
| `modal` | 是否阻断底层交互（Modal/Drawer 默认 true） |
| `dismiss_on_outside` | 点击外部是否关闭 |
| `focus_trap` | 是否启用焦点陷阱 |
| `managed` | 是否由框架自动清理（内置浮层均为 true；`Custom` 可设为 false 手动管理） |

`OverlayKind::Custom` 无预设行为，`modal` / `dismiss_on_outside` / `focus_trap` 均需手动调用 builder 设置。

### Focus Trap

- 浮层打开时焦点自动移入浮层内第一个可聚焦节点
- `Tab` / `Shift+Tab` 仅在浮层内循环，不逃逸到下层
- 浮层关闭后焦点回到触发元素；隐藏含焦点子树须统一 `FocusOut` 并注销 IME

### enter / leave 动画

浮层打开/关闭支持两段式动画（公开 `AnimationConfig`，内部 `TransitionPlayer`）。单体浮层在 leave 完成后移除节点；Message / Notification 逐项完成 leave，最后一项消失后移除 overlay。动画发现阶段若 entry membership 改变，框架在同一轮同步 `OverlayStack`；稳定动画帧不重复重建。`Suspended` 时冻结视觉推进。

## 无障碍

<a id="无障碍"></a>

框架从当前 WidgetTree 按需生成语义树（`AccessibilitySnapshot`），供测试 `TestApp`、Agent Bridge 以及未来读屏桥消费；不登记轮询或额外帧。

### 语义标注

- View 通过 `.role(AccessibilityRole)`、`.accessible_name(...)`、`.accessibility_state(...)` 与 `.aria("aria-*", value)` 覆写显式字段；未覆写字段继续从组件实时快照派生

### 焦点链

- `Tab` / `Shift+Tab` 遍历有效可见可接收事件的语义节点
- 无当前焦点时分别从首项 / 末项开始
- 浮层内受 `OverlayStack` focus trap 约束——焦点不逃逸到浮层外的节点
- 隐藏含焦点子树须统一 `FocusOut` 并同帧注销 IME

### 安全

- password / sensitive 字段永远不出现在语义快照、Agent Bridge 响应或日志
- 语义快照挂在事件/due work/帧轮次末尾，内容变化才改写；不注册额外 timer/线程/端口

## 事件系统

<a id="事件系统"></a>

### SystemEvent —— 系统事件

OS 原始输入经平台层映射为统一的 `SystemEvent` 枚举，共 29 种变体：

| 类别 | 变体 |
|------|------|
| 指针 | `PointerDown` / `PointerDoubleClick` / `PointerUp` / `PointerMove` / `PointerEnter` / `PointerLeave` |
| 滚轮 | `Wheel` |
| 键盘 | `KeyDown` / `KeyUp` |
| 剪贴板 | `Copy` / `Cut` / `Paste` |
| 文本输入 | `TextInput` |
| IME | `ImeCompositionStart` / `ImeCompositionUpdate` / `ImeCompositionEnd` |
| 焦点 | `FocusIn` / `FocusOut` |
| 窗口 | `Resize` / `WindowMaximize` / `WindowMinimize` / `WindowRestore` / `WindowFocus` / `WindowBlur` |
| 主题/区域 | `ThemeChanged` / `LocaleChanged` |
| 定时器 | `Timer` |
| 拖拽 | `DragStart` / `DragMove` / `DragEnd` |
| 文件 | `FileDrop` |

事件先沿 root → target 执行 opt-in capture，再从 hit-test target 向祖先冒泡；返回 `EventResult::Handled` 即停止。`PointerDoubleClick` 在每个节点先按专用变体派发，节点未处理时在同一节点回退为第二次 `PointerDown` 后才继续冒泡，确保内层普通控件不会被外层双击手势抢占。

View 的 `.on_event` / `.on_pointer` / `.on_key` / `.on_focus` / `.on_scroll` handler 作为节点元数据随 build 与 reconcile 替换，先于组件 `EventHandler` 执行；返回未处理才进入组件和父节点。`*_capture` 使祖先参与捕获。`.on_pointer` 明确选择连续 PointerMove；其他 View 不改变边界感知快路径。`focusable(true)` / 正 `tab_index` 只登记该节点的 Tab 顺序，不产生 timer、frame request 或跨窗状态；`.focus_handle(&handle)` 绑定应用持有句柄，reconcile 保留同一节点身份时换绑，remove / root reset / session shutdown 时失效。

### SemanticEvent —— 语义事件

组件可将原生输入转为高层语义动作，供 `on_semantic` 回调、Agent Bridge 以及 `ComponentHandle::emit()` 消费：

| `SemanticKind` | 触发源 |
|----------------|--------|
| `Click` | 鼠标左键 / Enter 键 |
| `Change` | 值变化（Input、Select、Slider） |
| `Submit` | 表单提交 |
| `Cancel` | Escape 键 / 取消按钮 |
| `Toggle` | Space 键（Checkbox/Switch） |
| `Navigate` | 方向键导航 |
| `Select` | 选项选中 |
| `Scroll` | 滚动偏移变化 |
| `Expand` | 展开/折叠 |
| `Custom` | 用户自定义 |

`SemanticPayload` 携带具体数据（点击坐标、变化值、选中等）。

### HandlerTable

`WidgetTree` 按 `ComponentId` 索引 `HandlerTable`，每个节点可注册多个 `HandlerRegistration`（按 `SemanticKind` 分组）。Reconcile 时同类型同 key 复用，不同 key 替换，适配 `State` 指纹绑定。

原始 `SystemEvent` View handler 直接属于 `BoxedWidget`，不进入语义 `HandlerTable`；reconcile 整体替换同节点声明，remove / root reset 随节点释放。无 handler 且组件无 `EventHandler` 的节点不参与交互态缓存判定。

## Form 校验模型

`Form` widget 只负责布局配置，不持有字段值、规则或业务闭包。`Form::field(...).build()` 生成应用侧 `FormModel`：字段值以 type-erased immutable handle 保存，成功校验组装为 typed `Values`；内置、inline custom 与字段依赖规则按声明顺序同步执行，每字段止于第一条错误。默认 `OnSubmit` 由 `validate()` 激活；`OnChange` / `OnBlur` 分别由 `set_value()` / `blur()` 激活并缓存当前错误。依赖源变化后以访问集对直接与传递依赖各重验一次，循环不会重复执行。

`Form::list(...).build()` 生成应用侧 `FormListModel`：schema 中的不可变规则按行共享，字段值与错误逐行独立；`FormListItemId` 单调分配且删除后不复用。列表只用一个 `State<Vec<FormListItemId>>` 表达结构；`render_rows()` 构建期读取该 State，并把稳定 ID 写为 keyed child。增删只触发所属根 View 的一次结构 reconcile，未删除行按 key 复用；字段校验不触发树遍历、绘制、timer、FrameOpportunity 或跨窗 wake。

## VirtualScroll

<a id="virtualscroll"></a>

虚拟列表用于万级数据场景，仅渲染可视区内的行：

- **视口**：由 `.size(w, h)` 设定，超出部分不创建 DOM/Widget 节点
- **行高**：`.item_height(h)` 固定行高，快速计算 materialized_range
- **预渲染**：`.overscan(n)` 控制可视区外额外渲染行数（默认 5），减少快速滚动时的白屏
- **物化**：滑出视口的行从树中移除，重新进入时重建，不保留实例状态
- **render 契约**：`.render(|index| view)` 返回普通 `View`；工厂按 `ComponentId` 存在 keyed side table，物化时捕获 State / Effect 并注册事件，组件数据不持有业务闭包
- **工作边界**：初次构建、布局导致可见范围变化或 wheel 事件才刷新本视口子树；范围未变不重建，无 timer / FrameOpportunity / 跨窗 wake。滚动继续登记本视口 Composite 与 rect damage，同轮由现有失效队列合并
- **滚动状态**：`VirtualListScroll` 内部维护 offset + item_count，不参与全局 dirty 合并

## 图形

<a id="图形-api与帧提交硬约束"></a>

`GraphicsBackend` = API 请求（非 OS 别名）。轴：`RasterMode` × `PresentMode` × API；按 recipe 装配。

解析：builder > 环境变量 > Settings > 默认 **Vulkan**。禁跨 API 偷换；仅显式 `Auto` 可跨 API probe。registry 只陈述能力（可含 Planned stub），不替 App 选 API。

```text
App / WindowSession
  → resolve GraphicsBackend
  → bootstrap（recipe | Auto 候选）
  → GraphicsDevice（可按 adapter/API 共享；线程亲和）
  → WindowSurface（每窗；logical / drawable / DPR）
  → FrameEncoder（单一有序、API 中立）
  → Presenter::present() -> Result<PresentOutcome, GraphicsError>
```

- **帧提交**：一帧一条命令序列；禁双画序；每帧至多一个 `Presenter`；成功指标仅提交成功后记。initialize / resize / make-current / begin-end-frame / present → typed `Result`；CPU 像素写入 retained buffer 不等于提交成功，最终 OS present（含 GDI `GetClientRect` / `GetDC` / `StretchBlt`）失败须 typed 返回；失败帧保留 dirty。透明 CPU segment 只收 source-independent op；Additive / Scroll 等目标相关 op 必须进入 Native IR，无法精确降级的几何或状态在录制边界 typed 拒绝。
- **DisplayList 录制**：文本指令以 `Arc<str>` 共享不可变内容，仅在 recorder 生效时创建所有权；列表 clone 不复制文本缓冲。无缩放 Picture 在整数矩形裁剪下保留一条精确裁剪指令；CPU segment 同尺寸 replay 走连续行拷贝 / 混合，禁逐像素重复求缩放坐标。scratch batch 只清已写并集，写区过大或无界时清整面。recorder 嵌套、panic 展开与 replay 临时停录均须恢复上一层目标和开关，禁止留下悬空录制指针或改变调用方状态。
- **矢量便捷图元**：`PaintContext::stroke_arc` 使用弧度并分解为至多四段三次 Bézier，再进入共享 `Path` 描边、DisplayList 与 CPU / native GPU tessellation；禁旁路录制另画一遍。
- **尺寸契约**：`GraphicsEngine::logical_extent()` 是布局与窗口 reconciliation 的精确 logical viewport；默认等于 canvas，仅 drawable-sized 引擎覆盖。`WindowDriver` 禁以单一 DPR 从 physical canvas 分别反推两轴，避免非整数缩放的独立取整造成 layout 漂移或 busy resize。GPU context 的 `width` / `height` 与 PixelUpload canvas 为 drawable physical。
- **绘制与提交解耦**：GPU 主路径可绘全帧；仅当 damage 外最终像素不变且 backend 已证明 present coherency 时才提交窄 damage，否则 Full。`PresentUpload` 的 CPU canvas 是 retained buffer，可独立提供 dirty-rect 绘制与 scroll memmove；Vulkan present 即使仍为 `FullOnly`，也不得把 CPU 绘制扩大为全帧。绘制 damage 与 present damage 是正交能力。**未证明 coherency 时走 Full 是正确性优先的合规资源策略**，禁止为「省带宽」在未证明一致性时提交窄 damage。
- **damage**：UI dirty 为 logical top-left；提交按 DPR / transform 转 drawable，min `floor`、max `ceil`、裁到 extent。resize / DPR / orientation / `currentTransform` / surface generation 改变后首帧强制 Full。多块脏区以 AABB 并集清空（避免离散清空时父背景 FillRect 填入缝隙），干净区域也被重绘——遵循「未证明安全则保守」原则。Vulkan incremental present 相对 `currentTransform`；Wayland 优先 [`damage_buffer`](https://wayland.freedesktop.org/docs/html/apa.html#protocol-spec-wl_surface)；禁直接 `as i32` 截断。
- **present coherency**：typed `FullOnly` / `RetainedBuffer` / `TrackedSwapchain`；`PresentDamageTracker` 只在成功 present 后提交 signature 与 history。缺 identity / history / generation / transform / 修复能力一律 Full（见「绘制与提交解耦」——未证明时 Full 是合规策略）。
- **IR**：`FrameRasterOp` = `FillRect`（SrcOver）、`FillRectAdditive`、`FillRoundedRectAdditive(FrameRadius)`、`ScrollCopy`。后三者须直接作用于累积目标；`FrameRadius` 只容纳有限非负半径。native GPU 通过 readback → 共享参考 apply → replace upload 保持逐像素语义，缺 readback / upload 任一侧则 typed `NotImplemented`；禁透明 CPU segment + SrcOver 冒充。
- **回退**：缺实现 / Planned stub → typed 失败后 Software/CPU；禁称「平台永久不支持」。unsupported → 有界 CPU segment；禁近似冒充。
- **恢复**：surface rebuild → recipe rebuild → 同 API 下一 recipe → Software，各步只尝试一次；仅 `Auto` 可跨 API。旧 engine 须先 checked teardown，再创建同 native surface 的 replacement；teardown 失败时禁止探测第二份 context。Software 的 `ExternalPresenter` 成功才重置序列，序列耗尽或 `OutOfMemory` 进入终态。resize 失败仍记住最新目标 extent；backend 不得把 `DeviceLost` / `SurfaceLost` / OOM 抹成 `NotImplemented`。Vulkan wait-idle 返回 `DeviceLost` 时仍须销毁本窗 child；共享 device 标记 lost 后所有 peer typed 停止提交，池不得把它交给 replacement，最后一个 lease 才销毁逻辑 device。其他 wait 失败保持 typed 且保留未排空父对象。
- **诊断**：成功 recipe 记录 backend 与可得的 adapter identity；Vulkan 须含名称 / 类型、vendor / device、API / driver 版本与 queue family。候选级扩展查询或 graphics queue 的 present-support 查询失败只拒绝该候选 / queue，继续检查其余 queue 与适配器；最终 adapter / queue 选择失败须列出全部已检查候选及拒绝原因，保留首个 typed 根因。Vulkan 仅在 `VK_EXT_device_fault`、`deviceFault` 与 Vulkan 1.1 core / `VK_KHR_get_physical_device_properties2` 查询路径同时可用时启用 fault reporting；驱动返回 `ERROR_DEVICE_LOST` 后才查询，address / vendor info 各至多 16 条，不分配 vendor binary。首次 fault 报告或查询失败均随 `GraphicsDeviceLost` 缓存到共享 device 原因链，peer 与后续错误不得覆盖它。
- **滚动帧**：`begin_frame` 先清 dirty 区，故 `ScrollCopy` 读到的是已清空像素；render_frame 须把滚动视口并入清/绘区。
- **绘制裁剪同步**：`begin_frame` 以 `FrameReady` 返回实际清除 / 裁剪区；`FrameRenderer` 必须以该区驱动录制剪枝。引擎把 `DirtyRects` 请求提升为 Full 时，present damage 也须提升；因后端不支持局部绘制而主动请求 Full 时，仍可在缓冲一致性已证明后保留窄 present damage。实际区不得小于请求区，否则 typed `InvalidState`；禁另算一份录制 clip。
- **所有权**：`draw` 不持有 GL/D3D/Vulkan/Metal 对象；bootstrap 收 `NativeSurfaceHandle`。共享 `GraphicsDevice` 以 adapter / API / queue family / thread affinity 为 key；每个新 `WindowSurface` 仍须查询该 queue 的 present support，不兼容则该窗另建 recipe。Vulkan runtime 以 UI 线程本地弱引用复用 instance，按 physical device + queue family 复用 device；surface / swapchain / command pool / fence / staging buffer 仍逐窗独占；复用单 staging buffer 时，CPU 覆写或替换前必须等待上一 submission fence，禁在 GPU 仍读取时写入。`vkQueuePresentKHR` 的 wait semaphore 按 swapchain image 独立持有并按 acquire 返回的 image index 复用；可用 `VK_EXT_swapchain_maintenance1` 时每次 present 绑定独立 fence，重建前只等待本窗 frame fence，再逐 fence 等待并 reset；新旧 image 数相同时跨 generation 复用整组 present semaphore / fence，禁止把逐窗重建扩大为 `vkDeviceWaitIdle`。关闭前仍须逐 present fence 等待。扩展缺失时，运行期旧 swapchain 与其 semaphore 延迟到新 generation 中已呈现 image 被再次 acquire 且对应 acquire wait 的 submission 完成后回收。禁以普通 submission fence 或 `vkDeviceWaitIdle` 冒充 presentation 已消费 semaphore；无扩展的最终 shutdown 没有规范级 completion primitive，兼容回收不能充当 P6 真机通过证据。生命周期边界为 `try_shutdown`（无 void `shutdown`）；`ThreadBoundGraphicsContext` 错线程 Drop 时 leak 内层，禁错线程 native teardown。

## 设计令牌与色彩体系

<a id="设计令牌与色彩体系"></a>

色彩体系包含相互独立的“选色色板”和“运行时令牌”。选色色板公开 12×10 主色、13 阶中性色、4 类功能色阶与 AntV 10 色分类数据色板；运行时由 `ThemePrimitives`（8 个基色）推导 `DesignTokens`（~100 个令牌）。两者共享种子约定，但不把 120 色复制进每个主题实例。

### 模型

```text
  PrimaryHue / generate_color_scale       bg / text / border + 5 个语义基色
                 │                                      │
                 ▼                                      ▼
     ColorScale（选色，按需取用）              ThemePrimitives
                                                        │
                                                        ▼ mix / alpha
                                               DesignTokens（~100 字段）
                                                        │
                           ┌────────────────────────────┼────────────┐
                           ▼                            ▼            ▼
                         View                         render    功能色阶按需生成
                    (tk.color_*)                 (ctx.tokens())
```

- `ui::theme`：定义 `PrimaryHue` / `ColorScale` / `generate_color_scale`、中性与分类色板、`ThemePrimitives`、`DesignTokens` 及推导公式
- `draw::painting`：定义 `IColorTokens` trait，`PaintContext` 通过 trait 消费颜色
- `app`：管理 `Theme` 实例（`Arc<dyn TokenProvider>`），由 `AppHandle::set_theme` 触发广播

### 基色与推导

| 基色 | 角色 | 亮色默认 | 暗色默认 |
|------|------|----------|----------|
| `primary` | 品牌主色（取自 12 色板 Blue） | `#1677ff` | `#1677ff` |
| `success` | 成功 / 正向 | `#52c41a` | `#49b915` |
| `warning` | 警告 / 提醒 | `#faad14` | `#faad14` |
| `error` | 错误 / 危险 | `#ff4d4f` | `#ff4d4f` |
| `info` | 信息 / 提示（默认 = primary） | `#1677ff` | `#1677ff` |
| `bg` | 页面底色 | `#f5f5f7` | `#151515` |
| `text` | 文字基色 | `#000000` | `#ffffff` |
| `border` | 边框基色 | `#e4e4e7` | `#38383a` |

推导公式（`ThemePrimitives::into_design_tokens`）：

- **品牌色 hover/active**：primary 向 white/black 各混 15%
- **品牌色 bg/border**：亮色 primary→white 85%/55%、暗色 primary→bg 80%/45%
- **背景层级**：`color_bg_container` = bg→white 55%（亮）/ bg.lighten(4%)（暗）；`color_bg_elevated` = white（亮）/ bg.lighten(12%)（暗）；`color_bg_layout` = bg→white 20%（亮）/ bg.darken(3%)（暗）
- **文字层级**：text.with_alpha(224/153/102/51) → text / secondary / tertiary / quaternary
- **填充层级**：text.with_alpha(31/15/10/5) → fill / secondary / tertiary / quaternary
- **语义色**：与品牌色同公式，各自 bg/border 对应混 white（亮）或混 bg（暗）
- **链接色**：与 primary 一致

### 主题切换

- 切换路径：`AppHandle::set_theme(Theme)` → 逐窗 `WindowDriver` 标记 palette-only dirty
- **palette-only repaint**：仅使用语义色 / 令牌色的节点参与重绘；使用固定 `Color::from_rgb()` 的节点不重绘
- `DesignTokens` 为纯数据 struct（`Clone`），`DynTokens` 以 `Arc` 共享
- 系统主题跟随：`App.follow_system_theme(true)` 为 opt-in；仅在 display 发出变化信号时更新，不轮询
- 自定义主题：`from_primitives`（覆盖 8 基色）/ `from_primaries`（传入 12 个主色种子，仅 Blue 进入品牌令牌）/ `with_brand_primary`（只换品牌色）
- 自定义 `Color` 使用 8-bit RGBA；`hex` 接受 6 位 RGB / 8 位 RGBA，`with_alpha` 替换 8-bit alpha，不混入第二套浮点通道语义

### 色板边界

- `PrimaryHue::palette()` 返回静态 `ColorScale`；0 最浅、9 最深、5 为主色，`shade()` 越界返回 `None`
- `generate_color_scale()` 以 HSV 阶梯从任意 RGB 种子生成同结构色板；alpha 不参与推导，输出不透明
- `NEUTRAL_PALETTE` 是显式 13 阶选色色板；`DesignTokens` 的文字、背景、填充与边框仍从 bg / text / border 动态推导
- `DesignTokens::functional_color_scale()` 从当前实例的 success / warning / error / info 种子按需生成，故主题覆写后保持一致
- `DATA_VISUALIZATION_PALETTE` 是固定 10 色离散分类顺序，不参与主题切换与 palette-only 重绘
- 色板值是纯 `Color` 数据；访问或生成不登记帧、timer、线程或窗口工作

## 附：大模型控制协议

<a id="大模型控制协议"></a>

产品附能力（开发预览），不改变主路径应用写法。协议名 `uix.agent.v1`。用法 → [`使用.md`](使用.md#agent-bridge-开发预览)；缺口 → [`进度`](进度.md#附能力不计-p6)。

### 边界与组成

- 显式启用（`agent-control` feature + `.enable_agent_control()`）、仅限本机同一 OS 用户的进程级端点。不是 TCP、跨机器远控、UIA/读屏桥；不提供 shell、文件或网络访问。
- 三层：语义树、动作执行器、传输。`TestApp` 与真窗 Bridge 共用前两层；传输差异不得进入组件。
- 内置组件自动提供语义与动作；自定义复用 `AccessibilityRole`/`AccessibilityState`。v1 不负责截图或 GPU readback。

### 发现与安全

- Discovery：Windows `%LOCALAPPDATA%\uix-agent`；Linux/macOS `$XDG_RUNTIME_DIR/uix-agent-<uid>`。描述文件含 pid、endpoint、随机 token；端点成功后原子公布，退出删除。
- 传输：Windows Named Pipe（受保护 DACL 只授权当前进程 `TokenUser` SID）；Linux/macOS UDS（目录 `0700`，accept 后核 peer effective uid），其他 Unix 无可靠 peer credential API 时 fail-closed。不监听 TCP/UDP。Wire：UTF-8 JSON Lines，单条 ≤ 4 MiB。
- 首条必须带 token 的 `hello`；连接内串行，并发用多连接（≤ 8）。同窗动作容量 64 FIFO。

### 语义与动作

- 快照含 `window_id`、generation、`revision`、`presented_revision`、节点树。节点含 opaque `node_id`、可选 `automation_id`、role、state、bounds、actions。
- `node_id` 仅同 generation 有效；跨启动定位用 `automation_id`。password/sensitive value 永不出现在快照、响应或日志。
- 动作经目标 `WindowSession` 正常 semantic/`SystemEvent` 路径；禁 IPC 线程直接改 Widget/State/绘制树。
- 动作后 State → Effect → reconcile → 最多 32 settle 轮次。视觉证据用 `wait` 等到 `presented_revision >= revision`；不可呈现 → typed `not_presentable`。

### 错误与资源

- typed error 覆盖 unauthorized/window_not_found/stale_window/node_not_found/unsupported_action/timeout 等。
- 上限：消息 4 MiB、文本 64 KiB、连接 8、每窗队列 64、settle 32、wait 30 s。
- 除 transport worker 外无轮询线程；无客户端时主循环 DeepIdle。审计只记结果码与耗时；token/输入文本/password 不记录。
