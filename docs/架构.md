<a id="核心理念最高规则-105"></a>

## 核心理念（最高规则 #105）

> **用最少资源，做最好效果。**

冲突时以本规则为准，按文档重构，不留兼容层。裁决原文 → [#105](决策.md#d105)。

| 信条 | 含义 |
|------|------|
| 有触发才工作 | 无事件 / 失效 / register → DeepIdle |
| 无 pending 零开销 | 不无条件 layout / render / present / tick Effect / 定时 wake |
| 变化尽量窄 | 脏区 / Composite / 节点级标脏 |
| 效果不妥协 | active 期完整正确（拖拽、hover、IME、动画） |
| 全框架统一 | `app` / `ui` / `draw` / `native` / `data` 均遵守 |

<a id="开发者契约零维护"></a>

**开发者契约（#130）**：调用方只写 View + State（`set`/`update`）、业务 Effect、`run_after`/`run_interval`、opt-in 主题/连续指针；**禁止**维护 Picture 名单 / ActiveWorkRegistry / 手动全树 invalidate / 固定 interval 探活 / 轮询 Effect（#131）/ 后台直改 WidgetTree。跨线程回 UI **只**走 `post_to_ui`（#133）。裁决 → [#130](决策.md#d130)。

<a id="新-api-审查清单"></a>

**新 API 审查**（公开 API / 主循环 / 每帧回调须能答；否则不得合并；豁免 → #181+，当前无 · [#158](决策.md#d158)）：

1. 何时工作？（事件 / 失效 / register）
2. 何时休眠？（pending 清空且 unregister → DeepIdle？）
3. 标脏能否窄到 rect / Composite？
4. 同帧变更能否 batch？

7. 调用方是否零维护？（#130 →「否」须维护则不合格）

## 本仓硬约束（UIX）

六域：`core` / `native` / `draw` / `ui` / `app` / `data`。`A → B` = A 可直接依赖 B；未列禁止。

| 域 | 允许依赖 |
|----|----------|
| `core` | — |
| `native` | `core` |
| `draw` | `core`, `native` |
| `ui` | `core`, `native`, `draw` |
| `data` | `core` |
| `app` | `core`, `native`, `draw`, `ui`, `data` |

- 下层不反向依赖；同层经 trait / registry 正交组合（[#168](决策.md#d168) · [#171](决策.md#d171)）。渲染轴 → [#168](决策.md#d168)–[#172](决策.md#d172)。
- `native` 封装 OS；上层只用 `native::traits`，禁止 `use native::backends::*`。除 `native` 外跨 OS 同构（[#167](决策.md#d167)）。
- `#[cfg(windows/unix)]` 仅 `native/backends/`、`native/graphics/**/platform/`、`native/factory/`；上层用 trait + `Result`。
- `draw` ↛ `ui`/`app`；`ui` 不碰平台 backend；业务回调不进组件 struct；`data` 不进 UI 热路径、默认不 load/save。
- 入口：`use uix::prelude::*;`

<a id="主循环要点"></a>

**主循环（#106–#118 · #173）**：三态 `DeepIdle` / `RegisteredActive` / `Active`（无 LightIdle）；无 pending → blocking `wait_event`。Active 帧：UiEvent → due work → `post_to_ui` → semantic → Effect → **一次** reconcile → layout? → render/present?。进程 wake ≠ 全窗 Active。禁止：固定 interval 探活、DeepIdle 下 `tick_effects`、无 register 的周期工作。

## 应用作者入口

入口：`use uix::prelude::*;`（[#69](决策.md#d69)）。门面 → [#178](决策.md#d178)–[#180](决策.md#d180)。后台回 UI 只走 `post_to_ui`。全栈边界 → [#166](决策.md#d166)。

### 示例 vs 探针

| 来源 | 角色 |
|------|------|
| [README · 示例](../README.md#示例) | **入门复制**：最小 Counter |
| `counter_facade_compiles_*`（`src/tests/ui/view/combinators.rs`） | README 的 **编译探针**（CI 守卫） |
| [`demo/`](../demo/README.md) | **能力全景**（多页 / Timer / 主题）；非 starter |

### 点击路径

| API | 何时用 |
|-----|--------|
| `on_click(&state, \|s\| …)` | **默认**：有 State，指纹稳定（[#178](决策.md#d178)） |
| `on_click_fn(\|\| …)` | 无 State；每次 reconcile 保守重绑。`_fn` 因 Rust 无法重载而保留 |
| `on_click_capture` | 兼容别名；新代码勿用 |
| `semantic_handler!` | 需显式指纹 / 非 Click 语义时 |

### 宏分层

| 层 | 宏 | 受众 |
|----|-----|------|
| 日常 | `views!` · `with_cloned!` | 应用作者（异质子节点 / root·on_start 捕获） |
| 进阶 | `component!` | 自定义组件作者 |
| 框架 | `tree!` · `impl_widget_component!` · `semantic_handler!` | 框架 / 深度集成；日常应用少用 |

### Style 链

样式真相在 `ViewNode`；`StyleExt` 仅是 `Into<ViewNode>` 桥接（委托同名方法）。**先** builder 专有（`primary` / `on_click`），**再** `bg` / `padding` 等。列容器：填满用 `column`，intrinsic 用 `column_fit`。
