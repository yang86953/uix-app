<a id="核心理念最高规则-105"></a>

## 核心理念（最高规则 #105）

> **用最少资源，做最好效果。**

冲突时以本规则为准，按文档重构，不留兼容层。裁决原文 → [#105](决策.md#d105)。

| 信条 | 含义 |
|------|------|
| 有触发才工作 | 无事件 / 失效 / register → DeepIdle |
| 无 pending 零开销 | 不无条件 layout / render / present / tick Effect / 定时 wake |
| 变化尽量窄 | 脏区 / Composite / 节点级标脏 |
| 效果不妥协 | active 期完整正确（拖拽、hover、IME、动画） |
| 全框架统一 | `app` / `ui` / `draw` / `native` / `data` 均遵守 |

<a id="开发者契约零维护"></a>

**开发者契约（#130）**：调用方只写 View + State（`set`/`update`）、业务 Effect、`run_after`/`run_interval`、opt-in 主题/连续指针；**禁止**维护 Picture 名单 / ActiveWorkRegistry / 手动全树 invalidate / 固定 interval 探活 / 轮询 Effect（#131）/ 后台直改 WidgetTree。跨线程回 UI **只**走 `post_to_ui`（#133）。裁决 → [#130](决策.md#d130)。

## 本仓硬约束（UIX）

六域：`core` / `native` / `draw` / `ui` / `app` / `data`。`A → B` = A 可直接依赖 B；未列禁止。

| 域 | 允许依赖 |
|----|----------|
| `core` | — |
| `native` | `core` |
| `draw` | `core`, `native` |
| `ui` | `core`, `native`, `draw` |
| `data` | `core` |
| `app` | `core`, `native`, `draw`, `ui`, `data` |

- 下层不反向依赖；同层经 trait / registry 正交组合（[#168](决策.md#d168) · [#171](决策.md#d171)）。图形装配与边界 → [#181](决策.md#d181)–[#186](决策.md#d186) · [#202](决策.md#d202)。
- `native` 封装 OS；普通平台能力只走 `native::traits`，禁止 `use native::backends::*`。图形请求由 App 按 [#202](决策.md#d202) 解析，初始化仅允许 `draw::engine::bootstrap → native::factory` 入口；probe 单元是 recipe 行，运行期恢复只走 [#182](决策.md#d182) / [#202](决策.md#d202) 的有限状态机。除 `native` 外跨 OS 同构（[#167](决策.md#d167)）。
- 平台 `#[cfg]` 仅在 `native/backends/`、`native/graphics/**/platform/`、`native/factory/`；上层用 trait + `Result`。图形 Cargo feature 必须同时裁剪 registry 行、模块和可选依赖，禁止“仅禁用 registry 但仍编译实现”。
- `draw` ↛ `ui`/`app`；`ui` 不碰平台 backend；业务回调不进组件 struct；`data` 不进 UI 热路径、默认不 load/save。
- 入口：`use uix::prelude::*;`

<a id="图形-api与帧提交硬约束"></a>

### 图形 API 与帧提交硬约束

目标所有权与调用形态由 [#181](决策.md#d181)–[#186](决策.md#d186) 与 [#202](决策.md#d202) 裁定；当前实现偏差和直接源码证据只在[问题台账](问题.md#已确认图形架构缺陷)维护，实施顺序只在 [P6.9](进度.md#p69-图形契约整改)维护。

```text
App / WindowSession
  → resolve GraphicsBackend（builder > env > Settings > Vulkan；Auto 仅显式 opt-in）
  → graphics bootstrap（具体 API 的 recipe；或显式 Auto 候选）
  → GraphicsDevice（每 adapter/API 可共享；线程亲和）
  → WindowSurface（每窗口；logical/drawable/DPR）
  → FrameEncoder（单一、有序、API 中立）
  → Presenter::present() -> Result<PresentOutcome, GraphicsError>
```

| 边界 | 硬约束 |
|------|--------|
| App 选择 | `GraphicsBackend` 是 API 请求，不是 OS 别名；默认 Vulkan。具体请求不得跨 API 偷换，只有显式 `Auto` 可按 registry 顺序跨 API probe。平台 registry 只陈述当前 adapter 是否已实现。 |
| 帧顺序 | clear、native draw、CPU segment、offscreen render/blit 进入同一命令序列；禁止同时存在“延迟 native 队列”和“立即 blit”两种画序事实源。 |
| present 所有权 | 每帧最多一个 `Presenter` 执行最终提交；`PresentOutcome` 只描述真实结果，不兼任“调用方还需 present”的命令。成功指标只能在提交成功后记录。 |
| 生命周期 / 恢复 | initialize、resize、make-current、begin/end-frame、present 均为 typed `Result`；失败帧保留 dirty。具体 API 按 `surface rebuild → recipe rebuild → 同 API next recipe → Software` 恢复；显式 `Auto` 才可继续其他 API 候选；`OutOfMemory` 不得静默回退。 |
| 线程 / 所有权 | context、surface、device 不得以无依据的 `unsafe impl Send/Sync` 跨线程；跨线程只传 API 中立且具 `Send` 证明的命令数据。旧对象必须在所属线程完成 shutdown/drop。 |
| API 中立 | `draw` 不持有 GL/D3D/Vulkan/Metal 对象或 proc loader；API 对象、shader、pipeline 与提交实现归 `native/graphics/<api>/`。原始窗口指针必须封装为 opaque handle，或置于写明安全前提的 `unsafe` 边界。 |
| recipe / caps | registry 允许同一 API 多个 `(backend,raster,present)` recipe；create/render/sample/crop、offscreen、partial redraw、surface damage 分别声明并由行为测试证明，禁止用一个布尔量推导无关能力。 |
| 未实现 API | 缺 registry 行、feature 或平台 adapter 必须形成包含请求 API、平台和 probe 阶段的 typed 初始化失败，并在 App 层明确记录 Software/CPU fallback；不得把实现缺口表述为 API 永久不支持该平台。 |
| fallback | unsupported operation 形成有界 CPU segment，保持 blend/clip/source crop/scissor，并只上传 damage；不等价能力显式 unsupported，不以近似效果冒充。 |
| 平台 surface | EGL damage 只是 compositor hint；没有 buffer-age/preserved-buffer 协议不得启用 partial redraw，且坐标转为左下角。Vulkan 使用 RAII 与事务式 swapchain 重建，fence 只在即将 submit 前 reset。各平台共用 logical/drawable/DPR 单一来源。 |
| 能力命名 | Metal `Cpu × PixelUpload` 只能称 Metal identity / pixel-upload context；未有 Metal native raster 前不得记录为 Metal GPU engine。D3D11/D3D12、EGL、Vulkan 也只能声明已由 caps 与证据证明的能力。 |

**迁移期间禁止兼容性弱化**：不得为匹配现实现而降低 Picture、blend、offscreen、partial redraw 或错误恢复要求；尚未满足的能力收紧 caps 并保留问题，直至对应验收关闭。

<a id="主循环要点"></a>

**主循环（#106–#118 · #173）**：三态 `DeepIdle` / `RegisteredActive` / `Active`（无 LightIdle）；无 pending → blocking `wait_event`。Active 帧：UiEvent 映射及其同步 semantic → due work → `post_to_ui` → AppState semantic → Effect → **一次** reconcile → layout? → render/present?。进程 wake ≠ 全窗 Active。禁止：固定 interval 探活、DeepIdle 下 `tick_effects`、无 register 的周期工作。

### 点击路径

| API | 何时用 |
|-----|--------|
| `on_click(&state, \|s\| …)` | **默认**：有 State，指纹稳定（[#178](决策.md#d178)） |

### 宏分层

| 层 | 宏 | 受众 |
|----|-----|------|
| 日常 | `views!` · `with_cloned!` | 应用作者（异质子节点 / root·on_start 捕获） |

### Style 链

样式真相在 `ViewNode`；`StyleExt` 仅是 `Into<ViewNode>` 桥接（委托同名方法）。**先** builder 专有（`primary` / `on_click`），**再** `bg` / `padding` 等。列容器：填满用 `column`，intrinsic 用 `column_fit`。
