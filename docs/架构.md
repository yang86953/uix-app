# 架构

> 分层、主循环、托管与图形硬约束（不含用法与排期）。

## 分层

依赖只能向下，未列边禁止：

| 域 | 允许依赖 |
|----|----------|
| `core` | — |
| `native` | `core` |
| `draw` | `core`, `native` |
| `ui` | `core`, `native`, `draw` |
| `data` | `core` |
| `app` | `core`, `native`, `draw`, `ui`, `data` |

- OS 能力经 `native::traits`；禁上层 `use native::backends::*`
- `#[cfg(OS)]` 仅：`native/backends/`、`native/graphics/**/platform/`、`native/factory/`
- `draw` ↛ `ui`/`app`；`ui` 不碰 backend；业务回调不进组件 struct：语义 handler、paint renderer 与虚拟子项 factory 随节点登记并以 `ComponentId` 归属，reconcile / remove / root reset 同步替换或清理；`Form` 自定义 validator 只在应用持有的 `FormValidatorTable` 中按稳定 `FormValidatorKey` 解析；`data` 不进热路径
- 图形初始化：`draw::engine::bootstrap → native::factory`（recipe 为单位）
- 公开入口：`uix::prelude::*`

## 主循环

<a id="主循环要点"></a>

事件循环仍只有三态（无 LightIdle），surface 可用性是与之正交的逐窗状态：

| 轴 | 状态 | 含义 |
|----|------|------|
| `LoopState` | `DeepIdle` / `RegisteredActive` / `Active` | 无待办并阻塞；等待已登记 deadline / frame callback；已有可立即执行工作 |
| `SurfaceState` | `Renderable` / `Suspended(reason)` / `Recovering { retry_at, attempt }` | 可提交；等待 expose / 非零 extent / surface 恢复；按 typed 原因有界重试 |

- `DeepIdle` 条件：无待处理事件、queue、due work、reconcile，也无 outstanding frame request / recovery deadline。dirty 若属于 `Suspended` 窗口，不算可立即执行工作。
- wake ∈ {OS / 生命周期、queue、due deadline、frame opportunity、recovery / availability deadline}；一窗 wake / Active 不得把他窗拉成 Active。
- **事件轮次**：批量 drain UiEvent + 同步 semantic → due 非视觉工作 → `post_to_ui` → AppState semantic → Effect；只合并 dirty / reconcile，并为该窗申请至多一个 frame request。
- **帧轮次**：收到 `FrameOpportunity { request_token, frame_time, target_present_time? }` 后，消费截至该点的最后一次 root → **一次** reconcile → 按需 layout → paint → 至多一次 present。成功才消费 dirty；提交后仍有动画 / dirty 才申请下一次机会。
- frame request 必须 one-shot、可合并、逐窗所有；`request_token = surface_generation + request_id`，原生回调只可完成完全相同的 outstanding token。fallback、surface 变化或 suspend 消费 / 取消 token 后，不能取消 OS 对象的 backend 也必须抑制迟到回调，防止它误吃同 generation 的下一次请求。平台可用原生节拍，否则用可取消的 monotonic deadline fallback；Qt [`QWindow::requestUpdate`](https://doc.qt.io/qt-6/qwindow.html#requestUpdate) 与 Win32 [update region](https://learn.microsoft.com/en-us/windows/win32/gdi/the-update-region) 同样要求“先累计、后一次绘制”。
- 原生登记须服从各平台提交时序：Wayland 在当前提交前登记 [`wl_surface.frame`](https://wayland.freedesktop.org/docs/html/apa.html#protocol-spec-wl_surface)；Windows 先登记 token，只有对应帧 present 成功后才把它提交给逐窗惰性 worker，worker 在 UI 线程外阻塞 [`DwmFlush`](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/nf-dwmapi-dwmflush)，再以私有窗口消息回送 exact epoch/token；macOS 为活动窗口惰性创建 [`NSWindow.displayLink(target:selector:)`](https://developer.apple.com/documentation/appkit/nswindow/displaylink%28target%3Aselector%3A%29)，请求只预置 token，exact present 成功后才解除暂停，一次 callback 立即再暂停并回送该 token。静态窗口不创建原生节拍对象；失败、拥塞、取消或窗口销毁均保留 deadline fallback 并丢弃迟到 callback，其中 macOS 取消已提交请求或销毁窗口须先 `invalidate`，API 不可用则直接沿用 fallback。DWM 合成机会与 display link 均不等于逐窗遮挡信号；遮挡须使用本窗独立的 compositor / window-server 能力，支持的 DXGI recipe 可另接 [frame-latency waitable object](https://learn.microsoft.com/en-us/windows/win32/api/dxgi/ne-dxgi-dxgi_swap_chain_flag)。
- 动画节点保持 open registration，但全窗只维护一个下一帧请求；`dt` 来自 frame opportunity 的单调时间。窗口 `Suspended` 时取消视觉 deadline、冻结动画，恢复首帧重基（`dt = 0`），不补跑隐藏期间的帧；业务时间继续由 Timer 表达。Apple [display link](https://developer.apple.com/documentation/quartzcore/cadisplaylink) 与 Android [Choreographer](https://developer.android.com/reference/android/view/Choreographer) 也以显示时间驱动视觉更新。
- `Hidden` / `Minimized` / zero extent 进入 `Suspended`：保留 dirty 与 animation registration，取消视觉 deadline，不 layout / paint / present。`WindowHide` / `WindowShow` 是逐窗生命周期信号；Windows 由 `WM_SHOWWINDOW` 同步真实可见性，`WindowDriver` 在视觉阶段前再复核 `PlatformWindow::is_visible()`，覆盖事件或运行时任务已隐藏但生命周期事件尚未到达的同轮。延迟首显在第一次成功 present 前豁免；`WindowShow` 只解除 `Hidden`，不得解除 terminal failure。
- Windows D3D11 bitblt swapchain 的普通 `Present` 若返回 [`DXGI_STATUS_OCCLUDED`](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/dxgi-status)，该窗进入 `Suspended(Occluded)`；这是可用性状态，不触发 surface / recipe rebuild。框架只登记 100 ms 起、指数退避且封顶 1 s 的逐窗 availability deadline；到期先于 animation / reconcile / layout / paint 调用一次不提交帧数据的 [`Present(0, DXGI_PRESENT_TEST)`](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/dxgi-present)。仍遮挡则只重登记 deadline，`S_OK` 或明确的 surface 生命周期变化才恢复 retained dirty，首帧 `dt = 0`。`test_present` 在 context / backend / engine 上均有默认 typed unsupported，应用零维护；只有能从普通 present 产生 `GraphicsOccluded` 的实现才会进入探测。D3D12 使用 flip model，而 DXGI 明确不为 flip presentation model 返回该状态，因此不得宣称支持或轮询探测。
- macOS delegate 用 [`windowDidChangeOcclusionState:`](https://developer.apple.com/documentation/appkit/nswindowdelegate/windowdidchangeocclusionstate%28_%3A%29?language=objc) 只唤醒对应 `WindowId`；通知不携带状态，`WindowDriver` 在所有视觉阶段前重新读取当前 [`NSWindow.occlusionState`](https://developer.apple.com/documentation/appkit/nswindow/1419321-occlusionstate?language=objc)。Visible 位未设置即进入逐窗 `Suspended(Occluded)`，保留 dirty / animation registration、取消 outstanding request 且不登记探测 deadline；Visible 只解除精确的 `Occluded` 并令恢复首帧 `dt = 0`。默认 `WindowOcclusionState::Unknown` 不得解除其他 backend 的 typed suspension；`Hidden` / `Minimized` / zero extent / terminal failure 仍有更精确的生命周期约束。通知只负责 wake、当前属性负责判定，因此合并或迟到通知不能应用旧状态，应用仍零维护。
- `SurfaceLost` / `OutOfDate` / `WouldBlock` 进入 `Recovering` 或等待目标生命周期信号；重试须有界并以 deadline 登记，持续失败不得因 retained dirty 形成 Active busy loop。`DeviceLost` 走既有同 API recipe → Software FSM；`OutOfMemory` 仍为 terminal，不静默回退。
- Wayland SHM buffer 从提交到 `wl_buffer.release` 期间保持 busy；present 只可 acquire free buffer，两块均 busy 时返回 typed `WouldBlock` 并保留 dirty，禁止轮换覆写 compositor 尚在读取的 buffer。当前绑定只提供 xdg-shell v3 且运行时绑定 `xdg_wm_base` v1，不能接收自 v6 才有的 [`xdg_toplevel.state.suspended`](https://github.com/wayland-mirror/wayland-protocols/blob/main/stable/xdg-shell/xdg-shell.xml)；`wl_surface.frame` 仍只表示提交后的合成机会，不得据此推断逐窗遮挡。升级该能力须先迁移协议 binding，再以 configure 中的 `suspended` 精确状态驱动本窗休眠。
- Wayland clipboard receive / send fd 与 display / wake fd 进入同一次阻塞 `poll`；两端均为 nonblocking，单轮 read / 全部 send 各有 64 KiB 总预算。receive 在 `WouldBlock` 后保留累积状态，只在 EOF / error / 新 selection 时释放；send 保留逐请求 payload snapshot + offset 到完成 / error。处理 poll 结果前须核对 fd 身份，旧结果不得消费新传输。`set_selection` 只能使用 pointer / keyboard press 产生的 serial，不得伪造 `0`。
- 禁：固定 16ms / interval 探活；DeepIdle 下 `tick_effects`；未 register 的周期工作；无 frame opportunity 的视觉推进；无条件 layout/render/present。
- 脏区尽量窄到 rect / Composite / 节点；同帧多个滚动视口分别登记 viewport + delta，统一并入 dirty / clear，并与 dirty 一起保留到提交成功；禁用“最后一个滚动覆盖前一个”的单槽状态。

无真实窗口 / GPU 时：主循环与托管语义须能被单元 / 集成测试驱动验证（不依赖真机 present），至少覆盖 one-shot 合并、可变 frame timestamp、隐藏动画零唤醒、失败不忙循环与恢复后 retained dirty 提交。测试仅在 `src/tests`；业务模块不挂载、不内联测试。

## 托管与多窗

<a id="托管与多窗"></a>

每窗一个 `WindowSession` 与配对的 `WindowDriver`：session 自有 `ActiveWorkRegistry`，driver 自有 `FrameScheduler` 与 `SurfaceState`。登记项包括：

| 种类 | 进入 RegisteredActive 的条件 | 退出 |
|------|------------------------------|------|
| Timer / AppTimer | `run_after` / `run_interval` 等已登记且未到期清空 | due 执行完或 handle cancel/drop |
| Animation | 节点动画仍在跑并由 registry open-register；`Renderable` 时由全窗 scheduler 合并一次下一帧 | 动画结束 unregister；`Suspended` 仅停帧、不丢登记 |
| ImeSession | 焦点在可文本输入节点并 start IME | blur / stop IME |
| FrameRequest / Recovery | 本窗有可呈现 dirty / animation 且已申请 callback，或 typed 恢复登记了 future deadline；同类最多一个 outstanding | callback / deadline 被消费、提交成功，或转入 `Suspended` / terminal |

- `post_to_ui` / 窗级定时只入**目标** session；不把他窗拉成 Active
- Timer handle 的 cancel / drop 若移除 pending 项，必须 wake 事件循环重算 deadline，使 session 可立即回 DeepIdle
- Frame request 的 cancel / callback 也必须带 `WindowId` + generation；迟到 callback 只能被丢弃，不能唤醒已换 surface / 已关闭的 session
- Wayland 的 compositor 确认态归每个 `WaylandWindowOps`：backend 不保存跨窗 `maximized` / `fullscreen`；异步 configure 以逐窗确认态判定 maximize / restore 边沿，只同步配对的 `WindowState` 并给该窗入队
- Wayland 为每个存活 `wl_surface` 登记 `WindowId`，seat 分别跟踪 pointer / keyboard focus；keyboard enter / leave 生成同窗 `WindowFocus` / `WindowBlur`，pointer、keyboard 与 repeat 事件只投递给当前已登记目标，unknown / 已注销 / identity 复用的 surface 不得沿用旧窗。text-input 的 `Enter` 必须匹配所选窗口，preedit / commit 到协议 `Done` 才按序生成同窗 composition / text 事件，`Leave` / stop 结束该窗会话；session generation 使旧对象的迟到回调失效
- macOS 的 `NSWindow` 以 `isReleasedWhenClosed = false` 创建，初始 `+1` 所有权归 `MacosWindowOps`，图形 shutdown 后才 close 并恰好 release 一次；弱 `delegate` 由窗口关联的真实 Objective-C 对象保活，delegate 与 content view 只在 raw pointer ivar 中保存 Rust context，并在各自 `dealloc` 回收一次后调用 superclass。直接 Objective-C FFI 必须服从目标 ABI；x86_64 的 `CGRect` 返回走 `objc_msgSend_stret`
- macOS 从 `NSEvent.window` / 窗口 delegate context 解析 `WindowId`，pointer、keyboard、focus / blur 事件一律带窗；共享 IME owner 以 `WindowId` + native view identity + generation 标识当前会话，只有完全匹配的 view 可提交或抑制文本事件，旧窗迟到的 blur / callback 不得停止或污染新窗会话
- 每窗 IME 焦点、会话、光标矩形归 `WindowSession`；共享原生输入服务只保留一个 owner。`Tab` / `Shift+Tab` 只遍历有效可见且可接收事件的节点；无当前焦点时分别从首项 / 末项开始，隐藏含焦点的子树须先走统一 `FocusOut` 并在同帧注销 IME，事件入口还须清除绕过公开 API 留下的失效焦点。切换目标须原子携带 `WindowId` + native handle，旧窗迟到的 blur 不得停止新窗会话
- `WindowDriver` 是逐窗事件后 work → animation / effect → 单次 reconcile → layout → paint → present 的唯一实现；主窗事件循环只负责 wait / 事件路由，副窗容器只负责集合 / 生命周期。两者共享 dirty 成功提交、IME sync、deferred show 与 loop state 语义；native window 关闭前完成图形 shutdown
- 浮层：`WidgetTree` 内 `OverlayStack` 管叠层与焦点陷阱；不单独作为跨窗 wake 源
- 语义事件在 Active 帧与 UiEvent 同步路径派发；不另开轮询线程
- Clipboard 能力只在事件 / due work 的词法作用域内注入；组件不得保存 platform 指针或让借用逃逸

## 自动化测试

- 应用用 `.automation_id("…")` 声明逐窗唯一、稳定的测试 selector；它只进入节点元数据，不参与 key reconcile、布局、绘制或命中。
- `test-harness` 下的 `TestApp` 在内存 `WidgetTree` 上通过真实 hit-test + `SystemEvent` 执行低层 click / text / key，并与未来 Bridge 共用 UI 层语义动作执行器；动作后有界收敛 State / Effect / reconcile / layout，不创建 OS 窗口或 GPU。selector / `node_id` 定位、未声明动作、不可见、禁用、modal 阻塞和未处理动作均 typed 失败。
- 真窗启用 `test-harness` 且设置 `UIX_AUTOMATION_DIR` 时，每窗输出 `uix-<pid>-window-<WindowId>.json`：复用共享语义节点模型，包含 generation、revision / `presented_revision`、层级、selector、logical client bounds、可见裁剪、焦点、accessibility 状态和节点实际支持的 `actions`；password value 不导出，关闭写 `closed: true`。
- 快照只挂在现有事件 / due work / 帧轮次末尾，内容变化才改写；不注册 timer、线程、网络端口或额外 wake，不触发 layout / paint / present。外部控制仍用系统鼠标 / 键盘走原生输入路径，快照只负责定位与断言。
- 多窗各写独立文件；一窗更新不发布他窗快照。该桥是测试能力，不是 UIA / 读屏桥或远程控制服务。

## 大模型控制协议

> 实现状态：`uix.agent.v1` 已定；`agent-control` feature + `.enable_agent_control()` 双门禁、共享语义节点 / 动作、逐窗 revision、有界 UI 命令队列 / settle、进程级 Bridge 生命周期，以及带 discovery / 随机 token 认证的 Named Pipe / Unix Domain Socket 已落地。现有自动化 JSON 快照仍是独立测试接口，不是本协议的双向传输层。

### 边界与组成

- `Agent Bridge` 是显式启用、仅限本机同一 OS 用户的进程级端点；一个端点管理该进程全部窗口，请求始终携带 `window_id`。它不是 TCP 服务、跨机器远控、UIA / 读屏桥，也不提供 shell、任意 Rust 调用、文件或网络访问。
- 框架内置组件自动提供节点语义和动作；自定义组件复用 `AccessibilityRole` / `AccessibilityState` 并声明动作。`.automation_id("…")` 是逐窗唯一的可选稳定业务标识；无该标识时，控制端先读快照，再使用当前窗口 generation 内的 opaque `node_id`。
- 协议分为语义树、动作执行器和传输三层。`TestApp` 与真窗 Bridge 最终共用前两层，避免无窗口测试与真实应用形成两套行为；传输差异不得进入组件。
- v1 不负责截图或 GPU readback；视觉证据继续由 app-control / OS 窗口捕获。协议提供 logical client bounds，使视觉结果可与语义节点对齐。

### 启用、发现与传输

- `agent-control` build feature 加 `App::enable_agent_control()` 是双门禁；任一未启用均不登记 Bridge 窗口、不启用对应语义跟踪，也不创建端点、线程、描述文件或 wake，Release 默认关闭。开关只在 GUI 原生窗口与图形引擎创建成功后生效。
- 当前用户的私有 discovery 目录保存 `uix-<pid>.json`：Windows 为 `%LOCALAPPDATA%\uix-agent`；Linux / macOS 为 `$XDG_RUNTIME_DIR/uix-agent-<uid>`，缺少 runtime dir 时退到系统临时目录。描述含 `schema`、`process_id`、endpoint、随机 session token 与 `ready` 状态；端点发布成功后才原子公布描述，正常退出关闭端点并删除描述。token 不进入日志。
- 传输是 backend 提供的本机有界 byte stream：Windows Named Pipe 使用 owner-only DACL 并拒绝远端客户端；Linux / macOS Unix Domain Socket 的目录为 `0700`、socket / 描述为 `0600`，accept 后再核对 peer uid。平台分叉只在 `native`，不监听 TCP / UDP。
- wire format 为 UTF-8 JSON Lines，一行一个对象，单条上限 4 MiB。首条请求必须是带 token 的 `hello`，认证成功后该连接才可发送其他请求；未知字段可忽略，未知 schema / message / action 必须 typed 拒绝，不能猜测执行。监听与 wait 均阻塞休眠；关闭用本机 self-wake 并取消活跃连接的阻塞 I/O，不依赖客户端配合。

### 会话与消息

每个请求含 `schema: "uix.agent.v1"`、客户端唯一 `request_id` 和 `type`；响应原样带回 `request_id`，并以 `ok` 区分成功与 typed error。v1 消息类型只有下列五种；除 `hello` 外均要求连接已认证：

| `type` | 请求 | 成功响应 |
|--------|------|----------|
| `hello` | token、客户端信息 | 协议版本、进程信息、能力上限 |
| `list_windows` | — | `window_id`、generation、标题、可见 / 可呈现状态、revision |
| `snapshot` | `window_id` | 当前完整语义树、revision、`presented_revision` |
| `perform` | `window_id`、generation、可选 `expected_revision`、action；节点动作另含 target | bounded settle 后的 revision 与 `settled`；敏感输入不回显 |
| `wait` | `window_id`、generation、`after_revision` 或待呈现 revision、timeout | change / presented / closed；到期返回 typed `timeout`，等待发生在 Bridge，不轮询 UI |

v1 只返回完整快照，不定义增量补丁、任意查询语言或长期事件订阅。一个连接按行串行处理；需要并发时可创建多个连接，同窗动作仍由容量 64 的目标窗队列按接收顺序执行，跨窗互不排序。单进程同时接纳至多 8 个连接。

[`agent_bridge.rs`](../src/app/agent_bridge.rs) 是平台无关的进程适配层：只登记已经创建成功的 live window，按 `WindowId` 排序提供 title / generation / visible / presentable / revision 元数据，并将 snapshot / perform 转为目标窗 ticket；pending open、占位 session 或猜测出的 id 均不可访问。相同 `window_id` 重建时 generation 单调递增，旧 UI publisher 自动失效；窗口与应用关闭由 `AppRuntime` 统一终止目录和请求。wait 以逐窗 `Condvar` 阻塞调用它的 transport worker，按 generation 等待 revision 变化、指定 revision 呈现或窗口关闭，最长 30 秒；目标窗变化不唤醒他窗 waiter，也不触发 UI wake、轮询或定时器。[`agent_protocol.rs`](../src/app/agent_protocol.rs) 负责认证、framing 与 wire 映射，[`native/agent_transport/mod.rs`](../src/native/agent_transport/mod.rs) 只负责同用户 byte stream、发现和取消；两者均不引用 `WidgetTree`。

```json
{"schema":"uix.agent.v1","request_id":"r1","type":"perform","window_id":1,"generation":3,"expected_revision":12,"target":{"automation_id":"counter.increment"},"action":{"kind":"invoke"}}
{"schema":"uix.agent.v1","request_id":"r1","ok":true,"type":"perform","window_id":1,"generation":3,"revision":13,"presented_revision":12,"settled":true}
```

### 语义树与定位

- 窗口快照含 `window_id`、generation、单调 `revision`、`presented_revision` 和节点树。节点至少含 opaque `node_id`、可选 `automation_id`、parent、role、name / description、可公开 value、state、bounds、`visible_bounds` 与 `actions`；纯装饰节点可省略，保持关系所需的 group 不省略。
- state 至少表达 visible、enabled、focused、selected、checked、expanded、read-only、password / sensitive 与 modal 约束。bounds 使用窗口客户区 logical top-left 坐标；协议层不猜测 DPR 或屏幕坐标。
- `node_id` 只保证在同一窗口 generation 内有效，并尽量随 reconcile identity 保持；跨启动 / 重建的稳定定位只使用 `automation_id`。节点动作的 target 必须恰含 `node_id` 或 `automation_id`；缺失、重复或过期分别返回 typed `node_not_found`、`ambiguous_target`、`stale_window` / `stale_revision`。窗口级低层输入不含 target。
- password 或标记为 sensitive 的 value 永不出现在快照、响应或日志。控制端可向这类节点发送文本，但成功响应不得回显内容。

### 动作与执行语义

- 节点语义动作优先：`invoke`、`focus`、`set_value`、`insert_text`、`select`、`toggle`、`increment`、`decrement`、`scroll`；节点未声明的动作返回 `unsupported_action`。窗口级低层兜底仅含发往当前焦点的 `press_key`，以及按 logical client 坐标走真实 hit-test 的 `click_at`。
- 节点 `actions` 由真实能力生成：语义 click handler、可聚焦事件组件、文本输入 client、role 对应的 toggle / value step，以及可滚动 viewport；执行器只能执行该列表中的动作。文本类 action 的 Debug / error 只保留 kind，不携带 payload；尚未有一致组件语义的 action 不得提前声明。
- 动作必须经过目标 `WindowSession` 的正常 semantic / `SystemEvent` 路径，遵守 visible、enabled、焦点、modal / overlay 和命中约束；禁止由 IPC 线程直接修改 Widget、State 或绘制树。
- `AppRuntime` 为每窗持有容量 64 的命令入口；未来 Bridge 只负责按 `window_id` 入队，队列仅在空 → 非空时触发一次 wake。目标 `WindowSession` 在 UI 轮次中、主线程任务之后且 AppState / Effect 之前按 FIFO 与本轮固定预算 drain；连续动作可同批，动作后的 snapshot 是 settle 屏障。IPC / transport 线程不持有或修改 `WidgetTree`。
- 动作随后走 State → Effect → reconcile → 必要 layout，最多观察 32 个 UI settle 轮次；实际执行过的 layout 不因失败帧需保留失效记录而继续阻塞响应。`settled: true` 不代表 Timer、动画、外部 I/O 或 present 已完成，动作引发的视觉 dirty 仍只申请本窗至多一个 outstanding frame request。控制端若需要视觉证据，须用 `wait` 等到 `presented_revision >= revision`；窗口不可呈现时返回 typed `not_presentable`，不得忙重试。
- `WindowSession` 自有 opt-in `WindowSemanticState`：未启用时不遍历语义树；Bridge 登记后以该窗 generation 和共享节点快照初始化 revision，并由 UI 所有者向进程目录发布 revision / visible / presentable 标量。正常帧在 reconcile / 必要 layout 后比较完整语义 / 布局状态，相同内容不递增。成功 present 才把 `presented_revision` 推进到当前 revision，失败帧不推进；关闭递增 revision 并清空节点。snapshot / wait 本身不触发 layout、paint 或 present。

### 错误、安全与资源约束

- typed error 至少覆盖 `unauthorized`、`unsupported_schema`、`invalid_request`、`window_not_found`、`stale_window`、`stale_revision`、`node_not_found`、`ambiguous_target`、`unsupported_action`、`not_interactable`、`blocked`、`did_not_settle`、`not_presentable`、`timeout`、`app_closed` 与 `internal`。
- 请求大小（当前 4 MiB）、文本 payload（当前 64 KiB）、进程连接数（当前 8）、每窗排队深度（当前 64）、settle 轮次（当前 32）与 wait timeout（当前 30 秒）均有上限；越界请求失败但不得拖垮应用。断连、坏消息和控制端退出不改变应用状态，也不形成重连 / 探活循环。
- 除阻塞等待连接的 transport worker 外，不允许轮询线程。无客户端、无请求时主循环保持 DeepIdle；显式 snapshot / perform 只唤醒目标窗，一窗的 revision 或 present 不发布他窗快照。
- 当前 wire 审计只记录结果码与耗时；token、输入文本、password / sensitive value 不记录，错误响应也不回显敏感 payload。

## 图形

<a id="图形-api与帧提交硬约束"></a>

`GraphicsBackend` = API 请求（非 OS 别名）。轴：`RasterMode` × `PresentMode` × API；按 recipe 装配。

解析：builder > 环境变量 > Settings > 默认 **Vulkan**。禁跨 API 偷换；仅显式 `Auto` 可跨 API probe。registry 只陈述能力（可含 Planned stub），不替 App 选 API。

```text
App / WindowSession
  → resolve GraphicsBackend
  → bootstrap（recipe | Auto 候选）
  → GraphicsDevice（可按 adapter/API 共享；线程亲和）
  → WindowSurface（每窗；logical / drawable / DPR）
  → FrameEncoder（单一有序、API 中立）
  → Presenter::present() -> Result<PresentOutcome, GraphicsError>
```

- **帧提交**：一帧一条命令序列（clear / native / CPU segment / offscreen）；禁双画序；每帧至多一个 `Presenter`；成功指标仅在提交成功后记。initialize / resize / make-current / begin-end-frame / present → typed `Result`；失败帧保留 dirty。透明 CPU segment 只收 source-independent op；Additive / Scroll 等目标相关 op 在录制边界 typed 拒绝。
- **绘制与提交解耦**：GPU 主路径可绘制全帧以消除 dirty-rect 绘制裁剪的脏数据风险；只有当 damage 外最终像素不变且 backend 已证明 present coherency 时，present 才提交窄 damage，否则提交 Full。software 回退可保留 dirty-rect 绘制裁剪省 CPU 像素，同样受 coherency 门控。
- **damage 坐标与一致性**：UI dirty 统一为 logical top-left；提交边界按当前 `WindowSurface` 的 DPR / transform 转为 drawable，min `floor`、max `ceil`、裁到 extent。resize、DPR、orientation / `currentTransform` 或 surface generation 改变后首帧强制 Full。Vulkan incremental present 的 rect 相对 `currentTransform`（[`VkPresentRegionKHR`](https://registry.khronos.org/Vulkan/specs/latest/man/html/VkPresentRegionKHR.html)），Wayland 优先 buffer 坐标 [`damage_buffer`](https://wayland.freedesktop.org/docs/html/apa.html#protocol-spec-wl_surface)；禁止直接 `as i32` 截断 logical rect。
- **present coherency**：能力 typed 为 `FullOnly` / `RetainedBuffer` / `TrackedSwapchain`；`PresentDamageTracker` 只在成功 present 后提交 surface signature 与 image / frame history，并给出本 image 必须修复的 `draw_damage`。缺 image identity、history、generation / transform 或修复能力一律 Full；当前仅 Windows GDI retained DIB 放行窄提交，GPU swapchain、PixelUpload 与 Wayland 仍为 `FullOnly`。DXGI [`Present1` dirty-rect contract](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/dxgi-1-2-presentation-improvements) 明确要求每个 dirty pixel 最新并跨 buffer 跟踪；damage 是 compositor hint，不是允许 stale pixel 的正确性豁免。
- **IR**：`FrameRasterOp` = `FillRect`（SrcOver）、`FillRectAdditive`、`ScrollCopy`。后两者 destination-dependent，须 Native / 参考执行器落地；优先 readback → 参考语义 apply → replace `upload_surface_pixels`，缺任一侧 typed `NotImplemented`；禁透明 CPU segment + SrcOver 冒充；圆角 Additive 同理拒绝。
- **回退**：缺实现 / Planned stub → typed 失败后 Software/CPU；禁称「平台永久不支持」。unsupported → 有界 CPU segment（保 blend/clip/crop/scissor，只上传 damage）；禁近似冒充支持。
- **恢复**：surface rebuild → recipe rebuild → 同 API 下一 recipe → Software；仅 `Auto` 可跨 API；`OutOfMemory` 禁静默回退。resize 失败仍记住最新目标 extent，恢复后按目标尺寸重建；backend 不得把 `DeviceLost` / `SurfaceLost` / OOM 抹成 `NotImplemented`。
- **滚动帧**：`begin_frame` 先清 dirty 区、encoder 后执行，故 `ScrollCopy` 读到的是已清空像素而非上一帧；render_frame 须把滚动视口并入清/绘区（非仅 exposed strip），由 paint 重新生成偏移内容。`ScrollCopy` 仍为 IR 能力，但当前不经 render_frame 发出。
- **所有权与生命周期**：`draw` 不持有 GL/D3D/Vulkan/Metal 对象；context 只经 factory；bootstrap 收 `NativeSurfaceHandle`。共享 `GraphicsDevice` 以 adapter / API / queue family / thread affinity 为 key；每个新 `WindowSurface` 仍须重新查询该 queue family 的 present support（Vulkan 查询是逐 surface 的 [`vkGetPhysicalDeviceSurfaceSupportKHR`](https://registry.khronos.org/Vulkan/specs/latest/man/html/vkGetPhysicalDeviceSurfaceSupportKHR.html)），不兼容则为该窗另建 recipe，不能拖垮已有窗口。原生 context / 图形引擎 / 渲染后端：生命周期边界仅为 `try_shutdown`（无 void `shutdown`）；`ThreadBoundGraphicsContext` 的 Drop 在错线程时 leak 内层，禁错线程 native teardown；`RenderSession` / `WindowSession` 保留 concrete `shutdown()` 作 Drop 便利并内部调用 `try_shutdown`。
