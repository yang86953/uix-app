# 架构

> 分层、主循环、托管与图形硬约束（不含用法与排期）。Agent 附能力见文末。

## 分层

依赖只能向下，未列边禁止：

| 域 | 允许依赖 |
|----|----------|
| `core` | — |
| `native` | `core` |
| `draw` | `core`, `native` |
| `ui` | `core`, `native`, `draw` |
| `data` | `core` |
| `app` | `core`, `native`, `draw`, `ui`, `data` |

- OS 能力经 `native::traits`；禁上层 `use native::backends::*`
- `#[cfg(OS)]` 仅限 `native/` 层；上层（`core`/`draw`/`ui`/`data`/`app`）禁止
- `draw` ↛ `ui`/`app`；`ui` 不碰 backend；业务回调不进组件 struct（语义 handler、paint renderer、虚拟子项 factory 随节点以 `ComponentId` 登记，reconcile / remove / root reset 同步清理）；`Form` 自定义 validator 只由应用侧 `FormModel` 持有；`data` 不进热路径
- 资源句柄（`BitmapHandle`、`WidgetId`、`ImageHandle`）采用 **generation 槽位复用** 而非引用计数：句柄 = `(slot_index, generation)`，释放时槽位标记为空并递增 generation，新分配复用同槽位时旧句柄自动失效。这比 `Arc` 省去原子操作开销，比原始指针安全——是「用最少资源」在资源生命周期上的核心机制
- 运行时是原生窗口 + 原生绘制；**禁 WebView / 嵌入式浏览器作为 UI 或呈现运行时**
- 图形初始化：`draw::engine::bootstrap → native::factory`（recipe 为单位）
- 公开入口：`uix::prelude::*`
- View 样式链只写入节点唯一 `Style`；水平 / 垂直 padding 保留另一轴，阴影进入同一盒模型绘制，不在组件内复制视觉字段
- `State` / `Computed` 的 `map` / `map_opt` 在根 View 构建期捕获底层 State 依赖并绑定结构 reconcile；`map_text` 走 DynamicLabel 的窄 Paint 绑定。Computed 缓存命中不得跳过依赖捕获。reconcile 的核心机制是 **keyed diff**：同类型、同 key 的节点保留身份和运行态（滚动位置、光标、动画进度），只 patch 变化的属性；类型或 key 不同才销毁重建。这比全树重建节省一个数量级的 CPU，是「局部状态只更新依赖节点」的引擎基础。
- `canvas(width, height, paint)` 仅提供固定 logical measure + render，无子节点 / 事件能力；绘制期读取的 State / Computed 在共享 ScenePaint 边界绑定到本节点 dirty rect，变化只产生窄 Paint，不注册每帧工作
- controlled Input 以绑定的 `State<String>` 为外部真值：构建期读取绑定结构 reconcile，编辑事件同步回写；内建 patch 比较运行值，值变化才重置文本 / 光标并发 Layout + Paint，同值重建保留运行态。`textarea` / `password` 工厂只声明模式，`max_length` 按 Unicode 字符限制用户输入；绑定值不进入公开 config snapshot
- controlled Checkbox / Switch 以绑定的 `State<bool>` 为外部真值：构建期读取触发结构 reconcile，点击或键盘切换同步回写，绘制期依赖只绑定本节点 Paint。非受控 `default_checked` 仅是初值，无关 reconcile 不覆盖用户运行值；两种模式均不轮询
- controlled Select 以选项文本作为外部真值：单选是 `State<String>`，多选是 `State<HashSet<String>>`；构建期将值映射为稳定选项顺序中的索引并绑定 reconcile，点击 / 键盘更改同步回写，绘制期只绑定本节点 Paint。`searchable()` 仅在聚焦后接收 `TextInput`，按大小写不敏感的包含关系过滤并保留原选项索引；查询、弹层、过渡与滚动均是实例运行态，无关 reconcile 保留且无轮询，过滤收窄时 damage 仍覆盖有上限的原弹层。非受控 `default_selected` 仅是初始索引
- Table 的 `sortable` / `selection` / `bordered` / `virtual_scroll` / `size` 是声明式配置：`size(width, height)` 固定视口，溢出行只在表体内滚动且表头保持可见；表级排序覆盖所有列，列级排序可单独开启，点击只切换方向并发 `Change`，数据顺序由调用方重建；复选框列仅在 selection 开启时参与 measure / hit-test / paint。虚拟滚动关闭时保持完整行遍历，开启后按固定 `virtual_row_height` 只遍历 viewport 与有界 overscan；两者滚动都只产生 body Composite，不注册逐帧工作。固定视口、排序方向、有效范围内的单选 / 多选行在同配置 reconcile 中保留
- `Table::data(Vec<R>, row_key)` 在 View build 边界把泛型行按 `TableDataColumn<R>` 投影为既有文本行；重复业务 key 在建树前返回 `TableDataError`。`bind(...).render(...)` 的 typed 行与 View factory 只进入按 `ComponentId` 管理的 render sidecar，`Table` component 仅保存文本、row key 与 View 列索引，paint / event / snapshot 不执行业务闭包。普通表物化全部 View 单元格，虚拟表只物化当前 viewport + overscan 行窗；子节点 key 由 row key + column index 组成，reconcile 重排复用仍在窗口内的节点。组件同时按 row key 重映射 selected / checked / expanded 索引；legacy `TableRow` 使用索引字符串作为隐式 key。结构化快照发布文本 rows、row_keys 与 view_columns。含 View 列时滚动触发布局与 Paint（当前未证明子树 pixel 一致性，暂不登记 composite-copy）——**目标是在 View 列内容不变时也启用 composite-copy**，与纯文本列同等待遇
- Table 列布局在每次 paint / hit-test 时划分 left / middle / right：固定列按声明顺序锚定两侧，只有 middle 应用有界水平偏移并裁在剩余视口。纵向滚动沿用 Composite；横向偏移会改变固定区与中间区的叠放关系，coherency 未覆盖该组合时退回本 Table Paint，不提交整表像素搬移
- Table 的 `column_groups` 在构建期扁平化为叶列与稳定范围元数据，排序、行数据和固定列继续只索引叶列。存在分组时表头增为两层：具名范围分占上下层，`TableColumnGroup::column` 的独立列跨两层；分组范围进入结构化快照，reconcile 仍按叶列位置保留可排序运行态
- Table 展开 factory 不进入组件 struct，而是按 `ComponentId` 存在 `RenderHandlerTable`；展开时只物化当前行的一个普通 View 子树，应用 reconcile 复用同类型 / 同 key 节点，折叠或换根随节点生命周期清理。子树以表体为 clip，并复用 body 的 viewport scroll transform；paint 不调用 factory
- Tree 将当前展开路径深度优先展平为稳定 key 行，28 logical 行高、虚拟滚动、键盘显露与指针命中共享同一可见索引。每行按实际 frame 为有上限的层级缩进、勾选槽、Lucide 展开槽、图标槽和标题槽分配非负几何；深层/长标题按 Unicode 单行省略并与行背景、焦点框一起裁在真实视口内。指针只在同一二维目标内完成按下与释放后选择、勾选或展开，移出、`PointerLeave`、`FocusOut` 取消未完成动作，hover 目标不变时不重复失效；滚轮只在真实 frame 内生效。展开/折叠仅在可见行数变化时发出一次 Layout 请求。相同节点配置 reconcile 按 key 保留选择、勾选、展开与滚动位置并清除未完成指针动作；Tree 无障碍值发布当前可见选中节点的标题与一基位置，不把业务 key 当作用户文案
- RichText 的 measure 使用估算字符度量，paint 使用真实字体 advance；真实布局缓存以内容、字体配置、实际宽度和解析后的主题正文色为键，主题切换不会复用旧色字形。折行字形、连续文字 run、选择/链接背景、代码复制按钮与二维命中共享相对 frame 坐标，绘制和可交互复制区统一裁在归一化实际 frame 内。链接与代码复制使用稳定 segment 目标，只有同一目标内完成按下与释放才提交；移出、`PointerLeave`、`FocusOut` 或 reconcile 清除未完成动作。默认正文色在 paint 时解析 `color_text`，显式 `.color(...)` 保持调用方颜色。不轮询
- Alert 以归一化实际 frame 统一计算状态强调线、图标、消息、说明和关闭槽；消息与说明各保持单行并按 Unicode 省略，正文使用主题 `color_text`，状态色仅承担背景、强调线和图标语义，全部绘制与关闭反馈统一裁在 frame 内。关闭槽仅在同一目标内完成指针按下与释放后提交，移出、`PointerLeave`、`FocusOut`、外部释放或 reconcile 取消未完成动作；`Enter` / `Space` 使用匹配键盘释放，`Escape` 直接关闭。关闭后 measure 返回零尺寸并请求一次布局，运行态 visibility 不被无关 reconcile 重开；无障碍 Alert 名称发布消息，非空说明发布为 value text。不轮询
- Drawer 的遮罩面板尺寸先归一化并收敛到真实 surface，四个 placement 共用有限非负 panel 几何；48 logical header、可选 footer、正文 body、标题/extra/关闭槽和内容子树共享裁剪边界，标题与 extra 在关闭槽前 Unicode 单行省略。闭合态发布 Button + `expanded=false` 并仅在匹配 PointerUp / KeyUp 后打开；父布局拉伸时，96×32 触发器的绘制与 hit-test 共同居中。打开态发布 Dialog + `expanded=true`，关闭槽同目标完整释放才关闭，移出、失焦或交互几何改变的 reconcile 取消未完成动作，Escape 仍由最上层 Drawer overlay 优先处理。遮罩、z-index 1000 和 focus trap 沿用统一 OverlayEntry；进出场继续只在注册动画期间请求帧。不轮询
- controlled Slider 以 `State<f64>` 为外部真值：构建期读取并按 inclusive range 约束显示，拖动、方向键与语义增减同步回写，绘制期依赖只绑定本节点 Paint；非受控 `default_value` 仅是初值，无关 reconcile 保留运行值。区间、步进与公开快照统一使用 `f64`；指针按区间起点取最近步进网格，方向键从离格值进入对应方向的相邻网格，结果按起点与步长的小数精度归一。绘制与命中使用本次实际控件框：受限高度按名义高度等比缩放轨道和滑块半径，极窄宽度把半径封顶到半宽，所有图形裁在控件框内；框外按下不启动拖动，已捕获拖动跨过 `PointerLeave` 后保持到 `PointerUp`。不轮询
- controlled Rate 以 `State<u32>` 为外部真值：构建期按离散评分上限约束显示，点击、方向键与语义增减同步回写，绘制期依赖只绑定本节点 Paint；非受控 `default_value` 仅是初值，无关 reconcile 保留运行值。普通模式一个数值单位对应一星，`allow_half` 模式一个单位对应半星，公开快照与无障碍 `value_max` 使用同一单位。半选字符由左右两个 clip 分别绘制活动色与空态色，不用容器背景擦除；默认字符保持每星 24 logical 的 Medium 格宽，显式自定义字符按 Unicode 可见宽度扩大格宽。绘制与命中共用本次实际控件框，受限高度同步缩放字号和格宽，框外指针不改变值，所有文字与焦点图形均裁在控件框内。不轮询
- controlled DatePicker 以 `State<Date>` 为外部真值：构建期读取触发结构 reconcile，选日同步回写，绘制期读取只绑定本节点 Paint；非受控 `default_value` 仅是初值，无关 reconcile 保留选值、弹层开闭与浏览月份。禁用谓词只在命中测试/绘制中求值，Week / Month / Quarter 先归一到周一/月初/季初再提交。触发框按实际高度相对名义尺寸缩放文字、内边距与图标，文字区在图标前单独裁切，全部触发绘制再裁在实际框内。共享月历面板至少 160 logical 宽，月份标题按实测文字宽度居中，左右 32 logical 边缘同时作为导航图标与命中区，星期标题行与六行 30 logical 日期网格分别布局，绘制与命中共用同一几何。打开状态注册为 z-index 900 的 Popover overlay，边界覆盖触发框与月历，避免后绘制兄弟覆盖或截获弹层点击；FocusIn、hover 清除和无关按键分别维护焦点重绘、旧高亮重绘与事件冒泡，快照导出格式化日期及 `expanded` 供无障碍 / Agent 读取。不轮询
- DateRangePicker 复用同一日历面板，以两个 `State<Date>` 为外部真值；首击仅保留组件内 pending 起点，hover 把 pending 与当前命中排序为绘制预览，次击排序后回写双 State，reconcile 保留弹层、浏览月份与未完成选择。预设在构建期解析为起止值，点击与普通范围共用禁用端点和提交路径；预设 footer 与每个 24 logical 行分别裁切，长标签不扩大浮层 damage。触发框按实际高度相对名义尺寸缩放范围文字、内边距与图标，文字区在图标前单独裁切；打开状态注册为 z-index 900 的 Popover overlay，边界覆盖触发框、月历和全部预设行，避免后绘制兄弟覆盖或截获点击。FocusIn、hover 清除和无关按键分别维护焦点重绘、旧预览重绘与事件冒泡，快照发布稳定范围文本及 `expanded`。无逐帧工作
- controlled TimePicker 以 `State<Time>` 为外部真值，`value_configured` 单独区分未配置值与有效的 `00:00`；指针选中单列时保留另一列并立即回写，键盘以活动列维护小时 / 分钟高亮并在 Enter 时合并提交。小时和分钟分别使用 24 / 60 个 32 logical 行及独立滚动位置，打开时把当前值居中到 200 logical 高视口，滚轮只改变指针所在列，绘制、hover 与点击使用同一行索引。触发框按实际高度相对名义尺寸缩放文字、内边距与时钟图标，文字区在图标前单独裁切；弹层至少 120 logical 宽，两列标签按实测文字宽度居中并整体裁切。打开状态注册为 z-index 900 的 Popover overlay，边界覆盖触发框和弹层；FocusIn、PointerLeave 与无关按键分别维护焦点、恢复已提交高亮及事件冒泡，快照发布 `HH:MM` 与 `expanded`。无逐帧工作
- controlled ColorPicker 以 `State<Color>` 为外部真值，指针或键盘提交预设时同步回写；非受控 reconcile 保留运行值。触发器以本次实际 frame 的短边相对名义尺寸缩放内边距、圆角、描边与焦点框，并在 frame 内统一裁切，事件命中使用最近一次实际 frame 而不是名义控件高度。色块先绘制固定明暗棋盘格再合成 RGBA 值；色板使用 8×3 个 24 logical 单元，内容区采用右/下边界排除的命中规则，避免 padding 或列边界映射到下一行。活动项随底色亮度选择黑或白描边，当前预设绘制同样具对比度的勾；方向键按一维相邻项或八列跨行移动，Home / End 到首尾，Enter / Space 提交。打开及有界退出动画期间注册为 z-index 900 的 Popover overlay，逻辑 `open` 单独发布为 `expanded`，退出完成后清除高亮且停止请求动画帧
- Cascader 以 `current_levels` / `level_indices` 分离当前可见列与各列活动索引，选择分支时只截断其后的路径并追加子列，所有祖先列持续可见；各列持有独立 `scroll_offsets`，指针、滚轮与键盘高亮共用 32 logical 行几何。配置相同的 reconcile 保留打开子级与滚动位置，只有 options 真正变化时才从根级重建导航。触发器命中使用最近一次实际 frame 的二维半开边界，文字、内边距和箭头按相对 32 logical 名义高度缩放并整体裁切；弹层每列至少 200 logical 宽、视口高 200 logical，每行文字在 24 logical 子级箭头槽前单独裁切。叶子提交才产生以 `/` 连接 value 路径的 Change；打开及有界退出动画期间注册为 z-index 900 的 Popover overlay，边界随可见列数扩展，快照发布标签路径与 `expanded`
- TreeSelect 将 `TreeNode` 深度优先展平为稳定的 key / title / depth / disabled 行，指针、滚轮和键盘共用 28 logical 行索引及 `VirtualListScroll`；指针 hover 与键盘 highlight 分开保存，禁用行不进入提交路径。打开时优先高亮并滚动到当前 key，否则定位首个可用行；同 nodes reconcile 保留高亮和滚动，节点集合变化时才重建活动项。触发器按最近一次实际 frame 的高度相对 32 logical 缩放文字、内边距和 Lucide 箭头，并在 frame 内统一裁切；弹层宽度取触发器与 200 logical 的较大值、视口最高 280 logical，空数据仍占一行并绘制本地化空态，层级标题按有上限的缩进裁在行内。二维半开边界同时约束触发、弹层、滚轮与可见行命中；打开及有界退出动画期间注册为 z-index 900 的 Popover overlay，退出完成前保留当前滚动画面，快照发布标题、key 与 `expanded`
- AutoComplete 以运行时 `value` / `cursor_char`、实测字形前缀位置 `glyph_xs` 与 `text_scroll_x` 共同维护 Unicode 字符编辑和水平光标可见性，字符索引只在修改文本时转换为 UTF-8 字节边界。过滤结果、键盘候选与指针 hover 分开保存，28 logical 行绘制、命中、滚轮和高亮自动显露共用 `VirtualListScroll`；同 options reconcile 保留候选和滚动，只有 options 变化才重新过滤。触发器使用最近一次实际 frame 的二维半开边界，并按相对 32 logical 名义高度缩放、裁切文字和光标；弹层宽度取触发器与 200 logical 的较大值、视口最高 280 logical，无结果仍绘制本地化空态，长候选裁在行内。查询编辑和候选提交都产生 Change；打开及有界退出动画期间注册为 z-index 900 的 Popover overlay，快照发布当前文本与 `expanded`
- Mentions 以运行时 `value` / `cursor_char`、实测字形前缀位置 `glyph_xs` 与 `text_scroll_x` 维护完整正文、Unicode 字符编辑和水平光标可见性。活动查询由光标前最后一个 `@` 到光标之间的无空白文本确定；提交时替换从该 `@` 到其后同一无空白 token（以及已有的首个分隔空白），再插入单个尾随空格，因此保留查询前后的正文并把光标落在空格之后。过滤结果、键盘候选与指针 hover 分开保存，28 logical 行绘制、命中、滚轮和高亮自动显露共用 `VirtualListScroll`；同 options reconcile 保留候选和滚动，只有 options 变化才重新过滤。触发器使用最近一次实际 frame 的二维半开边界并按相对 32 logical 名义高度缩放、裁切文字和光标；弹层宽度取触发器与 200 logical 的较大值、视口最高 280 logical，无结果仍绘制本地化空态，长候选裁在行内。正文编辑和候选提交都产生 Change；建议层注册为 z-index 900 的 Popover overlay，快照发布完整正文与 `expanded`

## 诊断

<a id="诊断"></a>

`core` 层提供统一诊断基础设施——错误收集、崩溃处理、中间件管道。所有上层模块无需引入第三方日志/错误收集库。

### 错误收集器（`Collector`）

线程安全的全局单例，收集、聚合、快照应用内所有 typed `Error`：

- **收集**：`Collector::instance().collect(error)` —— 任意线程可调用
- **配置**：`CollectorConfig` 控制最大容量（默认 4096）、非 Fatal 自动日志开关与级别、去重策略；Fatal 始终先写日志与崩溃报告再 abort
- **快照**：`Collector::instance().snapshot()` 返回 `CollectorSnapshot`，含时间戳、总量、当前存储数、按错误码/类别聚合统计
- **回调**：可按 `callback_id` 注册/注销，每个收集到的错误触发回调（例如对接外部监控）

### 崩溃处理（`fatal`）

- **panic hook**：`install_fatal_handler()` 将 Rust panic 转为 typed `Error`，写入 Collector，dump 崩溃报告（`uix_crash.log`），flush 日志后 abort
- **手动终止**：`fatal_abort(error)` / `abort_if_fatal(error)` / `collect_or_abort(error)` —— 按错误严重级别决定是否终止进程
- **崩溃报告**：含时间戳、总量、按错误码统计、每个错误简述

### 中间件管道（`middleware`）

可组合的请求处理拦截链，用于服务调用、IO 操作等需要在调用前后插入通用逻辑的场景：

- **`MiddlewarePipeline`**：`add(mw)` 注册中间件，`execute(ctx, handler)` 链式执行
- **`LogMiddleware`**：记录每次请求耗时与成功/失败状态
- **`RetryMiddleware`**：可配置最大重试次数，失败自动重试

```rust
let mut pipeline = MiddlewarePipeline::new();
pipeline.add(LogMiddleware);
pipeline.add(RetryMiddleware::new(3));

let mut ctx = MiddlewareContext {
    service_name: "FileService".into(),
    operation: "read".into(),
    ..Default::default()
};
pipeline.execute(&mut ctx, |c| {
    // 实际操作
    c.succeeded = true;
});
```

### 错误模型

所有错误走 `Error` 类型——含错误码（`Errc`）、严重级别（`ErrorSeverity`）、消息、源链、文件/行号。`what()` / `Display` 按外层到根因输出完整源链，`short_what()` 只输出单行简述；图形 frame / resize / external present 失败日志必须用完整文本，不能丢失 driver fault 根因。严重级别 `Fatal` 在收集时自动触发崩溃报告并 abort。

### 依赖注入

`app` 层提供 `Container`（prelude 别名 `DiContainer`）——基于类型的轻量服务注册与解析。自定义服务在 `App::run()` 前经 `App::singleton` 注册；`.settings(path)` opt-in 时，框架在进入运行模式前 load 并注册 `SettingsService`。字体与图片服务由图形运行时直接持有，不冒充可解析单例。

- 注册：`App::singleton(impl Any + Send + Sync)`，或直接使用 `container.singleton(...)`
- 解析：`handle.resolve::<T>()` 返回服务的 `Clone`，`container.resolve::<T>()` 返回容器内引用
- 生命周期：与 App 同寿，窗口间共享；`SettingsService` 的 Clone 共享同一锁保护状态，load / save 是冷路径。标量 codec 仅做 `Display` / `FromStr` 内存转换；`settings-serde` 结构体 codec 把单个 key 编成 JSON 字符串，均不触发 I/O。save 先同步同目录 temp，再把旧文件移入 backup 后安装新文件；load 会恢复“旧文件已移走但新文件未安装”的中断状态，并清理已提交或未提交的 sidecar

## 主循环

<a id="主循环要点"></a>

事件循环三态；surface 可用性是正交的逐窗状态：

| 轴 | 状态 | 含义 |
|----|------|------|
| `LoopState` | `DeepIdle` / `RegisteredActive` / `Active` | 无待办并阻塞；等待已登记 deadline / frame callback；已有可立即执行工作 |
| `SurfaceState` | `Renderable` / `Suspended(reason)` / `Recovering { retry_at, attempt }` / `TerminalFailure` | 可提交；等待 expose / 非零 extent / surface 恢复；按 typed 原因有界重试；不可恢复吸收态（无 deadline / frame request，仅随窗口 session 重建退出） |

### 必须

- `DeepIdle`：无待处理事件、queue、due work、reconcile，也无 outstanding frame request / recovery deadline。`Suspended` / `TerminalFailure` 窗的 dirty 不算可立即执行工作。
- wake ∈ {OS / 生命周期、queue、due deadline、frame opportunity、recovery / availability deadline}；一窗 wake / Active 不得把他窗拉成 Active；`TerminalFailure` 窗不因普通生命周期 / surface 信号重开视觉帧。
- 每个 `Active` 轮次先非阻塞分发挂起的 OS 事件，再执行 due work / frame；连续动画、Agent settle 或其他持续工作不得饿死输入、生命周期、关闭与跨线程 wake。
- **事件轮次**：批量 drain UiEvent + 同步 semantic → due 非视觉工作 → `post_to_ui` → AppState focus / semantic → Effect；只合并 dirty / reconcile，并为该窗申请至多一个 frame request。
- **帧轮次**：收到 `FrameOpportunity { request_token, frame_time, target_present_time? }` 后，消费截至该点的最后一次 root → **一次** reconcile → 按需 layout → paint → 至多一次 present。成功才消费 dirty；提交后仍有动画 / dirty 才申请下一次。
- frame request：one-shot、可合并、逐窗所有；`request_token = surface_generation + request_id`；原生回调只可完成完全相同的 outstanding token。fallback / surface 变化 / suspend 消费或取消 token 后，不能取消 OS 对象的 backend 必须抑制迟到回调。
- 动画保持 open registration，全窗只维护一个下一帧请求；`dt` 来自 frame opportunity 单调时间。`Suspended` 时取消视觉 deadline、冻结动画，恢复首帧 `dt = 0`，不补跑隐藏帧；业务时间继续由 Timer 表达。
- `Hidden` / `Minimized` / zero extent → `Suspended`：保留 dirty 与 animation registration，取消视觉 deadline，不 layout / paint / present。`WindowHide` / `WindowShow` 是逐窗生命周期信号；视觉阶段前复核真实可见性。延迟首显在第一次成功 present 前豁免；可用性信号只解除匹配的 suspend reason；`TerminalFailure` 为吸收态，普通 suspend / resume / surface change 与迟到 failure 均不得降级或重开 frame request，只能随窗口 session 重建。
- `SurfaceLost` / `OutOfDate` / `WouldBlock` → `Recovering` 或等待生命周期信号；重试有界并以 deadline 登记；持续失败不得因 retained dirty 形成 Active busy loop。`DeviceLost` 走同 API recipe → Software FSM，各步只尝试一次；`begin_frame` 内更换 engine 后，`FrameRenderer` 与 `WindowDriver` 须重读新 capability 并在同帧采用新提交协议。Software CPU 帧经窗口唯一 `ExternalPresenter` 成功才重置序列，重建或提交再失败则进入无 deadline 的 `TerminalFailure`。`OutOfMemory` 直接进入同一终态，不静默回退，也不接受普通生命周期恢复。
- 图形 engine 只返回 typed failure；普通遮挡为 Debug 可用性事件，其他最终 present 失败只由 `WindowSession` 边界记录一次 Error。
- 脏区尽量窄到 rect / Composite / 节点；同帧多个滚动视口分别登记 viewport + delta，统一并入 dirty / clear，保留到提交成功；禁用单槽「最后滚动覆盖」。

### 禁止

固定 16ms / interval 探活；DeepIdle 下 `tick_effects`；未 register 的周期工作；以 WebView 充当呈现或布局运行时；因 retained dirty 在不可呈现或持续失败时保持 Active busy loop。

### 平台帧机会与遮挡

各平台须按自身契约实现 one-shot frame callback（静态窗不创建节拍）。DWM/display link/`wl_surface.frame` 均不等于逐窗遮挡；遮挡检测须用本窗独立 compositor/window-server 能力。

- **Windows**：live recipe 以 `GraphicsContextCaps::present_occlusion` 声明能力。`PresentStatusAndTest` recipe：`Present` 返回 [`DXGI_STATUS_OCCLUDED`](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/dxgi-status) → `Suspended(Occluded)`，100 ms→1 s 有界 [`Present(…, DXGI_PRESENT_TEST)`](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/dxgi-present) 探测。`Unsupported` recipe 不登记遮挡 probe，只依赖 Hidden/Minimized/ZeroExtent 生命周期休眠。禁 DWM/帧机会冒充遮挡。
- **macOS**：[`windowDidChangeOcclusionState:`](https://developer.apple.com/documentation/appkit/nswindowdelegate/windowdidchangeocclusionstate%28_%3A%29?language=objc) 只 wake 目标窗；Visible 只解除精确 Occluded（无探测 deadline），恢复首帧 `dt = 0`。
- **Wayland**：`wl_buffer.release` 前 busy；双 busy → `WouldBlock` 保留 dirty。遮挡需 `xdg_toplevel.state.suspended`(v6+)；禁 frame/activation 冒充。Clipboard 与 display 同 poll、nonblocking、64 KiB 预算；`set_selection` 只用真实 press serial。

## 托管与多窗

<a id="托管与多窗"></a>

每窗一个 `WindowSession` 与配对 `WindowDriver`：session 自有 `ActiveWorkRegistry`，driver 自有 `FrameScheduler` 与 `SurfaceState`。

| 种类 | 进入 RegisteredActive | 退出 |
|------|----------------------|------|
| Timer / AppTimer | 已登记且未到期清空 | due 执行完或 cancel/drop |
| Animation | open-register；`Renderable` 时全窗合并一次下一帧 | 结束 unregister；`Suspended` 仅停帧 |
| ImeSession | 焦点在可文本输入节点并 start | blur / stop |
| FocusHandle command | 唯一存活绑定收到 focus / blur 后进入所属 AppState 队列 | 目标窗 UI 轮次消费；移除 / 换绑清除旧目标 |
| FrameRequest / Recovery | 本窗 dirty / animation 已申请 callback，或 typed 恢复登记了 deadline；同类至多一个 outstanding | 消费 / 成功提交 / `Suspended` / `TerminalFailure` |
| GraphicsMaintenance | 成功 soft present 后若主画布仍保留可重建 CPU staging，登记本窗一次性 deadline | 到期仅释放安全 staging；无资源、resize，或连续两个 soft-free 成功 present 后取消 |

- `post_to_ui` / 窗级定时只入**目标** session
- `AppState` 的组件注册、注销与事件消费只在所属 UI 线程执行；公开查询持有线程安全快照表。每次注册在同一 `ProviderContext` 下只采集一次组件字段，结构化字段与无障碍派生共用该次捕获；Button 的不可变 `StyleSet` / `Style` 在组件与快照间共享，不把完整样式重复内联进每份快照。生产 `ComponentHandle` 只弱持有该 `AppState`，可跨线程读取快照，或登记 paint invalidation / semantic event 后在释放锁后 wake 目标 session；回调、树修改与绘制仍只在该窗后续 UI 轮次发生，`Handled` 只表示事件已入队。失效句柄 no-op，禁后台线程直接持有或访问 `WidgetTree`。
- `FocusHandle` 只保存 `ComponentId` 与所属 `AppState` 弱引用，不持有 `WidgetTree`；同一 handle 只允许一个存活 View 目标，跨窗误复用返回 typed 歧义错误。focus / blur 可跨线程登记并 wake 目标窗，其他窗口的 drain 看不到该命令；节点隐藏或不接收事件时消费命令但不强制聚焦。失焦窗口可更新逻辑焦点身份，但不得发送 `FocusIn`、激活 focus-within 或重启视觉生命周期；重新获得窗口焦点时只激活最新存活目标。
- Timer cancel/drop 移除 pending 后必须 wake 重算 deadline，使可回 DeepIdle
- Frame cancel/callback 必须带 `WindowId` + generation；迟到只能丢弃
- 自定义标题栏是逐窗 opt-in 的窗口能力，不是组件皮肤。创建阶段须在首显前隐藏系统标题栏并重新校正 logical 客户区尺寸；配置失败则该窗创建失败，禁静默回系统标题栏。当前 Windows 仅移除 `WS_CAPTION`，保留 `WS_THICKFRAME` 等原生缩放能力；`GetWindowLongW` / `SetWindowLongW` 的零返回须先清空并读取 last-error 才能判定成败，任一样式读写失败必须 typed 返回。未实现 backend 返回 typed `NotImplemented`。
- `window_drag_region` / `window_control` / `window_control_named` 只在所属 `WidgetTree` 产生一次性 `WindowAction`，事件轮次内由本窗 `PlatformWindow` 消费；禁止进全局队列、跨窗广播或新增轮询 / frame request。拖动区允许子树先命中：子控件处理输入则停止冒泡；未处理的左键由拖动 / 双击接管，未处理的右键只在同一区域按下并释放后产生系统菜单动作，移出释放取消。`BeginMoveDrag`、最大化切换与系统菜单都保留客户区既有键盘焦点；系统菜单动作同时抑制该手势的 UI `ContextMenu` 默认项。窗口控制的展示子树不参与命中，也不导出独立语义节点；控制项自身可键盘聚焦，在语义树中是唯一的具名 `Button`，`Invoke` 复用 Enter 键路径而不直连平台窗口。指针捕获在控件外释放时先送 `PointerLeave` 取消动作；激活状态记录 Pointer 或具体键，只接受同源松开。组件消费 `FocusIn` / `FocusOut` 维护焦点视觉，背景按 active → focus → hover → normal 解析；交互态变化仅标脏该控制项 rect，不申请持续帧。
- Windows 窗口类启用 `CS_DBLCLKS`；拖动把当前左键手势移交 `WM_NCLBUTTONDOWN(HTCAPTION)`，拖动区左键 `PointerDoubleClick` 切换本窗最大化 / 还原，右键释放读取当前屏幕坐标并投递 `WM_NCRBUTTONUP(HTCAPTION)`，由 `DefWindowProc` 进入系统菜单 / `WM_SYSCOMMAND` 路径。屏幕坐标按有符号 `POINTS` 编码，允许负坐标显示器。最小化、最大化 / 还原继续产生既有逐窗生命周期事件；关闭只投递 `WM_CLOSE`，由 app 先 shutdown 图形与 session 再销毁 HWND。原生动作失败须终止或请求关闭该窗口会话，不得 busy retry。
- Wayland：每个存活 `wl_surface` 登记 `WindowId`；seat 跟踪 pointer/keyboard focus 只投递已验证目标；generation 丢弃迟到回调。
- macOS：事件从 `NSEvent.window`/delegate 解析 `WindowId`；IME owner = `WindowId` + native view identity + generation。生命周期由 `MacosWindowOps` 管理，图形 shutdown 后 close release。
- Windows DPI：上层客户区尺寸、resize 与指针 / 滚轮 / 拖放事件均为 logical；`GetClientRect` / drawable 为 physical。创建 UIX HWND 时仅在 `CreateWindowExW` 词法作用域切到 Per-Monitor V2，随后恢复宿主线程 context；`AdjustWindowRectExForDpi` 保证请求尺寸是客户区，`WM_DPICHANGED` 应用系统建议外窗矩形，再由同步 `WM_SIZE` 进入唯一逐窗 resize / graphics rebuild 路径。GPU 直接使用 physical client；Vulkan 创建与每次 resize 均从同一 HWND 查询 drawable，PresentUpload 的 CPU canvas 与 swapchain 对齐 physical，另存精确 logical viewport；GDI 保留 logical DIB，以同一全帧 `StretchBlt` 原点和外扩 physical clip 提交。target extent 改变须推进 surface generation，使下一帧 Full。禁改宿主 process awareness，禁一窗 DPI 变化重建他窗。
- 节点有效可见性 = authored tree gate ∧ 父级 `WidgetLayout::child_visible(index)` gate ∧ `WidgetComponent::visible()`；任一为 false 时整棵子树不参与布局、绘制、命中、语义导航或焦点候选。布局每轮在子项 frame 收敛前后同步父级 gate，变化时清理子树交互状态、推进 tree version 并失效新旧边界；重新打开父级 gate 不得覆盖调用方显式关闭状态，组件内部可见性变化也不得绕过祖先 gate。Carousel 用此契约只开放当前幻灯片；Modal / Drawer 关闭 overlay 后仍显示打开触发器，因此其组件节点保持可见，present 状态只控制浮层。
- **IME**：单行/多行文本均走系统 IME；框架只托管会话与光标矩形，不自造拼写/候选管线。composition → commit 须按平台输入法协议送达目标窗的目标控件；未 commit 的 composition 不得当最终文本写入 State。每窗 IME 归 `WindowSession`；共享原生输入只一个 owner（`WindowId` + native view identity + generation）。start/stop/失败须 typed，禁静默丢弃。隐藏、移除或替换子树须在节点仍可寻址时先结束其 hover / pressed / drag，统一 `PointerLeave` / `DragEnd` 且禁止迟到 `PointerUp` 合成点击；含焦点时还须统一 `FocusOut` 并同帧注销 IME，再执行生命周期销毁与 ID 失效。
- Windows IME：TSF `ITextStoreACP` 文档锁只在 `OnLockGranted` 回调内有效；read lock 内的异步 read-write 升级排队一次并返回 `TS_S_ASYNC`，同步重入返回 `TS_E_SYNCHRONOUS`。`GetTextExt` 返回 caret 的屏幕坐标，`GetScreenExt` 返回完整客户区的屏幕范围；TSF 活跃时忽略 IMM composition，避免重复提交。
- `Tab` / `Shift+Tab` 只遍历有效可见可接收事件节点；节点存在显式 `tab_index` 覆盖时以覆盖值为准（含 `0`），否则实时读取组件当前默认值，状态切换不得保留建树时的旧焦点资格。无当前焦点时分别从首项 / 末项开始；浮层内受 `OverlayStack` focus trap 约束
- `WindowDriver` 是逐窗 pipeline 唯一实现（work → reconcile → paint → present）；主循环只 wait/路由。
- 浮层：`WidgetTree` 内 `OverlayStack`；不单独作跨窗 wake 源。
- 语义事件在 Active 帧与 UiEvent 同步派发；不另开轮询线程。
- Clipboard 只在事件/due work 词法作用域注入；组件不得保存 platform 指针。

## 动画

<a id="动画"></a>

UIX 提供泛型逐帧动画系统，由主循环统一推进 `dt`（秒），窗口不可呈现时自动暂停。

### Animated\<T\> —— 声明式单值过渡

`Animated<T>` 复用 `State<T>` 发布当前插值，但不是布局节点。root capture 只收集被 `value()` / `progress()` / `is_finished()` 读取的 source，`WidgetTree` 以 sidecar 保存它们；同一 source 至多绑定一个 tree scope，其他窗口只观察共享值，不重复推进。

运行中的 source 进入所属窗口既有 `ActiveWorkRegistry`，与 widget animation 共用 one-shot frame request 和 frame opportunity `dt`。采样写入 State 后，主循环在同一帧消费 reconcile 请求，再 layout / paint / present；这避免零 `dt` immediate frame 抢占已登记的下一帧。完成或暂停在本轮登记同步时取消 open registration；root 移除 source 后，最多消费已经 outstanding 的一次帧机会再取消旧 id。`Suspended` 期间不采样、不 reconcile、不 layout / paint / present，恢复首帧仍以 `dt = 0` 重基。

延迟 source 在等待期登记 `ActiveWorkKind::Animation(id) -> deadline`，不进入 open animation 集合，也不申请连续帧；deadline 到期且窗口可呈现时才合并一个 immediate frame，再切换为 open registration。暂停、停止、完成或 root 移除通过受管 source 同步立即撤销旧 deadline；零时长过渡也只在正延迟到期后提交终值。窗口不可呈现时把 pending deadline park 为无 deadline 登记并阻塞等待，不采样、不 reconcile、不 layout / paint / present；恢复后的可呈现帧复核 source，未到期则恢复 deadline，已到期则从 `dt = 0` 启动。

当前公开面包含固定时长、typed 单值 / 多属性聚合 keyframe 与 Spring 过渡、固定时长延迟启动、pause / resume / stop / restart / reverse、普通固定时长的 `loop_count` / `loop_forever` / `loop_alternate`、一次性 `on_finish` / `set_on_finish`、Style 字段及 visual-only offset / scale 的 typed `*_animated(&Animated<T>)` 绑定，以及有限时间线的并行 / 串行 / stagger `AnimationGroup`。循环跨越大 `dt` 时按算术折算轮次与当前 leg，不逐轮迭代；`loop_count(0)` 直接提交终值，无 frame registration。keyframe 与 Spring 是单次播放并在每次替换时清除旧循环模式。

声明式完成回调归属于一份 `AnimatedPlayback`，clone 不复制；自然完成时 `AnimatedInner::advance` 在 playback mutex 内原子取走 callback，随后先发布终值、释放锁，再执行 `FnOnce`，因此回调可安全读取或控制同一 `Animated` 而不重入死锁。有限循环只在全部 plays 结束后消费；`stop` 提交终值但保留 callback，`restart` 后仍可自然触发；替换 playback 会连同旧 callback 一起丢弃；绑定已完成或无 playback 的 source 时在调用线程同步触发。自然推进发生在 source 所属窗口的 UI 帧，但 `Animated` 句柄可跨线程配置，所以 callback 仅要求 `Send + 'static`，不得被视为任意线程直访 `WidgetTree` 的授权边界。

View 的 `opacity_animated` / `bg_animated` / `color_animated` / `width_animated` / `height_animated` / `radius_animated` 只在 root build 内调用 source `value()` 并写入对应 Style 字段；capture 仍按 `ComponentId` 去重，adapter 不创建 wrapper 节点或新 timer。动画帧发布 State 后触发原 root reconcile，节点复用与 paint / layout 分类沿用同名静态样式 setter。

`offset` / `scale` 及对应 animated binding 写入节点 visual transform，不改变 layout frame；局部矩阵按“以 layout frame 中心缩放，再应用 offset”构造，并与祖先 transform、滚动位移按实际绘制顺序组合。paint、hit-test、空间事件本地化、文本选区、语义 frame / visible bounds 与 damage 均消费同一组合链；不可逆的零 scale 不命中。变换变化同时登记旧 / 新 visual subtree bounds，并增加 tree version 使 LayerTree 重建；变换子树禁用 Picture 缓存，变换路径上的滚动禁用 scroll-copy composite，保守退回 Paint。

普通 View 的 `enter_animation(AnimationConfig)` 在节点首次 build 时创建一次 `TransitionPlayer`，不包 wrapper、不触发布局，也不在同 key reconcile 时重启。`leave_animation(AnimationConfig)` 使声明树已移除的节点进入有界 pending-removal：保留原节点、子树和布局槽直至过渡完成，但立即清理指针 / 焦点并退出命中、语义、Timer、组件动画和浮层管理；完成后删除节点并请求布局。同 key 完成前重新出现会取消 pending-removal、复用原 ID 并恢复终态；enter 中转 leave 从当前 opacity / offset / scale 接续。零 duration 直接删除，不登记帧；pending-removal 即使不可见也会推进到完成，不泄漏保留节点。

节点 opacity 在 LayerTree 中与祖先 opacity 相乘，offset / scale 进入上述统一 visual transform；活动期禁用该子树 Picture 缓存，每帧登记旧 / 新 visual subtree damage。新节点或新离场即使在本帧 reconcile 后才出现，也会在帧末同步 animation registration，避免依赖下一次外部事件唤醒。

容器的 `stagger_enter(interval, config)` 只给直接子节点排程：首次 build 对全部子节点编号，后续 reconcile 仅对本轮新 mount 的节点从 0 编号，复用节点不重启或改写既有 deadline。首项登记 open animation，后续项登记绝对 deadline；等待期保持过渡起值且不进入连续帧集合，deadline 到期转为 open，迟到量作为首个 `dt` 一次消费。零时长延迟项到点提交终态；View 过渡与 `Animated<T>` deadline 共同由窗口 managed animation registration 托管，组件自身动画仍保持独立 open work，不因 View 过渡完成而被误取消。

`AnimationGroupItem` 以 type-erased control 保存异构 `Animated<T>`，但不复制状态与播放器；组构造时按 `ComponentId` 拒绝重复 source，再从子项原始起点重排 deadline。并行项 offset 为零、串行项 offset 累加前项 duration、stagger 第 n 项 offset 为 `n * interval`，显式 `delay` 由零副作用的有限 source 表达；总时长统一取最大 `offset + duration`。组自身不登记 frame work，`progress()` / `is_finished()` capture 全部子 source，播放控制以同一 `Instant` 批量作用于子项，因此每个真实 source 仍至多一份逐窗 registration；有限 counted loop 的内部组进度包含已完成轮次，不改变公开 `Animated::progress()` 的当前 leg 语义。等待 deadline 迟到时把超期量作为本次 `dt` 交给播放器，大步进可跨过多个 offset 且不 busy retry。空组、重复 source、既有延迟、无 playback、Spring 与无限循环无法证明有限总时长，构造时返回 typed `AnimationGroupError`，不做静默降级。

`KeyframeAnimation<T>` 在构建时校验有限 offset，裁到 `[0, 1]` 后稳定排序，重复 offset 保留最后声明；缺失边界由首末值补齐，`Animated<T>` 缺失 0 时改用当前值。采样以“起点 keyframe 的 easing”推进到下一点，利用有序 offset 二分定位分段；同一 FrameOpportunity 只做一次 O(log n) 采样，大 `dt` 直接裁到 duration 终态。空序列与非有限 offset 返回 typed `KeyframeError`，不会替换现有 playback；完成、暂停或 root 移除沿用 source registration 的 inactive 路径。

`keyframe!` 只生成一个应用侧结构体、同可见性构造器与 fieldwise `Animatable` 实现，不生成播放器或运行时注册。`lerp` 以同一采样进度推进全部字段，`delta` 取各字段绝对 delta 最大值；因此 `Animated<Generated>` 仍只有一个 `ComponentId` work source、一份 State 和一条错误 / 播放控制边界，Spring 完成也要求所有字段进入阈值。字段缺失或非 `Animatable` 是编译错误，不存在运行时部分属性回退。

Spring 只替换 source 内的采样器，不增加调度类型：`SpringAnimation<T>` 对归一化位移使用欠阻尼 / 临界阻尼 / 过阻尼解析解，初始速度以整段距离每秒表达。每次采样用 `Animatable::delta` 的绝对值把归一化速度换算到实际值空间；实际位移与实际速度同时低于 `Spring` 的静止阈值后精确提交终值并关闭 open registration。解析解不按小步循环积分，大 `dt` 仍为 O(1)；暂停立即 inactive，恢复后继续累计物理时间，窗口 Suspended 仍由既有首帧 `dt = 0` 规则重基。

### Animation\<T\> —— 泛型插值

`Animation::new(from, to, duration)` 创建从 `from` 到 `to` 的插值动画，类型参数 `T: Animatable`。

| 方法 | 作用 |
|------|------|
| `update(dt)` | 推进时间，返回当前插值 |
| `value()` | 只读当前插值，不推进 |
| `is_finished()` / `progress()` | 查询完成状态与进度 [0,1] |
| `pause()` / `resume()` | 暂停 / 继续 |
| `restart()` | 回到起始位置并继续播放 |
| `stop()` | 跳到终态并停止，不触发完成回调 |
| `reverse()` | 交换 from/to 并重新播放 |
| `easing(e)` | 设置缓动曲线 |
| `on_finish(FnOnce)` | 下一次推进到终态时触发一次 |

非正 `duration` 归一为零，并在首次 `update()` 时到达终态。完成回调要求 `Send + 'static`；`Animation` 克隆体共享同一个一次性回调，任一克隆体先完成后其余克隆体不再重复触发。

内置 `Animatable` 实现：`f32`、`f64`、`Color`、`Point`、`Rect`。`Animation<f32>` / `Animation<f64>` 额外提供 `fade_in(duration)` 和 `fade_out(duration)` 便捷构造。

`SpringAnimation::new(from, to, Spring)` 提供同一组值读取与 pause / resume / stop / restart / reverse 控制；`Spring::bouncy()`、`gentle()`、`snappy()` 与 `critical()` 提供预设，`custom()` 可设置 stiffness、damping、mass、初始 velocity 和双静止阈值。非有限或非正的收敛参数保留原配置，避免产生永不衰减的公开实例。一次性 `on_finish` 与 `Animation<T>` 保持相同的 clone 共享语义。

`KeyframeAnimation::new(frames, duration)` 提供相同的值读取、播放控制与一次性回调；`Keyframe<T>::easing` 属于从当前点出发的分段。反向播放以 `1 - progress` 对同一曲线采样，保持正向轨迹的时间反演；stop 提交当前方向的终点。

### Easing —— 缓动曲线

`Easing` 枚举将 `t ∈ [0,1]` 映射到缓动值：

| 变体 | 说明 |
|------|------|
| `Linear` | 线性 |
| `QuadIn` / `QuadOut` / `QuadInOut` | 二次方 |
| `CubicIn` / `CubicOut` / `CubicInOut` | 三次方 |
| `QuartIn` / `QuartOut` / `QuartInOut` | 四次方 |
| `BackIn` / `BackOut` | 弹性（超出后回弹） |
| `Bounce` | 分段弹跳缓出，输出保持 [0,1] |
| `Elastic` | 衰减振荡缓出，允许短暂越过终值 |
| `CubicBezier(x1,y1,x2,y2)` | 自定义三次贝塞尔（牛顿法 + 二分法回退） |

公开链式写法使用 `Easing::linear`、`ease_in/out/in_out`、`cubic_in/out/in_out`、`bounce`、`elastic` 这些关联常量；`Easing::cubic_bezier(...)` 构造自定义曲线。`sample(t)` 会收敛输入范围，但 Back / Elastic 的输出可越过 [0,1] 以形成回弹。

antd 5 预设：`antd_default()`（`cubic-bezier(0.25,0.1,0.25,1)`）、`antd_in()`、`antd_out()`、`antd_in_out()`。

### AnimationConfig / TransitionPlayer —— 进出场过渡

借鉴 antd 的 Modal / Drawer / Notification 等浮层 enter + leave 动画模式：

- `AnimationConfig` 只通过 `fade_in/out`、`slide_in/out`、`zoom_in/out` 构造，持续时间统一归一到非负值；应用不直接拼内部枚举字段
- `slide_in/out(Placement, duration)` 以 `Top / Bottom / Left / Right`（含角落变体归并到上下方向）表达视觉来源 / 去向；通用位移为 24 logical px，组件预设可在内部按自身尺寸收紧
- `TransitionPlayer` 是组件内部的单次播放器，将配置分解为 opacity / offset / scale 三路 `Animation<T>`，完成后停止登记帧工作
- 内建预设覆盖 Modal zoom、Drawer slide、Tooltip / Popover fade 与 Collapse fade；公开组件只接收 `AnimationConfig`

**enter 动画**：节点挂载或浮层打开时播放。**leave 动画**：关闭前播放，`finished` 后由 `OverlayStack` 移除节点。

### 帧驱动与暂停

- 动画由主循环每帧 `dt` 推进；widget 通过 `WidgetAnimation::update_animation(dt)` 生命周期钩子传播，`Animated<T>` source 由 tree sidecar 推进
- 每窗 `ActiveWorkRegistry` 只登记仍返回 active 的动画节点 / source；事件、reconcile 或失效发生时发现新动画，稳定逐帧阶段只推进已登记 id，不遍历整棵树——这是动画系统的核心节省机制：100 个已完成动画零开销，只有活跃动画才消耗帧预算
- **Suspended 时冻结**：窗口不可呈现时所有动画暂停，恢复首帧 `dt = 0` 重基，避免时间跳跃导致动画瞬切到终态。隐藏窗口不跑动画——同样是「用最少资源」：不可见时不消耗 CPU
- 动画完成（`is_finished() == true`）后从 registry 取消登记，不再触发帧请求

## 主题与配置

<a id="主题与配置"></a>

### LocaleProvider —— 可持久化的子树语言上下文

- `App::locale` 将全局默认 `Locale` 注册到应用容器，主窗与后续副窗构建根 View 时读取同一默认值。
- `LocaleProvider::child` 在词法作用域内构建子树；每个 `ViewNode` 捕获最近 Provider 上下文，展开后的 widget 节点继续持有该上下文。
- measure / event / render / lifecycle 进入组件钩子时恢复节点上下文；reconcile 同步替换上下文并触发布局与绘制失效，因此延迟渲染不会退回全局语言。
- Provider 作用域由 guard 托管，正常返回与 panic 展开都会恢复上层上下文；嵌套子树采用最近 Provider。

### ConfigProvider —— 组件树配置继承

借鉴 Ant Design 的 `ConfigProvider` 模式，UIX 提供组件树层级的配置继承机制。配置沿组件树下传，子节点继承父节点配置，局部可覆写。

- **已落地配置项**：`component_size`（`ControlSize::{Small, Medium, Large}`）、`disabled`、`ComponentOverrides`、按组件类型索引的 `TokenPatch`、`render_empty` View factory；Locale 由独立 `LocaleProvider` 管理。
- **继承链**：`App::config` 把全局 `ComponentConfig` 放入应用容器；`ConfigProvider::child` 只覆写显式字段，节点捕获最近上下文。不包裹时使用全局值或框架默认值。
- **优先级**：组件局部属性 > 最近 `ConfigProvider` > `App::config` > 框架预设。
- **实现**：与 Locale 共用 View 构建词法作用域和节点持久化上下文；reconcile 比较上下文，变化时同时失效布局与绘制。作用域 guard 保证 panic 展开后恢复父层。
- **当前影响范围**：尺寸默认值进入 Button（含 `button()` DSL）、Input、InputNumber、Select、Checkbox、Switch、Radio、Segmented、Slider、Rate、DatePicker、DateRangePicker、TimePicker、ColorPicker、List、Descriptions、Modal、Drawer；禁用默认值进入 Button（含 `button()` DSL）、Input、Select、InputNumber；构造覆盖进入 Button、Input、Select、Form；List / Table 的普通 View 路径消费 `render_empty`。

### 组件级令牌覆写

在 `DesignTokens` 层面按组件类型覆写令牌值，对标 antd v5 的 `theme.components`：

- **查询路径**：每个 widget 节点保留 Provider 上下文；绘制前按组件 `TypeId` 查 `ComponentTokenOverrides`，命中才进入补丁层。
- **载体**：`TokenPatch` 是覆盖全部现有 token 字段的 `Clone + PartialEq` 纯数据 struct；未设置字段委托给当前子树 `Theme`，再回退每帧根主题。
- **绘制作用域**：`PaintContext` 持有根主题引用及可恢复的 subtree theme / patch Arc；节点绘制前替换作用域，绘制后恢复，不改 `WidgetRender` 与 `TokenProvider` 公开签名。
- **失效**：Provider 上下文发生变化时 reconcile 保守失效该子树的布局与绘制；稳定帧只多一次组件类型查询，不引入轮询或帧请求。

## 组件系统

<a id="组件系统"></a>

UIX 的 UI 树由 `WidgetTree` 管理，节点通过 `component!` 宏定义，框架自动处理 reconciliation（diff → 复用/创建/销毁）。

### component! 宏

`component!` 将一个 struct 转为完整组件节点，自动生成 reconciliation 逻辑。可定义的生命周期方法：

| 方法 | 签名 | 调用时机 |
|------|------|----------|
| `measure` | `(&self, Constraints) -> Size` | 布局 measure 阶段，给定约束返回期望尺寸 |
| `render` | `(&self, Rect, &mut PaintContext, &WidgetTree)` | 帧绘制阶段 |
| `build` | `(&self) -> Vec<Box<dyn WidgetComponent>>` | reconcile 阶段，返回子节点列表 |
| `on_event` | `(&mut self, &SystemEvent) -> EventResult` | 事件派发阶段，返回是否消费 |
| `update_animation` | `(&mut self, dt: f64) -> bool` | 每帧动画推进；返回是否仍需下一帧 |
| `dirty_bounds` | `(&self, Rect) -> Rect` | 返回本次动画变化的窄绘制区域 |
| `on_mount` | `(&mut self)` | 节点首次挂载到树中 |
| `on_unmount` | `(&mut self)` | 节点从树中移除前 |
| `wants_continuous_pointer_move` | `(&self) -> bool` | 是否接收逐帧 PointerMove（默认 false） |

含子节点的组件通过 `children: WidgetChildren` 字段 + `build` 方法声明。

### WidgetTree 与 Reconciliation

- **树结构**：`WidgetTree` 为扁平 `SlotMap`，节点以 `NodeId` 索引；容器节点持有子节点列表
- **Reconciliation**：逐层 diff 新旧 struct，同类型且 key 匹配则复用节点，否则销毁重建
- **回调登记**：`render` / `on_event` / `build` 等闭包随节点以 `ComponentId` 登记在侧表中；reconcile / remove / root reset 时同步清理
- **脏标记**：`State::new` / `clone` 本身不绑定根 reconcile；仅根 View 构建期的结构性 `State::get` 绑定 reconcile，绘制期与 DynamicLabel 读取只绑定对应节点 Paint。`State` 写入只标脏实际依赖；`Computed` 惰性求值；同帧多次写入合并为一次 reconcile
- **受控导航**：`Navigation<K>::active_page`、`Tabs::active_key` 与 `Tabs::controlled` 在构建期读取外部 State，选择交互写回同一 typed key；reconcile 复用组件节点并刷新选中态。任意 `K` 只保留在应用 State / 绑定中，语义事件与结构化快照通过 `Display` 文本跨边界，不把任意应用类型塞入快照。

### 指针移动优化

同一 hit 目标上连续 `PointerMove` 不每帧触发重绘——仅 hover 目标变化时标脏。需要逐帧 PointerMove 的组件通过 `wants_continuous_pointer_move => true` opt-in。

### Widget Trait 契约

所有组件通过以下 trait 接入框架，`component!` 自动为 struct 生成实现：

| Trait | 职责 |
|-------|------|
| `WidgetComponent` | 组件入口，提供 `as_any()`、`snapshot_fields()`、`sync_from()`；复合交互组件可用 `exposes_semantic_children()` 折叠纯展示子树语义 |
| `WidgetLayout` | `measure(Constraints) -> Size` + `layout_children(frame, children, tree)`；定位容器可用 `child_overflow_expands_parent() == false` 保持自身占位 |
| `WidgetRender` | `render(frame, ctx, tree)` — 每帧绘制 |
| `WidgetLifecycle` | `on_mount()` / `on_unmount()` — 挂载/卸载钩子 |
| `EventHandler` | `on_event(&SystemEvent) -> EventResult` — 事件分发；`take_layout_request()` 在同次已处理事件后一次性请求当前节点及祖先重新布局；滚动组件可用 `scroll_delta_for_dirty` + `scroll_composite_viewport` 将 Composite 限定到真实 viewport |
| `WidgetAnimation` | `update_animation(dt)` 推进并返回是否仍 active；`dirty_bounds(frame)` 限定窄标脏 |
| `WidgetCapabilities` | `wants_continuous_pointer_move() -> bool` |
| `WidgetTextInput` | `accepts_text_input()` / `ime_composition_rect()` — IME 支持 |
| `Animatable` | 定义可插值类型（f32、Color、Point、Rect 等），供 `Animation<T>` 使用 |
| `TokenProvider` | 提供色彩/字号/间距/阴影令牌，组件通过 `ctx.tokens()` 获取 |
| `TextRenderer` | 文本测量与绘制 |
| `DebugRenderer` | 调试叠加层绘制 |

`IntoWidgetNode` 将任意组件转为 `WidgetNode`，由 `ViewNode` 和所有内置组件 impl。

组件只有在内部运行态改变子节点几何时才返回一次 `take_layout_request() == true`；树在同一事件轮次消费并将布局失效限定为当前节点及祖先，稳定状态不重复请求。该钩子不创建 timer 或持续帧工作，普通叶组件保持默认 `false`。

### Manager 系统

`WidgetTree` 通过组合的 `WidgetManagers` 提供横切能力，每个 manager 独立管理一种关注点：

| Manager | 职责 |
|---------|------|
| `StateManager` | 响应式 `State<T>` / `Computed<T>` 的依赖追踪与失效通知 |
| `FocusManager` | 焦点节点追踪、Tab 序管理、焦点变化事件 |
| `InteractionManager` | 指针命中测试、hover 状态、拖拽目标识别 |
| `DragManager` | 拖拽会话生命周期（DragStart/Move/End），跨节点数据传输 |
| `TextManager` | IME 组合态、文本选区、光标矩形管理 |
| `StyleManager` | 遗留样式预设查询（新代码优先 `ui::style::Style`） |

`WidgetManagers` 支持 per-component override：个别组件可使用独立 manager 实例，否则回退到树级默认。

## 布局

<a id="布局"></a>

布局分两阶段：**measure**（自底向上确定尺寸）→ **layout**（自顶向下分配位置）。

### Constraints

父容器向子节点传递 `Constraints { min: Size, max: Size }`：子节点在约束内自由选择尺寸，返回值被 `clamp` 到约束范围。`-1.0` 表示无上限，`0.0` 表示可为零。

### 容器布局算法

| 容器 | 主轴 | 交叉轴 |
|------|------|--------|
| `column` | 纵向 | 横向填满容器宽 |
| `column_fit` | 纵向 | 横向撑开到内容最大宽 |
| `row` | 横向 | 纵向填满容器高 |
| `row_fit` | 横向 | 纵向撑开到内容最大高 |
| `stack` | — | 子节点各自独立 measure，尺寸取最大 |

- `gap` 在主轴上插入固定间距；`padding` 收缩子节点可用空间
- `expand(true)` 子节点在分配剩余空间时获得弹性份额
- layout invalidation 仅标记受影响的子树
- 子节点溢出默认参与收敛扩张；Affix 等定位容器保留自然占位并只移动可见子树，不让视觉位移反向撑大父布局
- 事件与 Timer 轮次先批量收集 Paint / Layout / Composite，最外层返回时一次加锁提交；队列以节点索引合并 Paint。`WidgetTree` 按 `tree_version` 借用先序缓存，layout 以复用的根、祖先路径与栈一次收集受影响顺序，并在整轮收敛中复用正序与逆序结果

### Grid

普通 Grid 由 `GridTrack::{Px, Fr, Auto}` 定义列/行，自动放置按源顺序寻找完整可用矩形。

响应式 Grid 固定 24 个 `Fr(1)` 单元，以本 Grid 内容区的 logical 宽度解析 `Breakpoints`；每次正常 layout 都重新计算 `Col` 的当前 span，并将 offset/order 转成无重叠的显式 cell 后交给同一 `GridLayout`。resize 只使受影响窗口的布局子树失效，不登记轮询、帧请求或跨窗状态。`order` 不改 WidgetTree、事件或语义顺序；reconcile 同步断点/列配置并保留既有子节点运行态。

## 浮层

<a id="浮层"></a>

浮层组件（Modal / Drawer / Notification / Message / Popover / Tooltip / Popconfirm）由 `OverlayStack` 统一管理层级与焦点。

Modal 的声明宽高先归一化为有限非负值，再收敛到所属 surface；header、body、可选 footer、内容子树和关闭反馈共用同一对话框几何与裁剪，标题在 Lucide 关闭槽前按 Unicode 单行省略。zoom transition 只产生 Paint，内容子树始终按最终对话框几何布局，避免首个动画采样把子树永久压缩。闭合态在拉伸 frame 内把 96×32 触发视觉和命中共同居中，发布 Button、`expanded=false` 与非空名称；打开态发布 Dialog 和 `expanded=true`。触发器、关闭槽及 mask 外部区域都按稳定交互目标在匹配 PointerDown/PointerUp 后提交，PointerLeave、FocusOut 或交互几何变化取消；`Enter` / `Space` 同样在匹配 KeyUp 后打开，Escape 与 overlay focus trap 沿用统一栈规则。不轮询。

`Message` / `Notification` 以共享 `Placement` 将队列约束在本窗 logical 客户区；窗口尺寸变化时由当前 frame 重算整组矩形。每项以稳定 ID 经 `Entering → Holding → Leaving` 推进：仅进出场登记连续动画帧，持有期只用一个最近截止 timer，`duration_ms = 0` 不登记 timer；leave 完成后才删除运行项。队列为空时命中与 overlay entry 同时为空，放置与动画配置随 reconcile 同步且保留既有队列。

Message 的实际 frame 先归一化为有限非负客户区，按 40 logical 卡片高和 48 logical 步长计算可见容量，只把最新可容纳项送入布局、绘制、命中与 dirty/overlay bounds，较早项不改公开队列和计时状态。每项在动画后的实际卡片内分配状态图标、单行省略内容和最多 40 logical 的关闭槽，并以窗口 clip 约束阴影与全部绘制；关闭槽只在同一稳定项完成 PointerDown/PointerUp 后提交，PointerLeave、FocusOut、frame/placement 变化取消。非空队列快照发布 Alert 和内容名称，空队列回退 Generic。不轮询。

Notification 同样先归一化实际 frame，并按每项是否包含 description 使用 48 / 66 logical 卡片高和 12 logical 间距计算最新可见后缀；隐藏的较早项保留公开队列、稳定 ID 与原计时。卡片、Lucide 状态/关闭图标、标题、说明、关闭反馈和动画后的命中与 dirty/overlay bounds 共用实际几何及窗口 clip，标题与说明在关闭槽前分别按 Unicode 单行省略；同一稳定项完成 PointerDown/PointerUp 才关闭，PointerLeave、FocusOut、frame/placement 变化取消。非空队列快照发布 Alert，并分别汇总标题与说明；空队列回退 Generic。不轮询。

Popover / Popconfirm 把触发子树布局到包装器的归一化实际 frame，并以本窗 logical surface 同时计算绘制、命中、dirty 与 overlay bounds：先比较声明方向和主轴反向候选的越界量，再把 220×100 / 200×110 首选浮层收敛、平移并裁在 surface 内；箭头锚点随触发器中心在浮层边缘内收敛，阴影和动画 sweep 也只发布 surface 内 damage。标题、正文及确认/取消按钮按实际非负槽位 Unicode 单行省略，Popconfirm 使用 Lucide 警告图标。Click 触发器与 Popconfirm 操作只在同一稳定目标完成 PointerDown/PointerUp 或 KeyDown/KeyUp 后提交，PointerLeave、FocusOut 或几何配置变化取消；Popover 发布 Button、`expanded` 和内容值，Popconfirm 保持 Button、`expanded`、当前操作及确认 Submit 语义。不轮询。

ProgressBar 把声明进度和尺寸归一化为有限非负值，确定值限定在 `0.0..=1.0`；线形轨道、填充、移动块与圆形分段均以实际 frame 计算并统一裁剪，`round(false)` 不再回退 token 圆角。确定模式不登记逐帧工作，不确定模式只推进 phase，并把前后移动区域的并集与实际 frame 相交后发布 damage。Spin 普通模式仅在 Content 阶段绘制，转子直径收敛到实际 frame；包装模式保持零固有占位、把子树铺满实际 frame，在 AfterChildren 阶段仅于 spinning 时叠加主题色遮罩、转子与 Unicode 单行省略 tip，动画 damage 只覆盖变化的转子。默认快照发布 Status“加载中”，显式 tip 覆盖其名称。不轮询。

应用默认通知层由每窗独立 `NotificationHandle` 驱动；`AppHandle::notify_error` 只写入并唤醒其 `WindowId` 对应的队列。窗口间不共享 `State` slot、到期 timer 或动画登记。

### OverlayStack

- `WidgetTree` 内每个窗口一个 `OverlayStack`，维护 `OverlayEntry` 节点栈
- 后打开的浮层层级更高；关闭时自动从栈中移除节点
- 浮层不单独作为跨窗 wake 源
- overlay 命中先递归 owner 子树，再回退 owner，保证 Modal / Drawer 内容可正常接收输入且遮罩仍阻断底层；`Modal::show` 的内容是普通 View 子树，`ModalContext::close` 的 scoped 请求在语义回调结束后由 owner 路径消费，启动既有 leave transition。遮罩覆盖整窗，因此关闭与过渡使用 full-frame damage，但不轮询。overlay membership 变化以 `FullComposite` 强制整帧合成，不得把普通树节点伪标为 Paint-dirty
- 可读取 retained CPU 主表面的后端，在首个全屏 overlay 帧的 `begin_frame` 清除前捕获一份干净背景；后续全帧动画按 `Clear → backdrop PictureBlit → root overlays` 合成，不重放普通树。这是浮层路径上最重要的资源节省机制：Modal/Drawer 的进出场动画可能持续数十帧，若每帧重绘完整的底層组件树会浪费大量 CPU；捕获一次背景后只合成浮层自身，动画期间普通树的 draw 调用降为零。背景像素由不可变共享 `FrameImage` 持有。当前在普通树变脏、尺寸不符、debug overlay、首帧无已提交背景或后端不可读时退回完整渲染——**目标是扩展 backdrop 可用条件**，使更多场景受益于零重绘路径。overlay 存续期间一旦普通树变化，禁止从已含遮罩的表面重新捕获，直至所有 overlay 离场

#### OverlayEntry

每个浮层由 `OverlayEntry` 描述：

| 字段 | 说明 |
|------|------|
| `owner` | 触发浮层的 `ComponentId` |
| `kind` | `OverlayKind`（Modal/Drawer/Popover/Tooltip/ContextMenu/Message/Notification/Custom） |
| `bounds` | 浮层在窗口中的逻辑矩形 |
| `z_index` | 层叠顺序（后开 > 先开） |
| `modal` | 是否阻断底层交互（Modal/Drawer 默认 true） |
| `dismiss_on_outside` | 点击外部是否关闭 |
| `focus_trap` | 是否启用焦点陷阱 |
| `managed` | 是否由框架自动清理（内置浮层均为 true；`Custom` 可设为 false 手动管理） |

`OverlayKind::Custom` 无预设行为，`modal` / `dismiss_on_outside` / `focus_trap` 均需手动调用 builder 设置。

### Focus Trap

- 浮层打开时焦点自动移入浮层内第一个可聚焦节点
- `Tab` / `Shift+Tab` 仅在浮层内循环，不逃逸到下层
- 浮层关闭后焦点回到触发元素；隐藏含焦点子树须统一 `FocusOut` 并注销 IME

### enter / leave 动画

浮层打开/关闭支持两段式动画（公开 `AnimationConfig`，内部 `TransitionPlayer`）。单体浮层在 leave 完成后移除节点；Message / Notification 逐项完成 leave，最后一项消失后移除 overlay。动画发现阶段若 entry membership 改变，框架在同一轮同步 `OverlayStack`；稳定动画帧不重复重建。`Suspended` 时冻结视觉推进。

## 无障碍

<a id="无障碍"></a>

框架从当前 WidgetTree 按需生成语义树（`AccessibilitySnapshot`），供测试 `TestApp`、Agent Bridge 以及未来读屏桥消费；不登记轮询或额外帧。

### 语义标注

- View 通过 `.role(AccessibilityRole)`、`.accessible_name(...)`、`.accessibility_state(...)` 与 `.aria("aria-*", value)` 覆写显式字段；未覆写字段继续从组件实时快照派生
- 内置组件自带默认 role（如 `Button`→`Button`、`Input`→`TextBox`）
- `AccessibilityRole::None` 将节点及其子树排除出语义树

| `TextBox` | Input, InputNumber（单行） |

| `Combobox` | Select, AutoComplete, Cascader, TreeSelect, DatePicker, TimePicker, ColorPicker |
| `Dialog` | Modal |
| `Alert` | Alert, Notification, Message |
| `ProgressBar` | ProgressBar |
| `Table` | Table |
| `TabList` | Tabs |
| `List` | List, Menu |
| `Tree` | Tree |
| `Menu` | Dropdown |
| `Navigation` | Navigation, Anchor, Breadcrumb, Steps, Pagination |

#### AccessibilityState

每个语义节点附带运行时状态：

| 字段 | 类型 | 说明 |
|------|------|------|
| `disabled` | `bool` | 是否禁用 |
| `checked` | `Option<bool>` | 勾选状态（Checkbox/Switch） |

#### AriaAttribute

`AriaAttribute::new(name, value)` 保存一个静态属性名与字符串值；`.aria(name, value)` 按名称覆盖。组件状态自动派生以下常用属性，自定义 View 还可追加 `aria-description`、`aria-level`、`aria-placeholder`、`aria-live` 等属性：

| 属性 | 来源 |
|------|------|
| `aria-label` | `AccessibilitySnapshot::name` |
| `aria-disabled` / `aria-checked` / `aria-expanded` / `aria-selected` | `AccessibilityState` |
| `aria-valuetext` / `aria-valuenow` / `aria-valuemin` / `aria-valuemax` | `AccessibilityState` 的值与范围 |
| `aria-multiline` / `aria-required` | 输入与表单状态 |

### 焦点链

- `Tab` / `Shift+Tab` 遍历有效可见可接收事件的语义节点
- 无当前焦点时分别从首项 / 末项开始
- 浮层内受 `OverlayStack` focus trap 约束——焦点不逃逸到浮层外的节点
- 普通 `FocusIn` / `FocusOut` 仍按目标与冒泡处理；交互包装器通过 `EventHandler::on_focus_within` 观察整个子树，只在焦点跨越子树边界时收到通知，子树内切换不重复开关状态
- 零布局占位的浮动控件以 `hit_test_frame` 作为语义可见边界；已提升为浮层的节点不再受内容祖先 viewport 裁剪，确保视觉、命中与自动化边界一致
- 隐藏含焦点子树须统一 `FocusOut` 并同帧注销 IME

### 安全

- password / sensitive 字段永远不出现在语义快照、Agent Bridge 响应或日志
- 语义快照挂在事件/due work/帧轮次末尾，内容变化才改写；不注册额外 timer/线程/端口

## 事件系统

<a id="事件系统"></a>

### SystemEvent —— 系统事件

OS 原始输入经平台层映射为统一的 `SystemEvent` 枚举，共 29 种变体：

| 类别 | 变体 |
|------|------|
| 指针 | `PointerDown` / `PointerDoubleClick` / `PointerUp` / `PointerMove` / `PointerEnter` / `PointerLeave` |
| 滚轮 | `Wheel` |
| 键盘 | `KeyDown` / `KeyUp` |
| 剪贴板 | `Copy` / `Cut` / `Paste` |
| 文本输入 | `TextInput` |
| IME | `ImeCompositionStart` / `ImeCompositionUpdate` / `ImeCompositionEnd` |
| 焦点 | `FocusIn` / `FocusOut` |
| 窗口 | `Resize` / `WindowMaximize` / `WindowMinimize` / `WindowRestore` / `WindowFocus` / `WindowBlur` |
| 主题/区域 | `ThemeChanged` / `LocaleChanged` |
| 定时器 | `Timer` |
| 拖拽 | `DragStart` / `DragMove` / `DragEnd` |
| 文件 | `FileDrop` |

事件先沿 root → target 执行 opt-in capture，再从 hit-test target 向祖先冒泡；capture 保留窗口 logical 指针坐标，target / bubble 为每个当前节点换算 local logical 坐标并补偿祖先滚动偏移。返回 `EventResult::Handled` 即停止；无障碍状态为 `disabled` 的节点不得成为 Tab / FocusHandle / hover 目标，也不得建立 pressed、drag 或 keyboard activation；reconcile 将节点切为 disabled 时，须在 patch 前清除该子树 hover（原目标收一次 `PointerLeave`）、终止 potential / active pointer gesture（活动拖拽发一次 `DragEnd`、pressed 目标收 `PointerLeave`），再向当前焦点子树发送 `FocusOut` 并取消 outstanding keyboard activation，避免新配置的 disabled 早退吞掉清理。捕获阶段拦截 `PointerDown` 时同步撤销命中目标的 pressed / potential drag，不得在后续释放合成目标 Click 或 Drag；拦截 `PointerUp` 时仍以 `PointerLeave` 取消原 pressed 目标并窄标脏，禁止遗留激活视觉。键盘 Enter / Space 只允许一个 outstanding activation：首次已处理 KeyDown 锁定目标、键与修饰键，自动重复和另一激活键被吸收，匹配 KeyUp 回到同一存活焦点目标后才合成一次 Click；任意实际焦点切换先取消该激活，再向旧目标发送 `FocusOut` 清理视觉。`WindowBlur` / `WindowMinimize` 清除本窗 hover、终止 potential / active pointer gesture 和 outstanding keyboard activation：活动拖拽按最后位置发出一次 `DragEnd`，每个受影响的 hover / pressed 目标至多收到一次 `PointerLeave`，焦点目标收到 `FocusOut` 清理键盘 pressed；窗口 focus 状态幂等切换，逻辑键盘焦点身份保留，但停用 / focus 分别只向该目标与 focus-within 路径发送一次 `FocusOut` / `FocusIn`，`WindowRestore` 不冒充 `WindowFocus`。停用状态拒绝随后迟到的 Pointer、Wheel、FileDrop、Key、TextInput、IME 与 Copy/Cut/Paste，不把旧输入交给保留的逻辑焦点，也不得重新建立 hover、pressed 或 drag。`PointerDoubleClick` 在每个节点先按专用变体派发，节点未处理时在同一节点回退为第二次 `PointerDown` 后才继续冒泡，确保内层普通控件不会被外层双击手势抢占。

View 的 `.on_event` / `.on_pointer` / `.on_key` / `.on_focus` / `.on_scroll` handler 作为节点元数据随 build 与 reconcile 替换，先于组件 `EventHandler` 执行；返回未处理才进入组件和父节点。`*_capture` 使祖先参与捕获。`.on_pointer` 明确选择连续 PointerMove；其他 View 不改变边界感知快路径。`focusable(true)` / 正 `tab_index` 只登记该节点的 Tab 顺序，不产生 timer、frame request 或跨窗状态；`.focus_handle(&handle)` 绑定应用持有句柄，reconcile 保留同一节点身份时换绑，remove / root reset / session shutdown 时失效。

### SemanticEvent —— 语义事件

组件可将原生输入转为高层语义动作，供 `on_semantic` 回调、Agent Bridge 以及 `ComponentHandle::emit()` 消费：

| `SemanticKind` | 触发源 |
|----------------|--------|
| `Click` | 鼠标左键 / Enter 键 |
| `Change` | 值变化（Input、Select、Slider） |
| `Submit` | 表单提交 |
| `Cancel` | Escape 键 / 取消按钮 |
| `Toggle` | Space 键（Checkbox/Switch） |
| `Navigate` | 方向键导航 |
| `Select` | 选项选中 |
| `Scroll` | 滚动偏移变化 |
| `Expand` | 展开/折叠 |
| `Custom` | 用户自定义 |

`SemanticPayload` 携带具体数据（点击坐标、变化值、选中等）。

### HandlerTable

`WidgetTree` 按 `ComponentId` 索引 `HandlerTable`，每个节点可注册多个 `HandlerRegistration`（按 `SemanticKind` 分组）。Reconcile 时同类型同 key 复用，不同 key 替换，适配 `State` 指纹绑定。

原始 `SystemEvent` View handler 直接属于 `BoxedWidget`，不进入语义 `HandlerTable`；reconcile 整体替换同节点声明，remove / root reset 随节点释放。无 handler 且组件无 `EventHandler` 的节点不参与交互态缓存判定。

## Form 校验模型

`Form` widget 只负责布局配置，不持有字段值、规则或业务闭包。`Form::field(...).build()` 生成可克隆的应用侧共享 `FormModel`：字段当前值与不可变 schema 分离，以 type-erased immutable handle 组装 typed `Values`；`IntoFormValue` 同时提供供文本规则读取的稳定投影，`HashSet<String>` 投影按排序后的选项逐行连接而 typed handle 仍保留集合。内置、inline custom 与字段依赖规则按声明顺序同步执行，每字段止于第一条错误。默认 `OnSubmit` 由 `validate()` / `submit()` 激活；`OnChange` / `OnBlur` 分别由 `set_value()` / `blur()` 激活。字段一旦由其触发边界激活，后续值变化持续重验，避免修改后保留过期错误。错误集合由单一 State 发布，只有内容变化才请求所属根 View reconcile；依赖源变化后以访问集对直接与传递依赖各重验一次，循环不会重复执行。

`FormItem` 由一套共享几何同时驱动 render、子节点 measure 与 arrange：非空 help 占用底部 16px 并增加自然高度，剩余主区再按 Vertical 的标签行或 Horizontal / Inline 的标签槽分配给控件；受限 frame 只压缩这些区域而不生成负尺寸。外层 frame clip 约束状态条和全部文字，标签另在 label slot 内裁剪，帮助文字另在 help row 内裁剪；因此长标签不会覆盖控件，帮助文字不会覆盖子节点，Inline 与另外两种布局使用一致的状态渲染路径。`Form::gap` 在入口把负数及非有限值归一为 0，measure 与 arrange 始终读取同一有效间距。

`input_item`、`select_item`、`input_number_item`、`checkbox_item`、`switch_item`、`slider_item`、`rate_item`、`radio_item`、`segmented_item` 与 Picker item 在应用侧把已声明 schema 组合为 `FormItem + controlled component`：构建期读取外部 State，Change / FocusOut 事件把文本、集合、布尔、数值、日期、时间或颜色 typed 值同步到共享 model，错误 State 控制字段状态与内联首错文本。单值控件各绑定一个字段；`date_range_picker_item` 以一个共享 `FormItem` 绑定两个独立 Date 字段，Change 同步两值、FocusOut 激活两字段，聚合项按起止顺序呈现第一条错误，并让两字段共享同一焦点句柄。组件自身继续负责区间归一、步进、离散评分、组语义、禁用选项导航、日期粒度、范围排序与禁用日期；表单适配不复制这些规则。除文本 Input 与双字段日期范围的专用路径外，其他组件共用一条 typed Change / Blur / FocusHandle 绑定路径。每个已绑定字段复用一个 typed `FocusHandle`；`submit()` 失败只登记首错 focus 请求，不直接遍历或操作 `WidgetTree`。绑定闭包仍随 View handler 保存，validator 仍只属于 `FormModel`，不会进入 component struct；此路径不新增 timer、FrameOpportunity 或跨窗工作。

`Form::list(...).build()` 生成应用侧 `FormListModel`：schema 中的不可变规则按行共享，字段值与错误逐行独立；`FormListItemId` 单调分配且删除后不复用。列表只用一个 `State<Vec<FormListItemId>>` 表达结构；`render_rows()` 构建期读取该 State，并把稳定 ID 写为 keyed child。增删只触发所属根 View 的一次结构 reconcile，未删除行按 key 复用；字段校验不触发树遍历、绘制、timer、FrameOpportunity 或跨窗 wake。

## VirtualScroll

<a id="virtualscroll"></a>

虚拟列表用于万级数据场景，仅渲染可视区内的行：

- **视口**：由 `.size(w, h)` 设定，超出部分不创建 DOM/Widget 节点
- **行高**：`.item_height(h)` 固定行高，快速计算 materialized_range
- **预渲染**：`.overscan(n)` 控制可视区外额外渲染行数（默认 5），减少快速滚动时的白屏
- **物化**：滑出视口的行从树中移除，重新进入时重建，不保留实例状态
- **render 契约**：`.render(|index| view)` 返回普通 `View`；工厂按 `ComponentId` 存在 keyed side table，物化时捕获 State / Effect 并注册事件，组件数据不持有业务闭包
- **工作边界**：初次构建、布局导致可见范围变化或 wheel 事件才刷新本视口子树；范围未变不重建，无 timer / FrameOpportunity / 跨窗 wake。滚动继续登记本视口 Composite 与 rect damage，同轮由现有失效队列合并
- **滚动状态**：`VirtualListScroll` 内部维护 offset + item_count，不参与全局 dirty 合并

## 图形

<a id="图形-api与帧提交硬约束"></a>

`GraphicsBackend` = API 请求（非 OS 别名）。轴：`RasterMode` × `PresentMode` × API；按 recipe 装配。

解析：builder > 环境变量 > Settings > 默认 **Vulkan**。禁跨 API 偷换；仅显式 `Auto` 可跨 API probe。registry 只陈述能力（可含 Planned stub），不替 App 选 API。

```text
App / WindowSession
  → resolve GraphicsBackend
  → bootstrap（recipe | Auto 候选）
  → GraphicsDevice（可按 adapter/API 共享；线程亲和）
  → WindowSurface（每窗；logical / drawable / DPR）
  → FrameEncoder（单一有序、API 中立）
  → Presenter::present() -> Result<PresentOutcome, GraphicsError>
```

- **帧提交**：一帧一条命令序列；禁双画序；每帧至多一个 `Presenter`；成功指标仅提交成功后记。initialize / resize / make-current / begin-end-frame / present → typed `Result`；CPU 像素写入 retained buffer 不等于提交成功，最终 OS present（含 GDI `GetClientRect` / `GetDC` / `StretchBlt`）失败须 typed 返回；失败帧保留 dirty。透明 CPU segment 只收 source-independent op；Additive / Scroll 等目标相关 op 必须进入 Native IR，无法精确降级的几何或状态在录制边界 typed 拒绝。
- **DisplayList 录制**：文本指令（`DrawText` / `TextCenter` 等直接字符串变体）以 `Arc<str>` 共享不可变内容，列表 clone 不复制文本缓冲——这是「用最少资源」在绘制指令层的体现：100 个相同字符串的 label 只存一份堆分配。`BlitGlyphLayout` 以 `TextLayout`（`Vec<PositionedGlyph>` + `Vec<LineInfo>`）存储已布局字形，clone 时复制布局数据——这是文本绘制路径上最大的单次分配源；Picture 缓存命中时通过 `LayerTree::collect_picture_handles` 所有权转移避免重复 clone。缓存 DisplayList 与新绘 Picture 现在都进入私有 `FrameRecordingCanvas`，不再先 replay 到完整 CPU 表面。主帧与 Picture 内符合 identity / 整数 offset / SrcOver / 整数矩形 clip 的字形，先把当前 opacity 按 CPU 的 straight alpha 截断顺序折叠进 `Color`，再保留共享 coverage；紧邻同 clip 字形合为一个 `BlitGlyphs` Native IR，折叠后 alpha=0 直接 no-op。identity transform 下的普通矩形 / 圆角矩形先按 CPU 同样的 f32 加法应用当前 offset，只有最终几何为 surface 内整数矩形且为 SrcOver 时才保留为 Native IR；当前 fill opacity 先把 CPU 的 premultiplied 8-bit 源反解为可精确恢复同一源像素的 straight Color，部分整数 clip 由独立 `FillRoundedRectClipped` 携带，clip 直接使用 push 当时固化的 surface-space 坐标，空交集直接 no-op。Picture 只在透明开头、完整或局部 source、整数 1:1 destination、父画布 identity / SrcOver / opacity=1 且当前 offset 为有限整数、目标 clip 为整数矩形，且每对可见写区互不相交，或其实际交叠区被一块或多块已证明全不透明 cover 的无缝并集完整覆盖时，才丢弃局部 Clear、先把 offset 固化到 destination、按目标 clip 同步裁 source / destination，再按 source crop 收窄命令并检查坐标后事务性平移整条命令流；未覆盖重叠仍因 8-bit SrcOver 舍入不满足结合律而整图物化。其他 Picture 状态同样物化。scratch batch 是 CPU 绘制的核心节省机制：连续 CPU draw 不逐次 flush 上传，而是积累到 scratch 表面，在 painter-order 边界一次性 pack 紧凑脏区为 CpuSegment。主画布 scratch 初始及 resize / shutdown 后只保留 1×1 安全占位；每个 Picture 候选录制结束或失败后也立即收缩回 1×1。首次真实 CPU draw 才分配整面；纯 native 帧不扩容。scratch 只清已写并集，写区过大或无界时清整面；成功 flush 后复用同尺寸 scratch 分配并只重置光栅状态，中途放弃的录制在下帧前保守全清。圆角矩形的无变换 CPU 填充 / 描边按左右半扫描线只计算 SDF 边界，连续实心段批量写入，结果须逐像素等价于完整 SDF。recorder 嵌套、panic 展开与 replay 临时停录均须恢复上一层目标和开关，禁止留下悬空录制指针或改变调用方状态。
- **文本布局**：`FontService` 先按实际字体回退分段，再在有限 `max_width + word_wrap` 下按字形推进折行；单一字体长段不得旁路折行，显式换行与空行进入真实 `LineInfo`。常见中西文闭合标点若会落到行首，须与前一字符共同移到下一行。无字体上下文的测量统一使用宽字符、显式换行与标点禁则估算：`Typography::Paragraph` 按可用宽度计行，`Label` 不自动折行但须为全部显式行保留高度，并以样式 token / 物理单位字号参与首帧布局；`Button` 按样式字号和宽字符估算单行内容宽度，再在绘制时用实际字体宽度居中；`Tag` 同样按宽字符估算正文，并把勾选 / 关闭动作区作为固定宽度加入固有尺寸，关闭符号走 Lucide 图标字体；`Badge` 的普通胶囊按 11 logical、状态 / 圆点标签按 13 logical 估算可见文本，普通胶囊的 text 优先级与绘制、语义一致，溢出计数按实际 `max+` 标签量宽；`Tooltip` 的单行气泡按 12 logical 估算可见文本并加入 16 logical 横向 padding，render、overlay bounds 与 dirty damage 共用同一气泡尺寸和箭头间距；`Checkbox` 按尺寸档位以 12 / 13 / 14 logical 估算单行标签，并只为可见标签加入间距，测量与绘制共用该间距规则。Label / Button / Tag 字号在测量和绘制前统一收敛为有限正值，非法值分别回到组件默认值；Badge 的像素 / 物理 offset 转换后按分量收敛非有限值为 0。`Timeline` 以归一化实际 frame 计算行距、节点、连接线和文字槽，固定单行标签 / 说明按 Unicode 边界省略，全部绘制受 frame 与各自文字槽双层裁剪；反转只改变已完成项的视觉与 `List` 语义顺序，pending 始终位于末尾。
- **Switch 几何**：Small / Medium / Large 的轨道分别为 28×16 / 40×22 / 52×28 logical，并垂直居中于 24 / 32 / 40 logical 控件框；圆形滑块直径为 12 / 18 / 24 logical，横纵轴共用 2 logical 内边距，关闭态贴左、开启态贴右。
- **Radio 布局与焦点**：选项固有宽度由共享 Unicode 估算器量取当前尺寸字号，再加入随控件尺寸缩放的指示器与尾部空间；横向组累加各项且至少 120 logical，纵向组取最大项宽并按 24 / 32 / 40 logical 行高堆叠。焦点属于整个 `RadioGroup`，绘制时以当前选中项为锚，在原圆环外增加随尺寸缩放的独立焦点环；方向键相邻索引在首尾循环，受控值无匹配时按前进 / 后退方向分别进入首项 / 末项。
- **Input 行模型与附件**：Textarea 写入时把 CRLF / CR 收敛为 LF，以 `split('\n')` 的逻辑行保留末尾空行；固有高度、上下移动、光标绘制、选择区和滚动后点击命中共享该行模型，逐行命中坐标以 text area 为局部原点并按绝对逻辑行索引保存。空值 placeholder 不得生成超出真实值的光标索引；隐藏密码把已提交字符映射为掩码，但 IME 预编辑仍插在当前字符索引，光标按掩码前缀量宽；同一 password 模式 reconcile 保留运行时可见性，退出 password 模式时强制复位。Addon 使用 13 logical 的共享 Unicode 估算宽度加 16 logical 横向 padding，并与 prefix / suffix、clear、password、search 的独立槽共同进入单行固有宽度；绘制使用窗口坐标，交互命中矩形必须转换回组件局部坐标。
- **InputNumber 数值文本与几何**：数值缓冲使用可往返 `f64` 文本，聚焦 / 失焦不得把有效精度强制截成两位；步进前先提交当前缓冲，再按现值与 `step` 的十进制位数对常见浮点加法尾差做有限精度收敛，typed State 仍由 `InputNumberValue` 执行最终类型转换。三档固有尺寸固定保留 80 logical 文本主体，并在右侧追加 24 / 32 / 40 logical 方形步进区；实际受限高度下，按钮命中按本次绘制矩形的上下半区判断。背景、禁用色和焦点描边覆盖完整外框，内部只绘制步进分隔线；数字文本在主体 clip 内按实际字体推进定位光标，溢出时左移以保留尾部，步进箭头使用 Lucide 图标字体。
- **Select 文本、交互与浮层几何**：固有宽度按选项、分组与 placeholder 的 Unicode 文本指标估算并至少为 120 logical；实际受限高度同时决定绘制、光标与命中。触发器文字、搜索查询和多选标签只在扣除 28 logical 箭头槽后的内容区绘制，查询光标按实际字体推进定位并在溢出时保留尾部；多选标签按实测文字宽度裁切，关闭槽与 Lucide 图标保持独立。搜索 / 多选键盘高亮与已提交值分离，方向键不得提前写回，单选仅由 `Enter` 提交，多选由 `Enter` / `Space` 切换且保持展开。下拉行高固定 28 logical、视口上限 280 logical，空结果仍保留一行本地化空态；绘制前按 logical surface 选择下方或上方，滚动、行命中、dirty 与 popup bounds 共用本次渲染矩形。展开及关闭过渡期间注册 `Popover` overlay，使下拉在普通兄弟内容之后合成；触发器与下拉正文分别裁切，长文本不得覆盖箭头、复选框或相邻控件。
- **Segmented 文字与分段几何**：各项固有宽度由共享 Unicode 估算器按当前尺寸字号量取可见文字，再加入随高度缩放的 24 logical 基准横向空间；三档固有高度为 24 / 32 / 40 logical。绘制时以 `min(frame.h, nominal_height)` 作为实际控件高度，并把各项固有宽度按总宽比例缩放到完整 frame；绘制、分隔线和二维半开命中逐项消费同一宽度表，最后一项吸收浮点余量。字号、内边距和圆角共享实际高度比例，整体与每项分别裁切，受限宽高不得留下不可点击尾部，也不得让后续分段、选中块或文字越出控件。整体或单项禁用的当前选择使用独立 disabled thumb 填充与弱化文字，仍须保留选择辨识。方向键从当前索引向前或向后循环查找首个启用项；外部值未匹配时分别从首项或末项开始，全禁用时不改值。非受控 reconcile 优先按当前选项文本在新 options 中恢复选择，文本已移除时才回退到仍有效的旧索引。组件语义是互斥选择的 `RadioGroup`，不是关联面板的 `TabList`。
- **CPU 分配与资源上界**：可呈现主表面与真实离屏表面先检查像素数并可失败预留，resize 只在这些预分配成功后提交；失败返回 `GraphicsOutOfMemory`，保留旧尺寸且不消耗离屏句柄。API-neutral recorder 不持有可呈现 CPU 主表面；resize 只验证 logical extent 可寻址并原子更新。recorder Picture 槽只常驻 1×1 scratch 与一份 committed 表示：保留 IR 的 command / image / coverage 总量不超过同尺寸 BGRA 预算，超限在发布前物化为单张 `FrameImage`，二者不同时常驻。录制 scratch 的全尺寸像素同样延迟到首次 CPU draw；void 绘制入口的分配失败保留 1×1 安全占位和既有光栅状态，并把 typed OOM 延迟到帧边界。native GPU 的惰性软回退（`NativeGpuCanvas2D::ensure_soft`）分配失败时同样只保留 1×1 安全占位并把原 typed OOM 延迟到帧边界；OpenGL 的全目标 RGBA upload texture 也只在首次真实 soft upload 时创建，glyph-only / native-only 帧不预留。清除 / 重叠复制的裁剪加减使用扩宽整数，极端坐标不得溢出。图片缩放与字形 blit 先验证源 / 目标缓冲，只遍历实际可见目标区，禁按被缩小的源面积或离屏 coverage 空转。`ImageService` 的目标尺寸圆形 / 圆角方形 / 圆角矩形派生位图按源句柄、物理尺寸、圆角与 fit 模式缓存，分配失败回退原图绘制，源图卸载时同步失效派生句柄。字形光栅尺寸上限为 512 px，统一缓存受 **2048 项与 8 MiB coverage** 预算约束（Chrome / Flutter 同等水平），容量压力只逐项淘汰；D3D11、D3D12 与 OpenGL atlas 均最多 2048×2048 R8，cache 只保留精确尺寸的共享 coverage allocation，避免尾随 payload 绕过该上界。D3D12 使用两个固定且互不覆写的 shader-visible SRV 槽位隔离 soft texture 与 glyph atlas；图集满时按命令顺序先提交已有字形段，再覆写同一固定纹理。每段 glyph coverage 共用一张最多 4 MiB 的 staging footprint 并以 source box 分区复制，避免窄字形逐项 256-byte row pitch 放大；glyph 路径仅在当前 backbuffer 的 retained upload pool 预计总容量不超过 8 MiB 时长期复用，否则只保活到对应 fence。无原生 glyph 能力或字形单边超过 2048 的后端回退 cluster 面积上限为 1M 像素（4 MiB BGRA）、稀疏 union 上限为累计可见字形面积的 4 倍，最终 tile 不超过 1024×1024。高斯核以完整半径位编码进入最多 32 项的线程本地 LRU，半径上限为 256，命中共享不可变内核而不复制权重数组。
- **Picture 缓存**：符合条件的子树（≥ 8 节点且 ≥ 65536 估算像素）先成为候选；`LayerTree` 在每次 build 前按“子树预计重绘像素 / 离屏 BGRA 保留字节”全局排序，在每棵树 **32 MiB** 的离屏硬预算内提升为 `LayerNode::Picture`。同收益密度依次优先总重绘量更高、可复用既有句柄、`NodeId` 更小的候选，因场景变化超预算的旧缓存降级为 Direct / Clip 并进入 checked orphan sweep，选择结果因而有稳定上界且可动态淘汰。CPU 后端仍由 `CpuOffscreenPool` 管理离屏像素；API-neutral recorder 改用 `RecordedPicturePool`，每个 handle 保留独立候选 canvas 与原子发布的 committed encoder / image；GPU 后端使用 GPU RT。`sweep_orphaned_offscreens` 在 build 后释放未复用句柄。Picture begin 只重置候选 transform / clip / opacity / blend / save 等状态，不清 committed；flush、cached execute、nested blit 或 finish 失败会丢弃候选并保留旧缓存，成功 end 才一次替换。尺寸变化先创建 replacement，再销毁旧 handle，创建或 checked destroy 失败均保留旧缓存。Native GPU Picture 的 GPU RT 独立保存缓存结果；最近一次 checked flush 成功且恢复 swapchain target 也成功时，已上传到 GPU RT 的可重建 CPU `soft_fallback` staging 在 Picture end 立即释放，不等待后续 present 或 250ms maintenance。flush / restore 失败则保留未提交命令或 soft source，typed 失败与重试语义不变；GPU RT 与 Picture 句柄继续独立存活。CPU 与 recorder 的槽位数组在 destroy 后截断尾部连续空槽；GPU 后端的 `NativeGpuBackend::offscreens` 同样清理尾部空槽与越界 free ID。
- **GPU 路径上的 CPU 中转**：`FrameRecordingCanvas::scratch`（录制期积累 CPU 绘制后 flush 紧凑脏区）与 `NativeGpuCanvas2D::soft_fallback`（执行期 GPU 未原生实现的文字、non-identity / fractional 等剩余状态与阴影模糊的 CPU 中转）均按需分配。recorder 不持有完整 CPU 主表面；主画布与每个 Picture recorder 的 scratch 初始为 1×1，首次 CPU draw 才扩大，Picture paint 结束即收缩。identity、整数 offset、SrcOver、整数矩形 clip 的主帧字形直接录为 `BlitGlyphs`；Picture 内字形允许 identity 下的整数 offset。两者都先按 CPU 顺序把 opacity 截断到 straight alpha，再 premultiply 并由 atlas shader 应用 coverage；因此透明度字形仍保留 coverage `Arc`，并可在透明、整数 1:1 的完整或局部 source 中，于写区互不覆盖，或每个实际重叠区被不透明直角填充 / 不透明圆角填充保守 SDF 全覆盖内区的一块或多块无缝并集完整覆盖时平移 clip/坐标后拼入主帧；父画布整数 offset 会固化到 destination，整数目标 clip 会同步收窄 source / destination。D3D11 WARP、D3D12 WARP 与 Windows WGL 的 rounded + tiled-union + opacity-glyph Picture producer → main encoder → atlas 真实读回逐通道误差不超过 1，fake executor 同时证明量化 alpha 和零 FrameEncoder soft tile；`last_soft_upload_bytes` 也覆盖直接 `CpuSegment` / `PictureBlit`，不再只统计 Canvas fallback。矩形 / 圆角填充允许 nonzero offset，但仅在 identity transform 下按 CPU 同样的 f32 x/y 加法映射后仍是 surface 内整数矩形，且 SrcOver / clip 为整数矩形时，才录为 `FillRect`、`FillRoundedRect` 或携带部分 clip 的 `FillRoundedRectClipped`；fill opacity 会先量化为可精确恢复 CPU premultiplied 8-bit 源的 straight Color。D3D11、D3D12 与 OpenGL 将 glyph batch 送入最多 2048×2048 的 R8 atlas，按 coverage allocation 身份跨调用 / 跨帧命中；三者的 glyph shader 都按 CPU 的两级 8-bit 截断生成 premultiplied 源。OpenGL atlas 与 WGL / EGL 共享同一 pipeline，glyph-only 帧不创建全目标 RGBA soft texture。三个 GPU solid-rect 后端以 premultiplied SrcOver 提交；OpenGL scissor 按 logical 两端点分别换算 fractional DPR drawable 边界。未被无缝不透明并集完整覆盖的量化重叠、缩放、fractional source/destination/origin、后续 Clear、Additive / Scroll 或坐标溢出仍整图物化；这部分与 Picture 整体 opacity、其他 CPU 图元 opacity、GPU coverage 和模糊仍是活跃中转。`soft_fallback` 连续两个 soft-free 成功 present 后立即释放，最后一次 soft present 后则登记本窗 250ms 一次性 deadline；deadline 只做非视觉维护。**目标**：1) GPU 生成字形 coverage；2) 扩展其余需要组内合成的 Picture、non-identity / fractional 几何与 Picture / 其他 CPU 图元 opacity；3) GPU compute / 两 pass 降采样模糊替代 CPU 高斯。
- **矢量便捷图元**：`PaintContext::stroke_arc` 使用弧度并分解为至多四段三次 Bézier，再进入共享 `Path` 描边、DisplayList 与 CPU / native GPU tessellation；禁旁路录制另画一遍。
- **尺寸契约**：`GraphicsEngine::logical_extent()` 是布局与窗口 reconciliation 的精确 logical viewport；默认等于 canvas，仅 drawable-sized 引擎覆盖。`WindowDriver` 禁以单一 DPR 从 physical canvas 分别反推两轴，避免非整数缩放的独立取整造成 layout 漂移或 busy resize。GPU context 的 `width` / `height` 与 PixelUpload canvas 为 drawable physical。
- **绘制与提交解耦**：GPU 主路径可绘全帧；仅当 damage 外最终像素不变且 backend 已证明 present coherency 时才提交窄 damage，否则 Full。`PresentUpload` 的 CPU canvas 是 retained buffer，可独立提供 dirty-rect 绘制与 scroll memmove；Vulkan present 即使仍为 `FullOnly`，也不得把 CPU 绘制扩大为全帧。绘制 damage 与 present damage 是正交能力。当前 GPU 路径多数场景未达 coherency 证明条件——**目标是扩展 coherency 追踪**：识别纯色变化帧（主题切换）、无几何变化帧等场景，使窄 present damage 成为常态而非例外。在此之前，未证明 coherency 时禁止窄提交。
- **damage**：UI dirty 为 logical top-left；提交按 DPR / transform 转 drawable，min `floor`、max `ceil`、裁到 extent。resize / DPR / orientation / `currentTransform` / surface generation 改变后首帧强制 Full。多块脏区以 AABB 并集清空，干净区域也被重绘——这是当前实现，**目标是脏区拆分**：每个脏矩形独立清空，矩形内先绘父级背景再绘脏控件，消除 AABB 内干净像素的浪费。达到后 dirty rect 与重绘区域一一对应，零过度绘制。Vulkan incremental present 相对 `currentTransform`；Wayland 优先 [`damage_buffer`](https://wayland.freedesktop.org/docs/html/apa.html#protocol-spec-wl_surface)；禁直接 `as i32` 截断。
- **present coherency**：typed `FullOnly` / `RetainedBuffer` / `TrackedSwapchain`；`PresentDamageTracker` 只在成功 present 后提交 signature 与 history。缺 identity / history / generation / transform / 修复能力一律 Full（见「绘制与提交解耦」——未证明时 Full 是合规策略）。
- **IR**：`FrameRasterOp` = `FillRect`（SrcOver）、`FillRoundedRect(FrameRadius)`（SrcOver）、`FillRoundedRectClipped(FrameRadius, FrameRect)`（SrcOver）、`BlitGlyphs(Vec<FrameGlyphBlit>, clip)`（SrcOver）、`FillRectAdditive`、`FillRoundedRectAdditive(FrameRadius)`、`ScrollCopy`。identity transform 的普通半透明矩形与圆角矩形，先按 CPU identity-fill 契约仅给 x/y 加当前 offset；映射结果为整数、正尺寸且完全位于 surface 内时，当前 fill opacity 先经 CPU 同序的 premultiply → opacity 截断，再反解为 premultiply 后逐位相同的 straight Color。identity / 整数 offset / SrcOver 且当前 clip 为整数矩形的主帧有效字形保留共享 coverage；Picture recorder 允许整数 offset 并把它固化到 glyph 坐标。两者的 opacity 都严格先计算 `u8(color.a × opacity)`，RGB 保持 straight，之后由 reference / D3D11 / D3D12 / OpenGL 同序 premultiply → coverage 截断；alpha=0 不发布命令，避免把 glyph opacity 错折叠为 premultiplied 后缩放。Picture splice planner 先检查唯一透明首 Clear、有限整数且 1:1 等尺寸的 source/destination、父画布 identity / SrcOver / opacity=1、有限整数 offset、整数目标 clip、每条 image 的等尺寸 src/dst、所有 local/translated bounds 与 checked add；父画布 offset 先固化到 destination，目标 clip 同步裁 source / destination；局部 source 会逐命令求可见交集，圆角保留原始几何并附加 clip，glyph 平移共享 coverage 与收窄后的 clip，image 命令同步裁 source 子段。planner 收集 Fill / glyph / CPU segment / PictureBlit bl))`、right=`ceil(max(tr, br))`、top=`ceil(max(tl, tr))`、bottom=`ceil(max(bl, br))` 收缩后仍非空的整数内区作为 cover；`FillRoundedRectClipped` 再与 clip 求交。该内区内所有像素中心的 SDF ≤ -0.5、coverage 精确为 1，抗锯齿角部不冒充不透明。未被无缝 cover 交集以扩宽整数计算端点，极端坐标或空交集不得溢出；`FrameGlyphBlit` 验证非零尺寸、乘法、`usize → u32` 与 coverage 下界。`FrameRadius` 只容纳有限非负半径；D3D11、D3D12 与 OpenGL shader 均先执行 8-bit premultiply，再以 premultiplied SrcOver 应用 coverage。Additive - **回退**：缺实现 / Planned stub → typed 失败后 Software/CPU；禁称「平台永久不支持」。unsupported → 有界 CPU segment；禁近似冒充。
- **恢复**：surface rebuild → recipe rebuild → 同 API 下一 recipe → Software，各步只尝试一次；仅 `Auto` 可跨 API。旧 engine 须先 checked teardown，再创建同 native surface 的 replacement；teardown 失败时禁止探测第二份 context。Software 的 `ExternalPresenter` 成功才重置序列，序列耗尽或 `OutOfMemory` 进入终态。resize 失败仍记住最新目标 extent；backend 不得把 `DeviceLost` / `SurfaceLost` / OOM 抹成 `NotImplemented`。Vulkan wait-idle 返回 `DeviceLost` 时仍须销毁本窗 child；共享 device 标记 lost 后所有 peer typed 停止提交，池不得把它交给 replacement，最后一个 lease 才销毁逻辑 device。其他 wait 失败保持 typed 且保留未排空父对象。显式 `test-harness` 可为单窗安排至多一个下一帧 `GraphicsDeviceLost`：该真实绘制帧必须先返回 `Failed` 并保留 dirty，后续帧才进入同一生产恢复 FSM；无可恢复 GPU engine、重复待处理注入或关闭窗口须 typed 拒绝。默认构建不含此入口，注入证据不得冒充真实驱动或硬件矩阵。
- **诊断**：成功 recipe 记录 backend 与可得的 adapter identity；Vulkan 须含名称 / 类型、vendor / device、API / driver 版本与 queue family。候选级扩展查询或 graphics queue 的 present-support 查询失败只拒绝该候选 / queue，继续检查其余 queue 与适配器；最终 adapter / queue 选择失败须列出全部已检查候选及拒绝原因，保留首个 typed 根因。Vulkan 仅在 `VK_EXT_device_fault`、`deviceFault` 与 Vulkan 1.1 core / `VK_KHR_get_physical_device_properties2` 查询路径同时可用时启用 fault reporting；驱动返回 `ERROR_DEVICE_LOST` 后才查询，address / vendor info 各至多 16 条，不分配 vendor binary。首次 fault 报告或查询失败均随 `GraphicsDeviceLost` 缓存到共享 device 原因链，peer 与后续错误不得覆盖它。
- **滚动帧**：`begin_frame` 先清 dirty 区，故 `ScrollCopy` 读到的是已清空像素；render_frame 须把滚动视口并入清/绘区。
- **绘制裁剪同步**：`begin_frame` 以 `FrameReady` 返回实际清除 / 裁剪区；`FrameRenderer` 必须以该区驱动录制剪枝。引擎把 `DirtyRects` 请求提升为 Full 时，present damage 也须提升；因后端不支持局部绘制而主动请求 Full 时，仍可在缓冲一致性已证明后保留窄 present damage。实际区不得小于请求区，否则 typed `InvalidState`；禁另算一份录制 clip。
- **所有权**：`draw` 不持有 GL/D3D/Vulkan/Metal 对象；bootstrap 收 `NativeSurfaceHandle`。共享 `GraphicsDevice` 以 adapter / API / queue family / thread affinity 为 key；每个新 `WindowSurface` 仍须查询该 queue 的 present support，不兼容则该窗另建 recipe。Vulkan runtime 以 UI 线程本地弱引用复用 instance，按 physical device + queue family 复用 device；surface / swapchain / command pool / fence / staging buffer 仍逐窗独占；复用单 staging buffer 时，CPU 覆写或替换前必须等待上一 submission fence，禁在 GPU 仍读取时写入。`vkQueuePresentKHR` 的 wait semaphore 按 swapchain image 独立持有并按 acquire 返回的 image index 复用；可用 `VK_EXT_swapchain_maintenance1` 时每次 present 绑定独立 fence，重建前只等待本窗 frame fence，再逐 fence 等待并 reset；新旧 image 数相同时跨 generation 复用整组 present semaphore / fence，禁止把逐窗重建扩大为 `vkDeviceWaitIdle`。关闭前仍须逐 present fence 等待。扩展缺失时，运行期旧 swapchain 与其 semaphore 延迟到新 generation 中已呈现 image 被再次 acquire 且对应 acquire wait 的 submission 完成后回收。禁以普通 submission fence 或 `vkDeviceWaitIdle` 冒充 presentation 已消费 semaphore；无扩展的最终 shutdown 没有规范级 completion primitive，兼容回收不能充当 P6 真机通过证据。生命周期边界为 `try_shutdown`（无 void `shutdown`）；`ThreadBoundGraphicsContext` 错线程 Drop 时 leak 内层，禁错线程 native teardown。

## 设计令牌与色彩体系

<a id="设计令牌与色彩体系"></a>

色彩体系包含相互独立的“选色色板”和“运行时令牌”。选色色板公开 12×10 主色、13 阶中性色、4 类功能色阶与 AntV 10 色分类数据色板；运行时由 `ThemePrimitives`（8 个基色）推导 `DesignTokens`（~100 个令牌）。两者共享种子约定，但不把 120 色复制进每个主题实例。

### 模型

```text
  PrimaryHue / generate_color_scale       bg / text / border + 5 个语义基色
                 │                                      │
                 ▼                                      ▼
     ColorScale（选色，按需取用）              ThemePrimitives
                                                        │
                                                        ▼ mix / alpha
                                               DesignTokens（~100 字段）
                                                        │
                           ┌────────────────────────────┼────────────┐
                           ▼                            ▼            ▼
                         View                         render    功能色阶按需生成
```

| `info` | 信息 / 提示（默认 = primary） | `#1677ff` | `#1677ff` |
| `bg` | 页面底色 | `#f5f5f7` | `#151515` |
| `text` | 文字基色 | `#000000` | `#ffffff` |
| `border` | 边框基色 | `#e4e4e7` | `#38383a` |

推导公式（`ThemePrimitives::into_design_tokens`）：

- **品牌色 hover/active**：primary 向 white/black 各混 15%
- **品牌色 bg/border**：亮色 primary→white 85%/55%、暗色 primary→bg 80%/45%
- **背景层级**：`color_bg_container` = bg→white 55%（亮）/ bg.lighten(4%)（暗）；`color_bg_elevated` = white（亮）/ bg.lighten(12%)（暗）；`color_bg_layout` = bg→white 20%（亮）/ bg.darken(3%)（暗）
- **文字层级**：text.with_alpha(224/153/102/51) → text / secondary / tertiary / quaternary
- **填充层级**：text.with_alpha(31/15/10/5) → fill / secondary / tertiary / quaternary
- **语义色**：与品牌色同公式，各自 bg/border 对应混 white（亮）或混 bg（暗）
- **链接色**：与 primary 一致

### 主题切换

- 切换路径：`AppHandle::set_theme(Theme)` → 逐窗 `WindowDriver` 标记 palette-only dirty
- **palette-only repaint**：仅使用语义色 / 令牌色的节点参与重绘；使用固定 `Color::from_rgb()` 的节点不重绘
- `DesignTokens` 为纯数据 struct（`Clone`），`DynTokens` 以 `Arc` 共享
- 系统主题跟随：`App.follow_system_theme(true)` 为 opt-in；仅在 display 发出变化信号时更新，不轮询
- 自定义主题：`from_primitives`（覆盖 8 基色）/ `from_primaries`（传入 12 个主色种子，仅 Blue 进入品牌令牌）/ `with_brand_primary`（只换品牌色）
- 自定义 `Color` 使用 8-bit RGBA；`hex` 接受 6 位 RGB / 8 位 RGBA，`with_alpha` 替换 8-bit alpha，不混入第二套浮点通道语义

### 色板边界

- `PrimaryHue::palette()` 返回静态 `ColorScale`；0 最浅、9 最深、5 为主色，`shade()` 越界返回 `None`
- `generate_color_scale()` 以 HSV 阶梯从任意 RGB 种子生成同结构色板；alpha 不参与推导，输出不透明
- `NEUTRAL_PALETTE` 是显式 13 阶选色色板；`DesignTokens` 的文字、背景、填充与边框仍从 bg / text / border 动态推导
- `DesignTokens::functional_color_scale()` 从当前实例的 success / warning / error / info 种子按需生成，故主题覆写后保持一致
- `DATA_VISUALIZATION_PALETTE` 是固定 10 色离散分类顺序，不参与主题切换与 palette-only 重绘
- 色板值是纯 `Color` 数据；访问或生成不登记帧、timer、线程或窗口工作

## 附：大模型控制协议

<a id="大模型控制协议"></a>

产品附能力（开发预览），不改变主路径应用写法。协议名 `uix.agent.v1`。用法 → [`使用指南 · Agent Bridge`](使用指南/Agent%20Bridge.md#agent-bridge-开发预览)；缺口 → [`进度`](进度.md#其他活跃差距)。

### 边界与组成

- 显式启用（`agent-control` feature + `.enable_agent_control()`）、仅限本机同一 OS 用户的进程级端点。不是 TCP、跨机器远控、UIA/读屏桥；不提供 shell、文件或网络访问。
- 三层：语义树、动作执行器、传输。`TestApp` 与真窗 Bridge 共用前两层；传输差异不得进入组件。
- 内置组件自动提供语义与动作；自定义复用 `AccessibilityRole`/`AccessibilityState`。v1 不负责截图或 GPU readback。

### 发现与安全

- Discovery：Windows `%LOCALAPPDATA%\uix-agent`；Linux/macOS `$XDG_RUNTIME_DIR/uix-agent-<uid>`。描述文件含 pid、endpoint、随机 token；端点成功后原子公布，退出删除。
- 传输：Windows Named Pipe（受保护 DACL 只授权当前进程 `TokenUser` SID）；Linux/macOS UDS（目录 `0700`，accept 后核 peer effective uid），其他 Unix 无可靠 peer credential API 时 fail-closed。不监听 TCP/UDP。Wire：UTF-8 JSON Lines，单条 ≤ 4 MiB。
- 首条必须带 token 的 `hello`；连接内串行，并发用多连接（≤ 8）。同窗动作容量 64 FIFO。

### 语义与动作

- 快照含 `window_id`、generation、`revision`、`presented_revision`、节点树。节点含 opaque `node_id`、可选 `automation_id`、role、state、bounds、actions。
- `node_id` 仅同 generation 有效；跨启动定位用 `automation_id`。password/sensitive value 永不出现在快照、响应或日志。
- 动作经目标 `WindowSession` 正常 semantic/`SystemEvent` 路径；禁 IPC 线程直接改 Widget/State/绘制树。窗口动作 `press_key`、`click_at`、`pointer_move`、`pointer_down`、`pointer_up` 只合成既有 `SystemEvent`，不调用 OS 输入注入；拆分的指针按下/释放只表达左键，客户端负责成对结束手势。
- 动作后 State → Effect → reconcile → 最多 32 settle 轮次。视觉证据用 `wait` 等到 `presented_revision >= revision`；不可呈现 → typed `not_presentable`。
- 逐组件视觉 gate 由 Demo 隔离库存驱动：公开导出/组件声明与库存精确相等，每项必须有非零语义目标、浅色桌面、深色紧凑及适用状态证据。单体 focus 状态必须来自语义 `focus`；公开构建器只能以其可见子树内真实可聚焦节点证明，禁回退为点击。open/scroll/change/focus-trap 等交互必须经过动作、settle、真实 present 与独立截图，再由 CSV 和联系表汇总。

### 错误与资源

- typed error 覆盖 unauthorized/window_not_found/stale_window/node_not_found/unsupported_action/timeout 等。
- 上限：消息 4 MiB、文本 64 KiB、连接 8、每窗队列 64、settle 32、wait 30 s。
- 除 transport worker 外无轮询线程；无客户端时主循环 DeepIdle。审计只记结果码与耗时；token/输入文本/password 不记录。
