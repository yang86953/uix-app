# 使用

> 怎样用 UIX 写应用（不必关心框架内部）。

入口：`use uix::prelude::*`。可复制示例 → [README](../README.md#示例)；能力展示 → [`demo`](../demo/README.md)。导出一览 → [`prelude.rs`](../src/prelude.rs)。

## 窗口与状态

```rust
let count = State::new(0);
App::new()
    .title("UIX Counter")
    .size(420, 260)
    .root(move || {
        column((
            count.map_text(|n| format!("当前值: {n}")).font_size(24.0),
            button("+1").primary().on_click(&count, |c| c.update(|v| *v += 1)),
        ))
        .gap(12.0)
        .padding(16.0)
    })
    .run();
```

- 状态：`set` / `update`；点击：`on_click(&state, …)` 或 `on_click_fn`
- 文本：`label` / `map_text`；条件：`show` / `Option`
- 布局：`column`（填满）/ `column_fit`（撑开）；子节点用元组或 `views!`
- 样式：先语义（`.primary()`）再 `.padding` / `.gap` / `.bg`；自定义：`component!`
- 自定义绘制：`render => (&self, frame: Rect, ctx: &mut PaintContext) { … }`；内部 tree 参数由宏注入，应用不导入 runtime 类型

只描述 View + State；重绘与活动任务由框架处理。

## 常用写法

| 需求 | 写法 |
|------|------|
| 文本输入 | `input().placeholder("…")` 或 `Input::new`；单行/多行均走系统 IME（composition→commit 框架托管） |
| 语义事件 | `.on_semantic(SemanticKind::Click, \|ev\| …)`（点击也可用 `on_click`） |
| 主题 | `.theme(Theme::antd_light())`（默认 light）；`.follow_system_theme(true)`；运行中 `set_theme` / `ThemeToggle`（全应用） |
| 浮层 | 用 `Modal` / `Drawer` / `Message` / `Notification` 等组件；`OverlayStack` 由框架维护，应用勿手管 z-order 名单 |
| 结果页 | `ResultView::new(ResultType::Success).title("…")`（命名避免与 `std::result::Result` 冲突） |
| 动画 | `Animation::new(from, to, secs)` 做插值；组件动画由框架按本窗显示帧机会推进，窗口不可呈现时自动暂停并在恢复首帧重基时钟；勿用 `run_interval` 模拟帧时钟 |
| 多窗 | `handle.open_window(WindowConfig::new(…))`（`on_start` 等处取 `AppHandle`） |
| 定时 | 业务延时 / 周期任务用 `run_after` / `run_interval` → `TimerHandle`（drop 取消；需存活则 `detach`）；不用于驱动逐帧动画 |
| 跨线程回 UI | 只走 `post_to_ui`；`AppHandle` 上定时 / `post_to_ui` 绑**该窗** |
| 无障碍 v1 | 组件自带静态 ARIA；自定义组件填 `AccessibilityRole` / `AccessibilityState`；`Tab` / `Shift+Tab` 按可见焦点顺序前后循环，浮层内受 focus trap 约束；**无读屏桥** |
| Settings | 默认不读盘；`.settings("app.settings.json")` 后 `handle.resolve::<uix::data::SettingsService>()` |
| 图形 | 默认 Vulkan；可选 `.graphics_backend(…)`。失败 → **typed** 诊断后 Software/CPU；禁静默换 GPU API；仅显式 `Auto` 跨 API → [架构 · 图形](架构.md#图形-api与帧提交硬约束) |
| CLI | `.mode(AppMode::CLI)`（可选） |

## 表单、表格与虚拟列表回调

`Form` 规则只保存稳定 validator key，闭包放在应用持有的表中；引用未登记 key 会返回 `FormValidationError::MissingValidator`，不会静默跳过：

```rust
let mut validators = FormValidatorTable::new();
validators.register("username", |value| {
    (value == "ada").then_some(()).ok_or_else(|| "用户不存在".to_string())
});

let mut form = Form::new().with_field(
    FieldDef::new("user", "用户名")
        .value("ada")
        .rule(ValidationRule::required("必填"))
        .rule(ValidationRule::custom("username")),
);
let valid = form.validate(&validators).expect("validator key 已登记");
```

`Table::expandable(height, renderer)` 返回可直接放进 View / `tree!` 的 `TableBuilder`。renderer 由框架按组件 identity 登记，reconcile、节点移除或 root 重建时自动替换 / 释放；应用不维护 renderer 表：

```rust
Table::new()
    .columns(vec![TableColumn::new("姓名", 160.0)])
    .rows(vec![vec!["Ada".into()]])
    .expandable(48.0, |row, ctx, rect| {
        let color = ctx.tokens().color_text();
        ctx.draw_text(&format!("第 {row} 行"), Point::new(rect.x + 8.0, rect.y + 8.0), color, 12.0);
    })
```

`VirtualScroll::renderer` 同样返回可直接放进 View / `tree!` 的 builder；子项 factory 由框架逐组件持有，滚动窗口变化时只重建可见子项：

```rust
use uix::ui::foundation::VirtualScroll;

VirtualScroll::new()
    .item_count(10_000)
    .item_height(32.0)
    .size(320.0, 480.0)
    .renderer(|index| Label::new(format!("row-{index}")).into_node())
```

## 自动化测试

给需要稳定操作的节点加 selector；它不改变 View identity：

```rust
let count = State::new(0);
let root_count = count.clone();
let mut app = uix::ui::test_harness::TestApp::new((420.0, 260.0), move || {
    let count = root_count.clone();
    button("+1")
        .primary()
        .on_click(&count, |count| count.update(|value| *value += 1))
        .automation_id("counter.increment")
});

app.invoke("counter.increment").unwrap();
assert_eq!(count.get(), 1);
```

测试启用 `test-harness` feature。`TestApp::perform` 接受 selector 或当前快照的 `node_id`，语义动作包含 `invoke` / `focus` / `set_value` / `insert_text` / `select` / `toggle` / `increment` / `decrement` / `scroll`；`snapshot` 的每个节点只声明实际支持的 `actions`，并携带 generation / revision / `presented_revision` 元数据。便利方法与 `click` / `type_text` / `press_key` / `resize` / `settle` 同样走框架 semantic / `SystemEvent`、visible / enabled 与 modal 约束；重复 selector、未声明动作或不可交互分别返回 typed `ambiguous_target`、`unsupported_action`、`not_interactable` / `blocked`。文本动作的 Debug 和错误不回显 payload。

`Radio`、`Segmented` 与单选 `Select` 的节点另带 `selection`：`options`、`selected_indices`、`disabled_indices`、`multiple`、`expanded`。索引从 `0` 开始；测试可调用 `app.select("period", 2)`。多选 `Select` 仍公开状态，但不声明单值 `select`；越界 / 非十进制索引返回 `invalid_value`，禁用选项返回 `not_interactable`。

需要 app 控制真实窗口时，在启动前设置快照目录：

```powershell
$env:UIX_AUTOMATION_DIR = "$PWD\target\uix-automation"
cargo run --features test-harness --bin uix-demo
```

框架按现有事件 / 帧更新 `uix-<pid>-window-<WindowId>.json`；`revision` 只在共享语义 / 布局快照变化时递增，`presented_revision` 只在成功 present 后推进，失败帧不推进。`visible_bounds` 是窗口客户区 logical 坐标，包含滚动与裁剪结果。控制端据此定位并用系统鼠标 / 键盘操作，再读取 role / name / focused / state 断言；password value 不写入快照。空闲时不轮询、不新增 wake。

## Agent Bridge（开发预览）

应用须同时在依赖中启用 `agent-control` feature，并在 GUI builder 上显式调用运行时开关：

```rust
App::new()
    .enable_agent_control()
    .root(|| app_view())
    .run();
```

开关在首个 GUI 原生窗口与图形引擎创建成功后启动本机端点；未启用时不登记 Bridge 窗口，也不创建端点、线程、描述文件或额外 wake。Windows 描述文件位于 `%LOCALAPPDATA%\uix-agent\uix-<pid>.json`，Linux / macOS 位于 `$XDG_RUNTIME_DIR/uix-agent-<uid>/uix-<pid>.json`（无 `XDG_RUNTIME_DIR` 时使用系统临时目录）。描述文件给出 `uix.agent.v1`、进程号、Named Pipe / Unix Domain Socket endpoint 与本次进程的随机 token；目录、描述文件和 endpoint 均限制为当前 OS 用户，token 应视为敏感值。

端点使用 UTF-8 JSON Lines。每条消息以换行结束，连接首条消息必须认证；之后可按连接内顺序调用 `list_windows`、`snapshot`、`perform` 与 `wait`：

```json
{"schema":"uix.agent.v1","request_id":"hello-1","type":"hello","token":"<descriptor token>"}
{"schema":"uix.agent.v1","request_id":"list-1","type":"list_windows"}
{"schema":"uix.agent.v1","request_id":"snapshot-1","type":"snapshot","window_id":1}
{"schema":"uix.agent.v1","request_id":"invoke-1","type":"perform","window_id":1,"generation":1,"expected_revision":4,"target":{"automation_id":"counter.increment"},"action":{"kind":"invoke"}}
{"schema":"uix.agent.v1","request_id":"select-1","type":"perform","window_id":1,"generation":1,"target":{"automation_id":"period"},"action":{"kind":"select","value":"2"}}
{"schema":"uix.agent.v1","request_id":"key-1","type":"perform","window_id":1,"generation":1,"action":{"kind":"press_key","key":"enter","modifiers":[]}}
{"schema":"uix.agent.v1","request_id":"click-1","type":"perform","window_id":1,"generation":1,"action":{"kind":"click_at","x":120.0,"y":48.0}}
```

`hello` 成功响应会列出 request types、语义 / 窗口动作、可用 key names / modifiers 与主要硬上限。节点语义动作必须带只含 `automation_id` 或 `node_id` 之一的 target；`select.value` 是零基十进制索引字符串。窗口级 `press_key` / `click_at` 不带 target，分别发往当前焦点和 logical client 坐标的真实 hit-test。低层动作仍走目标窗正常 `SystemEvent`、FIFO 与 bounded settle，不绕过 visible / enabled / modal 约束；成功表示输入已派发并 settle，是否产生业务效果须再读 snapshot 或 wait。

单条消息上限 4 MiB，文本动作 payload 上限 64 KiB，单进程最多同时接纳 8 个连接；一个连接串行处理消息，需要并发时使用多个连接。`wait` 按目标窗 generation 等待 revision 变化、指定 revision 呈现或窗口关闭，最长 30 秒，不轮询或唤醒 UI。应用正常退出会关闭连接并移除描述文件；控制端不得记录或转发 token、文本动作 payload 与 sensitive / password value。该接口仍是开发预览，真窗端到端与跨用户拒绝证据见 [`AGENT-R1`](进度.md#未关闭)。

## 不必做

不维护重绘名单；不申请 redraw / vsync；不手写探活定时器；不碰内部 registry / `OverlayStack` 调度；不为各桌面 OS 写两套上层 UI。现为 Rust API，无独立 UI 脚本语言。
