# 使用

> 怎样用 UIX 写应用（不必关心框架内部）。

入口：`use uix::prelude::*`。可复制示例 → [README](../README.md#示例)；能力展示 → [`demo`](../demo/README.md)。导出一览 → [`prelude.rs`](../src/prelude.rs)。

> ⚠️ **当前阶段：Windows P6 gate 未闭合。** 下方为框架目标写法；标注 ⚠️ 的能力仍在验证中。稳定：View + State + 组件声明式写法、布局、主题、多窗、定时器、`test-harness` 自动化测试。验证中：默认 Vulkan 图形路径、微软拼音 IME（[RISK-001](进度.md)）、遮挡停帧（[RUNTIME-R2](进度.md)）。详见[进度](进度.md)。

## 窗口与状态

```rust
let count = State::new(0);
App::new()
    .title("UIX Counter")
    .size(420, 260)
    .root(move || {
        column((
            count.map_text(|n| format!("当前值: {n}")).font_size(24.0),
            button("+1").primary().on_click(&count, |c| c.update(|v| *v += 1)),
        ))
        .gap(12.0)
        .padding(16.0)
    })
    .run();
```

- 状态：`set` / `update`；派生状态 `Computed<T>`（自动追踪依赖，惰性求值）；副作用 `Effect`（依赖变化时执行）
- 点击：`on_click(&state, …)` 或 `on_click_fn`
- 文本：`label` / `map_text` / `dynamic_label(fn)`（`label(closure)` 兼容别名）；条件：`show` / `Option`
- 布局：`column`（填满）/ `column_fit`（撑开）；子节点用元组或 `views!` 宏：
  ```rust
  views! { label("A"), label("B"), label("C") }
  ```
- 样式：先语义（`.primary()`）再 `.padding` / `.gap` / `.bg`；自定义：`component!`
- 自定义绘制：`render => (&self, frame: Rect, ctx: &mut PaintContext) { … }`；内部 tree 参数由宏注入，应用不导入 runtime 类型

### 自定义组件

#### 简单组合：用函数或闭包

对于只组合现有组件的场景，直接在 `root` 中写闭包或抽取函数即可，无需 `component!`：

```rust
fn counter_view(count: &State<usize>) -> impl View {
    column((
        count.map_text(|n| format!("计数: {n}")).font_size(20.0),
        button("+").primary().on_click(count, |c| c.update(|v| *v += 1)),
    ))
    .gap(8.0)
    .padding(12.0)
}
```

#### `component!`：自定义绘制与事件

需要自定义 `measure` / `render` / `on_event` 时用 `component!`。宏内方法用 `=>` 箭头语法：

```rust
use uix::prelude::*;

component! {
    /// 一个自定义绘制的色块组件。
    pub struct ColorBlock {
        color: Color,
        size: f32,
    }

    measure => (&self, constraints: Constraints) -> Size {
        constraints.clamp(Size::new(self.size, self.size))
    }

    render => (&self, frame: Rect, ctx: &mut PaintContext, _tree: &WidgetTree) {
        ctx.fill_rect(frame, &self.color, Radius::zero());
    }
}

// 使用
App::new()
    .root(move || ColorBlock { color: Color::RED, size: 48.0 })
    .run();
```

`component!` 自动生成 `WidgetComponent` trait 实现与 reconciliation 逻辑。应用只需定义 struct 字段和方法（`measure` / `render` / `build` / `on_event` 等）。

含子节点的组件用 `build =>` 返回 `Vec<Box<dyn WidgetComponent>>`：

```rust
component! {
    pub struct MyContainer {
        children: WidgetChildren,
    }

    build => (&self) -> Vec<Box<dyn WidgetComponent>> {
        self.children.take()
    }

    render => (&self, frame: Rect, ctx: &mut PaintContext, _tree: &WidgetTree) {
        ctx.fill_rect(frame, &Color::rgba(240, 240, 240, 255), Radius::new(8.0));
    }
}
```

只描述 View + State；重绘与活动任务由框架处理。空闲时框架阻塞等待，勿手写探活。`run_interval` 与动画是显式成本；高频 `State` 写入仍推高本窗帧率（框架合并为至多一个 outstanding frame request，不自动节流）。

## 常用写法

| 需求 | 写法 |
|------|------|
| 文本输入 | `input().placeholder("…")` 或 `Input::new`；多行用 `Input` 的 `textarea` 模式。⚠️ 微软拼音真机验证未过（[RISK-001](进度.md)），框架托管就绪 |
| 语义事件 | `.on_semantic(SemanticKind::Click, \|ev\| …)`（点击也可用 `on_click`） |
| 主题 | `.theme(Theme::antd_light())`（默认）；`.follow_system_theme(true)`；`set_theme` / `ThemeToggle`；自定义色板 `DesignTokens::from_primaries([Color; 12], is_dark)` |
| 浮层 | `Modal` / `Drawer` / `Message` / `Notification` 等组件；框架维护 `OverlayStack`，应用勿手管 |
| 结果页 | `ResultView::new(ResultType::Success).title("…")`（命名避免与 `std::result::Result` 冲突） |
| 动画 | `Animation::new(from, to, secs)` 做插值；框架自动推进，窗口不可呈现时暂停、恢复首帧重基；勿用 `run_interval` 模拟帧时钟 |
| 多窗 | `handle.open_window(WindowConfig::new(…))`（`on_start` 等处取 `AppHandle`） |
| 定时 | 业务延时 / 周期任务用 `run_after` / `run_interval` → `TimerHandle`（drop 取消；需存活则 `detach`）；不用于驱动逐帧动画 |
| 跨线程回 UI | 只走 `post_to_ui`；`AppHandle` 上定时 / `post_to_ui` 绑**该窗** |
| 无障碍 v1 | 组件自带静态 ARIA；自定义填 `AccessibilityRole`/`AccessibilityState`；`Tab`/`Shift+Tab` 焦点循环，浮层内 focus trap；无读屏桥 |
| Settings | 默认不读盘；`.settings("app.settings.json")` 后 `handle.resolve::<SettingsService>()` |
| 图形 | 默认 Vulkan；可选 `.graphics_backend(…)`。失败 typed 诊断后 Software/CPU；禁静默换 GPU API；仅 `Auto` 跨 API → [架构](架构.md#图形-api与帧提交硬约束) |
| CLI | `.mode(AppMode::CLI)`（可选） |

## 表单、表格与虚拟列表

`Form` 自定义规则只存稳定 validator key，闭包放在应用持有的 `FormValidatorTable`；未登记 key → `FormValidationError::MissingValidator`，不静默跳过：

```rust
let mut validators = FormValidatorTable::new();
validators.register("username", |value| {
    (value == "ada").then_some(()).ok_or_else(|| "用户不存在".to_string())
});

let mut form = Form::new().with_field(
    FieldDef::new("user", "用户名")
        .value("ada")
        .rule(ValidationRule::required("必填"))
        .rule(ValidationRule::custom("username")),
);
let valid = form.validate(&validators).expect("validator key 已登记");
```

`Table::expandable` / `VirtualScroll::renderer` 返回可直接放进 View 的 builder；renderer / factory 由框架按组件 identity 登记并在 reconcile / 移除 / root 重建时清理，应用不维护表：

```rust
Table::new()
    .columns(vec![TableColumn::new("姓名", 160.0)])
    .rows(vec![vec!["Ada".into()]])
    .expandable(48.0, |row, ctx, rect| {
        let color = ctx.tokens().color_text();
        ctx.draw_text(&format!("第 {row} 行"), Point::new(rect.x + 8.0, rect.y + 8.0), color, 12.0);
    })
```

```rust
use uix::ui::foundation::VirtualScroll;

VirtualScroll::new()
    .item_count(10_000)
    .item_height(32.0)
    .size(320.0, 480.0)
    .renderer(|index| Label::new(format!("row-{index}")).into_node())
```

## 不必做

不申请 redraw/vsync；不手写探活定时器；不直接操作框架内部 registry/OverlayStack（框架自动维护）；不为各桌面 OS 写两套上层 UI。现为 Rust API，无独立 UI 脚本语言。

## 附：自动化测试

给需要稳定操作的节点加 `.automation_id`（不改变 View identity）。启用 `test-harness`：

```rust
let count = State::new(0);
let root_count = count.clone();
let mut app = uix::ui::test_harness::TestApp::new((420.0, 260.0), move || {
    let count = root_count.clone();
    button("+1")
        .primary()
        .on_click(&count, |count| count.update(|value| *value += 1))
        .automation_id("counter.increment")
});

app.invoke("counter.increment").unwrap();
assert_eq!(count.get(), 1);
```

`perform`/`click`/`type_text`/`press_key`/`select` 走真实 semantic/`SystemEvent` 与可见性/modal 约束；文本不回显。真窗设 `UIX_AUTOMATION_DIR` 写逐窗 JSON 快照（`revision`/`presented_revision`）；空闲不轮询。细节 → [架构](架构.md#自动化测试)。
