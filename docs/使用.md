## 权威范围

本文及 `使用/` 下的专题文档共同持有 UIX 的当前公开用法。所有可编译 Rust 示例都携带全局唯一的 `uix-compile=<id>` 标识；依赖 opt-in feature 时同时标注 `uix-feature=<Cargo feature>`。示例只使用当前已落地的公开 API；概念性伪代码必须显式标为伪代码，尚未交付的目标写法不进入使用文档。

## 应用组成与复用边界

UIX 复用的是完整应用，而不只是界面。应用业务规则、领域状态、服务、异步流程、导航编排和生命周期由 Rust 持有；UIX 提供统一的 App、窗口、事件循环、平台、数据与运行保障契约，使这些应用逻辑与同一套界面在已交付平台间复用。界面描述支持两种方式（产品方向声明见[定位与原则](产品/定位与原则.md#定位)）：

- **推荐**：用 [uix-lang](uix-lang/README.md)（`.uix` 文档）描述界面，编译时自动转换为 Rust。
- **支持**：Rust 声明式 API 直接书写界面——uix-lang 已登记能力映射到相同的 Rust 语义；未登记能力继续通过 Rust API 使用。

公开 `uix!` 生成已登记 `ViewNode`，`uix_app!` 把 `<App>` 根文档组装成现有 `App` builder；Rust 组合根继续持有最终 `.run()`、业务接线与窗口生命周期，也是 uix-lang 的底层表示。平台专属能力必须通过显式 capability 消费，不能把平台分支当作普通应用逻辑的默认组织方式。可编译的 uix-lang 子集见 [uix-lang 快速开始](uix-lang/指南/快速开始.md#当前可编译的第一个-view)。

## 使用原则

使用文档按 UIX 产品定义（见[定位与原则](产品/定位与原则.md)）给出**推荐用法**：

- **资源优先**——示例展示空闲休眠、按需绘制、不浪费内存的写法；框架自动托管的部分（见[不必做](使用/能力与边界/不必做.md)）不手工干预。
- **Rust 优先**——类型系统在编译期保证正确性；状态、事件与校验以类型化方式表达，不用字符串拼装。
- **原生优先**——上层代码不感知平台差异；平台能力通过统一入口消费，不散落平台 ifdef。
- **容错可观测**——失败以 typed `Error` 表达，恢复有路径，崩溃有报告（见[运行保障](使用/框架设施/运行保障.md)）。
- **使用方按需编译**——非传递必需的能力通过显式 Cargo feature 选择；运行时关闭不能替代编译期裁剪。

每篇专题先声明依赖与权威范围，再给出当前可用的行为、示例和限制：

| 写法 | 含义 |
|------|------|
| `rust uix-compile=<id>` | 已落地示例，只使用公开 API，由外部 consumer 持续编译 |
| `rust uix-compile=<id> uix-feature=<feature>` | 同上，且示例依赖显式启用的 opt-in Cargo feature 才能编译 |
| 非 Rust 围栏（`uix` / `toml` / `bash` / `text`） | UIX Lang 示例、依赖清单、命令行或纯说明文本；概念性伪代码显式标为伪代码，不进入编译覆盖 |
