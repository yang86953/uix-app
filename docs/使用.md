## 权威范围

本文档及 `使用/` 子目录下的文档组件共同构成 UIX 的公开用法真相。所有 Rust fence 示例携带全局唯一 `uix-compile=<id>` 标识，依赖 opt-in feature 时附加 `uix-feature=<Cargo feature>`。示例只使用当前已落地的公开 API；尚未交付的目标写法由 [Vikunja 项目 4](https://yang-server.tail9d5559.ts.net:3456/projects/4) 跟踪。

## 使用方式

界面描述支持两种方式（产品方向声明见[定位与原则](产品/定位与原则.md#定位)）：

- **推荐**：用 [uix-lang](uix-lang/README.md)（`.uix` 文档）描述界面，编译时自动转换为 Rust。
- **支持**：Rust 声明式 API 直接书写界面——两种方式语义一一对应，按项目情况选择。

公开 `uix!` 已是已登记 View 子集的可用编译期入口；本目录的 Rust 示例继续作为完整应用 / 窗口生命周期和尚未登记能力的当前入口，也是 uix-lang 的底层表示。可编译的 uix-lang 子集见 [uix-lang 快速开始](uix-lang/指南/快速开始.md#当前可编译的第一个-view)。

## 使用原则

使用文档按 UIX 产品定义（见[定位与原则](产品/定位与原则.md)）给出**理想使用方式**：

- **资源优先**——示例展示空闲休眠、按需绘制、不浪费内存的写法；框架自动托管的部分（见[不必做](使用/不必做.md)）不手工干预。
- **Rust 优先**——类型系统在编译期保证正确性；状态、事件与校验以类型化方式表达，不用字符串拼装。
- **原生优先**——上层代码不感知平台差异；平台能力通过统一入口消费，不散落平台 ifdef。
- **容错可观测**——失败以 typed `Error` 表达，恢复有路径，崩溃有报告（见[运行保障](使用/运行保障.md)）。

每个文档组件先给「接口」声明，再给当前可用的用法：

| 写法 | 含义 |
|------|------|
| `rust uix-compile=<id>` | 已落地示例，只使用公开 API，由外部 consumer 持续编译 |
