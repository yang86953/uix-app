# UIX Lang 语言完善计划

[← 返回 UIX Lang 索引](../README.md)

> **状态**：目标设计 / 实施计划。本文冻结 UIX Lang 的目标架构、渐进实施顺序、风险门禁与完成标准，不表示目标语法已经全部实现。当前可用能力仍以各规范章节的状态标记和[语言首页](../README.md#状态声明)为准。

## 1. 当前基线

UIX Lang 当前由 `uix-derive` 过程宏在编译期读取 `.uix`，完成递归导入、解析、局部语义检查和 Rust 代码生成，再把生成文件交给 Cargo 编译。正式产物不携带解析器或解释器。

当前已经实现：

- 内置与自定义组件、属性、事件、Slot、If / For 与样式主题；
- Widget 的字符串 `props`、`state`、`computed`、`external` 和同步 `actions`；
- 无参数同步 action 的单表达式与 `do` 多语句主体；
- Record、类型化状态、组件导入导出、生成文件与源码位置诊断；
- `uix!`、`uix_app!`、`uix_items!` 三个 AOT 宏入口。

当前主要缺口是：语言前端和 AOT 生成仍耦合在过程宏内，表达式类型与 Rust 调用点耦合，缺少统一 Typed IR、完整类型 / Effect 检查、类型化服务、异步 action、应用级流程，以及与 AOT 同源的动态开发后端。

## 2. 目标与边界

UIX Lang 最终负责普通应用的界面、状态、业务判断、用户 action、异步服务编排、结果处理、导航、窗口流程、反馈和生命周期。Rust 只负责框架实现、复杂算法、服务与平台适配，以及选择、注入、启动和关闭的薄组合根。

正式构建继续把 UIX Lang AOT 转换为确定的 Rust：

- 不携带生产解释器、虚拟机、垃圾回收器或运行时源码；
- 不使用字符串服务定位、未类型化状态字典或自动动态回退；
- 服务、函数、路由、窗口和组件能力在编译期解析并检查；
- 动态开发能力必须显式启用且不改变正式构建结果。

当前非目标：生产动态页面、远程业务脚本、插件沙箱、系统编程、线程、执行器控制、文件句柄、原生窗口句柄、渲染资源与平台私有对象语言化。

## 3. 目标架构

唯一语言流水线为：

```text
源码与导入图
  → 词法 / 语法 AST
  → 名称解析
  → 类型与 Effect 检查
  → 后端无关 Typed IR
  ├─ AOT：生成 Rust
  ├─ Dev：动态加载与热重载
  └─ Tooling：check / fmt / LSP
```

按 SMC 划分责任：

- **UIX Lang Compiler System**：拥有源码图、语法、类型、名称、诊断、组件 schema 和 Typed IR；物理实现目标为普通库 `uix-lang-core`。
- **AOT Adapter**：`uix-derive` 只拥有公开过程宏入口、调用 crate 环境适配和 Rust 生成，不另行定义语言语义。
- **Application System**：拥有 action 任务、取消、超时、路由、窗口、反馈与生命周期；语言只能调用其公开窄端口。
- **外部服务 System**：拥有网络、数据库、文件和平台资源；UIX Lang 只依赖声明的 Function / Service 契约，不取得实现对象的私有能力。

组件标签、属性、事件、类型、Cargo capability 和诊断名称集中到一份 schema。AOT、动态后端、参考文档与工具链消费同一事实源，禁止各自维护近似登记表。

## 4. 语言能力路线

目标语法由[语法](../规范/语法.md)持有；表达式、组件、控制流、模块与编译模式的详细语义分别由对应规范持有。主要交付为：

1. 结构化 Record / Enum / Widget 成员，公共边界显式类型；
2. 通用 `TypeRef`、名称解析、局部推断与渲染纯度 / Effect 检查；
3. 参数化 Action、`match`、Action 内 `for`、返回类型与穷尽性检查；
4. 编译期绑定的 Function / Service、async action、取消、超时和并发策略；
5. App state、静态路由、具名窗口、反馈和生命周期 action；
6. 与 AOT 同源的动态后端、状态迁移、热重载和开发诊断；
7. 共享前端上的 `check`、`fmt` 与最小 LSP。

## 5. 渐进实施顺序

| 阶段 | 交付 | 门禁 |
|---|---|---|
| 1 | 等价抽出共享前端 | 现有语法、宏返回值与生成行为不变 |
| 2 | 通用类型 AST、名称解析、Typed IR 和统一诊断 | 现有 fixture 全部经新前端产生等价结果 |
| 3 | 结构化 Action / Service；旧字符串 action 降低到同一 AST | 不保留第二套 action 语义与生成路径 |
| 4 | 类型化服务、async action、取消、超时与真实应用闭环 | AOT 先通过，TODO 应用不再由 Rust 编排业务分支 |
| 5 | App state、路由、多窗口、反馈和生命周期 | 每个 Application 窄端口具有所有权、失败和关闭契约 |
| 6 | 动态后端、热重载与状态迁移 | 与 AOT 共用 Typed IR 和语义测试；正式 feature 不含动态依赖 |
| 7 | 迁移 props / state / computed、替代任意 `external`，完善 fmt / LSP | 迁移完成后删除旧解析实现，只保留定向诊断 |

每一阶段只在对应语法、诊断、AOT 生成和真实消费者证据闭合后更新“已实现”状态。动态后端不得先于对应 AOT 语义存在。

## 6. 风险门禁

- **避免一次性重写**：共享前端先做等价抽取，再逐步改变语言表面；不得同时重写解析、类型、运行时和动态后端。
- **避免双重语义**：迁移语法可以并存，但必须立即降低到同一 AST / Typed IR，不复制名称解析和 codegen。
- **避免 Rust 泄漏**：新增业务能力必须通过显式类型契约；`external` 仅作为迁移入口，不继续扩张。
- **避免动态污染 AOT**：正式宏入口不得因解析失败或缺少 capability 自动退化为动态执行。
- **避免状态误迁移**：热重载只在组件身份、业务 key、state 名称与类型兼容时保留值；不兼容时局部重置并报告。
- **避免完成度失真**：没有真实应用闭环，不以语法节点数量或单元测试数量宣称语言完成。

## 7. 测试与验收

- 解析与类型测试覆盖全部声明、作用域、泛型、模式、Effect 和 SourceSpan；
- compile-pass / compile-fail 测试覆盖未知名称、类型错误、非穷尽 `match`、非法 `await`、递归 action、服务签名与 capability 门禁；
- 确定性任务测试覆盖 `drop` / `restart` / `parallel`、顺序、取消、超时、卸载、关窗与退出；
- 模块测试覆盖导入闭包、可见性、循环、同名冲突和增量失效；
- AOT 与动态后端对同一 Typed IR 产生等价 View、状态、action 结果与诊断；
- 热重载覆盖有效更新、错误源码回退、兼容状态保留、不兼容状态重置和契约变化拒绝；
- TODO 应用完成加载、CRUD、持久化、失败、取消、超时、路由、设置窗口和反馈，Rust 入口不含业务条件分支；
- 主演示的普通业务编排迁入 `.uix`，图形故障注入、测试控制面和服务实现继续留在 Rust；
- 未启用开发 feature 时，依赖与产物中不存在动态值、解释器、文件监视、运行时源码和服务字符串分发表。

## 8. 完成定义

UIX Lang 只有同时满足以下条件才视为完成：目标语法全部登记并实现；AOT 可独立交付；动态模式与 AOT 同源；普通应用只保留薄 Rust 组合根；当前规范、参考、指南、生成 schema 和工具链对同一语言事实一致。
