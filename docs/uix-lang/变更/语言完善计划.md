# UIX Lang 语言完善计划

[← 返回 UIX Lang 索引](../README.md)

> **状态**：实施计划。本文只规划 UI 描述语言及其编译工具链，不规划业务流程语言能力；职责边界以[UI 描述语言边界](应用开发语言目标.md)为准。

## 1. 当前基线

UIX Lang 当前由 `uix-derive` 在编译期读取 `.uix`，完成递归导入、解析、局部语义检查和 Rust UI 代码生成，再交给 Cargo 编译。正式产物不携带解析器或解释器。

当前已经实现：

- 内置与自定义组件、属性、事件、Slot、If / For 与样式主题；
- Widget 的 props、界面 state、computed、external 和同步 actions；
- 无参数同步 action 的单表达式与 `do` 多语句主体；
- Record 界面数据结构、组件导入导出、生成文件与源码位置诊断；
- `uix!`、`uix_app!`、`uix_items!` 三个 AOT 宏入口。

当前改进点集中在 UI schema 的单一事实源、诊断质量、类型化界面数据、增量编译、格式化与编辑器支持。类型化服务、异步 action、业务工作流、路由决策和生命周期语言化不在计划内。

## 2. 目标与边界

UIX Lang 最终仍只负责界面结构、样式、展示数据、界面状态和局部交互。Rust Application System 拥有业务契约、领域状态、服务、失败语义与生命周期；`.uix` 通过窄回调和 State / props 消费这些能力。

正式构建继续 AOT 生成确定的 Rust UI 代码：

- 不携带生产解释器、虚拟机、垃圾回收器或运行时源码；
- 不使用字符串服务定位或未类型化业务状态字典；
- 不生成网络、数据库、持久化、事务或应用工作流；
- 不因编译失败或能力缺失自动动态回退。

## 3. 编译器架构

```text
.uix 源码与导入图
  → UI 词法 / 语法 AST
  → UI 名称与 schema 检查
  → Rust View 代码生成
  └─ Tooling：check / fmt / LSP
```

按 SMC 划分责任：

- **UIX Lang Compiler System**：拥有 UI 语法、组件 schema、诊断与源码映射；
- **AOT Adapter**：`uix-derive` 适配过程宏输入、调用 crate 环境与 Rust token 生成；
- **Application System（Rust）**：拥有业务状态与流程，只向 UI 暴露公开窄契约；
- **UI Runtime System**：拥有 View、组件、布局、绘制、事件与界面状态生命周期。

组件标签、属性、事件、数据类型、Cargo capability 和诊断名称应集中到一份 schema，由 AOT、参考文档和工具链共同消费。

## 4. 能力路线

1. 抽取并统一组件、属性、事件和数据类型 schema；
2. 完善 UI 表达式、界面 state、computed 与 action 的名称和类型诊断；
3. 改善 Record 等界面数据结构及 Rust 边界映射；
4. 完善样式、主题、动画、可访问性与响应式布局描述；
5. 提供共享检查入口、格式化和最小 LSP；
6. 在不进入发布产物的前提下评估纯 UI 热重载。

同步 action 的后续工作只改善现有局部 UI 交互语义、诊断和生成质量，不扩展参数化业务 Action、Service、异步、重试、路由或生命周期能力。

## 5. 渐进实施顺序

| 阶段 | 交付 | 门禁 |
|---|---|---|
| 1 | UI schema 单一事实源 | 现有语法、宏返回值与生成行为不变 |
| 2 | 名称、类型、SourceSpan 与统一诊断 | 现有 fixture 产生等价结果，错误定位更精确 |
| 3 | UI 数据结构与 Rust 回调边界收敛 | 业务真值和业务分支仍由 Rust 持有 |
| 4 | check / fmt / 最小 LSP | 与 AOT 使用同一 UI 语法和 schema |
| 5 | 可选纯 UI 热重载 | 不包含业务执行器，不进入默认发布依赖 |

## 6. 风险门禁

- **避免职责漂移**：新增语法必须能解释为 UI 描述；业务规则或流程一律留在 Rust；
- **避免双重语义**：迁移语法必须降低到同一 UI AST 和 codegen；
- **避免动态污染 AOT**：正式宏入口不得自动退化为动态执行；
- **避免状态混淆**：界面 state 不得成为领域真值的唯一所有者；
- **避免完成度失真**：只有真实宏消费者和文档示例通过后才标记 UI 能力完成。

## 7. 测试与验收

- 解析和诊断覆盖当前 UI 声明、作用域、类型与 SourceSpan；
- compile-pass / compile-fail 覆盖未知名称、类型错误、事件字段、action 递归和 capability 门禁；
- 模块测试覆盖导入闭包、可见性、循环、同名冲突和增量失效；
- 主演示保持 `.uix` 描述 UI、Rust 持有业务与生命周期；
- 未启用开发能力时，依赖与产物中不存在解释器、文件监视或运行时源码。

## 8. 完成定义

UIX Lang 的文档、schema、AOT 生成和工具链对同一 UI 描述事实一致；业务规则、领域状态、服务和应用流程仍由 Rust 实现；新增 UI 能力均有编译诊断和真实消费者证据。
