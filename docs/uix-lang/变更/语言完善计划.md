## 1. 当前基线

UIX Lang 当前由共享 `uix-lang-compiler` Compiler System 完成递归导入、SourceGraph、无损 CST/AST、TypedUiIr、语义检查和 Rust Emitter；`uix-derive`、`uix` CLI 与 LSP 都是入口 Adapter。正式产物不携带解析器或解释器。

当前已经实现：

- 内置与自定义组件、属性、事件、Slot、If / For 与样式主题；
- Widget 的 props、界面 state、computed、external 和同步 actions；
- 无参数同步 action 的单表达式与 `do` 多语句主体；
- Record 界面数据结构、组件导入导出、生成文件与源码位置诊断；
- `uix!`、`uix_app!`、`uix_items!` 三个 AOT 宏入口。

schema v3、共享语言前端、Typed UI IR、格式化、编辑器支持、可选纯 UI 热重载 Adapter 与会话级增量阶段缓存已落地；当前改进集中在诊断质量。2026-08-27 起，组件专属值类型（CascaderValue 等）已登记进 schema 并挂接 capability 门禁；Widget 成员支持 `@props/@state/@computed/@actions` 块级形式。类型化服务、异步 action、业务工作流、路由决策和生命周期语言化不在计划内。

## 2. 目标与边界

UIX Lang 最终仍只负责界面结构、样式、展示数据、界面状态和局部交互。Rust Application System 拥有业务契约、领域状态、服务、失败语义与生命周期；`.uix` 通过窄回调和 State / props 消费这些能力。

正式构建继续 AOT 生成确定的 Rust UI 代码：

- 不携带生产解释器、虚拟机、垃圾回收器或运行时源码；
- 不使用字符串服务定位或未类型化业务状态字典；
- 不生成网络、数据库、持久化、事务或应用工作流；
- 不因编译失败或能力缺失自动动态回退。

## 3. 当前架构摘要

```text
.uix 源码与导入图
  → SourceGraph
  → Lossless CST / AST
  → 名称、schema、能力与 UI 类型检查
  → Typed UI IR
  → Rust View 代码 + SourceMap
  └─ Adapter：AOT / check / fmt / LSP
```

按 SMC 划分责任：UIX Lang Compiler System 拥有源码图、语法、UI 投影 schema、语义 IR、诊断与源码映射；`uix-derive` 只是当前 AOT Adapter；Rust Application System 持有业务状态与流程；UI Runtime System 持有 View、Widget、布局、绘制、事件和界面状态生命周期。

组件标签、属性、事件载荷、样式、数据构造、句柄位和 Cargo capability 集中到 `UiProjectionSchema`；语法规则仍由规范与共享前端持有，Widget 运行行为仍由 UI Runtime 持有。详细阶段契约、Module 依赖、缓存键和失败语义不在计划中重复定义，统一见[编译器架构](../设计/编译器架构.md)。

## 4. 能力路线

1. 抽取 `UiProjectionSchema`，统一组件、属性、事件、样式、数据类型与 capability 登记；
2. 建立稳定 SourceGraph、Lossless CST / AST 和 Typed UI IR；
3. 让名称、界面 state、computed、action 与 Record 诊断消费共享语义模型；
4. 把现有 Rust 生成收口为只消费 Typed UI IR 的 Emitter，保持宏契约不变；
5. 已提供共享 check、fmt、compile、query 和最小 LSP Adapter；
6. 已提供默认关闭的 `hot-reload` feature：外部开发工具提交 overlay，Adapter 复用完整 AOT 编译链并按 `CompilationKey` 返回新结果或无变化。

同步 action 的后续工作只改善现有局部 UI 交互语义、诊断和生成质量，不扩展参数化业务 Action、Service、异步、重试、路由或生命周期能力。

## 6. 风险门禁

- **避免职责漂移**：新增语法必须能解释为 UI 描述；业务规则或流程一律留在 Rust；
- **避免双重语义**：迁移语法必须降低到同一 UI AST 和 codegen；
- **避免事实双写**：同一登记项不得同时在 AOT、工具链和参考文档维护独立矩阵；
- **避免 IR 越界**：Typed UI IR 只解析 UI 可判定约束，不复制 Rust 类型系统或运行时 Widget 行为；
- **避免动态污染 AOT**：正式宏入口不得自动退化为动态执行；
- **避免状态混淆**：界面 state 不得成为领域真值的唯一所有者；
- **避免完成度失真**：只有真实宏消费者和文档示例通过后才标记 UI 能力完成。

## 7. 公开 API 测试

- 测试只通过公开宏、AOT、`check`、LSP 和格式化入口提交输入并观察公开输出或诊断；
- compile-pass / compile-fail 只覆盖使用方可见的未知名称、类型错误、事件字段、action 递归和 capability 门禁；
- 导入闭包、缓存、增量失效、解析阶段和 lowering 都是内部实现，不建立模块测试；
- AOT 与 `check` 对同一无效输入应给出相同稳定诊断代码和主 SourceSpan；
- 主演示和文档示例只作为公开 API 消费者编译，不测试其内部源码结构；
- 未启用开发能力时，使用方从公开构建结果中不应取得解释器、文件监视或运行时源码入口。

## 8. 完成定义

UIX Lang 的规范、`UiProjectionSchema`、Typed UI IR、AOT 生成、参考文档和工具链对同一 UI 描述事实一致；业务规则、领域状态、服务和应用流程仍由 Rust 实现；新增 UI 能力均有编译诊断和真实消费者证据。
