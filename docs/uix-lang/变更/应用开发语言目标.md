# UIX Lang 应用开发语言目标

[← 返回 UIX Lang 索引](../README.md)

> **状态**：目标设计。本文声明产品方向、能力边界和实施顺序，不表示所列语法已经实现；当前可用能力以[规范](../规范/总览.md)为准。

## 目标

UIX Lang 是普通应用的主开发语言。使用方在 `.uix` 中声明界面、状态和应用业务流程；UIX 框架负责执行生成代码、组件协调、资源生命周期和平台能力。Rust 主要用于框架实现、高级扩展、复杂算法与基础设施适配，不再与 uix-lang 并列为普通应用的主路径。

语言负责到应用业务流程为止，包括状态转换、业务判断、用户 action、异步能力编排、结果处理、导航、窗口流程和应用反馈。网络协议、数据库驱动、文件句柄、线程、执行器、绘制与平台资源的具体实现不进入语言。

## 语言能力目标

在现有声明式 UI、组件 state、computed、事件和受限表达式之上，按阶段登记：

1. 同步 `action`：具名、静态绑定的业务操作，可读取组件输入与状态并调用已登记状态操作。
2. 结构化语句：局部 `let`、赋值、`if` / `match`、提前 `return`，不把语句塞入单表达式语法。
3. 异步 `action`：`await`、成功、失败、取消与超时后的显式应用响应。
4. 类型化服务：语言只依赖服务公开签名，调用在编译期绑定；实现由 Rust 扩展提供。
5. 应用流程：导航、窗口、反馈和生命周期入口通过类型化能力调用，不使用字符串服务定位或全局动态对象。

第一阶段只实现无参数、单表达式同步 action，用来冻结声明、名称解析、事件调用和 AOT 生成契约；多语句与异步语义在该契约稳定后扩展。

## AOT 性能契约

正式构建默认把 UIX Lang 完整转换为 Rust 并交给 Cargo 编译。语言能力不得要求发布产物携带解释器、虚拟机、垃圾回收器、运行时源码解析器、字符串变量表或 `Any` 状态字典。

生成器应优先产生静态类型、直接调用和明确所有权代码，避免无条件装箱、隐式分配、隐式克隆和动态分发。这里承诺不增加语言运行时开销，不承诺消除框架组件、业务数据与异步任务自身的必要成本。

静态入口不得因编译失败或能力缺失自动退化为动态执行；未登记能力继续在编译期给出位置、原因与修复建议。

## 动态开发模式

动态解析首先服务开发期热重载，不是正式应用的默认执行方式。目标数据流为：

```text
.uix 源码 → 共享解析与类型检查 → 类型化语义模型
                                 ├─ 正式 AOT：生成 Rust
                                 └─ 开发动态：加载并热重载
```

开发动态模式必须显式启用，按内容哈希缓存解析结果，并复用静态编译器的语法、类型和诊断规则。动态成本只由启用它的开发会话承担。状态保留必须依赖稳定组件与业务 key，源码变化无法安全迁移时应给出可观察重置结果。

生产动态页面、插件和远程业务流程不属于当前 `0.0.1` 范围。未来如登记，必须作为独立 capability，声明版本兼容、签名验证、能力白名单、资源上限、取消与失败语义；不能改变正式 AOT 的默认值。

## 实施顺序

| 阶段 | 交付 | 成功标准 |
|---|---|---|
| 1 | 无参数、单表达式同步 action | 事件调用静态展开为 Rust；未知、重复、递归和非法引用在生成前诊断 |
| 2 | 多语句同步 action | 状态转换、局部值、条件与返回具有确定顺序和 Rust 映射 |
| 3 | 类型化服务与异步 action | `await`、结果、取消和错误路径都有编译及运行契约 |
| 4 | 应用级流程入口 | 普通应用的导航、窗口、反馈和生命周期不再要求 Rust 业务编排 |
| 5 | 开发期动态解析与热重载 | 与 AOT 共用语义测试；动态模式显式启用且不进入默认发布产物 |

每一阶段都先登记语法和诊断，再实现 AOT 生成与真实宏消费者测试；动态后端不得先于对应 AOT 语义存在。

## 非目标

- 不把 UIX Lang 扩展为系统编程语言或 Rust 替代品。
- 不在语言中直接暴露线程、原生句柄、渲染资源或平台私有对象。
- 不以运行时反射、字符串查找和未类型化字典换取语法便利。
- 不让开发期热重载成为生产正确性的依赖。
