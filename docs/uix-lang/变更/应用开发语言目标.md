# UIX Lang UI 描述语言边界

[← 返回 UIX Lang 索引](../README.md)

> **状态**：长期产品边界。文件名为兼容既有链接保留；本文取代此前“应用开发语言”方向。

## 目标

UIX Lang 是 UIX 的 UI 描述语言，不是应用业务语言。使用方在 `.uix` 中声明界面结构、样式、展示数据、界面状态和局部交互；Rust 实现业务规则、领域模型、服务与应用流程。

```text
Rust Application System（业务真值与流程）
        │ props / State / 类型化回调
        ▼
UIX Lang（界面描述与交互绑定）
        │ 编译期生成
        ▼
UIX Rust View API（布局、绘制与事件连接）
```

按 SMC 划分，Rust Application System 拥有业务契约、领域状态、失败语义和生命周期；UIX Lang 只描述其 UI Adapter。`.uix` 不取得服务实例、事务、执行器或跨 System 状态所有权。

## UIX Lang 负责

- 界面树、组件组合、Slot、If / For 渲染与静态应用外壳配置；
- 样式、主题、状态伪类、动画和可访问性描述；
- 文本插值、展示值派生、列表投影和只读格式化；
- 输入草稿、展开、选中、分页、弹层开关等界面状态；
- 事件与 Rust 回调的绑定；
- 只影响当前界面的同步 action，例如组合多个局部 UI 状态更新、选择样式和提前结束当前处理器。

界面状态不能成为订单、权限、余额、任务进度等领域事实的唯一真值。业务结果需要反映到界面时，由 Rust 更新 State 或 props，再由 UIX Lang 描述如何呈现。

## Rust 负责

- 业务规则、领域模型、校验、授权与状态转换；
- 网络、数据库、文件、Settings、凭据和平台能力；
- 异步任务、取消、超时、重试、并发与错误恢复；
- 导航决策、多窗口编排、应用启动/关闭及资源生命周期；
- 业务事件、跨 System 协作和可持久化消息；
- 需要复杂算法、测试替身或独立契约的任何能力。

Rust 通过 props、`State<T>`、回调 props、`external` 或组合根向 UI 暴露窄契约。界面事件可以触发这些契约，但 UIX Lang 不复制业务分支，也不根据传输成功推断业务完成。

## 现有 action 的边界

已实现的无参数同步 action 和 `do { ... }` 语句面保留，但定位为**界面交互编排**：

- 允许读取 props、界面 state 和 computed；
- 允许更新界面 state、切换主题/样式、调用其他界面 action；
- 允许调用 Rust 提供的显式回调，把业务输入交给 Rust；
- 不新增参数化业务 Action、Service、`await`、重试、事务、路由或生命周期语法；
- 不把异步结果、业务错误或领域状态机放入 `.uix`。

当 `if` 判断涉及业务政策而不是呈现差异时，判断必须在 Rust 中完成，UIX Lang 只消费结果。

## 编译契约

正式构建把 `.uix` 静态转换为 Rust UI 代码并交给 Cargo 编译。发布产物不携带 UIX Lang 解释器、虚拟机、字符串服务注册表或未类型化业务状态字典。静态入口不会因能力缺失自动退化为动态执行。

未来的检查、格式化、LSP 或开发期热重载只能扩展 UI 描述工具链，不能改变本文的职责边界。

## 非目标

- 不把 UIX Lang 扩展为应用脚本、工作流或通用编程语言；
- 不在语言中声明 Service、事务、线程、执行器、原生句柄或持久化；
- 不以 Function / Service 包装把业务逻辑迁入 `.uix`；
- 不让局部界面 state 取代 Rust 领域状态；
- 不让开发期动态能力成为生产正确性的依赖。
