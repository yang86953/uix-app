# 版本策略

[← 返回 UIX Lang 索引](../README.md)

> **文档角色**：兼容策略——持有版本号、兼容性分类、变更登记和证据链接规则。
>
> **接口**：声明 UIX Lang 的语言版本口径与兼容性承诺。依赖：[编译契约](../规范/编译契约.md)。导出：[变更日志](CHANGELOG.md)。

## 版本号

- 语言版本跟随根 crate 版本；当前为已内部发布的 **0.0.7**，不存在独立于 crate 的语言版本号。
- `0.0.7` 补齐 `VirtualScroll` 行模板中的嵌套 `<For>`、行字段数据源与字符串字面量比较作用域，并明确 `For key` 不接受字符串字面量；内部使用方仍必须以实际授权交付物随附的规范和变更日志为准，不能只比较版本字符串。
- 正式发布后，兼容新增使用 minor、兼容修复使用 patch；破坏性变更在 `1.0.0` 后使用 major。SemVer 的 `0.y.z` 阶段不承诺稳定公开 API，破坏性变更至少提升 minor，并在可行时提供废弃提示和迁移入口。

## 兼容性承诺

1. **同版本、同 capability 不静默降级**：已登记的标签、属性、事件和样式在相同授权交付版本及 capability 配置下保持确定语义；确需移除或收窄时记录破坏性影响，并在可行时走“废弃提示 → 迁移入口 → 移除”流程。
2. **未登记能力编译诊断**：任何未登记能力使用时得到带位置与修复建议的编译期诊断，不生成占位 View、不静默回退；目标设计本身不产生可用入口。
3. **宏入口契约明确**：当前 `uix!` 返回 `ViewNode`，`uix_app!` 返回尚未调用 `.run()` 的 `App` builder，`uix_items!` 生成模块级 Record 结构体与 Visual 静态项。未来若改变这些返回契约，必须按破坏性变更登记，不能以“内部实现”名义静默修改。
4. **已登记映射确定**：语言结构与对应 Rust 声明式 API 具有确定的语义映射；具体版本的验证范围与环境结果由发布记录和关联任务持有，不以首页摘要替代证据。
5. **目标设计与实现分离**：未来契约只进入设计或实施计划，不写入当前规范和参考；实现并取得证据后再迁入规范、参考与指南。
6. **文档随版本匹配**：使用方不得混用不同交付版本的规范、组件参考和生成器；无法确认文档版本时按不兼容处理并先核对交付来源。

## 变更登记流程

1. 尚未实现的方案只进入目标设计或实施计划，必须显式标记状态，不写入当前规范、参考或可复制示例。
2. 行为实现并取得对应契约证据后，更新[规范](../规范/总览.md)与参考正文，注明 capability、限制和诊断。
3. 在[变更日志](CHANGELOG.md)登记日期、范围、兼容性影响和关联任务；破坏性变更补充迁移入口。
4. 同步更新[语言首页](../README.md)摘要与文档地图，消除重复清单和过时状态。
5. 涉及公开 Rust 编译围栏时，只运行对应的外部消费者 `*_public_api.rs`；纯文档结构、链接和内部映射不建立项目测试。

## 证据与链接

- 规范和参考必须自包含当前契约，不能要求读者访问任务系统才能理解语义或限制。
- Gitea Issue 只作为补充追踪证据；可交付文档使用稳定的 `Gitea #编号`，不写内网主机地址或依赖登录态的 URL。
- 发布记录应列出版本、capability、验证命令和环境；任务关闭不自动等于语言能力已登记。
