# UIX Lang 编译器架构

[← 返回 UIX Lang 索引](../README.md)

> **文档角色**：架构契约——持有当前共享 Compiler System 与工具链的 System、Module、阶段与 Adapter 边界。
>
> **接口**：声明 UIX Lang 编译工具链的阶段契约、责任边界和迁移门禁。依赖：[语言边界](语言边界.md)、[语言规范](../规范/总览.md)、[编译契约](../规范/编译契约.md)。导出：[语言完善计划](../变更/语言完善计划.md)。
>
> **状态声明**：当前架构。可选纯 UI 热重载 Adapter 已通过默认关闭的 `hot-reload` feature 提供；本文不改变当前语法、三个公开宏的返回值、生成语义或 AOT 发布契约。

## 1. 设计目标

共享 `uix-lang-compiler` Compiler System 把 `.uix` 转换为确定的 Rust UI 代码，同时为 `uix check`、`uix fmt`、`uix compile`、`uix query` 和 LSP 提供同一套语言事实。

1. 语法、组件登记、诊断和文档不再分别维护同一事实；
2. 过程宏不再同时承担导入、解析、语义检查、生成和工具接口；
3. AOT 与开发工具复用同一前端和语义 IR，不形成两套语言；
4. 所有阶段保留稳定源码身份和位置，诊断不依赖生成后的 Rust 文本猜测来源。

不以引入解释器、虚拟机、业务语言或多后端抽象为目标。Rust 是唯一生产代码生成目标。

## 2. SMC 边界

UIX Lang 编译器是独立的**构建期 System**，不加入 UIX 运行时 System 的启动、状态和生命周期图。

| 边界 | 拥有 | 不拥有 |
|---|---|---|
| **UIX Lang Compiler System** | UI 源码图、语言语法与语义、UI 投影 schema、语义 IR、编译诊断和源码映射 | Widget 运行态、应用业务状态、窗口生命周期 |
| **UI Runtime System** | View、Widget、State、布局、事件和绘制的公开 Rust 契约与运行语义 | `.uix` 语法、导入图和编译诊断 |
| **Rust Application System** | 业务规则、领域状态、服务、失败语义和应用生命周期 | UI 编译阶段和局部界面状态 |
| **入口 Adapter** | 把过程宏、check、fmt、LSP 的输入输出适配到 Compiler System 公开命令 | 语言规则、schema 副本和独立生成逻辑 |

`uix-derive` 是当前 AOT 入口 Adapter，不是语言规则的长期所有者。过程宏只负责读取调用环境、选择公开编译命令、登记 Cargo 依赖并返回 Rust token；语言能力不能只在宏入口中私自实现。

## 3. 目标流水线

```text
.uix 根文件
  → SourceGraph：解析相对路径、导入闭包、可见性和稳定源码身份
  → Lossless CST：保留注释、空白与原始 token
  → AST：只表达文法结构
  → Semantic Model：名称绑定、作用域、schema 与能力门禁
  → Typed UI IR：规范化的 UI 结构、界面数据、状态和交互绑定
  → Rust Emitter：生成确定的 Rust UI 代码、同名 `.uixmap.json` 与 SourceMap
  → cargo：完成 Rust 名称、类型、借用和目标平台检查
```

各入口复用范围固定如下：

| 入口 | 复用阶段 | 结果 |
|---|---|---|
| `uix!` / `uix_app!` / `uix_items!` | 全部阶段 | Rust token、递归文件依赖和诊断 |
| `uix check` | SourceGraph 至 Typed UI IR | 语言诊断，不生成 Rust |
| `uix fmt` | SourceGraph 与 Lossless CST | 保留注释的确定性格式化结果 |
| LSP | SourceGraph 至 Semantic Model | 增量诊断、定义、引用、补全和悬停信息 |
| `HotReloadAdapter` | overlay、SourceGraph 至 Rust Emitter | 新的 AOT `CompileOutput` 或相同 `CompilationKey` |

开发工具不得另写宽松解析器。需要错误恢复时，由同一 Syntax Module 产生带错误节点的 CST；AOT 在存在错误节点时拒绝生成。

## 4. 阶段契约

| 契约 | 最小内容 | 所有权规则 |
|---|---|---|
| `SourceGraph` | 规范化文件身份、内容摘要、导入边、导出选择、来源链 | Source Module 创建；后续阶段只读 |
| `LosslessCst` / `Ast` | token、注释、空白、文法节点和 SourceSpan | Syntax Module 创建；不引用 Rust token |
| `UiProjectionSchema` | 标签、属性、子节点约束、事件载荷、样式、数据构造、句柄位和 Cargo capability | Compiler System 持有唯一版本；Semantic 与 Emitter 只取得只读视图 |
| `SemanticModel` | 声明身份、作用域、名称绑定、schema 项身份和期望类型 | Semantic Module 创建；不包含业务对象或服务句柄 |
| `TypedUiIr` | 已展开导入、已解析组件引用、规范化控制流/样式/状态/事件及完整 SourceSpan | Compiler System 的跨 Module 私有契约；Emitter 只能消费它 |
| `SourceMap` | 生成片段到原始文件、行列和语义节点的映射 | Emitter 创建；AOT Adapter 负责落盘或转交诊断 |
| `Diagnostic` | 稳定代码、阶段、主位置、关联位置、原因和修复建议 | 每个 Module 返回；System 统一排序和去重 |

`TypedUiIr` 中的“Typed”只承诺 **UI 语言可判定的类型和约束已经解析**。对 `external`、回调和调用处 Rust 标识符，IR 保存结构化表达式、期望类型与 SourceSpan；最终 Rust 类型、借用和 trait 约束仍由 cargo 检查，不复制 Rust 类型系统。

## 5. schema 的事实边界

`UiProjectionSchema` 是可登记 UI 文本面的单一事实源，包含：

- 标签与属性名、值类别、必填/默认值、子节点和父子约束；
- 事件名、`$event` 载荷字段、句柄位和回调形状；
- 样式属性、主题 token、数据构造与 Cargo capability 门禁；
- 每个登记项的稳定身份、语言版本、状态和参考文档元数据。

schema 不包含：

- UIX Lang 的文法产生式和作用域规则；
- Widget 的布局、绘制、事件传播或状态生命周期实现；
- 业务类型、业务校验、服务发现和运行实例；
- 任意 Rust 代码片段或过程宏专用分支。

规范正文持有语言规则和语义解释；schema 持有可枚举登记事实；UI Runtime 的公开 Rust 契约持有实际运行行为。参考清单由 schema 生成或由检查器逐项对照，禁止手写第四份登记矩阵。

## 6. Module 与依赖

| 私有 Module | 单一职责 | 输入 | 输出 |
|---|---|---|---|
| Source | 构建并增量维护源码与导入图 | 根输入、文件读取端口 | `SourceGraph` |
| Syntax | 词法、容错 CST 与 AST | 源码快照 | `LosslessCst`、`Ast`、语法诊断 |
| Semantic | 名称、作用域、schema、能力与 UI 类型检查 | AST、schema 只读视图 | `SemanticModel`、`TypedUiIr`、语义诊断 |
| Emit | 把合法 IR 降低为 Rust UI 代码 | `TypedUiIr`、公开 Rust 映射契约 | Rust token、`SourceMap` |

Compiler System 组合根按顺序调用 Modules，并持有 schema、诊断汇聚器和缓存。Modules 不直接取得兄弟实例，也不通过全局注册表、字符串服务定位或回调绕过 System；只交换上表中的不可变值。

fmt 和 LSP 是 Compiler System 的入口 Adapter。格式策略可作为 Syntax Module 的窄 Component；增量文档会话由 LSP Adapter 持有，不得把编辑器生命周期写入 Compiler System 的语言契约。

当前 `CompilerSession` 是这条生命周期边界的实现：它按规范文件路径缓存最新源码对应的 AST 或稳定语法诊断，并按根文件、目标形状和完整 `CompilationKey` 只保留最新分析、lowering、check 与 Emit 结果。LSP 与 `HotReloadAdapter` 各自持有会话；文档关闭显式淘汰直接或递归依赖该文件的根并立即复核仍打开的根，Adapter 销毁释放其余缓存。文件读取与导入闭包解析仍在每次命令中重新确认，缓存命中只跳过未变化的阶段计算，不把旧文件系统状态当作当前真相。

## 7. 命令、失败与确定性

Compiler System 公开四类命令：`compile`、`check`、`format`、`query`。命令结果必须满足：

- `compile` 发现任何 error 时不返回可编译的部分 Rust 结果；
- 诊断按来源链、文件位置、阶段和稳定代码确定性排序；
- 未登记能力、缺失 capability 和导入失败不动态降级；
- 同一源码图、语言版本、schema 版本、capability 集与编译器版本产生相同 IR 和 Rust 输出；
- Adapter 只能补充调用环境诊断，不能覆盖 Compiler System 的语义结论。

增量缓存键至少包含文件内容摘要、递归依赖摘要、语言版本、schema 版本、capability 集与编译器版本。缓存只复用阶段产物，不改变诊断顺序和失败语义。

`HotReloadAdapter` 是开发工具入口，不是 UI Runtime Module。它固定编译 `View`，只持有根文件、调用方提交的 overlay 与最后一次成功 `CompilationKey`：递归依赖变化返回新的 AOT `CompileOutput`，源码图未变化返回 `Unchanged`，编译失败保留上次成功身份。文件监视、Rust 编译进程、产物加载和应用重启均由外部开发工具负责；Adapter 不解释 IR、不执行回调，也不取得 `App`、业务状态或应用生命周期。

## 8. 迁移顺序

| 阶段 | 改动 | 兼容门禁 |
|---|---|---|
| 1 | 抽取 `UiProjectionSchema` 并让现有 AOT 读取 | 当前登记矩阵、宏返回值和生成行为不变 |
| 2 | 建立稳定 SourceGraph、CST/AST 与 `TypedUiIr` | 现有 compile-pass / compile-fail 结果等价 |
| 3 | 把流程收口到 Compiler System，`uix-derive` 变为薄 Adapter | 生成文件路径、依赖追踪和 SourceSpan 契约不退化 |
| 已完成 | 基于共享前端提供 check、fmt、compile、query 和最小 LSP | 工具诊断与 AOT 对同一输入一致 |
| 已完成 | 可选纯 UI 热重载 Adapter | `hot-reload` 默认关闭，不监视文件、不加载产物、不执行业务逻辑 |
| 已完成 | `CompilerSession` 阶段缓存与 Adapter 会话复用 | 变化文件定向重解析，未变化源码图复用分析、lowering 与输出，诊断和失败语义不变 |

每阶段只迁移一个事实所有者；旧入口在新入口通过等价验证后删除，禁止长期双写 AST、schema 或 codegen。

## 9. 验收门禁

- schema 每个登记项都能追溯到规范/参考条目和一个公开 Rust 映射；
- AOT 与 check 对同一无效输入返回相同稳定诊断代码和主 SourceSpan；
- fmt 往返不改变 AST，连续两次格式化字节一致；
- 修改导入闭包中的任一文件只失效受影响源码图；
- Emitter 不接收 CST/AST，Syntax 不依赖 Rust token 或 UI Runtime 实现；
- 发布依赖中不存在解释器、文件监视器、LSP 会话或运行时 `.uix` 源码。
