# 统一组件语言方案

[← 返回语言边界](语言边界.md)

**状态：2026-09-12 实施候选。** 本文给出完整框架改造第二阶段的具体语言与执行合同；不是已发布语法指南。首批实现使用独立实验入口，旧入口不在同一已发布版本中静默换义。解析成功不等于下述运行合同已实现。

## 要解决的问题

普通 Widget 的构建期展开、Module 的共享执行、Rust 库声明已有可复用基础，但它们并存还不是统一组件模型：模块状态不能直接代表多个 UI 实例；Rust 自由捕获不能在动态宿主重建；纯 UIX 作者不应重复填写组件登记或给每个组件加 Rust 包装。

选择具有显式状态的组件声明，而不引入依赖调用顺序的 hooks。语言借鉴 TSX 的代码与标签表达组合，不承诺 TypeScript、JavaScript 或 npm 兼容。使用现有可移植值语义：`Int` 为有检查的 i64，`Float` 为有限 f64；不采用 JS 的隐式真值、字符串加数值转换或隐式 undefined。

## 同一份可读输入

以下仅为候选语法，语法树直接持有声明、类型、表达式和源区间；不将函数体、参数列表或类型编码成 XML 字符串属性。

```text
import { Column, Text, Button } from "uix-widgets";

export component Counter(initial: Int = 0) {
  state count: Int = initial;

  function increment(): Unit {
    count = count + 1;
  }

  return <Column>
    <Text>{count.toString()}</Text>
    <Button onClick={increment}>增加</Button>
  </Column>;
}
```

- 一个文件可以导出多个组件、函数和类型，无须额外放一个实例当文档根。导入器从显式入口和导出关系计算闭包。
- 参数是只读输入，可有类型受检的默认表达式。默认值按声明顺序求值，不读取尚未绑定的后继参数。
- `state` 在实例挂载时初始化一次；输入变化不重置已有状态。相同组件同时渲染两次，状态不共享。条件卸载后再挂载创建新实例。
- 普通函数、局部 `let`、条件、返回、数组和记录与 JSX 共用词法作用域；事件是函数值，不是字符串形式的处理器。
- `children: View` 表示调用方传入的 UI 表达。具名子内容也是有类型参数，不新增逐组件插槽登记。子内容保留声明处的变量与事件捕获，主题等运行上下文按实际挂载位置传播。
- 条件 UI 使用条件表达式；列表可使用 `items.map((item) => <Row key={item.id} ... />)`。`key` 是实例身份元数据，不混入控件业务属性。重复 key 是带来源位置的错误，不能静默复用错误实例。

卡片与可编辑列表验证输入、事件、子内容和有状态子组件，不能只用一个无参计数器证明复用。普通对象/数组不得被拿来传递任意 Rust 句柄；原生资源有独立、受检的绑定合同。

## 一份语义，两种执行

```text
源文件及导入闭包
        ↓
结构化 AST → 名称/类型/效果/身份检查 → 组件执行 IR
        ├─ AOT：原生 Rust 初始化、表达式、事件和视图函数
        └─ 动态：受检 IR 执行，使用相同组件实例与原生绑定合同
                         ↓
               既有 UI 树、布局、绘制与交互
```

不为两条路径维护不同示例或不同类型检查器。AOT 的业务与界面表达式生成原生代码，不能打包源码再调用解析器，也不能把完整表达式 IR 交给动态解释器执行。允许两条路径共用拥有型值、资源句柄、身份检查和原生控件适配；这是公共运行合同，不是解释源码。

组件实例由 UI owner 管理，实例状态、事件捕获和子实例身份有单一所有者；不为每个组件创建线程、worker 或常驻轮询。状态或输入失效后才重算需要更新的投影。将现有 Module 的类型、检查和原生生成能力抽为共享实现时，保留其已承诺的模块事务/异步行为，不直接把一个 Module 实例套成每个组件的独立后台线程。

## 实例、事件与失败

| 合同 | 静态和动态都必须证明 |
| --- | --- |
| 身份 | 父实例、调用位置和显式 key 决定子实例；重排不交换输入框草稿、焦点或局部状态；卸载删除事件入口 |
| 初始化 | 只读参数与局部状态类型匹配；挂载失败不留下半初始化子实例 |
| 更新 | 派生 UI 只读，不在渲染过程中写 state、发请求或启动事务；输入/状态更新有有界失效路径 |
| 同步事件 | 读到当前输入及当前捕获；事件状态更新按同一提交边界处理。可失败准备与状态提交分开，不把外部效果视为可自动回滚 |
| 异步 | 操作归属实例或显式应用作用域；取消、超时、晚到结果与卸载的结果明确，不在 UI owner 阻塞等待 |
| 错误 | 原文件、行列、错误类别一致；失败不降级为占位控件或静默忽略属性 |
| 替换 | 先验证新闭包和类型；状态兼容性不满足时明确要求重建，不能按字段位置误接状态 |

同步事件的具体状态提交接口复用现有运行合同所需的最小机制；最终规范须明确哪些状态已提交、哪些外部效果已发生，不能宣称跨网络或数据库的自动全局回滚。

## 原生组件与 Rust 绑定

纯 UIX 组件的公共接口由声明自动导出。原生实现使用同一接口形状，应用不因内部是否有 `.rs` 而换一种使用方式。底层控件仍复用现有 Rust 实现，普通组合控件逐步改用纯 UIX。

原生库提供包级入口和有类型的导出签名；构建器从该唯一来源生成编译绑定、动态适配与查询描述。不要求作者手写静态/动态两份登记。首批可以消费现有原生库描述，但这是迁移桥，不把旧巨型 JSON 变成纯 UIX 组件的额外手工登记要求。

动态宿主只能调用已编入并开放的原生导出；从 `.uix` 读取 `.rs` 文件不等于能执行 Rust。未知签名、句柄种类、能力或版本不匹配，在创建实例前拒绝。框架不通过官方包名推断能力，第三方测试库必须走完全相同的入口。

## 工具、按需构建与迁移

- check、compile、动态 load、fmt、query 和 LSP 共用源码单元及来源 ID。AST 保留原区间；格式化后的文件重新解析产生对应新范围，不挪用旧偏移。
- 导出组件及其实际依赖形成静态闭包；动态许可形成额外显式根。未选择动态解释、网络、ORM 或某个驱动时，不进入目标依赖与制品。
- 实验入口先证明 Card、Counter、可编辑列表及真实原生投影，再迁移代表控件，最后迁移受影响库、工具和示例。不是把所有控件永远包在旧语法解释桥中。
- 历史 `--lib` 测试须分类：通用语言/生命周期合同迁移并保留行为验证；旧四包路径修复；旧内置组件与 capability 数量断言改为真实第三方库公共合同；不得只删除失败测试或重新将官方组件硬编码进框架。
- 移除旧入口前明确版本边界和具体迁移例子。源码候选不改变已发布 crates.io 0.0.8 制品；本目标不自动发布新版本或迁移外部消费者。

## 验收顺序

1. 同一源码闭包的结构化 AST、导出、名称/类型检查与准确负例位置。
2. 两条路径执行同一 Counter/Card/List：独立实例、参数更新、回调、子内容、重排、卸载和错误结果一致；直接构建并运行 AOT 消费者，不以 token 文本存在某字段证明 AOT。
3. 用公开控件在真实 UI 树中完成指针/键盘、中文编辑、焦点及主题，保留样式工作台既有视觉能力。
4. 以真实未用依赖、资源和 release 二进制证明按需构建，检查 AOT 目标没有动态前端/解释调用。
5. 完成库与工具迁移后再将已实现合同迁入规范。网络与 ORM 按完整框架目标继续，不因该闭环完成而结束总目标。

网络/ORM 的协议、后端和成熟依赖选型在服务设计中另行形成具体方案。本阶段不预先承诺未核实的外部库版本，也不将示例 mock 当作服务交付。

## 当前实验前端边界

2026-09-12 源码候选新增 `uix_app::lang::compiler::component_source`（`lang-build` feature）：

- `parse(source, source_name)` 直接建立导入、组件、函数、类型、状态、语句及 UI 表达式 AST；保留原源码快照、稳定来源 ID 和 UTF-8 字节区间。诊断的行列为一基 Unicode 标量位置，编辑器协议仍须从原字节范围转换 UTF-16。
- `link_file(path)` / `link_file_with_overlays(path, overlays)` 读取纯 `.uix` 导入闭包，自动连接选择的导出和别名，拒绝私有/不存在的导出、重复顶层名称与循环导入。编辑器缓冲区支持替换依赖及父目录已存在的未保存文件；后续阶段消费同一拥有型快照。
- 单独 `link_file` 的裸包导入保留为 `Binding::NativeImport`，**不表示库或签名已验证**。下一步 `check(linked, native_libraries)` 验证所选原生导出、组件输入和函数签名；未知包/导出、重复参数、无效 required/参数数目都拒绝。没有按 `uix-widgets` 名称硬编码控件，也没有为纯 UIX 组件要求登记表。
- 单文件至多 1 MiB、语法节点至多 16384、解析和实际 AST 树高至多 64；导入闭包至多 256 文件、8 MiB、64 层。这些是实验入口的有界执行合同，不是对旧入口的变更。超过限制返回诊断。
- `check` 返回只读 `CheckedSource`：拥有原闭包与选中原生签名的冻结副本，携带表达式类型、名字解析、词法绑定身份、捕获集、函数效果及规范化字面量。类型别名按真实来源解析；Int/Float、记录、数组和普通数据方法与既有 Module 共用运行时数据类型及运算合同。语义分析总工作预算 262144、展开类型至多 4096 节点/64 层，防止短别名源构造指数大小的类型树。
- 组件输入与函数参数只读；默认值按顺序绑定，不能读取当前/后继参数；具名函数允许省略有默认值的尾部实参。实例 `state` 先于函数/渲染语句声明，只保存拥有型数据，不能保存回调或 View。普通 `let` 可在本函数内重赋值，跨函数捕获为只读值；持久交互写 `state`，不靠共享可变局部变量隐式延长生命周期。
- 具名函数、lambda、局部别名与分支赋值通过调用关系推导 Pure/Query/Command，渲染的直接或间接写状态/外部效果在原调用位置拒绝；创建一个写状态的事件回调并不等于在渲染中执行它。函数类型当前以 Command 为参数回调的保守上界，原生接口可提供更窄上界；尚未提供 UIX 函数类型的显式效果标注，也不声称已实现通用高阶效果多态。
- `key` 为 Int/String 身份元数据，不允许作为组件业务参数。标签子内容按接口使用 `View` 或 `String`：前者接受 View/嵌套 View 数组且忽略缩进空白，裸文字要求明确的文字组件；后者接受原文本和 String 表达式，不把整数/布尔隐式变成字符串。`children` 属性与标签子内容不能重复提供。更完整的文本规范化和实际 UI 投影仍随执行阶段落实。
- Counter、Card、可编辑列表共同输入位于 `tests/fixtures/components/`，已通过上述共享语义检查；它们仍是**前端测试输入，不是已经可运行的应用示例**。

本批未完成原生调用实现绑定、实例状态与 UI 投影，也未接通新组件的 AOT、动态执行或现有 CLI/LSP。当前 NativeLibraries 是供共同检查器消费的类型化接口输入，不是让库作者永远手写另一份组件表；原生绑定单一来源生成仍待贯通。`parse` / `link_file` 不冒称检查或编译，`check` 不冒称执行，不以语义测试替代双路径真实消费者验收。现有 Widget/Module 入口保持原义；待共享实例合同和真实消费者闭环后再迁移正式工具入口。
