# UIX Lang 语言服务器

[← 返回 UIX Lang 索引](../README.md)

> **文档角色**：当前指南——只提供可复制的语言服务器启动与编辑器接入用法，不定义语言规则或未来能力。
>
> **接口**：声明 UIX Lang 语言服务器（`uix-lang-ls`）的启动方式、LSP 能力、失败语义与适用限制。依赖：[编译契约](../规范/编译契约.md)、[编译器架构](../设计/编译器架构.md)。导出：无。

语言服务器是共享 `uix-lang-compiler` Compiler System 的入口 Adapter：诊断、schema、格式化、源码图与语义 IR 全部来自同一公开命令，服务器自身不维护独立语言规则。实现位于工作区成员 `uix-lang-lsp`，`uix lsp` 子命令与独立二进制 `uix-lang-ls` 委托同一实现。

## 前置条件

- 已构建语言服务器二进制（二选一）：
  - 独立二进制：`cargo build --release -p uix-lang-lsp`，产物为 `target/release/uix-lang-ls`；
  - 工具链入口：`cargo build -p uix-lang-cli`，产物为 `target/debug/uix-lang-cli`（经 `lsp` 子命令运行）。
- 编辑器或客户端支持 LSP 3.17 子集（stdio JSON-RPC、`textDocument/*`）。

## 启动方式

服务器只使用 stdio，不监听端口、不读取配置文件：

```bash
# 方式一：独立语言服务器二进制（推荐编辑器接入）
target/release/uix-lang-ls

# 方式二：经 uix 工具链子命令，行为与方式一完全一致
target/debug/uix-lang-cli lsp
```

## 编辑器接入

客户端以「命令 + 无参数」方式启动服务器即可。以 Zed 为例（`settings.json`）：

```json
{
  "languages": {
    "UIX Lang": {
      "language_servers": ["uix-lang-ls"]
    }
  },
  "language_models": {}
}
```

LSP 客户端配置（通用 JSON 形式，`command` 按仓库路径调整）：

```json
{
  "uix-lang-ls": {
    "command": "uix-lang-ls",
    "args": []
  }
}
```

## 能力清单

| LSP 能力 | 行为 |
|---|---|
| `textDocument/didOpen` / `didChange` / `didClose` | 全量同步（`change: 1`）；内存 overlay 覆盖磁盘参与递归 `@import` 检查，诊断按根发布 |
| `textDocument/publishDiagnostics` | 与 `uix check` 同源的诊断；错误位于导入依赖时发布到依赖文件 URI，并清空根文件残留 |
| `textDocument/completion` | 上下文感知：标签名（组件 + 控制元素 + 自定义组件）、属性名、`@` 事件、样式属性、`#token`、样式类与顶层指令 |
| `textDocument/hover` | 语义 IR 最窄节点优先（组件、事件载荷字段、State 句柄位、capability 门禁），schema 词查询兜底 |
| `textDocument/definition` | 自定义组件 / 样式类 / Record / Visual 等声明跳转；`@import` 路径字面量跳转目标文件 |
| `textDocument/references` | 导入闭包内全部文件的全词边界引用，支持 `includeDeclaration` |
| `textDocument/documentSymbol` | 语义声明层级大纲；语法未完成时退回顶层声明扫描 |
| `textDocument/formatting` | 共享格式化入口的单次全文替换编辑；语法错误时返回 null |
| `workspace/didChangeWatchedFiles` | 磁盘依赖变化后失效编译缓存，并立即复核仍打开的根 |

## 可见失败与限制

- **诊断只报第一个失败来源**：与 `uix check` 一致，同一根每次只发布当前失败来源的诊断；修复后自动清空。
- **虚拟文档（非 `file://` URI）不参与导入解析**：没有目录基准，`@import` 相对路径无法定位，跳转到目标文件的功能同样不可用。
- **语法错误期间能力降级**：补全、大纲退回扫描模式；悬停、定义、引用与格式化可能返回 null 或空结果，这是预期行为而非故障。
- **补全上下文是编辑器侧启发式**：扫描器只定位光标所处的语法位置（标签内、样式块、`#` 引用等），语言正确性仍以编译器诊断为准；表达式内部不提供上下文补全。
- **不监视文件系统**：服务器不自行监听磁盘变化，依赖客户端发送 `workspace/didChangeWatchedFiles`；未发送该通知的客户端在依赖文件被外部修改后，需重新保存根文件才能刷新诊断。
- **性能契约**：跨请求阶段复用由 `CompilerSession` 承担，语义与失败语义与单次命令完全一致；证据与边界见[编译器架构](../设计/编译器架构.md)与 [UIX-PERF-004](../../性能/UIX-PERF-004.md)。

## 安全边界

- 服务器通过 stdio 与唯一客户端通信，不监听网络端口，不接受远程连接。
- 文件访问限于两类：读取工作区内被打开或被 `@import` 引用的 `.uix` 源码；客户端显式通知变化的文件缓存失效。不写入任何文件。
- 会话内存有界：overlay 与诊断记账只随打开文档增长，文档关闭即释放对应快照与缓存。
