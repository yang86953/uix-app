# 统一组件实验入口

[← 语言首页](../README.md) · [语义与当前边界](../设计/统一组件语言方案.md#当前双路径执行边界)

以下 API 属于当前源码实验批次，尚未发布为新版本。旧 `uix!` 不改变语义；源码版 CLI 的检查、格式化、显式组件编译和 LSP 诊断/格式化已识别新家族。这里说明已经贯通的入口，不表示完整工具链或框架改造已结束。

## 纯 UIX 组件

```tsx
import { Row, Text, Button } from "uix-widgets";

export component Counter(initial: Int = 0) {
  state count: Int = initial;
  return <Row>
    <Text>{count.toString()}</Text>
    <Button onClick={() => { count = count + 1; }}>增加</Button>
  </Row>;
}
```

另一个 `.uix` 通过 `import { Counter } from "./counter.uix";` 复用它，不需要 Rust 包装或逐组件登记。`initial` 更新不重置已初始化的 count；需要两个独立计数器时实例化两次。列表使用显式 key 保留换序后的局部状态。

## 检查、编译与挂载

组件源入口在 `uix_app::lang::compiler::component_source`。两条路径消费同一 `CheckedSource`：

```rust
let linked = component_source::link_file(path)?;
let checked = component_source::check(linked, &library.interfaces())?;

// 动态宿主：显式启用 uix-dynamic。
let program = component_source::lower(&checked, "Counter")?;

// AOT 构建端：启用 lang-build，写入 OUT_DIR，目标代码用 include! 读取。
let rust_expression = component_source::emit_native(&checked, "Counter")?;
```

AOT 表达式构造的 `Program` 包含原生 Rust 函数体，不是打包源码或表达式 IR。通常在 build.rs 使用公开构建入口，它登记整个导入闭包，并将不同导出写入不同文件：

```rust
let generated = builder.compile_component("src/counter.uix", "Counter", &interfaces)?;
// OUT_DIR/uix/component/src/counter.uix.Counter.rs
```

目标代码可 `include!(concat!(env!("OUT_DIR"), "/uix/component/src/counter.uix.Counter.rs"))`。直接使用底层 emit_native 时，构建脚本自行为来源闭包输出 `cargo:rerun-if-changed`。完整接入可参考 uix-widgets 的 build.rs 与独立消费者测试；CLI 用法见下节，旧宏不切换此语法。

两条路径按入口裁剪未使用的组件、函数及原生接口，但保留可达默认参数、状态初始化和捕获。未使用声明仍先检查；此行为不等于已经裁掉所有 Rust 控件模块或 Cargo 依赖。

目标端启用 core 的 `ui,uix-components` 以及 widgets 的 `uix-components`；动态路径额外选 `uix-dynamic`。使用包级 `uix_widgets::components::library()` 获得检查接口及同一份真实构造器：

```rust
use std::collections::BTreeMap;
use uix_app::lang::runtime::components::{ComponentLimits, ui::UiHost};

let host = UiHost::new(
    program,
    uix_widgets::components::library()?,
    BTreeMap::new(),
    ComponentLimits::default(),
)?;
```

在所属窗口的根/组件构建闭包中调用 `host.view()`，并按应用策略处理其错误。`new` 只初始化语言实例，`view` 才在实际窗口上下文中构建控件。一个 UiHost 对应一个挂载树；多窗口或两个独立根分别创建 owner。克隆控制句柄不会复制组件状态。最后一个挂载回执销毁会关闭 owner；也可显式 `close()`，旧事件不能使其复活。

`host.update(inputs)`、`host.dispatch(token, arguments)` 返回明确结果；UI 控件的 void 回调通过 `host.error()` 暴露最近一次失败。事件的原生投影准备失败时，语言状态与投影版本保持不变，旧 UI 仍可使用。原生构造错误包含对应 JSX 来源。初次构造或窗口上下文变更导致的 `view` 错误直接返回调用者，不静默替换成空 UI。

直接使用 Snapshot 的 EventToken 只对当前投影版本有效。原生控件的 NativeCallback 另由挂载树持有内部租期：一帧中的连续输入使用原回调捕获和最新组件 state，不要求每个系统事件后立即重建整树；移除事件槽或卸载 owner 会立即撤销，不能借旧控件回调恢复已卸载组件。

## 命令行与编辑器诊断

本节命令使用当前源码以 `lang-tools` 构建的 `uix`，不是已发布版本的能力承诺。原生库从自己的同一签名声明生成只读接口文件，应用在最近的 `uix.json` 引用它们：

```json
{
  "component_libraries": ["vendor/native-components.json"]
}
```

路径相对于该配置所在目录；也可明确指定绝对路径。这里列出的是原生库的签名文件，**不是纯 `.uix` 组件登记表**。未配置时原生接口为空；不根据包名自动加载官方库、Rust 代码或网络内容。旧 `packages` 配置可以共存，新组件检查不读取旧 XML 控件目录。

```sh
uix check src/counter.uix --json
uix check --target component src/counter.uix
uix fmt --check src/counter.uix
uix fmt src/counter.uix
uix compile --target component --entry Counter src/counter.uix
uix query native-exports --project . --json
uix lsp
```

- `check` 从首个非注释声明识别新家族，或由 `--target component` 明确选择；检查失败不改用旧语法。整个导入闭包仍先检查，未引用声明的错误不被裁剪隐藏。
- `compile` 必须指定真实导出组件名，stdout 是构造 Program 的 Rust 表达式，与 Cargo 入口使用同一 `emit_native`。此命令不负责组装应用、运行 Cargo 或生成 `.uixmap.json`；需要可复现构建依赖跟踪时使用 `Builder::compile_component`。
- `native-exports` 查询配置中的原生包、导出名和类型/效果签名，不表示已装载真实实现，也不枚举任意应用目录或纯组件导出。旧 `query components` 仍是旧投影目录。
- CLI 诊断保留原文件、UTF-8 字节范围与一基行列；LSP 使用同一诊断转换 UTF-16 范围。新组件的打开/编辑、依赖 overlay 关闭，以及客户端 `didChangeWatchedFiles` 通知会复核相关打开来源；包含接口/配置改动及之前失败的根。接口/配置读取落盘内容，不把其未保存编辑当作 UIX overlay。
- `fmt --check` 只检查是否需要格式化；`fmt` 在候选验证成功后写入文件。LSP 的 formatting 返回同一候选和原文完整 UTF-16 编辑范围，不直接写磁盘。悬停、定义、引用、大纲和补全仍未接通，暂返回空结果，不借旧 XML 扫描提供错误结果。

库作者可使用 `component_source::interface::encode(&libraries)`，或在构建脚本调用 `builder.export_component_interfaces("native-components.json", &libraries)`，产物位于 `OUT_DIR/uix/interfaces/`。默认构建只写构建目录；分发时显式更新生成文件，并测试其与真实绑定相等，不手工维护另一套属性类型。该 JSON `version` 当前为 1，未知版本/字段、重复对象键、冲突导出或非法签名均报错。单文件含配置限 1 MiB、接口清单限 32 项、接口闭包限 8 MiB；类型沿用共同检查预算，另保留 JSON 解析器的有界嵌套限制，导出端同样检查可再读取性。

API 使用 `CompilerSystem::check_component_file[_with_overlays]` 得到 `ComponentOutput`，其中 `checked` 是同一受检语义，`interface_files` 是额外失效来源。内嵌入口 `check_component_inline(source, name, libraries)` 不搜索配置；允许显式原生签名，相对纯组件导入需要真实文件入口。LSP 不建立运行实例或工作线程；每会话组件成功快照和根索引各最多 32 项，关闭/变化时失效。

运行时仍必须提供并验签实际 `UiLibrary` / `NativeBindings`，接口文件不能授予或模拟宿主能力。序列化仅由 `lang-build` 提供，不因为消费生成的 AOT Program 就启用 serde、编译器或动态执行。

### 格式化合同

`component_source::format(source, source_name)` 与 `CompilerSystem::format_inline/format_file`、CLI/LSP 共享现有解析器。具体 token 来自解析消费，而不是另写一个正则或 XML lexer。语句块使用两空格缩进、语句换行，代码标点空白规范化；当前不按行宽重排参数或属性。

注释、字符串转义、数字写法和 **JSX 文本（包括空格、换行和缩进）原字节保留**。因此 JSX 原文本缩进不会因为父级代码缩进改变而重写；库的 String 子内容合同优先于视觉对齐。只有代码空白可以调整，格式化不要求导入文件或原生接口可用，也不将类型检查失败变成格式化失败。

返回前重新解析候选，比较移除来源区间后的完整 AST，并逐项核对非空白 token 的种类/字节；不会用字符串删改 Debug 输出来“忽略区间”。新 CST 连续覆盖输出，区间对应新文本，不能复用格式化前的语义 NodeId。

输入仍受既有解析预算约束；具体语法最多 131072 个 token，输出最多 1 MiB。语法错误、超限或等价检查失败不返回候选、不覆盖原文件。重复格式化结果不再变化。解析器的 lambda 预判只读参数前缀，不将括号内 JSX 文本当作代码；递归路径内部装箱错误，公开诊断形状不变，过深输入返回深度错误。

## 原生库的单一属性声明

只在确实需要 Rust 控件/平台实现时声明原生属性。纯 UIX 组合组件不使用此宏。

```rust
use uix_app::lang::runtime::components::{NativeCallback, OptionalProp};

uix_app::native_props! {pub struct EditorProps {
    value: String,
    on_change: NativeCallback<(String,)> => "onChange" = NativeCallback::default(),
    disabled: OptionalProp<bool> = OptionalProp(None),
}}
```

`EditorProps::signature()` 与 `EditorProps::read()` 由同一个声明生成。省略默认值的字段必需；`=>` 指定 UIX 名称；未知属性或错误数据类型拒绝。`OptionalProp` 区分未提供与显式 false/0，不用默认值哨兵覆盖 Provider。支持 String、Bool、Int/i64、Float/f64、Unit、数据数组、View 子内容，以及 0–4 个拥有型数据参数的回调。复杂自定义数据类型可实现公开 NativeProp/NativeData，但不会因此成为任意 Rust 资源句柄。

`UiLibrary::component::<EditorProps>(package, name, constructor)` 将这一接口绑定到真实构造器。构造器接收解码后的 EditorProps 与 UiBuildContext，返回 `RuntimeResult<ViewNode>`；通过 `context.children(Children)` 展开 View 属性。`NativeCallback::call` 返回类型化结果；Unit 通知可用 `emit`，未提供的可选通知为 no-op，真实事件失败仍返回错误。框架不按官方包名猜测映射，第三方使用完全相同的注册入口。

构造器必须可重复执行，不能在构造期间派发同一 owner 的事件。读取的 State/Computed、捕获的 Effect 和媒体断点交接给既有树生命周期；事件准备恢复挂载时的 Provider/主题/视口，等待接纳期间已过期的状态快照不复用。构造/Effect 中已经发生的业务外部写入不能回滚，因此业务写入应通过事件/服务接口发生。

## 当前库接线范围

本批已接通官方包的 Column、Row、Text、Button、Input，具体属性、默认值和控件行为由 uix-widgets 的 `docs/统一组件接入.md` 持有。本章只说明框架通用的编译、类型化原生接口与挂载合同，不为其他库自动推断控件映射。完整组件迁移、热替换、异步资源及发布入口仍按改造目标继续推进。
