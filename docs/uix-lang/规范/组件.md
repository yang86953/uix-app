## 1. 组件定义

`<Widget>` 是组件定义标签，`name` 为必填属性，**只能出现在顶层声明区**；定义后即可在本文档及导入方以同名标签使用。

UIX Lang `<Widget>` 是由转换器验证并在调用位展开的逻辑组件模板，不等同于 Rust `widget!` 宏生成的 `Widget` 类型。每个实际调用位仍形成独立组件实例：props、computed 与事件适配器在当前调用作用域建立；private state 由当前窗口 `WidgetTree` 内的 `WidgetStateStore` 按静态调用声明和实际 key / 位置路径拥有，并跟随对应 View 子树的 reconcile 生命周期复用或清理。

```uix
<Widget name="HelloWorld">
  <Text>Hello, World!</Text>
</Widget>
<HelloWorld />
```

## 2. 属性（props）

`props` 声明组件输入参数，形式为 `'name: Type'` 或 `'name: Type = 默认表达式'`，多个用 `,` 分隔；使用方通过同名属性传值，组件内以 `{name}` 引用。无默认值的 prop 必填；有默认值时调用方可省略，显式传值始终覆盖默认值。默认表达式仅允许字面量与已登记数据类型构造，不允许状态、回调或其他动态表达式。类型分基础值与回调两类：

| 类型 | 说明 |
|---|---|
| `String` / `number` / `bool` / `Date` / `Time` / `Color` / `Point` | 值类型 |
| `()` | 回调：无参无返回 |
| `(参数类型列表)` | 回调：带参无返回，如 `(String)` |
| `(参数类型列表) -> 返回类型` | 回调：带参带返回，如 `(String) -> bool` |

回调参数与返回类型限基础值类型（`String` / `number` / `bool`）。

**响应式状态引用**：props 也可声明 `State<T>` 类型（`State<String>` / `State<number>` / `State<bool>`）。句柄由 Rust 调用方创建并拥有；组件读取当前值，也可以通过 `setState` 对同一句柄提交同步更新，但不会取得句柄或其生命周期所有权：

```uix
// Rust 侧：let shared_count = State::new(0);（在 uix! 宏调用处可见）
<Widget name="SharedCounter" props="count: State<number>">
  <Text>{count}</Text>
  <Button @click="setState(count: count + 1)">+1</Button>
</Widget>
<SharedCounter count={sharedCount} />
```

> 共享状态模式：Rust 侧持有 `State<T>`，通过 props 传入组件；数据流向仍保持“props 进、回调或显式句柄更新出”。领域状态建议投影为只读值和业务回调，不以可写 UI 句柄绕过 Application System。

```uix
// 声明带默认值的问候组件。
<Widget name="Greeting" props="name: String = 'UIX'">
  // 读取组件的字符串 prop。
  <Text>Hello, {name}!</Text>
// 结束问候组件声明。
</Widget>

// 带返回值的回调：确认结果由 Rust 侧决定
<Widget name="ConfirmButton" props="label: String, onConfirm: () -> bool">
  // 点击时调用由使用方传入的确认回调。
  <Button type="primary" @click="onConfirm()">{label}</Button>
// 结束确认按钮组件声明。
</Widget>

// 带参回调：输入内容直接交给 Rust 侧处理
<Widget name="SearchBox" props="keyword: State<String>, onSearch: (String)">
  // 受控输入框绑定使用方传入的响应式字符串状态。
  <Input value={keyword} @change="onSearch(keyword)" />
// 结束搜索框组件声明。
</Widget>

// 使用唯一 Column 根组合三个 prop 示例。
<Column gap="8px">
  // 使用默认 name prop。
  <Greeting />
  // 从 Rust 调用处接收返回 bool 的确认回调。
  <ConfirmButton label="删除" onConfirm={doDelete} />
  // 从 Rust 调用处接收共享搜索状态与带参回调。
  <SearchBox keyword={searchKeyword} onSearch={doSearch} />
// 结束示例组合根。
</Column>
```

> 函数类型 props 的传值也是表达式：`onConfirm={doDelete}`——调用参数在调用方作用域求值，`doDelete` 只需在 `uix!` 宏展开处可见（见[表达式](表达式.md)）。

### 2.1 外部依赖（external）

组件体直接引用 Rust 侧函数、闭包或值时，必须通过 `external` 显式声明根标识符；多个名称使用逗号分隔：

```uix
<Widget name="SearchBox" props="keyword: String, onSearch: (String)"
           external="debounce, format">
  <Input value={keyword} @change="debounce(onSearch, 300)" />
  <Text>{format(keyword)}</Text>
</Widget>
```

组件体可见名称由 props、state、先声明的 computed、同步 action、`For`/受限闭包局部变量、语言内建操作、数据类型构造器和 `external` 的并集组成。使用未声明名称时，转换器在对应表达式的 UIX 行列返回诊断；`external` 只声明依赖，不导入符号，最终 Rust 可见性和类型检查仍由宏调用点的编译负责。组件调用参数属于调用方作用域，不需要重复写入被调用组件的 `external`。

> **职责边界**：`external` 与回调 props 是连接 Rust 业务能力的显式入口。业务实现、错误和异步生命周期留在 Rust；UIX Lang 只绑定和调用，不复制服务契约或业务流程。

### 2.2 状态输入与可写绑定

| 绑定种类 | 实例所有者 | 组件内读取 | `setState` 目标 | 受控句柄位 |
|---|---|---|---|---|
| 普通值 prop | Rust 调用方 | 当前投影值 | 不允许 | 不允许 |
| `State<T>` prop | Rust 调用方 | 句柄当前值 | 允许；更新同一句柄 | 允许 |
| 私有 `state` | 当前 Widget 实例的 `WidgetTree` | 当前实例值 | 允许 | 允许 |
| `computed` | 无独立状态；每次展开派生 | 只读结果 | 不允许 | 不允许 |
| 回调 prop / `external` | Rust 调用方 | 只能调用或传递 | 不适用 | 不适用 |

`setState(name: value)` 中的 `name` 必须解析为当前 Widget 的私有 state 或 `State<T>` prop。普通 prop、computed、action、局部变量和回调不能成为目标；跨 Widget 更新只能通过显式传入的 `State<T>` 或 Rust 回调完成。该规则同时约束单表达式事件和 `do` action。

## 3. 状态（state）

`state` 声明组件私有的**界面状态**，形式为 `'name: 初始值'`；组件内以 `{name}` 读取，通过 `setState` 更新。它适合输入草稿、展开、选中、分页和弹层开关，不应成为领域事实的唯一真值：

```uix
<Widget name="Counter" state="count: 0">
  <Text>Count: {count}</Text>
  <Button @click="setState(count: count + 1)">Increment</Button>
</Widget>
<Counter />
```

`setState` 使用命名参数语法：`setState(name: 新值表达式)`，可一次更新多个私有 state 或 `State<T>` prop：`setState(count: count + 1, done: true)`。所有目标先按[状态输入与可写绑定](#22-状态输入与可写绑定)解析；写入按源码顺序执行。

**类型注解**：初始值默认按字面量固定类型（字符串 → `String`、数字 → `f64`、布尔 → `bool`）。需要其他类型时使用 `'name: Type = 初始值'` 显式注解，白名单为 `String` / `number` / `bool` / `u32` / `usize` / `f32` / `i32` / `Date` / `Time` / `Color` / `Point` / `CascaderValue` / `HashSet<String>` / `Vec<String>` / `Vec<number>` / `Vec<UploadFile>` / `Vec<已声明Record>` / `Option<String>` / 文档内声明的 record 名：

```uix
<Widget name="Rating" state="rating: u32 = 7, step: usize = 1, offset: f32 = 180, selected: Date = Date(2026, 8, 10), cities: HashSet<String> = []">
  <Rate value={rating} count="5" />
  <Button @click="setState(rating: rating + 1)">+1</Button>
</Widget>
```

类型化状态的初始值与 `setState` 更新值都会保留作者书写的数字形状，整数字面量不会被组件 `number` 语义附加小数点。

**语义类型初始值**：`Date` / `Time` / `Color` / `Point` 使用数据类型构造调用初始化（见[词法 · 数据类型构造](词法.md#32-数据类型构造)）；`CascaderValue` 与 record 使用对象字面量；`HashSet<String>`、`Vec<String>`、`Vec<number>` 与 `Vec<Record>` 接受类型匹配的数组字面量，`Vec<UploadFile>` 仅接受空数组 `[]`；`Option<String>` 接受 `None` 或 `Some('文本')`。

**句柄位绑定**：受控组件与双向绑定属性（`open`、`value`、`checked`、`current`、`pageSize`、`offset`、`scrollY`、`model` 等）需要 `State<T>` 句柄。私有 state 的句柄由当前 Widget 实例拥有；`State<T>` prop 的句柄由 Rust 调用方拥有。两者都可直接绑定，转换器不会复制或另建状态槽：

```uix
<Widget name="Feedback" state="open: false">
  <Button @click="setState(open: true)">打开</Button>
  <Modal open={open} @ok="setState(open: false)">...</Modal>
</Widget>
```

引用只读 prop 或回调到句柄位属性时，编译期给出「句柄位属性」诊断。

### 3.1 派生值（computed）

`computed` 声明组件只读派生值，形式为 `'名称: 表达式'`，多个声明以顶层逗号分隔。表达式可读取 props、state、`external` 和**先声明的 computed**：

```uix
<Widget name="PanelSummary" state="activeKeys: Vec<String> = []"
           computed="visible: activeKeys.filter(|key| key.length > 0), remaining: visible.length">
  <Text>剩余 {remaining}</Text>
</Widget>
```

转换器按源码顺序为每个派生值生成组件体局部 `let` 绑定；每次 View 展开重新求值，不建立缓存、依赖图或运行时状态槽。当前项不能引用自身或后续 computed，因此依赖顺序天然无环；自引用、前向引用、未声明外部符号及与 prop/state/external 的名称冲突均在编译期诊断。computed 是只读值，不能作为 `setState` 目标或句柄位绑定。

### 3.2 同步 action

`actions` 声明组件拥有的无参数同步 UI 交互操作。形式为 `'名称: 单表达式'` 或 `'名称: do { 语句... }'`，多个声明以顶层逗号分隔。action 只能从所属 Widget 模板的事件处理器调用：

```uix
<Widget name="Counter" state="count: 0, limit: 10"
        actions="increment: setState(count: count + 1), incrementSafely: do { let next = count + 1; if next > limit { setState(count: limit); return; } setState(count: next); }, reset: setState(count: 0)">
  <Text>Count: {count}</Text>
  <Button @click="incrementSafely()">Increment</Button>
  <Button @click="reset()">Reset</Button>
</Widget>
```

`do` 块支持 `let name = expression;`、已有局部的 `name = expression;`、`expression;`、`if expression { ... } else { ... }`、`return;` 与 `return expression;`。本阶段不支持 `match`、action 参数、异步、循环、解构、类型注解及 `break` / `continue`。

每个 action 块和 `if` 分支建立词法作用域。同一块不能重复 `let`；内层可以遮蔽外层局部或组件字段。`let` 初始化表达式先读取外层同名绑定，新局部从下一条语句起可见。赋值只允许写入最近的 action 局部，且编译器只把实际被赋值的 Rust 局部生成为可变绑定；组件 state 仍必须通过 `setState` 修改。表达式名称按“最近局部 → 组件字段/computed → 同组件 action → 内置 → external”解析。

转换器在事件表达式位置把 action 主体静态内联，再按源码顺序降低字段绑定、`setState`、`setStyle` 与普通调用；action 直接或间接调用的 `setStyle` 都绑定到发起调用的实际事件 View。生成物不包含 action 名称查找、运行时分发表或语言解释器。action 可以读取 props、state、computed，调用同组件其他 action、语言内建操作和 `external`，但不能隐式引用 `$event`。

每次 action 内联都建立独立的 Rust 标签块或等价局部控制流。`return` 只退出当前 action；被调用 action 的 `return` 不跳过调用方后续语句。`do` 块正常落空返回 `()`，`return expression;` 的值与各分支最终类型由 Rust 检查。`setState` 调用严格保持源码顺序。

action 与 props、state、computed、external 共享名称空间；重复、冲突、带参数调用、非事件位置调用及非法 `$event` 均在生成 Rust 前诊断。转换器为全部 action 建立静态调用图，并拒绝直接或间接递归。

action 只用于局部界面状态转换、样式/主题切换和 Rust 回调转发。参数化业务 Action、声明式业务返回类型、异步、服务、重试、事务和领域状态机不登记；相关逻辑由 Rust 实现，见[语言边界](../设计/语言边界.md)。

## 4. 类型化界面数据结构（Record）

`<Record>` 在顶层声明区定义供界面绑定和 Rust 边界共享的数据形状，字段类型使用与 state 注解相同的白名单，并可递归引用已声明 record、`Vec<number>` 与 `Vec<Record>` 等集合。`uix_items!` 宏把 record 生成为模块级 Rust 结构体，供 `uix!` 与 Rust 侧回调共同引用。Record 不拥有领域行为，也不取代 Rust 领域模型：

```uix
<Record name="Profile" fields="email: String, level: String, accepted: bool, volume: number" />
```

```rust
// Rust 侧生成模块级结构体，函数可直接引用语言面声明的类型。
uix_items!("src/main.uix");

fn submit_profile(model: Profile) -> Result<(), String> { ... }
```

```uix
// 声明本示例中表单界面绑定的数据形状。
<Record name="Profile" fields="email: String, level: String, accepted: bool, volume: number" />

// 声明持有 Profile 状态并调用 Rust 提交函数的表单组件。
<Widget name="FormPage" state="profile: Profile = { email: 'owner@example.com', level: '中级', accepted: true, volume: 35.0 }" external="submit_profile">
  // 把响应式 record 状态绑定到表单并转发提交事件。
  <Form model={profile} @submit="submit_profile">...</Form>
// 结束表单组件声明。
</Widget>
```

record 初始值使用对象字面量，字段必须与声明一一对应；record 名与组件共享 PascalCase 命名空间，重复声明与未声明引用在解析期诊断。

Record 名与组件共享 PascalCase 命名空间，字段只描述数据。业务校验、权限、持久化和状态转换由接收该结构的 Rust 代码负责。

## 5. 静态视觉记录（Visual）

`<Visual>` 在顶层声明区为既有 Rust 视觉结构提供具名静态值。Rust 类型只定义内核消费的字段形状，`.uix` 是尺寸、间距、比例、图标、展示文案和主题角色等值的唯一事实源；`uix_items!` 把声明生成为同模块只读 `static` 值及自动派生的 `_REF` 借用常量，构造、测量、布局、绘制与 `uix!` 组合根必须共同读取这组静态项。借用常量直接指向该 `static`，不生成第二份指针存储：

```rust
// Rust 只定义字体绘制内核需要的静态形状，不保存第二份默认值。
pub(crate) struct IconVisual {
    default_size: f32,
    glyph_scale: f32,
    color: ColorValue,
}

uix_items!("src/ui/widgets/general/icon/icon.uix");
```

```uix
<Visual
  name="ICON_VISUAL"
  type="IconVisual"
  defaultSize={24.0}
  glyphScale={0.85}
  color={icon_text_color()}
/>

<KernelView value={build_icon_view(kernel, ICON_VISUAL_REF)} />
```

Visual 字段必须具名；大型视觉契约应拆成多个有语义名称的 Visual，再由父 Visual 引用子静态值。固定数组可写为 `{[FIRST_VISUAL, SECOND_VISUAL]}`；组件实例应保存编译器生成的 `NAME_REF`，避免复制完整视觉表并保持单一静态地址。Visual 名称不能占用 `_REF` 后缀。禁止把几十个匿名数字继续塞进 `build_*_view(...)` 或嵌套构造器，也禁止在 Rust 中复制 `DEFAULT_*_VISUAL`、运行时解析 `.uix` 或用 `OnceLock` 固化第二份表。真实 UI 子树、条件和插槽仍使用普通 UIX 标签；Visual 不承载业务状态、事件算法、I/O 或生命周期。

## 6. 组合与复用

组件可嵌套其他组件（含自定义组件）；组件树深度不限，转换后对应 Rust 声明式 View 组合的嵌套，不因此生成额外的 `widget!` 类型或运行期模板对象。

### 6.1 内容插槽（Slot）

组件模板以 `<Slot />` 声明唯一默认插槽，以 `<Slot name="名称" />` 声明具名插槽。调用方直接子节点没有 `slot` 属性时进入默认插槽，`slot="名称"` 则进入同名占位：

```uix
<Widget name="Panel" props="title: String">
  <Container>
    <Text>{title}</Text>
    <Slot />
    <Container><Slot name="footer" /></Container>
  </Container>
</Widget>

<Panel title="用户信息">
  <Text>默认主体</Text>
  <Button slot="footer">保存</Button>
</Panel>
```

插槽内容在**调用方作用域**求值，不能读取被调用组件的私有 state；转换器先按调用方 props/state、`external` 与 For 局部绑定展开内容，再在模板占位处内联，不新增运行时状态或解释机制。调用方不提供某个插槽内容时，该占位为空且不报错；For 内的插槽内容按调用方当前项求值，被调用组件的 props/private state 则按同一实际 key 或位置路径隔离实例。

组件模板中的默认/具名 Slot 必须唯一，`name` 与调用方 `slot` 都必须是非空字符串字面量。未声明插槽接收子节点、未知具名目标、重复占位和动态归位名称均在编译期诊断。

## 7. 事件绑定

事件绑定使用 `@事件名="处理器"` 语法，事件名为 camelCase。常用事件：`@click`、`@mouseEnter`、`@mouseLeave`、`@change` 等（事件名与[事件文档](../../使用/交互与反馈/事件.md)对应，登记清单见[事件参考](../参考/事件.md)）。

处理器是**受限表达式**（见[表达式](表达式.md)），可调用同组件同步 action、内置操作、Rust 侧可见函数或回调 props：

```uix
// 声明 setStyle 引用的动态样式类。
hoverStyle {
  // 使用已登记的内边距属性提供悬停反馈。
  padding: 8px;
// 结束动态样式类声明。
}

// 声明事件示例拥有的状态与 Rust 外部回调。
<Widget name="EventExamples" state="count: 0" external="onConfirm, onClick">
  // 展示当前组件状态，供点击更新结果读取。
  <Text>Count: {count}</Text>
  // 事件处理器可以更新当前组件 state。
  <Button @click="setState(count: count + 1)">Increment</Button>
  // 事件处理器可以调用显式登记的 Rust 外部函数。
  <Button @click="onConfirm()">确认</Button>
  // 内置 setStyle 可以切换到当前文档声明的样式类。
  <Button @mouseEnter="setStyle('hoverStyle')">悬停</Button>

  // 需要事件信息时，只在处理器中显式传递事件参数 $event。
  <Container @click="onClick($event)">
    // 普通渲染树不读取只存在于处理器作用域的 $event。
    <Text>点击容器后由回调读取坐标</Text>
  // 结束可点击容器。
  </Container>
// 结束事件示例组件声明。
</Widget>
```

事件参数：处理器可显式接收事件对象 `$event`（编译为 Rust 事件参数），属性访问如 `$event.x`、`$event.value`、`$event.code` 必须存在于当前事件的字段登记表；未知字段在生成 Rust 前诊断，并列出合法字段。不需要事件信息时省略 `$event`。各事件类型的载荷字段登记见[事件参考](../参考/事件.md)。
