# 组件

[← 返回 UIX Lang 索引](../README.md)

> **接口**：声明 UIX Lang 的组件模型——组件定义、props、state、computed、类型化业务模型与事件绑定。依赖：[语法](语法.md)、[表达式](表达式.md)、[词法](词法.md)。导出：[控制流](控制流.md)、[编译契约](编译契约.md)。
>
> **状态声明**：已实现；prop 默认值、扩展状态与 record 类型、内容插槽及事件字段均由编译期转换器验证并展开。

## 1. 组件定义

`<Component>` 是组件定义标签，`name` 为必填属性，**只能出现在顶层声明区**；定义后即可在本文档及导入方以同名标签使用。

```uix
<Component name="HelloWorld">
  <Text>Hello, World!</Text>
</Component>
<HelloWorld />
```

## 2. 属性（props）

`props` 声明组件输入参数，形式为 `'name: Type'` 或 `'name: Type = 默认表达式'`，多个用 `,` 分隔；使用方通过同名属性传值，组件内以 `{name}` 引用。无默认值的 prop 必填；有默认值时调用方可省略，显式传值始终覆盖默认值。默认表达式仅允许字面量与已登记数据类型构造，不允许状态、回调或其他动态表达式。类型分基础值与回调两类：

| 类型 | 说明 |
|---|---|
| `String` / `number` / `bool` / `Date` / `Time` / `Color` / `Point` | 值类型 |
| `()` | 回调：无参无返回 |
| `(参数类型列表)` | 回调：带参无返回，如 `(String)` |
| `(参数类型列表) -> 返回类型` | 回调：带参带返回，如 `(String) -> bool` |

回调参数与返回类型限基础值类型（`String` / `number` / `bool`）。

**响应式状态引用**：props 也可声明 `State<T>` 类型（`State<String>` / `State<number>` / `State<bool>`）——使用方传入 Rust 侧创建的响应式状态，组件内读写即读写同一状态，实现跨组件共享数据：

```uix
// Rust 侧：let shared_count = State::new(0);（在 uix! 宏调用处可见）
<Component name="SharedCounter" props="count: State<number>">
  <Text>{count}</Text>
  <Button @click="setState(count: count + 1)">+1</Button>
</Component>
<SharedCounter count={sharedCount} />
```

> 共享状态模式：Rust 侧持有 `State<T>`，通过 props 传入组件；数据流向仍保持“props 进、回调或状态更新出”。UIX Lang 已登记绑定具有确定的 Rust 语义映射。

```uix
// 声明带默认值的问候组件。
<Component name="Greeting" props="name: String = 'UIX'">
  // 读取组件的字符串 prop。
  <Text>Hello, {name}!</Text>
// 结束问候组件声明。
</Component>

// 带返回值的回调：确认结果由 Rust 侧决定
<Component name="ConfirmButton" props="label: String, onConfirm: () -> bool">
  // 点击时调用由使用方传入的确认回调。
  <Button type="primary" @click="onConfirm()">{label}</Button>
// 结束确认按钮组件声明。
</Component>

// 带参回调：输入内容直接交给 Rust 侧处理
<Component name="SearchBox" props="keyword: State<String>, onSearch: (String)">
  // 受控输入框绑定使用方传入的响应式字符串状态。
  <Input value={keyword} @change="onSearch(keyword)" />
// 结束搜索框组件声明。
</Component>

// 使用唯一 Column 根组合三个 prop 示例。
<Column gap="8px">
  // 使用默认 name prop。
  <Greeting />
  // 从 Rust 调用处接收返回 bool 的确认回调。
  <ConfirmButton label="删除" onConfirm={doDelete} />
  // 从 Rust 调用处接收共享搜索状态与带参回调。
  <SearchBox keyword={searchKeyword} onSearch={doSearch} />
// 结束示例组合根。
</Column>
```

> 函数类型 props 的传值也是表达式：`onConfirm={doDelete}`——调用参数在调用方作用域求值，`doDelete` 只需在 `uix!` 宏展开处可见（见[表达式](表达式.md)）。

### 2.1 外部依赖（external）

组件体直接引用 Rust 侧函数、闭包或值时，必须通过 `external` 显式声明根标识符；多个名称使用逗号分隔：

```uix
<Component name="SearchBox" props="keyword: String, onSearch: (String)"
           external="debounce, format">
  <Input value={keyword} @change="debounce(onSearch, 300)" />
  <Text>{format(keyword)}</Text>
</Component>
```

组件体可见名称由 props、state、先声明的 computed、`For`/受限闭包局部变量、语言内建操作、数据类型构造器和 `external` 的并集组成。使用未声明名称时，转换器在对应表达式的 UIX 行列返回诊断；`external` 只声明依赖，不导入符号，最终 Rust 可见性和类型检查仍由宏调用点的编译负责。组件调用参数属于调用方作用域，不需要重复写入被调用组件的 `external`。

## 3. 状态（state）

`state` 声明组件私有状态，形式为 `'name: 初始值'`；组件内以 `{name}` 读取，通过 `setState` 更新：

```uix
<Component name="Counter" state="count: 0">
  <Text>Count: {count}</Text>
  <Button @click="setState(count: count + 1)">Increment</Button>
</Component>
<Counter />
```

`setState` 使用命名参数语法：`setState(name: 新值表达式)`，可一次更新多个：`setState(count: count + 1, done: true)`。

**类型注解**：初始值默认按字面量固定类型（字符串 → `String`、数字 → `f64`、布尔 → `bool`）。需要其他类型时使用 `'name: Type = 初始值'` 显式注解，白名单为 `String` / `number` / `bool` / `u32` / `usize` / `f32` / `i32` / `Date` / `Time` / `Color` / `Point` / `CascaderValue` / `HashSet<String>` / `Vec<String>` / `Vec<number>` / `Vec<UploadFile>` / `Vec<已声明Record>` / `Option<String>` / 文档内声明的 record 名：

```uix
<Component name="Rating" state="rating: u32 = 7, step: usize = 1, offset: f32 = 180, selected: Date = Date(2026, 8, 10), cities: HashSet<String> = []">
  <Rate value={rating} count="5" />
  <Button @click="setState(rating: rating + 1)">+1</Button>
</Component>
```

类型化状态的初始值与 `setState` 更新值都会保留作者书写的数字形状，整数字面量不会被组件 `number` 语义附加小数点。

**语义类型初始值**：`Date` / `Time` / `Color` / `Point` 使用数据类型构造调用初始化（见[词法 · 数据类型构造](词法.md#32-数据类型构造)）；`CascaderValue` 与 record 使用对象字面量；`HashSet<String>`、`Vec<String>`、`Vec<number>` 与 `Vec<Record>` 接受类型匹配的数组字面量，`Vec<UploadFile>` 仅接受空数组 `[]`；`Option<String>` 接受 `None` 或 `Some('文本')`。

**句柄位绑定**：受控组件与双向绑定属性（`open`、`value`、`checked`、`current`、`pageSize`、`offset`、`scrollY`、`model` 等）需要 `State<T>` 句柄。组件私有 state 与 `State<T>` props 在这些位置直接以句柄引用，无需由 Rust 侧创建状态槽：

```uix
<Component name="Feedback" state="open: false">
  <Button @click="setState(open: true)">打开</Button>
  <Modal open={open} @ok="setState(open: false)">...</Modal>
</Component>
```

引用只读 prop 或回调到句柄位属性时，编译期给出「句柄位属性」诊断。

### 3.1 派生值（computed）

`computed` 声明组件只读派生值，形式为 `'名称: 表达式'`，多个声明以顶层逗号分隔。表达式可读取 props、state、`external` 和**先声明的 computed**：

```uix
<Component name="PanelSummary" state="activeKeys: Vec<String> = []"
           computed="visible: activeKeys.filter(|key| key.length > 0), remaining: visible.length">
  <Text>剩余 {remaining}</Text>
</Component>
```

转换器按源码顺序为每个派生值生成组件体局部 `let` 绑定；每次 View 展开重新求值，不建立缓存、依赖图或运行时状态槽。当前项不能引用自身或后续 computed，因此依赖顺序天然无环；自引用、前向引用、未声明外部符号及与 prop/state/external 的名称冲突均在编译期诊断。computed 是只读值，不能作为 `setState` 目标或句柄位绑定。

## 4. 类型化业务模型（Record）

`<Record>` 在顶层声明区定义类型化业务模型，字段类型使用与 state 注解相同的白名单，并可递归引用已声明 record、`Vec<number>` 与 `Vec<Record>` 等集合。`uix_items!` 宏把 record 生成为模块级 Rust 结构体，供 `uix!` 与 Rust 侧回调共同引用：

```uix
<Record name="Profile" fields="email: String, level: String, accepted: bool, volume: number" />
```

```rust
// Rust 侧生成模块级结构体，函数可直接引用语言面声明的类型。
uix_items!("src/main.uix");

fn submit_profile(model: Profile) -> Result<(), String> { ... }
```

```uix
// 声明本围栏中组件状态依赖的业务模型。
<Record name="Profile" fields="email: String, level: String, accepted: bool, volume: number" />

// 声明持有 Profile 状态并调用 Rust 提交函数的表单组件。
<Component name="FormPage" state="profile: Profile = { email: 'owner@example.com', level: '中级', accepted: true, volume: 35.0 }" external="submit_profile">
  // 把响应式 record 状态绑定到表单并转发提交事件。
  <Form model={profile} @submit="submit_profile">...</Form>
// 结束表单组件声明。
</Component>
```

record 初始值使用对象字面量，字段必须与声明一一对应；record 名与组件共享 PascalCase 命名空间，重复声明与未声明引用在解析期诊断。

## 5. 组合与复用

组件可嵌套其他组件（含自定义组件）；组件树深度不限，与 Rust 函数组件/`component!` 的嵌套对应。

### 5.1 内容插槽（Slot）

组件模板以 `<Slot />` 声明唯一默认插槽，以 `<Slot name="名称" />` 声明具名插槽。调用方直接子节点没有 `slot` 属性时进入默认插槽，`slot="名称"` 则进入同名占位：

```uix
<Component name="Panel" props="title: String">
  <Container>
    <Text>{title}</Text>
    <Slot />
    <Container><Slot name="footer" /></Container>
  </Container>
</Component>

<Panel title="用户信息">
  <Text>默认主体</Text>
  <Button slot="footer">保存</Button>
</Panel>
```

插槽内容在**调用方作用域**求值，不能读取被调用组件的私有 state；转换器先按调用方 props/state、`external` 与 For 局部绑定展开内容，再在模板占位处内联，不新增运行时状态或解释机制。调用方不提供某个插槽内容时，该占位为空且不报错；For 内调用继续遵守既有逐实例 props/state 限制。

组件模板中的默认/具名 Slot 必须唯一，`name` 与调用方 `slot` 都必须是非空字符串字面量。未声明插槽接收子节点、未知具名目标、重复占位和动态归位名称均在编译期诊断。

## 6. 事件绑定

事件绑定使用 `@事件名="处理器"` 语法，事件名为 camelCase。常用事件：`@click`、`@mouseEnter`、`@mouseLeave`、`@change` 等（事件名与[事件文档](../../使用/交互与反馈/事件.md)对应，登记清单见[事件参考](../参考/事件.md)）。

处理器是**受限表达式**（见[表达式](表达式.md)），可调用内置操作、Rust 侧可见函数或回调 props：

```uix
// 声明 setStyle 引用的动态样式类。
hoverStyle {
  // 使用已登记的内边距属性提供悬停反馈。
  padding: 8px;
// 结束动态样式类声明。
}

// 声明事件示例拥有的状态与 Rust 外部回调。
<Component name="EventExamples" state="count: 0" external="onConfirm, onClick">
  // 展示当前组件状态，供点击更新结果读取。
  <Text>Count: {count}</Text>
  // 事件处理器可以更新当前组件 state。
  <Button @click="setState(count: count + 1)">Increment</Button>
  // 事件处理器可以调用显式登记的 Rust 外部函数。
  <Button @click="onConfirm()">确认</Button>
  // 内置 setStyle 可以切换到当前文档声明的样式类。
  <Button @mouseEnter="setStyle('hoverStyle')">悬停</Button>

  // 需要事件信息时，只在处理器中显式传递事件参数 $event。
  <Container @click="onClick($event)">
    // 普通渲染树不读取只存在于处理器作用域的 $event。
    <Text>点击容器后由回调读取坐标</Text>
  // 结束可点击容器。
  </Container>
// 结束事件示例组件声明。
</Component>

// 提供规范示例的唯一文档根。
<EventExamples />
```

事件参数：处理器可显式接收事件对象 `$event`（编译为 Rust 事件参数），属性访问如 `$event.x`、`$event.value`、`$event.code` 必须存在于当前事件的字段登记表；未知字段在生成 Rust 前诊断，并列出合法字段。不需要事件信息时省略 `$event`。各事件类型的载荷字段登记见[事件参考](../参考/事件.md)。
