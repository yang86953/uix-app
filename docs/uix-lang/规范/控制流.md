# 控制流

>
> **状态声明**：已实现；`If` / `ElseIf` / `Else` 由编译期转换器生成单次短路条件链。

## 1. If 条件渲染

`<If {条件表达式}>` 按条件决定是否渲染子节点。其后可紧邻任意个 `<ElseIf {条件表达式}>`，并以可选 `<Else>` 收尾：

```uix
<If {role == 'owner'}>
  <Text>主人面板</Text>
</If>
<ElseIf {loggedIn}>
  <Text>欢迎回来</Text>
</ElseIf>
<Else>
  <Button @click="login()">登录</Button>
</Else>
```

分支必须相邻，空白与注释不打断配对，其他元素会结束当前链。转换器只求值到第一个命中分支；孤立 `ElseIf` / `Else`、`Else` 后继续追加分支、重复 `Else` 或为 `Else` 提供条件都会在编译期诊断。

> 与 `visible` 样式的区别：`<If>` 不生成节点（等价 Rust `if` 分支），`visible` 保留节点但隐藏。

## 2. For 循环

`<For {变量名} in {数据表达式}>` 遍历数组渲染子节点；子节点内以 `{变量名}` 访问当前项。`{变量名}` 为单标识符绑定声明，`{数据表达式}` 为数据源。

需要索引时声明第二个绑定：`<For {item} {index} in {items}>`，子节点内以 `{index}` 访问下标（用于 `removeAt(index)` 等操作）。

需要稳定行身份时声明 `key`：`<For {item} in {items} key={item.id}>`——列表增删、重排时以 key 保留行身份（勾选态、滚动位置、动画状态不因位置变化而错位）。普通容器中的 For 对应 Rust `.key(key)`；作为 `VirtualScroll` 唯一直接模板时对应 `.render_keyed(key_fn, renderer)`，key 会在行构建前同时拥有节点协调与组件私有状态，行根不得再设置第二份 key。数据项无稳定 id 时省略（退化为按位置）。

```uix
// 声明循环示例拥有的列表状态。
<Component name="LoopExamples" state="items: Vec<String> = ['项目'], todos: Vec<String> = ['待办']">
<For {item} in {items}>
  // 直接渲染字符串列表的当前项。
  <Text>{item}</Text>
</For>

<For {todo} {i} in {todos}>
  <Button @click="setState(todos: todos.removeAt(i))">删除</Button>
</For>
// 结束持有循环状态的组件声明。
</Component>

// 提供规范示例的唯一文档根。
<LoopExamples />
```

## 3. 与组件私有状态的组合

For 内调用拥有私有状态或 props 的组件需要逐实例存储；转换器对不支持的情形给出定向诊断（见[编译契约 · 诊断模型](编译契约.md#4-诊断模型)）。
