# 控制流

[← 返回 UIX Lang 索引](../README.md)

> **接口**：声明 UIX Lang 的条件渲染与循环——`If` 与 `For`。依赖：[表达式](表达式.md)、[组件](组件.md)。导出：[样式与主题](样式与主题.md)。
>
> **状态声明**：混合契约。View 的 If / ElseIf / Else 与 For 已实现；Action 内 `match`、有界 `for`、`break / continue` 和异步结果分支为目标。

## 1. If 条件渲染

`<If {条件表达式}>` 按条件决定是否渲染子节点。其后可紧邻任意个 `<ElseIf {条件表达式}>`，并以可选 `<Else>` 收尾：

```uix
<If {role == 'owner'}>
  <Text>主人面板</Text>
</If>
<ElseIf {loggedIn}>
  <Text>欢迎回来</Text>
</ElseIf>
<Else>
  <Button @click="login()">登录</Button>
</Else>
```

分支必须相邻，空白与注释不打断配对，其他元素会结束当前链。转换器只求值到第一个命中分支；孤立 `ElseIf` / `Else`、`Else` 后继续追加分支、重复 `Else` 或为 `Else` 提供条件都会在编译期诊断。

> 与 `visible` 样式的区别：`<If>` 不生成节点（等价 Rust `if` 分支），`visible` 保留节点但隐藏。

## 2. For 循环

`<For {变量名} in {数据表达式}>` 遍历数组渲染子节点；子节点内以 `{变量名}` 访问当前项。`{变量名}` 为单标识符绑定声明，`{数据表达式}` 为数据源。

需要索引时声明第二个绑定：`<For {item} {index} in {items}>`，子节点内以 `{index}` 访问下标（用于 `removeAt(index)` 等操作）。

需要稳定行身份时声明 `key`：`<For {item} in {items} key={item.id}>`——列表增删、重排时以 key 保留行身份（勾选态、滚动位置、动画状态不因位置变化而错位）。普通容器中的 For 对应 Rust `.key(key)`；作为 `VirtualScroll` 唯一直接模板时对应 `.render_keyed(key_fn, renderer)`，key 会在行构建前同时拥有节点协调与组件私有状态，行根不得再设置第二份 key。数据项无稳定 id 时省略（退化为按位置）。

```uix
// 声明循环示例拥有的列表状态。
<Widget name="LoopExamples" state="items: Vec<String> = ['项目'], todos: Vec<String> = ['待办']">
<For {item} in {items}>
  // 直接渲染字符串列表的当前项。
  <Text>{item}</Text>
</For>

<For {todo} {i} in {todos}>
  <Button @click="setState(todos: todos.removeAt(i))">删除</Button>
</For>
// 结束持有循环状态的组件声明。
</Widget>

// 提供规范示例的唯一文档根。
<LoopExamples />
```

## 3. 与组件私有状态的组合

For 内可以调用带 props、private state、computed、事件与状态样式的自定义组件。props、computed 和事件适配器在每次实际迭代中建立；private state 与动画、transition、动态 class 等状态从组件的静态声明基座和当前完整 For 实例路径共同派生。

- 有 `key` 时，完整嵌套业务 key 路径拥有组件实例；增删或重排后，同 key、同组件调用位置继续复用私有状态。
- 无 `key` 时，完整嵌套位置路径拥有组件实例；它只适合顺序不变的数据，插入或重排会按新位置解释实例。
- 行移除、分支不再生成组件、key 改变或根类型改变时，旧节点不再承载其状态作用域，窗口树在协调事务结束时释放对应私有状态。
- 组件模板中的 Slot 仍在调用方循环作用域求值；被调用组件的 private state 不会泄漏给插槽内容。

因此，需要保留行内组件状态的数据必须提供稳定、唯一的业务 key；不能把数组位置误当成可重排数据的业务身份。

## 4. Action 控制流目标

> **状态**：目标。当前同步 Action 只支持 `if / else`、局部值、赋值、表达式和 `return`。

Action 目标上增加：

- `match value { pattern => do { ... } }`：用于 Enum、Option、Result、AwaitOutcome 和 bool，必须穷尽；
- `for item in values do { ... }`：只遍历有限集合；
- `break` / `continue`：只在 Action 的 `for` 内合法；
- `await service.call() within 30s`：结果显式区分 `Ok`、`Err`、`Cancelled`、`TimedOut`。

View 的 `<If>` / `<For>` 决定节点结构，Action 的 `if` / `match` / `for` 决定业务执行顺序；两者使用不同 AST，不允许把业务循环伪装成渲染循环或把 View 节点写入 Action 块。
