## 1. 编译时转换

`.uix` 文档在正式构建时由公开宏自动触发转换；当前 `uix-derive` AOT Adapter 把它转换为 Rust UI 代码并随调用 crate 一起编译，运行期不携带 UIX Lang 解释器。生成代码只构造界面、连接状态与事件，不取得业务 System 的职责。转换规则：

| UIX Lang | Rust API | 说明 |
|---|---|---|
| `<Button class="primary">` | `button("...").apply_style(...)` | 组件 + 样式类 |
| `@click="handler"` | `.on_click(...)` | 事件绑定 |
| `state="count: 0"` + `setState` | `State<T>` 私有状态槽 + 组件实例作用域 | 状态由窗口 `WidgetTree` 按静态调用声明和实际 key / 位置路径复用与清理 |
| `actions="toggle: expression, reset: do { ... }"` + 事件调用 | 事件位置静态内联的 Rust 表达式或标签块 | 无参数同步 UI action；不生成运行时 action 分发。`@actions { … }` 块级形式与之等价，同 `@props` / `@state` / `@computed` |
| `props="name: String = 'UIX'"` | 调用位类型化局部绑定 | 带默认值的组件输入；无默认值即必填 |
| `@theme light { ... }` | 主题令牌 `ThemeTokens` | 主题 |
| `baseButton { ... }` | `Style` 定义 | 样式类 |
| `<For {item} in {items}>` | `for` 循环生成 `ViewNode` 列表 | 循环渲染 |
| `<If {a}>...<ElseIf {b}>...<Else>...` | 单个 `if / else if / else` 分支 | 相邻短路条件链 |
| `<Visual name="ICON_VISUAL" type="IconVisual" ... />` | 同模块只读 `pub(crate) static ICON_VISUAL: IconVisual` | UIX 唯一拥有的具名静态视觉事实 |

> 映射为**语义等价**而非逐字对应：语言是 Rust API 的文本投影，每个结构都能翻译为确定的 Rust 声明式代码。

> UIX Lang `<Widget>` 会在调用位展开为声明式 View 代码，不是 Rust `widget!` 宏的别名。它的逻辑实例身份由编译器生成的作用域标记与 `WidgetTree` 内部状态存储共同维护，不需要为每个声明生成新的 Rust 组件类型。

导入、语法、语义和生成现已收口到共享 `uix-lang-compiler` Compiler System；AOT、`uix check`、`uix fmt`、`uix query` 与语言服务器（`uix-lang-ls`，`uix lsp` 委托同一实现）通过 Adapter 复用同一前端。文件输出同时保留同名 `.uixmap.json` 源码映射；阶段契约见[编译器架构](../设计/编译器架构.md)。

## 2. 公开宏契约

### 2.1 uix!

`uix!` 是 UIX 对外提供的编译期入口宏（proc-macro，当前由 `uix-derive` 实现）：

```rust
// 导入公开 uix! 宏与 ViewNode 类型。
use uix_app::prelude::*;

// 声明由应用组合根调用的界面构造函数。
fn build_view() -> ViewNode {
    // 编译期读取调用 crate 下的 src/main.uix 并生成 ViewNode。
    uix!("src/main.uix")
// 结束界面构造函数。
}
```

- `uix!(r#"<Text>Hello</Text>"#)`：把单个字符串字面量作为内嵌 UIX 源码转换。
- `uix!("path.uix")`：编译期读取并转换 `.uix` 文档；相对路径以调用 crate 的 `CARGO_MANIFEST_DIR` 为基准。
- 两种入口都生成一个 `ViewNode` 表达式；输入不是单个字符串字面量时由过程宏拒绝。
- 当前 `uix!` 返回 `ViewNode`；文档根为 `<App>` 时给出改用 `uix_app!` 的定向编译诊断。未来改变返回契约必须按[版本策略](../变更/版本策略.md)登记为破坏性变更。
- 宏把确定性 Rust 表达式写入 Cargo `$OUT_DIR/uix-lang-gen/<文档主名>-<稳定标识>.rs`，并以 `include!` 返回；相同输入复用相同路径且内容不变时不重写文件。内嵌源码按内容隔离，避免同一 crate 的多个宏调用互相覆盖。

### 2.2 uix_app!

`uix_app!("path.uix")` 要求 `<App>` 根并返回现有 `App` builder，不调用 `.run()`、不创建第二套应用或窗口所有者：

```rust
// 从 UIX 文档构建 App，并继续使用现有 Rust 生命周期扩展点。
uix_app!("src/main.uix")
    // 配置语言面范围外的启动钩子。
    .on_start(|handle| { /* ... */ })
    // 由调用方决定何时进入事件循环。
    .run();
```

- `theme` 在宏展开期按“同文档 `@theme` 优先、内建 `light` / `dark` 次之”解析；未知初始主题与未知 `setTheme('...')` 目标均编译失败。同名文档主题覆盖内建预设，主题表归当前 `App` 实例所有。
- `@theme` 白名单与运行时 `DesignTokens` 实际颜色、排版、间距、尺寸、阴影、动效、断点和明暗字段闭合对齐；`primaryColor` / `backgroundColor` 兼容别名保留色板推导语义。样式中的 `#tokenName` 按颜色或数值类型验证，未知或不兼容 token 在生成期失败。
- `类名:hover/:disabled/:checked` 在编译期登记为同前缀基础类的差异层；hover 使用既有组件状态存储和指针事件，disabled / checked 使用元素同名事实，不新增运行时契约。选择优先级为 disabled > checked > hover，未声明字段保留基础值。

### 2.3 uix_items!

`uix_items!("path.uix")` 生成两类模块级项目：顶层 `<Record>` 对应公开 Rust 数据结构体（见[组件 · Record](组件.md#4-类型化界面数据结构record)），顶层 `<Visual name="NAME">` 对应只读 `pub(crate) static NAME: Type` 值与直接指向它的 `pub(crate) const NAME_REF: &'static Type` 借用常量（见[组件 · Visual](组件.md#5-静态视觉记录visual)）。该入口允许文件只有模块级声明，适合被多个 Rust widget 共享的纯视觉资源；同一文件若交给 `uix!` 或 `uix_app!`，仍必须包含唯一显式根。Record 只共享界面数据形状；Visual 只提供 Rust 内核消费的静态 UI 值；两者都不得承载业务行为或创建运行时解释路径。

## 3. 当前框架能力使用模式

UIX Lang 只负责界面、组件界面状态、事件表达式和无参数同步 UI action；业务、定时异步、多窗口编排、国际化资源加载、平台能力与运行保障按以下模式由 Rust 接入。`uix!` 返回 `ViewNode`，`uix_app!` 返回现有 `App` builder；应用生命周期入口以 Rust [使用文档](../../使用.md)为准：

1. **调用类——Rust 回调**：业务与平台函数通过回调 props 或 `external` 显式暴露给界面（见[表达式](表达式.md)）：

   ```uix
   <Button @click="notify('保存成功')">保存</Button>
   <Text>{formatTime(now())}</Text>
   ```

2. **驱动类——Rust 侧驱动，UI 侧响应**：Rust 侧定时器 / 异步任务更新 `State`，界面经 props 或表达式响应式感知：

   ```uix
   // Rust 侧：每秒 clock.update(|v| *v += 1)（State<u64>，作为 props 传入）
   <Text>{clock}</Text>
   ```

   （`State` props 见[组件 · props](组件.md#2-属性props)）

3. **配置类——App 属性与 Rust 入口**：启动配置走 `<App>` 属性（`title` / `size` / `theme` / `settings`）；其余链式配置（`.on_start()`、`.enable_agent_control()` 等）在 Rust 入口完成，详见[配置](../../使用/框架设施/配置.md)与[Agent 控制](../../使用/能力与边界/Agent控制.md)。

长期边界：同步 action 只承接局部界面状态转换和呈现条件；异步、服务、业务判断、导航与应用生命周期始终由 Rust 承接。这不是待补齐的语言缺口。

## 4. 编译模式边界

- **正式 AOT**：默认且必须可独立交付；UI 描述静态生成 Rust，发布产物不携带解析器、解释器或字节码虚拟机。
- **开发工具**：`uix check`、`uix fmt`、`uix compile`、`uix query`、`uix scaffold visual`、语言服务器（`uix-lang-ls`）复用同一 Compiler System、语法和 schema，但不能执行业务流程，也不能进入默认发布依赖。
- **纯 UI 热重载 Adapter**：仅在显式启用 `uix-lang-compiler/hot-reload` 时可用，固定处理 `View`；调用方提交 overlay 后得到新的 AOT `CompileOutput` 或相同 `CompilationKey`。它不监视文件、不解释或加载结果，编译失败也不得替换上次成功身份。
- **生产动态业务**：远程业务脚本、插件工作流和字符串服务分发不属于 UIX Lang。

静态入口不得因解析失败或能力缺失自动退化为动态执行。无论使用何种开发工具，Rust Application System 始终拥有业务状态、失败语义和生命周期。

## 5. 诊断模型

> 注：本文及 UIX Lang 文档中的「诊断」指**编译期诊断**（编译器错误提示），与框架运行时诊断系统（错误收集、恢复协调与崩溃报告，见[架构 · diagnostics](../../架构/platform/diagnostics.md)）是不同概念。

- 未登记标签、属性、事件、数据类型：编译期诊断，携带组件名 / 属性名、所属文档类别与修复建议，不静默生成占位 View（容错可观测原则）。
- 语法与结构错误：带源码位置（SourceSpan）与修复建议。
- 表达式语义错误（名称、类型、借用）：由 Rust 编译器兑底；错误位置指向 `$OUT_DIR/uix-lang-gen` 下可查看的生成文件，每段用户表达式前都有 `// [uix-lang] 文档:行:列` 注释，可回溯 `.uix` 原始位置。
- 解析期和 UIX 语义诊断继续直接使用 SourceSpan 指向 `.uix` 行列，不经过生成文件回映。
- 能力门禁：组件要求使用方启用对应 Cargo feature 时，未启用会得到定向诊断。
- 条件链门禁：孤立或被其他元素打断的 `ElseIf` / `Else`、重复尾分支与非法属性在生成前诊断。
- 组件输入门禁：调用缺失无默认值 prop 时诊断；默认值仅接受字面量和已登记数据类型构造。
- 事件载荷门禁：`$event` 及其字段必须属于当前 `(标签, 事件名)` 登记；同名事件不能跨组件推断载荷，未知字段诊断会列出合法字段。
- 类型化值门禁：数组、Option 与嵌套 record 初始值按声明类型递归验证，不把不匹配值交给 Rust 侧兜底。
- 组件专属值类型门禁：schema 登记的载荷类型（如 `CascaderValue`、`Vec<UploadFile>`）要求拥有它的 Cargo capability；未启用时在生成前给出定向诊断（与组件 capability 同一模型），不再等到 rustc 报公开符号缺失。
- action 门禁：块级重复局部、非法局部赋值、非法 `$event`、非事件调用、参数调用及静态调用图中的直接/间接递归均在生成前诊断；Rust 标签块保证嵌套 action 的 `return` 仅退出自身。
- 职责门禁：Service、异步 action、业务流程和生命周期结构未登记，必须编译期拒绝，不生成占位代码。

## 6. 维护约定

- 只有属于 UI 描述职责的语言能力可以进入规范；业务能力由 Rust 文档和对应 System 契约持有。
- 目标阶段与责任边界见[编译器架构](../设计/编译器架构.md)，完整实施顺序与验收标准由任务体系持有，历史设计依据见[目标设计](../变更/目标设计.md)。
- 公开示例变化时运行对应的外部消费者 `*_public_api.rs`；纯文档结构与链接不建立项目测试。
