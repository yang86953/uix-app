## 1. 编译时转换

`.uix` 文档在编译期由 **uix-app 框架自动转换**为 Rust 声明式代码（等价于过程宏展开），随 crate 一起编译；运行期无解释器、无额外开销。转换规则：

| UIX Lang | Rust API | 说明 |
|---|---|---|
| `<Button class="primary">` | `button("...").apply_style(...)` | 组件 + 样式类 |
| `@click="handler"` | `.on_click(...)` | 事件绑定 |
| `state="count: 0"` + `setState` | `component!` 私有状态 | 有状态组件 |
| `props="name: String"` | 函数组件参数 / `component!` 字段 | 组件输入 |
| `@theme light { ... }` | 主题令牌 `ThemeTokens` | 主题 |
| `baseButton { ... }` | `Style` 定义 | 样式类 |
| `<For {item} in {items}>` | `for` 循环生成 `ViewNode` 列表 | 循环渲染 |
| `<If {cond}>` | `if cond { ... }` 分支 | 条件渲染 |

> 映射为**语义等价**而非逐字对应：语言是 Rust API 的文本投影，每个结构都能翻译为确定的 Rust 声明式代码。

## 2. 公开宏契约

### 2.1 uix!

`uix!` 是 uix-app 提供的编译期入口宏（proc-macro）：

```rust
// 导入公开 uix! 宏与 ViewNode 类型。
use uix::prelude::*;

// 声明由应用组合根调用的界面构造函数。
fn build_view() -> ViewNode {
    // 编译期读取调用 crate 下的 src/main.uix 并生成 ViewNode。
    uix!("src/main.uix")
// 结束界面构造函数。
}
```

- `uix!(r#"<Text>Hello</Text>"#)`：把单个字符串字面量作为内嵌 UIX 源码转换。
- `uix!("path.uix")`：编译期读取并转换 `.uix` 文档；相对路径以调用 crate 的 `CARGO_MANIFEST_DIR` 为基准。
- 两种入口都生成一个 `ViewNode` 表达式；输入不是单个字符串字面量时由过程宏拒绝。
- `uix!` 永久保持 `ViewNode` 契约；文档根为 `<App>` 时会给出改用 `uix_app!` 的定向编译诊断。

### 2.2 uix_app!

`uix_app!("path.uix")` 要求 `<App>` 根并返回现有 `App` builder，不调用 `.run()`、不创建第二套应用或窗口所有者：

```rust
// 从 UIX 文档构建 App，并继续使用现有 Rust 生命周期扩展点。
uix_app!("src/main.uix")
    // 配置语言面范围外的启动钩子。
    .on_start(|handle| { /* ... */ })
    // 由调用方决定何时进入事件循环。
    .run();
```

- `theme` 在宏展开期按“同文档 `@theme` 优先、内建 `light` / `dark` 次之”解析；未知初始主题与未知 `setTheme('...')` 目标均编译失败。同名文档主题覆盖内建预设，主题表归当前 `App` 实例所有。
- 第一版 `@theme` 生成白名单为 `primaryColor` 与 `backgroundColor`；样式中的 `#primaryColor` / `#backgroundColor` 保留为运行期主题令牌引用，切换主题后随当前 token 更新。

### 2.3 uix_items!

`uix_items!("path.uix")` 把文档顶层声明的 `<Record>` 生成为模块级 Rust 结构体（见[组件 · Record](组件.md#4-类型化业务模型record)）。

## 3. 框架能力使用模式

uix-lang 只描述界面；框架能力（定时异步、多窗口、国际化、平台能力、运行保障等）不属于 UI 描述，按以下三种模式使用，**无需新语法**。`uix!` 返回 `ViewNode`，`uix_app!` 返回现有 `App` builder；具体应用生命周期入口以 Rust [使用文档](../../使用.md)为准：

1. **调用类——Rust 函数直调**：业务与平台函数在 `uix!` 宏调用处可见即可调用（见[表达式](表达式.md)）：

   ```uix
   <Button @click="notify('保存成功')">保存</Button>
   <Text>{formatTime(now())}</Text>
   ```

2. **驱动类——Rust 侧驱动，UI 侧响应**：Rust 侧定时器 / 异步任务更新 `State`，界面经 props 或表达式响应式感知：

   ```uix
   // Rust 侧：每秒 clock.update(|v| *v += 1)（State<u64>，作为 props 传入）
   <Text>{clock}</Text>
   ```

   （`State` props 见[组件 · props](组件.md#2-属性props)）

3. **配置类——App 属性与 Rust 入口**：启动配置走 `<App>` 属性（`title` / `size` / `theme` / `settings`）；其余链式配置（`.on_start()`、`.enable_agent_control()` 等）在 Rust 入口完成，详见[配置](../../使用/配置.md)与[Agent 控制](../../使用/Agent控制.md)。

原则：界面只声明「长什么样、响应什么」；复杂逻辑不属于界面描述，留在 Rust 侧。

## 4. 诊断模型

- 未登记标签、属性、事件、数据类型：编译期诊断，携带组件名 / 属性名、所属文档类别与修复建议，不静默生成占位 View（容错可观测原则）。
- 语法与结构错误：带源码位置（SourceSpan）与修复建议。
- 表达式语义错误（类型、借用）：由 Rust 编译器兑底；错误位置当前指向宏调用处，行号回映为[目标设计](../变更/目标设计.md#设计-2错误回映与组件封装边界)。
- 能力门禁：组件要求使用方启用对应 Cargo feature 时，未启用会得到定向诊断。
