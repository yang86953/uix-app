# 模块系统

[← 返回 UIX Lang 索引](../README.md)

> **文档角色**：规范——持有当前文件导入、导出、可见性、合并和递归依赖契约。
>
> **接口**：声明 UIX Lang 的多文件组织——`@import` / `@export` 与增量编译。依赖：[语法](语法.md)、[组件](组件.md)。导出：[编译契约](编译契约.md)。
>
> **状态声明**：组件、样式、主题、Record 和 Visual 的文件导入已实现。模块系统只组织 UI 描述，不导入或定义业务 Service。

## 1. 文件入口限定

`@import` 只在传给 `uix!`、`uix_app!`、`uix_items!` 的 `.uix` 文件中生效；内嵌源码没有稳定的相对目录，因此使用 `@import` 会得到编译期诊断。

## 2. 路径基准

相对路径以当前写出 `@import` 的文件为基准，而不是统一相对根文件；嵌套导入按各自文件逐级解析，依赖图必须无环。

## 3. 导入

`@import('path')` 引入目标文件显式导出的全部组件；`@import('path', 'WidgetName')` 只引入指定组件及其在该文件内依赖的私有组件。

## 4. 导出

`@export('Widget1', 'Widget2')` 显式导出同一导入单元中存在的组件；没有 `@export` 的文件不能被导入，未导出的组件不能被具名导入。

## 5. 合并规则

导入文件自身的根元素不会进入调用方；样式类、主题、`Record`、`Visual` 与所选组件一起进入编译文档。同名声明来自不同文件时立即报错，同一声明经多条选择性导入重复到达时幂等合并。

## 6. 增量编译

根文件及全部递归导入文件都由宏登记为编译依赖，任一文件变化都会触发调用 crate 重新编译；文件读取、UTF-8、循环、缺失导出与重复声明错误会保留具体来源路径。

```text
@import('./widget.uix')
@import('./widget.uix', 'MyWidget') // 只引入 MyWidget
@export('Widget1', 'Widget2')
```

每个可导入文件仍须满足“一份文档、一个根元素”的语法；该根用于文件独立检查，被其他文件导入时忽略。例如组件库可以把其中一个公开组件写作根元素。

## 7. 导出边界

`@export` 只公开 UI 文档内的 Widget；其依赖的 Record、Visual、样式和主题按当前合并规则进入编译文档。根文件与所有递归导入形成唯一 UI 源码图，供 AOT 与文档工具消费。

业务函数和服务由 Rust 模块系统组织，通过回调 props、`external` 或组合根注入，不由 `@import` / `@export` 管理。循环、缺失导出、不可见 UI 声明、命名冲突和非幂等重复必须保留完整来源链诊断。
