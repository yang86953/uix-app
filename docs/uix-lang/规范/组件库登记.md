# 组件库登记

[← 返回语言索引](../README.md)

框架编译器通过项目提供的声明识别具体组件，不在代码中固定某个组件库的标签集合。本页维护加载、校验与生成合同；每个组件库独立维护其控件 API 和用法。

## 加载入口

应用的 `uix.json` 在 `packages` 中列出候选库路径。默认描述文件是各库根的 `uix-library.json`，也可通过包项的 `descriptor` 指定文件名。

`Builder::from_env()` 按项目位置读取目录；`Builder::library(path)` 可显式增加声明。工具与第三方集成通过 `ComponentCatalog` 的公开读取接口加载相同内容，CLI、LSP 与编译器会话应使用同一项目目录。

## 声明事实

| 声明项 | 编译器消费的事实 |
| --- | --- |
| `units` | 实现模块、传递依赖、外部依赖和资源的归属 |
| `components` | 标签所属单元、构造表达式、属性、事件与子节点合同 |
| `data_constructors` / `value_types` | 库自有的数据构造和状态载荷类型 |
| `symbols` / `enums` | 共享门面名字与分支的归属 |
| `text_factory` / `theme_factory` | 库提供的文本与主题创建表达式 |
| `generated` / `install` | 门面模板与安装语句插入点 |
| `module_view` | 模块视图的属性、事件和子节点描述 |

构造表达式中的占位符由编译器绑定，调用的是声明指向的 Rust API。框架负责检查形状与归属，不执行组件库提供的构建脚本来决定裁剪结果。库声明不存在的标签不会自动退回到运行时解释。

## 检查与生成

编译器把源文件可达的标签、属性、数据构造、主题与子节点转换为已登记 Rust 表达式，同时收集所需单元。未知标签、错误的属性类型、非法子结构或缺失能力应在编译期产生带源位置的诊断。

本框架直接支持的结构和组装入口见 [框架节点](../参考/框架节点.md)。具体组件的默认值和回调载荷由其库声明给出，框架不复制维护具体控件属性表。

## 使用根与交付

UIX 可达源提供自动根，Rust 调用提供显式根，动态入口提供预先批准的候选根。构建器统一计算依赖与资源闭包，然后生成只含所选实现的目标源码视图。

Host 上的编译器依赖与 target 上的应用依赖分开处理；未使用库或组件的专属实现不因候选目录存在就进入目标。完整预构建流程见 [使用方按需编译](../../架构/使用方按需编译.md)。

## 动态 UI

模块运行时保留库定义的字符串视图标识与拥有型数据，组件库提供投影器。脚本宿主接收类型擦除的 UI payload，解析器通过公开注册入口登记；框架负责能力与生命周期检查，不拥有具体控件枚举。

正式构建中，装载和解析器登记均检查预生成动态白名单。新控件要求更新配置并重新构建，热重载不能增加未编译能力。
