## 1. 形式化文法（EBNF）

```ebnf
document       := declaration* root_element

declaration    := import_decl
                | export_decl
                | style_class
                | theme_block
                | widget_def
                | record_def

import_decl    := '@import' '(' string_literal (',' string_literal)? ')'
export_decl    := '@export' '(' string_literal (',' string_literal)* ')'

style_class    := class_name '{' style_declaration* '}'
class_name     := identifier
style_declaration := style_property ':' style_value ';'

theme_block    := '@theme' identifier '{' theme_declaration* '}'
theme_declaration := theme_property ':' theme_value ';'

widget_def  := '<Widget' 'name' '=' string_literal
                  ('props' '=' string_literal)?
                  ('state' '=' string_literal)?
                  ('computed' '=' string_literal)?
                  ('external' '=' string_literal)?
                  '>' node* '</Widget>'

record_def     := '<Record' 'name' '=' string_literal
                  'fields' '=' string_literal '/>'

root_element   := element | app_element
app_element    := '<App' app_attribute* '>' node* '</App>'

element        := '<' tag_name attribute* '>' node* '</' tag_name '>'
                | '<' tag_name attribute* '/>'

tag_name       := PascalCase_identifier
attribute      := attribute_name '=' attribute_value
attribute_value:= string_literal | expression

node           := element | text_node | expression_interpolation
                | control_flow | slot

control_flow   := if_chain | for_element
if_chain       := if_element elseif_element* else_element?
if_element     := '<If' '{' expression '}' '>' node* '</If>'
elseif_element := '<ElseIf' '{' expression '}' '>' node* '</ElseIf>'
else_element   := '<Else>' node* '</Else>'
for_element    := '<For' '{' identifier '}' ('{' identifier '}')?
                  'in' '{' expression '}' ('key' '=' '{' expression '}')?
                  '>' node* '</For>'

slot           := '<Slot' ('name' '=' string_literal)? '/>'

expression     := <见 [表达式](表达式.md)>
```

文法记号：`*` 零次或多次，`?` 零次或一次，`|` 选择，`()` 分组；`PascalCase_identifier` 与 `identifier` 的词法见[词法](词法.md)。解析器对未登记标签、属性与格式错误给出带位置与修复建议的诊断（见[编译契约](编译契约.md)）。

## 2. 文档结构

一个 `.uix` 源文件由**顶层声明区**与**一个根元素**构成：

- **顶层声明区**（位于文档开头、元素树之外）：`@import` / `@export` 指令、样式类定义、`@theme` 主题、`<Widget>` 组件定义、`<Record>` 业务模型。**组件定义与样式声明不允许出现在元素树内部**。
- **根元素**：通常为 `<App>` 或一个自定义组件，是界面树的起点。

### 2.1 App 根元素

`<App>` 只由 `uix_app!` 消费，必须恰有一个可渲染直接子元素；多个页面根需要显式包入 `Column` 或 `Container`。

| 属性 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `title` | 字符串 | — | 窗口标题 |
| `size` | 字符串 | — | 窗口尺寸（`"宽x高"`，如 `"400x300"`） |
| `theme` | 字符串 | `light` | 初始主题名 |
| `settings` | 字符串 | — | 持久化文件路径（对应 Rust `.settings(path)`） |

四项属性均为字符串字面量，`size` 在宏展开期按正 `i32` 的 `宽x高` 严格校验。`uix_app!` 返回现有 `App` builder 而不调用 `.run()`，因此 `.on_start()`、`.custom_title_bar()`、`.enable_agent_control()` 等生命周期扩展仍在 Rust 侧链式配置。

```text
// 顶层声明区
@theme light { ... }
baseButton { ... }
<Widget name="HelloWorld">...</Widget>

// 根元素
<App theme="light">
  <HelloWorld />
</App>
```

## 3. 元素

### 3.1 标签

标签名对应组件；内置组件见[组件参考](../参考/组件/布局组件.md)与[组件速查](../../使用/界面构建/组件速查.md)，自定义组件见[组件](组件.md)。

### 3.2 属性

属性写在开始标签内，形式为 `属性名="字面量"` 或 `属性名={表达式}`：

```uix
<Text fontSize="18px" color="#FF5722">文本</Text>
<Text fontSize={titleSize}>动态字号</Text>
<Button disabled={isBusy}>保存</Button>
```

属性值只有两类：**字面量**（字符串 / 数字 / 布尔 / 颜色）与**表达式** `{expr}`。属性值不接受标签；对象表达式只允许用于已登记的结构属性。

### 3.3 文本与表达式

- 元素内容中的纯文本直接书写。
- 表达式用单花括号 `{expr}` 包裹，在文本节点中即插值：

```uix
<Text>Count: {count}</Text>
<Text>Hello, {name}!</Text>
```

`Text` 中只要出现插值，生成器就会建立 `DynamicLabel` 延迟求值闭包。组件 `State` 在闭包执行时读取并登记到该文本节点；状态变化只使该节点的绘制失效，不会因为文本值变化而重建整棵 View。用于 `If`、`For`、`key` 或布局属性等结构位置的状态表达式仍在 View 构建时读取，并按结构依赖触发 reconcile。

文本中需要字面花括号时转义：`\{` 与 `\}`。示例：`<Text>函数签名: \{name\}</Text>` 显示为「函数签名: {name}」。

### 3.4 嵌套与自闭合

- **嵌套**：标签可任意嵌套形成层次结构；根元素唯一。
- **自闭合**：无子节点的元素可写作 `<Element />`。

```uix
<Container direction="row" gap="8px">
  <Icon name="star" />
  <Text>嵌套结构</Text>
</Container>
```
