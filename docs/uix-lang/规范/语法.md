# 语法

>
> **接口**：声明 UIX Lang 当前的 UI 文档结构与元素文法。依赖：[词法](词法.md)。导出：[表达式](表达式.md)、[组件](组件.md)、[控制流](控制流.md)、[模块系统](模块系统.md)。

## 1. 结构 EBNF

本节只描述文档结构。大写名称是下表逐项定义的词法单元或子文法，不是未定义的非终结符：

```ebnf
document          := import_decl* declaration* root_element
items_document    := import_decl* declaration* root_element?

declaration       := export_decl
                   | style_class
                   | theme_block
                   | record_def
                   | visual_def
                   | widget_def

import_decl       := '@import' '(' SQ_STRING (',' SQ_STRING)* ')'
export_decl       := '@export' '(' SQ_STRING (',' SQ_STRING)* ')'

style_class       := IDENTIFIER '{' STYLE_MEMBER* '}'
theme_block       := '@theme' IDENTIFIER '{' THEME_MEMBER* '}'

record_def        := '<Record' name_attr fields_attr '/>'
visual_def        := '<Visual' visual_name_attr visual_type_attr
                       visual_field+ '/>'
widget_def        := '<Widget' name_attr
                       member_attr* external_attr?
                     '>' widget_member* node* '</Widget>'

name_attr         := 'name' '=' DQ_TEXT
visual_name_attr  := 'name' '=' DQ_TEXT
visual_type_attr  := 'type' '=' DQ_TEXT
visual_field      := ATTRIBUTE_NAME '=' (DQ_TEXT | '{' EXPRESSION '}')
fields_attr       := 'fields' '=' DQ_TEXT
member_attr       := props_attr | state_attr | computed_attr | actions_attr
props_attr        := 'props' '=' DQ_TEXT
state_attr        := 'state' '=' DQ_TEXT
computed_attr     := 'computed' '=' DQ_TEXT
actions_attr      := 'actions' '=' DQ_TEXT
external_attr     := 'external' '=' DQ_TEXT

widget_member     := '@props' '{' FIELD_TEXT? '}'
                   | '@state' '{' FIELD_TEXT? '}'
                   | '@computed' '{' FIELD_TEXT? '}'
                   | '@actions' '{' FIELD_TEXT? '}'

root_element      := app_element | element
app_element       := '<App' app_attribute* '>' node+ '</App>'
app_attribute     := attribute | event_attribute
element           := '<' TAG_NAME (attribute | event_attribute)*
                       '>' node* '</' TAG_NAME '>'
                   | '<' TAG_NAME (attribute | event_attribute)* '/>'
attribute         := ATTRIBUTE_NAME ('=' (DQ_TEXT | '{' EXPRESSION '}'))?
event_attribute   := '@' EVENT_NAME '=' DQ_TEXT
node              := element
                   | TEXT
                   | '{' EXPRESSION '}'
                   | view_control_flow
                   | slot_element

view_control_flow := if_chain | for_element
if_chain          := if_element elseif_element* else_element?
if_element        := '<If' '{' EXPRESSION '}' '>' node* '</If>'
elseif_element    := '<ElseIf' '{' EXPRESSION '}' '>' node* '</ElseIf>'
else_element      := '<Else>' node* '</Else>'
for_element       := '<For' '{' IDENTIFIER '}' ('{' IDENTIFIER '}')?
                       'in' '{' EXPRESSION '}'
                       ('key' '=' '{' EXPRESSION '}')?
                     '>' node* '</For>'

slot_element      := '<Slot' name_attr? '/>'
```

| 单元 | 定义所有者 |
|---|---|
| `IDENTIFIER` / `TAG_NAME` / `ATTRIBUTE_NAME` / `EVENT_NAME` | [词法 · 命名规范](词法.md#1-命名规范)；事件名前导 `@` 不属于名称本身 |
| `SQ_STRING` / `DQ_TEXT` | [词法 · 引号规则](词法.md#3-字面量)；前者是单引号字符串，后者是双引号属性内容 |
| `EXPRESSION` | [表达式规范](表达式.md) |
| `STYLE_MEMBER` / `THEME_MEMBER` | [样式与主题](样式与主题.md)及[样式属性参考](../参考/样式属性.md) |
| `TEXT` | 标签间文本；`{` 需按词法规则转义，插值由独立表达式节点表示 |

开始标签与结束标签必须同名；父子限制、叶节点限制、属性值类别和 capability 由对应[组件参考](../README.md#参考)校验。结构文法不把任意 `TAG_NAME` 自动变成已登记标签。

`uix!` 与 `uix_app!` 使用 `document`，始终要求唯一显式根；`uix_items!` 使用 `items_document`，共享 Record/Visual 资源可以只有顶层声明，也可与普通视图文档共用同一文件。`<Visual>` 只能位于根元素之前并使用自闭合标签。`name` 必须是合法的 `SCREAMING_SNAKE_CASE` Rust 静态项名且不能占用 `_REF` 后缀，`type` 必须是同模块 PascalCase Rust 结构名，其余属性按 camelCase 或 snake_case 映射到具名 Rust 字段。花括号值必须是可用于 Rust 静态初始化的受限 `const` 表达式；Visual 顶层数组生成固定 Rust 数组，而不是界面 state 使用的 `Vec`。

## 2. Widget 成员

成员声明存在**属性形式**与**块级形式**两种等价写法；同一成员只能选择其一，双写在编译期拒绝。

块级形式（推荐用于多字段声明）：

```uix
<Widget name="Counter">
  @props {
    label: String,
  }
  @state {
    count: 0,
  }
  @computed {
    caption: label + count,
  }
  @actions {
    increment: setState(count: count + 1),
  }
  <Button @click="increment()">{caption}</Button>
</Widget>
```

属性形式（保留兼容，短声明仍然简洁）：

```uix
<Widget name="Counter"
        props="label: String"
        state="count: 0"
        computed="caption: label + count"
        actions="increment: setState(count: count + 1)"
        external="submit_count">
  <Button @click="increment()">{caption}</Button>
</Widget>
```

- `props` 声明界面输入和 Rust 回调；
- `state` 声明当前组件实例拥有的界面状态；
- `computed` 声明只读展示派生值；
- `actions` 组合当前事件中的局部 UI 状态更新和回调调用；
- `external` 显式列出组件体引用的 Rust 符号；external 只有字符串属性形式，不提供块级写法。

两种形式的声明体使用完全相同的 `name: value` 逗号列表语法；块级形式允许尾随逗号以便多行维护（成员列表统一放宽到属性形式）。成员块的约束：

1. 只能出现在 `<Widget>` 模板内部、作为直接子节点；普通元素内的同形文本保持文本语义；
2. 同一成员类别最多一个声明块，且与同名属性形式互斥；
3. 成员块是纯声明载体，不进入视图体，也不参与 Slot 归位。

这些成员不得用来取得业务 System 的状态所有权。领域真值通过 Rust 持有的 `State<T>` / props 输入，业务操作通过回调 props 或 `external` 进入 Rust。

## 3. 类型语法

不同声明位置使用不同的闭合类型集合，不能把 state 白名单自动当作 prop 或回调白名单：

```ebnf
prop_type          := value_prop_type
                    | callback_type
                    | 'State' '<' shared_state_type '>'
value_prop_type    := 'String' | 'number' | 'bool'
                    | 'Date' | 'Time' | 'Color' | 'Point'
shared_state_type  := 'String' | 'number' | 'bool'

callback_type      := '(' callback_args? ')' ('->' callback_return)?
callback_args      := callback_value (',' callback_value)*
callback_value     := 'String' | 'number' | 'bool'
callback_return    := callback_value

state_type         := value_prop_type
                    | 'u32' | 'usize' | 'f32' | 'i32'
                    | PAYLOAD_TYPE
                    | 'HashSet' '<' 'String' '>'
                    | 'Vec' '<' vector_item_type '>'
                    | 'Option' '<' 'String' '>'
                    | RECORD_NAME
vector_item_type   := 'String' | 'number' | UPLOAD_ITEM_TYPE | RECORD_NAME
record_field_type  := state_type
```

核心通用类型之外，组件专属载荷类型（如 `CascaderValue`、`Vec<UploadFile>`）由 [UiProjectionSchema](../设计/编译器架构.md#5-schema-的事实边界) 按拥有它的组件类别登记，并挂接对应 Cargo capability 门禁：未启用 capability 时在编译期得到定向诊断，而不必等到 Rust 侧符号缺失。当前登记与适用位置以[输入组件参考](../参考/组件/输入组件.md)和 schema 为准。

`RECORD_NAME` 必须引用当前文档或导入图中已声明的 Record。props、state 与 Record 的默认值和递归形状分别以[组件 · props](组件.md#2-属性props)、[组件 · state](组件.md#3-状态state)和[组件 · Record](组件.md#4-类型化界面数据结构record)为准。缺失值只使用已登记的 `Option<String>`，语言不增加隐式 `null`。

## 4. 同步 action 语法

```ebnf
action            := IDENTIFIER ':' (EXPRESSION | 'do' action_block)
action_block      := '{' statement* '}'
statement         := let_statement
                   | assignment
                   | expression_statement
                   | if_statement
                   | return_statement

let_statement     := 'let' IDENTIFIER '=' EXPRESSION ';'
assignment        := IDENTIFIER '=' EXPRESSION ';'
expression_statement := EXPRESSION ';'
if_statement      := 'if' EXPRESSION action_block
                       ('else' (if_statement | action_block))?
return_statement  := 'return' EXPRESSION? ';'
```

同步 action 已实现为无参数、仅事件位置可调用的静态 UI 交互块。它可以读取 props、界面 state 和 computed，更新界面 state，调用同组件 action、内置 UI 操作和显式 Rust 回调。

以下结构不登记：参数化业务 Action、异步 action、`await`、Service、事务、重试、业务错误处理、业务循环和领域状态机。需要这些能力时，在 Rust 中实现并向界面提供窄回调。

## 5. App 边界

当前 `<App>` 只描述静态应用外壳和单根 View：`title`、`size`、`theme`、`settings` 及界面内容。`uix_app!` 返回尚未运行的现有 Rust `App` builder。

应用启动/关闭、导航决策、多窗口编排、异步任务、平台服务和资源生命周期不进入 UIX Lang，由 Rust 组合根与对应 Application Systems 持有。

## 6. 非目标语法

下列形状不是“尚未实现的目标”，而是职责边界之外的结构：

- `<Service>` / `<Method>` 与字符串服务注册；
- 带 `async`、`concurrency`、重试或事务语义的 `<Action>`；
- 在 `.uix` 中实现路由决策、窗口流程或生命周期 action；
- 网络、数据库、文件、线程、执行器和平台句柄；
- 承载领域行为的 Record / Enum 方法。

转换器遇到未登记结构时必须编译期拒绝，不生成占位业务代码，也不自动回退到动态解释。
