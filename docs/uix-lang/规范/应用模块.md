# 可移植应用模块

[← 返回 UIX Lang](../README.md)

本文持有 `<Module>` 的语言与执行合同。界面文件的既有 Rust 绑定不改变；
可移植模块显式声明输入、状态、函数和宿主端口，不捕获任意 Rust 作用域。

## 构建与入口

`uix-modules` 启用应用模块的 AOT 执行；`uix-dynamic` 额外启用运行期源码
分析。两者默认关闭，均不依赖 Scheme 的 `extensions` feature。

`uix_app::uix_module!("path/to/module.uix")` 在构建期生成原生 Rust 函数并返回
不可变 `Module`。`uix_app::app::modules::load_module(source, source_name)` 与
`load_module_file(path)` 在运行期解析一次并冻结类型化执行产物。文件入口只读取
调用方明确指定的来源，不扫描或监听目录。`Instance::new(module, ports, limits)`
创建独立实例，`call(name, arguments)` 调用导出的函数、查询或命令。

共享业务来源见 [文本处理模块](../../../examples/modules/text_bench.uix)。宿主显式
注入 `documents_read` 和 `documents_commit`，签名的名称、参数顺序、类型、返回
类型和效果必须与声明完全一致；缺少或不匹配在实例创建时拒绝。

## 声明

Module 必须声明 `name`、非空 `version` 和非负整数 `schema`。模块
接受以下成员；重复名称、未知属性、自由 Rust 名称与未支持语法在装载前拒绝。

| 成员 | 属性 | 语义 |
|---|---|---|
| Import | from、as、version | 文件入口的包内显式组合，见下文；内嵌入口拒绝 |
| Data | name、fields、export | 按声明顺序定义结构化记录；字段写作 `name: Type` |
| State | name、type、value | 每实例状态，初值为常量拥有型值图 |
| Function | name、params、returns、body、export | 纯函数，不读取实例状态或调用宿主 |
| Query | 同上 | 只读查询，可读取状态及调用 query 端口 |
| Command | 同上 | 可以更新模块状态和调用显式宿主端口 |
| AsyncCommand | 同上 | 经显式异步端口挂起并恢复，片段间有版本检查 |
| View | 无属性 | 有界动态界面模板，详见下文 |
| Port | name、params、returns、effect、async | `query` 或 `command` 宿主合同 |

Function 默认不导出，Query/Command 默认导出；可用 `export="true/false"`
显式选择。`params` 省略表示无参数，`returns` 必须存在。函数体复用既有表达式
和 `do { ... }` 语句语法，包含 let、局部赋值、if/else、return；局部变量按值
推导类型，不允许遮蔽模块名称或同一作用域重复声明。非 Unit 函数所有路径必须返回。

**异步入口（当前源码）**：`AsyncCommand` 使用相同参数、
返回类型和导出规则。`Port async="true"` 声明显式异步能力；同步端口默认
`async="false"`。`await` 只能写在 AsyncCommand 内的
`let result = await port(arguments);`，允许位于 if/else 分支；目标必须是声明的
异步宿主端口。不能在普通表达式、同步 Command、Query 或 Function 中等待，
也不能把异步端口当同步函数调用。嵌套等待另一个 AsyncCommand 暂不属于首版；
宿主可以分别投递，UI onClick/onChange 可以直接调用 AsyncCommand。


## 值、求值与效果

- 类型：Unit、Bool、Int（有符号 i64）、Float（有限 f64）、String、Bytes、
  Array&lt;T&gt;、Data 记录、Option&lt;T&gt;、Result&lt;T,E&gt;。记录按完整字段集合进行
  结构类型匹配。集合为拥有型值，复制后的更新不改变原集合。
- 整数运算溢出、除零、非法下标和非有限浮点结果返回类型化失败；不依赖 Rust
  debug/release 的不同算术行为。整数与浮点无隐式混算，数字字面量可按明确 Float
  上下文初始化。字符串长度和下标按 Unicode scalar value，非 UTF-8 字节或字素簇。
- 参数与普通操作数从左到右求值，`&&`、`||`、三元条件短路。记录字段按源码顺序
  求值；数组保留顺序。Some/None 和 Ok/Err 为显式数据构造，结果值需要完整类型上下文。
- 字符串方法：len、trim、chars、words、lines、split、join（字符串数组）、replace、
  contains、toUpperCase、toLowerCase。words 按 Unicode 空白切分，空文本为零个词。
  Array 支持 len、get（返回 Option）、push（返回新数组）、contains、map、filter。
  map/filter 使用不逃逸的单参数纯闭包，禁止读取状态或调用有副作用入口。
- Option 的 isSome、Result 的 isOk 返回 Bool；unwrapOr 显式选择后备值，参数仍
  按普通调用规则求值。标量可用 toString 生成展示文本。
- 纯函数只调用纯函数；查询不能写状态或调用 command 端口。`setState(name: value)`
  只允许出现在 Command 的语句位置，同次多字段更新先求值全部右值再应用。

## 状态、失败与生命周期

实例由单个应用执行上下文串行持有。每次公开调用以工作状态快照执行，成功才
提交；失败时丢弃本次模块状态更新。`revision()` 只在状态改变时递增。
宿主已经产生的效果不随模块状态回滚，也不会自动重试；宿主应返回明确业务结果，
例如用 Result 表达版本冲突。

`replace(candidate, expected_generation)` 在候选身份、端口和 schema 验证通过后
原子切换。相同 schema 下同名同类型字段迁移，新增字段采用候选初值；类型冲突、
schema 不符或陈旧代际失败保留旧实例。`generation()` 标记产物代，替换推进 revision。
`revoke()` 阻止后续业务调用，`close()` 释放状态与端口并阻止再次使用实例。

默认每次调用最多 100,000 个执行步骤、64 层调用、1 MiB 值图、65,536 个值节点、
2 秒协作式超时。输入、集合操作、状态和局部变量都执行规模检查；取消、超时和
配额为宿主失败，不能被模块变成成功。`Cancellation` 可跨线程发起请求。
同步原生端口无法抢占，回调必须遵守宿主返回时限；返回后重新核对超时与取消，
超时不意味着已经发生的外部效果被撤销。宿主 panic 转为 HostFailure。

运行失败携带类别、原 `.uix` 来源和位置。应用消费失败或交给既有 diagnostics，
语言运行器不另外输出日志，也不记录参数与领域内容。

## 动态界面与工作线程

本节描述当前源码中的可移植 `View` 合同，不扩张旧 `uix!` 宏的动态能力。
模块最多一个 `View`，有一个普通根节点。当前基础节点为 `Column` / `Row`
（gap、padding）、`Text`（text）、`Input`（value、placeholder、onChange）和
`Button`（text、disabled、onClick）；所有普通节点必须有模块内唯一的静态标识符
`key`。间距为 0–4096 的有限 Float。展示表达式只读模块状态、局部值和纯函数，
不执行宿主查询或命令；输入事件通过 `$event.value: String` 传值。

结构复用共享语法：`<If {condition}>`、紧随的 `ElseIf` / `Else`，以及
`<For {item} in {items} key={item.id}>`；For 数据源必须是 Array，必须提供
String 或 Int 稳定身份，同一循环实例内重复 key 使整个候选提交失败。条件和循环
不额外产生布局容器。嵌套循环捕获各层拥有型行值；事件根据当前已提交的可见
实例解析，不按旧位置回放，隐藏、已删除、禁用目标或旧产物代拒绝。

`Instance::view()` 返回与状态同次提交的拥有型快照；读取不重新执行模块。
`ViewSnapshot.key` 在静态 key 后逐层附加 `/s<UTF-8小写十六进制>` 或 `/i<十进制>`
身份段。应用应直接使用快照中的 key 路由，不根据行序号猜测；业务作者负责不复用
同一 key 代表不同业务身份。展开界面最多 4096 节点，所有 key、属性和事件捕获
共同受 Limits 的值字节/节点预算限制，递归与执行仍使用深度/步数/取消/时间预算。
属性或列表求值失败、重复身份或配额不足均保留原状态、原 revision、原界面。

`ModuleWorker::spawn(instance, capacity, wake)` 由专用线程独占实例，容量为
1–1024 个等待请求；`ModuleHandle` 可克隆，call/event/replace 非阻塞投递，满队列
返回 Quota，不隐式丢弃或重试。`ModuleRequest.sequence` 仅对接受的请求递增；
`ModuleSnapshot.sequence` 是已终止请求的最大序号，配合 pending_sequences 判断确认；
失败也确认自己的序号，但保留提交状态/界面。
`wait(timeout)` 仅供非 UI 线程等待，等待超时不取消业务；保留 cancellation 的克隆
后可显式请求取消。丢弃回执不等于取消，失败也可从 snapshot.error 消费。

`ModuleView::spawn` 返回 worker 所有者及投影器。根工厂调用 `project()` 只读取
快照并构建普通 ViewNode，不解析源码或执行业务；automation_id 为
`模块名/快照key`。输入草稿用已接受序号保护，较早完成不能覆盖较新输入；队列
拒绝或执行失败会在下一次投影恢复权威值，移除节点或替换代清除旧草稿。业务失败
保留旧界面并显示错误；关闭/撤权使 project 返回类型化错误，由应用决定卸载界面。

worker 的 wake 只唤醒所属窗口/独立后台工作区，宿主需保证其短时返回。
handle.close/revoke 立即停止接受、禁止旧结果发布并清除公开状态/界面；在途同步
端口不能抢占，也不能保证外部效果撤销。worker Drop 只请求停止，
`worker.close(timeout)` 才在非 UI 线程等待实际回收；超时明确表示线程尚未退出。
这些入口不替代应用的挂载、卸载及端口生命周期责任，也不承诺崩溃后恢复。

## 显式异步宿主与恢复

本节描述当前源码；本次版本交付与平台边界见[交付与许可](../../产品/交付与许可.md)。
`AsyncHostPorts` 与原有 `HostPorts` 分别注入
`Instance::new_with_async_ports(module, sync_ports, async_ports, limits)`；旧 new
入口不隐式授权异步端口。`ModuleHandle.call/event` 投递异步业务并返回最终结果
回执，`Instance.call/event` 不能阻塞模拟异步，会明确要求使用 worker。

`AsyncHostPort { signature, start }` 的 start 接收 `AsyncCall`：拥有型 arguments、
Cancellation、OperationId 和 AsyncCompletion。OperationId 的 instance、generation、
request、await_ordinal 区分进程内实例、代、请求和第几次等待，不承诺重启持久身份。
start 必须短时返回，宿主选择自己的事件循环或受控后台执行；该回调没有 UI、
模块状态的可变借用。启动失败/panic 转为技术失败，已发生外部效果不回滚。

`AsyncCompletion.complete(RuntimeResult<Value>)` 可以跨线程调用且只接受一次。
Ok 仅确认结果已经交回槽位，不确认 continuation 已成功提交；返回值类型/值预算
错误进入任务失败，业务 Result::Err 仍是类型化业务值。重复完成为 Conflict，终止后
迟到完成为 Cancelled；最后一份未完成回执被丢弃形成 HostFailure，不无限挂起。
保留回执的宿主负责最终完成或取消外部工作，框架不自动重试。

每个 await 前提交完整同步片段和对应界面；if/let 的内部控制流块不是额外事务。
等待只保留有界 owned locals，worker 可以处理其他请求。恢复同时验证模块代和
**整个状态 revision**（保守冲突，不是字段级合并）；有任何中间状态改变则 Conflict，
不重跑之前的片段。先前已提交片段保留，尚未提交片段失败时回滚。取消/超时/更换
模块/撤权/关闭均终止后续恢复，禁止迟到发布，不撤销外部事实。

调用预算贯穿整个异步任务：默认 2 秒总截止时间、100,000 步及现有值/深度预算，
不在 await 后重置。worker 的 capacity 分别限制等待请求与在途异步任务（各 1–1024）；
超过在途容量在执行首段前 Quota，不排无限等待。请求、完成及取消事件唤醒 worker，
没有常驻定时轮询；仅在有在途任务时安排最近截止时间等待。长时同步端口或 start
仍无法抢占，宿主必须履行外部任务和资源退出责任。

异步终态可以乱序。`ModuleSnapshot.sequence` 是已终止请求的最大序号，
`pending_sequences` 显式列出仍在途序号；不能仅凭较大 sequence 推断前面全部完成。
ModuleView 对输入草稿同时检查这两项。排队但未开始的请求不算已确认；每个回执
仍给出自己的最终结果。连续异步输入可能因中间状态写入而冲突，不自动重试或
承诺“后输入总覆盖先输入”，应用应按业务需要显式取消/节流并处理失败。

## 等价性与验证

AOT 与动态入口消费同一标签、表达式和 do 块解析器及应用模块类型检查结果。
AOT 生成原生 Rust 函数，动态执行器消费有类型节点；两条路径共用 checked
值操作、端口校验、预算与状态提交合同，不在运行时重新编译 AOT 来源。

公开行为入口为 `tests/uix_modules_public_api.rs`，验证同一模块的结果、状态、
宿主效果顺序、类型拒绝、算术失败、短路、取消、配额、实例隔离和热替换终态。
语言等价不承诺两种方式具有相同速度、内存分配或资源耗尽阈值。


## 包内组合与统一工具链

当前源码支持显式 `Import from="./text.uix" as="text" version="1"`。
文件入口以根文件所在目录为包边界，读取实际依赖闭包并冻结来源内容；
拒绝网络/绝对路径、路径或符号链接越界、循环、重复别名和不匹配的精确版本。
内嵌入口不读盘，不扫描/监听/发现未引用文件。闭包含根最多64文件和64模块实例，
最多16条依赖边深度，总源码4 MiB、每文件1 MiB；结构类型展开最多4096节点。

通过 `text.process(...)` 只能消费显式导出函数/查询/命令；`Data export="true"`
才允许依赖签名中的限定类型名。完整结构决定类型兼容，不以同名代替结构相等。
根不自动再导出依赖。根实例持有全部链接状态，别名路径隔离各自状态；同一别名
复用一份状态，不同别名独立。宿主端口按限定别名路径注入，导入不放宽纯/只读/命令
效果。同一同步调用片段内直接执行依赖，不为组合增加队列或隐藏实例。

首版只允许根View，带View的业务库依赖明确拒绝，不静默丢弃。依赖AsyncCommand
可作为根View事件目标；await仍只等待本模块显式异步宿主端口，不支持任意异步
函数互相等待。完整界面复用由宿主显式挂载ModuleView，见前述动态界面合同。

替换以根及各依赖别名的模块名/schema保持身份；允许兼容版本/算法变化，
类型/身份/schema冲突拒绝且旧状态、界面和代保持。依赖的声明、符号和失败保留
真实SourceId/源区间；AOT生成追踪全部来源文件，不在运行期重读。

CLI `check` 自动识别模块（亦可显式 `--target module`），`compile --target module`、
`fmt` 和 `query modules --json` 复用共享前端。LSP的模块诊断、定义、悬停、能力说明
使用相同来源图，根或依赖编辑使相应分析失效，关闭释放overlay/根记账；没有隐藏
扫描或定时轮询。旧UI的 `@import` 与Scheme语法不因此改变。

示例来源为[组合包](../../../examples/modules/composed/main.uix)，
公开行为入口为[组合消费者](../../../tests/uix_module_composition_public_api.rs)。
实际源码、CLI/LSP制品和验收边界见 TASK-069（内部历史记录，不作为公开版本说明）；
协议通过不等于真实编辑器UI或分配器级内存回收已验收。


## 外部文本工作台

当前公开源码提供独立宿主 [module_workbench.rs](../../../examples/module_workbench.rs)，
以及可替换的 [v1 源码](../../../examples/modules/workbench/v1/main.uix) /
[v2 源码](../../../examples/modules/workbench/v2/main.uix)。
它不替换 Scheme `text_workbench`，只操作本进程的合成文本，不读取真实文档。

在源码目录准备全新合成包并启动（不修改仓库内的示例源）：

```bash
cd /path/to/uix-app
package="$(mktemp -d /tmp/uix-module-workbench.XXXXXX)"
cp ./examples/modules/workbench/v1/main.uix "$package/main.uix"
cargo run --locked --offline --no-default-features \
  --features uix-dynamic,agent-control --example module_workbench -- \
  --module-source "$package"
```

1. 在所需工作面点击“装载”，再“异步读取”；编辑草稿、“规范空白”后“按版本提交”。
   合成存储初始版本为1，读取通过有界队列交给独立领域线程，固定50ms是示例服务延迟，
   不是框架响应保证。成功提交才推进版本；冲突保留草稿和原基准版本，不覆盖、不重试。
2. 保持宿主进程运行，将该合成包的 `main.uix` 更新为上面的v2源码，点击本侧“替换源码”。
   v2保留兼容状态，标题/按钮变为“大写分隔”，实际处理变为大写词组以 ` | ` 连接。
   候选解析/身份/schema/端口不兼容时保留旧代；不监听目录，不自动重编译或重启。
3. “状态”读取当前写权及权威文档；“提交旧代动作”在替换后验证旧commit代际拒绝，
   未替换时不会发送当前代提交。“撤权”关闭本侧写权并撤销实例能力；“停用”关闭并join
   模块worker，移除挂载；随后显式“装载”创建新实例/新授权，空草稿需重新读取。
4. 前台原生窗口与Agent后台工作面各自拥有管理线程、worker、ModuleView、状态、草稿和
   焦点，只通过显式领域端口共享内容与版本。Agent使用框架原装客户端按实际实例发现/绑定，
   不把后台根当成前台输入通道；在后台提交后，前台旧草稿可能提交冲突，这是预期隔离。
5. 顶部“关闭工作台”执行真实原生关闭，再关闭后台工作面、两侧模块/管理线程与领域读取服务。
