## 图形契约整改（2026-07-12）

<a id="d181"></a>

### #181 有序帧命令流与唯一 present 语义

- **日期 / 状态**：2026-07-12 / active。
- **裁决与理由**：一帧内的 clear、native draw、CPU fallback segment、offscreen render/blit 必须进入同一按 painter order 执行的 API 中立 `FrameEncoder`；只有 `Presenter` 拥有一次最终 present，返回 `PresentOutcome`。拒绝“native 延迟提交 + offscreen 立即执行”和让同一 `RenderOutcome::Present` 同时表示“需要外部 present”与“已经尝试 present”，因为二者会改变画序并伪造成功语义。
- **影响**：`draw::pipeline` / compositor / GPU engine / software upload；Picture、局部重绘和指标必须以真实 present 结果为准。
- **生命周期**：`supersedes: 无`；`amends: #162,#168,#169`。实施与验收 → [P6.9 GFX-R1](进度.md#p69-图形契约整改) · [BUG-20260712-004](问题.md#bug-20260712-004)。

<a id="d182"></a>

### #182 可失败图形生命周期与受控恢复

- **日期 / 状态**：2026-07-12 / active。
- **裁决与理由**：context/surface 的 initialize、resize、make-current、begin/end-frame 与 present 全链路返回 typed `Result`，至少区分 `SurfaceLost`、`DeviceLost`、`OutOfMemory`；失败帧不得清 dirty、不得计成功，须在帧边界执行 surface 重建、同 recipe 重建、下一候选或 Software 回退。拒绝仅日志吞错和逐帧无状态重试，因为会造成永久黑屏、错误指标或忙循环。
- **影响**：`native::traits`、engine、FrameRenderer、event loop、诊断与恢复测试；运行期恢复是有限状态机，不改变 [#162](#d162) 的初始化期选择边界。
- **生命周期**：`supersedes: 无`；`amends: #162,#170,#172`。实施与验收 → [P6.9 GFX-R2](进度.md#p69-图形契约整改) · [BUG-20260712-005](问题.md#bug-20260712-005)。

<a id="d183"></a>

### #183 图形线程亲和与资源所有权

- **日期 / 状态**：2026-07-12 / active。
- **裁决与理由**：context、surface 和 API device 对象显式绑定创建它们的 UI/render thread，不以 `unsafe impl Send/Sync` 绕过；跨线程只发送拥有 `Send` 证明的 API 中立命令/资源描述。长期资源模型为“每 adapter/API 共享 `GraphicsDevice` + 每窗口 `WindowSurface` + 每帧 `FrameEncoder`”，但正确性整改先于共享与批处理优化。
- **影响**：`RenderBackend` 约束、所有 native context、窗口会话、glyph/image cache 与多窗资源复用。
- **生命周期**：`supersedes: 无`；`amends: #164,#168,#171`。实施与验收 → [P6.9 GFX-R3/GFX-R6](进度.md#p69-图形契约整改) · [RISK-20260712-004](问题.md#risk-graphics-thread-affinity)。

### #184 Recipe registry、能力真值与 API 中立边界

- **日期 / 状态**：2026-07-12 / active。
- **裁决与理由**：probe 单元是可重复的 `(GraphicsBackend, RasterMode, PresentMode)` recipe 行，而非单一 API identity；同一 API 可有多行。create/render/sample/crop、partial redraw、surface damage 等能力独立声明，只有完整满足契约才置 true。GL/D3D/Vulkan/Metal 对象与 proc loader 留在 `native/graphics/<api>`；`draw` 只提交 API 中立命令。删除或收窄保证失败的公开 factory，并用 opaque native handle 或显式 `unsafe` 契约封闭原始指针。
- **影响**：registry/caps、`IGraphicsContext` 拆分、OpenGL glow 所有权、公开 factory、feature/cfg 守卫。
- **生命周期**：`supersedes: 无`；`amends: #162,#163,#164,#168,#169,#171,#172`。实施与验收 → [P6.9 GFX-R4](进度.md#p69-图形契约整改) · [BUG-20260712-008](问题.md#bug-20260712-008)。

### #185 Hybrid fallback 的顺序、混合与成本边界

- **日期 / 状态**：2026-07-12 / active。
- **裁决与理由**：unsupported operation 只能形成仍在统一命令流中的 bounded CPU segment；按 damage tile 上传，并保持 blend、clip、offscreen source crop 与 scissor 语义。依赖 destination 的 blend 若无等价实现必须通过 caps 显式拒绝，不能在透明 CPU buffer 上近似后再 alpha-over。拒绝“首个 unsupported 后整帧 CPU overlay + 全 surface 上传”，因为语义错误且 4K 可产生约 33 MiB/帧传输。
- **影响**：NativeGpuBackend、CPU rasterizer、D3D11/D3D12 soft path、Picture/offscreen 与跨后端一致性测试。

### #188 外部 presenter 的待提交帧语义

- **日期 / 状态**：2026-07-12 / active。
- **裁决与理由**：`RenderOutcome::Present` 只表示最终 presenter 已成功提交。CPU/Software 的 external presenter 路径在 `GraphicsEngine::end_frame` 后只能返回 `PresentPending`；窗口会话执行唯一的外部 `IPresenter::present`，成功后报告最终提交并通知恢复状态机，失败则保留 dirty 并将 typed failure 交给恢复。禁止在外部 present 之前记录 present 指标、重置 recovery 或清 invalidation。
- **影响**：`RenderOutcome`、`FrameRenderer`、`GraphicsEngine` 恢复 hook、主/副窗口 event loop、Software/Null engine 与回归测试。

### #189 CPU fallback 的有界 tile 提交

- **日期 / 状态**：2026-07-12 / active。
- **裁决与理由**：API 中立 `SoftFallbackTile` 描述整张 CPU source surface 中的最小 alpha-visible 矩形；native context 必须只上传、复制并采样该 tile，同时保留完整 source pitch。未实现 partial-tile 的 context 必须返回 typed `NotImplemented`，不得静默升级为整帧上传。这样 native、GL 与 CPU fallback 都能以同一“透明 RGB 不影响提交”的规则保持 painter-order 语义并约束传输成本。
- **影响**：`IGraphicsContext`、`NativeGpuBackend`、D3D11/D3D12 soft upload、跨后端回归；该数据对象可跨线程，native texture/context 仍不能跨线程。

### #190 Picture 离屏的 checked 失败边界

- **日期 / 状态**：2026-07-12 / active。
- **裁决与理由**：Picture 的 bind/clear、flush、restore target 与有序 blit 必须经返回 `Result` 的 checked 边界传播；`LayerTree` 收到失败后须尝试恢复 target、保持 Picture 与帧 dirty，并在 `FrameRenderer` 返回 typed failure 前停止，不得再调用 `end_frame` 或最终 present。旧 bool/void 入口仅为兼容旧调用方保留，不能成为 production compositor 的成功路径；拒绝把 native 失败留待最终 present 或只写日志，因为会让部分帧与成功指标混淆。
- **影响**：`RenderBackend` / `GraphicsEngine` 的 Picture helper、`picture` compositor、`FrameRenderer`、NativeGpu/GL/CPU backend 与失败回归。

### #195 Native 执行 API-neutral raster DTO

- **日期 / 状态**：2026-07-13 / active。
- **裁决与理由**：`IGraphicsContext` 是 draw 到 native 的唯一 raster 命令边界；它只接受 API-neutral 的 clear、solid rect、soft tile、offscreen bind/blit DTO 并返回 typed failure。WGL/EGL context 在 make-current 后创建并独占 GL program、buffer、texture 与 FBO；`draw` 不得保留 `glow`、`NativeOpenGlRuntime`、runtime lease 或能直接触达 GL 对象的 `GpuBackend`/`GpuCanvas2D`。兼容层仅可 re-export 纯 shader 文本，不能重新引入对象或 loader。离屏 Picture 作为当前目标时，source blit 必须先提交该目标的有序 segment；self-blit 必须 typed 拒绝。这样才能把对象线程亲和和 native 生命周期保持在 native，同时让 draw 只处理平台无关命令和画序。
