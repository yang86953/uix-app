## 内容摘要

UIX 是一个 **Rust 原生跨平台应用开发框架**：提供开发完整应用所需的通用能力，让同一套界面与应用逻辑运行在多个平台的原生窗口上。范围不只包括组件与绘制，还包括应用组合根、生命周期、窗口与事件循环、网络、数据库与 ORM、文件和平台服务、运行保障及开发工具。React 只类比组件层，不是整体能力上限。UIX Lang 的目标是 TSX 式组件语言，同一定义支持编译与动态加载；当前旧 UI AOT、可移植模块和 Scheme 扩展仍按各自合同运行，运行时不绑定浏览器或 Web 技术栈。

产品目标覆盖 Windows、Linux、macOS 与移动端原生窗口，当前主要面向 Windows 与 Linux，移动端 backend 暂缓。这里的“应用框架”不表示 UIX 接管应用业务，也不表示全部目标能力和平台已经交付。网络和 ORM 已明确纳入目标，尚无统一公开 API；旧“全栈仅限 UI、应用壳和本地数据”的边界已被替代。

核心取向：

- **原生绘制**：不使用 WebView 或 Electron 作为界面运行时，由 UIX 图形管线直接绘制到原生窗口。
- **Rust 宿主与按需执行**：旧 UI 描述默认 AOT 生成 Rust；可移植应用模块通过显式 `uix-modules` / `uix-dynamic` 选择 AOT 或动态执行，不要求旧 UI 文件迁移。
- **应用级复用**：Rust 宿主通过统一的 App、窗口、调度、平台与数据契约在已交付平台间复用；平台专属能力仍以显式 capability 和 typed error 表达。
- **软件动态扩展**：按需启用标准 Scheme R7RS-small，在运行中增加功能、业务规则、命令、事件、服务实现和界面；扩展自有状态，宿主通过显式能力约束其访问，见[产品边界](产品/能力.md#软件动态扩展的产品边界)。
- **资源优先**：无待处理事件、计时器、队列或帧机会时进入休眠，避免固定 tick 和无条件重绘。
- **按需构建**：通过显式 feature 选择控制编译图，再由链接裁剪移除已选能力中的不可达内容。
- **平台收敛**：上层使用统一契约，平台差异收敛在平台与图形边界内；实际平台覆盖仍以交付说明为准。

框架与组件库共同支持界面组件、表单、数据展示、动画和浮层；框架还提供或规划统一图形、多窗口、应用服务、网络、数据库与 ORM、平台能力及工程工具。框架的目标、当前入口和限制见[能力与边界](产品/能力.md#完整应用开发能力目标)，不将具体控件职责混入框架。

网络与 ORM 属于框架目标，同步接入不再被一概排除。仍不把 WebView 作为界面运行时，不承诺跨网络远程控制（显式启用的同用户本机 Agent 控制面除外）、诊断模块自动远程上传、任意执行历史 `.uix` 中的 Rust 自由名称、无授权 I/O 或原生机器码热替换。两条扩展路线的目标与限制见[能力与边界](产品/能力.md)。
